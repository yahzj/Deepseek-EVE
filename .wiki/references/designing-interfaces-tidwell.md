## 结论先行

- **模式语言的本质**：模式（Pattern）不是僵死复制的 UI 模板，而是在**特定上下文（Context）**中，平衡多方相互冲突的**制约力（Forces）**，经过时间与工程检验的**通用解决方案（Solution）**。
- **软件即系统（Software Is Systems Now）**：现代交互设计已彻底告别孤立单页图纸的时代。现代界面是跨设备、多视口、连续状态流转的有机生命体，UI 是人与底层复杂状态机进行心智对话的动态投影。
- **屏幕类型四元分类（The Four Screen Types）**：所有现代复杂应用界面，本质上都是四种基础屏幕类型的单体或复合嵌套：
  1. **Overview（概览型）**：宏观掌控，呈现集合、列表、仪表盘与多维切片。
  2. **Focus（聚焦型）**：深入微观，全屏或大区域专注呈现单一实体（如特定舰船、单一行星）。
  3. **Make（创作型）**：提供工具箱与画布，供用户装配、构筑、定制复杂产物。
  4. **Do（任务型）**：步骤闭环，引导用户快速完成明确的单一事务（如结算、跃迁确认）。
- **《大鲸鱼-深空放置》的核心工程映射准则**：
  1. **空间认知定锚**：坚决采用 **Center Stage（中心舞台） + 双侧 Action Panels（动作面板） + 底部 Collapsible Panel（折叠控制台/日志）** 的经典 HUD 拓扑，确保深空态势与操作控件永不争夺主视区。
  2. **装配与仓库无缝流**：将 **Two-Panel Selector（双栏选择器）** 与 **Dynamic Queries（动态多维过滤）** 深度整合，鼠标悬浮即时触发参数差分前馈，消除装配调试的认知摩擦。
  3. **长周期放置的安全探索**：挂机放置资产积累周期以日、周计。系统必须全面落地 **Safe Exploration（安全探索）** 与 **Preview（变更预览）**，高危不可逆操作（拆解、重置、覆写）必须提供物理隔离与撤销回退机制。
  4. **组件系统的原子契约**：严格遵循 **Atomic Design（原子设计）**，将 `@whale/ui`（原子/分子基元）与 `@whale/desktop` / Core 状态解耦，杜绝样式硬编码与布局漂移。

## 二、十二核心章节深度精要与模式库归纳

### 第 1 章：为人设计与人类认知行为模式 (Designing for People)

软件是人类心智的延伸。设计界面前，必须深刻理解人类大脑处理信息、做出决策和形成习惯的神经与认知机理。

#### 核心认知原理与行为模式库
- **Safe Exploration（安全探索）**：
  - *机理*：用户在不熟悉新界面时天然充满防御与恐惧。如果误触会导致无法挽回的破坏（如格式化、误卖神装），用户会陷入瘫痪。
  - *模式策略*：界面必须提供零代价的探索环境。允许随时回退、随时取消，将不可逆危险操作置于安全区之外。
- **Instant Gratification（即时反馈与即刻满足）**：
  - *机理*：人类多巴胺奖赏回路对毫秒级的输入响应极度敏感。长达数秒无声无息的处理会引发系统崩溃的疑虑。
  - *模式策略*：在 100ms 内给予视觉/听觉应答；耗时任务立即展示进度或骨架屏，先呈现已有结果。
- **Satisficing（满意解决策）**：
  - *机理*：心理学家赫伯特·西蒙提出，人类极少为了寻找「全局最优解」去通读全屏文字，而是抓取眼帘中第一个「看起来能用」的选项（满意即止）。
  - *模式策略*：弱化冗长说明，依靠醒目的视觉锚点、自解释的图标与推荐标记引导第一直觉。
- **Changes in Midstream（流程中途变更）**：
  - *机理*：用户在执行复杂任务的半途，往往会因为外部刺激或新线索临时改变主意。
  - *模式策略*：避免强行锁死多步表单；允许用户在保持当前输入草稿的前提下，跳出查看参考数据或修改上一节点。
- **Deferred Choices（延迟选择）**：
  - *机理*：在用户建立充分信任和上下文之前，过早要求其配置偏好或填写敏感信息会导致流失。
  - *模式策略*：采用渐进式引导，让用户先体验核心价值，非关键选项允许点击「跳过」或「稍后设置」。
- **Incremental Construction（增量构建）**：
  - *机理*：面对高维复杂产物（如装配一艘战列舰），人类无法一次性在大脑中并发构思全部部件。
  - *模式策略*：支持模块化拼装、局部测试、随时保存中间态，让构筑过程演化为分步迭代。
- **Habituation（习惯化）**：
  - *机理*：人类大脑具有极强的神经修剪机制，对长期重复出现且无害的强刺激（如常驻的黄色警示标、千篇一律的确定确认框）会自动视而不见（警报疲劳）。
  - *模式策略*：警示必须分级且克制；将破坏性操作的确认从无意识的「点击确认」升级为有意识的交互（如长按 3 秒、输入删除关键词）。
- **Spatial Memory（空间记忆）与 Prospective Memory（前瞻记忆）**：
  - *机理*：海马体对物体在三维/二维空间中的物理位置极为敏感，人类寻找工具往往靠「它在左上角那个格子里」，而非靠阅读标签。前瞻记忆则是「记住未来要执行某事」。
  - *模式策略*：UI 核心功能入口的位置必须高度稳定，严禁无故随视口或会话跳动；通过未读标记、任务气泡外化前瞻记忆线索。
- **Streamlined Repetition（流畅重复）与 Keyboard Only（键盘可达）**：
  - *机理*：专家用户（Power Users）在执行成千上万次高频操作时，任何额外的鼠标移动和点击都是认知与生理折磨。
  - *模式策略*：提供批处理操作（Batch Actions）与快捷键闭环支持，实现手指不离键盘的全程盲打体验。

### 第 2 章：内容组织与信息架构 (Organizing the Content)

信息架构（IA）是界面的骨骼。优秀的信息架构将混乱的数据世界转化为清晰有序的认知空间。

#### 信息组织维度与 MECE 原则
- **MECE 原则（Mutually Exclusive, Collectively Exhaustive）**：
  - 分类体系必须做到「相互独立，完全穷尽」。分类重叠会导致用户在选择时陷入认知停顿，分类遗漏会导致功能成为死角。
- **LATCH 五大组织维度**（Richard Saul Wurman 提出，本书进一步延展）：
  - **Location（位置）**：物理或虚拟空间坐标（如星系图谱、舰体装配槽位）。
  - **Alphabetical（字母表）**：文本检索与字典索引（适合已知名称的快速查找）。
  - **Time（时间）**：时间线、活动日志、历史记录、挂机演算时序。
  - **Category / Facet（类别与分面）**：按功能属性、品质阶梯、工业类型进行多维打标。
  - **Hierarchy（层级与数值大小）**：科技树、从属关系、DPS/装甲厚度等数值降序。

#### 四大核心屏幕类型（The Four Screen Types）
```
┌───────────────────────────────┬───────────────────────────────┐
│        Overview (概览型)       │         Focus (聚焦型)        │
│ 作用：鸟瞰全局、多维状态巡检  │ 作用：专注单一实体的深邃洞察  │
│ 典型：仪表盘、星系全图、资源表│ 典型：单舰详情、特定星球地表  │
├───────────────────────────────┼───────────────────────────────┤
│          Make (创作型)        │          Do (任务型)          │
│ 作用：构筑、组装与定制复杂物  │ 作用：封闭、聚焦、高效执行闭环│
│ 典型：装配车间、战略蓝图规划  │ 典型：跃迁确认、资产交易结算  │
└───────────────────────────────┴───────────────────────────────┘
```

#### 本章核心模式精选
- **Dashboard（仪表盘）**：
  - 将多源、异构的关键指标（KPIs）汇总于单一紧凑屏幕，使用极度精炼的图表、状态指示灯和数字聚合，支持一键点击下钻。
- **Canvas Plus Palette（画布与调色板）**：
  - 左侧/右侧提供组件工具箱（调色板），中央是开阔的组装舞台（画布），支持自由拖拽、磁吸吸附、连线与属性联动。
- **Alternative Views（多重视角）**：
  - 同一数据集提供不同视角的无缝切换（例如：星系既可展现为 3D/2D 空间拓扑图，也可展现为高密度的资源收益数据表格）。
- **Many Workspaces（多工作区）**：
  - 允许专家用户针对不同工作流（如纯挂机监控、大规模工业制造、舰队决战配置）保存并自由切换独立的窗口布局与工作台。
- **Wizard（向导模式）与 Settings Editor（设置编辑器）**：
  - 将复杂漫长的初始化流程切片为线性步骤，并在复杂设置中采用分类清晰的左侧目录与右侧配置面板。

### 第 3 章：导航、路标与寻路 (Navigation, Signposts, and Wayfinding)

界面的导航决定了用户「身在何处」、「能去何方」以及「如何回去」。

#### 六大经典导航模型
1. **Hub-and-Spoke（轴辐式）**：
   - 核心枢纽为中枢（Hub），所有分支功能为辐条（Spoke）。访问不同分支必须先回到主中枢。适合层级森严、各模块独立性强的系统。
2. **Fully Connected（全连接网状）**：
   - 每个页面皆可直达任意其他页面。给予最大灵活性，但在大规模系统中极易引发迷航与认知过载。
3. **Multilevel or Tree（多级树形）**：
   - 经典的父子层级关系，适合信息量极其庞大且分类严谨的体系（如科技树、深空殖民地行政划分）。
4. **Step-by-Step（步骤流式）**：
   - 严格线性锁定推进（1 → 2 → 3 → 完成），剥离一切非必要干扰，保障任务原子性。
5. **Pyramid（金字塔式）**：
   - 顶部是极简概览，往下逐层展开宽度与深度，越深信息越密集、专业度越高。
6. **Flat Navigation（扁平导航）**：
   - 所有主要功能处于同一层级，通过底部 Tab 或顶部导航栏直接平铺切换，跳转成本极低。

#### 本章核心模式精选
- **Clear Entry Points（清晰切入点）**：首页或模块入口不得平铺过载，必须有层次鲜明的主要操作按钮（Primary Action）引导初次进入。
- **Modal Panel（模态面板）**：彻底中断主视图交互，要求用户必须在此刻聚焦并处理眼前紧急任务，避免背景状态污染。
- **Escape Hatch（逃生舱）**：任何深层下钻或全屏沉浸界面，左上角或右上角必须提供醒目、一致的「返回」或「关闭」逃生通道。
- **Breadcrumbs（面包屑）**：清晰提示 `主星系 > 恒星系 > 柯伊伯带 > 采矿驳船` 的空间与层级归属，支持任意父级的一键跃迁。
- **Annotated Scroll Bar（带注释滚动条）**：滚动条不仅是位移工具，更是迷你地图（Minimap），在其上标注错误标记、搜索命中高亮或重要里程碑。
- **Animated Transition（动画过渡）**：用位移、淡入淡出维持空间连续性，告知大脑「新面板是从左侧滑入的，关闭时它会退回原处」，强化空间心智定位。

### 第 4 章：屏幕元素布局与格式塔视知觉 (Layout of Screen Elements)

布局是将功能块在二维空间中建立秩序的艺术。人类视觉系统遵循格式塔（Gestalt）心理学法则。

#### 格式塔四大核心组织法则
1. **Proximity（邻近原则）**：空间上距离相近的物体，会被知觉自动聚类为一个整体。**间距是最廉价也最强有力的分组工具**。
2. **Similarity（相似原则）**：具有相同视觉属性（颜色、形状、字号、字体风格）的物体，会被大脑归为同类功能项。
3. **Continuity（连续原则）**：视觉倾向于沿着平滑连续的线条或对齐的边缘流动，形成清晰的视觉动线（Visual Flow）。
4. **Closure（闭合原则）**：即使没有封闭的硬框线，大脑也会利用对齐边缘或背景色块自动脑补出完整的边界。

#### 核心布局模式精选
- **Visual Hierarchy（视觉层级）**：
  - 利用「尺寸（Size）、字重（Weight）、对比度（Contrast）、留白（Whitespace）」四要素，使玩家视线在 0.1 秒内精准命中屏幕头号核心信息（如当前战力或离线挂机净产出）。
- **Progressive Disclosure（渐进呈现）**：
  - 核心界面仅呈现 80% 用户所需的常规信息；高阶参数与专家级微调（如每个激光炮台的精确散热角与电容损耗）隐藏在「展开/更多」之下，兼顾新手平易性与专家深邃度。
- **Center Stage（中心舞台）**：
  - 屏幕核心黄金区域留给最重要的主视觉模型（3D 舰船模型、星系天体雷达），周围工具与数据面板环绕布局，主次分明。
- **Grid of Equals（等宽网格）**：
  - 针对地位平等的实体集合（如装备背包格、科技研究卡片），采用几何均等的栅格化排列，赋予秩序感。
- **Module Tabs（模块选项卡）与 Accordion（手风琴）**：
  - 在受限屏幕空间内组织平行模块，选项卡适合跨模块快速横跳，手风琴适合在单列内按需收放。
- **Collapsible Panels（可折叠面板）**：
  - 侧边栏与底部信息区支持一键折叠为微型图标栏（Icon Bar），将最大视界空间让位给主舞台。

### 第 5 章：视觉风格与美学 (Visual Style and Aesthetics)

视觉美学不仅是装饰，它直接决定了界面的可读性、感知性能与情感共鸣。

#### 视觉设计要素与工程约束
- **Typography（排版工程）**：
  - 采用模块化字阶（Modular Type Scale）。大标题、章节头、正文、微型注脚保持严格的比例级数（如 1.25 或 1.333）。
  - **数值等宽对齐（Tabular Figures / Monospace Numerals）**：在展示频繁变动的数值（如金币、算力、秒级产出）时，必须启用 OpenType `tnum` 属性或等宽字体，杜绝数值跳动导致的界面横向抖动。
- **Color & Contrast（色彩模型与无障碍对比度）**：
  - 严格遵守 WCAG 2.1 规范，关键文本与背景对比度至少达到 4.5:1（大字 3:1）。
  - 杜绝仅靠颜色传达状态（如红绿代表敌我/损耗）：必须辅以形状、图标或文字标签，避免色觉障碍玩家迷失。
- **企业与高信息密度美学（Enterprise & HUD High-Density）**：
  - 减少大面积纯白/高光发热；利用微边框（1px Borders）、半透明叠加（Glassmorphism / Sci-Fi HUD）、极窄留白与深色底衬，实现冷静、专业、硬核的沉浸感。
- **五大视觉风格变迁**：
  1. *Skeuomorphic（拟物风）*：高光质感、重力阴影，提供极强物理暗示（早年操作台）。
  2. *Illustrated（插画风）*：生动温情，多用于轻度休闲产品。
  3. *Flat Design（纯粹扁平）*：剥离一切立体阴影，有时因意符过弱导致可点击性下降。
  4. *Minimalistic（极简主义）*：极度留白与字体优先，追求极致纯净。
  5. *Adaptive / Parametric（自适应/参数化微风格）*：根据设备状态、主题变量动态微调投影与辉光，科幻 UI 的主流演化方向。

---

### 第 6 章：移动端界面 (Mobile Interfaces)

移动设备带来了前所未有的物理约束：屏幕狭小、触控无精确定位、手持晃动与注意力高度碎片化。

#### 移动端适配核心策略
- **Linearize Content（内容线性化）**：
  - 将桌面端并排的多列复杂布局，降维拆解为单列垂直堆叠流（Vertical Stack），消灭横向滚动。
- **Strip to Essence（剔除冗余，聚焦本质）**：
  - 移动场景下用户只关注核心状态；非核心配置与复杂分析退居二级入口。
- **Touch Targets（触控热区准则）**：
  - 物理触控热区不得小于 44×44 pt / 48×48 dp；视觉图标可以精细小巧，但感应外框必须宽松（Generous Borders），杜绝误触。
- **Bottom Navigation（底部易达导航）**：
  - 单手拇指热区集中在屏幕下半部。主功能 Tab 必须固定于底部，顶部仅放置逃生与辅助工具。
- **Collections and Cards（卡片流呈现）**：
  - 卡片天然具备自封闭的边界，最适合在可滑动列表或胶卷走马灯（Filmstrip）中容纳异构信息单元。

---

### 第 7 章：列表呈现模式 (Lists of Things)

软件系统的本质是集合的展现与操作。列表是所有数据驱动型系统的基石。

#### 四大核心展示场景与模式选型
- **Two-Panel Selector / Split View（双栏选择器 / 分割视图）**：
  - *机制*：左侧为稠密实体列表，右侧为主详情/操作视窗。左侧选中项高亮激活，右侧毫秒级响应联动。
  - *场景*：桌面端复杂系统的绝对王者模式（如背包仓库、装配库、星系资产清单），完全消除跨页跳转成本。
- **One-Window Drilldown（单窗下钻）**：
  - *机制*：在受限视口中，点击列表项整屏滑入详情页，左上角提供返回箭头。移动端与小屏的标配。
- **List Inlay（列表内嵌展开）**：
  - *机制*：点击列表项直接在其下方展开详情（手风琴式展开），无需离开列表上下文。适合详情短小轻量的场景。
- **Cards & Thumbnail Grid（卡片与缩略图网格）**：
  - *机制*：用于视觉资产占比高、需要展示图片/立绘/雷达图的多维实体（如舰船造船厂展厅）。
- **Pagination vs Infinite List（分页 vs 无限流）**：
  - *权衡*：无限列表适合探索性、休闲浏览（如战斗历史日志）；精确资产管理必须采用分页（Pagination）或快速跳转（Jump to Item / Alpha-Numeric Scroller），以支持精准寻址与稳定定位。
- **New-Item Row（新建项行）**：
  - 在列表首行或末行常驻内联输入框，无需打开弹出层即可连续批量录入数据。

---

### 第 8 章：动作与命令交互 (Doing Things: Actions and Commands)

用户通过指令作用于系统。命令模式的核心是明确意图、即时前馈与可逆保障。

#### 核心命令模式库
- **Direct Manipulation（直接操控）**：
  - 遵循本·施奈德曼原则：持续展现被操控对象，用物理手势/鼠标拖拽替代抽象菜单命令（如直接拖拽武器插槽到舰体、直接用滚轮缩放星系）。
- **Action Panel（动作面板）**：
  - 将与当前选中对象相关的所有操作集中收拢于专用工具条中，禁用非活跃操作，提供清晰的状态上下文。
- **Button Groups（按钮组）**：
  - 将互斥操作（如 `停留 / 跃迁 / 攻击`）或关联工具紧密编组，减少视觉离散度。
- **Preview（实时预览）**：
  - 在最终提交变更前，提供无副作用的模拟前馈（例如：未购买前在舰体上实时试穿武器，动态展示火力曲线与电容负载变化）。
- **Cancelability（可取消性）与 Spinners/Loading**：
  - 任何超过 1 秒的操作必须允许玩家中途取消；加载状态必须明确指示是本地阻塞还是网络挂起。
- **Multilevel Undo（多级撤销）与 Command History（命令历史）**：
  - 彻底淘汰粗暴的二次确认弹窗；通过完整的命令模式栈记录操作历史，提供 `Ctrl+Z` 多级撤销能力，彻底解除玩家的探索心理包袱。
- **Macros（宏命令）**：
  - 允许高级玩家将一连串高频重复命令（如批量行星开采、自动化物资倾倒）录制或编排为一键宏。

---

### 第 9 章：展示复杂数据 (Showing Complex Data)

高维数据的可视化不仅是图画，更是认知的放大器。

#### 认知基础：前注意力变量（Preattentive Variables）
在人类意识介入（需要花费认知力去计数和阅读）之前，视皮层会在 200ms 内自动并行捕获这些视觉变量：
- **位置（Position）**：感知最为精确（散点图、坐标系）。
- **尺寸/长度（Length/Size）**：适合表达定量数值差异。
- **形状（Shape）**：适合表达定性分类。
- **色相（Hue）**：适合区分类别（敌、友、中立）。
- **色彩饱和度与明度（Saturation/Value）**：适合表达强度、风险等级或温度梯度。
- **朝向（Orientation）**：适合表达矢量方向与航道趋势。

#### 复杂数据交互模式库
- **Datatips（数据悬浮提示）**：
  - 保持图表整洁不堆砌数值，鼠标悬浮时弹出高信息密度的格式化微型数据卡片。
- **Data Spotlight（数据聚光灯）**：
  - 高亮鼠标悬停所关联的数据链条，其他无关线条或节点半透明弱化，瞬间从视觉迷雾中提炼信噪比。
- **Dynamic Queries（动态多维过滤）**：
  - 通过连续滑块、多选复选框，直接过滤庞大数据集。滑块拖动的每一微秒，主视窗图表实时重排，形成极度顺滑的动态探索流。
- **Data Brushing（笔刷联动）**：
  - 跨多重视角的联动选择。在「DPS分布图」中圈选一批舰船，旁边的「成本散点图」与「星系分布图」中对应的斑点即刻同步高亮。
- **Small Multiples（小型多图表 / 分面图）**：
  - 采用相同的坐标轴与尺寸，并排平铺数十个微型图表（如对比 20 个采矿基地的 24 小时产能波动），大脑可以瞬间比对模式异同。

---

### 第 10 章：获取用户输入：表单与控件 (Getting Input from Users)

表单是系统与用户之间摩擦力最大的交互环节。优秀表单的唯一目标是最小化输入阻力。

#### 表单核心模式库
- **Forgiving Format（宽容格式）**：
  - 绝不强求用户严格按照特定格式输入。无论是 `1000000`、`1,000,000` 还是 `1M`，系统底层自动清洗解析，不报错弹窗。
- **Good Defaults and Smart Prefills（良好默认值与智能预填）**：
  - 永远不要呈现空白表单。根据玩家历史行为、当前最高效方案预填 90% 的参数，用户只需确认或微调即可。
- **Input Hints & Inline Validation（输入线索与内联校验）**：
  - 输入框内常驻微弱提示（Prompt），在失焦（Blur）后即刻以平易绿勾或文字进行内联校验，杜绝在点击最后提交时才弹出全屏报错。
- **List Builder（双列表挑选器）**：
  - 左侧为备选池，右侧为已选池，中央提供添加/移除按钮与拖拽能力。解决多对多复杂配置的最直观模式。
- **Autocompletion & Drop-down Chooser（自动补全与智能下拉）**：
  - 键入首字母即刻模糊联想，按匹配度与使用频率排序，支持键盘光标直接选定。

---

### 第 11 章：UI 系统与原子设计 (UI Systems and Atomic Design)

随着前端规模膨胀，界面不再是一张张画纸，而是工业化装配的工程系统。

#### Brad Frost 原子设计理论（Atomic Design）深度解构
```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           Brad Frost 原子设计分层层次                        │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. Atoms (原子)       : 最小不可分割单元 (Button, Input, Icon, Color Token)  │
│ 2. Molecules (分子)   : 原子组合体 (SearchInput = Input + SearchBtn + Icon) │
│ 3. Organisms (有机体) : 复杂功能区块 (FittingSlotPanel, MarketOrderList)    │
│ 4. Templates (模板)   : 页面布局骨架 (TwoPanelLayout, HUDDashboardFrame)     │
│ 5. Pages (页面)       : 注入真实业务数据与状态的最终呈现实例 (MainScreen)    │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 设计系统落地契约
- **Design Tokens（设计令牌）**：
  - 杜绝在 CSS/TSX 中出现散装数值（如 `#1a202c`、`padding: 13px`）。一切颜色、圆角、字阶、间距、发光滤镜统一抽象为语义化 Token（如 `token.color.accent.cyan`、`token.space.md`）。
- **组件解耦契约**：
  - 原子与分子组件必须是纯展示型（Pure Presentational / Dumb Component），严禁耦合业务状态或单例 Store；有机体组件负责连接领域状态机。

---

### 第 12 章：屏幕之后：智能与预测式系统 (Beyond and Behind the Screen)

交互设计的终极边界是打破屏幕作为被动接收器的局限，演进为能洞察用户意图的协同伙伴。

#### 核心理念与前沿范式
- **Anticipatory Systems（预测式系统）**：
  - 系统根据情境（当前挂机时长、电容枯竭速度、历史配船偏好），先于用户提出请求前做好准备（例如：在弹药即将耗尽时，静默预购补给并亮起高置信度的补给建议）。
- **Assistive Systems（智能辅助系统）**：
  - 不剥夺玩家操控权，而是在复杂决策时充当副官（Copilot），提供方案对比与风险推演。
- **Natural Interaction（自然交互体验）**：
  - 将无缝的物理手势、键盘流、语音与意图推断融为一体，消除机器与人类思维之间的阻抗。

---

## 三、《大鲸鱼-深空放置》科幻 HUD 放置游戏工程落地映射

将 Jenifer Tidwell 的交互模式库深度注入《大鲸鱼-深空放置》的前端与游戏逻辑，形成标准化的 HUD 交互规范。

- **Center Stage 绝对权威**：中央星系雷达与战术空间是玩家建立空间记忆的核心。左右面板无论如何展开收折，中央视口的比例与中心点必须保持平滑缩放，禁止跳变。
- **复合屏幕类型映射**：
  - 平时巡检状态为 **Overview（概览型）**。
  - 点击单舰进入 **Focus（聚焦型）**。
  - 打开船坞装配进入 **Make（创作型）**。
  - 点击星门跃迁进入 **Do（任务型）** 闭环。

### 2. 舰船装配与仓库：Two-Panel Selector 与 Dynamic Queries

- **装配车间模式实现**：
  - **左侧（Two-Panel Selector）**：装备仓库清单，集成 **Dynamic Queries**（按高/中/低槽位、能量消耗、衍生品级实时过滤，支持键入过滤），采用 **Tabular Figures** 等宽字体展示 DPS、转速、CPU 占用。
  - **右侧（Focus & Make）**：舰体 2D 骨架槽位拓扑图。
- **即时前馈（Preview）与数据悬浮（Datatips）**：
  - 当鼠标在左侧装备库 Hover 时，右侧对应可用槽位即刻呼吸式微光高亮（指示示能 Affordance）；
  - 舰船状态栏实时呈现**差分预览（Preview）**：例如电容运转时间用绿色呈现 `+1m24s` 或红色呈现 `-45s (电容不足)`；
  - 离开 Hover 即刻复原，无需玩家真实装上武器才能查验结果。

### 3. 长周期放置资产的安全探索与可逆性

- **Safe Exploration 机制**：
  - 放置挂机资产（如累积数周的深空稀金、传奇战舰蓝图）极其珍贵。
  - **非损毁操作零摩擦**：舰体配件的拆装、改装完全可逆，脱卸零损耗、零惩罚。
- **高危不可逆操作的双重互锁（Interlock）**：
  - 严禁单纯使用「确定/取消」弹窗（习惯化会导致脑瘫式点击）。
  - 拆解/销毁传奇舰船：要求**长按 2 秒激活**，或**键入指定确认词（如 SHIP-DESTROY）**；
  - 熔炼装备提供**暂存隔离区（Safety Buffer）**，在退出船坞前允许随时一键「撤销熔炼（Undo）」。

## 四、交互设计模式审查与反模式速查清单

| 交互设计维度 | 良好模式实践 (Good Pattern) | 常见反模式 (Anti-Pattern) | 认知与工程根因 | 改进法则 |
| :--- | :--- | :--- | :--- | :--- |
| **状态呈现** | **Center Stage + Action Panel**：空间位置恒定，主控视区开阔 | **Popup-in-Popup（弹窗套娃）**：多层 Modal 互相覆盖，背景主态彻底失控 | 破坏空间记忆，遮盖上下文，引发迷航焦虑 | 将深层信息收拢为右侧滑出抽屉或双栏选择器 |
| **数值展示** | **Tabular Figures + 差分预览**：等宽字体、动态色值增量提示 | **跳动变宽文本 + 盲选装配**：数字跳动导致布局抖动，装配后才知超载 | 破坏视觉稳定性；增大评估鸿沟与执行阻力 | 必须启用等宽数值；悬浮即时计算前馈 |
| **探索与容错** | **Safe Exploration + Multilevel Undo**：操作可逆，随时复原 | **警报麻木弹窗（Alert Fatigue）**：无论轻重缓急全弹窗，玩家无脑点击「确定」 | 习惯化导致警报失效；恐惧阻碍玩家自主探索 | 区分破坏等级；非破坏性操作无缝撤销，破坏性采用交互互锁 |
| **数据筛选** | **Dynamic Queries + Preattentive Highlighting**：拖动滑块毫秒级重绘 | **Submit to Filter（点击提交查询）**：每次微调都需点击「查询」并转圈等待 | 打破认知流（Flow），无法建立参数与结果的心智映射 | 前端轻量本地索引；过滤条件输入即触发响应 |
| **表单与配置** | **Forgiving Format + Smart Prefills**：兼容缩写，预填历史优选值 | **Strict Regex Error（严苛正则报错）**：输入空格或小写字母即弹出爆红提示 | 增加无效认知负担；将机器的懒惰转嫁给人类 | 宽容解析输入；永远提供高置信度的默认预填 |
| **界面体系** | **Atomic Design + Token 治理**：设计基元严格分层，布局参数全局绑定 | **Snowflake Components（雪花组件）**：每个页面随手写专属 CSS，样式各自为政 | 维护成本指数爆炸；界面视觉割裂，破坏品牌统一性 | 严格按原子/分子分层；严禁散装颜色与随意边距 |
