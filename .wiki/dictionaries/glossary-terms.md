> 知识地图摘要页：权威原文以 Sources 为准。

**结论先行**：`docs/glossary.md` 是现行名称的单一登记处，只收**名称、当前含义和实现入口**，不存调参读数、事故过程或发布沿革；数值一律去当前数据与导出函数取。新术语先登记再进文案，官方命名以**代码与船长口径**为准。

## 一、用途与读法

- 收录边界：只收现行名称、定义和实现入口；不保存调参读数、事故过程、逐问逐答或发布沿革（`docs/glossary.md:3`）。
- **不维护第二份参数表**：数值由当前数据与导出函数决定（`docs/glossary.md:4`）。
- 读法：先按主题找章节 → 按术语名定位该行 → 顺着「当前含义与入口」列跳到对应的代码单点或文档，本页不替代实现。
- 旧记录默认禁读；缺失定义时先补当前词条，不自动打开历史副本（`docs/glossary.md:4`、`docs/glossary.md:192`）。
- 词条可带状态：如「船长2026-10-30确认实施，待验收」（`docs/glossary.md:42-43`）与「2026-11-01船长确认更名，二号已实现待验收合入」（`docs/glossary.md:63`）——**确认≠已上线**。

## 三、代表词条抽样

只是抽样，完整定义回原文对应行。

- 一、领域与流程：`船长`（最终裁定者，`:10`）、`四步闸门`（集中提问→中文设计总结→显式确认→实现登记，`:12`）、`真档/门槛档`（真实进度与合成测试条件不可混用，`:14`）、`随档字段`（写入后还需过读档白名单，`:16`）、`远征`（出击交战与善后返航状态机，`:26`）、`限时倍率表`（带有效时间的 tuning，过期不作永久基准，`:36`）。
- 二、战斗与敌方：`指挥成本/指挥容量`（船型固定占用点 vs 可同时指挥点数预算，`:42`）、`承伤三层`（护盾、装甲、结构；结构是正式名，耐久不是第四层，`:52`）、`动能/爆破/能量`（三系伤害，克制读 `typeLayerMult`，`:54`）、`齐射保护`（玩家实际承伤窗口，单点 `combat/damage.ts`，`:62`）、`伤害类型配色`（动能金、爆破橙、能量青，同源语义色，`:77`）。
- 三、装备、舰船与技能：`CPU、协处理器`（装配预算与减占用，单点 `ships/fitting`，`:83`）、`位数组`（按位置保存槽位布局，清洗不得挤掉空位，`:85`）、`侦察机/战斗机/强击机/轰炸机`（四型无人机，`:92`）、`护卫舰T1…泰坦T5`（敌我共用质量级别；「旗舰」只用于入侵指挥职务或正式名称，`:102`）、`训练许可/工作量/rank`（学习成本与进度，`:107`）。
- 四、工业、经济与打捞：`信用点`（中文单位，英文 credit，内部字段仍 `isk`，`:114`）、`原矿/原材料`（采集物与精炼材料，不能都叫矿物，`:115`）、`数字稀有度/R标签`（唯一表 `RARITY_TIER`，不决定渠道归属，`:123`）、`挂买单预扣`（`PlayerOrder.escrowIsk` 托管，`:129`）、`wreckThreat`（回收采用冻结威胁口径，`:137`）。
- 五、探索、建设与任务：`信号空间/信号谜质`（当前旧探索玩法的正式玩家名；代码兼容标识仍可保留 wormhole，`:145`）、`谜质科技`（消耗谜质与信用点的研究树，`:151`）、`星球地块/危险度/宜居度`（地表建设，不是星系安全等级，`:156`）、`工地现场/建站交付`（未建成工地不等于已建成停靠站，`:158`）、`次数链/链奖金`（长期累计目标与逐级奖励，`:161`）。
- 六、界面术语：`一级页/二级窗口`（一级不滚，内容在内窗完整可达，`:173`）、`旋转逻辑空间`（竖屏横向逻辑尺寸，覆盖层用同轴坐标，`:174`）、`命名色/语义色阶/组件token`（分层色板，不在页面另抄硬编码，`:176`）、`富卡/提示归属`（同元素单机制、内层优先，`:177`）、`音效语义 id`（如 `invasion-alarm`，共用 `SFX_CUES`，一经使用不改名，`:182`）、`音高随机/音分`（1 半音＝100 音分，默认 ±100，`:186`）。

## 四、新术语登记流程

1. **先判现行性**：确认名字指代的是当前实现，而不是旧方案或原型；原型功能明确标状态（`docs/glossary.md:190`）。
2. **核对代码单点**：在词条「入口」列写出真正决定行为的文件或函数，页面读实际接线（`docs/glossary.md:192`）。
3. **按两列写词条**：`术语` ｜ `当前含义与入口`；含义写定性，数值不落表（`docs/glossary.md:4`）。
4. **存疑先问**：定义有歧义或与代码不一致时核对当前代码，仍不确定交船长裁定（`docs/glossary.md:3`）。
5. **同步文案**：新玩家文本先取稳定 id 再写中文；未获英文准备授权只写中文并登记延期（见下节）。
6. **缺了就补**：缺失定义先补当前词条，不打开历史副本补造（`docs/glossary.md:192`）。

## 五、命名权威：代码与船长口径

- 正式名称优先使用当前内容目录；英文只在获得准备授权后查 `docs/glossary-en.md`（`docs/glossary.md:190`）。
- 旧称不作为新文案用语，但**旧原始记录不改写**：`耐久`、`三联读数`、F 族`制式巡逻`及被正式舰名替代的称呼属禁用旧称（`docs/glossary.md:191`）；对应现行名分别为承伤三层之下的「结构」（`:52`）、「编队读数」（`:152`）。
- 名称冲突时以代码为准而非页面文案：同一机制在界面另写规则即为违规口径（`docs/glossary.md:62`、`docs/glossary.md:91`）。
- 同名不同物必须分开：玩家无人机与敌方机型、市场渠道与物品稀有度、基准价与成交价都不共用一套口径（`docs/glossary.md:70`、`:122`、`:126`）。

## 六、中英对照与英文延期

入口关系如下，顺序即权限顺序：

| 环节 | 入口 | 规则 |
|---|---|---|
| 中文词条 | `docs/glossary.md` | 名称与实现入口的现行口径，先登记 |
| 英文对照 | `docs/glossary-en.md` | **只在获得准备英文授权后**查阅（`docs/glossary.md:190`） |
| 延期清单 | `docs/l10n-pending.md` | 未准备英文的玩家文本在此登记待译 |
| 文本实现 | `packages/data/src/l10n/table.ts` | 文案 id 与 `en: ''`、`enDeferred: true` 的落点 |
| 检查 | `npm run l10n:check` 等 | `package.json:116-120`、`package.json:139-141` |

- 未获明确指令时只写中文、`en: ''`、`enDeferred: true`，并登记 `docs/l10n-pending.md`；保留已有英文，不用机翻填充。
- 获准准备英文后再查对照表并跑参数槽检查（`l10n:params`），避免占位符直接显示给玩家。
- 说明：`glossary-en.md` 与 `l10n-pending.md` 不在本批只读范围内，本页只登记入口关系，不引其行号。
