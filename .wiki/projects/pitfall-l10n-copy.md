# 本地化与文案：踩坑与经验

> 本页是 docs 提炼的经验记录，**非现行规则**；与 `AGENTS.md`、`docs/development-conventions.md` 或代码冲突时，以现行文件与代码为准。归档来源已标「历史」，其中读数是当时快照。

## 结论先行

- 带 `{pN}` 的模板一旦接到「不喂参数」的渲染点，缺键不会报错，而是把占位符原样印给玩家——这是本地化最贵的静默失败。
- 静态工具只覆盖它「看得见」的形态：`l10n:params` 只扫 `tr('字面量')`，映射表的值、对象直插、拼接派生、变量展开都能绕过去；工具全绿不等于玩家看到的是一句完整的话。
- 切语言不刷新，多半是模块加载时取词被存成常量；重载后恢复英文会制造「实时切换通过」的假象，必须同页热切复测。
- 延期登记清零只证明**已登记**翻译完整，不证明派生文案、模块缓存、运行期参数都本地化；静态读数与实机扫描各管一段，不能互相代替。
- 玩家文案最常混进的是两类东西：内部键名（「族」字三义）和开发侧残留（日期/裁定/路线图编号/「口径」）——词表与闸门只能兜住无歧义项，语境分工要人工判。
- 通讯与公告的坑集中在「整篇 vs 单条」和「段数对齐」：单条改文不读上下文会语境断裂，英文按段数对齐，改段数就让整段回落中文。
- 既有英文不等于正确英文：延期期间旧英文可能仍在描述已废弃规则；新增文案应取新 id，别改写旧英文。
- 术语表存在 ≠ 本次已授权翻译：`glossary-en.md` 是权威译名表，授权边界仍是船长明确启动英文准备。

## 一、取词机制与参数契约

### 坑 1.1 带参模板接上不喂参的渲染点，`{pN}` 直接漏给玩家

- **现象**：通讯主题行显示「{p1} ×{p2}」；插件日志显示「已为 X 装上插件：{p2}。」——玩家直接读到占位符。
- **根因**：`interpolate()` 找不到键就原样保留 `{pN}`（静默失败）；`COMMS_SUBJECT_ID['msg-blackbox-plug-unlock']` 错挂奖励清单模板 `ui.comms.072`，而 `commsSubjectText()` 只做 `tr(l10nId)` 不喂参；`packages/core/src/plugs.ts:155` 调 `addLog(..., 'core.plug.001', { p1 })` 只喂 p1，模板要 p1/p2 两槽。
- **解法 / 规避**：通讯主题新增 `ui.comms.079`；`core.plug.001` 补喂 p2、正文只留船名；把两条判据转正进 `npm run l10n:params`——A「映射表的值指向带参模板」、B「`addLog/logEvent` 的 id 与参数静态对账」。
- **复发检查点**：`npm run l10n:params`；新增映射表/主题表时核对目标模板是否含 `{pN}`、渲染点是否喂参；展开语法与变量传参工具会保守跳过，需夹具人工核。
- **来源**：`docs/design/comms-param-fix-20261001.md:14`、`:19-23`（`COMMS_SUBJECT_ID` 错挂与工具盲区）、`:27-30`（插件日志漏 p2）、`:36-41`（231 文件/4,875 条普查，历史读数）、`:49-51`、`:71`（判据转正）。

### 坑 1.2 模板硬槽没传空串、对象直插、内层参数缺失

- **现象**：玩家看到 `{p1}`；附注槽译文里的内层占位符没被替换；停靠日志把返回对象直接塞进模板。
- **根因**：`dockUnloadNote` 返回对象时正文没读 `.text`；使用槽译文时没同时提供 `p2p1/p3p1` 这类内层参数；模板硬槽「即使无内容」也必须传空串，缺键和拼好的分隔符会直接泄露。
- **解法 / 规避**：正文读对象字段再入模板；槽译文连同内层参数一起给；列表参数传 `p{n}List` 逐项值及可选 `ItemId/ItemParams`，分隔符由渲染层按语言取；core 用 `logParams/logParamsOf`，空列表用槽 id。
- **复发检查点**：`npm run l10n:render`（改 `composeParts`/`paramsFor` 必跑）；人工搜 `addLog/logEvent` 调用点的对象实参与嵌套槽；新模板上线前用中英各渲染一遍看有无 `{`。
- **来源**：`docs/design/copy-audit-20260930.md:7`（`dockUnloadNote` 与 `p2p1/p3p1`，两项护栏建议当时未实施）；`docs/development-conventions.md:106`（§十一之三 参数契约）、`:107`（`l10n:render`）。

### 坑 1.3 模块加载时就取词，热切语言不刷新

- **现象**：设置里点 English 后主界面切换，但星图页签、舰船页签/筛选、装配伤害标签、日志过滤标签仍是中文；重载后这些标签恢复英文。
- **根因**：`pages/MapPage.tsx` 的 `MAP_TABS`、`panels/StarMap.tsx` 的 `LABEL_MODES`、`pages/ShipPage.tsx` 的 `SHIP_TABS`、`ui/shipInfo.tsx` 的 `DMG_LABEL`、`panels/appSettings.tsx` 的 `KIND_LABEL/KIND_DESC` 在模块加载时调用 `tr` 存成常量；页签类重载后恢复⇒是模块级缓存而非译文表缺失。
- **解法 / 规避**：改为渲染期取词/按语言依赖；不能用「重载后恢复英文」宣称实时切换通过，重载只用于区分缓存与真实漏译。
- **复发检查点**：`rg -n "^(const|let)\s+\w+\s*=\s*(tr|t)\(" apps/desktop/src/renderer/src` 抽查模块级取词；实机在英文下逐页热切（不重载）再重载对比；回归项「模块加载后中英往返取词、禁止模块变量提前取词」。
- **来源**：`docs/design/l10n-settings-native-audit-20261018.md:45-51`（缓存清单与「不建议用重载绕过」）、`:74`（新增回归）、`:75`（真实点设置 English、不用 API 替代）。

### 坑 1.4 跳过 id 直接渲染中文，或派生文案没走 id

- **现象**：英文界面仍见成就 81 条卡名、舰船子类 `def.subClass`、实验室 fuel 分类、工业/打捞说明参数与数量单位、运输母港名、`aria-label`「稀有度R1」、设置背景名、公共日志空态「（暂无事件，航线静悄悄）」。
- **根因**：core 返回裸中文、界面直接渲染数据字段、字符串在别处先拼好；不是译文表缺条，而是这条文案根本没走 id，静态检查自然看不见。
- **解法 / 规避**：照 `CommandResult` 先例（`engine.ts:63` 注释）——`error` 中文原串永远照写，另加 `errorId`+`errorParams`，返回类型保持 string；返回 `string|null` 的闸门改结构化 `CoreBlockReason`，渲染层统一走 `cmdText(r)`；测试断言改成断 id 与参数，不再靠中文子串。
- **复发检查点**：`npm run l10n:core-zh`；`rg -n "addLog|logEvent" packages/core/src` 看第二参；实机扫描后把残留逐项归类为「缓存/未走 id/未翻译」，不按页面数夸大成多项根因。
- **来源**：`docs/design/l10n-core-zh-20260927.md:41-48`（改造形状）、`:58`（`CoreBlockReason`）、`:64-75`（落点与断言改法）；`docs/design/l10n-settings-native-audit-20261018.md:53-64`（重载后仍漏清单）、`:66`（公共日志空态只算一项）。

## 二、文案审核：玩家语域与开发残留

### 坑 2.1 内部键名被当成玩家词汇（「族」字三义）

- **现象**：界面出现「武器族加成」「本族武器单发 +12%」「采矿舰族专精」「航运族舰船」等玩家从没定义过的词；「族」在敌方势力语境里又确实是玩家熟悉的词。
- **根因**：A `ShipDef.weaponFamilyBonus` 的键=伤害类型（kinetic/explosive/plasma），B `ShipRole`=己方舰船类别（采矿舰/武装舰/装甲舰/货运舰），两者把内部键名直接印给玩家，而「族」已被 C 类敌方势力占用。
- **解法 / 规避**：A/B 去掉「族」正字（伤害类型/舰船类别），C 保留；第二批按船长令统一为「势力」，但只动玩家可见文案，字段名/代码注释/内部 id 一律不动；改动处留 `⟪文案调整 2026-09-24⟫`（共 15 处）；「色族」「与协会同族不同行」属物种义，有意保留。
- **复发检查点**：改词前先查词典与代码字段的三层含义，别只按字面替换；`npm run l10n:list` 复扫未接线字面量；闸门会抓 id 形态（`ui.shipInfo.008b`→`ui.shipInfo.184`）与重复键（TS1117）。
- **来源**：`docs/design/copy-jargon-20260924.md:8-14`（三类含义与误导根因）、`:32`（15 处记号）、`:37`（只动玩家可见文案）、`:49-50`（有意保留）、`:56-57`（闸门抓错记录）。

### 坑 2.2 开发侧残留混进玩家可见文案

- **现象**：文案出现「（2026-09-17 船长定）」「自 2026-09-15 起」「开发路线图 B3.1」；通讯初稿写「最后一条保命的口径」，被体检当场拦下。
- **根因**：开发讨论与裁定过程顺手写进表文；「口径」「待定」「复核」在开发语境正常，玩家看不懂；公告也容易混入验收/校准话术。
- **解法 / 规避**：按 §十三 玩家文案纯净清单清理；按报障/裁定改过的文案留 `⟪文案调整 YYYY-MM-DD⟫` 与工作文档台账；`content:check` 新增「开发侧残留契约」，只收无歧义判据（`YYYY-MM-DD`、船长定/令/裁、待定/待裁决/占位/复核/验收/TODO/WIP），并故意不判三处——游戏内「船长」、`ui.perf.*` 调试件、`ui.Expedition.*` 的「本批」（订单批次）。页面常驻说明行的旧原则是「情境+一句引导」、机制细节归手册（历史材料）。
- **复发检查点**：`npm run content:check`（改前 4 处红、落地后 0 处）；护栏只兜无歧义项，语境仍需人工审；新写公告禁开发话术。
- **来源**：`docs/design/copy-audit-20260930.md:125-136`（日期类真问题）、`:140-143`（开发侧残留处理）、`:163-173`（契约判据与三处不判）、`:198-204`（路线图编号 B3.1）；`docs/design/comms-20260911.md:520-529`（「口径」被体检拦下）；`docs/archive/retired-docs-20261029/copy-cleanup-pending.md`（**历史档案**：页面说明行只留情境+引导）。

### 坑 2.3 旧称、旧名混进新文案

- **现象**：样稿写「演习场讨伐令」，官方现名已是「演习场驱逐令」；同一条通讯主题写旧族名「鱿烬亡军」、正文却写「鱿鱼亡军」；补英译时可能沿用 family/crest 旧词。
- **根因**：改名批次只改正文或只改一处，主题/标题/旧工作文档稿没一起改；旧称在词典里已标「历史旧称不得混入玩家可见文案」。
- **解法 / 规避**：命名冲突按§5.2 停下请船长裁；旧称只留历史语境；`msg-wh-siege` 中文已正字「势力徽记」，英文应用 faction crest 而非 family crest。
- **复发检查点**：改名批次同时搜主题表与正文表；对新稿 grep 旧称；引用 `glossary-en.md` 时看行内 `⟪文案调整⟫` 日期，不抄旧行。
- **来源**：`docs/design/comms-20260911.md:375-379`（讨伐令→驱逐令裁决）；`docs/design/comms-import-20261001.md:61`（主题旧族名应为漏改）；`docs/design/copy-jargon-20260924.md:41`（family crest→faction crest）、`:63`（`msg-wh-siege` 勿用旧词）。

### 坑 2.4 审核假阳性：控制台截断与拼接片段

- **现象**：控制台里看到「）」缺开括号，一度当成硬伤；探针复核发现括号配平——是 PowerShell 把长行截断。把「标点配对」判据加进 `content:check` 后，11 处报红里 10 处是正常片段。
- **根因**：界面文案大量由两三条 id 在调用点拼成一句，单条看当然不配平；终端显示会截断长行，不能当证据。
- **解法 / 规避**：报障/记账前一律用 `read` 读原文或写探针复核，不信控制台截断显示；标点配对判据留在审核工具（带长片段豁免），`content:check` 只留无歧义判据。
- **复发检查点**：任何「硬伤」先回原文核对；对拼接调用点禁用单条字面量判据；审核工具输出要写清「片段豁免」理由。
- **来源**：`docs/design/copy-audit-20260930.md:233-249`（拼接片段与豁免）、`:262-267`（PowerShell 截断造成的假象）。

## 三、通讯与公告：整篇语境与段数契约

### 坑 3.1 单条改文不读整篇，语境断裂或重复

- **现象**：站点通讯 v2 被船长判作废（孤立推销广告）；并网致谢与并网通报同刻触发、开头同款、内容重复；`first-wormhole` 与 `msg-wormhole-unlock` 都在讲声望够了可解锁；被袭篇与低安细则讲两遍。
- **根因**：按条审、按条写，没读同一篇前后条；`copy:audit` 语料按条长排序会把同一篇拆散，看起来像互不相关的单条。
- **解法 / 规避**：`whale-copy` 规程新增「先读整篇，再写这一句」；整篇复核另起探针按行序读；同刻触发的两封合并或分工；v1/v2 作废，v3 才接住上文、用推销口气讲作用/价值/获取图鉴。
- **复发检查点**：写/改任一条前读完同篇所有条与触发时机；用按行序的整篇探针复核；公告类同时核「同一机制是否已有一篇在讲」。
- **来源**：`docs/design/copy-audit-20260930.md:310-322`（v1/v2 作废与 v3 主稿）、`:364`（规程回写「先读整篇」）、`:375-392`（E19–E21 三处重复）。

### 坑 3.2 强调段落与正文不逐字一致，高亮静默失效

- **现象**：`highlight` 指向的段落不在 `body` 里时界面不高亮，运行期也不报错（只有 `content:check` 报「界面不会高亮」）。
- **根因**：`CommsMessageDef.highlight` 必须与 `body` 段落逐字相等才生效；手写两份文本必然漂移。
- **解法 / 规避**：数据侧把任务链七行抽成同源 `BRIEFING_CHAIN`，`lines` 与 `highlight` 同源；`content:check` 新增「强调行契约」（`highlight` 非空、不含空段、每条都必须是 `body` 里的一段，故意写错实测会报）；core 用例守 `commsInbox` 透传（未写 `highlight` 必须 `undefined`，避免误高亮第一段）。
- **复发检查点**：`npm run content:check`；改 `body` 后同批更新 `highlight`；不要为了「突出重点」破坏正文结构。
- **来源**：`docs/design/comms-20260911.md:421-430`。

### 坑 3.3 通讯登记/触发判据读错数据源，误发与静默重复

- **现象**：教程刚过就收到「敌情通报：鱿烬亡军的蜂群」，而口径应是扫描出该星系才发；同一星系两封同触发面；导出工具里的触发时机族名出现内部代号。
- **根因**：`wormholeFoes.ts` 五张 `wh-*` 卡一律 `hidden: true` 且 `galaxyId` 写死 `'galaxy-hub'`（开局即在 `exploredGalaxies`），`anomalies.ts` 把卡摊进 `ANOMALIES` 让 `foeFamily` 判定从第 0 帧起恒真；同级消费方（`lairs.ts`、`salvage.ts` 等）都跳过 `hidden === true`，只通讯这一处漏。
- **解法 / 规避**：`foeFamily` 判定加 `if (anomaly.hidden === true) continue`（只认星图可见卡）；登记契约「四封必须都在 + 四个触发面互不相同」+死触发器守卫；导出工具触发判据逐条照 `commsTriggerMet`，族名走单点 `weekendFamilyNameZh()`（未知族「未知势力」），查不到名字回落原文 id。
- **复发检查点**：`npm run content:check`（通讯登记契约）；新增通讯逐条核触发面；导出工具不自己发明触发条件。
- **来源**：`docs/design/comms-20260911.md:518-521`（登记契约与负向验证）、`:531-562`（隐藏卡污染与改法）；`docs/design/comms-export-20261001.md:36-39`（族代号、触发判据口径）。

### 坑 3.4 已发布公告不回改，「公告是当时的记录」

- **现象**：早期公告只有 1~2 条要点（现行契约 3~5 条）、数值与现状不一致（如「满级合计可达 160%」与现行 165%），审核时想统一改掉。
- **根因**：公告是当时的玩家向记录，回改等于改写历史；3~5 条与第三人称契约都是后来才立的口径。
- **解法 / 规避**：立明文口径「历史公告不回改」——只允许清开发残留、改排版/错别字，不改机制陈述与数值；新公告第三人称「玩家」、3~5 条要点。
- **复发检查点**：审公告先分「历史记录 / 待发稿」；对已发布正文的机制陈述改动须船长精确授权本篇本次；条数/人称以 §十二 为准。
- **来源**：`docs/design/copy-audit-20260930.md:64-69`（早期公告越界只建议不改）、`:203`（E6 只报不改）、`:295`（立为明文口径）；`docs/development-conventions.md` §十二（现行公告规则）。

## 四、英文延期与覆盖验收

### 坑 4.1 延期台账的「状态」列语义漂移，易被读成英文已完成

- **现象**：同一节正文写「未授权准备英文」、两项均 `en: ''`/`enDeferred: true`，表格状态列却写「已本地化」；全文件「已本地化」146 处、「待本地化」197 处并存。
- **根因**：状态列没有单一口径，混用了「中文已入表」与「英文已翻译」两种含义；正文与表格由不同批次写就，没人回头统一。
- **解法 / 规避**：台账状态列应显式写「中文已落地·英文延期」这类单一口径；判断覆盖以 `en`/`enDeferred` 字段为准，不以状态词为准；延期清零不等于全游戏无遗漏。
- **复发检查点**：读 `l10n-pending` 逐条看 `en` 字段；`rg -n "已本地化|待本地化" docs/l10n-pending.md` 只作线索；汇报区分「已登记」与「已覆盖」。
- **来源**：`docs/l10n-pending.md:427-435`（射程确认提示节正文与表格矛盾）；`docs/design/l10n-settings-native-audit-20261018.md:31`（「全部本地化完成」汇报不准确）、`:93`（不用延期清零证明无遗漏）。

### 坑 4.2 静态读数全绿 ≠ 玩家看不到中文

- **现象**：`l10n:check` 报 6,639 条全部有引用、0 重复/未解析/参数不匹配（历史读数），实机切英文仍查出 81 处；另一轮 6,563 条 0 待译 0 延期（历史读数），全仓仍报 15 条渲染层中文源码字面量与 169 条 `l10n-keep`。
- **根因**：静态工具只认表内 id 与可解析引用；模块缓存、派生字符串、拼接、未走 id 的字段、无 id 数据都不在读数范围。15 条/169 条多数是冻结键、回退、调试探针与本地化实现内部文本，按规则保留，但不能当玩家覆盖证明。
- **解法 / 规避**：静态读数 + 实机扫描 + 逐项归因三步；实机用真实语言操作（点设置 English）而非测试 API；隐藏窗口抓帧先预抓帧+双动画帧等待，避免抓到上一页。
- **复发检查点**：收口跑 `npm run l10n:check`/`l10n:params` + 英文实机巡检；报告把「闸门读数」与「实机结果」分开写；失败轮的巡检报告不得当作通过证据。
- **来源**：`docs/design/l10n-settings-native-audit-20261018.md:17`（首轮 81 处与复查）、`:31`、`:73`（6,639 条读数与 15 条字面量）、`:75`（81 处/实机操作）；`docs/design/l10n-en-release-20261018.md:43`、`:47`（6,563 条与 169 条 `l10n-keep`）。

### 坑 4.3 既有英文可能描述已废弃规则；新文案取新 id 别改写旧英文

- **现象**：`core.consumable.009/.010` 旧英文仍写「必须已探索/非高安/没有副站」等已作废限制；新增加速剂/预警若改写旧英文，会破坏既有覆盖与逐字保护。
- **根因**：延期期间中文规则先改、英文表滞后；旧英文不会随机制自动失效；随手改写旧英文又与「保留已有英文」冲突。
- **解法 / 规避**：审英文时按当前机制逐条核对，废弃限制要改；新增文案用新 id + `en: ''`/`enDeferred: true` 登记，旧 id/英文逐字保留（本批 9 个新 id 与台账成对）；术语以 `glossary-en.md` 冻结表为准（已上线「信号空间」= `Signal Space`，未来玩法才用 `Wormhole`）。
- **复发检查点**：改英文前查该 id 是否已发布；新增条目与 `l10n-pending` 成对；补英译前查 `glossary-en.md` 对应行（含 `⟪文案调整⟫` 与 ⚠ 待裁定标记）。
- **来源**：`docs/design/l10n-en-release-20261018.md:17`（术语分流）、`:29`（旧英文描述废弃限制）；`docs/design/boost-copy-ammo-warning-20261009.md:20`（新 id 避开改写旧英文）、`:26`、`:31`、`:43`（旧 id/英文逐字保留、9 个新 id 成对）。

### 坑 4.4 术语表存在 ≠ 本次已授权翻译

- **现象**：`glossary-en.md` 已有大量译名（甚至有 800 多行），容易被当成「可以顺手补英文」；早期英文里「信号空间」与「虫洞」曾混用 `Signal Space`/`Wormhole`。
- **根因**：词表是术语权威表，不是翻译授权；授权边界是「只有船长明确启动英文准备后才按表出稿」，未启动只能登记延期、保留已有英文。
- **解法 / 规避**：未授权时写 `en: ''`/`enDeferred: true` 并登记 `l10n-pending`；启动后才按 `glossary-en.md` 出稿、清延期标记；两个词按最新 `⟪文案调整 2026-10-06⟫` 分流，标 ⚠ 的行须船长裁定。
- **复发检查点**：动手补英文前确认授权批次；grep 旧英文中 `Wormhole` 是否误指已上线信号空间；不因「词表里有」就自动起译全仓。
- **来源**：`docs/glossary-en.md:3-7`（状态与授权边界）、`:43-44`、`:76-78`（Signal Space/Wormhole 分流）；`docs/design/l10n-en-release-20261018.md:17`。
