> 知识地图摘要页：权威原文以 Sources 为准。

## 用途

给接手本仓库的开发者或 AI 一张执行地图：哪些改动需要先停下确认、一次能落多大范围、在哪个工作树提交、交付时怎么汇报。规则原文以 `AGENTS.md` 与 `docs/development-conventions.md` 为准，本页只做导航，不复制全文。

本页不覆盖两块：检查命令与提交审批见 [[verification-and-commit]]；文档阅读、生成与归档见 [[docs-system]]。

## 结论先行

- **默认直接实现**：需求明确、改动可逆、同一功能域内的，先做再汇报，不逐项等确认。
- **只有后果大或不可逆才等确认**：新大功能或玩法、存档结构、数值经济体系、跨域改动、玩家公告、范围模糊、高返工代价；且一轮问完（集中提问 ≤3 问 → 中文设计总结 → 船长一次点头 → 开工）。
- **只本地提交**：自测、船长验收、公告审核都完成后才推送。
- **汇报固定格式**：首行「报告老大喵」，四要素齐全（改了什么文件、行为怎么变、怎么验证、留了什么取舍）；小修与明确指令可三行内。
- **子代理按需**：默认主代理直接施工；只有并行收益大于编排开销时才派工，产物由主代理复核。
- **留痕按规模**：大功能、跨域、待裁决建 `docs/design/` 工作文档；小修与明确指令不建，写进汇报与提交信息。

## 开工顺序

| 步骤 | 做什么 | 依据 |
|---|---|---|
| 1 | 读 `AGENTS.md` 执行入口 | AGENTS §0 |
| 2 | 读 `docs/catalog.md` 按任务选文档 | 目录 §工作入口 |
| 3 | 涉及设计、数值、UI/UX、架构或历史决策时先查 `.wiki` 知识库 | AGENTS §5.4 |
| 4 | 按任务读相关规则与设计稿 | 目录 §按任务查阅 |
| 5 | 查代码现状，核实文档是否仍适用 | AGENTS §0；正文 §二 |

首次接手或大工程要通读约定正文；续接会话若已丢失规则上下文，重新读入口与目录，不凭记忆开工。

## 确认闸门（风险分档，原四步闸门）

默认不走确认：需求明确、改动可逆且落在同一功能域内的，直接实现并在汇报里交代。

| 项目 | 要求 |
|---|---|
| 触发条件 | 新大功能或玩法；存档结构变化；数值、经济体系调整；跨域改动；玩家可见公告；需求或范围确实模糊；高返工代价的操作 |
| 确认做法 | 一轮问完：集中列关键问题（≤3 个）→ 中文设计总结（方案、取舍、模块、数值、边界、增删清单）→ 船长一次点头 → 开工 |
| 已确认方案执行 | 按正文第一章推进，不重复确认；要推翻已确认设计才重新确认 |
| 不算确认 | 沉默、「随便」「你看着办」「都行」、跳过提问 |

**典型误判**：把小修和明确指令也拖进确认流程；把「先做一版看看」当成范围授权；把旧文档里的方案当成已批准；把批量需求中可直接执行的部分擅自扩成新取舍。

## 模块内优先与跨域申请

| 情形 | 规则 |
|---|---|
| 功能域划分 | 模块按功能域；同域的 core 与界面算同一个模块 |
| 一次工作 | 只落一个域；跨域先向船长申请 |
| 跨域留痕 | 提交说明与工作文档写批准依据 |
| 动手前 | 先找域内同类子模块，沿用其结构；没有对照项才新设计并写明理由 |
| 共享底层/文档 | 不算跨域，但修改理由必须属于本批，不顺手改别处 |
| 交付自报 | 功能域、同类参照、是否跨域；`scope:check` 只提示文件范围，不替代人工批准 |
| 超大文件 | 生产单文件超过 800 行先给拆分方案，获准后才改 |

## 工作树与合入纪律

| 角色/动作 | 规则 |
|---|---|
| 主树（main） | 由一号与船长维护，是已合入规则的权威入口 |
| 附属树 | 二号 `Deepseek-EVE-d2`、三号 `Deepseek-EVE-verify`、零号 `Deepseek-EVE-zero`；实际分支开工时用 Git 核对 |
| 实现与提交 | 在所属附属树完成，不直接写主树 |
| 合入顺序 | 自测 → 同步 main → 解冲突 → 主树干净且核验通过才合入 → 附属树追平 main |
| 推送 | 开发期间只本地提交；自测、验收、公告审核完成后代码与公告同批推送 |
| 文档 | 附属树读主树 docs，不另维护一套规则；被指定改文档时先在指定树检查提交再合入 |
| 重叠改动 | 停写相关区域，报告证据与影响，等协调；不回滚、不抢修他人 WIP |

编码与落盘：历史文件让 Git 直接物化；批量写显式 UTF-8、绝对路径、写前校验，保持原 BOM/行尾，合入后核对乱码与应保留内容。

> 文档缺口：`docs/development-conventions.md:29` 把主树路径写死为 `H:\大鲸鱼\Deepseek-EVE`，与当前实际工作区路径可能不一致；工作树归属与分支一律以 Git 现场核对为准，不凭文档路径推定。

## 汇报格式

每次汇报固定结构：

1. 首行「报告老大喵」。
2. 结论先行。
3. 修改文件清单。
4. 行为变化。
5. 验证结果（命令与结果；桌面外壳、真档取证、性能与几何结论注明验证目标与工具）。
6. 已知取舍；自家违规写明规则与修正。

小修与明确指令的改动可三行内汇报；涉及验收、发布、跨域或未决事项时按上述完整口径。

玩家报障按玩家提供的复现条件、代码与确定性用例核查，不拿船长真档代替；结论写复现路径、根因位置、玩家现象与改法。

## 检索纪律与子代理分工（按需）

- 文档检索默认 `rg --glob '*.md' --glob '!**/archive/**' <关键词> docs`，在读取前排除旧记录。
- 超过 500 行的文件禁止全文盲读；用 Serena 的符号概览、查引用、查定义定位后再精准读写。
- 设计、数值、UI/UX、架构或历史决策类问题，先查 `.wiki` 知识库（`wiki_query`/`wiki_drill`/`wiki_read`，边界见 AGENTS §5.4）。
- 子代理不再强制：默认主代理直接施工；只有并行收益大于编排成本（独立并行任务、跨多文件且写入不重叠、独立只读取证与审查）时才派工，派工写明 Serena 实例前缀与写入范围。
- 子代理负责局部施工，主代理负责验证、终审 diff 与最终质量；子代理同样遵守真档只读与同域优先，不得绕过主代理发布或推送。

## 常见操作与边界

| 想做的事 | 正确入口 |
|---|---|
| 新功能/改数值，但范围没批准 | 先走确认闸门；后果大或不可逆才需要，否则直接做并汇报 |
| 要改另一个功能域 | 先申请，并在提交与工作文档留批准依据 |
| 发现文档与代码不一致 | 核实现行实现并记录差异，不自行解禁历史文档 |
| 想顺手清理别的模块 | 停手；共享文件也只能服务本批 |
| 看到他人未提交改动 | 停写、报告、等协调 |
| 临时探针 | 一次性的删除，可复用的转 `tools/` 正式入库；只处置自己的 |
| 新提议与旧规则冲突 | 停下冲突部分，列原话、出处、后果、选项与推荐，请船长裁决 |

## 维护边界

本页是知识地图，不承载具体命令清单、审批参数或检查矩阵；这些随工具变化较快，统一由 [[verification-and-commit]] 维护。文档目录、生成索引与归档规则由 [[docs-system]] 维护。
