# 工业与经济：踩坑与经验

> 本页是 docs 提炼的经验记录，非现行规则；与 AGENTS、docs 现行正文或代码冲突时，以它们为准。

## 结论先行
- 工业三线（精炼炉 / 组装机 / 实验室）是**三份平行实现**，不是一套共用逻辑；新增或改造产线要先按 15 项关注点逐项对照（投料时机、取料来源、自停、封顶、退料、离线统计、技能、调试、存档……），漏一项就是玩家可见 BUG。
- 主控占用有五处口径（`MainActivityKind`、`mainActivityOf`、`AUTO_HALT_KINDS`/`WARN_KINDS`、停机 case、活动栏/忙态），手抄漏一处就会出现"门禁认它、界面看不见"或"另一扇门仍能双占"；现行由登记表派生 ＋ `arch:guard` F8 兜底。
- 同一件商品有"基准价"和"行情价"两个价源；改价必须两处同改并重跑全链体检，否则面板净收益与数值平衡会长期对不上。
- 改价从来不是改一个数：燃料行价 → 判据阈值 `4000 × 单价` → 四活动重判 → 零件占比、公告、工具里写死的旧读数一起漂移。
- 面板读数必须走 core 导出单点，且只显示本产线真吃到的技能；卡面自算配方规格值会造成"起线记录、封顶判据、净收益"三套口径。
- 黑市/货架类修复的边界是"旧货架只隐藏、不补抽"：不删除、不重抽、已售罄不恢复，否则会改写已成交资产与随机守恒。
- 运输的"停止"要区分折返中/停运/返港/接续；提示沿用"即时到港"会让玩家以为没停下；在途不允许改承运量。
- 声望修复的历史教训：不要自造没有船长原话的"合理"口径；一次性补偿必须带删除前提与检索口令；削账只降不升、只对不达标档动手。

## 1. 主控活动与手动工作位
### 坑：实验室产线没进主控活动登记表，主控被"双占"
- **现象**：实验室产线在跑时，采矿 / 打捞 / 远征 / 长途运输 / 建站交付仍能同时开工，主控出现两个活动。
- **根因**：`startLabRun` 借用 `'refine'` 档（起线侧通），但 `MainActivityKind` 没有 `'lab'`、`mainActivityOf` 不读 `state.labRuns`（占用侧不通）；`state.ts` 的停机表有 `'lab'`、`activity.ts` 没有——同一件事三处口径不一致。结构性来源是 `MainActivityKind` ＋ `AUTO_HALT_KINDS` ＋ `WARN_KINDS` ＋ `INTERRUPTIBLE` 四张手抄表，新活动要改四处。
- **解法 / 规避**：立"登记表"（kind / detect / 显示名 / 分档 / 停机函数），四张表全部派生；`'lab'` 作为一行登记、走"先警告再切"档；`arch:guard` 新增 F8 契约护栏（`start*` 入口必须过门禁、档位必须能被探测、可中断的必须有停机 case）。
- **复发检查点**：新增任何"占主控"的活动后跑 `npm run arch:guard`（F8 应为 0 处）；补登记表后跑实验室与活动矩阵用例。
- **来源**：`docs/design/activity-gate-registry-20261001.md:42`、`:56-63`、`:68-79`、`:173-229`

### 坑：新工业 HUD 页三颗开工键没有手动位守卫，主控可被无限打断
- **现象**：主控空闲时点哪条产线都能开工，且每点一次就再切一次；手上那条被停、当前那一批进度直接丢弃。
- **根因**：新 HUD 页（`IndustryHudPage.tsx`）精炼/组装/实验室三处主控键的禁用判据只有 `have <= 0` / `!learned` / `lockTip`，缺"手动工作位被占"这一档；旧工业页本来有（`manualNote` / `manualBuildNote`）。旧页的实验室卡也只查野外/返航。
- **解法 / 规避**：core 新增单点 `manualSlotOf(state)`（三线共用的 1 个手动名额，AI 核心驱动不算、`active:false` 不算），三键据此置灰并给置灰理由；**不要拿 `mainActivityOf` 当这把尺**（它有优先级，旧档双占时会答错）。
- **复发检查点**：`rg -n "manualSlotOf" packages/core/src`；新工业页三键 `disabled` 是否都带 `manualNote`；旧页实验室卡与野外/返航两格仍未补齐（已知缺口，属下一批）。
- **来源**：`docs/design/industry-manual-slot-guard-20261001.md:16-22`、`:30-33`、`:50-55`、`:69-73`

### 坑：门禁/活动栏/忙态不同源，进洞那一刻的自动停线漏了实验室
- **现象**：实验线在跑时主控照样能进虫洞（经另一扇门的双占）；进洞时实验线不会自动停。
- **根因**：`wormhole.ts` 的 `shipActivityBusy` 与 `ENTRY_STOP_META` 原先两处都漏 `lab`；活动栏、`lab.ts` 停机日志（固定写"已自动停止『亲自开炉』"）、确认弹窗 `key`（起炉/起线共用一个 `'refine'`，警告窗口内点"起线"被当成二击直接执行）也各自漂移。
- **解法 / 规避**：忙态、活动行、门禁判据三处同源（`shipBusyLabel` / `activityOverview` / `mainActivityOf`）；活动行取数走 `labRunViews` 单点；停止文案走 `activityStopLabel` 单点；起线确认 `key` 改 `'lab'`。
- **复发检查点**：`rg -n "ENTRY_STOP_META|shipActivityBusy|activityStopLabel" packages/core/src`；跑进洞活动锁矩阵与 `activity-lab-20261001` 用例。
- **来源**：`docs/design/activity-gate-registry-20261001.md:131`、`:135-139`、`:141`、`:157`

## 2. 三条产线的口径分叉
### 坑：三份平行实现各漏各的，玩家报的"材料占用"是取料来源分叉
- **现象**：玩家反馈"实验室的生产是不是没和其他工业用同一套逻辑"，并再次报早已修过的材料占用类 BUG。
- **根因**：全仓是 `industry.ts`（炉子）/ `manufacturing.ts`（组装机）/ `lab.ts`（实验室）三份实现；改前实验室跟炉子族，而两条既有线本身也不统一——炉子/实验室"货仓优先 → 仓库"，制造线"只吃物品仓库"。玩家说的"占用"最可能就是船上货仓的料被优先吃掉；旧口径的"炉内预占账 `claimedUnits`"实验室根本没有。
- **解法 / 规避**：船长裁定"默认族 = 组装机型"（一条线一批 · 开工整批扣料 · 只吃仓库 · 完成即结束 · 循环开关 · 停机退料）；实验室改为组装机同构，炉子族取料仍是"货仓优先"（按裁定属例外族，维持）。
- **复发检查点**：新增/改造产线时按 15 项关注点列对照表，每项给两处以上 `文件:行` 锚点；核对 `oreAvailable` / `countWare` / `labMaterialAvailable` 三种取料口径。
- **来源**：`docs/design/industry-line-parity-20261001.md:15-19`、`:26-27`、`:41-47`、`:121-126`

### 坑：组装机循环续做不扣料，第二件起是"白造"
- **现象**：循环线续做的那几件不扣料（玩家手上只有「通用黑匣」这类等价组材料时），产物照出。
- **根因**：`advanceManufacturing` 续做分支直接 `removeWare(state, need.itemId, …)`——不查等价组、不写 `spentMaterials`、忽略返回值；而开工那一处走等价组 ＋ 记账，同一张卡两条路两种口径。探针实测：开工后通用 4，第 1 件完成续做后仍 4（第 2 件白造），取消后退到 5。
- **解法 / 规避**：两条路都收成 `spendMaterialsFor`（等价组按组序取够 ＋ 逐笔记实际扣的那种 ＋ 凑不齐整体回滚并停线）；退料账语义钉成"只记在跑那一件"。
- **复发检查点**：`npm run test -w @whale/core -- manufacturing-loop-materials-20261001`（3 条，改前必红）；新增"续做/循环"分支时搜 `removeWare(` 是否绕过记账。
- **来源**：`docs/design/industry-line-parity-20261001.md:64-75`

### 坑：新产线漏掉旁路（调试加速、离线统计、停靠拒因），修好主线仍不全
- **现象**：炉子没有"调试 1 秒化"，实验室完全不参与离线结算统计，炉子停靠拒因在英文界面漏中文。
- **根因**：这些旁路是每条线各自接的，没有"新产线必接清单"；普查发现 `debugQuick` 全仓 20 处触点里 `industry.ts` 零处，`advanceLab` 当时也没传 `settleStats`。
- **解法 / 规避**：本批把 `debugQuick` 三处补进炉子、`advanceLab(…, stats)` ＋ `labBatches` 补进离线统计；拒因 `errorId` 的炉子存量登记为待收（丁项），不假装已清零。
- **复发检查点**：`git grep -n "state.debugQuick" -- packages/core/src` 三条线是否都有触点；`rg -n "settleStats" packages/core/src`；`npm run l10n:check` 查裸中文。
- **来源**：`docs/design/industry-line-parity-20261001.md:32-34`、`:39`、`:90-92`、`:123`

### 坑：卡面读数自己算，起线记录/封顶/净收益三套口径；技能作用域也归类错
- **现象**：实验室卡按配方规格值显示"每批工期 5 分钟"和"产出倍率 X%"，收率技能效果在卡面完全看不见；曾把精炼族的 `refineRate` 当"通用技能"报给实验室。
- **根因**：`labBatchUnitsOf` / `labCycleMsOf` 未导出，卡面自读 `recipe.outputUnits` / `recipe.cycleMs`；技能作用域没查清——`refineRate` 只在 `industry.ts` 读，是精炼炉专属；跨机器通用的只有 `industrial-automation`（产线节拍学）。
- **解法 / 规避**：两个读数函数改导出，卡面/起线与净收益都读同一单点；删掉假读数（产出倍率、配方规格工期）；口径写进约定「卡片只允许显示本产线真吃到的读数，此类读数一律走 core 导出单点」。
- **复发检查点**：`rg -n "labBatchUnitsOf|labCycleMsOf" packages/core/src apps/desktop`；跑 `fuel-cap-lab-skills-20260930`（无技能 600/满级 780、工期 5 分→3 分且起线同数）。
- **来源**：`docs/design/industry-line-parity-20261001.md:193-217`、`:222-238`

## 3. 精炼与价格：一物一价与全链体检
### 坑：同一件商品两个价源从没同步，平衡设计从未在面板生效
- **现象**：船长报"虚空母矿精炼虚空晶为什么是亏损"——面板算出 −73,375（−56%），按基准价算的设计平衡却是 +10,125/批。
- **根因**：2026-09-15 的令只改了 `items.ts` 基准价（1,800 → 3,600），`marketCatalog.ts` 行情价一直是 1,800；精炼面板 `marginPctOf` 两侧都取**当前行情价** ⇒ 那次平衡从未在面板生效。随后母矿被排除体积平衡、行情价从 915 拉回 1,300，料价再涨到 130,000。
- **解法 / 规避**：一物一价——行情价与基准价同改到 5,400（按母矿 1,300 口径反算平衡点 4,735，留约 13% 余量）；补一条「精炼面板口径必须净额为正」用例钉住口径。
- **复发检查点**：`rg -n "min-voidcrystal" packages/data/src/items.ts packages/data/src/marketCatalog.ts` 两处必须同值；`npm run content:check` 看蓝图价格口径警告数是否新增。
- **来源**：`docs/design/voidcrystal-price-20261001.md:8-29`

### 坑：改一个价格，全链都要跟着体检（燃料链转负、配方比价翻转、零件占比漂移）
- **现象**：虚空晶价一改，两条燃料配方料价从 240,940 → 348,940（行价 420 时 −28%）；"新配方比旧配方更贵"的船长口径被翻过来；专属装备/舰船零件体系的 45/30/25 占比漂成 42.3/27.4/27.7。
- **根因**：价格是跨系统的输入——燃料配方、T5 配方比较、零件料价锚（`parts.test.ts` 三条绝对料价锚）、蓝图价格警告、已发公告里写死的行价都读同一批数；改价时没有"全链影响清单"。
- **解法 / 规避**：按船长令把燃料行价抬到 5,800（自产成本 = 行价 ×10% 口径），T5 的"更贵"落在非虚空晶料（226,000 vs 24,940，9.06×）而不是总料价；零件锚与占比下界按现状放宽并注明待裁；公告数值另行裁定。
- **复发检查点**：改任一原料价后重算 `npm run balance`、`npm run content:check`、`parts` 专项；逐项列出"燃料配方 / T5 / 零件 / 蓝图 / 公告 / 手册"影响面。
- **来源**：`docs/design/voidcrystal-price-20261001.md:31-43`、`:51-63`

### 坑：燃料提价后，所有"值不值得烧"的判据与散落旧读数一起过期
- **现象**：虚空晶 ×10、罐容 6,000 → 60,000、行价 120 → 420 之后，判据阈值从 310,267 变成 1,606,267 ISK/时，采矿增益从"翻倍级"回落到 +17%~+33%；`tools/mining-curve.ts` 里写死的旧料价 77.57 落后一版。
- **根因**：判据是 `4000 × 单价` 的派生值，散落在工具与文档里；一边改数一边留旧读数，就会出现"工具算的"和"引擎算的"两套。已写进代码但**未推送**的公告也不是"历史公告"，发布前必须对齐。
- **解法 / 规避**：工具改为现算（读 `LAB_RECIPES` ＋ `ctx.items`，市场价读 `marketCatalog`）；公告与待审稿两处逐字同步并打 `⟪文案调整⟫` 标记；四条活动（采矿/悬赏远征/打捞/AI 副船）按新自产价重判。
- **复发检查点**：`rg -n "77\.57|46_540|4000 \*" tools docs packages` 搜写死旧值；`npm run balance`；改罐容/配方上限时同步检查"恰好装满/满仓"用例的存量（59,400/59,700）。
- **来源**：`docs/design/fuel-cost-cap-20260930.md:19`、`:29-35`、`:44-46`、`:48-72`、`:93-95`

### 坑：精炼卡"收益不正确"其实是毛/净口径错位，不是结算没扣料
- **现象**：船长反馈"精炼炉收益不正确，好像并未扣除材料成本"；查证引擎每批已实扣料，问题只在工业页精炼卡的 ≈ISK/h 按矿物毛产值算、没扣被炼资源价值。
- **根因**：卡面估算口径与结算口径不是同一个：结算扣料，展示只算产出。另外历史锚（本页所属的旧设计稿已自标"立稿留档"）里的倍率/技能加成已被后续改动覆盖（现行公式以代码与术语权威为准），引用旧数字必然踩空。
- **解法 / 规避**：卡面改净口径 `(Σ floor(批×perOre×倍率)×矿物收价 − 批×原料收价) × 3_600_000 ÷ 周期`，标「（净）」、负值警示色并写"净亏：直接卖原料更划算"，tooltip 给毛产值与"不随市场、未计成交税"；`content-check` 加配平护栏（零技能 产值/耗料 ∈ [0.98, 1.08]）。
- **复发检查点**：`npm run content:check`（配平护栏）；任何卡面 ≈ISK/h 改动先问"扣料了吗、按哪个价、含不含税"；引用历史精炼数值前先核对 `balance.ts` 与 `docs/glossary.md`。
- **来源**：`docs/archive/retired-docs-20261029/refine-balance-50.md:1-7`、`:10-14`、`:58-63`（历史档案）

## 4. 市场与黑市
### 坑：黑市按"感觉"而非真实类型排除原料，出现"单个矿石销售"
- **现象**：黑市货架上出现星幽矿 ×1、售价 4,495 信用点，真实购买扣款、仓库 +1、商品售罄——不是显示错误。
- **根因**：`blackMarketCandidateGoods` 未排除大宗原料；`blackMarketLotQuantity` 只给无人机 50 架，其余默认 1 件。两道缺口叠加：类型判据缺失 ＋ 成组数量只覆盖一个品类。
- **解法 / 规避**：按物品目录的**真实类型**排除原矿/原材料/气体/冰矿（不按名称或货号前缀猜）；既有购买入口复用候选检查，直接购买旧原料返回原有拒因、不扣款不发奖。
- **复发检查点**：`npm run test -w @whale/core -- black-market-bulk-resource-20261013`（含 600 组种子/日期抽签）；新增黑市品类时查"候选类型判据 ＋ 成组数量"两处。
- **来源**：`docs/design/black-market-bulk-resource-fix-20261013.md:9-12`、`:15-20`、`:24-27`

### 坑：修货架不能"补抽"——旧条目只隐藏、不重抽
- **现象**：若把旧货架里的原料条目删掉重抽，会改动已成交资产、售罄状态与当日随机结果。
- **根因**：货架是"每天生成一次"的既有记录，修复只能约束**新生成**；对旧数据的任何重抽都是事后改写玩家资产与随机守恒。
- **解法 / 规避**：旧货架的原料条目不删除、不重新抽签，只隐藏并拒绝购买；已售罄不恢复，其他商品原顺序/数量/价格保持，次日正常生成新货架；不补抽、不补发、不追改已买到的矿石与钱包。
- **复发检查点**：`rg -n "blackMarketLotQuantity|blackMarketCandidateGoods" packages/core/src`；读档往返 + 同日/回拨不重抽用例。
- **来源**：`docs/design/black-market-bulk-resource-fix-20261013.md:15-20`、`:33-37`

### 坑：市场池量按"感觉"定，和玩家产能脱节——采了卖不掉、炼了也卖不掉
- **现象**：17 个矿带里 15 个覆盖比 < 1，气/冰类只有 0.02~0.05×；矿物侧冥铁合金 0.16×、星髓晶 0.24×；flow 梯度失控到 833× 差距（6 ~ 5,000/窗），收入被池子锁死。
- **根因**：池量是 2026-09 早期按"越稀有越小"的直觉定的，从未与玩家产能（掘洞级＋满技能＋2×MK1；矿物侧＝主控精炼炉满技能）对齐。
- **解法 / 规避**：按单价分层定覆盖比（≤20 ISK ×15 / ≤200 ×6 / ≤400 ×3 / >400 ×2），`supplyFlow = round(基准日产×覆盖比÷1440)`、`poolTarget = flow×120`；把"玩家产能 vs 池吸收"做成正式工具 `npm run liquidity:audit`，改后复跑要求建议值 = 现值（倍率 1.0×）。
- **复发检查点**：`npm run liquidity:audit` 幂等；改池后连带检查任务需求量（`round(poolTarget × 1%~3%)`）与快递体积上限。
- **来源**：`docs/design/market-pool-liquidity-20260910.md:8-19`、`:21-34`、`:71-84`、`:113-115`

### 坑：市场三份大文件拆分，靠"等价性证据"而不是"看起来一样"
- **现象**：拆 core 市场引擎/数据目录/渲染页时，任何一处字面差异都可能悄悄改掉价格、税、结算顺序或订单生命周期。
- **根因**：市场是"函数正文不动、只搬位置"的重构，风险集中在私有跨文件依赖、公开旧 API、随机消费顺序；仅靠 review 看不出等价性。
- **解法 / 规避**：固定种子交易轨迹对照（4 种子 × 普通/铁人 = 8 条轨迹、872 个检查点逐次核对完整状态与命令结果）；135 个声明语法正文等价、616 条商品字段/顺序与 570 条源码绑定一致；旧入口只留具名兼容出口、公开 API 集合保持；一次性搬迁探针核验后删除。沙箱内 CLI 子进程因 tsx 系统用户信息限制启动失败 → 沙箱外重跑，**不许改断言规避失败**。
- **复发检查点**：拆域后跑 `npm run test -w @whale/core` 市场专项 ＋ 8 条轨迹对照 ＋ 桌面合成档交易 IPC 保存重载；比对字段/主键顺序与绑定条数。
- **来源**：`docs/design/market-domain-folders-20261030.md:10-17`、`:21-22`、`:28-32`、`:33-34`

## 5. 运输与离线
### 坑：停止长途运输"停不下来"——显示与入口沿用错模板，还允许在途改货量
- **现象**：船长报"停止长途运输后，不会停下；运输途中不应该可以调整承运量"。停止后成功提示仍沿用"即时到港"，活动栏与动画仍显示正常运输、允许重复停止。
- **根因**：停止链路本身能折返（合成回归已验证跨三段中断真实折返、到站只计当前段、交战停止即使获胜也不续运），但**文案与视图**没复用折返/战斗暂停；卡片还留着在途调整入口与弹窗分支。
- **解法 / 规避**：停止成功提示复用折返/战斗暂停文案；折返和战后停运已挂账时不重复显示停止操作；按船长裁定移除卡片在途调整入口、弹窗调整分支与引擎 `setHaulingLoadNow`——出发前设置货量，停运靠站后重新开始才能改。
- **复发检查点**：`rg -n "setHaulingLoadNow" apps/desktop packages` 应为 0；跑运输停止/运输作业/运输预览/工业遭遇 4 文件专项；桌面隐藏 Electron 实测"途中无调货按钮、二次确认后折返、到港退出运输"。
- **来源**：`docs/design/hauling-stop-lock-20261101.md:9-12`、`:22-25`

### 坑：取证脚本在自动保存前读旧快照，把"没跑到"误判成"功能失败"；没复现别宣称根因
- **现象**：停止运输的隐藏 Electron 脚本首轮被判失败，实际是脚本在 60 秒自动保存前读取了旧快照；另外"到港后继续自动运输"在独立合成条件下未复现。
- **根因**：验收脚本与正式保存周期对不齐（时序问题不是功能问题）；未复现的玩家报告容易被当成"已找到根因"写进结论。
- **解法 / 规避**：按正式保存周期修正等待，**不改保存机制**来迁就脚本；报告如实写"已证实的缺陷是折返阶段显示/提示仍像运输中；若复测仍有继续接单，需要具体按钮入口/是否二次确认/停止时是否交战/是否已等到返港"，不据此声称所有停止问题均已找到根因。
- **复发检查点**：取证脚本先确认"正式自动保存周期与读取时点"；结论区分"已复现/未复现/已证实缺陷"三档；隐藏 Electron 用例必须独立临时 userData、只关自建 PID。
- **来源**：`docs/design/hauling-stop-lock-20261101.md:23`、`:25`

### 坑：离线简报没有运输遇袭汇总，最后一场战报会被后续战斗覆盖
- **现象**：玩家离线回来只有总收支和少量日志摘要；若离线期间运输遇袭，看不出"遇袭几场、胜负、损失、补给、交付与停运原因"。
- **根因**：离线走正式 `simulateOffline → advanceGame`（按航段边界/事件时点/战斗步长交替推进，遇袭真实模拟、战斗期间暂停运输计时，不是离线免战或重新抽签），但简报只按总量汇总，没有按事件归集，最后一场战报还会被后续战斗覆盖。
- **解法 / 规避**：拟增加遇袭/胜负/损失/补给/运输交付与停运原因摘要——**先交船长确认再新增**，本批不擅自动离线战斗、计酬或真实折返规则。
- **复发检查点**：`rg -n "simulateOffline|advanceGame" packages/core/src`；新增离线事件类型时逐类核对简报有无对应汇总（运输遇袭是当前已知缺口）。
- **来源**：`docs/design/hauling-stop-lock-20261101.md:16`、`:18`、`:26`

## 6. 赏金与声望
### 坑：三档保底"名存实亡"——代码早取消，注释与界面还在声称有保底
- **现象**：实现按"取消保底后的逻辑"写，界面与部分注释仍声称每日赏金三档各派一条；船长按"最低级不给声望、每种难度至少刷一条"重新确认时，恢复工作要连注释与用例一起改。
- **根因**：规则取消时只改了实现，没同步注释/界面/旧用例，形成"代码说没有、文案说有"的双口径。
- **解法 / 规避**：恢复真实保底（0/1/2 点档位声望：一档 0、二档 1、三档 2；首胜另算），先匹配三档再填剩余席位、候选不足不造地图不跨区；同步注释与界面；已生成任务板不重刷、新规则下次换板生效；未完成任务按已锁定难度发新奖励、不追补已完成任务。
- **复发检查点**：`npx tsx tools/bounty-standing-check.ts`（真实地图、每档 200 种子）；`npm run test -w @whale/core -- bounty` 保底/候选不足/分区/同星系多卡/确定性用例。
- **来源**：`docs/design/bounty-standing-20261030.md:43-48`、`:56-58`、`:60`

### 坑：自造"合理"的声望口径，把玩家 6 点声望变成 41 点（历史）
- **现象**：玩家反馈"更新后原本 6 声望突然变成 41 声望"；数据链是 6 →（读档回填 `max(40, 旧可支配)`）→ 40 →（累计门槛 40 达标）→ 入侵被触发 → 贡献声望 +1 → 41。
- **根因**：两处口径都没有船长原话——新档初始 40 写成"能买 5 张"、老档回填补 40 下界写成"别让老玩家比新玩家少一档门槛"；而且无条件"累计 > H 就削到 H"会把**合法的**入侵贡献声望每次读档削一遍（自查时抓到的自家 bug）。
- **解法 / 规避**：新档两条账从空表起步（`INITIAL_STANDING = 0`）、老档只搬可支配那本不补下界；修复只降不升、只对"按悬赏进度本来就不达标"的档动手（`H < 40`），达标档一字不动；`standingClawbackDone` 只生效一次（无论有没有真削到）。
- **复发检查点**：`rg -n "STANDING_CLAWBACK_THRESHOLD|repairStandingFromBountyProgress|standingClawbackDone" packages` 应已随补偿退役删除（2026-10-27 令）；保留的长期口径用例（新档初始 0 / 老档只搬可支配）仍在。
- **来源**：`docs/archive/retired-docs-20261029/standing-clawback-blackbox-20260926.md:27-31`、`:41-54`、`:65-77`（历史档案；现行边界见 `docs/architecture.md` 与 `weekend-invasion.md`）

### 坑：一次性补偿必须可删——删除前提、检索口令与"长期口径别跟着删"
- **现象**：读档修复/补发类一次性补偿留在代码里，日后规则变化会被再次执行，成为新的错误来源。
- **根因**：补偿的本意是"存量只处理一轮"，但代码不会自己过期；混在正常读档链里就永远有机会重跑。
- **解法 / 规避**：代码埋同名横幅，检索口令 `git grep 明日删除` 一次列全；删除前提写清（削减已在正式档生效过一轮、该补发的档都补过）；区分"长期口径"（新档初始声望 0、老档回填只搬可支配）不跟着删；标记随档保存、缺省不落键 ⇒ 零迁移。
- **复发检查点**：`git grep 明日删除` 应为 0；`rg -n "compensateMissingWeekendBlackBox|hasAnyBlackBox|hasAnyPlug" packages` 应为 0；测试档生成器里依赖"初始赠送 40"的 26 处已改显式 `bumpStanding`。
- **来源**：`docs/archive/retired-docs-20261029/standing-clawback-blackbox-20260926.md:79-92`、`:94-117`（历史档案）

### 坑：调声望门槛只该动被裁定的那几处，双账净值口径最易写错
- **现象**：自然入侵与信号发射器共用累计门槛 80 → 60 时，很容易顺手把信号空间扫描 40、黑市 100、矿带（2~13）/悬赏卡（1~13）/市场商品（4~40）各自的门槛一起"统一"掉；高安点火扣 10 与结束固定奖 10 的可支配净值也容易算成 +20 或 0。
- **根因**：声望门槛不是一条，而是各内容自己的累计门槛；兑换与点火同时动"可支配/累计"两本账，净值口径一错就会凭空造声望。
- **解法 / 规避**：只改裁定的两处（自然入侵、发射器，均为 60，同判据）；信号空间扫描 40、黑市 100 与各内容门槛不动；高安召唤扣 10、结束固定奖 10 ⇒ 可支配净零、累计仍 +10；已有场次不取消、未结算按新奖励、已结算不追补、既有图纸/黑匣不回收。
- **复发检查点**：`npm run test -w @whale/core` 门槛 59/60 边界、余额零、高安 9/10 与结算净值、旧已结算不追补用例；`node tools/standing-economy-native-check.cjs`（59/60 × 经典/现代 × 桌面/手机共 8 组）。
- **来源**：`docs/design/bounty-standing-20261030.md:10-16`、`:22-31`、`:35`
