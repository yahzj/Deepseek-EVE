> 知识地图核心概念页：本页系统梳理唐·诺曼（Don Norman）以人为本设计（Human-Centered Design, HCD）与认知工程心理学的核心交互模型，确立人机界面的基本认知规律与容错设计底线。

## 结论先行

- **HCD 核心哲学**：技术应当适应人的认知、生理与情感需求，而不是强迫人类迁就机器或算法的机械逻辑；人犯错不是人的缺陷，而是**糟糕设计的必然产物**。
- **两大核心问题**：任何交互界面必须回答两个基本问题——**可发现性**（Discoverability：能做什么、在哪操作）与**可理解性**（Understanding：这意味着什么、系统现在处于何种状态）。
- **行动循环与鸿沟**：人类与外界交互由「七阶段行动模型」驱动；设计者的核心职责是弥合**执行鸿沟**（不知道怎么让系统做事）与**评估鸿沟**（不知道系统到底变成了什么状态）。
- **交互六大基石**：可发现性、示能（Affordance）、意符（Signifier）、映射（Mapping）、反馈（Feedback）、概念模型（Conceptual Model）。
- **差错二分与防错**：行动偏差分为**失误（Slips）**（目标正确但执行变形，潜意识主导）与**错误（Mistakes）**（目标或规则本身选错，意识层主导）；禁止依赖单薄麻木的「确定/取消」确认弹窗，必须优先使用**强制功能（Forcing Functions）**、**可逆撤销（Undo）**与**合理性检查（Sensibility Checks）**。

## 一、以人为本设计的本质与两大挑战

以人为本设计（Human-Centered Design, HCD）是一种将人类的需求、能力、行为习惯与心理模型置于首位的设计哲学与实践方法。

```
┌────────────────────────────────────────────────────────┐
│                   以人为本设计 (HCD)                   │
├───────────────────────────┬────────────────────────────┤
│ 1. 认知心理契约           │ 2. 物理与生理限制          │
│ - 顺应人类短时记忆与注意力 │ - 触达距离、肌肉疲劳       │
│ - 尊重长期习惯与心智模型   │ - 视觉识别度、听觉通道负荷 │
└─────────────┬─────────────┴─────────────┬──────────────┘
              │                           │
              ▼                           ▼
┌───────────────────────────┐ ┌──────────────────────────┐
│ 可发现性 (Discoverability)│ │ 可理解性 (Understanding) │
│ 「我能做什么？怎么做？」   │ │ 「这代表什么？结果如何？」│
└───────────────────────────┘ └──────────────────────────┘
```

1. **可发现性（Discoverability）**：用户能否直观发现哪些动作是可能的、当前可以在何处采取行动。
2. **可理解性（Understanding）**：用户能否理解控制项的作用方式、系统内部运行的逻辑，以及所有控制、指示、反馈所表达的真实含义。

技术的悖论（Paradox of Technology）：技术赋予产品更强大的功能与更低的单位成本，但功能密度的增加必然导致控制复杂度急剧膨胀。若无卓越的 HCD 介入，技术进步往往换来更沉重的认知负担。

## 二、日常行动心理学：执行与评估两大鸿沟

用户在与任何系统交互时，大脑与物理系统之间始终存在两道天然鸿沟：

```
                    ┌─────────────────────────┐
                    │      用户的心理目标     │
                    └───────────┬─────────────┘
                                │
          ┌─────────────────────┴─────────────────────┐
          ▼                                           ▼
┌──────────────────┐                         ┌──────────────────┐
│  执行鸿沟 (Gulf) │                         │  评估鸿沟 (Gulf) │
│ 用户设法跨越：   │                         │ 用户设法跨越：   │
│ - 我能做什么？   │                         │ - 发生了什么？   │
│ - 怎样操作？     │                         │ - 系统现在怎样？ │
│ - 怎么把意图转化为│                         │ - 目标达成了吗？ │
│   系统支持的操作？│                         │ - 我该如何解读？ │
└─────────┬────────┘                         └────────▲─────────┘
          │ (依靠：前馈、意符、映射、约束)             │ (依靠：反馈、概念模型、系统表象)
          ▼                                           │
┌─────────────────────────────────────────────────────┴─────────┐
│                    物理系统 / 数字界面状态                     │
└───────────────────────────────────────────────────────────────┘
```

### 1. 执行鸿沟（Gulf of Execution）
- **定义**：用户从「想达成什么」到「如何在系统中把这个目标执行出来」之间的认知落差。
- **化解途径**：依赖清晰的**前馈（Feedforward）**机制——包括显眼的意符、符合直觉的自然映射、直观的物理/逻辑约束以及良好的概念模型。

### 2. 评估鸿沟（Gulf of Evaluation）
- **定义**：用户完成操作后，到「看懂系统状态变化、确认自身目标是否达成」之间的理解阻抗。
- **化解途径**：依赖高质量的**反馈（Feedback）**机制——包括即时响应、无歧义的视觉/音频信号、状态指示器以及易于解读的系统表象。

## 三、行动的七个阶段（Seven Stages of Action）

唐·诺曼将人的完整行动闭环拆解为 7 个连续的心理阶段，形成驱动行为的完整认知循环：

```
                    ┌────────────────────────┐
                    │       1. 目标 (Goal)   │
                    │   形成想要达成的状态   │
                    └───────┬────────▲───────┘
                            │        │
         ┌──────────────────┘        └──────────────────┐
         │ 执行桥梁 (Execution)           评估桥梁 (Evaluation)│
         ▼                                              │
┌─────────────────┐                            ┌─────────────────┐
│ 2. 计划 (Plan)  │                            │ 7. 对比 (Compare)│
│ 确定行动方案    │                            │ 比较现状与目标  │
└────────┬────────┘                            └────────▲────────┘
         ▼                                              │
┌─────────────────┐                            ┌─────────────────┐
│ 3. 明确 (Specify│                            │ 6. 解释 (Inter- │
│ 明确具体动作序列│                            │    pret) 解读状态│
└────────┬────────┘                            └────────▲────────┘
         ▼                                              │
┌─────────────────┐                            ┌─────────────────┐
│ 4. 执行 (Perform│                            │ 5. 感知 (Perce- │
│ 作用于界面/物理 │                            │    ive) 接收反馈│
└────────┬────────┘                            └────────▲────────┘
         │                                              │
         └──────────────► 物理/虚拟世界 ◄───────────────┘
```

### 1. 目标（Goal）
- **核心问题**：我想达成什么状态？（例如：「调整舰船电容输出，支撑高耗能中槽护盾回冲」）。

### 2. 执行三阶段（前向通路）
- **计划（Plan）**：在可选的策略中做出选择（例如：「通过超频电容回充器还是关掉次要武器？」）。
- **明确（Specify）**：将高层策略转化为具体的交互控制动作（例如：「找到电容模块面板，点击超频按钮」）。
- **执行（Perform）**：实施肌肉运动或按键操作（例如：「鼠标悬停在图标上，左键单击」）。

### 3. 评估三阶段（逆向反馈通路）
- **感知（Perceive）**：感官接收外部系统的反馈信号（例如：「看到按钮边框变红发光、听到高频充能音效」）。
- **解释（Interpret）**：结合上下文赋予感知信号以意义（例如：「这代表超频模式已成功激活」）。
- **对比（Compare）**：将解释后的系统状态与初始目标进行对照（例如：「电容恢复速度从 45GJ/s 上升到 82GJ/s，护盾回冲已稳定，目标达成」）。

### 4. 驱动模式
- **目标驱动（Goal-driven / Top-down）**：由内在意图发起，自上而下经过计划执行，再自下而上进行评估。
- **事件驱动（Event-driven / Bottom-up）**：由外部突发刺激发起（如警报、闪烁、电量告警），先经过评估阶段的感知与解释，再触发新的防御或应对目标。

## 四、交互设计的六大基本原则

六大原则构成了支撑 HCD 落地、消除两大鸿沟的工程框架：

```
┌────────────────────────────────────────────────────────┐
│                   交互设计的六大基本原则               │
├────────────────────────────────────────────────────────┤
│  1. 可发现性 (Discoverability) — 让所有可能操作一目了然 │
│  2. 示能 (Affordances)       — 物理/数字层面的可交互潜力│
│  3. 意符 (Signifiers)        — 指明在何处、如何操作    │
│  4. 映射 (Mappings)          — 控制器与物理/逻辑的对应 │
│  5. 反馈 (Feedback)          — 即时、适度、有意义的结果│
│  6. 概念模型 (Conceptual)    — 传达清晰、一致的系统表象 │
└────────────────────────────────────────────────────────┘
```

### 1. 可发现性（Discoverability）
- 用户能否在不查阅说明书或盲目乱试的情况下，看到界面中哪些地方能够交互。
- 隐藏的手势交互、无提示的悬停触发和缺少视觉线索的盲区，都是破坏可发现性的典型反模式。

### 2. 示能（Affordance）
- **本质**：物体与行动主体（人或智能体）之间的**基本关系与交互可能性**，由物体的物理特性与行动主体的生理能力共同决定。
- **特性**：示能是客观存在的，无论是否被观察到（例如：椅子天然具有支持人坐下的示能；屏幕玻璃具有被触摸的示能）。
- **数字界面局限**：在纯平面玻璃/屏幕上，真实的物理示能仅有「触摸、滑动、点击」，屏幕上的按钮并不具备物理维度的按压示能。

### 3. 意符（Signifier）
- **本质**：任何向用户发出明确信号、告知「这里存在某种示能、应该如何使用」的物理或感知标记。
- **设计优先级**：**在人机交互与界面设计中，意符的重要性远高于示能**。
- **反面教材（诺曼门 Norman Door）**：一扇需要「拉」才能开的玻璃门，却安装了扁平的推板；或者一扇需要「推」的门，却装了拉手。错误的意符导致用户本能做出相反动作并归咎于自身笨拙。

### 4. 映射（Mapping）
- **本质**：控制器与其所控制的对象、动作及其引发的状态改变之间的空间与逻辑对应关系。
- **自然映射（Natural Mapping）**：
  - **空间一致**：左边控制项对应左侧设备，横向滑块对应横向移动。
  - **隐喻一致**：音量旋钮顺时针旋转表示调大，垂直推杆向上表示增加。
  - **文化感知**：颜色心理学、阅读方向等文化习惯（例如：红色代表警告/停止，绿色代表安全/通过；但需注意跨文化差异与色盲无障碍友好）。

### 5. 反馈（Feedback）
- **即时性**：延迟大于 100ms 会让人感觉到卡顿，大于 1s 会引发用户的质疑并诱发重复误点。
- **信息丰富度适度**：过度无节制的反馈会导致**警报疲劳（Alert Fatigue）**，用户最终会将其无视或关闭。
- **多感官通道融合**：关键操作结合视觉（高亮/形变）、听觉（提示音效）与触觉（触感震动）。

### 6. 概念模型（Conceptual Models）与系统表象（System Image）

```
┌──────────────────┐               ┌──────────────────┐
│   设计师模型     │               │    用户模型      │
│  (Design Model)  │               │   (User Model)   │
└────────┬─────────┘               └────────▲─────────┘
         │                                  │
         │  设计师只能通过系统表象说话       │ 用户只能从系统表象学习
         ▼                                  │
      ┌────────────────────────────────────────┐
      │         系统表象 (System Image)        │
      │  UI界面、交互反馈、物理外形、文字文档  │
      └────────────────────────────────────────┘
```

- **设计师模型**：工程师与设计团队关于系统底层如何运作、数据如何流转的真实心智模型。
- **用户模型**：用户通过使用产品、观察表象而在脑海中构建出的心智推测模型。
- **系统表象**：产品的实际呈现物。**设计师无法向每个用户面对面解释原理，用户只能通过系统表象建立理解**。若系统表象充满歧义或隐瞒关键机制，用户必然构建出歪曲的虚假心智模型。

## 五、人类认知的三个处理层次

唐·诺曼将大脑处理外界刺激与决策的认知机制分为三个层级，分别对应不同的设计考量：

| 层次 | 大脑机制 | 时间尺度 | 驱动要素 | 核心体验与评估指标 | 设计对应点 |
|---|---|---|---|---|---|
| **本能层 (Visceral)** | 生物本能、潜意识反射 | 毫秒级 (极快) | 外观、声音、物理触感、比例 | 好看、悦目、震撼、反感、恐惧（纯直觉） | 视觉美学、色彩搭配、排版质感、材质光泽、音效打击感 |
| **行为层 (Behavioral)** | 熟练技巧、潜意识控制 | 秒级 (即时) | 功能性、易用性、执行阻力、控制感 | 流畅、掌控、得心应手、挫败、迟钝（操作感） | 符合人体工程、快捷键效率、低阻力反馈、自然映射 |
| **反思层 (Reflective)** | 意识思考、逻辑评估、长期记忆 | 分钟至年级 (深层) | 自我意象、文化价值、故事认同 | 骄傲、满足、值得、有格调、自豪感（价值感） | 品牌声誉、成就系统、仪式感、意义感、个性化定制 |

1. **本能层设计**：决定了「第一眼印象」。在这个层级，美感与吸引力先入为主，高质量的本能层能提升用户对后续轻微可用性缺陷的容忍度。
2. **行为层设计**：决定了「用起来爽不爽」。讲求无缝的可用性与掌控感，交互应该行云流水，尽量不打断用户的专注心流。
3. **反思层设计**：决定了「用户事后如何回忆与评价」。反思层能够改写记忆（即使过程中有波折，只要终局或成就感足够辉煌，反思层仍会给出极高评价）。

## 六、差错心理学：失误与错误分类及防错体系

**根本公理**：人类并非冷冰冰的数字处理器，人的注意力和工作记忆极其脆弱。将事故归咎于「人为疏忽」（Human Error）是极不负责的伪解释。**差错本质是系统设计与人类生理认知局限发生碰撞时的应激破裂**。

```
                                ┌─────────────────────────┐
                                │       人为差错分类      │
                                └────────────┬────────────┘
                                             │
                   ┌─────────────────────────┴─────────────────────────┐
                   ▼                                                   ▼
       ┌───────────────────────┐                           ┌───────────────────────┐
       │      失误 (Slips)     │                           │     错误 (Mistakes)   │
       │ 目标正确，执行过程变形│                           │ 目标或规则本身制定错误│
       │ (潜意识/熟练行为主导) │                           │ (意识层/逻辑推理主导) │
       └───────────┬───────────┘                           └───────────┬───────────┘
                   │                                                   │
  ┌────────────────┼────────────────┐                 ┌────────────────┼────────────────┐
  ▼                ▼                ▼                 ▼                ▼                ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ 动作/捕获失误│ │ 描述相似失误 │ │ 模式失误     │  │ 基于规则错误 │ │ 基于知识错误 │ │ 记忆失效错误 │
│ Capture Slip │ │ Description  │ │ Mode-error   │  │ Rule-based   │ │ Knowledge-   │ │ Memory-lapse │
└──────────────┘ └──────────────┘ └──────────────┘  └──────────────┘ └──────────────┘ └──────────────┘
```

### 1. 差错的两大根本分类

#### A. 失误（Slips）：潜意识执行阶段的偏差
用户意图和目标完全正确，但在转化为具体动作序列时发生了执行走形。常发生在熟练、无意识的操作中：
1. **捕获失误（Capture Slips）**：想要执行的新动作与一个高频惯常动作拥有相同前奏，大脑自动驾驶被更强的惯性动作「捕获」（如：打算在星图打开探索雷达，习惯性按下了跳跃按键）。
2. **描述相似失误（Description-similarity Slips）**：动作本身正确，但作用在了与目标极其相似的错误对象上（如：将珍贵的金色图纸拖入了旁边长相相近的分解炉槽位中）。
3. **模式错误（Mode-error Slips）**：系统处于某一特定模式，但用户以为处于另一模式，导致相同操作产生完全违背预期的结果（如：大写锁定状态输密码；VI编辑器的插入与命令模式）。
4. **记忆失效失误（Memory-lapse Slips）**：在执行多步连续动作时受到微小打断，导致遗忘了中间某一步（如：插卡取款后拿了现金却忘了拔走银行卡）。

#### B. 错误（Mistakes）：意识决策与目标阶段的偏差
动作完全精准地执行了，但最初形成的目标或推导依据本身就是错误的。发生在意识分析层面：
1. **基于规则的错误（Rule-based Mistakes）**：错误诊断了当前局势，调用了不适用的预设规则；或者规则本身存在设计缺陷。
2. **基于知识的错误（Knowledge-based Mistakes）**：面对陌生的异常局势，由于缺乏充分知识或心智模型严重失真，做出了错误的逻辑推理。
3. **记忆失效错误（Memory-lapse Mistakes）**：在形成规划阶段遗漏了关键前提或约束条件。

### 2. 防错与容错工程体系

#### A. 约束（Constraints）的四种维度
通过限制可能采取的操作范围，阻断错误路径：
- **物理约束（Physical Constraints）**：物理世界的空间尺寸阻隔（如 USB 接口的防呆防反插；异形钥匙与锁孔）。
- **文化约束（Cultural Constraints）**：长期形成的社会约定俗成（如：红灯停绿灯行；关闭按钮通常位于右上角）。
- **语义约束（Semantic Constraints）**：依赖对情境含义与环境常识的理解（如：救生艇必须放置在船舷而非内舱底）。
- **逻辑约束（Logical Constraints）**：通过严密的逻辑推论缩小选择（如：拼图只剩最后一块时，其位置与朝向在逻辑上被锁定）。

#### B. 强制功能（Forcing Functions）
物理或代码层面的刚性约束，不满足前提无法继续下一步或导致物理互斥：
1. **互锁（Interlocks）**：强制操作按严格顺序发生（如：微波炉门未关紧时电路被物理切断，绝对无法通电微波加热；汽车必须踩住刹车才能挂入前进挡）。
2. **锁死（Lock-ins）**：防止过早退出或在关键进程未完成前被意外终止（如：未保存文档关闭前阻止直接退出进程）。
3. **封锁（Lockouts）**：物理或逻辑上阻断危险区域的进入（如：地下高压电缆井防坠落锁盖；危险操作前的双人双钥机制）。

#### C. 防错与容错的四大工程法则
1. **可逆撤销（Undo）远优于单薄的确认弹窗**：
   - 依赖「您确定要删除吗？[确定/取消]」弹窗是极度懒惰的劣质防错。频繁弹窗会导致**确认麻木（Confirmation Fatigue）**，用户的大脑会无意识将其视为普通干扰直接秒点「确定」。
   - **最优解**：允许操作直接执行，但在有限时间内（如 5-10 秒）提供显式、醒目的「撤销（Undo）」能力，或进入可恢复的软删除隔离区。
2. **防错技术（Poka-yoke）**：
   - 在输入阶段就杜绝错误可能（例如：只能输入数字的文本框直接屏蔽非数字键盘输入；不可用状态的按钮直接置灰并提示缺失前提，而不是等点击后再弹报错）。
3. **合理性检查（Sensibility Checks）**：
   - 系统检测到反常激增的数值（如比日常交易大 1000 倍的金额转账）或违背常理的操作时，暂停并要求二次校验。
4. **NASA 航空安全自报机制与非指责文化（Just Culture）**：
   - 鼓励报告设计漏洞，将所有事故与差错视作改进系统表象与交互约束的宝贵线索，杜绝归咎于个人。

## 七、双钻设计模型与以活动为中心的设计

### 1. 英国设计委员会双钻模型（Double-Diamond Model）

```
     1. 寻找正确的问题 (Problem)           2. 寻找正确的解法 (Solution)
           ┌──────────┐                         ┌──────────┐
          /            \                       /            \
         /   发散调研   \   收敛聚焦          /   发散构思   \   收敛落地
        / (Discover)     \  (Define)         /   (Develop)    \  (Deliver)
       /                  \                 /                  \
      ◄                    ►               ◄                    ►
       \                  /                 \                  /
        \   深入观察     /   明确核心问题    \   多种原型设计 /   验证与部署
         \  真实痛点    /                    \  Wizard-of-Oz  /
          \            /                       \            /
           └──────────┘                         └──────────┘
```

1. **钻石 1：发散与收敛——确保解决的是「正确的问题」**
   - **发散（Discover）**：跳出初始预设，走到真实环境中深入观察，收集无偏见的行为数据。
   - **收敛（Define）**：剥离表面症状，使用五问法（Five Whys）收敛定位根本原因，定义核心设计挑战。
2. **钻石 2：发散与收敛——确保提出的是「正确的解法」**
   - **发散（Develop）**：头脑风暴，探索多种完全不同的概念原型与交互模式，避免首选方案锁定。
   - **收敛（Deliver）**：通过低成本原型实测，收敛至最鲁棒、体验最优的工程解法并实现落地。

### 2. HCD 的四步迭代循环与测试法则

```
        ┌──────────────► 1. 观察 (Observation) ──────────────┐
        │                 深入真实用户与使用情境             │
        │                                                    ▼
4. 测试 (Testing)                                    2. 构思 (Idea Generation)
   5人定性测试法则                                      跨学科团队发散多种假设
        ▲                                                    │
        │                                                    │
        └────────────── 3. 原型 (Prototyping) ◄──────────────┘
                          绿野仙踪法 (Wizard of Oz)
```

- **测试 5 人法则（Nielsen-Norman 5-User Rule）**：在定性可用性测试中，**5 名典型用户就能暴露系统中 85% 以上的核心可用性缺陷**。与其花费巨大预算在开发末期做一次 100 人的大型测试，不如在原型阶段分批进行多轮 5 人的小步快跑迭代。
- **绿野仙踪法（Wizard of Oz）**：在没有编写昂贵复杂后台算法前，通过幕后人工模拟系统响应，快速验证前端交互概念与心智模型是否顺畅。

---

### 3. 以活动为中心的设计（Activity-Centered Design, ACD）

- **活动（Activity） vs 任务（Task）**：
  - **活动**：由高层目的驱动的一组关联行为的总和（如：「在深空组织一次小行星带采矿远征」）。
  - **任务**：为了完成活动所必须执行的一个具体操作小节（如：「配置激光采矿器功率」、「清空矿仓」）。
- **ACD 的普适性**：不同文化背景、不同习惯的人在微观任务操作上各不相同，但**人类从事某项高级活动的心理目标与认知结构高度统一**。围绕活动而非散碎任务组织产品界面与信息流，能够建立高度统一、富有生命力的产品骨架。
