# 玩家站独立模块

状态：起步及经营预设扩展已制作，含六项科研、扩站/升级、制造、额外基础课程、警戒输入和基础维修；模块没有接入主游戏循环、正式存档、站点目录或任务页。当前规则以末节为准。

入口为本目录`index.ts`，不从`@whale/core`主出口导出。模块只依赖本目录的纯数据与规则，没有DOM、Node、GameState或SimContext依赖。

## 使用顺序

1. `createPlayerStation()`创建未批准、未建成的独立状态。
2. 宿主实现`PlayerStationHost`，负责真实库存/运输或独立预览的合成资源。
3. `playerStationCommand(state, host, action)`批准、暂停、恢复、取消或建设施；`advancePlayerStation`只消费宿主传入的有效流逝毫秒。
4. 宿主在真实到货时从货舱取出对应物资，调用`receivePlayerStationMaterials`；拒收物资留在该货舱，不重复退款。不能仅凭出发在途量就调用到货。
5. 取消主体后，用`takePlayerStationRecovery`领取实际回收运力可承载的材料，再由宿主真实运回；模块不会自动写入共仓。
6. `playerStationView`只读展示；`serializePlayerStation`/`loadPlayerStation`用于模块快照，不是正式游戏存档。

## 并行施工

`project`只保存主体工程，`projects`按开工顺序保存各地块设施工程。设施的暂停、恢复、取消命令必须指定`cellIndex`，不会操作其他工程。多个空地块可同时施工，每个项目普通施工负荷4点；首座发电标记`startup`，仅这一项免站内电力。生活设施优先，其余电力按工程先后分配，暂停项目不占施工负荷，缺电保进度。

每项完工时重新分配电力，保证大步与分步推进一致，不提前使用未完工电源。设施快照v3保存多工程、顺序及工程师身份；读取旧v1/v2时只迁移原有三类设施和工程，不改变原料/进度/暂停，不补发人员或新建筑。

## 宿主契约

- `take`是同步、不可重入的原子扣料，不足时返回false且不改资源；`give`同步完成一次返还，不失败、不重入模块。
- 名称与可用量由宿主提供，不在模块另建物品目录。工程学只提供0至5的整数等级，规则仍按确认的每级8%减料。
- 技能完成、到货和开工发生在同一时点时，宿主先推进到该时点，再更新技能，交接到货并执行`reconcilePlayerStation`。不把新技能追溯到已开工工程，也不把运输等待记为施工。
- 在线/离线共用同一推进函数；离线上限由宿主现有机制执行。模块不计墙钟、不另起定时器、不增加离线折扣。
- 独立快照不包含宿主库存/船只。宿主必须把模块状态与资源写入同一个一致性快照，不能只回滚模块、保留已退款库存。
- UI接收视图与命令回调，不导入正式GameEngine。合成预览不是生产/航路算法，不代表正式资源接入已完成。

## B1人口与转运

`population.ts`独立保存6个来源人口身份、待用材料、一个有限接收计划及当前副船阶段；不把居民塞进设施状态，不新建正式游戏档字段。`PopulationHost`提供来源发现、实际接收条件/容量、副船位置/余舱/互斥及原子物资接口；不得把主控船、忙船或原有货物占据的空间当作可用运力。`claimShip`同步原子占船，`releaseShip`在真实交接终点同步释放且不得失败或重入，航行中不允许宿主抢占任务船。

- 每单位预留100m³，含去程7m³耗材；每单位首次处理消耗民用修理组件4、冷却导管20、电路基板10，工程学不减免。
- 首趟1人；其后按剩余目标/真实余舱/来源/名额缩量。逐单位实际开始才预留名额、消费来源与材料；居民、在途及保护人口不重复计算。
- 正常阶段为出港1分钟、去程2分钟、复苏10分钟/人、装船1分钟、返程2分钟、接收2分钟/人；首人18分钟，首人加后续5人同趟共84分钟。只在接收完成后产生本站待命居民，不新增接收电耗。
- 停止只撤后续单位，当前单位继续处理/安全交接；未用材料留原账。接收失能时原船沿实际本地航段返回来源站原舱保护，保留身份/名额/已完成接收进度，安置后释放船只。恢复检查占10分钟/人，不重扣复苏材料；主动停止后不会自动接回。
- 本批仅一个计划/一艘任务船，以此落实来源与接收各一条共享通道，不宣称多船并发调度已实现。不含课程/派工、生产科研、战损、来源摧毁、居民故障期生存或未确认维修数值。

宿主用`playerStationNextEventMs`和`stationPopulationNextEventMs`按最近事件切段：先推进人口到边界（`advanceStationPopulation(..., true)`延后边界协调），再推进设施，最后`reconcileStationPopulation`决定下一单位。外部技能/到货/供电变更也须先推进此前时间再改输入，不能倒算。人口状态用`cleanStationPopulation`严格清洗，必须与设施、库存及船只互斥账整体保存，单独回滚人口会复制资源。

## B2基础课程与资格

`training.ts`只保存与来源人口身份对应的单工种资格、待开课队列及一个正在受训者；不再记一份居民总量。基础工程/研究课程各30分钟、共用1席，不接库存/收费接口，不受工程学或其他技能缩时。只有已接收的普通待命居民能开课；排队不占人，暂停或缺保障后仍保留当前人员、席位与进度。

`StationTrainingHost.residents()`提供本站居民身份，`available()`只核对其他岗位的占用，必须排除本模块的`active`自身，否则会形成自我阻塞；其他工作安排必须反向检查`training.active`，不能挪用受训者。`ready()`由宿主核对生命维持容量和服务中心正常运行。C2预览已把工程、精炼及采矿/返航占用纳入`available`；课程内已限制一人一席，已有资格者不再受训，不开放未确认的跨工种转训。

课程按队列顺序自动选择身份序号最小的合格普通待命居民；缺人口或保障时保留等待，不强抽其他工作的人。完成只给原人口相应资格，不自动派工、不增加人口或复制资格；仅支持移除未开始的队列项，运行中使用暂停/恢复保留工时，不另定未确认的取消/转训规则。

宿主合并`stationTrainingNextEventMs`与其余模块的最近事件，课程和人口先推进此前时间并延后新任务协调，再结算精炼/设施，最后协调人口和下一门课程。刚接收的居民不借用此前航程受训，课程结束同刻失去保障时不先抢下一人。`cleanStationTraining`必须使用同份人口快照的已接收身份列表验证；禁止给未接收者、当前受训者重复发资格。预览外层v5整体保存课程、精炼和原设施/人口/副船/库存，旧v1/v2只补空课程账，旧v1至v4只补空精炼账，不补资格、人员或物资。

## B3工程师施工与五类设施

新增基础精炼设施、初级研究室，沿确认料单和60/90分钟有效工期，各占1格、1名基础工程师和4点施工电力。原三类保障设施继续有限无人装配；首座发电启动例外不扩大。精炼/研究室未完工不收运行负荷，完工后各待机1点；C1精炼作业总耗电6点、C3科研作业总耗电4点已接，只有实际派工才推进作业。

宿主`PlayerStationHost.engineers()`提供已接收、取得工程资格、未被课程或其他岗位占用的人口身份，不排除本模块已有工程的人员。模块自行扣除全部`projects[].engineerIndex`选择空闲工程师，暂停/缺电仍占用，完工/取消随项目移除释放；缺人、缺生活保障、电力或材料时不开工扣料。`playerStationNextEventMs`须同时传入宿主，否则人类工程会因缺工程师输入保持阻塞。

设施快照v3要求人类工程绑定有效且不重复的身份，自动工程不允许夹带工程师字段；宿主外层v4进一步核对该人是同一人口账的居民、同一课程账的工程师，且不在受训。旧内层v1/v2只迁移原三类设施，旧外层v1/v2/v3不可夹带新设施或用工字段。只读视图展示需用/可用工程师、项目人员和阻塞原因，人口表显示施工占用；不因此宣称真实生产、科研或正式资源互斥完成。

## C1基础派工与人类精炼

`refining.ts`只管理每座已建精炼设施的一份任务、原居民身份、开工批量/周期、有效进度及完成批数。普通居民、工程师或研究员都可承担基础精炼，不增精炼职业/课程；同一设备只一名劳动者，人员不能同时受训、施工或在另一设备工作。停机/缺料/缺电仍保留安排，主动停止则释放人员、清除未完成批次进度，不重复发已完成产物。

`StationRefiningHost`由宿主提供居民/设备互斥、实际供电、公共库存和现有配方取数。`recipe`须复用现有主控开炉参数，`output`须复用`refineBatchOutputOf`，不加人类效率倍率、不复制技能或配方公式。模块不引用GameState/SimContext；开发预览的`refining-baseline.ts`在模块外使用合成主控状态调用既有入口，正式接入需用真实技能/科技输入替换，不把合成取数当作已联调。

沿原精炼整批到点扣料，开工不预扣；`settle(input, output)`同步原子交接，失败不扣料/发半份产物，不能重入。多台在同刻争用最后一批时依任务顺序结算，未取到材料者保留本批到点进度，补料后零时间完成一次结算；缺料/缺电期间没有产物或工时。主动停止时原料未扣所以不退款，重新安排的新批次进度归零。

站点宿主`workingCells()`提供具备人员/原料且未手动暂停的作业请求，统一供电单点按精炼6点总负荷（非待机1点再加6）分配，生活/中心仍优先。缺料/手动暂停只保留设备待机负荷，不释放人员。宿主每段冻结已请求负荷，按设施/人口/课程/精炼最近事件切段：先推进此前课程/人口，结算精炼，再结算设施，最后协调新任务；本批刚产物资或刚释放电力不能倒算此前航程/施工。预览推进异常时整体恢复模块/库存/副船，正式宿主也须保持同等事务边界。

预览外层v5整体保存精炼任务与技能测试输入，内层设施保持v3、正式存档仍v31。清洗核对批量/周期来自既有六档合成技能组合，人员确为同份人口账居民且未受训/施工、地块确为精炼设施；缺账或冲突整份拒读。旧v1至v4只补空精炼账，不增加原料/产物/居民。C1不含真实AI设备交接、人类采矿、科研或正式存档集成。

## C2人类采矿与返航供料

`mining.ts`管理每项任务的原居民、矿船、采集点、离港/采掘/返航进度、停止标记、船上货物、随机状态和富矿窗口。采矿不要求专门课程；一人一船，暂停与停止返航仍占人/船，卸货交接完成才释放。离港未完成时撤回保留原船货物，不伪造一次入库；采掘时停止丢弃当前未完成循环，已采货物随船返航；返航中停止保留原时长及已走进度，不传送或重新点火。安全返航不被暂停或站点失能卡在野外。

`StationMiningHost.params/cycle/returnMs`必须复用既有采矿、货舱和航程单点，不另造人类倍率。开发宿主`mining-baseline.ts`用真实磷虾船型、双MK1采集器和统一0至5技能合成输入，调用`advanceMining`执行一个循环，保留富矿及随机状态，再用既有`scaledReturnMs`折算合并去程的返航腿。自动循环卸货后不清尚未结束的富矿奖励窗口，与现有主控一致；不使用AI核心、debug一秒化或跃迁燃料。C2预览只开放玩家站同星系的磷光霾场，暂不包含跨星系/复合带或真实探索声望门禁。

船货只存任务或原船货物其中一处，`claimShip`原子占船并转交原船全部货物，`unload`原子入库且不得重入，`releaseShip`在交接后同步完成且不得失败。宿主必须同时对照人口转运和其他工作占用，禁止直接换人/船绕过返航。矿船卸货排在此前精炼/课程/人口/施工时间结算之后，新到原矿只能供后续时间的精炼；五模块按最近事件切段并冻结本段保障，刚建成电源不补此前采掘进度。预览推进异常时连同矿船/船货/随机状态整体回滚。

外层预览v6保存采矿与独立原船货物账、测试技能及两艘合成船，与全部旧状态一起恢复。清洗拒绝船/人重复、任务与船只锁定不一致、非居民或多岗、未知货物/采集点/伪造周期航程、任务和原船两份货物。旧v1至v5只补空采矿账及空舱的开发合成矿船，不补库存原料/产物/居民/资格；这是测试宿主，不修改正式资产。真实玩家舰船装配、探索/声望、AI作业竞争和正式存档接入仍需集成验证。

## C3首项科研

`research.ts`只保存一项“初次站体扩容”的项目进度、完成标记与一份研究室/研究员安排，不生产通用科研点。有效工时60分钟是开工单授权的可调测试基准，非发布数值；首项不收未定的试验材料费，不串联制造、培训或警戒方向。

`StationResearchHost`注入已接收研究员身份、其他工作占用、实际研究室及生活/中心/科研供电；模块不复制课程资格或人口。安排需一名基础研究员及一座已建研究室，一站同时一项；暂停和缺电仍保人、保设施与进度，恢复只继续有效时间。`release`只撤出岗位，不取消项目或抹去已完成工时，不自动再派；再次安排合格研究员可从原进度继续。完成自动登记技术并释放岗位，技术不因后续停电遗忘，不直接增加地块或设施。

宿主把科研请求并入原站点供电单点：研究室待机1点、作业总耗电4点，不额外再加待机电力。按六模块最近事件切段，科研先读取本段旧条件，冻结此前负荷，再处理课程/人口、精炼、施工和矿船卸货；新建电源、研究室、课程或刚释放功率不补此前时间。其他模块交接失败连同科研进度/完成/岗位一起回滚。

预览外层v7整体保存科研，内层设施仍v3、正式存档仍v31。旧v1至v6只补空科研账，不授予技术或进度；v7缺账、未知项目、完成与进度不符、非研究资格、错设施或与课程/生产/工程多岗的快照整份拒读。正式科技解锁入口、扩建施工、完整研究计划与材料扣退留后续，不将这一测试项目当作完整科研目录。

## 经营预设扩展

船长明确授权自主补齐科研与建筑，覆盖前述C3阶段的单项范围限制。科研状态v2（可读旧v1）包含六项目目录、当前项目、非当前归档与有限计划；同一项目进度不存两份，完成只登记技术。`researchCompleted`是门禁单点，队列续项不借用前项时间。

`development.ts`管理外围扩站、原地保障升级与限定无人维修。宿主提供真实科技、设施、合格工程师、剩余功率及原子扣退料。发展工程各自锁原材料与不同工程师、暂停仍占人；取消按原投入和剩余有效工时退料。扩站不占旧格；升级保原能力，完成后替换。维修不需人/电，恢复原等级，不改人口或研究。

设施模块通过`cellCount`（9/16）、`unlocked`、`facilityState`及`externalConstructionPower`注入发展成果，仍由原供电单点分配。内层运行字段保持v3，序列化/读入可显式传入已验证地块数；外层v8需交叉验证扩站资格，不能只让内层接受16格来冒充发展成果。

`manufacturing.ts`沿精炼结构，有限订单锁定宿主真实单批配方/周期，到点原子结算；缺料/电、暂停保配置，主动停止不退尚未消费料，末批完成释放人员。`academy.ts`只提供一份额外基本课程席位，继续写原资格账，不复制人数；服务中心/额外席位计划合计不得超过来源人口。完整舰员团队模拟训练不是此课程。

预览宿主在原事件时间轴合并上述模块，冻结本段实际负荷；新物料、资格、电源只供后续时间。外层v8整体保存发展/制造/课程及原状态，旧版只补空账，科技、设施、配方和多岗严格成对校验。警戒只对宿主实际返航输入显示近域信号，不内置另一套敌袭生成器。正式主存档、真实AI/资源、站点和任务界面尚需统一接入验收，详见`docs/design/player-station-preset-completion-20261120.md`。

## 第二阶段续作

`crew.ts`与`crewContent.ts`提供真实成员/舰船/培训席位、团队资格/潜力/属性、累计技能点、学习机会/永久特性和事后二择。`StationCrewHost`只在招募时核验外部普通待命居民；已归属团队的人口持续占用，待命/暂停不能归还同一人口又保团队。训练claim/release真实船锁，实际出击经验只由宿主在新报告上调用`awardCrewExperience`，不能每拍给守备空挂机经验。

`security.ts`有限巡逻/护航/三来源清剿及专用守备与crew纯状态互不依赖，由宿主原子占用团队/船并调用真实战斗。缺补给返航/暂停，不死亡、毁站或没收共享全仓；清剿成果保留且不可重复领取。报告只有显示窗口，经验游标和历史目标账属于组合宿主。

`campaign.ts`提供八项目标及显式自主据点确认，无资产/外交/奖励接口。`StageTwoSession`在原经营时间轴加入crew/security，整体保存/回滚原经营v8和第二阶段外层v1；历史成果须同资源/任务交叉验证，不能只信任目标字符串。正式存档、AI竞争、真实舰队/人口/任务和内容规模仍有接入缺口，见`docs/design/second-stage-crew-security-20261121.md`。
