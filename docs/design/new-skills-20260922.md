## 五、待裁决：技能树排布体检 vs「两条前置」

### 现象（读数）

```
✗ b-warship 没挂住：装甲舰操作 的子（护卫舰操作、驱逐舰操作、巡洋舰操作、战列操作）没有一个在它正下方
✗ b-warship 往回长：护卫舰操作（x=84）跑到了前置 装甲舰操作（x=548）左边
✗ b-warship 往回长：驱逐舰操作（x=200）…
✗ b-warship 往回长：巡洋舰操作（x=316）…
✗ b-warship 往回长：战列操作（x=432）…
```

### 根因（结构上不可能同时满足，不是排布参数没调好）

这四条技能是**全仓第一批「同一本书内两条前置」的节点**（全仓仅这四条有多前置）。排布体检的两条口径（`tools/skilltree-layout-check.ts` ③）是：

- **3a 挂得住**：每个有子的节点，至少有一个子落在它**正下方**；
- **3b 不回头**：子不许跑到父的**左边**。

设两个父列 `pA`（武装舰操作）、`pB`（装甲舰操作），`pA < pB`。共享子要"挂得住"给 `pA` ⇒ 必须有一个子在 `pA` 列；但 3b 要求**每个子** `x ≥ pB` ⇒ `pA ≥ pB`，矛盾。（对 `pB` 同理。）**一列只能承一个父 ⇒ 两条边不可能同时满足 3a＋3b。**

### 可选做法

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **甲（推荐）** | ①算法：多前置的**共享子轮流承父列**（前两个子分别落在两个父的正下方，其余开新列）；②体检：**多前置节点只对"承父列"的那条边判 3a/3b**，同节点的其余前置边豁免这两条 | 体检口径新增一条「多前置合流」特例；树形仍是"往下长"，两个父都挂得住 |
| 乙 | 数据 / 口径都不动，只给体检加豁免（装甲舰操作落在最右、四条斜线从右侧汇入） | 视觉效果右重左空，四条线较长 |
| 丙 | 前置改成**一条**（只留武装舰操作） | 与船长「两条都要 Lv1」的原裁定冲突，须改口；体检口径零改动 |

## 六、已知取舍

- 舰种操作在 `createPlayerSpec` 内取 `ship.tier` ⇒ **只影响主控在驾的那艘**；副船 / 无人机不吃（与船长裁定一致）。
