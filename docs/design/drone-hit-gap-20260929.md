## 二、「收窄类是不是最后计算」的实情（回答船长那一问）

引擎里「收窄 / 缺口」这一族**没有统一的"最后一道"**，按对象分三处，共同点是**都只在战前合成阶段算一次**
（写进 `UnitSpec`），开火时直接消费：

| 对象 | 落点 | 位置 |
| --- | --- | --- |
| 回避缺口（`evasionGapPct` 姿态陀螺 / 掠袭折射涂层 / 规避机动学） | `evasion = gapCombine(gaps, base)` = `1−(1−基础)Π(1−x)` | **最内层**：`hitChance` 的 `(基础命中 + 命中加成 − 回避) × 距离衰减 × 索敌 × 失稳`，收窄作用在**被减数**上 ⇒ 在距离衰减**之前** |
| 抗性缺口（`*ResistAdd`） | `mergeResist` 按缺口复合、上限 0.9 | 战前合成 |
| 抗性削减（`allResistPenaltyPct` 掠袭折射涂层 −15） | 放在**抗性合成与调谐之后**（源码原话「作用于最终值」） | 结算链最外层的**减法**、下限 `RESIST_FLOOR −0.9` |
| 命中代价（`hitPenalty` → `hitMul` 失稳） | `clamp(下限, 上限, raw × eqHitMul × hitMul)` | clamp **之内**、回避减完与距离衰减之后 |

⇒ 唯一"确实是最后一道"的是**抗性削减**那一支；回避缺口是"最内层"。本批按船长的机制偏好走
**回避缺口同一条链**（路径①），即让「对方对机群的命中」收窄 5% 落在同一处被减数上。

## 三、设计（已确认 · 甲案）

### 3.1 数据

- **删**：`mod-wh-e-tac` 的 `droneHullHpBonusPct: 0.8`（该字段与「鱿蜂结构层」的设计归属见
  `docs/design/wormhole-exclusive-20260913.md`；塔的 +80% 是 2026-09-27 那批补的，本次改判撤掉）。
- **增**：`mod-wh-e-tac` 的 `droneHitGapPct: 0.05`。
- 塔改后 = **放飞无人机单发 +50% · 对方对机群的命中 ×0.95**（CPU 44 不变）。

### 3.2 引擎

- 新字段 `ModuleDef.droneHitGapPct`（本职 = 战术导控族 `drone-tac`）。
- `stackingOf`：归 **`gap` 组 / kind `drone-hit`**（与回避缺口、抗性缺口同一把尺：多件复合、
  界面标「多装递减」）。**不**掉进 `flat` 兜底（那会写成「全额叠加」）。
- `CombatUnit.droneHitGapPct` = 本舰所装件**求和**（与 `droneHullBonusPct` / `droneShieldBonusPct`
  同款：只有一件带它时与"取值"等价）。
- 消费点 = `droneHitChance`（**只作用于"打机群"这一支**，打舰一字不动）：

  ```
  综合闪避 = 被瞄准那一架的机型闪避 × (1 − 收窄)
           = 0.45 × 0.95 = 0.4275（蜂鸟例）
  命中 = clamp(下限, 上限, (基础命中 + 命中加成 − 综合闪避) × 1 × 索敌 × 失稳)
  ```

  数值 = **命中 ×0.95**（例：0.90 − 0.45 = 0.45 → 0.90 − 0.4275 = 0.4725），与"把闪避乘 0.95"
  在数学上同值；落在这里是为了与闪避/抗性缺口**同一条链**。
- ⚠ **只对我方打敌机生效**（`droneHitChance` 的调用点只有一处 = 我方开火段），敌方近防炮打我方
  机群走的是另一条公式（`clamp(pdHitFloor, 1, pdAcc − 机型闪避)`）。**不**动那一条。
