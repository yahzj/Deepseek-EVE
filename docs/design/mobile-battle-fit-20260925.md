## 一、结论

1. **「手机端旋转＋按宽缩放」没消失**：两套布局都在跑（`is-mobile-rot` 生效、`--mob-scale 0.7033`、
   逻辑空间 1200×554.5）。消失的是 2026-09-22 那套「窗口壳：固定设计尺寸 ＋ 装不下整块等比缩放」
   （`fb19000b`）——同一天按船长令「界面回滚，战斗界面回滚到全屏显示」（`fd9651da`）把战斗界面
   从窗口壳里拿了出来 ⇒ 手机上只剩「按宽缩放」，逻辑**高度**被机型宽高比锁死，装不下就硬裁。
2. 战斗界面内部按桌面版式要 **约 700px**，手机只有约 540~555px；其中战场那 **353px** 是车道
   自己声明的内容高（两排舰影 ＋ 两排血条），而手机路径历史规则把车道最小高压到 210px
   （2026-09-06「舞台最小高下调给操作区让位」）⇒ 舞台裁 127px、车道裁 143px。
3. 修法＝**甲（整块等比缩放：只缩不放）＋ 乙（压底栏：图例/装填单行横滑）＋ 两处留白收紧**。

## 三、方案（已实现）

### 乙 · 手机路径压底栏（只动 `is-mobile-rot`）
- `.app-bts-legends` / `.app-bts-reloads`：`flex-wrap: nowrap; justify-content: flex-start;
  overflow-x: auto; overflow-y: hidden`；子项 `flex: 0 0 auto`（**不许压扁 chip**：压扁会让 chip
  内部换行、反而更高——第一版实测图例从 112 涨到 178 就是这个坑）。
- `.app-bts-chip.is-foe { order: -1 }`：敌方射程 chip 恒在首屏（单行横滑会把排在后面的推出屏外）。
- 留白收紧（不动触控尺寸与字号）：底栏容器 padding 12/16/16 → 6/16/8、dock `gap` 10 → 6、
  距离尺 `margin-top 4→0` / `padding-top 6→2` / 刻度条 `height 14→8`、顶栏 padding 12→6、`row-gap 10→6`。
- ⚠ 本批规则必须排在 2026-09-06 那批**之后**（同为 3 类选择器 ⇒ 靠顺序取胜；第一版排在前面，顶栏没生效）。

### 甲 · 只缩不放的整块等比缩放（`ui/battleFit.ts`）
- 新增包裹层 `.app-battle-fit`（顶栏／舞台／底栏三层包在里面）。
- ① 先量**车道的纯内容高**（临时摘掉 `flex` 拉伸与最小高再读 `scrollHeight`；血条是绝对定位挂在
  舰影下沿的，必须用 `scrollHeight` 而不是 `offsetHeight`），把它写进车道的 `min-height`
  ⇒ 车道不再裁自己的血条。
  ⚠ 不能拿 `scrollHeight` 直接比 `clientHeight`：写进 353 之后盒高也是 353 ⇒ 判成"不用抬" ⇒
  又掉回 210，**会自激振荡**（第一版实测踩到，读数里 `车道内联最小高` 是空的）。
- ② 把包裹层交回内容撑（`height: auto` 读一次 `offsetHeight`，同拍还原）得 `need`。
- ③ `k = min(1, 可用高 / need)`：`k = 1` ⇒ `height: 100%` ＋ 无 transform（**与改造前逐像素一致**，
  桌面宽窗口恒为这一支）；`k < 1` ⇒ 高度取 `need`、`transform: scale(k)`（origin `top center`），
  并给整屏挂 `is-bts-fit`（内容已缩进可用高 ⇒ 不需要滚动）。
- 读数写在 `data-bts-k / data-bts-need / data-bts-avail` 上，供体检工具读取。
- 量尺寸只用 `offsetHeight / clientHeight / scrollHeight`（不受 transform 影响）⇒ 无自激；
  `ResizeObserver` 只盯整屏可用区，不盯舞台（舞台的高是本层给的）。
