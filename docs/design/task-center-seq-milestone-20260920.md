## 二、改了什么

**core（`packages/core/src/firstTasks.ts`）**
- `visibleFirstTasks`：改为**顺序解锁**——只给 `FIRST_TASKS` 数组序里**第一条还没完成的**；全完成 ⇒ 空。
- `FirstTaskDef.prereq` 字段删除 ＋ 10 处 `prereq:` 数据删除。
- 新增 **`firstTaskProgress(state) → { done, total }`**（页头 N/13 的唯一出处）。
- 新增 **`milestoneBoard(state) → MilestoneChainRow[]`**：**13 条链各一行**（链名 · 对应「第一次」任务 id/标题 ·
  `unlocked`（= 该任务已完成才上里程碑页）· 档位/总档 · 终身计数与下一档阈值 · 可领奖金 · 下一级奖金）。
- `firstTaskBoard` 保留签名与字段（面板与用例仍读），语义按新口径重述（顺序解锁下恒为"当前这一条"）。
- `index.ts` 导出 `firstTaskProgress` / `milestoneBoard` 与类型 `MilestoneChainRow`。

**UI**
- 新增 `apps/desktop/src/renderer/src/panels/MilestoneTasks.tsx`：页头「◆ 里程碑 · 已解锁 N/13」·
  **一条都没解锁时给提示**（"先去「重要任务」把当前那一条做完"）· 已解锁的链每张一卡（名字 / 档位 / 已累计 X/Y 单位 /
  可领奖→**领奖按钮只在这里** / 下一级奖金读数）· 全都没得领时一句"达到下一档后回这里领"。
- `panels/Expedition.tsx`：任务中心加**第 5 个页签「里程碑任务」**（`TaskTabKey` + `TASK_TABS` + 两处 focus 白名单 + 渲染分支）。
- `panels/FirstTasks.tsx`：**只渲染当前这一条**（丙案）· 去掉"已完成"相关分支与**链领奖按钮** ·
  页头改用 `firstTaskProgress` · 卡上补**只读一行**「里程碑 {链名}：{级} 级 · 已累计 X/Y 单位——在「里程碑任务」页领奖」。
- l10n：`ui.Expedition.424`（页签名）＋ `ui.MilestoneTasks.001~008`（页头/空态/只读行/可领提示），中英齐全。

## 三、玩家可见变化（读数）

| 项 | 改前 | **改后** |
|---|---|---|
| 「重要任务」页的卡 | 满足前置的**一起出现**（实测新档 1 条、推进中最多 8~13 条） | **恒 1 条**（当前这一步）；已完成的不再占位 |
| 页头读数 | `已完成 / 可见条数` | **`已完成 / 13`**（与可见条数脱钩） |
| 链（里程碑）进度与领奖 | 在「第一次」卡片内 | **独立页签「里程碑任务」**；「第一次」卡上只留只读一行 |
| 里程碑页解锁 | — | 恒显；`unlocked` 逐条开（完成哪条「第一次」，它对应的链就上页） |

## 四、已知取舍 / 待你定

1. **`onOpenComms`（「看情报」）现在没有触发点**：那个按钮原本只挂在"已完成"的卡上，而丙案下已完成的卡不再渲染
   ⇒ 本页不再有入口（**历史信件仍能在通讯页翻到**）。要不要在「里程碑任务」页每张链卡上补一个"看情报"入口？
2. 里程碑页**只列已解锁的链**（未解锁的不占位）——如果你更想"13 条全列出、未解锁置灰"，一句话就改。
3. `firstTaskBoard` 里的 `hidden` 判据在丙案下天然不成立，**保留**是给用例与老调用方兜底（已在注释写明）。
