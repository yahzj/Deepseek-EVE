## 四、验收要点（真机怎么看）

1. **战斗画面**：进一场战斗 ⇒ ①目标旁飘伤害数字（同拍同目标合成一个）；②打空/未命中飘灰 `MISS`；
   ③右上武器条里「攻坚炮台 MK3·动能型」应为**动能弹药（金）**、「巡航导弹架 MK3」应为**爆破弹药（橙）**、
   激光为**能量弹药（青）**；④倍速/暂停时飘字跟着快/停。
2. **快递任务页**：页头「距下批刷新 **h:mm:ss** · 每 **120** 分钟一轮」；卡片「剩余 h:mm:ss」；
   抽到手超过 20 分钟的单子**仍能出发**（旧 bug：会判"已到期"）。
3. **组装机**：零件卡产物行「… ×10 件 · 行情 930 · **整批 9,300**（利润率 50%）」；消耗品卡同理。
4. **货柜拆解**：事件日志「📦 拆解 贵重品货柜：得到 **星图真迹 ×6**（奢侈品）。」
5. **切活动停机**：开一条制造线后直接去采矿/开远征 ⇒ 统一日志里应有「停线…」且**材料已退回仓库**；
   一次性图纸的线被停后，**蓝图书架里那本书回来了**（名额也恢复）。

## 五、工具与闸门（本轮入库，都是正式件）

| script | 作用 |
| --- | --- |
| `npm run ui:tdz` | 渲染层"先用后声明"（TDZ）体检——**直接执行**那种必崩的报红；已挂 `ui:rot-check` |
| `npm run ui:dmg-color` | 伤害类型配色契约（两族同 token · 逐主题三色可分 · 动能不比能量蓝）；已挂 `ui:theme-check` |

| `npm run unbox:log-sample` | 拆解日志样张（数量口径） |
| `npm run courier:clock` | 快递页倒计时读数样张（120 分钟口径） |
| `npm run save:diff -- <副本> <存档>` | 存档差异复核（只读；补账后对账） |
| `npx tsx tools/save-grant-ships.ts <存档> <舰id>:<艘数>…` | **给存档补发成品船——会写真档**；双备份＋外科式改写＋自检；**刻意不挂 npm script** |

## 六、纪律与踩坑（防重踩）

- **推送**：`git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main`
  （直连 github 不通）；推前确认主树干净、闸门全绿，**且船长点头**。
- **真档**：一律只读；只有船长明令补账时才用 `save-grant-ships.ts`（先关掉游戏，否则它下次自动保存会盖掉）。
- **两个"两套实现"的坑（本轮各修一处，都留了契约）**：① 伤害类型颜色曾有两套（类型色 vs 层位色）⇒
  现合并成同一条 CSS 规则；② 弹种曾按"全船主流弹种"报 ⇒ 现一律按武器自己的 `shotsByType`
  （`nextAmmoType` 已标为兼容导出，**不得再用于推断弹种**）。
- **回滚/异常态**：停机、取消、读档往返三条路上的"退料/退书"必须**对称**（本轮修的就是不对称：
  取消退、停机不退）。加任何"线上记账"字段时，**记得同时登记进 `save.ts` 清洗器**（漏登记＝读档丢），
  本轮 `bookSpent` / `spentMaterials` 都是这么修的。
- **别开子代理**（AGENTS §5.1）；UI 观感不自己截图当结论（§6）。
