# 战斗线技能填充提案（一号域：技能数据/文案；触点接续见 §四）

> 输入：docs/design/handoff-weapon-skills.md（二号 2026-09-05 交接）+ commit d64fe73。
> 范围：三形态武器族技能首批；防御三隐藏件与无人机第二批候选（需防御/数值数据先落地）。

## 一、现状结论

- 唯一已接线战斗技能 `gunnery`（炮术学）：`dmgScale = (1+5%/级×Lv)×(1+powerBonus)`，构建期乘进
  动能炮/导弹架（gun）与激光（beam）与基础舰炮单发——**三形态共用一区**；
- 武器形态：动能炮（turret/kinetic，命中衰减+近盲）/ 导弹架（missile/explosive，追踪命中不衰减
  +近盲安全射距）/ 激光炮（laser/plasma，必中 + 威力衰减 50%）/ 无人机（fixed，不吃炮术）；
- 支援装备已有按系 `damageTypeBonusPct` 加算通道（装备词条，非技能）。

## 二、首批技能（武器族专精乘区，乘算叠加于 gunnery 之上）

| id | 名称 | 组/rank | 效果文案草稿（⟦数值⟧ = 初稿，待 C4 校准） |
|---|---|---|---|
| kinetic-gunnery | 动能炮术 | 战斗 r1 | 动能武器（炮台）专精：单发伤害每级 +⟦3%⟧（与炮术学乘算叠加） |
| missile-launching | 导弹发射学 | 战斗 r1 | 导弹架专精：爆破导弹单发伤害每级 +⟦3%⟧（与炮术学乘算叠加） |
| laser-cannon | 激光炮学 | 战斗 r2 | 激光炮专精：光束单发伤害每级 +⟦3%⟧（与炮术学乘算叠加；必中不受影响） |

- 族判定按武器条目来源（模块 slot：turret→动能族 / missile→导弹族 / laser→激光族；基础舰炮归动能族? 否——舰炮吃 gunnery 但不吃族技能，维持兜底定位）；
- `gunnery` 保留（通用基础，文案已准确）；
- 克制/命中/装填/射程等参数**不设技能**（激光必中与导弹追踪是形态性格，不稀释）。

## 三、第二批候选（本批不导，防止无效技能）

- 火控阵列学（命中乘子，激光无效）、武器装填技术（装填 −%/级，乘区=装填循环，触点战斗循环）、
  无人机作战学（无人机单发 +%/级，现无人机不吃炮术，需独立乘区）——触点均在 combat 战斗循环
  （二号数值域），列入提案待数值模型；
- 护盾操作学/能量管理学/船体加固理论（HIDDEN）：防御侧数据落地后随批次开放。

## 四、接线与验证（文件划分声明）

- 接线点：`balance.ts` battle 段（族技能系数字段）+ `combat.ts` createPlayerSpec（每条目按来源族
  乘 `(1+族技能%/级×Lv)`，在 support 加算与 dmgScale 之外构建期折算）——本次**由一号按此清单接入
  （船长授权"导入并验证"）**，与二号 C4 校准轮按文件/字段错开；若二号并行接手数值域，触点行变更
  以本清单为准；
- 验证：content-check（技能引用/分组）＋ core tests：createPlayerSpec 三形态满级单发 = 基础×
  dmgScale×族乘；三族互不串乘（装动能族技能不打导弹/激光）；基础舰炮不受族技能影响；gunnery 不学
  仅族技能时族乘仍生效（乘算并列）。手册/技能页自动呈现（数据驱动）。

## 七、第四批：弹药集约学（2026-09-05）

- ammunition-condensing（战斗 r2）：出发预载弹药 +8%/级（+40%）；触点 = `ammoLoadTotals`（per-gun 多键预算整体放大，实际装载仍受携带库存上限约束）；
- 签名迁移：`ammoLoadTotals(me, bal)` → `(me, bal, state)`（调用点 combat.ts 装载流程 + v18b2.test 同步）；
- 验证：core 354/354 全绿；战斗线可见技能 = 12 条（炮术 + 三族 + 火控/装填/无人机 + 盾/能量/船体 + 弹药集约）。

## 八、第五批（收尾批次，2026-09-05）：减伤调谐 / 无人机整备 / 舰族操作（5 条，含战斗线收口）

| id | 名称 | 组/rank | 效果（满级） | 触点（createPlayerSpec） |
|---|---|---|---|---|
| shield-tuning | 护盾调谐学 | 工程 r2 | 护盾减伤缺口每级收窄 2%（等效抗性约 +2pp/级，合计封顶 90% 不变） | resists 段 tune(shieldRes)（在抗性改装件合并之后乘缺口） |
| armor-tuning | 装甲调谐学 | 工程 r2 | 装甲减伤缺口每级收窄 2%（同上） | resists 段 tune(armorRes) |
| drone-servicing | 无人机整备学 | 战斗 r3 | 无人机装填时间 −4%/级（满级 ×0.8，至少保留 60%） | 无人机武器条目 reloadMs 折减（2200ms 基准） |
| armed-ops | 武装舰操作 | 舰船 r3 | armed 族驾驶：全武器（含基础舰炮）单发 +3%/级（+15%） | dmgScale 乘链（条件 ship.role==='armed'） |
| armored-ops | 重装舰操作 | 舰船 r3 | armored 族驾驶：装甲+结构容量 +4%/级（+20%，与船体加固理论乘算） | hp.a/h 乘链（条件 ship.role==='armored'） |

- 设计点：调谐学按"减伤缺口收窄"建模（与抗性改装件乘算叠加、封顶 0.9 保持）；两操作学带舰族条件，
  避免与通用工程技能叠成无条件堆叠（工业族不受影响；内容库里 armed=5 艘、armored=3 艘可受益）；
- **更正（船长 2026-09-05，提交后复核）**：原"无人机整备学 = 放飞 CPU −8%/级"作废——带宽已并入 CPU，
  CPU 是全船静态载荷约束（装配 + 放飞共用同一池，无人机卡面 cpuUse 即原带宽占用），**技能不折减放飞
  CPU**；船长拍板改 = 无人机装填时间 −4%/级（描述与武器装填技术统一口径：每级 −4%、至少保留 60%；
  武器装填技术只覆盖炮台/导弹架/激光炮，两者独立乘算），装载循环 CPU 判定恢复原语义；
- 收口口径：战斗效果技能至此 = 15 条（上批 12 + 无人机整备学 + 双调谐学）；武装/重装两条属舰船族系操作；
  技能目录总数 57 → 62（战斗组 +1、工程组 +2、舰船组 +2）；
- 验证：combat.test 批次五用例（缺口 0.4→0.46 双向不串、无人机装填 2200→1760 且 CPU 判定不受技能影响、
  armed/armored 族门控 ×1.15/×1.2）；
  core 358/358 全绿、content-check 通过、四包 typecheck 通过。

> 技能填充到此告一段落（P1 扩军 + 战斗批①~⑤ + 补全轮）；此后如再补 = 新需求（见 roadmap 候选区 B3 掉落/回收系统载体）。
