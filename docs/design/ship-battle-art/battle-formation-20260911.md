## 二、几何规则（数值精确）

- **前排判据**（只看 tag 与数据，不看谁还活着 ⇒ 击毁不会让阵形重排跳动）：
  `(w{n}-)?foe-0`（本波首舰）**或**该舰级为**头目档**（`FoeShipDef.elite`，界面经
  `core/foeShipEliteOf(卡, tag)` 反查）⇒ **前排**；其余（僚机、杂鱼、非头目）⇒ **后排**。
- **抬升**：前排 `0`（基线，最前最低）；后排 `+RANK_STAGGER = 72px`（＝一条血条高 48 的 1.5 倍，
  满足船长「≥68」）；可选 `RANK_BY_WAVE`（见 §五）按波再抬 `波序 × 72`。
- **编队高度** = `max(抬升 + 舰高)`，后排队顶对齐既有 `LAY.TOP` ⇒ 编队整体向下多占 72px（主舰下沉），
  我方舰位不动。
- **锚点**：`layout()` 逐舰 `y = TOP + env − 抬升 − 舰高/2`，`x` 仍按前缀和推进
  （**锚点永远跟实际舰宽**，2026-09-11 船长「乙」裁决）。

### 2.1 代表编成读数（贴脸 200m；锚点 = 舰体中心）

| 编成 | 舰 | 抬升 | y（改前 → 改后） | 血条宽 |
|---|---|---|---|---|
| 单舰（教学卡 / 坟场 / 穹顶 / 碎晶…） | 1 | 0 | 93 → **93（逐像素不变）** | 185 |
| A 族头目 + 3 杂鱼（灰霾/蜃影/赤环/占港…） | 4 | 0 / 72×3 | 全 93 → **165 / 93×3** | 185 / 168×3 |
| C 族主体 ×2（裂谷/星髓/深渊之门/噬口） | 2 | 0 / 72 | 全 93 → **165 / 93** | 185 / 185 |
| 旧路径 主体 + 2 僚机（坟场/虚海/穹顶/奥罗…） | 3 | 0 / 72×2 | 93 / 112×2 → **128 / 75×2** | 185 / 堆叠 |

（C 族两舰同为 170 宽 → 间距 174 ⇒ 条宽 185 仍不压叠；A 族 3 杂鱼同为 170、间距 174 ⇒ 条宽收到 **168**
吃掉原本 11px 压叠；旧路径双僚机只有 94 间距（90 宽）⇒ 该梯队**整组竖排到编队下方**。）

## 三、血条与舰名（船长 ③）

- **血条跟着各舰走**：每条**绝对定位在本舰正下方**（`.app-bts-unit > .app-bts-hpWrap.is-unitBar`，
  `left:50% / top:100% / translateX(-50%)`）⇒ 不参与行内布局，**不影响入场/爆炸/尸骸动画**；
- **宽度口径**：`min(185, 同梯队相邻舰间距 − 6)`，下限 140；间距 < 146 的梯队整组竖排（见 §二.1）；
- **舰名**仍浮在各舰上方（不动）；**前排**的血条不再重复舰名（与改造前"首条不带名"一致），
  后排/堆叠的条带舰名（便于对应）；
- 尸骸不显示血条（＝改造前"只给存活单位画条"）。

**踩过的坑（首次探针即抓出，已修）**：① 界面**不能**用 `foeMainTagOf` 判"主舰"——它把
`w{n}-foe-{k}`（k≥1）也算主舰（2026-09-09 为"第 2 艘主舰不当僚机"而放宽）⇒ A 族 3 艘杂鱼被判成主舰、
**阵形根本不生效**；改用「首舰 或 头目档」。② 拥挤梯队的血条若排在**行内**会撞上前排的条（探针实测
Δx=181 / Δy=22 重叠）⇒ 改为排到**编队下方**的堆叠区。

## 五、多波次增援：两种口径（**待船长定**，现取 ①）

船长 2026-09-11 对"是否按波再分一层"答「**分别看下差异**」，故本批做成一行开关
`RANK_BY_WAVE`（现值 `false` = ①），两种口径的逐卡读数（残兵 + 新一波同屏、贴脸距离）：

| 卡（波数） | ① 不分波（现值） | ② 按波分层（`true`） |
|---|---|---|
| `ano-gravekeeper` 坟场守墓者（2 波，每波 1 舰） | 两舰**同一梯队**（抬 0/0，y93/93），编队高 78 | 残兵基线、增援抬 72（y165/93），编队高 150 |
| `ano-maw-hunt` 噬口猎杀令（2 波；第 1 波 2 舰） | 两波的主体**同层**（抬 0/72/0，y165/93/165），编队高 150 | 增援整体再抬一层（抬 0/72/72，y165/93/93），编队高 150 |
| `ano-vault-sentinel` 穹顶守卫（3 波，每波 1 舰） | 同梯队（y93/93），编队高 78 | 残兵基线、增援抬 72（y165/93），编队高 150 |
| `ano-voidedge-warden` 虚海守望者（3 波，每波 1 舰） | 同梯队（y93/93），编队高 78 | 残兵基线、增援抬 72（y165/93），编队高 150 |

- **① 语义**：增援与残兵**同一梯队**（同角色同层）——画面读作"又一艘并入同一条战线"，编队不额外变高；
- **② 语义**：**第 n 波再抬 n×72** ⇒ 增援是**视觉上独立的第二梯队**（"从后方梯队压上"），代价是编队再高 72px，且
  该卡整局都停在这个更高的编队上（波序不随"当前第几波"回落）。
- 两种口径**血条都不重叠**（探针已对多波混排各跑一遍：330 对两两比对全过）。

## 七、已知取舍（如实登记）

1. **编队整体下沉 72px**：这是"前排在基线、后排抬高"的必然结果（后排顶对齐既有 `LAY.TOP`）；
   我方舰位不动，故敌编队的底线比改前低 72px（单舰编成不受影响）。
2. **改造前那处"多舰卡锚点不跟舰宽"的错位被修掉了**（船长「乙」裁决）：A 族 4 舰卡的主舰锚点左移约 120px，
   现在弹道/射程弧/血条对准实际舰体；**距离读数不受影响**（距离尺是米 → 百分比，与舰宽无关）。
3. **旧路径双僚机**（94 间距）的条走**堆叠区**（排在编队下方），不在各舰正下方——这是"185px 条放不下 94px 槽位"的
   必然折中（船长已批准该口径）。
4. **按波分层**（`RANK_BY_WAVE`）**待船长定**（见 §五）；现值 ①。
5. 无人机编队位（母舰上侧 `slots`）本批**不动**；无人机攻击阵位仍按敌舰中心 + 旧口径偏移。
