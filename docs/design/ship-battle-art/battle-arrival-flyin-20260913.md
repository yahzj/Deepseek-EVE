## 1. 船长口径（原话）

> 「我希望的实际上动画是，**舰船从屏幕外以减速的形式进场并落到舰船战斗位置**。
> 这里只影响动画。**不影响舰船实际位置**。」

## 2. 实现口径（四条，缺一不可）

1. **动的是舰船本体**，不是覆盖图形：我方列整列（`.app-bts-col.is-me`：舰名 + 舰体 + 三层血条同进）、
   敌方**逐舰**（`.app-bts-unit`）。**同批删除了原来那层"跃迁环覆盖层"**（见 §5）。
2. **只动 `transform` / `opacity`**（合成层，不触发重排）：舰船坐标（`lay.meLeft` / 逐舰 `marginLeft`）、
   编队几何、血条锚点、距离尺**一字不改**；动画终点恒为 `translateX(0)` ＝ 该舰的战斗位置
   ⇒ 动画卸载（窗口结束）时**无跳变**。
3. **起点 = 本侧屏幕外**：我方自**左缘外**、敌方自**右缘外**；位移由布局**现算**并写进 CSS 变量：
   - 我方：`-(lay.me.x + 舰宽/2 + 40)`
   - 敌方：`dims.W − lay.foe[i].x + 舰宽/2 + 40`（逐舰按各自机位算，斜向菱形两排一致）
   40px 是余量，保证起点完全落在 `overflow: hidden` 的泳道之外（任意窗口宽都成立）。
4. **节奏**：单舰 **950ms**、缓动 `cubic-bezier(.12,.75,.2,1)`（前快后慢、末段几乎停住再落位）、
   前 12% 快速淡入；逐舰**错峰 60ms**（`i × 60`）⇒ 编队依次跃入，末舰 ≤ 1130ms 落完。
   入场窗口仍为 `ARRIVAL_FX_MS = 1300`（战斗时钟口径，只演一次：中途退出再进战场**不重播**）。
   **入场期本动画取代**敌单位原有的挂载淡入（`app-bts-foe-in`）；此后**波次增援**（窗口已过）仍走原淡入。
5. **谁入场**（沿用第一次裁定的口径，本次未动）：**虫洞内 = 敌方**（洞里是它们的地盘）；
   **洞外**（悬赏 / 低安遭遇 / 教学）= **我方**。

## 3. 真机实测（无头 Chrome + CDP · 网页版构建 · 窗宽 1440）

| 场合 | 首帧（进场） | 末帧（落位） | 结论 |
|---|---|---|---|
| 洞外 · 我方（悬赏即时开战） | t=5ms x=**−217** · opacity 0 | x=90 | 起点在泳道左缘（0）之外 ⇒ 完全屏幕外；**回退 0 次**（单调减速） |
| 洞内 · 敌方（虫洞迎战 · 2 舰） | #1 x=1411（已在飞）/ #2 x=**1468** | 934 / 1021 | #2 起点 **> 泳道宽 1428** ⇒ 仍在屏外，**错峰可见** |

**落位零残余**：入场窗口后我方列 `getBoundingClientRect().x = 148.6` vs 元素 `left = 148.596px`；
敌方 #1/#2 = 934 / 1021 与布局逐字一致 ⇒ 动画终点确实回到战斗位置。

**负向验证（真红）**：临时摘掉 `is-arriving` 挂载 ⇒ 我方首帧 x=**36**（在屏内，"从屏外飞入"消失）、
敌方首帧距落点仅 16px（只剩原淡入）⇒ 探针确实在测飞入本身；还原后读数与改前逐字一致。

**四连**：typecheck 四包 0 错 · core 113 文件 / 1149 用例全绿 · `content:check` ✅ · desktop build ✅。

## 4. 已知边界

- 若将来窗口宽度小于"舰宽 + 40px"（约 220px 级），起点位移仍成立（余量固定、不随窗口缩）；
  但那种宽度下泳道本身已不可用，不在验收范围。
- 本动画与**阵形几何**无关：第二排的右移/下移走 `marginLeft`（不是 `transform`），故两者不打架
  （实测第二排落位 x 与布局一致）。
- 不做"拖影 / 尾焰拉长 / 落点闪光"等附加表现；船长如要另议。
- **极端时序（正常流程到不了）**：动画从**战场界面挂载**起算，而 `is-arriving` 只挂到「战斗时钟 ≤ 1300ms」
  为止 ⇒ 若界面在开战 **350ms 之后**才挂载（此时 950ms 动画跑不完窗口），飞入会被窗口截断、舰船瞬移到落点。
  正常两条入口都是**点击即刻挂载**（悬赏「出发」/ 虫洞「迎战」⇒ 挂载时 elapsed≈0），实测首帧 t=5ms，
  故不触发；**若日后出现**（例如别的入口在战斗中段才把战场界面挂上来），把窗口口径改为"**按挂载起算**"
  或把 `--arrive-ms` 压到剩余窗口内即可（一行级改动，本次按现状接受、如实登记为边界）。

## 5. 被取代的旧口径（作废留档）

同日先落过一版 **`5e289e35`「跃迁入场」**：在泳道里叠一层绝对定位 SVG（三层同心跃迁环 + 上下各 5 条
向心尾迹 + 出场闪点），锚点 = `top: 50%`（泳道垂直中线）+ `left: lay.meLeft | lay.foeLeft`（列左边缘）。

**为什么作废**：① **方向不符**——船长要的是"舰船本体飞入"，不是"原地画一圈环"；
② **位置实测也不对**——舰列钉在泳道顶部 `LAY.TOP`(54px)，而该层锚在泳道中线 ⇒
真机实测**洞外偏低 234px / 偏右 37.5px、洞内偏低 142px**（偏差随泳道高度变化）。

**处置**：该覆盖层（`.app-bts-warp` 与 `app-warp-ring/streak/flash` 三条关键帧）**整体删除**，
源码与构建产物里已无任何规则；`docs/roadmap.md` 同日那条已就地标注"口径已被取代"作过档记录。
