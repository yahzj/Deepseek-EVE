# 战斗画面「舰种体积」（舰身大小随舰种档，2026-09-11 船长定；状态：**已确认并实现**）

> 船长 2026-09-11 原话：「战斗动画中，能否让舰船动画的体积和舰船种类挂钩？」
> 同日经集中提问 → 中文设计总结 → 显式「确认」后实现（本文件 = 已确认口径的落地稿）。

## 一、口径（船长确认项，逐条）

| # | 事项 | 裁定 |
|---|---|---|
| ① | 体积阶梯 | **T1 110 / T2 140 / T3 170 / T4 205 / T5 240**（px，舰身显示宽） |
| ② | 锚点 | **T3 = 170 = 改造前的统一主尺寸** ⇒ 巡洋舰与今天逐像素一致，其余按档上下 |
| ③ | 僚机 / 轻装 | 同档 × **0.53**（＝改造前 90/170 的既有比例，语义"轻装更小"保留） |
| ④ | 生效范围 | **敌我双向**：玩家取 `ShipDef.tier`；敌舰取编成条目所引舰级的 `FoeShipDef.hullClassTier` |
| ⑤ | 旧路径卡 | 威胁推导路径的 13 张卡（D/E/G 三族 9 张 + 遭遇模板 4 张）**无舰种档** → 回落改造前的 170/90；船长裁定「**延后**，其他种族在二号处补完」 |
| ⑥ | 溢出保险 | 一行宽过本窗口能给敌列的空间时**等比收缩**（下限 0.4；间距不参与收缩） |

阶梯依据 = 仓库既有的「舰种 = 质量分级」五档（`packages/data/src/hullClass.ts` 的 `HULL_CLASS_NAME`：
护卫舰 / 驱逐舰 / 巡洋舰 / 战列舰 / 旗舰），因此"大船看着大"与图鉴/船卡的档位标注同源，不是另立一套。

## 五、已知取舍（如实登记，供船长裁决）

1. **旧路径卡延后**：D/E/G 三族与遭遇模板仍 170/90。等二号把各族舰级补齐（`AnomalyDef.ships`）后，这些卡**自动**获得舰种体积，
   无需再改界面代码——反查器按 tag 走，卡一挂舰级就生效。
2. **无人机的"目标舰外推"是配套项**（把旧口径的 42~68px 阵位随目标舰变大外推）：
   体积放大后敌舰半宽变大（T4 巨兽 205 → 半宽 102），若阵位仍按 42~68px 摆，机群会**压在敌舰舰体上**。
   现口径 = `42~68 + max(0, (舰宽 − 170) / 2)`（敌舰不增大时不内收）；T3 目标舰逐像素不变。
3. **僚机档阶梯目前是"待用能力"**：现内容 13 张舰级路径卡均为"主体 + 同型主体"编成，**没有 `escort: true` 条目**，
   因此 58/74/90/109/127 这组僚机档只有旧路径（回落 90）与测试用例在走；二号补 D/E/G 舰级时写僚机条目即生效。
4. **4 单位编成在贴脸瞬间的轻微重叠**：头目 T3 + 3×T2（灰霾/蜃影/赤环）行宽 602，比我方为 **T1 小舰**时
   贴脸瞬间的可用半宽多约 10px ⇒ 外翼僚机与我方舰体最多约 10px 视觉重叠（T3+ 我舰无此现象）。
   若船长目测觉得碍眼，可选项：把这三张卡的杂鱼档下调，或给"贴脸"档单独收一点行宽（都属另行确认的改动）。
5. **本批不动无人机编队位**（母舰上侧 `slots`，绝对 px）：母舰变大后编队位仍在舰体上方，观感可接受（无人机会"骑"在甲板上方）。
6. **敌列宽由内容撑出（CSS `max-width: 340px`）**：故溢出预算按**窗口**算（`W − 左右留白 − 我列宽 − 最小间距`），
   不吃 `foeW` 实测值——否则"行越大 → 列越宽 → 预算越大"或反之会自我反馈。收缩只在本窗口放不下整行时发生。
