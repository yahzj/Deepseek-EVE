# 无人机可被击落（2026-09-10，**已确认并实施**）

> **状态：船长已确认并实施**。船长指令（原话）：「调整完后开始实施无人机可被击落。」
> 损失持久性**船长选乙：永久损失（耗材流）**——被点防击落的无人机战后从清单永久扣除，需重新补充。
> 定位契约（`docs/design/drone-roles-20260910.md`）已先落地：四型的血量/闪避/抗性现在**真正参与战斗**。
> 经办：引擎与平衡 = 二号；表现层（机群递减/被击落演出）= 三号（待对接，见 §六 数据契约）。

## 一、要解决的问题

现状：无人机是"不消耗、不被击落"的纯火力模块——四型的生存包（血厚/闪避/脆）**没有任何战斗意义**，
无人机流因此只有"火力/射程"一个维度，缺一个天然制衡（这也是 C6 评估里无人机流偏强的根因之一）。

目标：让敌方**点防**真实射击机群 —— 机群规模随战斗递减、DPS 随之下降；
攻坚机靠血厚硬扛、侦察机靠闪避、哨戒机靠距离（在点防射程外安全）。

## 二、机制设计（拟）

### 1. 敌方点防（Point Defense）

| 概念 | 口径 |
| --- | --- |
| 点防射速 | `pdRate`（次/秒，每艘敌舰各自结算；敌方多舰 = 多份点防） |
| 点防命中 | `pdAcc`（基础命中率，与敌方通用命中加成叠加） |
| 点防威力 | `pdDmg`（每次命中对**单架**无人机的单发伤害，逐层抗性消费） |
| 点防射程 | `pdRangeM`（只有在该距离内的放飞无人机才可能被点防打到） |
| 强度来源 | 由异常点 `threat` 派生（balance 参数区间，首轮给薄/中/厚三档），后续可按敌族给"点防强/弱"性格 |

### 2. 逐架生存与击落

- 放飞时每架无人机按机型 `DroneDefense` 生成**独立血量池**（盾/甲/结构 + 三系抗性 + 闪避）。
- 点防每次结算：随机挑选一架**当前存活且在点防射程内**的无人机 → 按现成 `hitChance` 口径掷命中
  （守方 = 该机型闪避，攻方 = 敌点防命中）→ 命中则按 `pdDmg` 走三层消费。
- 血量归零 = **本场击落**：该架立即停火（不再产生弹道/伤害），同机型其余架不受影响。

### 3. 与定位的对应关系（设计意图）

| 机型 | 点防下的表现 |
| --- | --- |
| 侦察机（闪避 0.45 / 血 19） | 靠闪避躲——命中率最低，但一旦挨打就碎 |
| 战斗机（0.25 / 40） | 中庸，机群主力 |
| 攻坚机（0.10 / 97） | 几乎必被打中，但**要打很多轮才掉一架**——耐消耗的攻坚平台 |
| 哨戒机（0.18 / 23） | 脆，但**常在点防射程外**（5 km 射程 vs 点防 1.5~3 km）——靠距离活命 |

### 4. 反制手段（本轮**不做**，观察后再定）

候选：无人机电子对抗装置（降点防命中）、中继天线顺带削点防、或战术导控给"抗点防"。
先看首轮数据，避免一次上太多变量。

## 三、损失持久性（**关键取舍，请船长选**）

| 选项 | 内容 | 影响 |
| --- | --- | --- |
| **甲（推荐）** | **本场折损、战后归队**——被击落的无人机只在本场消失，战斗结束返回清单 | 只影响单场表现与战术（长卡更吃力、重复清剿更谨慎）；经济不受冲击；实现干净、易回滚 |
| **乙** | **永久损失**——战后从清单扣除对应架数，需重新购买/制造补足 | 最硬核、最有分量；但会把无人机流变成"耗材流"，与"免弹药、免货舱"的定位冲突，且需要同步做经济补偿（降价/回收/修理）与存档字段 |
| **丙** | **可修复损失**——战损进入"待修"状态，消耗修理组件或回港修复；未修复不能出战 | 折中方案；需要新增状态字段与工业/维修链路，工程量最大 |

**我的建议：先甲**（本场折损），把乙/丙留作后续独立批次——理由是"点防机制本身"已经能带来
"机群递减、攻坚耐打、哨戒靠距离"的全部战术变化，而永久损失会立刻冲击经济与重复清剿体验，
宜等点防数值稳定后再决定要不要加。

## 五、平衡目标（首轮数值口径，需船长点头或改数）

| 项 | 建议首轮 |
| --- | --- |
| 点防强度 | 威胁 <50：接近 0；50~80：薄；80~100：中；>100：厚（具体系数我出表） |
| 期望效果（威胁 96 穹顶守卫） | 无人机流胜率自 **100%** 降到 **60~80%**；交火时长 +20% 左右 |
| 机群损失量级 | 满编 D3（10 架）在硬卡损失 **2~4 架**（约 20~40%），软卡 0~1 架 |
| 不变项 | 炮流/激光流不受影响（点防只打无人机） |

## 七、实测（`npm run battle:pd-tune`，满技能，5 种子，王鲭 4 高槽）

| 配置 | 噬口猎杀令(80) | 坟场守墓人(88) | 穹顶守卫(96) |
| --- | --- | --- | --- |
| **D3 满编（4 猎鹰 + 6 雷鸥）** | 100%/41s/**0.8 架** | 100%/27s/**1.2 架** | **60%**/67s/**4.2 架** |
| 满舱 16 猎鹰（全攻坚机） | 100%/37s/**0 架** | 100%/23s/**0 架** | 100%/59s/**0 架** |
| 射程向（甲板+导控+中继×2，雷鸥 9km） | 100%/47s/**0 架** | 100%/41s/0.2 架 | 100%/66s/**1.0 架** |
| 炮流对照（纯炮 4×MK3） | 100%/76s/0 架 | 100%/68s/0 架 | 100%/104s/0 架 |

**四型定位在战损上完整兑现**：
- **攻坚机（97 血 / 闪避 0.10）**：满编 16 猎鹰在硬卡 **0 损失**——几乎必被打中，但打不穿；
- **哨戒机（23 血 / 闪避 0.18）**：D3 里被击落的**绝大多数是雷鸥**（硬卡 4.2 架全是它）——脆；
  但一旦装上中继天线把射程拉到 9 km，**跑到点防射程外**，硬卡损失降到 1.0 架——靠距离活命；
- **战斗机（赤鸢）**：梭鱼 D2 行显示中等损失（硬卡 3.0 架，多为赤鸢）——中庸；
- **侦察机（0.45 闪避）**：点防命中率仅 0.10，几乎打不中（数据里最少被击落）。

**经济口径（战损估值 ÷ 该卡奖励）**：噬口 **0.9%**、坟场 **1.0%**、穹顶 **2.7%**——
「有痛感但不劝退」：硬卡一次约损失 4.1 万 ISK 的无人机（该卡奖励 150 万），
但机群规模会随连打逐步下滑，需要回港补货。

**C6 结论随之更新**：无人机流对硬卡从"稳赢"变为"**60% 胜率 + 20~40% 机群战损**"，
炮流（0 战损）在长盘经济上重新具备优势——这正是此前缺失的制衡。

## 八、表现层数据契约（给三号对接）

引擎已就绪的字段，UI 可直接消费：

| 字段 | 位置 | 含义 |
| --- | --- | --- |
| `arcs.me[].count` | `battleArcsFor` 返回 | 该机型**存活**架数（被击落后自动减少；合并条目不变） |
| `arcs.droneLost` | `battleArcsFor` 返回（可选） | 本场已击落架数（机型 id → 架数） |
| `fx[].droneDown === true` | 战斗事件环 `battle.fx` | **该架被点防击落**的事件（`src:'drone'` + `artId` + `side:'me'`），UI 据此出小爆炸/坠落演出（视觉物件按"一律 SVG 线稿"约定） |
| `state.droneLossNotice` | 结算后写入 | 一次性提示（已接 toast）：机型与架数摘要 |
