## 顺序与范围

1. 复跑 11×11 活动切换判据、活动实际入口、停止/取消/退料/返航、虫洞与战斗锁定、活动栏跳转。
2. 比对主控活动栏、左上角舰船状态窗、活动动画窗及最小化/导航切换行为。
3. 隔离浏览器量两套布局的手机竖屏/横屏、各页与弹层几何、控件可达和连续视口事件；不把截图当观感验收。
4. 明确证据的同域小修先补红测试，再修与验证；需要改版式的项目集中给船长确认。

## 初步证据（待测试）

- `App.tsx` 手机旋转 `update` 在 `zoomed` 判据前先采纳宽度变化；捏合改变 visualViewport 宽度时仍重排，与既有“捏合期间尺寸冻结”相反。
- `sceneOfShipwin` 没有主控船低安遭遇战分支，活动门禁却明确锁定该战斗；可能出现作业动画与交战状态不一致。
- `activityKindOf` 只管理采矿/打捞/长途运输/扫描虫洞四个动画窗口；其余主控项目在活动栏显示，不把“没有新动画”擅判漏洞或自动新增。
- 原活动窗口收起/打开按 null→kind 上升沿；直接切不同 kind 会保留最小化状态。是否每次切换都展开是体验政策，本批不凭喜好修改。

## 已复现并修复的同域缺陷

- 修前生产入口 3 条红：主控遭遇战场景仍为 work-mine；捏合时旋转层缩放 0.703→0.468；键盘布局高 300px 导致退出旋转。
- `ShipStatusWin.tsx` 补主控遭遇战场景优先级，副船遭遇不影响主控；不改活动门禁、取消和奖励。
- `App.tsx` 捏合时宽度变化不越过尺寸冻结；方向优先读物理屏幕 API，避免软键盘改布局视口后误判横屏；保留既有 1200 逻辑宽、地址栏滞回与双指缩放。
- 初轮活动邻域 44 条通过；新增显示与视口 6 条中修前 3 红，其余 3 条通过。完整页面几何仍待验证，不能扩称所有手机版已修。

## 手机适配第一轮

- 沿既有窗口样式修复操作行/搜索行挤压、顶层页签多行吃掉面板、舰队筛选区过高、通讯正文列最小宽度及“前往”被裁切。
- 只在 `pointer: coarse` 生效：顶部功能页签单行横滑、面板标题操作区允许换行和内滚，正文在二级面板滚动；触屏输入字号下限 16 CSS px，保留双指缩放与一级页不滚。
- 从 `styles.css` 重生成两套样式，冻结基准 `_baseline-main.css` 未修改。没有改日志布局、没有缩小按钮/字体来掩盖内容缺失。
- 同级参照：现有手机战斗图例单行横滑、`.wui-panel-body` / `.app-win-body` 内滚、公共面板标题和设置按钮族。
- 批次范围依据：船长明确要求核查全部主控活动显示，允许在活动域核查中修正舰船状态窗的必要显示分支；手机适配只修改共享外壳/样式，不跨入舰船装备或玩法数值。
- 技能依据：ui-ux-pro-max 的 ux 域 `Viewport Meta / width=device-width initial-scale=1`、`Viewport Units / account for mobile browser chrome`，支持视口稳定与操作可达；不因此推翻现有自动旋转和双布局裁定。
- 活动与舰船状态显示同域核查，手机约束只改共享样式/入口；不跨玩法模块改逻辑、取消代价、奖励或数值。

## 下一轮手机整体布局建议（待确认）

- 只调整触屏手机，桌面 classic/modern 外观与本机偏好继续保持；不修改冻结样式基准。
- 手机日志改为按需打开的抽屉，默认不占主区；收起/展开入口常驻且可触控，日志完整可读，不删除信息。
- 小横屏导航紧凑排列并保持全部页面可达；不把导航/日志与主区平分到只剩十几像素，不把全界面继续缩小。
- 页面功能页签仍走稳定单行横滑；标题、操作区和正文明确分工，滚动放二级窗口，窄屏长名/英文换行。
- 手机弹层按旋转后的逻辑宽高约束；固定操作区不被内容推走，正文内滚。不同类型弹层分批复核，包括装配、交易、虫洞和战斗宿主。
- 视口层保留双指缩放；转屏、地址栏、输入键盘分别处理，不用禁止缩放来掩盖问题。键盘期间控件可见性需真机复测。
- 验证门槛：两布局、两语言、320/390 竖屏与 568/844 横屏，实际触控点和滚动可达；不只扫静态盒子，观感由船长验收。
- 此方案改变手机端旧版日志/导航的空间分配，不凭“优化”授权自行推翻历史布局；请船长确认后再落码。
