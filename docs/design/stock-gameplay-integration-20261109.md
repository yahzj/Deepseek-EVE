## 一、核心原则：钱说话

**取消「行为信号 → 服务器算景气 → 加涨跌」的贴标签逻辑。** 8 家上市公司成为游戏内市场的真实交易对手：玩家与市场的每一笔成交，都记入对应公司的账本——玩家买入的钱是公司营收，玩家卖出的货是公司采购支出。公司赚不赚钱直接决定股价。

旧联动的问题（船长裁定「联动逻辑还是有问题」）：公司是虚构的，与游戏世界没有任何业务往来，行为信号与股价之间是人为贴的标签。新逻辑只有一条因果链：**真实交易 → 公司利润 → 股价**。

## 三、财报与股价

每家公司周期结算：

```
营收 = 玩家买入总额 + 玩家间交易税
成本 = 玩家卖出总额 × 收购折算率 + 基准运营成本
毛利 = 营收 − 成本
```

**毛利环比 vs 近 4 周均值 → 内在价值锚漂移**（单周上限 ±2%），股价跟随锚点。财报通过快讯公开：「星舰重工周报：弹药销售额环比 +34%，营收创新高」。

负向联动自然出现（不需要硬编码）：

| 玩家集体行为 | 公司利润方向 | 股价方向 |
|---|---|---|
| 大量打怪、买弹药修理 | 星舰重工 / 星港维修营收 ↑ → 利润 ↑ | 涨 |
| 大量卖矿 | 星际矿业采购支出 ↑ → 利润 ↓ | 跌（供给冲击） |
| 大量买船 | 星舰重工营收 ↑ | 涨 |
| 自给自足不交易 | 无流水 | 不动 |

## 四、行为传导（打怪/采矿/制造/运输）

打怪不直接发信号，传导链：

- 打怪 → 弹药消耗、维修、补给 → 市场补货 → 星舰重工 / 星港维修营收 → 股价涨。
- 采矿 → 卖矿 → 星际矿业采购成本 → 利润受压 → 股价跌（玩家赚矿钱、能源股承压）。
- 制造 → 买材料/蓝图 → 对应公司营收。
- 运输 → 完成订单 → 星门物流营收。
- 玩家自给自足（自造弹药、不参与市场）→ 不影响股价，符合真实经济逻辑。

---

## 五、资本联动

- 游戏 ISK ↔ 交易所现金双向流动（已有入金/出金）。
- 股市收益来源 = 公司利润增长（玩家买股票 = 投资公司，公司赚得多 → 股价涨 → 股东收益）。
- 闭环：游戏内赚钱 → 股市投资公司 → 公司继续向市场供货 → 其他玩家消费 → 公司利润 → 股价。

## 六、数据与上报

- 客户端按周期聚合上报与公司的成交：`{公司, 买入金额, 卖出金额, 成交笔数}`（非击杀数、非行为计数）。
- 游戏内本地记录流水（留痕审计），服务端按全服聚合出财报。
- 上报与游戏内市场机制解耦：市场规则不动，只增加归属统计。

**防作弊裁定（2026-11-09 船长裁定「全部砍掉」）**：

- 不做存档交叉校验——单机游戏改档防不住，设计目标不是防作弊而是「让玩家的钱真实决定股价」。
- 不做单账号贡献封顶——全服活跃玩家仅数十人，封顶会误伤活跃玩家，且「大玩家坐庄」是 economy-pvp 已确认玩法。
- 不新增操控税——市场已有贸易税（`market/holdings.ts` `netAfterTax`）与买卖价差（`market/pricing.ts` 单边价差），自买自卖天然亏钱。
- **只保留流水留痕**：财报计算本来就需要流水记录，顺带可审计。将来玩家规模扩大再谈风控。

**服务端已交付（2026-11-09，全部在 `exchange-server-go`，未碰游戏本体）**：

- `POST /api/exchange/company-flow`（鉴权）：游侧批量上报 `{"flows":[{"good","side","amount","count"}]}`；服务端按前缀规则归属公司、按 UTC 日累计（`exchange_company_flows`）。
- `GET /api/exchange/companies`（公开）：8 家公司 + 当前锚点偏移 + 最近周报。
- `GET /api/exchange/company-reports?limit=`（公开）：最近周报列表。
- 周报结算：每回合检查跨周，从上次检查点补结算到上周（单次最多 8 周）；无流水周只前移检查点。
- 股价影响：公司内在价值锚 = 静态 Anchor × (1 + 偏移)，偏移按毛利环比漂移（单周 ±2%、总 ±20%、每周回归 5%）；做市参考价与价值人格锚点均读动态锚。
- 财报快讯：写入 `exchange_news`（persona `company`），游戏内通讯与股市快讯共用同一快讯源。
- 客户端：简单界面右栏新增「企业」面板（公开数据，游客可见）；`HttpExchangeClient.getCompanies()`，Mock 提供演示数据。
- 开关：`EXCHANGE_COMPANY_ENABLED`（服务入口默认开）。

**游侧接线（2026-11-09 船长批准「把市场成交接进账本」后完成）**：

- `features/market/MarketDetail.tsx`：`doBuy` / `doSell` / `doSellAll` 三处成交成功分支调用 `reportCompanyFlow(goodKey, side, 钱包差值)`——买入按实际支付、卖出按净到账（含部分成交与即时成交部分），不改任何玩法逻辑与数值。
- `features/exchange/companyReporter.ts`：流水队列 60 秒/满 20 条批量上报，失败重试，游客不上报；上限 200 条。
- 财报快讯复用现有快讯通道，无需改动（服务端已写入同一快讯源）。
- 第一版只采集「即时成交」；限价挂单的延迟成交暂不上报（其对手方的即时成交已计入对应公司流水）。

## 十一、交易所一键关闭（2026-11-09 船长令）

> 船长原话：「如果服务器没有了，我希望有一个一键关闭股票系统的功能」

**机制**：客户端 `features/exchange/availability.ts` 周期探测交易所公开端点 `/api/exchange/meta`（60 秒/次，5 秒超时）；**连续 3 次失败**判定交易所不可用，主导航「股市」入口与活动栏「交易所」组自动隐藏；服务恢复后下一次探测成功即自动出现。首次探测未完成前按「可用」处理，避免入口闪现。

**一键操作**：停掉交易所服务（`sudo -n systemctl stop whale-exchange`）或断开其端口——玩家端入口在约 3 分钟内自动消失，无需发版、无需服务端改动；恢复服务后入口自动回来。

**探测路径注意**：不能用 `/health`——nginx 只把 `/api/exchange/` 转发给交易所（8788），根路径 `/health` 落到 Node 主服务（8787），Node 活着时会永远 200、测不出交易所死活。

**改动面**：`features/exchange/availability.ts`（新增）+ `App.tsx` 导航过滤 + `ActivityBar.tsx` 交易所组条件渲染，均在入口层，不动玩法逻辑。
