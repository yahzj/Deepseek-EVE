# 工作文档 · 装备库排序（按武器攻击类别 · rank 从低到高）（2026-09-24 · 三号）

> **状态：进行中**（已落码并过闸门，待船长真机验收观感）
> **船长原话（照抄）**：「**物品仓库页面的装备（装备库）排序有问题，现在的排列很混乱，希望按照武器攻击类别，rank 从低到高排序。**」
> ＋（方案回话）「**按你推荐来**」。

## 一、病根（用真档实证，不是推断）

装备库原先直接 `Object.entries(state.moduleBay)` 渲染 ⇒ **顺序 = 获得/存盘顺序**，既不分类别也不分档位。
拿船长真档（41 种）排一遍，排序前的头几行就是"跳跃"的：`动能稳定器 MK3 → 射速计算机 MK3 → 巡航导弹架 MK3 →
目标锁定阵列 MK3 → 护盾充能力场装置 MK3 …`——玩家看到的正是这个。

## 二、现行口径（船长选定「按你推荐来」）

主键 **① 攻击类别**：**动能 → 爆破 → 能量**（与战斗画面 `DMG_ORDER` 同序）
次键 **② 档位（rank）从低到高**：

| 段 | 规则 |
| --- | --- |
| **基础型号** | 民用（-1）→ 基础件（0）→ MK1（1）→ MK2（2）→ MK3（3）→ 异星原型（3.5）。**档位取自 id 的单点规则**（`civ` / 无后缀 / `-1` / `-2` / `-3` / `proto`），**不靠中文名正则**（改名不影响排序） |
| **势力 / 虫洞专属件** | 没有 MK 档 ⇒ **统一排在该类别末尾**，内部按**名义火力（单发 × 门数 ÷ 装填秒）由低到高**（同值再按 id）；非武器件走槽位段 |
| **非武器件** | 排在武器之后，按核心既有的**槽位展示顺序**（`MODULE_SLOTS`）分组，组内按名称 |

## 三、实现（单点 + 接线）

- 新增 **`apps/desktop/src/renderer/src/ui/modOrder.ts`**（单点）：`modFrameOf` / `nominalDpsOf` / `modOrderKey` /
  `compareModOrder` / `sortModEntries`；
- **`pages/ItemsPage.tsx`** 只改一行取数：`modRows = sortModEntries(Object.entries(state.moduleBay).filter(…), engine.ctx)`；
- 只决定**展示顺序**：不动数据/数值/存档，也不动筛选（筛选仍在 `itemSubs.ts` 单点里）。

## 四、契约与读数（新工具 `npm run mod:order`）

`tools/mod-order-check.ts` 用**真排序函数**排全目录并核对四条：① 武器段在前；② 同类别档位单调不减、
且专属件一律在基础型号之后；③ **MK1/MK2/MK3 每类齐备**（**民用档只有动能系有**，故不强制）；④ 非武器件槽位顺序不回退。
同时把三类武器的完整顺序摊出来当**验收表**（`--all` 连非武器件一起印）。

**工具第一次跑就抓出两个真错**（留档）：
1. **虫洞专属「近防炮 MK1」**（`mod-wh-e-pd`）被纯 id 规则判成基础档 MK1、插进了基础段 ⇒
   改为**武器件优先判专属**（`mod-lair-*` / `mod-wh-*` 且带 `damageType`）；
2. 契约第一版要求每类都有"民用"档 ⇒ 被自己的工具判红（爆破/能量系**本来就没有**民用件）⇒ 改为只强制 MK1~MK3。

## 五、真档实测（一次性探针，用完即删）

拿船长真档 41 种装备库排一遍：**排序后**的顺序为
`攻坚炮台 MK3·动能型 → 近防炮 MK3 → 守墓者长炮 → 劫掠者转管炮 →`（动能）
`巡航导弹架 MK3 → 掠袭导弹巢 →`（爆破）
`攻坚激光炮 MK3 → 酸液喷吐器 →`（能量）
`精密采集器 MK3 → 赃物强化舱 → 折叠货舱扩展 MK3 → 打捞器 MK3 → 护盾充能装置 MK3 → …`（非武器件，按槽位）
——**条目数 41 → 41 守恒、集合一致**（只换顺序，不丢不增）。
