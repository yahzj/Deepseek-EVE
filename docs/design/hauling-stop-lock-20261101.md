# 运输停止与在途货量锁定

状态：2026-11-09 按船长原定口径恢复即时停靠修复并补回归，随0.1.5发布；离线战斗结算规则未修改。

船长原话：「我发现停止长途运输后，不会停下。运输途中不应该可以调整承运量。以及离线时的战斗要怎么办」。2026-11-09补充裁定：「之前特意设置过，取消长途运输后立刻回港，方便玩家做别的事，按照这个修正」。本次仅修运输域，保留中断无本段运费、实体货物不变和到站停止规则。

## 现场与修复

- 长途运输“停止”取消本段虚拟运量并立即停靠回本段出发站，不创建返航航段；本段未完成则放弃本段运费，实体货物不改。
- 独立的“到站后停止”仍完成并结算当前段，到站后不再接续下一段。
- 遭遇战期间请求停止先写入既有`abortAfterBattle`状态；战斗与损伤正常结算后取消运输、停靠回原出发站，不进入普通返航行程。旧在途状态若已处于`returning`，手动停止同样立即停靠。
- 当前开战时，停止请求挂在既有战斗/运输状态上；先正常结算战斗与战损，再即时停靠运输起点，清除战败结算可能创建的普通返航行程；战斗胜负、战利品与损伤仍照常结算。
- 继续保留在途禁止调整承运量、停止二次确认及“到站后停止”入口；停止成功提示改回即时停靠表述。
- 按船长新裁定移除卡片在途调整入口、弹窗调整分支与桌面引擎`setHaulingLoadNow`。出发前设置货量，停运靠站后重新开始才能更改。已存的`targetM3`仍保留承运和兼容用途，不增加迁移字段。
- 本次停止成功提示复用即时停靠日志`core.hauling.019`；遇袭时另用现有`ui.industrial.008`提示航程暂停到战斗结算。不新增英文文案。

## 离线现状

正式`simulateOffline`调用同一`advanceGame`；运输按航段边界、事件时点和战斗步长交替推进。遇袭真实模拟，战斗期间暂停运输计时；战胜并具备续航条件才继续，败退/沉船/无法修复则停运返港。战斗配置和损伤随档，未结束的战斗上线接续。不是离线免战或重新抽签。

当前离线简报缺乏运输遇袭专门汇总，只有总收支和少量日志摘要，最后战报会被后续战斗覆盖。拟建议增加遇袭/胜负/损失/补给/运输交付与停运原因摘要，需先交船长确认，不在本次擅自新增。
