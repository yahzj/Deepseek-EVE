# 存档丢失防线：浏览器不给写时必须让玩家看见（2026-09-25）

状态：**已实现 · 待船长验收**（真机结论仍需那位玩家在 Safari 上复测）
船长原话（照抄）：
- 报障：「**玩家反应，他的macbook关掉游戏后存档就丢失了**」
- 追问后确认：「**是Safari ，下午玩的，这会发现没存档了。**」
- 裁定：「**按你推荐来**」（＝ 甲＋乙＋丙＋丁 全做）

## 一、根因（两层，第二层才是我们的责任）

**玩家侧（机制）**：MacBook 上只有**网页版**可玩——本仓没有 macOS 安装包
（`apps/desktop/electron-builder.yml` 只有 `win:` 目标，`release.yml` 只跑 `--win`；网页版由
`.github/workflows/pages.yml` 自动发到 GitHub Pages）。网页版的存档存在**浏览器 localStorage** 里
（`game/storage.ts` 的 `localStorageBridge`，键 `whale:idle:save`，备份同处）。
时间线（下午玩、当晚没）**排除了 Safari 那条「7 天不访问清站点数据」**，指向"写入根本没落地"：
**隐私窗口**（老版 Safari 里 `setItem` 直接抛配额错；新版给会话级存储，关窗即清）或
「**阻止所有 Cookie**」/禁用站点数据。

**我们侧（放大器，四条）**：
1. **写失败是静默的**：`setWithBudget` 吞异常 → `persist()` 返回 false，而自动存档 **130+ 处全是
   `void this.persist()`**，返回值没人看；只有手动点「保存」才弹「保存失败！」。
2. **启动没有存储体检**：全仓原本没有 `navigator.storage.*`，也不识别隐私窗口/禁用站点数据。
3. **网页版有自己的入口**：`web/src/main.tsx` 与桌面 `apps/desktop/src/renderer/src/main.tsx` 各写一份启动序列。
   本批第一版把体检只加在桌面入口 ⇒ **网页版（正是 Safari 玩家走的那条路）等于没体检**，
   设置里显示"没量到"。那个文件里本来就写着「网页版有自己的入口：桌面入口改了这里也必须改」——已经漏过一次。
4. **读档抛错会被静默盖掉**：`engine.start()` 里读档抛错就 `createInitialState`，紧接着 `persist()`
   与 15 秒心跳把新档写回去 ⇒ 旧档即使只是一时读不出来也会被覆盖。

## 二、修法（甲 · 乙 · 丙 · 丁）

| 条 | 内容 | 落点 |
| --- | --- | --- |
| **甲** | **启动存储自检 ＋ 明示告警**：写-读-删一个体检键（桌面端改走只读 IPC，绝不碰真档）；不通 ⇒ 弹一次玩家可见告警 ＋ 设置里显示状态；**自动存档失败也走同一条提示**（每类每局一次） | `game/saveGuard.ts`（新）· 设置面板「存储状态」行 |
| **乙** | **申请持久化存储**：`navigator.storage.persist()`（Chromium 系生效、Safari 静默跳过）＋ 设置里显示「已获/未获持久保存」 | `game/saveGuard.ts` |
| **丙** | **关页前补一次落盘**：`pagehide` ＋ 切到后台（`visibilitychange → hidden`）各 `persist()` 一次（自动落盘是 15 秒一拍，关窗时最后一段本来会丢） | `App.tsx` |
| **丁** | **防覆盖**：读档**抛错**（≠"没有档"）⇒ **挂起写入**（首次落盘与心跳都不写），弹告警，放行入口 = 设置 → 存储状态 →「允许写入存档」 | `engine.ts` 的 `saveWriteState()` / `allowSaveAfterLoadError()` |

**顺带收口（防第 3 条再犯）**：两个入口共用的启动动作抽成 `game/boot.ts`
——`prebootRenderer()`（布局样式/宇宙背景/配色）与 `startGameEngine()`（**先体检再 start**），
两个入口都只调它们；以后新增启动动作只改那一个文件。

## 三、验证读数（注入故障量出来的；`npm run save:guard-check`）

| 场景 | 告警条 | 设置「存储状态」 | 结果 |
| --- | --- | --- | --- |
| ① 正常（能写） | 无 | 存档在本浏览器里 · **可写** · 未获持久保存 | 体检键用完即删（`whale:idle:storage-probe` = null） |
| ② 浏览器不给写（`localStorage` 全抛错） | 「本页当前无法保存进度。请换一个普通窗口重新打开本页；想留退路请定期「导出存档」。」 | 存档在本浏览器里 · **不可写** | 不再静默：告警弹出、本局不写档 |
| ③ 旧档读不出来（读主档键抛错、体检键正常） | 「旧存档读取失败，已暂停写入，避免覆盖旧档。可在「设置 → 存档」里允许写入，这会另起新档。」 | …· **已暂停写入（旧档读取失败）** ＋ 放行按钮 | **等 20 秒跨过 15 秒心跳，旧档原封不动** |
| ④ 设置里点「允许写入存档」 | 「存档已写入本地。」 | 回到 可写 | 新档写入成功 |

（③ 第一版探针量出"旧档被改写"，查出来是**探针自己的取数竞态**：先让应用跑起来再埋哨兵，
被应用启动时的落盘盖掉。改成"文档开头就埋哨兵 ＋ 堵住读取"后复测通过。）

## 五、边界与待办

- **Safari 不支持 `navigator.storage.persist()`**（乙对它无效）；Safari 侧真正管用的是甲（让玩家当场看见）
  与"换普通窗口 + 定期导出"。
- Chromium 系 `persist()` 按"站点参与度"授予，首次可能拿不到（读数如实显示"未获持久保存"）。
- **戊（设置里加一句网页版存档说明）按船长"按你推荐来"未做**——状态行已经把事实摆在设置里；要加请说。
- **真机复测清单（请转达那位玩家）**：
  1. 用**普通窗口**打开游戏，进「设置 → 存储状态」，看是否显示「可写」；
  2. 若显示「不可写」或不弹任何东西仍丢档，请回报：浏览器版本、是否隐私窗口、
     以及 Safari「设置 → 隐私 → 管理网站数据」里该站点**还有没有数据**（**先别点移除**）；
  3. 建议习惯：重要进度先点「导出存档」存一份到本机。
- 本批**未推送**（网页版推送即部署）：等船长发话。
