## 三、六组读数

### 3.1 在线 8 小时 vs 离线 8 小时（`npm run econ:audit` §一）

同一档、同一时长、同一作业，分三条产出线各测一次：

| 产出线 | 在线 8h | 离线 8h | 差额 |
|---|---|---|---|
| ① 纯随机事件（不开采矿） | 钱包 **+12,162 ISK** · 日志 36 条 | 钱包 **+0 ISK** · 日志 8 条 | **事件收入归零** |
| ② 采矿自动循环 | 矿石 **20,600 件**（钱包 26,876） | 矿石 **20,440 件**（钱包 10,000） | 矿石 **−160 件（−0.78%）** |
| ③ 技能训练队列 | 采矿技术 3 级 / 精炼学 3 级 | 采矿技术 3 级 / 精炼学 3 级 | **完全一致** |
| ④ 城墙：游戏时刻推进 | 8.00h | 8.00h | **一致** |

**结论**：离线与在线在**采矿产出、技能训练、制造/精炼**上等价（差 0.78% 来自货舱循环边界）；
差的是**随机事件**——离线走静默模式（`advanceGame({offline:true})`，2026-09-21 船长裁定「乙案」），
只推进到点节奏、不发钱不建单。对新档这**不是小数**：8 小时在线事件收入 12,162 ISK = 开局钱包
10,000 的 **122%**；而离线这 8 小时钱包一分不涨。

"睡一觉回来"这个最常见场景，未点技能玩家**丢掉三分之二的时间**。

## 五、与既有已确认口径的冲突（§5.2 摆冲突，等裁决）

**冲突 A · 市场池基准船**
1. **新事实**：满配矿舰（鲸王级 ＋ 3×MK3）在 17 个矿带里 14 个覆盖比 < 1，最低 0.16×。
2. **既有已确认口径**：`docs/design/market-pool-liquidity-20260910.md` 第 4 行——
   「追补口径：**基准不取沙猫裸船，也不用座头鲸满配 → 「按 MK1 照掘洞级估算」**」（2026-09-10 船长定）；
   同批船长原则：「**理论上越低级的矿需求量越大，但差异太大玩家挖高级矿会卖不出去**」。
3. **二者不可同时成立**：按**掘洞级**标定 ⇒ 高阶矿对掘洞级卖得掉（当前读数是 2×，✓）；
   但同一批高阶矿对**满配矿舰**是 0.16–0.47×（✗）——即"卖得掉"这条只在基准船上成立。
4. **可选做法**：① 维持掘洞级基准（把"矿舰超产"当作有意的市场约束）；② 池基准改为
   **满配矿舰**（高阶矿 flow ×3–6，会连带矿石价格与需求分层）；③ 折中：只抬**顶级档**
   （>400 ISK 那四支：星幽/玄晶/暗星冰/寒髓冰）到覆盖比 ≥1。

**冲突 B · 打捞锚**

2. **既有已确认口径**：`docs/design/b3-salvage.md` §91 与 `b3-flavor-content.md` 第 6 行——

**冲突 C · 顶档 1e12**

## 八、三条收益曲线对照与调整方案（2026-09-28 船长追加口径）

> **船长原话（照抄）**：「**裁决先延后，我说下我期望的情况，期望中，挖矿+矿石精炼的收益曲线应该和悬赏
> 回收以及单纯工业化加工的收益曲线想当，能否基于这点，给出调整方案**」

三条线分别指：**A 挖矿＋矿石精炼** · **B 悬赏＋回收（打捞→回收炉）** · **C 单纯工业化加工（制造）**。

### 8.1 实测曲线

| 线 | 开局（无技能 · 一条主控线） | 中期 | 满配（**闸门后**） | 放大倍数 |
|---|---|---|---|---|
| **A 挖矿＋精炼** | **41,791 ISK/时**（沙猫裸船 · 母港橄榄岩；24h 均值 58,031） | — | **15,082,200 ISK/时**（星幽矿池封顶；暗星冰 20,520,000） | **×361** |
| **B 悬赏＋回收** | **55,248 ISK/时**（1 台打捞器 · L1 卡 · 保底密度 · 无技能） | 796,167（4 台 · L2 · 保底密度 · 满技能）· 1,432,368（深空密度吃满单炉） | **6,803,748 ISK/时**（6 炉：主控 ＋ 5×alpha）＋ 悬赏 258,623 | **×128** |
| **C 工业化加工** | **121,500 ISK/时**（电路基板 · 现货口径 · 无技能） | — | **7,198,608 ISK/时**（护盾充能力场 MK3 · 变现口径；现货 13,198,608） | **×59** |

### 8.2 诊断（三条读数）

1. **终点**：B（6.80M）与 C（7.20M）**已经相当**（差 6%）；**A 是它们的 2.1–2.2 倍**。
2. **斜率**：A ×361 · B ×128 · C ×59 ⇒ **A 是 C 的 6.1 倍、B 的 2.8 倍**——三条线不平行。
3. **起点**：A 41.8k ≈ B 55.2k（同一带 ✓）；**C 121.5k 高 2.2–2.9 倍**。

### 8.3 关键机制：A 线的收益**不由产能决定**

- 满配矿舰名义 **95,722,941 ISK/时**，而市场池只吃得下 **15,082,200 ISK/时**（覆盖比 **0.16×**）。
- ⇒ **压船产能对收益完全无效**（池是瓶颈，压产能只改"多久填满池"）；**只有压单价或压池有效**。
- 压池（下调 `supplyFlow`）会撞 **2026-09-10 船长令**（覆盖比最低档必须 >1 ⇒ 掘洞级基准仍要卖得掉）。
- ⇒ **唯一不撞既有令的 A 线旋钮 = 矿石与矿物的单价**。

### 8.4 两个方案

**甲案 · 压 A 到 B/C 的水平（终点对齐 7M 带）**

| 动作 | 数值 | 预期读数 |
|---|---|---|
| 矿石单价 ×0.5 | 星幽 490→**245** · 暗星冰 360→**180** · 玄晶 340→**170** · 寒髓冰 230→**115** · 磷光霾/极光云 330→**165** | A 池封顶 15.08M → **7.54M** |
| 矿物单价 ×0.5 | 冥铁 780→**390** · 星髓晶 245→**122** · 同位聚晶 55→**27** · 重钨 90→**45** | 堵住"改卖矿物"的旁路（矿物侧 104.98M → 52.5M） |
| **连带补偿**：回收 Y 或炉速 ×2 | 因回收池均价随矿物腰斩 ⇒ B 会从 6.80M 掉到 ≈3.4M，需补回 | B 回到 **≈6.8M** |
| C 不动 | — | 7.20M |

⇒ 终点 **A 7.54M / B 6.8M / C 7.20M**（三线同带 ✓）。副作用面最小（不动池 flow、不动船、不动技能）。

**乙案 · 抬 B 与 C 到 A 的水平（终点对齐 15M 带）**

| 动作 | 数值 | 预期读数 |
|---|---|---|
| B 抬 ×2.2 | 回收 Y ×2.2 或炉位/核心效率 ×2.2 | 6.80M → **15.0M** |
| C 抬 ×2.1 | MK3 制造周期 ×0.5 或售价 ×2 | 7.20M → **15.1M** |
| A 不动 | — | 15.08M |

⇒ 终点 **A 15.08M / B 15.0M / C 15.1M**。代价 = 全游戏数字整体通胀约 ×2（货币侧仍安全，
但 1e12 顶档从 16.3 年变成 8 年左右，**仍不可达**）。

**起点对齐（两案都要附带的子问题）**：现 A 41.8k / B 55.2k / C 121.5k。
- 抬 A：母港矿价 12→**25** ⇒ A 开局 ≈**87k**；
- 或压 C：零件现货价 ×0.6 ⇒ C 开局 ≈**73k**。

### 8.5 先要补的一个读数（缺口）

**C 线的闸门没测**——上面用的是"制造净收益"，没有量**装备市场池一天能吃下多少件 MK3**。
若装备池吸收 < 7.2M/h，C 的实际收益同样会被闸门压下来（与 A 同理）。**动手前应先补这一读数**。

## 九、矿石按体积平衡（2026-09-28 船长令 · 先做这一件）

> **船长原话（照抄）**：「**我查了下原版EVE，它是通过不同矿石每单位体积不同来进行平衡的。体积越小的
> 矿石，每次挖掘采集到的单位量越多，如果我希望不同矿石的平均每次挖掘价值在1~1.3之内按稀有度分布。
> 我应该如何修改？先完成这个在回头讨论收益曲线平衡**」

### 9.1 现状读数（三条硬事实）

| # | 事实 | 证据 |
|---|---|---|
| 1 | **8 支矿石的 `unitM3` 全是 1**，`RARITY_TIER` 里也全是档 1 | `items.ts` ORES 段；`rarityTier.ts` |
| 2 | **体积完全没参与产出**：`unitsPerCycle = max(1, floor(ship.oreUnitsPerCycle × 产量乘链 × (1+Σ矿枪)))`，算式里没有 `ore.unitM3` | `packages/core/src/mining.ts:115` |
| 3 | **单循环价值极差 29–38×** | 沙猫裸船 130（橄榄岩）→ 4,900（星幽矿）= **37.7×**；鲸王满配 6,227 → 180,810 = **29.0×** |

### 9.2 改法（三步 · 引擎一行 + 数据一批 + 连带四件）

**第一步 · 引擎把"每循环单位"换成"每循环 m³"**（`mining.ts:115`，一行）

```
unitsPerCycle = max(1, floor(ship.oreUnitsPerCycle × prodMult × (1 + Σ矿枪) ÷ ore.unitM3))
```

- `ShipDef.oreUnitsPerCycle` 的语义由「单位/循环」变成「**m³/循环**」，**数值一个不动**
  （沙猫 10 · 掘洞 18 · 鲸吞 34 · 开拓 38 · 鲸王 58 · 座头鲸 140）。
- ⚠ **当前 8 支矿 unitM3 全是 1 ⇒ 新旧公式逐位等价**：落地当天**零读数漂移**（先用一条用例钉死）。
- **满舱节奏完全不变**：满舱判据是 `unitsPerCycle × unitM3`（`mining.ts:490`）＝每循环 m³，
  改后该乘积**恒定** ⇒ 装满货舱要几秒、一趟几循环都不变。

**第二步 · 给矿石设"体积阶梯 + 配套单价"，令 `单价 ÷ unitM3`（每 m³ 价值）按稀有度落 1.0–1.3 带**

数学上：`单循环价值 = 每循环 m³ × (单价 ÷ unitM3)` ⇒ 每循环 m³ 对全矿相同，
**只要"每 m³ 价值"落在 1–1.3 带，单循环价值就自动落在带内**（这也正是 EVE 的实态）。

**第三步 · 连带四件（不做会崩或会失真）**

| # | 连带 | 为什么必须做 |
|---|---|---|
| a | **`refine[].perOre` 重标** | `perOre` 是"每**单位**原矿产多少矿物"。unitM3 一变，同体积原矿的单位数变了 ⇒ 同 m³ 的精炼产出会跟着变 `unitM3` 倍（星幽矿 5 m³/单位 ⇒ 产出 ÷5） |
| b | **`marketCatalog` 矿石行重标** | `basePrice` 全变 ⇒ 连带三处：① 覆盖比分层（2026-09-10 令按**单价**分档：≤20→×15 / ≤200→×6 / ≤400→×3 / >400→×2）② `supplyFlow`/`poolTarget`（天花板 ISK = flow × 新单价）③ 副站资源任务需求量（= `poolTarget × 1%~3%` 件数） |
| c | **`rarityTier.ts` 矿石 8 行补档** | 现在全是 1；新分层要排 1–5，并过 `content:check` 的稀有度契约 |
| d | **存档存量折算**（⚠ **B 类需裁决**） | 仓库无容量上限 ⇒ 只影响读数；但**船上货舱**（`freeCargoM3`）与**虫洞背包**（`WORMHOLE_SLOT_M3 ÷ unitM3` 定格数）会**直接超容** ⇒ 要么做迁移折算，要么容忍超载 |

### 9.5 需要船长定的五件事

1. **「1~1.3」的口径**：是**全域极差**（最贵矿单循环价值 ÷ 最便宜矿 ≤ 1.3），
   还是**相邻档比值**（每档 +≤30%，5 档总跨 ≈2.9 倍）？**本节表按"全域极差"做。**
2. **锚点**（§9.4 三选一）——它同时决定新手收入与 A 线满配收益。
3. **体积阶梯**：本表用 `0.2 / 0.5 / 1 / 2 / 5`（5 档、跨度 25×）。要不要更平（如 `0.5 / 1 / 1.5 / 2 / 3`）？
4. **虚空母矿**（虫洞专属，现价 915 最高）算不算进这条带？本表把它与星幽矿同列 R5。
5. **存量折算**（§9.2d）：做迁移，还是容忍老档货舱超载？
