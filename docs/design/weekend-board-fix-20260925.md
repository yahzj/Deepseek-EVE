## 四、报障②：清缴不加进度 —— **真因 = 出发归属按卡 id 反查 ⇒ 串星系**（已修）

> ⚠ 本节第一版把原因写成了"活动栏读数不动"——**船长纠正**：「**② 是对应的星系，玩家打的红环常驻悬赏，
> 不加红环的进度条。**」据此重查，真因如下（前一版结论作废，保留在下面作"顺带做实"的两条改进）。

### 真因与读数（`npm run weekend:board` ④ 段 · 船长真档）

H 族是"每星系抽一支驻留舰队"，抽签只在**本族那几张独立卡**里抽 ⇒ **多个被占星系会抽到同一张卡**
（真档：深渊之门／暗星坟场／红环航道三处都是 `ink-raid`）。而出发路径原来是**按卡 id 反查星系**：

```
深渊之门 板面那一行 = ink-raid ⇒ 旧口径按 id 反查 = galaxy-redring ← 以前会串到这一处！
暗星坟场 板面那一行 = ink-raid ⇒ 旧口径按 id 反查 = galaxy-redring ← 以前会串到这一处！
红环航道 板面那一行 = ink-raid ⇒ 旧口径按 id 反查 = galaxy-redring
虚海边缘 板面那一行 = ink-harass ⇒ 旧口径按 id 反查 = galaxy-voidedge
```

`anomalies.find(a => a.id === id)` **永远命中列表第一个**同 id 行 ⇒ 串的是**整条链**：
出发落盘的 `expedition.foeGalaxyId` → 威胁覆写 · **进度记账星系** · 结算日志里的星系名 ·
残骸注入星系 · 遇袭敌群池选卡。船长档里"第一个"恰是红环 ⇒ 点核心／坟场的行，进度全记到红环；
**若玩家那边的"第一个"是核心**（门禁锁死）⇒ 点红环一分进度都不给 —— 正是报障原话。

### 修法（已落码 · `75c93421`）

- core 新增单点 **`weekendLaunchGalaxyOf(state, hintGalaxyId, cardGalaxyId, nowWallMs)`**：
  **界面那一行的星系**（hint）是活的占领区就采信它；否则逐字回落卡面星系（结算/打捞/遭遇这些没有界面行的路径零变化）；
- 引擎：`foeGalaxyOf(anomalyId, hint?)` / `weekendDispatchOf(id, hint?)` /
  `startExpeditionAt(id, foeGalaxyId?)` / `startExpeditionFromMiningAt(id, foeGalaxyId?)`；
- 界面：常驻悬赏卡的「出击 / 确认转战 / 星系出击栏」三处传 `anomaly.galaxyId`（`autoPerf` 传目录卡的星系）；
- 用例 `packages/core/tests/weekend-launch-galaxy.test.ts`（2 例）：同 id 两星系各归各；hint 非占领区/无 hint/活动结束 ⇒ 老口径。
- 巡检工具 ④ 段现在**并排打印"修后归属 / 旧口径反查"**，以后一眼看出有没有串。
