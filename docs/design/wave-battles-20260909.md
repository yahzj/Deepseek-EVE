# 多波次敌人设定(低安顶段悬赏)设计稿(2026-09-09;方向已船长拍板,本稿待终审)

> 背景:敌人强度复调轮(r4)real sim 终验打穿终局闸 → 船长定:**暂停单敌血量微调路线**,
> 引入多波次机制化解"后期单体血量过大",并作为**低安加强**的实现方式。
> 船长拍板(2026-09-09):首批 = 深低安顶段 4 张(噬口 80 / 坟场 88 / 虚海 88 / 穹顶 96);
> 单场目标 **90~150s**、波间无喘息;胜率预估 **同步校准**(按总波战力折算 + 修正低估)。
> 复调轮 r4 数值保留,随本机制统一重构(每卡总血 = 现 r4 foeHpOverride,拆波不改总预算)。

## 一、机制(引擎)
- **波次 = 同场续刷**:战斗保持"一次悬赏整场结算"(声望/首胜/奖金/残骸注入按原卡,不按波发奖)。
  敌方单位清空且未到末波 → 引擎补刷下一波(同族敌舰,按每波构成生成;波间无喘息,
  不重置双方状态,护盾/回充照常);
- **数据结构(AnomalyDef 可选字段,零迁移)**:
  `waves?: Array<{ units: number; hpShare: number; escortMul?: number }>`
  —— units = 本波主舰数;hpShare = 占该卡总战力的血比例(Σ≈1);escortMul 预留(僚机随波)。
  缺省 = 单波(现行为,全量兼容);有 waves 时引擎按波生成:单波总血量 = 现敌血算法
  (foeHpOverride/曲线) × hpShare,单舰血 = 波血 ÷ units;
- **推进**:敌清空 → 波次+1 补刷(波间同 tick 续战);末波清空 → 正常胜利结算;
  中途败北 = 原失利规则;撤退/召回沿用现状(整场语义不变);
- **UI/日志**:战斗横幅/日志提示「第 N/总 波来袭」;结算与现状一致。

## 三、胜率预估/AI(同步校准)
- `winEstimate`/preview:按卡总战力口径折算多波(每波 hpShare×units 计入敌方总持续火力/血量
  近似),并**校准已知低估**(09-06 决策点 5:实测穹顶 100% 而 preview ~87%)——校准目标 =
  预估向 battle:calibrate 实战收敛(±5pp 内),玩家悬赏列表胜率展示、AI 85% 闸、real sim
  最终验证闸同源受益;
- 校准杠杆(设计时定):logit 扩散系数/敌方火力折算(不在本稿展开,实现时按矩阵拟合)。

## 四、范围与边界
- 首批仅上述 4 张悬赏(主控与 AI 同源跟随,引擎自然支持);低安伏击遭遇=当地悬赏卡,
  若抽中多波卡 → 伏击战同样多波(结算语义一致,无需单独实现);
- 其余悬赏/中低安维持单波;复调轮 r4 数值保留至本机制统一接管(单卡拆波后旧 foeHpOverride
  即为其总预算);
- 时长:单波卡不受影响;多波卡单场目标 90~150s(实测校准,不再硬卡 40~90s 带)。
