> 状态：**已确认**（船长 2026-09-14 三条裁定，见 §2）。
> 经办：二号（d2）。落码提交见 `docs/roadmap.md` 同日条目。
> 相关：`packages/core/src/combat.ts`（常量 + `isFoeEngageable` + 播种处）、`packages/core/src/state.ts`
> （`BattleUnitRt.enteredAtMs`）、`packages/core/src/save.ts`、`packages/core/src/wormholeBattle.ts`、
> `apps/desktop/src/renderer/src/panels/BattleScreen.tsx`。

## 1. 起因（船长报障 · 已取证）

船长两次描述同一个现象：

> 「战斗界面，敌方增援出现时，我方炮台同时开火，会出现敌方动画卡着不消失的情况。建议敌方出场动画结束后才允许开火。」
> 「之前的"卡着不消失"是指**血条打空后，舰船形象和血条都不清理消除**。」

**取证读数**（真引擎复现，7 张多波卡 × 5 种子 × 6 种装配 = **210 场**，逐拍重放界面的阵亡判据）：

| 装配行 | 出现"幽灵"的场次 | 首见即 0 血的敌舰 | 其满血中位 |
|---|---|---|---|
| 沙猫级（开局船） | 0/35 | 0 | — |
| 鲸王 3×动能 MK3 | 11/35 | 11 | 55 |
| **S4 大白鲨 5×MK3** | **25/35** | 29 | 96 |
| T3 长尾鲨 5×导弹 MK3 | 0/35 | 0 | — |
| T3 牛鲨 5×动能 MK3 | 24/35 | 25 | 96 |
| D3 王鲭无人机重装 | 21/35 | 49 | 55 |

合计 **81/210 场复现**，幽灵 **全部**来自增援波（`w1-` 第二波 93 个 · `w2-` 第三波 21 个 · 首波 **0** 个）；
界面漏帧会放大（每 5 拍才看一次 ⇒ 146/210）。

**真因（两条叠加）**：

1. **界面侧**：判定"敌舰阵亡"靠"**看见它从有血变成 0 血**"这一瞬间（`BattleScreen.tsx` 的
   `sum === 0 && prev > 0`，而 `prev` 来自上一帧观察）⇒ 某个单位**第一次被看到就已经是 0 血**时，
   永远不登记阵亡 ⇒ 视觉行不撤队 + 血条照画（`corpseOn` 为假时才渲染血条）⇒ **舰影与空血条永久留场**。
2. **引擎侧**：波次转场窗口内战斗时钟**停表**（`waveClearAt`），窗口走完后**一帧内追平**——
   实测：全局 14800 那一帧把战斗时钟从 11500 直接推到 14800（**一帧 3300ms = 33 拍**）。
   新一波在这 33 拍里被结算，界面还没来得及画第一帧 ⇒ 首次观察即 0 血。
   ⇒ 这正是船长说的「**敌方增援出现时，我方炮台同时开火**」：瞬伤武器（动能炮 / 无人机）踩得到，
   导弹因飞行时间反而踩不到（长尾鲨 0/35）。

## 2. 船长裁定（2026-09-14 · 照抄）

1. 「**①乙，初始不可开火，且对洞内洞外都生效。**」
2. 「**②和洞外一致。**」（= 洞内也要有尸骸/爆炸演出）
3. 「**③补。并且参考①动画没结束不开火**」（= 增援/次波补入场动画，动画没结束不开火）
4. 追加：「**补吧**」（= 同意顺带补上界面侧的防漏判，即 §3.3）

## 3. 口径与落点

### 3.1 入场窗口（单一出处）

- `BATTLE_ARRIVAL_FLY_MS = 950`（飞入时长）· `BATTLE_ARRIVAL_STAGGER_MS = 60`（逐舰错峰）——
  **界面直接 import 这两个数**当 `--arrive-ms`，不许各写一份（"看得见的动画"与"不可选中窗口"永远同一个数）。
- 单位运行态新增 `BattleUnitRt.enteredAtMs`（战斗时钟；**含逐舰错峰**）。
  **窗口 = `[enteredAtMs, enteredAtMs + 950)`**。
- **谁有窗口**（"有动画才有窗口"）：
  - **洞内开战首波**（敌方跃迁入场，船长 2026-09-13 口径）⇒ 有；由 `wormholeStartBattle` 调
    `stampFoeArrivalFx` 盖（同时把它们的首发推到窗口之后）；
  - **洞外开战首波**⇒ **没有**（那一场是我方飞入，敌方没有入场动画，行为与改动前逐字一致）；
  - **每一次波次转场** ⇒ 有（**前提：真的等过转场窗口**，见 §3.2）；
  - **单波内增援**（机制总开关仍关闭）与**读档中断补缺** ⇒ 有。
- **窗口内双方都不动手**：我方**不可选中**它（见下），它自己的首发也在窗口之后
  （播种时装填取 `max(自身装填, 窗口)`）。

### 3.2 大步长 / 离线补算不盖窗口（一处必须的分叉）

转场窗口内战斗时钟停表，`state.gameMs` 走完窗口后**一帧追平**。故：

- **入场时刻取 `state.gameMs`（全局时钟）**，不能取 `battle.lastTickGameMs`（此刻它还停在"上一波全灭那一刻"）
  ——拿它当"现在"会把窗口算到**过去**，机制等于没做（**这是实现过程中真踩到的 BUG，探针当场抓到**：
  改前 81/210 场幽灵，改后仍 85/210；换用全局时钟后归零）。
- 但**离线 / 大步长**推进时，一次调用就跨过整个转场窗口（玩家根本没看见转场、也没有动画可言）⇒
  **不盖窗口**：否则"最后一波的敌人免疫到本次推进结束"⇒ 该赢的场次被拖成超时判负
  （`tests/wave-battle.test.ts` 的大步长用例当场抓到）。判据 = **进入本拍时 `waveClearAt` 是否已经存在**
  （`pendingGap`）：实时路径是"上一拍记下、本拍才越过" ⇒ 盖；离线路径是"本拍才发现全灭、本拍就续刷" ⇒ 不盖。
- `waveEnterGapMs = 0`（无转场节拍）⇒ 同样不盖（没有转场演出，也就没有入场动画）。

### 3.3 我方的"不可选中"单点 + 界面防漏判（两条互补）

- 引擎：新增 `isFoeEngageable(b, tag)`（紧挨 `isAlive`）= **真值存活 且 已过入场窗口**，
  **两处选靶单点同时换判据**：`randomAliveFoe`（随机选靶）与 `firstAliveFoe`（锁定装置的集火），
  外加 `pickFoeDronetTarget` 按"母舰还在入场 ⇒ 它的机群也打不到"。
  **为什么是选靶而不是伤害免疫**：引擎里**命中与伤害同拍结算**（没有在途弹道状态，界面那条延迟弹道只是演出）
  ⇒ 选靶处排除即**彻底**堵住"登场第一拍就被齐射带走"。
  **我方枪口会跳过它去打别人**；窗口内若没有别的可打目标 ⇒ 本拍自然停火（转场时正是这种情况）。
- 界面（"补吧"那条）：阵亡登记改为**只要观察到 0 血且未登记过就登记阵亡**——
  有前值（正常阵亡）⇒ 照旧演爆炸；**没有前值**（首见即 0 血：漏帧 / 入场期被打死 / 重进战场）
  ⇒ **不登记尸骸 ⇒ 立即出队**、不重放爆炸。首帧预登记同样把"已经是尸体"的直接登记掉。
  这条是**兜底**：即使将来又有别的路径让界面漏看一帧，也不会再永久留场。

### 3.4 洞内与洞外一致（②）

`wormholeBattleViewOf` 去掉 `foeHp` 的 **0 血过滤**（与 `expedition.ts` 一直以来的口径一致）⇒
**洞里从此也有尸骸 / 爆炸 / 淡出演出**（此前敌人是"直接消失"的）。
实测（真节点战）：改前 **0 次**出现过 0 血单位，改后 **1058 次**（2 次击杀 × 各自演出期）。
该视图的唯一消费者是战斗界面（已核）。

### 3.5 逐舰入场动画（③）

`is-arriving` 由"只看开战前 1300ms"改为**逐舰按引擎的 `enteredAtMs` 判定** ⇒
**每一次波次转场 / 增援的新单位各自播一次飞入**（首波照旧：洞内敌方飞入、洞外我方飞入）。

## 4. 存档

`enteredAtMs` 随档（`cleanBattle` 白名单补一条，落在 `units` 的 persist 登记内）；战斗时钟也随档
⇒ 战中重载后 `lastTickGameMs − enteredAtMs` 依旧正确（窗口不会因重载而重启或消失）。
**老档 / 没有入场动画的单位缺该字段 ⇒ 视为"窗口已过"（恒可交战），零迁移。**

## 5. 读数（本轮实测）

- **幽灵探针复跑（同一批 210 场）**：**0/210 场**（改前 81/210）· 首见即 0 血 **0 个**（改前 114 个）；
  四种观察节奏（每 1/2/3/5 拍）全为 0。
- **标定对照**（`npm run battle:calibrate -- --std`，128 格 = 4 技能档 × 32 卡 × 5 种子）：
  **只有 7 张多波卡的 26 格变化**，其余 25 张卡逐字不变；**时长均 +0.60s**（最大 +8s = 3 波卡；
  单次转场 ≈ +1s）· **胜率均 +0.16pp（升 1 格 / 降 0 格）** · 残血基本不变。
  ⇒ 代价 = "每道波次转场我方少打约 1 秒"，方向与"动画没结束不开火"的意图一致。
- **负向验证（7 条，逐条临时改坏 → 用例如实红 → 还原）**：
  ①随机选靶退回 `isAlive` ②集火判据退回 `isAlive` ③转场不盖 `enteredAtMs` ④洞内首波不盖
  ⑤存档白名单漏字段 ⑥`waitedGap` 写死 false ⑦入场时刻退回冻住的战斗时钟。
- **四闸门**：typecheck ×4 0 错 · core **125 文件 / 1310 用例**全绿（新增
  `tests/battle-arrival-grace.test.ts` **9 例**）· `content:check` ✅ · 桌面 build ✅。

## 6. 旧条款改判（§5.2 处置）

**作废**：`docs/archive/roadmap-2026-09-13.md` 条目「战斗入场效果：跃迁入场」（船长 2026-09-13 原话、一号落地 `5e289e35`）——
> 「既然开始做战斗效果了，那么能否在开始时做一个入场效果？**为了最小程度防止BUG，入场效果仅为动画**。
> **玩家和敌舰的位置依旧不改变**。」

**改判为**：入场效果 = **动画 + 一段"不可选中"窗口**（窗口与动画同一个数）。
**仍然成立的部分**：**位置一律不改**（入场层不进 `layout()`、不碰任何坐标/编队几何/血条锚点/距离尺）——
这一条是那句原话的真正用意（"为了最小程度防止BUG"），一字未动。
**同时改判**："按战斗时钟只演一次（只在前 1300ms）" ⇒ 改为**逐舰按 `enteredAtMs` 各演一次**（③）。

## 7. 已知取舍（如实登记）

- **洞内首波的敌方首发被推迟到窗口之后**（原本开战即满装填）：这是"动画没演完谁都不动手"的直接推论，
  影响面 ≈ 0.95s；若只想约束我方、不想动敌方的首发节奏，把 `seedUnit`/`stampFoeArrivalFx` 里那句
  `Math.max(..., windowMs)` 去掉即可（一处）。
- **读档中断补缺**（`advanceBattleFor` 的开战首波兜底）按"增援入场"处理 ⇒ 也会盖窗口（罕见路径）。
- **我方也不是完全免费**：转场时我方装填被冻住、窗口内又无处可打 ⇒ 每道转场少约一轮齐射
  （标定读数见 §5）。
- **界面那条兜底（§3.3）不影响引擎**：它只让"界面漏判"不再永久留场。
