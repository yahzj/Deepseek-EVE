## 一、槽位模型（Q1 复数安装 × Q2 数量制）

- 三类物理槽：**高槽 / 中槽 / 低槽**。每艘船有各自的槽位数（`ShipDef.slots =
  { high, mid, low }`，见 §四表），每个槽位 = 1 个安装位（复数安装：高槽 N = 可装
  N 件高槽类模块；多门炮齐射、多把矿枪共采、多个无人机装置并网）。
- 槽位**没有尺寸**（数量制；口径/尺寸已在 V18 口径取消中移除）。
- 同类唯一约束：护盾/装甲的**抗性系与容量系**（增强器·扩展器·镀层·增厚板，
  按 家族+系 判定）全船同系仅 1 件——防"两块动能膜"叠出超模乘入抗性；
  **线性可叠件**（武器、挂架、导控、矿枪、货舱扩展）允许复数，效果线性求和、
  不叠乘、无惩罚。
- 工业/无人机线性件复数全生效（见 §六引擎点）。
- 总量平衡器：CPU 成倍档（5/15/40）不变——槽位决定"能带几件"的上限、CPU 决定
  "能带多好"；顶配船满槽但只够 5~6 件 40CPU 高级件，取舍依旧成立。

## 二、模块归槽（Q3 映射落地）

ModuleDef.slot 保留六家族值（turret/miner/shield/armor/propulsion/cargo——家族
语义是装配校验与引擎构建的依据），**新增 `ModuleDef.rack: 'high'|'mid'|'low'`**
槽类归属字段（Q3 映射集中落数据）；UI 徽标显示 高/中/低槽。归属表（V18A 内容）：

| 槽类 | 家族（slot 值） | 备注 |
|---|---|---|
| 高槽 | 炮台 turret 5 · 采集器 miner 5 · **无人机挂架 3** · **无人机导控阵列 3** | 挂架/导控 = V18A 新家族（§三） |
| 中槽 | 护盾增强器/扩展器（shield 12）+ 矢量推进器（prop 3） | 增强/扩展/推进可同船（原二选一解除） |
| 低槽 | 装甲镀层/增厚板（armor 12）+ 货舱扩展（cargo 5） | 甲件与扩舱争位 |

- 同槽内异类自由混装（中槽可 增强器+扩展器+推进器 同船）。
- 装配台槽位区按 高/中/低 三组展示（§五）。

## 三、高槽"无人机流派"新家族（远行星号式装置位；V18A 新增 6 件 → 装备共 54 件）

无人机机制现状：携带于货仓、受 船 droneBayM3（仅 armed/armored/hauler 有舱
15~130 m³）+ 放飞 CPU 约束，自动装载参战并入主船火力（v1 不损毁、不占槽）——
玩家只能"带多少"，没有"强化无人机"的装配维。V18A 补上：

| id 族 | 名称（SS 风味） | 效果 | CPU（成倍档） | 渠道 |
|---|---|---|---|---|
| mod-drone-rack-1/2/3 | 无人机甲板扩展 MK1-3 | `+droneBayM3` 15/35/70 m³（携带/放飞上限；无人机 1.5~10 m³/架——MK1 ≈ 多 2-5 架重型、MK3 可整队扩容） | 5/15/40 | MK1 平价、MK2/3 稀有（市场专供，无蓝图） |
| mod-drone-tac-1/2/3 | 战术导控阵列 MK1-3 | 放飞无人机单发伤害 +12/25/40%（求和；基础 = 无人机的 def.dmg） | 8/20/45 | 同上 |

- 流派：**炮击流**（同型炮 ×N）｜**无人机流**（甲板扩展 + 导控 ×1-2，配少量炮兜底；
  输出不耗弹药、低安长线省补给）｜**混编**（主炮 + 一扩展）｜采矿船 矿枪 vs 炮 vs
  挂架的产量/自保/副火力取舍。带 0 舱船（industrial）装挂架 = 外挂甲板获得舱容
  （可，代价是高位与 CPU）。
- 引擎点：createPlayerSpec 装载段 `droneBayM3 + Σ(挂架)`、无人机武器 shotDmg ×
  `(1+Σ导控)`（单点乘入）；装载贪心/cpu 约束不变；导控对 AI 副船同源生效。

## 五、装配交互（复数安装）与 CPU 校验

- **装配**：装备库点某件 → 归属类若有空位则装入**第一空位**；该类满 → 拒绝并提示
  （"高槽已满（3/3）：先卸下再装"）；也支持**点空位行**从该类候选件清单中选装
  （双向入口，装配台 UI）。
- **卸下**：槽位行上的件一键卸下退回装备库；同件多件装时按"后装先卸"不区分
  （同型多门炮装配 N 次 = N 门，卸 1 次 = 少 1 门——fitted 位数组天然表达）。
- **同类唯一校验**：护盾/装甲抗性系与容量系同型号同系只可 1 件（装配第二件时拒绝，
  提示"同类唯一：动能型增强器已装"）；同型炮可重复装。
- **CPU 校验**：沿用六槽合计 ≤ 船体 cpu（改为全位合计）；无人机放飞余量 = cpu − 全位
  合计，语义不变。
- 装配页 UI：槽位区 = 高槽组（位 1..N）/中槽组/低槽组，每组每行 = 槽位序 + 已装件名
  （悬浮窗/短效同 V17）+ 卸下钮；空位行 = "空 · 装入…"入口；顶部 CPU/合成抗性预览
  行保持（血量/抗性/速度预览改为按全位装配计算）。

## 六、引擎与数值影响（本设计的重心声明）

- **战斗**：高槽每门炮 = 独立武器条目（createPlayerSpec 逐件展开；同 id 同参多门
  合并为一条 ×N 的齐射条目避免 UI 弧线爆炸）；炮台各自固定弹种——多门不同弹种炮
  同船时，开火按各自弹种扣 battle.ammo 对应键（原"整场一型"改为 per-gun 扣键），
  某型弹尽该炮停火；基础舰炮兜底保留（无炮/无弹可还击）。胜率预估 meDps 遍历全部
  武器条目（自动涵盖多炮）；弹药出发预载按各炮需求分型装载。敌方换算不动，
  玩家侧成长经 battle-calibrate 校准轮复核。
- **工业**：采矿 = 高槽全部 miner 件加成求和（`(1+Σbonus)` 近似多枪共产）；货舱容量 =
  低槽 cargo 件加成求和；AI 采矿/运货同源（mining/inventory 单点函数）。经济曲线
  （24h 产量/收益）需 balance-check + 回调（矿枪基础/价格/矿带产出以校准轮定稿）。
- **AI 副船**：无操作差异（装配由玩家给），战斗/采矿自动吃多件。
- **市场/弃船/卖船守卫**：fitted 检查改按全位遍历（形状见 §七）。

## 七、存档迁移（version 17 → 18）

- `CURRENT_STATE_VERSION = 17 → 18`；MIGRATIONS 新增 17→18：每船 fitted 由六槽
  Record 迁移为三类位数组 `{ high: (id|null)[], mid: [...], low: [...] }`。
- **原位映射**（稳定落位）：high[0]=原 turret、high[1]=原 miner；mid[0]=原 shield、
  mid[1]=原 propulsion；low[0]=原 armor、low[1]=原 cargo——新布局该类位数不足时
  溢出件退回装备库并日志（如 1 中槽船原装盾+推进 → 推进退回；不丢资产）。
- normalize/空槽函数（labels.emptySlots）与 save sanitize 按新形状容错；
  test-save 门槛存档 case 注入（B 级交付标准，tools/make-test-save.ts case v18：
  一艘满槽高配船 + 多炮多弹型弹药 + 复数矿枪示例）。
- 行为前置：旧档迁移在 GameEngine.start 的 repair 链执行（幂等）。
