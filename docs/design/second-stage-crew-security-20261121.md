# 第二阶段：舰员培养与区域安全

> 状态：本批非破坏性独立流程实现与自测完成、待验收；内容扩充及正式接入仍有下述缺口。
> 授权：船长要求「继续完成第二阶段剩余内容」，经集中总结“由我定稿非破坏性规则、零号独立开发、不永久死亡/毁站/没收、不清协会声望、不自动断共享网，正式接入另验”后答「继续」。本轮可确定团队、成长、事件、外派守备和独立目标，不再逐项等待数值确认。

## 范围与顺序

1. 舰员团队引用真实已接收居民，按舰级用工；资格、团队潜力和成长独立保存。无团队舰船保持原能力；不把舰长另做一套品质系统。
2. 同一培训中心承接舰员模拟课程，使用真实团队/训练舰、实际席位和功率。普通工种课程与团队成长分账；待命、卸船、暂停不返还成员来制造双份人口。
3. 技能学习机会与永久特性来自有效成长事件；候选、阈值、随机状态和待答二择保存，切活动/读档不重抽。二择不超每队/全局20%，待回复每队1/全局2封，全局6小时间隔，10%只在门禁满足时抽取，不保底。
4. 外派、守备与训练共用团队/船只锁定，胜负走现有战斗引擎。补给不足停止，返航完成才释放船只。清剿针对有限真实来源，只发一次成果，不默认无限循环。
5. 安置、生产、科研、扩站、舰员、补给、安全与防守各有实际检查，满足后显式确认独立；无奖励接口、外交侧效应或第三阶段自动开放。

## 边界

- 本轮只扩展`packages/core/src/playerStation/`与开发预览/专项，不将新字段加入正式GameState，不改主存档版本，不碰参赛包与原有方向按钮。
- 非破坏性：失败安全返回，不扣全母港仓库、不永久删除团队/居民/舰船。实际补给仍按任务扣除，不用失败免成本复制材料。
- 用户原长期内容规模目标保留，事件/技能/特性目录必须如实报告数量，功能闭环不等于全部百条内容已完成；不生成换名改百分比的重复条目凑数。
- 新增预览中文留稳定id与注入文本，不提前写正式公告或英文；完整主游戏接线、集中整库回归、玩家观感验收和发布另行执行。

## 验证要求

专项覆盖居民/舰船/席位互斥、潜力/点数累计守恒、成长事件门禁、技能购买/回复幂等、暂停/待命/读档不重抽、外派返航/来源去重、现有战斗基准和阶段目标。整体快照与所有资源一起回滚；大步/小步应相同。浏览器桌面/手机操作不得以合成测试API代替真实控件。

依据：`.wiki/references/game-programming-patterns.md`（confidence: verified）的状态单点/最小解耦与`.wiki/references/designing-interfaces-tidwell.md`（confidence: verified）的动作面板/安全探索。Serena/知识库工具未提供，限定源码与现行设计read/rg降级；不查归档、Git历史正文、content-csv或个人存档。

## 已实现机制

| 模块 | 实际行为 | 当前边界 |
|---|---|---|
| 舰员团队 | 资格1/2/3档占用1/2/3名原普通居民；资格和进修30分钟；高资格可换配低档船，解散清培养后归还成员 | 六人是独立预览样本，不增加正式居民或舰船 |
| 长期培养 | 火控、损管、机群三门模拟；统一一席、实际训练船和工作5点电；每10分钟一步，主/主/次属性成长 | 不开火、不耗训练弹药/维修件/无人机，不把课程当真实出击 |
| 潜力/点数 | 普通属性合计24/48/72；累计点数上限6/12/18独立计量，花点不重发；进修保旧成长只扩空间并补真实成员 | 不洗点、不洗特性；无独立舰长品质或技能槽 |
| 事件/二择 | 每2至4步有效成长产生机会，保存随机/阈值/候选；10%二择受每队/全局20%、6小时、每队1/全局2封限制；待答不阻塞成长 | 内容库为14技能、16特性、24普通事件、12二择，不宣称达到原百条级目标 |
| 技能效果 | 学习先有机会、满足属性且付点数；团队常驻火力/防护小数增量，单轴封顶15%，特性只修正技能增量 | 未实现危机掩护/余量调配等离散战斗事件机制；新增固定增量特性不用已确认旧特性的同名/id冒充 |
| 外派 | 有限巡逻、补给护航、针对三处既有异常来源的清剿；5分钟去程/返程，清剿执行时长按真实战斗结果 | 预览舰船使用合法合成装配，零技能第三舰可胜三来源；不修改正式异常或战斗引擎 |
| 补给与成果 | 护航每趟民用组件4/基础弹60；其余按原战斗实际弹药/军用维修消耗扣一次；来源胜利永久清除且只发一次成果 | 失败安全返航，不死亡、毁站或扣母港全仓比例；守备不免费复制外出队伍 |
| 自动守备 | 明确保留团队和船只；有暴露后有限来源按既有6小时计划检查来袭，警戒给可见情报；缺补给/失利暂停，没守备报告风险 | 不依据玩家财富或建筑等级生成等比敌军；不做永久伤亡/被掳/营救与完整站损结算 |
| 阶段收束 | 安置、工业、科研、扩站、团队、护航、来源安全、守备八目标；显式确认自主据点，不改协会关系/资产/共享网 | 防守目标允许有效守备30分钟或真实击退，避免清光来源后硬锁阶段；不自动开放第三阶段 |

火力/防护增量在隔离船型参数表上进入原`startFleetBattleFor/advanceBattleFor`，不是UI估算胜负。真实装配与机群由原fit/adjustDroneLoad校验CPU/槽位/机舱。三种开发舰为鲣鱼、灰鲭鲨、锤头鲨；锤头鲨实际配损管模块/一架侦察机，三课程均有合法训练样本。

## 整体状态与验收

- `StageTwoSession`组合原`LabModel`，通过显式hook加入原最近事件时间轴；不另起循环。此前条件冻结后推进团队/安全，再结算原生产/工程；新增物资/资格不补此前工时。
- 只有原普通空闲居民能组队，团队全生命周期持续占人。训练/资格/原基础课程共用培训席位；外派和守备实际船锁，暂停不释放，途中停止返航完成才归还。
- 第二阶段外层`whale-second-stage-preview` v1包住原经营v8、团队、安全、阶段成果、独立战斗船锁与经验消费序号。无损接收旧经营快照；有任何阶段记忆后不退回旧格式。正式游戏仍v31。
- 行动经验按新报告编号消费一次，返回后不重复发；报告显示只保留最近100条，不承担永久目标记忆。阶段目标在每个真实事件边界登记，历史批次/成长/返航/防守读数与运行账交叉核验，不能只伪造目标枚举直接独立。
- 独立审查发现并修复：长推进挤掉护航目标、基础格式回退丢失目标、导入目标缺少成果依据。另补航程/返航/守备即时快照、规范序列化顺序和经验游标回归。
- `make-stage-two-fixture.ts`生成`stage-two-ready/trained/before-independence/complete.json`，均由正常模块命令建立，只能导入独立预览，不得替换正式游戏档。输出位于`tools/_ui-artifacts/second-stage/`。
- `stage-two-choice.json`由自然培养产生待答选择，不直接修改种子/事件计数；浏览器实际导入、重读与回复一次，结果不重复。无团队空档也保存组合时钟，不能靠读档重置安全检查计划。

## 后续接入与内容缺口
