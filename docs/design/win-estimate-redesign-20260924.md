# 悬赏胜率预估重做：三点距离 + 去种子化 + 实战胜利记录（2026-09-24）

状态：**进行中** —— 船长口径已逐条落码，四闸门全绿，**待船长验收**（视觉与最终手感由船长判）。

## 船长原话（照抄）

1. 「**武器的射程 → 期望距离，那就按照武器最大射程，最小射程，中距离各跑数次。不加入新参数。偏移也取消了。**」
2. 「**去种子化，有胜利记录时取代，三点各10局就够了，"残血"口径按照剩余比例。**」
3. 「**③按敌卡。记录残血最多的一次，如果都是满血则不覆盖。夹回当前射程内。**」
4. 起因为船长报障：「**胜率过于极端，98 胜率打噬口猎杀令连续失败**」。

## 一、旧口径的四个洞（本次要修的）

| # | 洞 | 后果 |
| - | -- | ---- |
| 1 | **固定种子表**（`20260909 + i×常量`） | 所有卡、所有玩家跑的是**同一批时间线**＝"同一条路线跑 N 遍"，不是抽样 ⇒ 系统性偏差（"显示必胜却翻车"的头号嫌疑） |
| 2 | **单点距离**（只有该星系设定/中距档） | 玩家实际可能在自己射程带边缘接战 ⇒ 那个距离上的表现根本没被采样 |
| 3 | **评估与实战不同尺**：不复制弹药档位 | 评估吃基础弹、实战吃 MK2/MK3 |
| 4 | **无实战反馈** | 打过的卡与没打过的卡用同一套采样，实战里已经证明可行的那个距离用不上 |

## 二、方案（逐条对照原话）

1. **三点距离采样**（原话 1）：按该船**主武器**的 `maxRangeM` / `minRangeM` / 中距档（`desiredRangeFor(me,'mid')`）
   各跑 `BOUNTY_MC_RUNS` 局；三处都复用引擎自己的 `mainWeaponOf` + `desiredRangeFor` ⇒ **不新增参数**；
   开战仍走 `startBattleFor`（与实战同一入口、同一夹紧），**旧"偏移"取消**。
2. **去种子化**（原话 2）：每局种子 = `散列(敌卡 id + 舰船装配/技能指纹 + 距离点 + 局号)` ⇒
   **同输入逐位可复现**（预热缓存稳定、用例可断言），**不同卡/不同点互不相关**（真抽样）。
3. **每点 10 局**（原话 2）：`BOUNTY_MC_RUNS = 10`（三点共 30 局/卡；旧口径单点 63 局）。
4. **实战胜利记录取代采样**（原话 2、3）：`state.winRecord[敌卡 id] = { desireM, remainPct }`；
   **只由实战胜利写入**（模拟评估是只读克隆，绝不写 ⇒ 不会自证）；**只在剩余比例更高时覆盖**
   （等值不写 ⇒ "两次都满血则不覆盖"）；消费时**夹回当前射程带**（换过武器仍能吃记录）。
5. **「残血」口径 = 剩余比例**（原话 2）：`(装甲 + 结构) ÷ 满值`（`hpMax`；护盾每场满值重建、不进分子）。
6. **同一场仗的四项对齐**（船长 2026-09-24 追问确认）：弹药 = **玩家当前档位**（快照复制 `ammoPref`）·
   补给 = **完全充足**（料放进取用开关真正读的那个池：仓库 或 该舰货仓）· **享受全部战斗加成**
   （照会战判定 `importantTasks['first-bounty']`、窝点档位、派系活跃都带进快照）· 存进快照的每星系目标距离照旧生效。
7. **输出新增读数**：`worstWinRate`（三点最低者 = "运气最差的距离上也赢得下来吗"）· `points`（逐点读数）·
   `recorded`（本卡是否走记录距离）。

## 四、验证（实测）

- **闸门**：`npm run typecheck` 全绿 · `npm run test -w @whale/core` **196 文件 / 2215 用例全绿** ·
  `content:check` · `l10n:check` · `ui:rot-check` · `ui:theme-check` · `npm run build` 全绿。
- **单卡耗时**（真内容 + T1 护卫舰裸装，`tools/_win-probe.ts` 实测后已删）：10 局/点 均 **28ms**（最大 71ms）；
  旧口径 63 局/点 均 **138ms**（最大 368ms）⇒ 预热**便宜约 5 倍**，引擎"每批 ≤2 张、预算 8ms"的泵自限为每批 1 张。
- **三点读数的实际意义**（同一次实测）：`ano-abandoned-platform` 三点 = **2500m 0% · 200m 30% · 2000m 0%**
  ⇒ 平均 10%、最差 0%——同一条船、同一张卡，**拉开距离就输、贴上去才有三成**。
  旧口径只会给一个数，正是"看着还行、实战翻车"的来源。
- **存档**：无记录的档**不落 `winRecord` 键**（与改动前逐字一致）；有记录则随档往返一致；非法行（距离 ≤0、比例越界）读档即清洗。

## 五、已知取舍与待裁决点

1. **派系活跃卡 / 赏金任务（窝点）卡仍走解析口径**（`bountyWinPercentGuarded`）：MC 缓存按**未加成卡**建键，
   而这两类卡的展示必须与实战一致（威胁 +10% / 窝点强化）。要不要把这两类也纳入 MC
   （引擎按"派生卡"另建键、快照临时置 `factionActive`/`lairTier`）——**等船长定**。
2. **「最差距离胜率」目前只在悬停里**；若希望玩家一眼看到，可提到主读数旁（新增一行文案）——**等船长定**。
3. **「计算中」是过渡态**：战力指纹一变就全板重算，头 1~3 秒部分卡显示「计算中」（不再显示旧口径的数）。
4. **记录按基础卡 id 记账**：窝点/派系是本卡的派生强化，共用同一行（打窝点赢下的距离也会被普通悬赏读到）。
5. **编队口径**：本模块服务**星图悬赏**（单舰入口 `startBattleFor`）；虫洞编队战斗走 `startFleetBattleFor`，
   本模块不覆盖（船长「如果是编队战斗则按编队算」在洞内路径由既有实现承担）。
