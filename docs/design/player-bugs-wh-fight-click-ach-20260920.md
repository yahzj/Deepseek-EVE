## 一、报障①：惊动守备后非得把残骸捞空才打得成

**根因（时序错位留下的旧闸门）**：遗迹收尾战的触发时机 **2026-09-16 已由船长改到"遗迹第一次打捞"**
（原为"这一格捞空那一拍"）⇒ 掷中时格上通常还剩 2~3 堆；而 `wormholeBattle.ts` 里
`wormholeStartBattle('ruins')` 的守卫还写着旧口径「**遗迹还没打捞完：先捞空再打。**」
⇒ 玩家点「迎战」只会收到这句拒因，**别的动作又都被 `gridActionBlocked` 拦着** ⇒ 只能一直捞到清空
（带 1 台打捞器时一次只收 1 堆，最明显）。

**第二处口子**：`wormholeActivateAt`（打捞/激活这一口）只查"超载/临时空间"，**没查"欠着一场战斗"**
—— 而 `wormhole.ts` 的 `gridActionBlocked`（扫描/前往/深入都过它）查了；界面那颗「打捞」按钮也没置灰。
所以"待迎战期间还能继续打捞"本身就是没堵上的缺口（栅栏注释却写着"别的动作一律被拦"）。

**修法**
- `packages/core/src/wormholeBattle.ts`：`kind='ruins'` 的守卫改为 **`run.pendingRuinsBattle`**
  （"这一场欠着"的凭据；悬停文案同步改成「遗迹深处的守备还没被惊动：先在遗迹格上打捞一次。」）
  ⇒ **堆没清也能打**；凭空开一场没被惊动的遗迹战仍被拒（`core.wormholeBattle.011`）。
- `packages/core/src/wormhole.ts`：新增 **`wormholePendingBattleReason(state)`**（遗迹守备 / 踩中埋伏两条
  的拒因**单点**）· `gridActionBlocked` 改读它。
- `packages/core/src/wormholeBattle.ts`：`wormholeActivateAt` 开头也读这同一份拒因 ⇒ **待迎战时"再捞一次"被拒**
  （core 收口）。
- 渲染层 `game/engine.ts` 新增 **`wormholeLayerBlocked()`**（只给"欠着的战斗"），面板
  `panels/Wormhole.tsx` 里作业按钮（扫描 / 打捞·采集 / 激活 / 继续深入）读 **`workBlocked = 动作闸 ?? 本条`**
  ⇒ 置灰 + 理由行可见；**撤离仍只读动作闸**（船长 2026-09-16 定过「确认期间层内动作全被拦，**但撤离照走**」）。
- 新增用例（`tests/wormhole-salvage.test.ts`）：1 台打捞器 + 3 堆遗迹 ⇒ 惊动后**格上还有堆**也能迎战；
  待迎战时再点打捞被拒（拒因含「迎战」）；没被惊动时凭空开战仍被拒。

## 二、报障②：进层扫描后地图点不动（"要缩放到最大才能点"）

**根因（本会话"拖动地图"引入的回归）**：`panels/Wormhole.tsx` 的地图框在 `pointerdown` 里
**无条件 `setPointerCapture`**。`click` 由浏览器派发给 **pointerdown 与 pointerup 两个目标的最近公共祖先**，
而捕获把 `pointerup` 改派到**地图框 div** ⇒ 公共祖先变成地图框 ⇒ **格子的 `onClick` 再也不触发**。
`z = 1`（适应窗口）时代码提前 return（不捕获）⇒ **只有"缩放过的地图"点不动**；
而换层自动缩放（半径 > 8 一进层就 > 1）⇒ 报障里"**进层以后**"与"**跟缩放有关**"两句正好对上；
退出面板再进来会把手动缩放复位 ⇒ "**到主界面再返回才好**"。

**修法**
- 捕获时机从"按下即捕获"改成 **"越过拖动阈值、确认是拖动那一刻才捕获"** ⇒ 纯点击从不捕获，
  格子的点击在**任意缩放**下都正常；拖动一旦开始，捕获照旧（拖出地图框不断线）。
- 新增 `onLostPointerCapture` 收尾（`mapDragRef`/`mapPanning` 清干净）：指针被别处抢走时
  `pointerup` 可能不来，留着状态会让之后每次移动都被当成拖动。
- ⚠ 这条属**界面指针行为**，core 用例覆盖不到（仓库里没有 DOM 测试运行器）⇒ 走
  `ui:rot-check` + 请你本地实点一次复测（"点格子有没有反应"是读数，不是观感）。
- ⚠ **过程自记**：改这条时我先用 PowerShell 批量替换写了该文件，PowerShell 5.1 的 `Set-Content -Encoding utf8`
  **加了 BOM 并把中文按 GBK 往返了一次**（整文件乱码）⇒ 当场 `git checkout HEAD --` 复原、改用编辑工具逐处重做。
  教训与约定 §三 同款：**源码/文档一律不裸用 `Set-Content`/`Out-File`**，写中文盘要用 .NET 显式 UTF-8。

## 三、报障③：已经建好的空间站拿不到成就

**根因（"峰值计数"只在事件点记账）**：四个里程碑计数原先都**只在事件发生那一刻**写账——
`sitesBuilt`（升到满档 · `station.ts`）· `aiCoreKinds`（核心入库 · `ai.ts`）·
`matterTechMaxed`（点满一级 · `matterTech.ts`）· `whMaxDepth`（进层 · `wormhole.ts`）。
于是"**事件发生在成就系统之前/之外**"的档（老档、或先建好站再更新到本版）账上永远是 0 ⇒
成就判据读 `firstStatOf` 永远不够 ⇒ **拿不到**。（`station.ts` 里那句"老档已有建成站的也照旧自愈"
当时只是注释里的一厢情愿：那段代码只在"升到满档"那条分支里跑。）

**修法**：`packages/core/src/engine.ts` 新增 **`reconcilePeakStats(state, ctx)`**，在成就判定前每拍现算一次
（三个读数都是小表遍历，代价可忽略；`peakFirst` 只升不降 ⇒ 幂等、零迁移）：
① 副空间站 = `stage >= tiers.length` 的座数 ② AI 核心 = 库存 > 0 的类数 ③ 谜质科技 = 已满级节点数
④ 层深 = 当前 `run.depth`（出洞后这个量不可推导 ⇒ 事件点那条仍是主路）。
顺带把 `aiCoreKinds` / `sitesBuilt` **补进 `FirstStatKey` 联合**（一直在用、只是漏登记）。

**另修一处同源内容偏差**：成就「谜质通晓」的阈值原为 **23 项**（= 当时的节点数），而本会话新增 C 线 T4
「工业多核调度」后节点表已是 **24** ⇒ 阈值与说明同步改成 24（`data/src/achievements.ts` + 用例）。

**新增用例**（`tests/achievements.test.ts`）：已建成副空间站（`stage` 满档）但账上无 `sitesBuilt` 的档，
**下一拍补齐并发出「拓荒者」**；AI 核心 / 谜质满级数同样靠现算兜底。

### 追加：船长令「里程碑都加入追溯检查」（同日）

**船长原话（照抄）**：「**里程碑都加入追溯检查。**」

⇒ 追溯面从上面那 4 个键**扩到全部六个里程碑计数键**（18 枚徽章全覆盖），函数改名
**`engine.reconcileMilestoneStats`**，并在函数头把**每个键的推导来源与精度**列成表（改判定先改那张表）：

| 键 | 现算来源 | 精度 |
|---|---|---|
| `rareBoxes` | `Σ state.rareBoxesOpened`（与 `industry.ts` 开箱那一刻同一本账） | **精确** |
| `sitesBuilt` | `stage >= tiers.length` 的副站座数（与 `station.ts` 升满档同一把尺） | **精确** |
| `matterTechMaxed` | 已满级节点数（与 `matterTech.ts` 同一把尺） | **精确** |
| `aiCoreKinds` | 库存里 > 0 的核心类数（与 `gainAiCore` 同一把尺） | 下界（某类花光后现算会少 ⇒ 只抬不降） |
| `whMaxDepth` | 这趟的 `run.depth` ＋ **最近一趟结算单 `lastSettle.depth`** | **下界**（更早那些趟没留痕） |
| `whBossClears` | 这趟的 `run.bossCleared` | **下界**（跨趟累计只在事件点记） |

**为什么下界也敢用**：成就判据是 `计数 >= 阈值`，抬到"至少这么多"只会让**该拿的**拿到，不会凭空发
（现算值本身就是真实发生过的事实）。所有写入都走 `peakFirst`（只升不降）⇒ 幂等、不回退、零迁移。

**仍不可追溯的两处**（写在函数注释里，谁要彻底追溯就得动存档结构 ⇒ 需船长点头）：
① `aiCoreKinds`：某类核心**被花光**后库存里就没有它了；② `whBossClears`：**跨趟累计**没有留痕
（层深至少还能从"最近一趟结算单"捞回一点）。

**新增用例**：`rareBoxesOpened` 逐型求和 ⇒ 精确补齐 7 箱并发出「初启箱庭」「拾荒老手」、不误发 20 箱那枚；
真进一趟洞 ⇒ 层深 3 / 守卫 2 追溯到位（发「深渊宿将」「斩层者」，不发第 4 层那枚）；
出洞后只剩结算单 ⇒ 层深照样按 `lastSettle.depth = 5` 追溯（守卫数不抬）。

⚠ **没动的**：**里程碑任务链（次数链）** 的进度仍按既有裁定（2026-09-17：老档只判「第一次」13 条完成、
其余终身计数老档没有 ⇒ **链从 0 起**）；链条目与成就读同一本账，追溯规则这次只落在成就那六个键上。
若你说的「里程碑」是指**链**，说一声我把同一张推导表接到链上去（能推导的只有 `scan`／`skills` 两条）。
