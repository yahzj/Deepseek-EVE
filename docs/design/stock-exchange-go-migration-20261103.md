## 结论先行

1. **目标**：服务端整体从 Node/TS 迁到 Go——主服务（账号/云存档/聊天/钱包/账本/现货市场/生产校验/文档）+ 交易所（撮合/行情/杠杆/AI）。Node 版保留为参照实现与回滚。
2. **硬约束：API 契约不变**。迁完后游戏客户端、服务器自带网页客户端、现有账号/存档/会话全部零改动；靠「黑盒契约测试」保证两套实现同口径。
3. **数据不迁格式**：继续用同一个 SQLite 文件与表结构（Go 用 `modernc.org/sqlite` 纯 Go 驱动）；迁移期**同一时刻只有一个写者**。
4. **渐进式切换，逐域上线**：每次只切一个域，先影子读比对、再切写、观察后再下一个；任何时候可切回 Node。
5. **P1 先做交易所撮合骨架**（不接资金、不接生产库），验证 Go 的 CLOB/撮合/恢复/测试链路，再往主服务域扩展。
6. **部署形态**：本地交叉编译 `GOOS=linux GOARCH=amd64` 静态二进制，服务器**不需要装 Go**，systemd 双单元（8787 主 / 8788 交易所）。

## 一、迁移阶段（G0 → G6）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **G0 撮合骨架（本批）** | Go 交易所服务：4 标的、CLOB、撮合、REST（stocks/book/trades/orders/cancel/mine）、SQLite 持久化 + 快照/事件日志恢复、单元测试 | `go test ./...` 全绿；交叉编译产物能起；HTTP 契约与 Node B0-1 对齐 |
| G1 认证与会话 | 用户名密码 scrypt、sessions 多设备、设备码旧通道、恢复码 | 与 Node 版登录/会话互通用例通过；旧 token 可直接用 |
| G2 云存档 | saves 版本/历史/409 冲突 | 往返测试、并发写冲突测试 |
| G3 聊天 + 静态 + 文档 | WS 双频道、3 秒打包、/docs 渲染、public 静态 | WS 端到端；与现有客户端联调 |
| G4 市场 + 产出校验 | 现货订单簿、5% 税、最低价、实例签名、产出配额 | 经济链路回归；账本余额守恒 |
| G5 交易所完整 | B0-2 行情推送 → B1 杠杆/强平/双仓位 → B2 AI 人格/事件/分红 → B3 量化 | 各批次按设计稿验收 |
| G6 切换与下线 | 主服务切 Go，Node 转只读备份/下线 | 全链路黑盒回归 + 数据对账 + 回滚演练 |

> 依赖关系：G1 是 G2/G3/G4 的前置（一切都要会话）；G4 依赖账本（搬 ledger 之前先确保哈希链校验等价）；G5 可在 G1 之后并行推进（交易所独立部署）。

## 二、兼容性契约

1. **HTTP**：路径、方法、请求/响应字段、错误码、状态码与 Node 版逐字节对齐；`{code,message}` 不变。
2. **鉴权**：`Authorization: Bearer`；Go 直接读同一个 `sessions` 表校验（只读），切写时统一切换。
3. **WS**：同一路径 `/api/chat/ws?token=`；消息帧格式不变。
4. **数据库**：表名/列名/索引与 Node 版一致；Go 迁移只加不改（新表用 `CREATE TABLE IF NOT EXISTS`）。
5. **静态内容**：`content-csv/` 目录与 CSV 格式不变；Go 读同一份文件。
6. **时间与随机**：服务端墙钟；随机种子与计数器持久化（`meta` 表），保证重启后可复现。

---

## 三、测试策略

1. **Go 单元测试**：撮合、冻结、账本、恢复、并发安全（`go test -race`）。
2. **黑盒契约测试**：一套独立脚本（Node 或 Go 写的 HTTP 客户端），对「Node 现有实现」和「Go 新实现」跑同一组用例，逐字段比对；**这是迁移验收的核心**。
3. **影子比对**：切换前让 Go 读同一份 DB 提供只读 API，与 Node 响应比对（只读影子不写库）。
4. **数据对账**：钱包余额、账本行数、`prev_hash` 链、存档版本数、订单/成交数量逐项核对。
5. **回滚演练**：每次切域前演练「切回 Node」，确保可逆。

---

## 四、部署与切换

- 构建：本地 `GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w"`，产物 scp 上服务器；
- 进程：`whale-server`(8787) + `whale-exchange`(8788) 两个 systemd 单元，独立重启与日志；
- 切换：维护窗口内停 Node → 起 Go → 冒烟（健康检查 + 登录 + 存档 + 下单）→ 观察 24h → 下一个域；
- 回滚：保留 Node 二进制与数据库备份，切回命令写进 runbook。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 双实现漂移（Node/Go 行为不一致） | 黑盒契约测试 + 影子比对 + 逐域切换 |
| 数据竞争/写者冲突 | 同一时刻单写者；切换窗口停旧起新；SQLite WAL + busy timeout |
| 测试翻译遗漏（111 个 Node 用例） | 先建契约测试再迁移；Node 用例作为行为参考，不逐行翻译 |
| 迁移期玩家数据风险 | 每次切换前全量备份（每小时策略已落地中）+ 回滚演练 |
| 时间成本 | 分阶段交付，每阶段可独立验收；不追求一次性大爆炸迁移 |
