# 虫洞「踩中埋伏」：进未扫描地点踩到敌人 ⇒ 事件提醒 → 确认开战（2026-09-16）

> **状态：进行中**（工作文档；船长验收 + 合入 main 后按 AGENTS.md §8 归档三步：并入 roadmap ＋ 词典登记 → 删本文件 → 重跑 `docs:index`）

## 一、船长原话（照抄）

1. 「**添加一个新的提示，如果移动途中被敌方拦截或者进入未扫描地点踩到怪了，都要弹窗提示，玩家确认后进入战斗。**」
2. 当轮澄清（回答"这提示用哪种形态"时，照抄）：「**这并不是新机制吧，触发形式应该是踩中雷后，调用事件提醒，
   之后触发战斗，并不是在战斗前提示。**」
3. 同轮四答：**确认前只能选「开战」** · **路径拦截那条不改**（现状即"移动前确认 → 移动＋开战"）·
   **已知敌格不弹**（明知故往直接开打）· 提醒**只写来由与坐标**。

## 二、现状（动手前核实的）

| 事实 | 出处 |
|---|---|
| **仓库里已有"先提醒、确认后才开战"的成套语言**：`run.pendingRuinsBattle` ＋ 页内警告条（红档 ＋ 单个按钮）＋ 点确认才开战；标记没清时别的层内动作全被拦 | 「遗迹惊扰守备」（船长 2026-09-13：`deferRuinsBattle`） |
| **"途中被拦截"那条**：移动**前**弹确认栏（「路径上有敌人阻拦」）⇒ 确认后移动＋**立刻开战** | `wormholeGridTravel(confirmIntercept)` ＋ `wormholeTravelTo` |
| **"进未扫描地点踩到怪"**：**完全没有提示** —— 到达那一刻直接进战斗 | `arrived.autoBattle` → `wormholeTravelTo` → `wormholeStartBattle('node')` |
| 「撤离」只被"战斗进行中"拦（`run.battle`），**不受 pending 标记影响** | `wormholeExtract` |

⇒ 结论：**不新造机制** —— 把 `pendingRuinsBattle` 那套**原样复用**到"踩中埋伏"这条触发链上（船长说的"调用事件提醒，
之后触发战斗"正是这个形状）。

## 三、机制（落码口径）

1. **触发**：玩家点了一个**还没扫描过的地点**、走到才发现里面是敌人（舰船信号）⇒ 到达那一刻
   **先发事件提醒、不直接开打**（`arrived.ambush`）。
2. **事件提醒**＝两条同源：**事件日志**「🕳 踩中埋伏（Q?,R?）：这个地点出发前没扫描过——里面是敌人，准备交火」
   ＋ **界面警告条**「⚠ **踩中埋伏**：这个地点（Q?,R?）出发前没有扫描过，里面是敌人——对方已经发现我们，
   打完才能继续探索」（**只写来由与坐标**，船长选定）。
3. **玩家确认**：点「**开战**」⇒ `wormholeStartBattle(state, ctx, 'node')` ⇒ 真进战斗（成功即清标记）。
   确认之前**别的层内动作一律被拦**（`gridActionBlocked`）——**撤离不受影响**（逃生门与遗迹那条同口径；
   ⚠ 这一条按"同级相似项"照抄遗迹的做法，**若船长要求连撤离也堵，一句话即改**）。
4. **只在"出发前未知"时成立**（船长 Q4 = 甲）：**已知**的敌格是自己点上去的（明知故往）⇒ 照旧到达即开打。
5. **路径拦截那条不改**（船长 Q3 = 甲）：拦路格即便"出发前未扫描"，移动前已经确认过"会被拦下并开战"
   ⇒ 照旧**直接开打**，不进埋伏流程（避免两次确认）。
6. **自动化不吃这套**：`deferAmbush` **只有界面传** ⇒ 读数工具 / 老调用方 / 用例不传 = **原行为**（到达即开打），
   工具读数与既有用例零变化。
