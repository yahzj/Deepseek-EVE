# 增压加速腔误接推进周期

> **状态：已修正，完整回归通过，船长授权推送**（一号 · main · 2026-10-09）
> 船长原话：「发现一个BUG，增压加速腔不是推进器，但是却有推进器相关点火冷却的说明」。
> 范围/不做：增压加速腔自身的速度生效与相关参数显示；不改其他速度件、推进器周期、价格、CPU、掉落和存档结构。星图UI任务保留，不在本轮修改。
> 批准依据：船长「修正后推送，然后外面继续星系相关的内容」，采用下列独立常驻渐增方案并授权本批发布。

## 复现与原因

无需读取个人存档。`shipInfo.tsx`的`crossFamilyShort`将全部非推进槽的`speedBonusPct`交给`thrusterCycleShort`；`moduleInfoLines`对同字段使用`ui.shipInfo.168`「点火期间」。因此增压加速腔的短行与详情也出现点火/冷却说明。

实际效果也有绑定：`playerSpec.ts`把它与所有速度收益汇入`thrusterBoost`/`speedBonusModules`，`combat.ts`的`unitSpeedMulOf`只有在`thrusterPhase(...).boosting`时消费`battleSpeedBonusOf`，否则返回1。结果是即使未装推进器，增压加速腔也只在默认点火窗口有效，60秒蓄压到峰值后遇到冷却归零。这不是单纯的文案问题。

经办责任：最初船长指定进入战斗逐渐增加、60秒到25%；经办人在补充方案中加入了「继承现有推进器周期」并据此实现。虽然补充方案曾获确认，当前报障明确指出物件不是推进器；按规则先报告并重新确认修正，不静默推翻此前方案、不只修改文案隐藏机制。

## 推荐修正方案

- 本件无点火或冷却。单件开战时5%，按整场游戏战斗时钟线性增长，30秒15%、60秒25%，之后本场持续保持；跨波不重置，新场重新开始，暂停不按墙上时间推进，读档/离线沿原战斗时钟续算。
- 仍与同舰速度件采用既有同池折权加算：推进器冷却时仅移除推进器的周期收益，本件仍在；按当前有效收益排序。其他原速度件的生效窗口保持既有行为，不借本次修复改为常驻。
- 捕获网的「关闭推进器」不单独关闭本件，捕获网已有的整体机动减速仍作用于最终速度；不改变网的减速系数或其他效果。
- 短行和详情统一显示本件5%→25%、60秒及多装递减，无推进器点火/冷却词。速度基线和实际战斗读数同步核对，避免仍把本件归到加力推进行。
- CPU30、基准价280万、分类/低槽、最大收益、多件递减权重和入侵掉落均不改。

文案候选优先复用现有`ui.alienLoot.004`参数模板「+{p1}% → +{p2}%，{p3}秒达到峰值」，补充常驻语义的中文短句先交审；英文仍仅登记待译。
