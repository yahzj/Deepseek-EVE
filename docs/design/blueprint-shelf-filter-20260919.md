## 1. 根因（真档只读坐实，非"书丢了"）

真档（`%APPDATA%\whale-idle\save.json`）读数：

| 项 | 读数 | 说明 |
|---|---|---|
| `blueprintStock` | `{}` | 书架上一本书都没有 |
| `learnedRecipes` | 85 条（其中**舰船蓝图 56 条**） | 学习**消耗一本**（`market.learnBlueprint` 扣 1、归零即删）⇒ 学过就没了，**书没丢** |
| 碎片 | `frag-mod-cargo-2` 26 · `frag-mod-cargo-3` 130 · `frag-mod-turret-kin-2` 1 | 这三张碎片卡**全是「装备」档**（`bp-cargo-2` / `bp-cargo-3` / `bp-turret-2`） |

两条口径叠加出死角：① 09-14 船长定「**蓝图书架也加入组装机同样的筛选**」；
② 书架**只列手上还没学的书**（全目录带筛选的是隔壁**组装机**）。
⇒ 书架上 `kind` 三个标签**静态全列**，而"舰船/消耗品"两档一张卡都没有 ⇒ 点下去必然空
（旧代码还留着一句"该筛选下书架里没有对应的书"兜底，但玩家看到的就是空网格）。
这正是 2026-09-14 注释里那条「避免看不见的筛选」要防的坑。

## 2. 改动清单（只动蓝图书架，不碰组装机）

`apps/desktop/src/renderer/src/panels/Industry.tsx`（`BlueprintShelfPanel`）：

1. 先把两类卡片各建一份**未筛选**的清单（蓝图书卡 `bookCards` ＋ 碎片逆向卡 `fragCards`），
   再据此**现算**三档标签：
   - `tabsShown`：一级只列"真有卡片"的门类（「全部」常显）；
   - `subsShown`：二级只在当前门类下真有该子类的卡片时列出（键与顺序仍取 `manuSubsOf` 单点表）；
   - `usesShown`：三级同样只列真有的图纸档（「全部图纸」常显）。
2. **自动回落**：卡片集合变化后（学掉最后一张该类书 / 逆向解锁 / 新书到架）若原选择已无卡，
   回落到「全部 / 全部子类 / 全部图纸」（`kindMissing` / `subMissing` + 一个 effect）。
3. 筛选判定收成单个 `passKeys()`（三个条件一处写），蓝图书与碎片卡共用。
4. 空态文案改写：`该筛选下书架里没有对应的书——…` ⇒ **`这一类书架里没有书，也没有可逆向的碎片。`**，
   并**按 2026-09-19 双语规矩**包 `t(...)` ＋ 在 `i18n/dict.en.ts` 登记英文
   （`No books or redeemable fragments in this category on the shelf.`）。
5. 空态早退判据由"书 0 本且筛后无碎片卡"改为"**两类卡片合计为 0**"（口径与上面一致）。

**不做**：不改组装机（它是全目录，标签必须常显）；不改碎片卡的门类归属；零数值 / 零存档改动、不需迁移。

## 6. 追加（同日 · 船长追问）：**删掉碎片卡头的「碎片 N/M」标签**

- **船长原话（照抄）**：「蓝图书架为什么要在卡片内的蓝图名称右边添加一个碎片数量的标签？」

  「×N」（持有本数）抄的版式。但书卡的 ×N 是**重复本数**（直接决定"学习还是出售"），碎片没有对应的

  卡头那颗是**第三次**。
- 处置（船长选「删掉卡头 chip」）：卡片头只留名称；名称的悬停 `title` 同步简化（去掉「（碎片 N/M）」）；
