## 离线自动续用专项检查（2026-10-09）

船长原话：「检查离线时，自动使用技能加速的功能是否正常」。本轮仅扩展已有诊断工具和记录，不修改业务实现。

离线正式入口调用 `simulateOffline`；开关及药效截止均进 `save.ts` 白名单，启动/读档/导入都会调离线结算。普通离线通常一次 `advanceGame(deltaMs)`，重复出击支路采用30秒分片；两条路径得到不同的扣剂和药效结果。

### 诊断方法

- 同一个合成初始状态，旧药效剩5分钟、自动续用开启；对比一次真实离线结算与30秒分段调用真实离线结算。
- 8小时使用默认额度；32小时用两条离线技能满级；64小时再开铁人。超上限部分不额外推进药效。
- 不执行个人档；队列空着也续用属于既有批准政策，空队列案例不是“故意造无意义用药”。
- 额外执行正式30秒分片支路：用无效循环目标触发该支路，真实循环入口随后关闭它，不创建战斗，但外层既定分片继续；此例只验证时间轴与续用，不代表验证战斗收益。
- 汇总参数 `textParams.p5p1` 与实际扣剂核对；初次诊断误读为 `params`，已修正探针字段并重新执行，不把探针异常当业务问题。

### 专项实跑结果

| 合成状态与结算时长 | 普通整段结算 | 30秒分段对照 | 结论 |
|---|---|---|---|
| 空队列8h | 扣1枚，剩24h | 扣1枚，剩16h5m | 补用被算在离线末刻，药效未扣已结算时间 |
| 空队列32h | 扣1枚，剩24h | 扣2枚，剩16h5m | 跨多剂少扣且剩余不正确 |
| 铁人空队列64h | 扣1枚，剩24h | 扣3枚，剩8h5m | 同上，正常最大额度可触发 |
| 空队列32h，只剩1枚 | 扣1枚、开关关、仍剩24h | 扣1枚、开关关、药效已过期 | 料尽收口正确，但末刻新药效凭空保留 |
| 巡洋舰操作Lv4→5，32h，库存充足 | 扣2枚，剩48h | 扣2枚，剩16h5m | 即使扣剂相同，截止时间也错误 |
| 铁人巡洋舰操作Lv4→5，32h，只剩1枚 | 已达Lv5、剩24h | 仍Lv4、药效过期 | 新药效错误覆盖整段离线，影响实际等级 |
| 存档重载后8h | 开关保留，扣1枚，剩24h | 开关保留，扣1枚，剩16h5m | 不是开关丢失，仍是补用时点错误 |
| 关闭开关，8h | 不扣剂 | 同政策 | 正常 |
| 旧药效72h，真实离开72h、结算额度8h | 不扣剂、只推进8h、剩64h | 同政策 | 超额度未结算时间不消耗药效，符合当前上限规则 |

正式30秒分片支路实跑8h：扣1枚、剩16h5m，与分段对照一致。这解释了为何是否开启重复出击会影响玩家的药效读数；不能把此支路正常等同普通离线整段也正常。

主树只读真实 core 复核32h：整段库存10→9、剩24h；分段10→8、剩16h5m。同样成立，不是本次手动续时修改引入，也不是零号旧基线独有。

### 根因与附带风险

1. `simulation.ts:183` 普通离线整段推进；`engine.ts:187` 先将 `gameMs` 加到结束时刻，`engine.ts:204` 才补用。`consumables.ts:191` 的 `max(gameMs, until) + 24h` 接在结束时刻后面，而非离线中真正应补用的时刻。
2. 技能队列再用这一药效状态推进整个 `deltaMs`，所以不仅剩余药效错误，库存有限时还会把不能覆盖整段的药效作用于整段训练。
3. `simulation.ts:93` 开启进程级静默记账，`simulation.ts:97` 遇结算额度0直接返回，未关记账；之后在线补用不写逐枚日志。正常玩家默认额度大于0，该例是可注入边界风险，不声称普通玩家必然遇到。异常退出也没有 `finally` 清理，属于同类生命周期风险，未主动制造引擎异常扩展范围。
