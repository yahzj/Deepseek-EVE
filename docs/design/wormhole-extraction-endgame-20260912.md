# 终局玩法「虫洞」（搜打撤底层）· 设计稿

> **状态：设计稿 · 待船长确认**（2026-09-12 一号起草；船长已确认 8 条，见 §1；**未落码**）
> 来源：船长 2026-09-12 提案原话——「我打算推出一个终局玩法的副本，采用的是类似搜打撤的底层。玩家需要准备 4 艘船，
> 前往虫洞探索战斗，迎接一波波敌人和随机事件。玩家有个背包界面，背包大小由玩家舰船合计的货仓决定，
> 约 500 立方的货仓会转换成一个背包格，玩家在虫洞内获得的所有物品都是按格子计算，残骸类物品可以叠加，
> 但是一格最多叠加 500 立方。玩家最终带着货仓内的东西离开虫洞算作结束。」
> 2026-09-12 第二轮追加：「提高虚空晶体积。战利品经济按照实际收益算，并不单纯看体积。②副本内战斗没结束无法撤退。③就叫虫洞。
> 这是战斗副本，不可能全带货船。并且还要拟定一个限制惩罚，根据玩家舰船的质量（实际上按级别转换，不是舰船的真实质量），
> 会压塌虫洞入口。因此最多只能带入战列舰，且玩家带入舰船的总质量越高，玩家可以探索的时间（回合数）越短。」

## 二、与既有规则的三处冲突（§5.2 要求先摆出来）

### 冲突 1：战斗目前只有主控 1 艘参战
- **旧规则**：`core/combat.ts` 建档只取 `createPlayerSpec(state, ctx, state.shipId)` —— 一场战斗我方只有 1 艘船；AI 副船从不参战。
- **新提案**：4 艘同时参战。
- **后果**：新增「我方多单位」战斗路径——敌方选靶、胜负判定、弃船结算、表现层（4 条我方舰影与血条）全受影响。
  既有 27 张悬赏卡**仍是单船、不受影响**，两条路径由副本类型分流。**这是本副本最大的一块工程量。**
- **D 批落地口径（船长 2026-09-13 定）**：
  | # | 项 | 口径 |
  |---|---|---|
  | a | 单位标识 | **主控仍是 `player`**（既有单船路径、存档、27 张卡、UI 一字不动）；僚舰 = `ally-1..ally-3`。主控 = `state.shipId`（若在编队里），否则编队第一艘 |
  | b | 逐船建档 | 每艘按**自己的**装配 / 技能 / 三层血 / 逐武器装填 / 抗性建档（`createPlayerSpec` 逐船调用） |
  | c | 弹药 | **整队共用一个池，但池 = 每艘船各自装载量之和**（各船按自己的装配档与货仓装载、**照付成本**）；战斗中共用扣减，战后余额按既有口径退还仓库。⚠ 多船混装**不同弹种档位**时，退还按"主控优先"的档口（共用池记不住两套档位，属已知简化） |
  | d | 编队机动 | **整队平均**（存活我方单位的战斗机动取平均）——与敌方 2026-09-11 定的「敌舰速度按所有船平均值算」**同一把尺**；期望交战距离仍取主控设定 |
  | e | 承伤 | 副本内节点之间我方装甲 / 结构**持久**（与既有 P0 承伤持久化同源，逐船写回各自的 `armorPct`/`durability`） |
  | f | 判负 | **我方全灭才判负**；主控沉了僚舰继续打（与 §六"该船 + 它的背包一起丢、其余船继续"自洽） |
  | g | 本批边界 | 僚舰的**无人机机群 / 近防炮 / 修理包**暂不参战（机群与点防子系统的多单位化留 F 批）；表现层 4 条舰影在 E 批 |

### 冲突 2：既有「结构过半自动脱离」保险
- **旧规则**：普通战斗有 `hullEscapeFrac = 0.5`（结构过半自动脱离、不弃船，且随档保留）。
- **新提案**：**副本内战斗没结束无法撤退**，且船会真沉。
- **后果**：副本内必须**关掉该保险**，否则"打到一半自动溜走"与搜打撤的风险张力矛盾。
- **做法**：副本战斗写 `hullEscapeFrac = null`（或 0），撤退**只发生在节点之间**、由玩家主动发起。
  ⚠ 该机制有测试守着，改动要就地标注与补用例。

### 冲突 3：既有物品体积是「精炼/矿物口径」，不是「占地方的战利品口径」
- 现有物品用 **0.01 m³ 计 1 单位**（虚空晶、三钛合金等），因为它们是**精炼与制造的中间料**。
- 「500 m³ 一格」是给**大宗残骸**设计的阈值 ⇒ 两者混用会出现天文数字（详见 §5.1，已按您的裁定修）。
- **处理**：**提高虚空晶体积**（让高价值物品也占地方）＋**战利品按实际收益计价**（不单纯按体积）。

## 三、虫洞结构（分节点推进）

```text
准备港（选最多 4 艘船 · 总质量不得超上限 · 换算背包格数与回合数）
   ↓  跃入
第 0 节点 ── 【层内节点】战斗 / 拾取点 / 随机事件 ──→ 战斗必须打完 ──→ 层末二选一：
   │                                                     ├─【继续深入】→ 下一节点（更深、更值钱、更硬）
   │                                                     └─【撤离】→ 撤离战 → 结算
   ↓
第 1 层 … 第 2 层 … 第 3 层（BOSS）
   ↓
撤离战（守住跃迁窗口；**打不完就走不了**）→ 带着背包里的东西回港 = 本趟结束
```

**层数：不限层数，每层末尾都有 BOSS**（船长 2026-09-12 已确认）

| 层 | 敌波 | 相对威胁 | 层末 |
|---|---|---|---|
| 第 1 层 | 2 波 | ≈ 威胁 45~60 | **BOSS**（≈ 65） |
| 第 2 层 | 3 波 | ≈ 威胁 65~80 | **BOSS**（≈ 85） |
| 第 3 层 | 3 波 | ≈ 威胁 85~96 | **BOSS**（≈ 100+） |
| 第 4 层及以后 | 3 波 | 继续上探（**威胁每层 ×1.16**） | **BOSS**（本层 ×1.2） |
| 撤离战 | 1 波 | ≈ 当层威胁 × 0.8 | —— |

**为什么"不限层数"不会失控**——三道闸门自己会收口：
1. **回合预算**（§4.3）：8,000 质量以下的轻编队最多 ~50 回合，每节点/每波/每堆都在扣，
   深层走得越远、捡得越多，能走的层数就越少；
2. **BOSS 是门**：打不过本层 BOSS 就进不去下一层，**难度本身就是软上限**；
3. **收益曲线（Q11 已裁定 · 见决议表）**：**收益涨得比难度快**（威胁 ×1.16 / 收益 ×1.2 每层）
   ⇒ 越深越值得冒险；收口不靠"收益转负"，而靠**前两道闸门**（回合预算 + BOSS 是门）。

**每层四类节点**

| 节点 | 内容 | 复用情况 |
|---|---|---|
| 战斗 | 一波波敌人（多波机制**已存在**：`anomaly.waves` + `wN-` 舰位前缀 + 波间间隔 3.3 秒） | `combat.ts` 多波路径 |
| 拾取点 | 散落的残骸堆/货箱，**手动拾取**（耗时、消耗 1 回合，可能被下一波打断） | 新增：拾取交互 + 计时 |
| 随机事件 | 星系已有随机事件框架（`state.events` / `advanceEvents`） | 复用 + 扩充事件池 |
| **层末 BOSS** | 每层压轴战；**打完才出现「继续深入 / 撤离」的抉择** | 复用舰级表 + 新增 BOSS 编成 |
| 撤离 | 玩家在**层末**发起（战斗未结束时不可用） | 新增：撤离相位 |

**敌方选靶模式（船长 2026-09-13 定 · 虫洞内专属机制）**

虫洞内的敌人**不是无脑打第一个**，而是按敌卡配置的选靶模式挑目标（多单位战斗才有意义；单船路径不读本字段 ⇒ 现有 27 张卡零变化）：

| 模式 | 键 | 判定 |
|---|---|---|
| **随机抽取**（缺省） | `random` | 存活我方单位**等权随机**——与"每发独立抽敌人"对称 |
| **打输出最高的** | `top-output` | 按该船武器的**名义 DPS 之和**取最高 |
| **打最小的** | `smallest` | 按**舰种档**（T1 护卫舰 < T2 驱逐舰 < T3 巡洋舰 < T4 战列舰）取最低 |
| **打最大的** | `largest` | 同上取最高 |
| **打非战斗船** | `noncombat` | 按**舰种定位**取非战斗船（`industrial` 工业/采矿 · `hauler` 货舰；`armed` 武装 · `armored` 装甲**不算**）。**编队里没有非战斗船时退回随机** |

- 并列（同输出 / 同档 / 多艘非战斗船）一律**等权随机**；模式随敌卡走（`AnomalyDef.foeTargeting`，不写 = `random`）。
- **只作用于虫洞内敌卡**：现有 27 张悬赏卡、低安遭遇、窝点派生卡**一律不写该字段** ⇒ 行为与随机数消费顺序**逐字节不变**（D 批用 `battle:calibrate --std` 改前/改后逐格对照钉住）。

## 四、★ 质量压塌与回合预算（本轮新增核心机制）

### 4.1 级别 → 质量换算（**按级别，不用真实质量**）

| 舰种档 | 名称 | 折算质量（**船长 2026-09-12 已确认**） |
|---|---|---|
| T1 | 护卫舰 | **500** |
| T2 | 驱逐舰 | **1,500** |
| T3 | 巡洋舰 | **3,500**（沿用建议值） |
| **T4** | **战列舰（＝入场上限）** | **7,000** |
| ~~T5~~ | ~~旗舰~~ | **禁止入场**（压塌入口） |

> 口径依据：`core/balance.ts` 的 `hullClassBaseSpeedMps = {1:340, 2:295, 3:258, 4:205, 5:155}` 与
> `types.ts` 的舰种档命名（**1 护卫舰 / 2 驱逐舰 / 3 巡洋舰 / 4 战列舰 / 5 旗舰**，`hull-class.test.ts` 有守卫）。

### 4.2 两条硬约束

1. **入场上限 = 战列舰（T4）**：任何 **T5 旗舰** 不得编入虫洞队（**皇带鱼级旗舰货舰 = T5，进不去**）。
2. **总质量上限 = 16,000**（**船长 2026-09-12 已确认**）：超上限无法跃入。
   ⇒ 可行编成示例：**4 艘 T3 巡洋舰（14,000）** ✅ · **2×T4 + 1×T2（14,000）** ✅ · **4 艘 T4（24,000）** ❌ 超限。

### 4.3 总质量 → 可探索回合数（**越重、时间越短**）

```text
总质量  = Σ 舰种档折算质量（T1 500 / T2 1,500 / T3 3,500 / T4 7,000）
超上限  → 无法跃入（总质量 > 16,000）
回合预算 = floor( 55 × (1 − 总质量 ÷ 16,000 × 0.53) )
```

> 公式与两个常数（**基础 55 · 系数 0.53**）＝船长 2026-09-12 已确认；下表为**逐格复算后的实测值**
> （脚本独立复算，非手算；`floor(55 × (1 − 14,000/16,000 × 0.53)) = 29`）。

| 编成 | 总质量 | 质量占比 | 回合预算 | 可否入场 |
|---|---|---|---|---|
| 4×T1 护卫舰 | 2,000 | 12.5% | **51** | ✅ |
| 3×T1 + 1×T2 | 3,000 | 18.8% | **49** | ✅ |
| 4×T2 驱逐舰 | 6,000 | 37.5% | **44** | ✅ |
| 2×T3 + 2×T2 | 10,000 | 62.5% | **36** | ✅ |
| 3×T3 + 1×T1 | 11,000 | 68.8% | **34** | ✅ |
| **4×T3 巡洋舰** | 14,000 | 87.5% | **29** | ✅ |
| 2×T4 战列舰 | 14,000 | 87.5% | **29** | ✅ |
| **2×T4 + 1×T2** | 15,500 | 96.9% | **26** | ✅（最重可行编成） |
| 2×T4 + 1×T3 | 17,500 | 109.4% | —— | ❌ 超上限 |
| 4×T4 战列舰 | 28,000 | 175% | —— | ❌ 超上限 |

> 校验：**最轻编队 51 回合 ↔ 最重可行编成 26 回合**，差幅约 **2 倍** ⇒ "越重时间越短"成立，且不至于把重编队压死。
> **标定留档（供日后调参）**：我原先倒推的常数是「基础 48 · 系数 0.6」（那时以 4×T3 = 23 回合为锚）；
> 船长裁定采用 **55 / 0.53** ⇒ 4×T3 = **29 回合**。两者都可，取船长值。

**⚠ 质量表更新后的两处连带（须知道）**：
1. **重装编成更贵了**：T4 由 6,000 提到 7,000 ⇒ **2×T4 + 1×T3（17,500）已超上限**，
   想凑 3 艘重舰只能 **2×T4 + 1×T2（15,500 / 26 回合）**。
2. **玩家现役舰里没有 T4 战列舰**（T4 只有「剑鱼级大型货舰」「蝠鲼级重载货舰」「玄武级重装旗舰」，
   都不是武装舰）⇒ **虫洞主力实际是 T3 巡洋舰**（长尾鲨/锤头鲨/牛鲨/电鳐，900~1,500 万 ISK 一艘、货仓 2,500~3,000 m³），
   **这四艘正是玩家最贵、最舍不得沉的船** —— 与"掉船真痛"的设计意图正好吻合。

**回合怎么消耗（已确认）**：**每经过一个节点消耗 1 回合**；战斗**每多打一波额外 +1**；
拾取**每堆额外 +1**（"手动拾取有风险"的落地方式）。~~回合耗尽 ⇒ **只能撤离**~~（撤离战打不完 = 全损）。

> ⚠ **2026-09-13 改裁定**：本行「只能撤离」作废 —— 撤离**无条件可以开始**（不必先清守卫、不必等回合耗尽），
> 但仍要打赢撤离拦截战；见 §13.5。

> **设计意图（正合您的"不能全带货船"）**：轻快编队（4×T1/T2）回合多但打不动深层；
> 重装编队（T3/T4）打得动但时间紧、捡不完。玩家要在**战力 / 货量 / 时间**三者之间做取舍。

### 4.4 与背包的联动（战斗副本 vs 货船）

| 编成 | 货仓合计 | 背包格数 | 总质量 | 回合 |
|---|---|---|---|---|
| **4×T3 武装巡洋舰**（长尾鲨/锤头鲨/牛鲨/电鳐） | 10,900 m³ | **21 格** | 14,000 | **29** |
| **4×T3 货运**（旗鱼级高速货舰） | 34,000 m³ | **68 格** | 14,000 | **29** |
| 3×T3 武装 + 1×T3 货舰 | 19,900 m³ | **39 格** | 14,000 | **29** |
| 2×T4 重装旗舰（玄武级 19,000 m³ 各）+ 1×T1 采矿（掘洞级 1,800 m³） | 39,800 m³ | **79 格** | 14,500 | **28** |

⇒ 天然形成**风险曲线**：**带武装船打工（格少但打得动）** ↔ **带货船刷量（格多但挨打）**，
而**入场上限（T4）** + **总质量上限（16,000）** + **回合惩罚**三者共同把"4 艘旗舰货舰刷爆"这条路彻底堵死。
⚠ **注意**：4×T3 货运编成**格数最多、回合与武装编成相同（都是 29）**，但**战力最弱** ⇒

### 5.3 ★ 战利品计价（船长裁定：按实际收益，不单纯看体积）

**两条计价方式并存，取其中更合理的一条**（这正是"不单纯看体积"的落地）：

```text
一格的价值 = min( 该格实装物品的单价合计 , 该格物品按 m³ 计的价值上限 )
```

- **大宗类（虚空晶 / 残骸料）**：按 **m³ × 每 m³ 价** 计价；虚空晶 **1,800 ISK/m³** ⇒ 一格 **90 万 ISK**；
- **精品类（装备/蓝图/彩头）**：按**单价**计价（小件也不吃亏），但受**每格价值上限**约束。

**虫洞战利品池（已按"矿物只有虚空晶"收敛）**：

| 精品 | 装备、蓝图 | 单价 5 万~50 万 | 单件（占不满一格） | 值钱但不吃满格 |
| 彩头 | 虫洞专属稀有物 | 单价 100 万~500 万 | —— | 低概率，一趟一件回本 |

## 六、入场 / 撤离 / 结算

| 情形 | 结果 |
|---|---|
| 在**层末**主动撤离并守住撤离战 | 背包内全部物品入账（回港卸入仓库），本趟结束 |
| **战斗中**想撤 | **不允许**（船长裁定：战斗没结束无法撤退）；战斗一开必须打完 |
| 某艘船被打沉 | 该船 + **它货舱对应的背包格**一起丢；其余船继续。**落码口径（船长 2026-09-13 裁定：「扣背包格，不足时丢弃货物」）**：沉船后**背包上限按"剩余编队合计货仓 ÷ 500"现算**（自动缩水），装不下的部分**当场丢**——按**每格价值从低到高**丢（价值 = 每格单位数 × 基础卖价；认不出的物品当最贵、最后丢）；一次丢**一格**（不是整条记录连锅端） |
| 4 艘全沉 | 本次收益归零（船与货全丢），不额外惩罚 |
| **回合耗尽** | ~~只能撤离~~ ⇒ **随时都能撤**（2026-09-13 改裁定，见 §13.5）；撤离战打不完 = 全损 |
| 撤退保险 | **副本内关闭**（`hullEscapeFrac` 不生效，见冲突 2） |

> ⚠ **2026-09-13 修一个真死局（审计抓到）**：「回合耗尽 ⇒ 只能撤离」这条首版**只做了一半**——
> `wormholeExtract` 硬要求「节点已结算 且 层末守卫已清」，于是当**回合付不起当前节点**、
> 且该节点是**拾取/事件**（没有「迎战」这条路可走）时：结算被拒（回合不足）、深入被拒（节点未清）、
> 撤离也被拒 ⇒ **玩家无路可走**（施工期只剩「放弃本趟（调试）」，上线后就是卡死）。
> 修法 = 抽出单点判据 **`wormholeOutOfTurns`**（`turnsLeft ≤ 0` 或 `turnsLeft < 当前节点 cost`）：
> **撤离在这两种情形下放行**（节点没结算、守卫没清都放行——只能撤离就是只能撤离），
> 面板同步给「撤离（进入撤离战）」按钮与读数文案；**战斗中（`run.battle` 非空）仍一律不许撤**
> （船长裁定「战斗没结束不能撤」优先于逃生门）。用例三条：逃生门放行 / 回合充足时守卫照旧是门（防过宽）/
> 战斗中的逃生门不生效；负向验证：注掉逃生门判据 ⇒ 逃生门用例真红。

   实现 = core 单点判据（扩 `shipBusyLabel` 语义）+ 相关动作门口统一拒因文案「该舰在虫洞里：先暂停并召回整队」。
4. **4 舰同屏的呈现**（推荐）：泳道内一列纵队 + 轻微前后错位；**顶部编队条撤掉**（信息已在舰身上）；
   距离尺与弹道锚点仍按主控（逐舰锚点另开一批）。

| **时钟前移（本批踩到的坑）** | 离开期间 `state.gameMs` 照走，而 `advanceBattleFor` 的步进基准是 `while (state.gameMs > battle.lastTickGameMs)` ⇒ **回来会把离开的时间一次补算成战时间**（实测 2×T1 离开 6 秒回来**当场团灭**，冻结白做）。修法 = `wormholeLeave` 记 `leftAtGameMs`，`wormholeResume` 用 `shiftBattleClock()` 把 `startedAtGameMs` / `lastTickGameMs` / `waveClearAt` / `repair.nextPulseAtMs` 整体前移（装填与近防炮冷却是倒计时，不用动） |
| 用例 | 口径①（九个入口被同一条拒因挡住）· 口径②③（离开即释放 + 进度保存 + 返回要空闲）· 口径④（离开期间冻结 + **回来不许补算战时间**：`state.gameMs - lastTickGameMs ≤ 250ms`）· 遭遇并行 · 锚点锁定 · 忙态口径不漂移 |

**已知取舍**：① 与既有"转战"式过渡（采矿→出击自动停采矿）不同，本方案是**拒绝**而非自动停掉对方——
因为"洞内那趟"不能凭空收场（要么打赢撤离战、要么全损）；② 主控编在洞里时洞外锚点冲突，
仍由 `shipLockedInWormhole` 兜（属锁定裁定）。

> **船长原话**：「我想制作类似**背包英雄**那种需要管理的背包格（**但是没有背包，货仓直接代表背包大小**）」

### 12.1 已确认口径（船长逐条裁定）

### 12.2 由裁定推导出的实现细节（**待船长点头**）

1. **网格几何**：**固定 8 列**，行数 = ⌈格数 ÷ 8⌉；末行不足的位置显示为**锁定格**（不可放）。
   20 格 ⇒ 8×3（24 显示位 / 20 可用）；4×T4（28,000 m³ = 56 格）⇒ 8×7 ✓。
2. **货柜物品**：**按族各一种**（A 海盗 / C 异形 / D 守墓 / E 巨构 / G 亡军）——保住「专属掉落按种族库走」这条口径
   （拆解时才知道内容物，族信息不能丢）；体积 2000 m³、`unreleased` 闸门内、形状 2×2。
3. **货柜怎么到手**：遗迹专属判定成功 ⇒ **散落在该格**（与残骸堆同款），玩家**拾取**（占 4 格）；
   放不下 ⇒ **整件拒收**（提示"先腾 4 格"）；撤离成功 ⇒ 货柜进仓库；失败 ⇒ 随趟一起丢。
4. **超载（裁定 8 的落地）**：沉船 ⇒ 格数按剩余编队现算 ⇒ 摆放超出新上限 ⇒ **超载态**：

### 13.2 由裁定推导出的实现细节（已落码）

1. **散货条"放不下"**：一条散货在网格里放不下 ⇒ 记入 `unplacedCells` ⇒ 判为**超载**；装货入口（拾取 / 打捞 / 采集 / 舰船战果）在入口处先拦（复用 F4 的 `wormholeOverloadBlockReason`）。
2. **免激活与"已处理"**：`grid.activated` 仍然表示"这一格的事做完了"（打捞 / 采集捞空时打标），但**不再由"激活"这一步驱动**。
3. **★ "逐堆拾取"在网格层退场（船长 2026-09-13 裁定 A · 收口一份判据）**：
   原先 `wormhole.ts` 的 `wormholeTakePile` 是"手拾一堆 = 1 回合"的老路，**不认识装备**，用的是旧的"格数够"容量判据 ——
   与打捞/采集的 F5 判据（网格里真能摆下 + 放不下整条回滚）**是两套**，也让 0 采集器的编队能逐堆把母矿搬空。
   船长裁定：**网格层不给逐堆拾取** —— 残骸只走「打捞」（要打捞器）、母矿只走「采集」（要采集器），
   装备门槛与回合口径（⌈堆数 ÷ 台数⌉）因此**只有一份实现**。落码：
   ① 删除 `wormhole.ts` 的 `wormholeTakePile`，只留**全仓唯一**的合并实现 `mergeIntoBag`（导出，纯函数）；
   ② 玩家入口只剩 `wormholeSalvage.wormholeTakePileAt`（超载闸 + 形状件分流 + `tryMergeIntoBag` 装舱判据），
   网格层调用**一律拒绝**（「网格层不能逐堆拾取：残骸用「打捞」、母矿用「采集」（都要对应装备）。」· 不扣回合）；
   ③ **逐堆拾取只服务老档线性层**（`run.pendingNode.piles`：那代存档的"每堆 +1 回合"已算进节点 `cost`，故不扣回合）。
   ⚠ 为什么不能把打捞的代码直接搬进 `wormhole.ts`：`state.ts` → `wormhole.ts`（`EMPTY_WORMHOLE_STATE`），
   而 `wormholeSalvage.ts` → `state.ts`（`addLog`）⇒ 反向 import 会成环（模块初始化即报错）。
4. **读数**：探索页头栏加「采集器 N 台」；矿脉堆列表给出「堆数 / 台数 ⇒ 每回合回收 N 堆、共 M 回合」。
5. **货仓页口径**：顶部说明改为"货柜 2×2、散货一种一条横条，**都能拖拽**（点一下选中、再点空格也算落位），放不下整件拒收；整理按钮自动重排"；**货柜清单与散货清单分开列**（货柜按件、散货按类，都可抛弃）。

**结论（给船长）**：
1. **贪深不划算**：激进打法收集多 57%，但到手率从 61% 掉到 38% ⇒ **期望到手反而略低**（283k vs 292k），
   还多损失 44 艘船。撤离开放后，"见好就收"是更优解 —— 这正是船长这条裁定想要的手感。
2. **作业装备的槽位代价很硬**：打捞器与采集器**都占高槽**，交出 2 个高槽后编队在第 1 层就场均损失 1.5~2.6 艘
   （船长难度基准是 5 炮满配「轻松打过第 1 层，允许战损」）。**待定**：是否给作业装备开中/低槽，或另立
   "搜打撤基准编队"的难度线。
3. **到手率**（61% / 38%）应作为配平主指标之一：它同时反映"战损"与"是否及时撤离"。
4. **货柜实际产出远低于设计期望**（0.00~0.07 件/趟）：层 2 起专属概率 12%×1.3^(d-2) 要"走到遗迹 + 捞空 + 掷中"
   三件事同时成立 ⇒ 建议后续单独看这条链（拆解批一并处理）。

### 13.7 货仓"装不下 / 超载"的确切口径（**船长 2026-09-13 问 + 实机档**）

> 船长问：「**当玩家打捞/采矿超出了背包容量时会怎么样？请给我一个这种情况的虫洞存档，我实机测试下**」

**两条完全不同的口径**（实机档：`test-save-wh-bag-*` / `test-save-wh-overload-*`，见 `docs/test-saves/README.md`）：

1. **"装不下"（打捞/采集超出容量）——不是超载**：
   `tryMergeIntoBag` 先按 F5 判据试装（合并 → 对齐货仓格 → **有摆不下的条目就整条回滚**）⇒
   **这一批只回收放得下的那几堆，剩下的留在原地**；日志「这一批只回收了 N 堆」+ 黄字
   「**货仓放不下：这一批只回收了 N 堆，剩下的仍留在原处**」；**那一回合照扣**（打捞器/采集器已经开工）。
   实机读数：wh-bag 档（25/27 格）打捞一批 ⇒ 回收 3 堆、剩 1 堆；去矿脉采集 ⇒ 回收 0 堆 + 同一条黄字。
2. **"超载"只由沉船缩容造成**（船长裁定 8）：格数是 ⌊编队合计货仓 ÷ 500⌋ **现算** ⇒ 船沉了格数就掉，
   而货还在船上 ⇒ `used > capacity` = 超载：**封锁扫描/前往/打捞/采集/拾取**，
   **撤离与深入也要先抛到容量内**；界面顶部红条 + 「一键抛到容量内」（**抛货永远可用 ⇒ 不软锁**）。
   实机读数：wh-overload 档（3 艘 = 20 格，货装 25 格）点地点即提示「货仓超载（25/20 格）：先抛货再继续」；
   一键抛货 ⇒ 0/20 格、立刻恢复可动。

**⚠ 本批修掉的真 BUG（存档清洗丢货条）**：`cleanHoldPlacement` 原先卡 `w,h ≤ 4`，而散货条天生可以更宽
（`cargoShapesFor(n)` 给 `1×n`；n 可到 8 格宽）⇒ **一条 6 格母矿条读档后被当坏值丢掉**：货还在 `run.bag`、
网格里却没有它 ⇒ `unplacedCells` 凭空冒出来 ⇒ **假超载**（玩家会被"先抛货"挡住，甚至抛掉其实还在船上的货）。
探针实测（6 格母矿条）：读档前 `cargoCells=6 / unplaced=0` ⇒ 读档后 `placements` 空、`unplaced=6`。
⇒ 改成按货仓真实几何校验（**宽 ≤ 8 列、高 ≤ 64**），并加回归用例「宽散货条过存档往返不丢」。

**⚠ 待船长定：一类货的几何上限 = 8 格**。一条货条只有两种形状（`1×n` 横 / `n×1` 竖），
而网格只有 8 列 ⇒ **n > 8 时横竖都放不下**（4×T3 的 20 格仓实测：8 格 ✓ / 9 格 ✗ / 12 格 ✗ / 20 格 ✗），
即**同一种货最多 4000 单位（母矿）或 4000 m³（残骸一类）**，再多就打捞不上来（报"货仓放不下"）。三个选项：
- **(a) 拆条**：一种货允许多条货条（每 8 格一条）——最贴合"背包英雄"观感，但要改 `wormholeHoldSyncCargo`
  的"一物品一条"不变式与逐条拖拽/抛弃口径；
- **(b) 补形状**：给散货条加矩形块（如 12 格 = 6×2、8 格 = 4×2）⇒ 单类上限提到"整仓"，改动集中在
  `cargoShapesFor`（判据 `canPlace` 本就支持任意 w×h）；
- **(c) 保持现状** + 文案说明"一类货最多 8 格"。
**经办人推荐 (b)**：改动最小、观感更好，且不动"一类一条"的账本口径；等船长点头再动。
### 13.8 遗迹安全货柜的搬运（**船长 2026-09-13 问 + 修掉两个真 BUG**）

> 船长问：「**那么，如果玩家打捞出安全货柜这种大体积的怎么办？**」

**修前实况（探针取证 · 两条路都是错的）**：
- 走「打捞」⇒ 货柜被当**普通散货塞进背包**（`tryMergeIntoBag`）：`bag=[{box-relic-a ×1}]`、
  货仓里变成 `1×1` 的货条、**只占 1 格**（2000 m³ 的单位体积让 `wormholeUnitsPerSlot` = 0，
  回退成 1 单位/格）⇒ 既不是 **2×2 方块**、也不占 **4 格**，还绕过了"放不下整件拒收"；
- 走「逐堆拾取」⇒ **网格层一律拒绝**（F5 裁定 A 的收口把形状件分支也堵死了）⇒ 正规入口不可达。

**修后口径（按船长 F4 裁定：货柜 2000 m³ = 4 格 · 2×2 · 放不下整件拒收）**：

| 场景 | 行为 |
|---|---|
| 「打捞」遇到货柜堆 | **打捞器搬不动它**：就地停下（不吞、不挡普通堆——货柜是捞空后才散落的，永远排最后），并点明「**点堆位自己拾取装舱**（占 2×2 = 4 格；放不下会整件拒收）」 |
| 玩家「拾取装舱」 | 走 `wormholeHoldStow` ⇒ 进**货仓格**（`kind:'box'`、`2×2`、占 **4 格**）；**网格层普通堆仍不许逐堆拾取**（裁定 A 照旧），只有形状件能走这条路 |
| 货仓腾不出 2×2 | **货仓这一层照旧整件拒收**（`wormholeHoldStow`：不塞散货、不硬挤缝），但**打捞/拾取的外层阶梯会把它接进「临时空间」**（§13.9）——两边都满才散落回原地；**不静默丢** |
| 界面 | 堆列表里**只有形状件**给「拾取装舱（2×2 格）」按钮，普通堆仍显示"待打捞/待采集"；只剩货柜时「打捞」按钮不亮（`bulkPiles` 计数）；另有一行说明"打捞器搬不动它" |
| 撤离 | 货柜在 `run.hold` 里 ⇒ 撤离成功由 `deliverExtraction` 收进仓库（§13.4 修的那条链），失败随趟丢 |

**回归用例**（`wormhole-salvage.test.ts` 新增 4 条）：打捞器搬不动货柜（不进 `bag`、留在原地、日志点明）、
拾取装舱（`2×2` + `shapeCells = 4`）、腾不出 2×2 ⇒ 整件拒收且堆在原地、普通堆仍不许逐堆拾取。
负向验证两组真红（把形状件分支挪回网格判定之后 / 让打捞吞下形状件）。

⚠ **仍待船长定**：一类货的几何上限 8 格（§13.7）——它与本节的"2×2 方块"是同一套格几何，
若选拆条或补矩形块方案，货柜的落点规则不受影响（货柜本来就是 `2×2`）。
#### 本批顺带查出的两个边角洞（**已确认，未擅动**）

1. **信标可能生成在入口格上** ⇒ 「到达即读出终点」只在 `wormholeGridTravel`（移动到达）里触发，
   而入口格开局就 `visited`、不经过移动到达 ⇒ **玩家站在信标上却读不到出口**，只能"先走开一回合再走回来"。
   工具的现政策就照玩家做法走（读出这一步）。
2. **出口格自己可能"未扫描"**（它不参与信号分配）⇒ 信标已标出终点、点它前往仍会被"前往未知地点"拦一次确认。

两条都建议在后续批次里收口（信标不落在入口格 / 出口格随信标一并算作已知），**待船长点头**。
### 13.9 临时空间（收货阶梯）+ 作业前容量预告 + 两条界面几何（**船长 2026-09-13 晚 · 已落码**）

> 船长原话：
> 「**打捞出了大件货时应该放进一个临时空间或者临时背包，让玩家进行协调。并且在打捞挖矿之前货仓可能会满的时候提醒玩家。**」
> 「**进入虫洞的按钮再放大一些，并保持正方形。舰船选择界面高度可以适当缩减，让上一层的虫洞界面不要有滚动条。**」

**① 临时空间 = 收货阶梯的第二层（`run.temp`，可选字段 · 零迁移 · 8 格）**

| 环节 | 行为 |
|---|---|
| 收货 | `wormholeStowOrTemp`：① 先试**货仓格**（形状件 2×2 / 散货对齐网格）→ ② 放不下 ⇒ **临时空间** → ③ 两边都满 ⇒ 才失败（**堆留在原地**，日志点明"腾出空间后回来拾取"）。遗迹打捞出的安全货柜、玩家「拾取装舱」都走这一条入口（判据只有一份） |
| 尺子 | 与货仓**同一把尺**：形状件按形状格（货柜 = 4 格）、散货按 ⌈单位 ÷ 每格单位⌉；上限 `WORMHOLE_TEMP_CELLS = 8`（= 2 件货柜） |
| 协调 | 货仓页新增「临时空间」块（已用 N/8 格 + 每件「放进货仓」/「抛弃」）：`wormholeTempStow`（腾出位置才成功，失败原样留在临时空间）/ `wormholeTempDiscard`（手动抛货）。引擎侧 `wormholeTempInfo/wormholeTempStow/wormholeTempDiscard` |
| 撤离 | `deliverExtraction` 把 `run.temp` 里的东西**一并入港**（不算丢）；失败仍随趟丢 |
| 存档 | `save.ts` 清洗：坏条（空 id / 非正数）丢弃、单位取整、空数组不写 |

**② 作业前「货仓可能会满」的预告（不拦路）**：地点信息卡把它摆在打捞/采集按钮之前（琥珀色 `.app-wh-hold-soon`）——
「这一格还有 N 堆、约 X 格，货仓只剩 M 格（差 K 格）——装不下的会留在原地」；按下按钮时再弹一句同样的提醒。
口径 = 把该格剩余**散货堆**按 m³ → 格折算（保守估计，同种物品可能压进已有的半格 ⇒ 文案写"约"），形状件不参与（它有自己的阶梯）。

### 13.12 「矩形 + 末行补齐」：单件不再受矩形取整限制（**船长 2026-09-13 深夜 · 已落码**）

### 13.14 散货「一件一格」+ 抛弃数量控件（**船长 2026-09-13 深夜·第二条 · 已落码**）

> 船长原话（照抄）：「**发现新问题，残骸和母矿不应该合并超过500立方米，当超过时，分作2个单独的物品格
> 并允许单独丢弃或者移动。玩家抛弃时，添加一个让玩家选择抛弃多少的拖动条并允许输入数量。**」

**① 一件一格（散货不再有跨格形状）**

| 项 | 口径 |
|---|---|
| 单件上限 | **一件最多 1 格**（= 每格 `per` 单位 ≈ 500 m³）；超过就**再起一件**：件数 = `⌈单位 ÷ 每格单位⌉`，最后一件可不满 |
| 落形 | 一律 `1×1`（`WORMHOLE_CARGO_PIECE`）⇒ **散货不再有矩形块 / 末行补齐**，那套只留给 2×2 货柜这类形状件 |
| 单独丢 / 单独拖 | 每件一条 `kind:'cargo'` 摆放件（各有 id）⇒ 网格里逐格拖、清单里逐件丢；不再"一种货一条" |
| 读档 | **零迁移**：老档的 8×1 大件照原样显示与计数（按它**实际占的格数**算），下一次动作（打捞/拾取/抛弃/整理）时自然拆成 1 格件 |
| 对齐 | `wormholeHoldSyncCargo` 重写：按"位置池"优先保住玩家摆好的格子，再给多出来的件找空位；装不下的记 `unplaced`（按**格数差**算，老档大件按 8 格算 —— 否则会误报"凭空少 21 格"） |

**② 抛弃数量控件**（同一条船长口径）：散货清单改成**一件一行**（含件号与坐标），点「抛弃」展开控件 =
**拖动条（步长 1，取值精确到单位）+ 可直接输入数量的数字框**，两者双向同步，旁边跟着
「共 N · 抛弃 M 单位（X m³）· 剩 K」读数与「确认抛弃 / 取消」；核心侧 `wormholeHoldDiscard(placementId, units?)`
支持**只丢这一件里的一部分**（余量留在原格，数量账本同步扣减，扣到 0 整件消失）；
形状件（货柜）没有"部分抛弃"，仍只认整件丢。

**⚠ 旧口径作废**：§13.10 的"矩形方块 / 取整损耗"与 §13.12 的"矩形 + 末行补齐"**对散货不再适用**
（一件最多一格，根本不会有跨格形状）；这两节保留为历史记录。§13.12 里"散货给货柜让位"的落点礼让**继续有效**。

**③ 顺带修掉一个真 BUG**：`wormholeDiscardToFit`（一键抛到容量内）原先用 `holdCellsUsed(run.hold)` 算
"形状件占格"，而那是**所有**摆放件的合计（含散货件）⇒ 缩容后刚摆下的散货把额度吃到 0，
**一键抛货会把贵货一起丢光**（实测：`cargoCap` 算成 0、两种货全丢）。改成 `wormholeHoldUsage().shapeCells`
（只数货柜）后，实测只丢便宜的 `ore-veldspar` 5000 单位、留住了 1000 单位母矿。

**验证**：typecheck 四包 0 错 · core **122 文件 / 1268 用例**全绿（改写：散货过存档往返（6 格 = 6 件）、
按量抛的 `unplacedCells` 口径、一键抛货顺序）· `content:check` ✅ · 桌面 build ✅ · 网页版 build ✅。
读数（无头 Chrome + 网页版构建 + 仓库自带测试档 `test-save-wh-bag-…`）：

**① 溢火结转的实现口径**（`rawDamageToKill` + `carryVolleyOverflow`）：
`applyDamage` 是**逐层乘系数**的（层克制 × (1−该层该系抗性)）⇒ 一发"超出部分的实收"与"原始伤害"不是一个量纲；

做法 = 对单调的 `applyDamage(...).dealt` 做二分，求"打空这一艘所需的最小原始伤害"，
`溢出 = 本次原始伤害 − 该值`；然后 `applyDamage` 到**下一艘存活敌舰**（`maxChain = 3` 防一条链无限转）。
**只在本场带了该装置时生效**（`battle.wormhole.volleyOverflow`）——开战时写进战斗快照、逐拍同一份。

**② 战后收口三项**都在洞内战收口处（`settleWormholeBattle`）**现算**（从货仓派生，不留状态）：

### 13.22 临时空间改成 **4 列 × 8 行 = 32 格的格子区**（**船长 2026-09-14 定案 · 已落码**）

**①船长原话（照抄）**：「背包格宽度是 8 格，那么可以在背包格右边添加一个用于丢弃和调整位置的

**谜质储存器拖进来会失效**（离开背包页时丢弃并失效）。

**②状态与几何**：新增可选字段 `run.tempGrid`（与 `run.hold` **同一个类型** `WormholeHoldState`，
`cols = 4`、容量 `WORMHOLE_TEMP_CELLS = 32`）⇒ 格几何 / 拖拽落位 / 换位 / 整理 / 不重叠判据
**全部复用 `wormholeHold`**（`makeHoldState(cols)` 起支持列数）。老档 `run.temp`（一种物品一条的列表）
读档后由 `wormholeNormalizeLegacyTemp` **一次性换算**进 `tempGrid`（旧容量 8 ≤ 新容量 32 ⇒ 必定装得下），
换算完清掉旧字段、不再写入 ⇒ **零迁移**。

**③口径**：
- **收货阶梯** = 「货仓 → 临时空间（32 格）→ 才失败」；散货的**数量账本仍是 `run.bag`**，
  两块板只是位置账本 ⇒ `wormholeHoldSyncCargo` 先按两板原位保留、再货仓找空位、最后临时空间找空位；
  `wormholeHoldUsage.unplacedCells` 也按**两板合计**算（否则把货挪进临时空间会被误报成超载）。
- **临时空间有东西 = 封锁其他操作**（船长 2026-09-14 **追加裁定**：「**临时空间内有物品就不允许进行
  其他操作，和之前的超载类似**」）：扫描 / 前往 / 激活（打捞·采集·开战）/ 拾取 / 撤离 / 深入**一律拦下**，
  理由写明「先去背包页放回货仓或丢弃」。为此 core 新增**动作闸单点** `wormholeActionBlockReason`
  （= 临时空间待清空 ?? 货仓超载），打捞·开战·拾取·撤离·深入都走它；**扫描**因模块依赖方向
  （`wormhole.ts` 不能反向依赖 `wormholeSalvage`）在 `gridActionBlocked` 里读 `run.tempGrid` 单独拦。
  ⇒ 上一版「沉船缩水可以先继续搜打撤」的口径**就此收回**：沉船后**立刻封锁**，与超载同款；
  **不软锁**依旧成立（放回/丢弃都在背包页，丢弃永远可用）。
- **谜质**：增益仍只从 `run.hold` 现算 ⇒ 放进临时空间**不生效**（界面压暗 + 悬停写明）；

- **离页强制**：界面在三个口子（切探索 / ✕ 关面板 / 撤离）拦下并弹确认条（**逐件列出**，
