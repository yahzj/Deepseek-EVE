# 终局玩法「虫洞」（搜打撤底层）· 设计稿

> **状态：设计稿 · 待船长确认**（2026-09-12 一号起草；船长已确认 8 条，见 §1；**未落码**）
> 来源：船长 2026-09-12 提案原话——「我打算推出一个终局玩法的副本，采用的是类似搜打撤的底层。玩家需要准备 4 艘船，
> 前往虫洞探索战斗，迎接一波波敌人和随机事件。玩家有个背包界面，背包大小由玩家舰船合计的货仓决定，
> 约 500 立方的货仓会转换成一个背包格，玩家在虫洞内获得的所有物品都是按格子计算，残骸类物品可以叠加，
> 但是一格最多叠加 500 立方。玩家最终带着货仓内的东西离开虫洞算作结束。」
> 2026-09-12 第二轮追加：「提高虚空晶体积。战利品经济按照实际收益算，并不单纯看体积。②副本内战斗没结束无法撤退。③就叫虫洞。
> 这是战斗副本，不可能全带货船。并且还要拟定一个限制惩罚，根据玩家舰船的质量（实际上按级别转换，不是舰船的真实质量），
> 会压塌虫洞入口。因此最多只能带入战列舰，且玩家带入舰船的总质量越高，玩家可以探索的时间（回合数）越短。」

## 二、与既有规则的三处冲突（§5.2 要求先摆出来）

### 冲突 1：战斗目前只有主控 1 艘参战
- **旧规则**：`core/combat.ts` 建档只取 `createPlayerSpec(state, ctx, state.shipId)` —— 一场战斗我方只有 1 艘船；AI 副船从不参战。
- **新提案**：4 艘同时参战。
- **后果**：新增「我方多单位」战斗路径——敌方选靶、胜负判定、弃船结算、表现层（4 条我方舰影与血条）全受影响。
  既有 27 张悬赏卡**仍是单船、不受影响**，两条路径由副本类型分流。**这是本副本最大的一块工程量。**
- **D 批落地口径（船长 2026-09-13 定）**：
  | # | 项 | 口径 |
  |---|---|---|
  | a | 单位标识 | **主控仍是 `player`**（既有单船路径、存档、27 张卡、UI 一字不动）；僚舰 = `ally-1..ally-3`。主控 = `state.shipId`（若在编队里），否则编队第一艘 |
  | b | 逐船建档 | 每艘按**自己的**装配 / 技能 / 三层血 / 逐武器装填 / 抗性建档（`createPlayerSpec` 逐船调用） |
  | c | 弹药 | **整队共用一个池，但池 = 每艘船各自装载量之和**（各船按自己的装配档与货仓装载、**照付成本**）；战斗中共用扣减，战后余额按既有口径退还仓库。⚠ 多船混装**不同弹种档位**时，退还按"主控优先"的档口（共用池记不住两套档位，属已知简化） |
  | d | 编队机动 | **整队平均**（存活我方单位的战斗机动取平均）——与敌方 2026-09-11 定的「敌舰速度按所有船平均值算」**同一把尺**；期望交战距离仍取主控设定 |
  | e | 承伤 | 副本内节点之间我方装甲 / 结构**持久**（与既有 P0 承伤持久化同源，逐船写回各自的 `armorPct`/`durability`） |
  | f | 判负 | **我方全灭才判负**；主控沉了僚舰继续打（与 §六"该船 + 它的背包一起丢、其余船继续"自洽） |
  | g | 本批边界 | 僚舰的**无人机机群 / 近防炮 / 修理包**暂不参战（机群与点防子系统的多单位化留 F 批）；表现层 4 条舰影在 E 批 |

### 冲突 2：既有「结构过半自动脱离」保险
- **旧规则**：普通战斗有 `hullEscapeFrac = 0.5`（结构过半自动脱离、不弃船，且随档保留）。
- **新提案**：**副本内战斗没结束无法撤退**，且船会真沉。
- **后果**：副本内必须**关掉该保险**，否则"打到一半自动溜走"与搜打撤的风险张力矛盾。
- **做法**：副本战斗写 `hullEscapeFrac = null`（或 0），撤退**只发生在节点之间**、由玩家主动发起。
  ⚠ 该机制有测试守着，改动要就地标注与补用例。

### 冲突 3：既有物品体积是「精炼/矿物口径」，不是「占地方的战利品口径」
- 现有物品用 **0.01 m³ 计 1 单位**（虚空晶、三钛合金等），因为它们是**精炼与制造的中间料**。
- 「500 m³ 一格」是给**大宗残骸**设计的阈值 ⇒ 两者混用会出现天文数字（详见 §5.1，已按您的裁定修）。
- **处理**：**提高虚空晶体积**（让高价值物品也占地方）＋**战利品按实际收益计价**（不单纯按体积）。

## 三、虫洞结构（分节点推进）

```text
准备港（选最多 4 艘船 · 总质量不得超上限 · 换算背包格数与回合数）
   ↓  跃入
第 0 节点 ── 【层内节点】战斗 / 拾取点 / 随机事件 ──→ 战斗必须打完 ──→ 层末二选一：
   │                                                     ├─【继续深入】→ 下一节点（更深、更值钱、更硬）
   │                                                     └─【撤离】→ 撤离战 → 结算
   ↓
第 1 层 … 第 2 层 … 第 3 层（BOSS）
   ↓
撤离战（守住跃迁窗口；**打不完就走不了**）→ 带着背包里的东西回港 = 本趟结束
```

**层数：不限层数，每层末尾都有 BOSS**（船长 2026-09-12 已确认）

| 层 | 敌波 | 相对威胁 | 层末 |
|---|---|---|---|
| 第 1 层 | 2 波 | ≈ 威胁 45~60 | **BOSS**（≈ 65） |
| 第 2 层 | 3 波 | ≈ 威胁 65~80 | **BOSS**（≈ 85） |
| 第 3 层 | 3 波 | ≈ 威胁 85~96 | **BOSS**（≈ 100+） |
| 第 4 层及以后 | 3 波 | 继续上探（**威胁每层 ×1.16**） | **BOSS**（本层 ×1.2） |
| 撤离战 | 1 波 | ≈ 当层威胁 × 0.8 | —— |

**为什么"不限层数"不会失控**——三道闸门自己会收口：
1. **回合预算**（§4.3）：8,000 质量以下的轻编队最多 ~50 回合，每节点/每波/每堆都在扣，
   深层走得越远、捡得越多，能走的层数就越少；
2. **BOSS 是门**：打不过本层 BOSS 就进不去下一层，**难度本身就是软上限**；
3. **收益曲线（Q11 已裁定 · 见决议表）**：**收益涨得比难度快**（威胁 ×1.16 / 收益 ×1.2 每层）
   ⇒ 越深越值得冒险；收口不靠"收益转负"，而靠**前两道闸门**（回合预算 + BOSS 是门）。

**每层四类节点**

| 节点 | 内容 | 复用情况 |
|---|---|---|
| 战斗 | 一波波敌人（多波机制**已存在**：`anomaly.waves` + `wN-` 舰位前缀 + 波间间隔 3.3 秒） | `combat.ts` 多波路径 |
| 拾取点 | 散落的残骸堆/货箱，**手动拾取**（耗时、消耗 1 回合，可能被下一波打断） | 新增：拾取交互 + 计时 |
| 随机事件 | 星系已有随机事件框架（`state.events` / `advanceEvents`） | 复用 + 扩充事件池 |
| **层末 BOSS** | 每层压轴战；**打完才出现「继续深入 / 撤离」的抉择** | 复用舰级表 + 新增 BOSS 编成 |
| 撤离 | 玩家在**层末**发起（战斗未结束时不可用） | 新增：撤离相位 |

**敌方选靶模式（船长 2026-09-13 定 · 虫洞内专属机制）**

虫洞内的敌人**不是无脑打第一个**，而是按敌卡配置的选靶模式挑目标（多单位战斗才有意义；单船路径不读本字段 ⇒ 现有 27 张卡零变化）：

| 模式 | 键 | 判定 |
|---|---|---|
| **随机抽取**（缺省） | `random` | 存活我方单位**等权随机**——与"每发独立抽敌人"对称 |
| **打输出最高的** | `top-output` | 按该船武器的**名义 DPS 之和**取最高 |
| **打最小的** | `smallest` | 按**舰种档**（T1 护卫舰 < T2 驱逐舰 < T3 巡洋舰 < T4 战列舰）取最低 |
| **打最大的** | `largest` | 同上取最高 |
| **打非战斗船** | `noncombat` | 按**舰种定位**取非战斗船（`industrial` 工业/采矿 · `hauler` 货舰；`armed` 武装 · `armored` 装甲**不算**）。**编队里没有非战斗船时退回随机** |

- 并列（同输出 / 同档 / 多艘非战斗船）一律**等权随机**；模式随敌卡走（`AnomalyDef.foeTargeting`，不写 = `random`）。
- **只作用于虫洞内敌卡**：现有 27 张悬赏卡、低安遭遇、窝点派生卡**一律不写该字段** ⇒ 行为与随机数消费顺序**逐字节不变**（D 批用 `battle:calibrate --std` 改前/改后逐格对照钉住）。

## 四、★ 质量压塌与回合预算（本轮新增核心机制）

### 4.1 级别 → 质量换算（**按级别，不用真实质量**）

| 舰种档 | 名称 | 折算质量（**船长 2026-09-12 已确认**） |
|---|---|---|
| T1 | 护卫舰 | **500** |
| T2 | 驱逐舰 | **1,500** |
| T3 | 巡洋舰 | **3,500**（沿用建议值） |
| **T4** | **战列舰（＝入场上限）** | **7,000** |
| ~~T5~~ | ~~旗舰~~ | **禁止入场**（压塌入口） |

> 口径依据：`core/balance.ts` 的 `hullClassBaseSpeedMps = {1:340, 2:295, 3:258, 4:205, 5:155}` 与
> `types.ts` 的舰种档命名（**1 护卫舰 / 2 驱逐舰 / 3 巡洋舰 / 4 战列舰 / 5 旗舰**，`hull-class.test.ts` 有守卫）。

### 4.2 两条硬约束

1. **入场上限 = 战列舰（T4）**：任何 **T5 旗舰** 不得编入虫洞队（**皇带鱼级旗舰货舰 = T5，进不去**）。
2. **总质量上限 = 16,000**（**船长 2026-09-12 已确认**）：超上限无法跃入。
   ⇒ 可行编成示例：**4 艘 T3 巡洋舰（14,000）** ✅ · **2×T4 + 1×T2（14,000）** ✅ · **4 艘 T4（24,000）** ❌ 超限。

### 4.3 总质量 → 可探索回合数（**越重、时间越短**）

```text
总质量  = Σ 舰种档折算质量（T1 500 / T2 1,500 / T3 3,500 / T4 7,000）
超上限  → 无法跃入（总质量 > 16,000）
回合预算 = floor( 55 × (1 − 总质量 ÷ 16,000 × 0.53) )
```

> 公式与两个常数（**基础 55 · 系数 0.53**）＝船长 2026-09-12 已确认；下表为**逐格复算后的实测值**
> （脚本独立复算，非手算；`floor(55 × (1 − 14,000/16,000 × 0.53)) = 29`）。

| 编成 | 总质量 | 质量占比 | 回合预算 | 可否入场 |
|---|---|---|---|---|
| 4×T1 护卫舰 | 2,000 | 12.5% | **51** | ✅ |
| 3×T1 + 1×T2 | 3,000 | 18.8% | **49** | ✅ |
| 4×T2 驱逐舰 | 6,000 | 37.5% | **44** | ✅ |
| 2×T3 + 2×T2 | 10,000 | 62.5% | **36** | ✅ |
| 3×T3 + 1×T1 | 11,000 | 68.8% | **34** | ✅ |
| **4×T3 巡洋舰** | 14,000 | 87.5% | **29** | ✅ |
| 2×T4 战列舰 | 14,000 | 87.5% | **29** | ✅ |
| **2×T4 + 1×T2** | 15,500 | 96.9% | **26** | ✅（最重可行编成） |
| 2×T4 + 1×T3 | 17,500 | 109.4% | —— | ❌ 超上限 |
| 4×T4 战列舰 | 28,000 | 175% | —— | ❌ 超上限 |

> 校验：**最轻编队 51 回合 ↔ 最重可行编成 26 回合**，差幅约 **2 倍** ⇒ "越重时间越短"成立，且不至于把重编队压死。
> **标定留档（供日后调参）**：我原先倒推的常数是「基础 48 · 系数 0.6」（那时以 4×T3 = 23 回合为锚）；
> 船长裁定采用 **55 / 0.53** ⇒ 4×T3 = **29 回合**。两者都可，取船长值。

**⚠ 质量表更新后的两处连带（须知道）**：
1. **重装编成更贵了**：T4 由 6,000 提到 7,000 ⇒ **2×T4 + 1×T3（17,500）已超上限**，
   想凑 3 艘重舰只能 **2×T4 + 1×T2（15,500 / 26 回合）**。
2. **玩家现役舰里没有 T4 战列舰**（T4 只有「剑鱼级大型货舰」「蝠鲼级重载货舰」「玄武级重装旗舰」，
   都不是武装舰）⇒ **虫洞主力实际是 T3 巡洋舰**（长尾鲨/锤头鲨/牛鲨/电鳐，900~1,500 万 ISK 一艘、货仓 2,500~3,000 m³），
   **这四艘正是玩家最贵、最舍不得沉的船** —— 与"掉船真痛"的设计意图正好吻合。

**回合怎么消耗（已确认）**：**每经过一个节点消耗 1 回合**；战斗**每多打一波额外 +1**；
拾取**每堆额外 +1**（"手动拾取有风险"的落地方式）。回合耗尽 ⇒ **只能撤离**（撤离战打不完 = 全损）。

> **设计意图（正合您的"不能全带货船"）**：轻快编队（4×T1/T2）回合多但打不动深层；
> 重装编队（T3/T4）打得动但时间紧、捡不完。玩家要在**战力 / 货量 / 时间**三者之间做取舍。

### 4.4 与背包的联动（战斗副本 vs 货船）

| 编成 | 货仓合计 | 背包格数 | 总质量 | 回合 |
|---|---|---|---|---|
| **4×T3 武装巡洋舰**（长尾鲨/锤头鲨/牛鲨/电鳐） | 10,900 m³ | **21 格** | 14,000 | **29** |
| **4×T3 货运**（旗鱼级高速货舰） | 34,000 m³ | **68 格** | 14,000 | **29** |
| 3×T3 武装 + 1×T3 货舰 | 19,900 m³ | **39 格** | 14,000 | **29** |
| 2×T4 重装旗舰（玄武级 19,000 m³ 各）+ 1×T1 采矿（掘洞级 1,800 m³） | 39,800 m³ | **79 格** | 14,500 | **28** |

⇒ 天然形成**风险曲线**：**带武装船打工（格少但打得动）** ↔ **带货船刷量（格多但挨打）**，
而**入场上限（T4）** + **总质量上限（16,000）** + **回合惩罚**三者共同把"4 艘旗舰货舰刷爆"这条路彻底堵死。
⚠ **注意**：4×T3 货运编成**格数最多、回合与武装编成相同（都是 29）**，但**战力最弱** ⇒
真正的取舍不是"货船更慢"，而是"**货船格子多但打不动深层 BOSS**"——这正是战斗副本该有的形状。

## 五、背包与战利品经济

### 5.1 容量换算（严格按船长口径）

```text
背包格数 = floor( Σ 舰船货仓容量(m³) ÷ 500 )
```

每格**只装一种物品**；**残骸类可叠加，每格上限 500 m³**。

⚠ **换算吃技能与货舱装备加成**：`cargoCapacityM3Of` 已含「深空物流 +4%/级 · 货舱管理 +3%/级 ·
货运舰操作 +5%/级（仅货舰）· 货舱扩展件」⇒ 同编队点满技能者格数更多（最多 ×1.725）。

### 5.3 ★ 战利品计价（船长裁定：按实际收益，不单纯看体积）

**两条计价方式并存，取其中更合理的一条**（这正是"不单纯看体积"的落地）：

```text
一格的价值 = min( 该格实装物品的单价合计 , 该格物品按 m³ 计的价值上限 )
```

- **大宗类（虚空晶 / 残骸料）**：按 **m³ × 每 m³ 价** 计价；虚空晶 **1,800 ISK/m³** ⇒ 一格 **90 万 ISK**；
- **精品类（装备/蓝图/彩头）**：按**单价**计价（小件也不吃亏），但受**每格价值上限**约束。

## 六、入场 / 撤离 / 结算

| 情形 | 结果 |
|---|---|
| 在**层末**主动撤离并守住撤离战 | 背包内全部物品入账（回港卸入仓库），本趟结束 |

| 某艘船被打沉 | 该船 + **它货舱对应的背包格**一起丢；其余船继续。**落码口径（船长 2026-09-13 裁定：「扣背包格，不足时丢弃货物」）**：沉船后**背包上限按"剩余编队合计货仓 ÷ 500"现算**（自动缩水），装不下的部分**当场丢**——按**每格价值从低到高**丢（价值 = 每格单位数 × 基础卖价；认不出的物品当最贵、最后丢）；一次丢**一格**（不是整条记录连锅端） |
| 4 艘全沉 | 本次收益归零（船与货全丢），不额外惩罚 |
| **回合耗尽** | 只能撤离；撤离战打不完 = 全损 |
| 撤退保险 | **副本内关闭**（`hullEscapeFrac` 不生效，见冲突 2） |

> ⚠ **2026-09-13 修一个真死局（审计抓到）**：「回合耗尽 ⇒ 只能撤离」这条首版**只做了一半**——
> `wormholeExtract` 硬要求「节点已结算 且 层末守卫已清」，于是当**回合付不起当前节点**、
> 且该节点是**拾取/事件**（没有「迎战」这条路可走）时：结算被拒（回合不足）、深入被拒（节点未清）、
> 撤离也被拒 ⇒ **玩家无路可走**（施工期只剩「放弃本趟（调试）」，上线后就是卡死）。
> 修法 = 抽出单点判据 **`wormholeOutOfTurns`**（`turnsLeft ≤ 0` 或 `turnsLeft < 当前节点 cost`）：
> **撤离在这两种情形下放行**（节点没结算、守卫没清都放行——只能撤离就是只能撤离），
> 面板同步给「撤离（进入撤离战）」按钮与读数文案；**战斗中（`run.battle` 非空）仍一律不许撤**
> （船长裁定「战斗没结束不能撤」优先于逃生门）。用例三条：逃生门放行 / 回合充足时守卫照旧是门（防过宽）/

1. **进洞门槛**：主控闲置 + 编队各船空闲（「进洞要求洞外主控处于闲置状态」）——属入场校验。
2. **人在洞里 = 占着主控**（`run.attending === true`）：采矿 / 扫描 / 打捞 / 掩护巡逻 / 远征（含 preflight）/
   长途运输 / 亲自开精炼炉 / 回收炉 / 制造线**一律开不了**（AI 核心不受影响）。
3. **临时离开 = 活动停止**：关掉虫洞界面 ⇒ `attending = false`、**主控立刻释放**（可去做别的），
   **虫洞进度原样保存**（层/回合/背包/待处理节点/进行中的战斗都在），**洞内一切冻结**
   （战斗不推进、不掉血、回合不扣）。
4. **返回虫洞要求主控空闲**（「要返回虫洞依旧要处于空闲」）——忙着则面板留在"已离开"态并给出拒因。

**落点（已落，将来改口径照这张表找）**：

| 落点 | 实现 |
|---|---|
| `WormholeRunState` | `attending?: boolean` + `leftAtGameMs?: number`（离开时刻）；`save.ts` 的 `cleanWormhole` 同步清洗（旧档缺省 `false`＝不占主控，安全侧） |
| 判据 | `state.ts` 的 `wormholePilotHoldReason(state)`：`run?.attending === true` ⇒ 拒因。⚠ **没塞进 `pilotUnavailableReason`**（被 `reconcilePilotShip` 每拍读，会改派驾驶船/补发保底船） |
| 九个活动入口 | 采矿 / 扫描 / 打捞 / 掩护巡逻 / 远征（`expeditionPreflight`）/ 长途运输 / `startRefineRun` / `startRecycleRun` / `startManufacturing`（后三者仅 `worker === 'pilot'`） |
| 洞内推进 | `advanceWormhole` 开头：`if (run.attending !== true) return`（冻结） |
| 动作 | `wormholeLeave(state)`（记 `leftAtGameMs`）/ `wormholeResume(state, ctx)`（查"别的活动"、**不把在洞里算忙**）+ 引擎包装 + 面板（开→resume、关→leave、顶部态文案、拒因警告条） |
| 忙态徽标 | `shipBusyLabel`：人在洞里时主控报「虫洞探索中」；离开即消失 |
| **时钟前移（本批踩到的坑）** | 离开期间 `state.gameMs` 照走，而 `advanceBattleFor` 的步进基准是 `while (state.gameMs > battle.lastTickGameMs)` ⇒ **回来会把离开的时间一次补算成战时间**（实测 2×T1 离开 6 秒回来**当场团灭**，冻结白做）。修法 = `wormholeLeave` 记 `leftAtGameMs`，`wormholeResume` 用 `shiftBattleClock()` 把 `startedAtGameMs` / `lastTickGameMs` / `waveClearAt` / `repair.nextPulseAtMs` 整体前移（装填与近防炮冷却是倒计时，不用动） |
| 用例 | 口径①（九个入口被同一条拒因挡住）· 口径②③（离开即释放 + 进度保存 + 返回要空闲）· 口径④（离开期间冻结 + **回来不许补算战时间**：`state.gameMs - lastTickGameMs ≤ 250ms`）· 遭遇并行 · 锚点锁定 · 忙态口径不漂移 |

**已知取舍**：① 与既有"转战"式过渡（采矿→出击自动停采矿）不同，本方案是**拒绝**而非自动停掉对方——
因为"洞内那趟"不能凭空收场（要么打赢撤离战、要么全损）；② 主控编在洞里时洞外锚点冲突，
仍由 `shipLockedInWormhole` 兜（属锁定裁定）。

**F 批校准终读数**（`npm run wormhole:econ` · 参考编队 = **4×巡洋 MK2**（长尾鲨 5×动能 MK2 + 推进/盾/索敌/稳像/装甲 MK2）+ 战斗系 Lv3 · 每节点 1 波 · 5 播种 · 强度系数 **10**）：

| 层 | 威胁（守卫/撤离） | 节点胜率 | 节点时长 | 节点残血 | 守卫胜率 / 残血 | 判定 |
|---|---|---|---|---|---|---|
| 1 | 45（54 / 36） | 100% | 18s | **77%** | 100% / 53% | **轻松打过（允许战损）✓** |
| 2 | 52（62 / 42） | 100% | 25s | **63%** | 100% / 34% | **战损加重 ✓** |

| 5 | 81（97 / 65） | **0%** | 27s | 0% | 0% | **墙** |

> **承伤持久**（船长裁定）⇒ 一趟 2~3 层累计 −40~−70%，「**结束时有概率损失船**」落在第 3 层往后 ✓。
> 收益另判：单位威胁收益逐层**严格上升 ✓**（收益 ×1.2 vs 威胁 ×1.16）。

### 收口对等清单（2026-09-13 审计 · **每一条都要么对齐、要么写明不做**）

> 起因：一天之内在**同一处**（`settleWormholeBattle` 的战后收口）踩了两回"漏结"——
> 先漏**弹药/修理组件退款**（后果：第二场起全队哑火，把假难度当成了数值墙），
> 再漏**机群战损**（后果：洞内无人机打不死，最便宜的一种白嫖）。
> 两次都不是"算法错"，而是**收口少抄了一步**；故把远征 `resolveBattleOutcome` 的收口逐步对照一遍，
> 逐条钉死状态，避免第三回。

| 收口步骤 | 远征 / 遭遇 | 洞内 | 说明 |
|---|---|---|---|
| 弹药退款（只退未打出去的） | ✅ | ✅ **2026-09-13 修** | 漏了 ⇒ 下一场仓库见底、全队哑火 |
| 修理组件退款 | ✅ | ✅ **2026-09-13 修** | 同上；退款按实装弹 id / 组件型逐项退 |
| 承伤持久化（装甲/结构残余） | ✅ | ✅ | 逐船 `persistFleetHullDamage` |
| **机群战损**（永久损失制 + 回收率） | ✅ | ✅ **2026-09-13 修** | 机群池只按**编队首舰**建池（D 批边界），故必须在**扣沉船之前**取到归属 |
| 战报（时长 / 双方开火命中 / 残血） | ✅ | ✅ | 洞内为 `🕳 …交火结束` 单行 |
| 战报里的船体维修装置消耗 | ✅ | ✅ **2026-09-13 修** | 与远征共用 `repairUsageText` |
| 沉船处置 | ✅ 弃船 + 补驾驶船 | ✅ | 洞内口径 = **真丢**（编队剔除 + `loseShip`；旗舰沉了同样自动补驾驶船） |
| 奖金 / 缴获 / 协会声望 | ✅ | ❌ **不做**（有意） | 洞内收益**只走背包**（撤离战入港），洞内不掉 ISK、不给声望 |
| 残骸密度注入 / 稀有残骸 | ✅ | ❌ **不做**（有意） | 洞内不改变星图残骸场——否则"不可见的地牢"会外溢影响可见经济 |
| 自动重复清剿安全阀（机群战损过半停手） | ✅ | ❌ **不做**（有意） | 洞内没有"重复清剿"这个循环，安全阀无从挂 |
| 全灭 | 受损 + 大概率被抢 | **全损**（编队全丢 + 背包清空） | 船长裁定：洞内没有撤退保险（冲突 2 已裁定） |

> 结论：**对齐项 7 条、按裁定不做 4 条**；四条"不做"都是**玩家可见经济面的隔离**，不是遗漏。
> 若将来要给洞内加"残骸/声望/清剿循环"，须先回来改这张表（并重走 §2 四步闸门）。
>
> 另两条同批补的护栏（都是"终局玩法的兜底"，不是新机制）：
> ① **绝不软锁**——全损把主控/唯一一艘也带走了 ⇒ 必须有可驾驶船（`loseShip` 的弃船补驾驶 + 协会保底舰船），
>    否则玩家打完终局内容后**没船可开**；
> ② **战中重载后收口照旧**——`myFleet` / `droneLost` 必须随档（否则重载一次，本场沉掉的船**又活过来**、
>    机群战损也不再落账）。两条都已写成用例，负向验证逐条真红。

> **过档（裁定前的旧读数，已作废）**：
> 参考编队 = **4×T3 长尾鲨（导弹 MK3 满配）**、5 播种实测：第 1~12 层**节点胜率 100%、残血 100%**（4~90 秒），
> 且**「敌开火」列恒为 0**——敌人一炮未放（常规开战距离下长射程编队把近程敌人钉在射程外）。

> 敌人"血是强化后的、炮还是自然值"（总血 11,168 / 单发 1,336，实战每发只掉 6~7 点）。
> 现已抽出单点 `wormholeDerivedAnomaly` 让**开战与逐拍同源**，并补用例「敌人真能疼你」钉死。
