# 启动卡顿与胜率预热排查

> 状态：已实现并以85580256本地合入main，技术验证完成、待实机反馈；三号verify，2026-10-09。不推送。
> 船长原话：「为什么游戏启动后短时间内特别卡，响应缓慢，你添加了什么？」并提供56.666秒性能快照。
> 范围：根据快照定位主线程长任务，对本轮100→10ms步长与原悬赏胜率预热进行合成档隔离对照；不读个人档、不改玩法、不撤回已确认规则、不发布/推送。
> 待裁决：无；单后台Worker、原10ms/30局、任务失效/停止和独立诊断按推荐方案实施。不推送。

## 快照与现场

- 41次挂机推进合计27.2ms、最多4ms；64次notify合计228.7ms、最多9.8ms，React提交合计228.3ms；战斗桶为0。
- 长任务25次累计23050ms、单次最大3503ms；FPS均49.34、最低0.77。不能把总长任务解释为游戏核心推进或重复加上notify/commit，两者有包含关系。
- `game/engine.ts::tick`在推进与notify之外调用`pumpWinCache`，该方法同步调用`estimateBountyWinOn`；每卡三点各10局，整卡结束后才再检查8ms预算，每批最多2卡，预算不能打断单卡或单局。
- 本轮`71a4a788`将共用战斗步长100→10ms、补算上限4万→40万，实战与胜率都使用同一战斗引擎。原预热机制不是本轮新增，但其同步单任务成本会因细步进增加；上一轮分析覆盖单场/多种子实时100ms外部泵，未覆盖整板30局同步预热的长任务预算。
- 界面心跳仍100/500ms，自动存盘仍60秒，敌人参数读取按静态表缓存索引；需要测量，不能仅凭文件大小认定JSON迁移或动画是原因。
- 公告授权保留，因新报障暂停公告落库；尚无公告/业务代码改动，不把公告许可当作性能新结构实施授权。

## 诊断计划

- 用真实`pumpWinCache`方法、真实评估入口与合成新手/合法无人机舰夹具，当前同一源码仅在内存替换100ms/4万步与10ms/40万步。
- 输出逐卡30局耗时、总预热耗时、实际单泵耗时与超50ms次数；核对源码哈希不变和真档未读。
- 本机Node读数只证明同步计算成本，不与玩家具体舰船/Chromium环境作逐毫秒等同。根据事实给出修复建议，不默默改回100ms或降低采样精度。

- 无人机场景整板计算约9.26倍；慢卡为`ano-haze-ambush`2724.5ms、`ano-nadir-static`2150.0ms、`ano-maw-hunt`2100.2ms。返回30局结果全部完整，原合成档JSON不变，全部正式core/data/游戏胶水源码前后哈希不变。
- 原始读数在`tools/_ui-artifacts/startup-win-cache-20261008/report-{100,10}.json`。探针只运行本批自有子进程，已退出；无个人档输入。临时两个脚本已删除，结果与方法留本稿；本轮未改业务实现、公告或主树。
- 与船长快照23秒长任务及3.5秒最大阻塞高度吻合，证明本轮细步进将原同步胜率预热放大为明显启动卡顿路径；不声称已读取船长配装或逐个对应其25条longtask。非战斗的`adv`和notify时长不包含该预热，所以现有快照看上去推进与React都轻。
- 前轮验证遗漏：实时战斗100ms外部泵的平均/P95/峰值不覆盖整板30局同步调用；不能用它证明启动响应无回归。原8ms预算是卡间软预算，单卡不可中断，性能注释的「每拍≤10ms」并非实际约束。

## 已确认修复方案

1. 保留实战和胜率评估的10ms真实战斗算法、每卡30局、原随机种子和结果规则，不回退步长、不降低采样数或使用简化公式。
2. 悬赏预热移至单个后台Web Worker，收到独立战力快照后串行推演；不传可写存档、不消耗真实rng。未完成仍沿用现有缓存未就绪显示。
3. 装配/技能/耐久等指纹变化时丢弃旧任务结果，切换实时战斗、停止引擎及更换状态时取消或暂停任务；限制一个计算worker，不并发预热整板。
4. 将预热耗时单列诊断，补启动输入响应、任务取消/过期结果、缓存一致及两端构建回归，用隐藏隔离窗口合成档验证，不读个人档。

功能域：战斗胜率评估及对应游戏胶水，诊断为共享底层；参照现有`winEstimate`和缓存指纹，不改采矿/存档/经济。按船长确认实施并先本地合入；随后两篇获批公告以96b61de3落库，本轮不远程推送。

## 实施边界

- 复用`buildEvalState/estimateBountyWinOn`，不修改原战斗算法和快照取数规则；worker由同一core/data构建，不复制一套公式。
- 每次最多一张卡在途；指纹、原状态对象、上下文对象或板面ID变化取消并清缓存，实时战斗/不可写/停止取消在途并让路，未完成卡回队头。
- 单worker只在需要时启动，每轮只传一次独立评估快照；完成/取消时释放。失败保留未就绪状态、不主线程回退，诊断记录派发、完成、取消和失败。
- 结构与性能回归先完成并本地合入，随后单独公告批按已审两篇逐字落库，不混改公告正文或新增第三篇。
