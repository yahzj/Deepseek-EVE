# 悬赏胜率预估改蒙特卡洛推演(设计定稿,2026-09-09 船长拍板)

> 状态:已确认(船长:方向"显示低却赢了"为主、N=21、扣分由模拟内部吸收、不加临界文案)。
> 经办:大鲸鱼二号。起因:玩家反馈「预估胜率和实际战斗情况不一致」。

## 一、诊断
- 旧玩家可见预估(`bountyWinPercentGuarded`) = 稳态解析(双方期望距离中点、恒 DPS)+ 外挂
  "带伤扣分"——四个失真近似:**不结算护盾战中被动回充(2%/s)、敌方火力不随减员下降、
  无视接近期与动态距离(命中/近盲/光束衰减随距离变)、带伤开局按残余缩血但预估按满血**。
- 探针实测(5 装配 × 7 档悬赏 × 9 种子):双向大偏差——多处显示 2%(guarded 下限)实际
  9/9 全胜(S4 对穹顶、S1 对坟场),部分对局反向(旧 32~84% 实测 0,如无人机装对赤潮/深渊门)。
- 澄清:离线/连续出击胜负从来不是按预估胜率掷骰,而是与在线同一引擎逐拍真实模拟——
  失真只在展示数字本身。

## 二、定稿方案(船长 2026-09-09 拍板)
- **蒙特卡洛推演 N=21**:玩家可见胜率 = 以当前战力快照跑 21 局真实模拟(独立种子掷骰;
  `startBattleFor + advanceBattleFor` 与实战同引擎:残余甲/壳开局、距离机动/近盲/护盾回充/
  敌方减员/超时血比全内建)取平均;同时记录平均装甲/结构损耗(取代旧独立解析 forecast)。
- **带伤修正内部吸收**:模拟以当前 armorPct/durability 开局,带伤影响天然进入结果;
  旧 `winPenaltyArmorPerFull/HullPerFull` 扣分公式退役(不叠加、不丢失)。
- **缓存与预热(船长提议)**:
  - 战力指纹(驾驶船+装配+无人机清单+技能+当前耐久)变化 → 悬赏全板重算,分帧完成
    (每批 ~60ms、节流 ≥400ms,全板 1~3 秒随批变准;换船/换装/技能升级/维修/损伤自动触发,
    最迟 1s 内开始;交火期跳过避免挤占实时推进);
  - 评估用独立快照与种子,不消耗真实存档 rng/弹药/状态;
  - 平时每秒心跳只读缓存,零新增成本。
- 展示下限 2% 保留(0/21 也显示 2%,语义"仍有希望");不加临界措辞文案(tooltip 改为
  "按当前船况实测推演…单局结果仍有随机波动"口径,去掉失效的"带伤预警口径"字样)。

## 三、口径与边界
- 只替换**玩家可见**预估(悬赏卡 `bountyWinPercentGuarded` 消费点 → engine 缓存);
  `battleWinPreview`(稳态)保留给 AI 门槛与离线模拟工具(playthrough-sim 数万次调用,
  微模拟不可行)——非玩家可见,两套口径注释互指。
- `bountyWinPercentGuarded/bountyDamageForecast` 原实现保留(预热完成前回退显示 +
  活动远征视图/测试兼容),注释标注已退役展示口径。
- 弹药按足量给(不计弹尽,与旧口径一致:展示"火力胜率");教程教学战加成按当前
  onboarding 进度复制,评估与实战同判定。
- 引擎节流参数:批预算 60ms、间隔 ≥400ms。

## 四、验证(探针对照,2026-09-09)
- 新 MC(21 局)vs 实测(9 种子):70 格绝大多数差 0,最大差 ±14pp(处于独立样本抽样
  误差范围 ≈±20pp 内)——"2% 假必败"与高估格全部修正;
- core 新增 winEstimate 用例 6 条(必胜=1/必败=0/可复现/runs/不污染存档/快照战力复制);
- core 全量 + typecheck ×4 + desktop build 绿。

## 五、已知取舍
- 展示 = N=21 抽样平均,临界局(真实 40~60%)仍有 ±11pp 抽样噪声与单局随机——属真实
  随机,非系统偏差;提高 N 可再缩噪声(成本线性,预热分帧可承受)。
- 首次打开/每次战力变化后 1~3 秒内数字从旧口径逐批变准(过渡期短暂显示旧值)。
