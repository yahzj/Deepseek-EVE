# 协处理插件与低槽扩展的收益比较

> **状态：船长明确不执行120建议，CPU插件保持80；结清**（三号 · verify · 2026-10-08）
> 最新裁定：「CPU插件80→120建议不执行」。以下为历史分析，不再作为待实施方案。
> 2026-10-08合入审计：协处理插件仍80，120建议未实施；扩槽同类型限一件、巨构8%代价和乘法负面已经合入，以下旧重复扩低槽／12%代价读数仅作历史，不能继续据此直接调价或调数值。
> 船长原话：「我发现，如果可以按照重复舰船插件，增加CPU的插件完全不如增加个低槽装势力的CPU」。
> 范围：核对重复插件、扩槽、算力和巨构协处理器的实际代价，给出调整建议；不更改玩家装备、不调其他插件、协处理器或战斗机制。
> 已裁决：CPU插件保持80，120建议不执行；下文原分析仅留历史，不再待裁或实施。

## 已核对现状

- 读取主树最新基线`eb93a525`；verify落后主树3提交，仅只读分析主树，不处理另一批星系与装配改动。此次涉及插件、算力与装配的5份关键数据和核心文件在两树无差异。
- 协处理插件：一插件格增加80 CPU，自身CPU占用0，重复件全额加算。
- 下层舱段插件：一插件格增加1低槽，自身CPU占用0；扩出的低槽可装巨构协处理器，每件增加90 CPU，自身CPU占用0，装备可换装。
- 两种插件的配方、黑匣用量与工时相同。低槽路线额外需要取得一件巨构协处理器；没有该装备时，普通协处理器MK3只给45 CPU，不能视为低槽路线必然更优。
- 巨构协处理器带装填时间增加12%的代价；当前`playerSpec`对多件装填惩罚只取最大值，不累计。该惩罚进入舰炮/导弹/激光装填链，不进入无人机攻击间隔链。
- 未改造舰体已有低槽不被新路线占用：扩槽后协处理器只安装在新增的低槽，故不能把「占用原有低槽」当作补偿代价。

- 结论：CPU插件并非对所有炮舰都被完全替代，但在有巨构协处理器货源的无人机舰或已有装填惩罚配装中，扩低槽路线同时多给CPU和换装空间，CPU插件定位明显偏弱。

## 建议方案

- 协处理插件加成建议80→120 CPU，保持占用0、不递减、允许重复。
- 其他插件、普通及巨构协处理器数值保持不变，低槽扩展规则与装填惩罚不改。
- 定位：协处理插件提供最高的纯算力效率且不需要额外装备；低槽插件提供可更换的装配空间，但转换成CPU时每格仍只有90。
- 建议值下1/3/5件纯CPU插件分别增加120/360/600 CPU；对应低槽路线90/270/450。上述为待确认数值的算术对比，不是实战胜率或平衡已通过的结论。
- 此方案让已有CPU插件受益，不削弱玩家已经不可拆换的低槽插件；不改存档版本，后续若获批应验证装配预算、放飞机群和战斗建档同源，并重跑小船最大重复件的读数。
