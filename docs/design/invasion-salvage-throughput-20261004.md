# 入侵打捞速度对标与有限池收尾

> 状态：已确认，已实现并合入，自测通过，待验收（三号 · verify · 2026-10-04）
> 船长：「如何让入侵残骸打捞和普通星系打捞比较接近，但是又允许捞光？」；确认本会话速度与库存分离方案。

## 已确认方案

- 入侵普通残骸按当地星系基础状态的普通打捞吞吐计量，不用临时星系密度或入侵剩余量加速；保留设备周期、技能及地区出量倍率。
- 同一组池量大则总打捞时间长；每轮实际量受剩余量及货仓空间封顶，扣量等于实际量，最后不足一轮直接拿完，不做渐近减速。
- 普通星系的恢复/保底与密度下降不变；入侵48小时闲置衰减、按族分桶、优先级不变。稀有残骸按件独立捞取，不扣普通池。
- 改判2026-10-02/03「入侵剩余量决定出量倍率」，保留当时的实际扣量与总量约束。依据：已向船长说明冲突后获得「确认」。
- 功能域：采矿与打捞，修改同域core入口与测试；AI通过共用入口继承，不重写AI作业。价格、回收掉落、核心渠道、存档、个人真档及界面不动。

## 落点

- `salvage.ts`：入侵倍率改读当地基础密度，不写入池账；普通取数不变。
- `salvaging.ts`：当地普通型号的平均单份体积，按基线等量组、组内威胁权重计算；入侵型号仅决定来源物品，不再决定速度。
- 整数计量：普通入侵轮先按既有入舱取整规则定量，再扣库存，避免每轮扣小数但入舱丢小数；不足1 m³尾量仍沿用既有至少1件例外（每桶最多不足1件），不改物品整数存储。
- 参照：既有 `autoTargetPickOf`、`wreckPoolOf`、`wreckUnitsOf`、`chargeWeekendWreckByVolume` 与主控/AI设备周期单点。
