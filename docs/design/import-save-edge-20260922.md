# 网页版导入存档"没反应"：取消判定竞态（2026-09-22）

> **状态：进行中**（已落码 · 自测绿 · 待船长验收；归档按 §十五）
>
> **船长原话（照抄）**：「**有玩家用的win10的EDGE 153.0.4234.48，无法导入存档，导入后没反应**」

## 一、根因（可复现的竞态，不是"边缘兼容性玄学"）
`game/storage.ts` 的浏览器版导入 `pickImportSave()` 里，"取消"是**靠 focus 兜底**判的：
对话框关闭、焦点回到页面后**硬等 300ms**，若 `input.files` 仍为空 ⇒ `finish({canceled:true})`。
而 **`finish` 一旦调用就永久锁定**（`done = true`，后续一律早退）。

Win10/Edge 上，系统文件对话框关闭后 **`change` 事件可能晚于 `focus` 几百毫秒**
（文件被杀软/Defender 扫描时尤其明显；存档 200~500 KB 正好落在扫描窗口里）⇒
**玩家明明选了文件，却在 `change` 到达之前被判成"取消"**，真正的 `change` 又被 `done` 挡掉
⇒ 界面表现 = **"导入后没反应"**（与玩家描述逐字吻合）。

## 二、修法
1. **去掉硬 300ms 的一次性判定**，改**轮询宽限 ~2 秒**（7 次 × 300ms）：期间一旦 `input.files` 有内容就
   **交给 change 接手**；整段宽限都没文件才判取消（真取消时最多多等 ~2 秒，无副作用）。
2. **顺带加固**：读取后剥掉 **UTF-8 BOM**（玩家常用 Windows 记事本另存一次，记事本会加 BOM ⇒
   `JSON.parse('\uFEFF{…}')` 直接抛错）。
3. 未动：Electron 那条 `window.whale.pickImportSave()` 桥（玩家走的是浏览器分支）· 10MB 上限 ·
   "导入不自动备份现有档"的旧裁定。

## 三、验证与上限
- `typecheck` 四包 0 错 · `build` ✅；同文件里的**导出**路径与 Electron 桥**没有同类硬超时**（已核对）。
- ⚠ **渲染层没有 DOM 测试夹具**（仓里只有 core 的单测）⇒ 这条竞态**没法写成自动用例**，
