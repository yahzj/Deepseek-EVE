## 二、玩家真正的损失：**没有抢到最后一下**那一档

船长 2026-09-25 定的爆率表（`weekendBlackBoxChanceOf`）：

| 情形 | 爆率 |
| --- | --- |
| 抢到最后一下 ＋ p > 50% | **100%** |
| 抢到最后一下 ＋ p ≤ 50% | 100% → 10% 线性 |
| **没抢到最后一下** | **25% × p** |

该玩家 p = 97.75% ⇒ 爆率 = **24.438%**。**按同一条确定性子流重算，那一掷是 0.015648 < 24.438% ⇒ 本该命中**
（本该拿到 1 个黑匣）。

## 三、真根因：**这一掷根本没有发生**（我们的 bug）

`weekendRollBlackBox` 只在**公开收口** `weekendEvent.weekendTick` 的"章鱼得手"分支里被调用；
而**引擎每拍走的是另一个收口** `weekendTickBoss`（`engine.advanceGame` → `weekendTickBoss`，
2026-09-26「章鱼人冷却 60 秒」那批新加的第 4 参闸就在它里面）。那个分支里**没有掷骰**：

```
if (weekendOctopusTick(state, ev, dt, inBattle)) {
  ev.flagshipDown = 'octopus'
  endWeekendEvent(state, nowWallMs)   // ← 原先这里漏了 weekendRollBlackBox
  return { down: 'octopus' }
}
```

一旦它在这里结束本场，随后公开收口 `weekendTick` 就因"本场已结束"直接返回 ⇒ **那一掷永远不发生**
⇒ `flagshipBlackBox` 缺省 ⇒ 结算补发判据 `ev.flagshipBlackBox === true` 为假 ⇒ **玩家一个黑匣都拿不到**。

**这不是个例**：引擎心跳里"章鱼把血条削空"这一类**全部**走本收口 ⇒ 所有"母舰被章鱼收走"的场次
都丢了这一掷（玩家按规则该得的黑匣被吞）。报障玩家只是其中一例，而且他的那一掷**本该命中**。

### 结论

1. **真档那一场（章鱼收尾 ＋ p=97.75%）在现行代码下已能拿到黑匣**（本种子掷中）——第六节的漏掷修得对。
   玩家若仍报"没有"，先核对他们跑的是不是最新构建（该修正已随 `72755124` 推 main）。
2. **新查出一个可复现的"击杀无黑匣"**（`window` 场景）：**活动窗口到点的那一刻正在进行的旗舰战整场作废**。
   - 复现：把墙钟拨到 `T0+74h−20s` 再开战（与真实"最后十分钟才开打"等价）；战斗照打、母舰血条照掉到 0，
     但结算侧把这一场全丢了。
   - 病根（三处同向）：
     ① `weekendTick` ④ 窗口到点分支**不看是否有旗舰战在打**就 `endWeekendEvent`（`weekendEvent.ts` ~1253）；
     ② `weekendApplyBattleOutcome` 开头一句 `ev.endedAtWallMs !== undefined` ⇒ 直接回落
        `weekendBattleInvolvedOf`，而后者又以"活动已结束"返回 `undefined`（`weekendBattle.ts` 749 / 668）；
     ③ `weekendResolveBattle` 同样以"本场入侵已结束"提前返回（`weekendBattle.ts` 231）。
     ⇒ 伤害台账不记、不判击沉、不掷黑匣、不发残骸、不写日志。
   - **与既有注释口径冲突**：`weekendFlagshipEncounterOf` 的头注写着「判据**不含**"活动是否已结束"：
     入侵结束那一刻若玩家正打得兴起，这一场照常打完」——界面认它，结算侧却把它丢了。
3. **两档"按表不爆"**（机制层，未动）：章鱼收尾 `25% × p`（97.75% 贡献也只有 24.4%）· 抢到最后一下但
   p ≤ 50% 走 10%~100%。玩家报"击沉没黑匣"多半来自这两档的观感，是否改口径等船长定。

### 待裁决（`window` 那一场怎么救）

- **甲**：让结算侧认"结束后仍在打的旗舰战"——`weekendApplyBattleOutcome` / `weekendResolveBattle` 对
  **旗舰这一档**放行（判据复用 `weekendFlagshipEncounterOf`，它本就刻意不看"已结束"），伤害照记、击沉照判、
  掉落照发；贡献奖已结过 ⇒ 不受影响。
- **乙**：`weekendTick` ④ 在"旗舰战进行中"时**推迟结束本场**（等这一场收尾后再结束，最多延后一场战斗的时长
  ≈ 10 分钟），与"章鱼停工 60 秒"同一精神（船长 2026-09-26：「这样玩家就能正常收掉 BOSS」）。
- **丙**：入口防呆——窗口剩余不足一场战斗时长时**拒绝开战**并提示（玩家不再白打，但也没有补打机会）。
- **推荐 乙 ＋ 甲**：乙治"正在打的这一场"（口径最自然：活动结束让位于战斗收尾），甲兜"离线大步长 / 意外
  已结束"的边角（避免再出现"看得见、算不到"）。**均需船长点头再动**（涉及窗口语义与结算口径）。
