# 「第一次」任务奖励前移：采集器 ⇒ 扫描 · 打捞器 ⇒ 挖矿（2026-09-20）

> **状态：进行中**（已实现，闸门全绿，待船长验收）
>
> **船长原话（照抄）**：「**第一次任务中，采集器和打捞器给的任务应该往前调，采集器是扫描星系给，
> 而打捞器应该是挖矿任务给。**」
>
> **本件范围**：13 条「第一次」里**两件工具的奖励归属**（前移），以及随之同步的情报信附件行。
> **不做**：其余奖励条目（2026-09-18 六口袋表原样）· 链（里程碑）奖金 · 老档补发/收回。

## 一、与旧口径的冲突（§5.2 · 船长亲自改判）

| 旧口径 | 出处 | 处置 |
|---|---|---|
| 「第一次采集原矿」⇒ **采集器 MK1** | 2026-09-18 奖励表（`core/firstTasks.ts` 行注 · `docs/review/first-tasks-review-20260917.md` §一/§4.3 表 · 情报信「档案补全 · 采矿与精炼」） | **作废**：采集器 MK1 **前移到「第一次扫描」** |
| 「第一次打捞残骸」⇒ **打捞器 MK1** | 同上 | **作废**：打捞器 MK1 **前移到「第一次采集原矿」**；**打捞那条自此没有实物奖励** |
| 「顺序解锁」只改可见性、不改奖励归属 | 2026-09-20 任务中心批 | 不冲突：本件纯改"哪条发什么"，判定/可见性/链条目一律不动 |

⚠ **老档不追溯**：奖励只在"真正第一次完成"的当下发放（`grantFirstReward`，去重键 = `importantTasks[id].done`）
⇒ 已发出去的照旧、不会收回；**已完成「第一次扫描」但还没做「第一次采集原矿」的档**会在挖矿那条拿到打捞器、
拿不到采集器（市场 31,200 ISK 有售 / `bp-miner-1` 蓝图可造，不构成卡点）。

## 二、改了什么

**内容/数据**

- `packages/core/src/firstTasks.ts`：
  - `first-scan` **新增** `reward: { modules: [{ moduleId: 'mod-miner-1', units: 1 }] }`（采集器 MK1）；
  - `first-mine` 的 reward 由 `mod-miner-1` 改为 **`mod-salvager-1`**（打捞器 MK1）；
  - `first-salvage` **删除** `reward` 行（⇒ 卡片落回「情报信一封」，只发信不发件）；
  - 模块头注的"奖励"一条改写成**现行全表**（13 条的六口袋 ＋ 两条只有信），旧句「本轮只有②填一张蓝图」作废。
- `packages/data/src/firstTaskMessages.ts`：三封情报信的附件行跟着挪——
  「档案补全 · 星图扫描」补上『随信附一台采集器 MK1』·「档案补全 · 采矿与精炼」改成『随信附一台打捞器 MK1』·
  「档案补全 · 残骸打捞」删掉附件行（正文只剩两条情报）。
  ⚠ 13 封情报信**只有中文、没有英文列**（既有缺口，属三号本地化范围，本件不碰）。

**测试与工具**

- `packages/core/tests/first-tasks.test.ts`：新增 2 例——① 奖励归属表（扫描=采集器、挖矿=打捞器、打捞=无）；
  ② 实发验证（扫描首拍发采集器且不双发；挖矿那拍发打捞器、**不再发采集器**）。原先那例"采集器挂在挖矿"已换掉。
- `tools/flow-newgame.ts`：把「奖励：采集器 MK1」断言从 ④ 采矿段**移到 ③ 扫描段**，④ 改成打捞器断言。
- ⚠ **顺带修两处被这条改动带出来的旧断言**（都不是回归，是"奖励日志"进了日志尾部/计数）：
  - `tests/exploration.test.ts` 两条事件池用例原先读"日志最后一条"；「第一次扫描」在新档首拍就会判过（母港本就已点亮）
    而它现在带奖励 ⇒ 奖励行（`core.firstRewards.001`）落在事件行之后。改成读"最后一条 ✦ 事件行"。
  - `tests/simulation.test.ts`「离线事件计数」用例：离线摘要的"事件条数 = 新增日志 − 1"是粗口径 ⇒
    奖励行会被数成 1 条事件。用例先把 13 条「第一次」标记完成、贯穿任务标记已发布，隔离出它真正要钉的
    "无事件时计数为 0 而不是 -1"。
