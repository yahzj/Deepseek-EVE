# 战斗超时判负（2026-09-10 · 状态：**已确认并实现**）

> 船长裁决（原文三连）：「1,重跑P1口径。2不调整。**3,超时直接判负,认定玩家撤退处理。**」
> 追加口径（原文）：「**1.判负。2.停止循环清剿。3.精简说明：战斗超时，舰船被迫撤退正在返航。**」
> 触发来源：2026-09-10 战斗复核发现的附带问题（见 `docs/design/mixed-damage-review-20260910.md` §6）。

---

## 1. 结论（一句话）

**战斗打满 `maxBattleMs`（10 分钟）不再按剩余血量比判胜——旧口径"平局算我方胜"作废；一律判负，
并按"被迫撤退"走既有轻损撤退结算（主控远征），玩家可见只留一句精简说明。**

---

## 2. 旧口径与它的问题

`packages/core/src/combat.ts` 结束判定的超时分支（原 2111-2116）：

```ts
const meRatio = totalHpRatio(b, 'player', me)
let bestFoe = 0
for (const f of foes) bestFoe = Math.max(bestFoe, totalHpRatio(b, f.tag, f))
b.ended = meRatio >= bestFoe ? 'me' : 'foe'   // ← 平局（双方都满血）也算我方胜
```

`expedition.ts:430 / 467` 里 `won = battle.ended === 'me'` → **判胜即发全额奖金 + 声望 + 战利品**。

**实测证据**（`npm run battle:calibrate`，2026-09-10 实机矩阵）：「无技能 · 鲣鱼+导弹MK3」一行在
威胁 **52 / 58 / 66 / 80 / 88 / 88 / 96 七格全部是 `100/600s/100%`** —— 打满 10 分钟、我方满血、
**并未击杀敌人**，却记为 100% 胜率并照发赏金。该行装配合法（鲣鱼级 `sh-falconet` CPU 110，
巡航导弹架 MK3 `mod-missile-3` 占 52；导弹射程 14.88 km > 上述各档敌军 2.6~7.7 km）。

⇒ 结果：**一架无技能护卫舰可以零风险"白刷"高威胁悬赏**（每场 10 分钟，无伤、无消耗、全额赏金）。

## 3. 新口径

### 3.1 判定（`combat.ts`）

打满上限即：

```ts
b.ended = 'foe'          // 判负
b.autoEscaped = true     // 交给结算侧走轻损撤退路径（复用 2026-09-08 既有通道，零新机制）
b.escapeReason = 'timeout'
```

- `totalHpRatio` 随之成为死代码，已删除；
- `balance.ts` 的 `maxBattleMs` 注释同步改为"打满即判负，结算按被迫撤退处理"（**数值未动，仍是 10 分钟**）。

### 3.2 结算（按"撤退"处理）

主控远征的两条自动撤离来源（结构损失过半 / 战斗超时）共用 `settleBattleRetreat`，
只按 `battle.escapeReason` 区分文案与来源：

| 项 | 超时撤退的处置（与既有撤退一字不差） |
|---|---|
| 耐久 | 失利扣损骰 ×0.5（约 **7.5%~15%**），下限 **5%** 保护——**绝不弃船** |
| 维修费 | 期望奖励 × `defeatCostRatio`(0.5) × 0.5 = **期望奖励的 25%** |
| 承伤持久化 | 本场已损装甲/结构照常写回 |
| 弹药/修理件 | 剩余照常退回仓库；无人机战损照扣（永久损失制） |
| 循环清剿 | **停止**（船长裁决第 2 条） |
| 返航 | `returnReason = 'retreat'`，转返航、**可召回**；窝点档位与派系活跃标记作废 |

### 3.3 玩家可见文案（船长裁决第 3 条：精简）

战斗日志（warn）：

```
⏱ 战斗超时（<目标名>）：舰船被迫撤退，正在返航——耐久 -X%，维修花去 Y ISK。
```

- 与船长给的样板「战斗超时，舰船被迫撤退正在返航」同形，**只是把损失数值按同级相似项补回**
  （另两条撤退日志——手动撤退/自动撤退——都带「耐久 -X%，维修费 Y」；不写会让超时成为唯一
  静默扣费的场景）。**若船长要求彻底去掉数值，删这一句尾即可，一行改动。**
- 循环清剿停止时才追加一句：`重复清剿已停止（战斗超时）——当前 装甲 X% / 结构 Y%。`
- 全套文案无开发/验收话语（符合约定第十三章）。

## 4. 三条边界裁决（船长已定）

| 场域 | 处置 | 说明 |
|---|---|---|
| **主控远征** | 判负 + **轻损撤退** | 撤退是主控既有机制，直接复用 |
| **低安遭遇战** | **判负**（走既有失利路径：耐久损失 + 可能被掠货） | 船长裁决第 1 条：遭遇战没有"撤退"概念，不为它新造轻损特例 |
| **AI 副船远征** | **判负**（走既有失利惩罚） | 同上（AI 无撤退指令） |

## 6. 回归

`packages/core/tests/retreat.test.ts` 新增一例（**不依赖击杀取样运气**：把双方血量都拉到 1e9，
必然走到超时判定）：

- `ended === 'foe'`（旧口径下此处为我方满血/敌未死 → 会判胜）；
- `escapeReason === 'timeout'`；
- **钱包不增反减**（判负 = 拿不到赏金，反被扣维修费）；
- 日志含「战斗超时」「舰船被迫撤退，正在返航」「重复清剿已停止（战斗超时）」；
- 耐久轻损且 ≥5%（绝不弃船）、船还在。

## 7. 预期的连锁影响（都是"变诚实"）

1. **胜率预估**（`winEstimate.ts`）与卡片展示的胜率：靠"拖到上限"骗胜的装配（风筝流/导弹流）
   预估会**下调甚至归零**——这是目的，但玩家可见的胜率数字会有一批变化，需在公告/手册口径上留意。
2. **校准矩阵**（`npm run battle:calibrate`）：所有 `600s` 格从"胜"变"败"，P1 复调轮口径随之重跑
   （见 `docs/design/power-ladder-rework.md` §五·2026-09-10 复跑）。
3. **循环清剿**：磨不死的目标不会再被无限重试（每场 10 分钟后停环），玩家需换装配/换目标。

---

## 8. 边界与未做

- **未动任何平衡数值**（船长裁决第 2 条）：副系份额维持常驻 8:2 / 窝点 6:4，敌血/敌伤一律未调；
- `maxBattleMs` 仍为 10 分钟（未缩短/延长）；
- 多波次战斗（`waves`）在超时点同样整场判负（不按波次分段判）；
- 窝点真实战斗的超时表现未单独实测（与常驻走同一判定路径）。
