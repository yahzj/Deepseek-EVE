# 工作文档 · 玩家存档「补偿性开启铁人模式」（2026-09-24 · 三号）

> **船长原话（照抄）**：「**这个存档是玩家误操作的，因为之前没提示，所以作为补偿给其开铁人模式**」

## 一、为什么这不是"玩家自助"，而是 GM 补偿

游戏里那条路**按设计走不通**：

- 存档页确实有「**旧档一次性转换**」入口（`SaveManager.tsx` 的 `handleIronman`），但它在 `im.modeChosen` 为真时**直接 return**（"模式选择机会已用完 ⇒ 没有入口"）；
- 更要紧的是这个档**已经关了铁人**：`ironman.closedWallMs` 已写 ⇒ core `enterIronman()`（唯一入口）**第一行就 `return false`**——那是船长 2026-09-23 定的**单向门**：「玩家**只能关闭**铁人模式，**无法再次打开**」。

⇒ 玩家遇到的正是那道没有提示的关闭动作（**船长认定为误操作**）⇒ 走**船长明令的越权补偿**：只改这份档的数据，
**代码一个字不动**（单向门照旧对所有人有效）。

## 二、改了什么（只动一个字段块）

| | 改写前 | 改写后 |
| --- | --- | --- |
| `state.ironman` | `{"on":false,"seq":487,"sinceWallMs":1790243692997,"closedWallMs":1790244430447}` | `{"on":true,"seq":487,"sinceWallMs":1790243692997}` |

- **`on: true`** ⇒ 铁人福利重新生效、代次恢复随落盘 +1；
- **删 `closedWallMs`** ⇒ 这是唯一必需的数据改动（留着它入模入口永远返回 false）；
- **保留 `seq: 487`** ⇒ 现值既是我方装载闸门的基准，又与**存档外账本**（`ironman-ledger.json` 的 `seq: 487`）同高
  ⇒ 补偿后**导入/导出自己这份档不会被自家闸门拦**；若把它写小，反而会把自己关在门外；
- **保留 `sinceWallMs`** ⇒ 那是"哪一刻入的铁人"，补偿不改写历史。
- **账本不动**（`{seq:487, updatedAtWallMs:1790241530586, rescues:0}`）；主进程只在存档代次**高于**账本时才抬账本，现两者同高 ⇒ 下次落盘也不会跳。

## 三、工具与安全纪律

新增 `tools/save-enable-ironman.ts`（**刻意不挂 npm script**，与 `save-grant-ships.ts` 同款：会写真档、只在船长下令时手工敲）：

1. **先关游戏**（游戏在跑时它下一次自动保存会把本次改写整个盖掉）——本次执行前实测：存档 86 秒未变、无游戏进程；
2. **双备份**：`%APPDATA%\whale-idle\save-20260924-220327.json` ＋ `%TEMP%\whale-ironman-backup-20260924-220327.json`；
3. **外科式改写**：不做 `JSON.parse → 整体重写`，而是**只替换 `"ironman":{…}` 这一段文本**，其余字节原样透传；
4. **自检三条**：改写后仍可解析 · 语义只差这一个字段块（**键序无关的深比较**）· 除该块外**逐字符相同**（不过即中止、不写盘）。

**先在副本上试跑**（`%TEMP%\ironman-dryrun\`）确认通过，才对真档执行。
