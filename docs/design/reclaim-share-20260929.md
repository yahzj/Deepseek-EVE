# 夺回奖按投入比例结算（2026-09-29）

- **状态**：进行中（船长已裁决口径；实现与四闸门跑完后转"已完成"，归档时并入 `docs/design/weekend-invasion.md` ＋ `docs/roadmap.md` 后删除本文）
- **船长原话（照抄）**：
  - 报障：「**出现新问题，玩家在入侵中完全0贡献，但是却有每个星系240残骸+200万**」
  - 口径裁决（本次三问三答）：**「乙：按投入比例缩水」** ＋ **「全清 500 万 = 甲案：乘玩家总投入 ÷ 占领区数（平均参与度）」** ＋ **「残骸按"件"四舍五入」**
- **范围**：只改**夺回奖**（每处 稀有残骸 ×8 件 = 240 m³ ＋ 2,000,000 ISK；全清追加 5,000,000 ISK）。
- **不做（本批一律不动）**：进度收入的单价与口径（每 1% 20 万 · 只结玩家投入）· 贡献四档奖 · 协会声望 · 旗舰黑匣与旗舰掉落 · 占领/夺回的**读数**（进度条、星图标记、"已夺回 N/M"照旧，夺回仍是事实，只是**给多少**变了）· 存档结构。

## 一、根因（报障复现）

**夺回奖整条判据里没有"玩家是否参与"这一项**，而"夺回"是按**进度条**判的：

| 环节 | 事实 | 出处 |
|---|---|---|
| 外围进度 | `NPC 铺底(t/48h) ＋ 玩家投入`，封顶 1 | `packages/core/src/weekendEvent.ts:876` |
| 核心进度 | 外围清完后 `(t−48h)/24h ＋ 玩家投入` | `packages/core/src/weekendEvent.ts:901-903` |
| 夺回判据 | 进度 ≥ 1（T0+48h / T0+72h 后**时间自己就推满**） | 同上 |
| 夺回奖记账 | 唯一判据 = 「已夺回 ∧ 不在 `reclaimPaid`」⇒ **记全额** | `packages/core/src/weekendBattle.ts:466-482` |

⇒ **一次都不打的玩家**在活动结束时也拿满：每处 240 m³ ＋ 200 万，全清再 500 万。
2026-09-27 那批修的是**漏发**（判据从"这一场战斗有没有夺回"改成"已夺回 ∧ 未记账"），修的时候没同时补参与门槛。

**铁证（探针实测，跑完即删）**：4 处占领区 · T0 = 现在 −80h · `contributed = {}`
- 进度读数 `1.000 / 1.000 / 1.000 / 1.000`（全是铺底铺的）
- 结算返回 `{share: 0, tier: 'none', isk: 13,000,000, wreck: 960}`
- 钱包 10,000 → 13,010,000；仓库 `wreck-rare-h-hi: 960`
- 对照：同一批的**贡献四档奖**（`tier: 'none'`）与**进度收入**（`progressIsk: 0`）本来就有 0 贡献保护。

## 二、新口径（船长 2026-09-29 裁决）

| 项 | 口径 |
|---|---|
| 单处夺回奖 | `全额 × 玩家在该处的投入比例`，比例 = `contributed[星系]`（0~1；NPC 铺底不算） |
| 全清追加 | `5,000,000 × (玩家总投入 ÷ 占领区数)`（平均参与度，封顶 1） |
| 取整 | ISK 四舍五入到 1 元；残骸**按"件"四舍五入**（1 件 = 30 m³ ⇒ 记的是 30 的整数倍） |
| 0 贡献 | 两笔都记 0（挂机彻底不产生收入） |
| 记账时机 | **结算那一拍**按**最终**投入比例算一次（`weekendSettleAndGrant` 的早退之前）⇒ 与"进度收入"同源同拍 |

**为什么把记账时机挪到结算拍**（实现取舍，写给后人）：若在"夺回那一刻"按当时比例记账，同一处**先被 NPC 铺满、玩家事后才去清缴**的情形会记成 0（而玩家确实出了力），且结果取决于"他当时恰好在别处打没打过一场"——同一行为算出不同奖励。改成结算拍后：与 `contributed` 台账（随档）同源、结果与出手顺序无关、与进度收入同一把尺，且战斗那一拍不再需要发金额。

**代价（已知取舍）**：夺回那两条日志（`core.weekend.001/002`）原先报具体金额，现在金额要到结算才知道 ⇒ 两条文案改为只写规格（「按玩家在该星系的投入比例结算，活动结束时统一发放」），并去掉 `p2/p3` 两个参数。玩家实际拿到多少，仍在**结算面板/结算通讯**里逐处列明（它们读的是实发台账）。
