## 二、改造形状（照本仓既有先例，不发明新机制）

`CommandResult` 的甲案先例（`packages/core/src/engine.ts:63` 注释）：**`error` 中文原串永远照写**（工具/老路径/回落用），
**另加** `errorId` ＋ `errorParams` 供界面按语言渲染；**保持 `string` 类型不变**（联合类型会外溢到全部读取点）。

本批同法：把那几个**返回 `string | null`** 的闸门函数改成返回**结构化拒因**（`{ error, errorId, errorParams? }`），
界面侧统一走 `cmdText(r)`（渲染层已有：`i18n/locale.tsx`，有 id 按语言取、没 id 回落中文原串）。
调用点**判空照旧**（`blocked !== null` 不受影响），只有 3 处**渲染处**改成 `cmdText(...)`。

## 三、待裁决点

1. 乙/丙 要不要在本批一起做（我的建议：**乙一起做**，丙的结算文本次批）。

   防两处文案漂移；代价 = 多一个 core 文件与一次 import 调整（不引入循环依赖，因为是纯数据）。
