## 一、真因（一行定死）

`packages/core/src/salvage.ts` 的 `asFoeFamily` 用**手写区间**收窄：

```ts
return v !== undefined && /^[A-H]$/.test(v) ? (v as FoeFamily) : undefined
```

而族码联合是 **`FoeFamily = 'A' | … | 'H' | 'R'`**（`packages/core/src/types.ts:2152`）——
**R 族（光环科技）落在区间外** ⇒

1. **注入时记不上族**：`injectWeekendWreck(…, asFoeFamily(card.foeFamily) ?? …)` 传进去的是 `undefined`；
2. **判据时读不出族**：连记录里明写的 `'R'` 也被丢。

于是「残骸场比占领活得久」这条**第二路**（靠族认卡）对 R 族整条失效：

- **活动进行中** ⇒ 第一路（星系仍在被占名单 ⇒ 占领供卡）替它供卡 ⇒ **还捞得到**；
- **打完旗舰结束入侵 / 夺回之后** ⇒ 只剩第二路 ⇒ **捞不到**：逐格捞上来的全是该星系自己的普通残骸，
  **入侵池一点不减**。

## 二、探针读数（真函数 · 修复前后对照）

```
⓪ asFoeFamily('R')：修复前 undefined（← 真因） · 修复后 'R'
① 活动进行中、星系在被占名单：修复前就捞得到（第一路供卡）：wreck-r-inv×176 · 池 272 → 95.7
② 收场之后（只剩第二路）：
   修复前：捞上 wreck-a-hi×27 ×4 格 · **入侵池 272.0 m³ 四格纹丝不动**  ← 玩家看到的就是这个
   修复后：捞上 wreck-r-inv×176 · 池 272 → 95.7 → 0（正常出量）
```

## 三、改法与验证

- **改**（`packages/core/src/salvage.ts`）：新增**唯一登记表** `FOE_FAMILY_CODES`（`A…H` ＋ **R**，
  与联合逐字一致），`asFoeFamily` 改为查表 ⇒ 不再有"手写区间漏一族"这种事；头注照抄船长原话与读数。
- **用例**（`tests/wreck-pool-stale-field-20260926.test.ts` 增 2 条）：
  ① **数据驱动契约**：卡面上出现过的**每一个**族码都必须能被 `asFoeFamily` 接受（读数：
  `A/B/C/D/E/G/H/R` 全部通过；将来加新族时这条先红）＋ `R` 必在登记表内、小写与表外码照旧不接受；
  ② **报障回归**：R 族注入记上族 ⇒ **收场之后**照样捞出 `wreck-r-inv`。
- **验证**：该文件 7 条全绿；全量 core 套件与其余闸门读数见汇报。
