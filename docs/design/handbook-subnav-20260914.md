# 手册「玩法速览 / 航行须知」子页面导航 + 正文拆段

> 状态：**已确认（船长 2026-09-14；四问四答全取推荐项）** · 经办：一号（主树 `main`）
> 落点：`apps/desktop/src/renderer/src/panels/Handbook.tsx` ＋ `styles.css`（纯渲染层，**零存档影响**）

## 一、船长原话（照抄，不改写）

> 「**手册的玩法速览和航行须知，做一个子页面导航栏来给里面的解释分页。且相关内容不要只用一个段落。
> 这样会形成一大段话文字挤成一团。**」

四问四答（**全取甲 = 推荐项**）：

| 问 | 答 |
|---|---|
| 子页面粒度 | **按词条分页**（玩法速览 19 页 / 航行须知 24 页；组名在子栏里作分组小标题） |
| 子导航形态 | **左栏第二列**（章节 ｜ 子页 ｜ 内容 三栏，复刻既有 `.app-hand-nav` 观感） |
| 正文改写幅度 | **拆分 ＋ 每段一行短小标题**（字数基本不变） |
| 搜索口径 | **仍搜整章（跨子页）**：子栏显示命中段数、未命中置灰 |

## 二、改前现状（为什么要改）

- **玩法速览**：6 组 19 条 ＋ 小贴士 3 条；**航行须知**：5 节 24 条。
- 每条都是「一张卡 + **一整段** 100~400 字」（如「装配」单段 500+ 字）：整章 = 一片文字墙，
  组与组之间只隔 16px，扫读困难（`renderSects` 直接 `{v}` 渲染成单段）。

## 三、落码

### 3.1 数据结构（`Handbook.tsx`）

```ts
interface HandEntry { title: string; paras: Array<[string, string]> }  // [段首小标题, 正文]
interface HandGroup { title: string; entries: HandEntry[] }
function handEntryHits(e: HandEntry, q: string): number   // 命中段数（0 = 未命中）
```
`GUIDE_GROUPS` / `RULE_SECTS` 由 `rows: Array<[string, string]>` 改为 `entries: HandEntry[]`；
`GUIDE_NOTES`（小贴士）保持字符串数组，单独占一个子页（key = `__tips`）。

### 3.2 交互

- 新状态 `pageKey`（当前子页 = 词条标题；空串 = 默认第一条）。**切章清空**（与关键词/筛选同一处重置）。
- 页面推导（无副作用、搜索即跳页）：
  `flat → matched（按关键词过滤） → cur = 玩家点的那条，若被滤掉则落到第一条命中的`。
- 子栏（`.app-hand-subnav`）：组名作分组小标题 + 每个词条一个按钮；`is-active` = 当前页、
  `is-dim` = 关键词下未命中（仍可点）；搜索时右侧显示命中段数；底部「小贴士」单条（`.app-hand-subsolo`）。
- 正文（`renderPage()`）：`.app-hand-card` 内按 `paras` 逐段渲染 `.app-hand-para`
  （`.app-hand-para-head` 小标题 + `.app-hand-card-body` 正文）；小标题为空串 ⇒ 该段作引导句不加标题。
- **页底翻页（船长当日追加：「加『上一条 / 下一条』」）**：按当前章的**阅读顺序**连续走、**跨组不打断**；
  搜索时只在**命中项**之间走（与"搜索即跳页"同一套口径）；「小贴士」排在「玩法速览」最后一条之后；
  到头的一侧留空位（`.app-hand-pager` 两端对齐 ⇒ 按钮位置不抖）。

### 3.3 样式（`styles.css`）

全部**复刻既有家族**（§六：新增内容先照同级相似项）：子栏/子项 = `.app-hand-nav` / `.app-hand-navitem`
那套（168px、`gap 2px`、`is-active` 同配方）；`.app-hand-para-head` = 11.5px/600/*#9fd8ff*（与
`.app-comms-head-from` 同色系）；≤1180px 断点把子栏收窄到 140px（与手册既有断点同阈值）。
