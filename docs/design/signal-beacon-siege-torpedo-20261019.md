# 信标围剿核查与鱼雷舰加成调整

> **状态：实现完成，待专项验收**（三号 · verify · 2026-10-19）
> 船长原话：「信号空间内，7层以上的围剿，玩家反应BUG，消灭信标上的围剿敌人后，无法触发信标，而且敌人会重复刷在围剿已经被消灭的格子上。鱼雷舰进行改动，将火力加成降低至25%，多余的转移到爆炸伤害加成上」。
> 范围/不做：信号空间信标/围剿、鱼雷舰加成及必要回归；不改未来虫洞、不碰个人档、不自行合入或推送。
> 待裁决点：无，按船长确认方案实施。

## 核查入口

- 信标到达效果：`wormholeGridTravel`；围剿胜利：`wormholeBattle`；候选格：`spawnTargetsOf`。
- 旧设计`wh-spawn-layer7-20260923.md`及源码`wormholeGrid.ts`曾允许已清敌人格重占，`wh-spawn.test.ts`对应断言已按本批新确认规则追平；历史公告不改。
- 原有两个隐秘调查未跟踪文件不属本批。

## 鱼雷舰现值与已实施值

| 舰船 | id | 通用火力 | 爆炸伤害 |
|---|---|---|---|
| 构件鱼雷舰 | sh-wh-e-frigate | 35%→25% | 20%→30% |

## 合成复现结果

命令：`npm run test -w @whale/core -- --run signal-beacon-siege-20261019 --reporter=verbose`。首轮三项中信标7/8层两项红、现行重刷一项绿，修复后3项全绿。

- 到达被覆盖信标→正式开围剿战→夹具指定敌全灭→正式慢镜/战果收口：`foe.cleared=true`、`activated=[]`、`exitKnown=false`。原地调用`wormholeActivateAt`拒绝「这里什么都没有：没有可执行的作业」，保存重载仍未标出入口。
- 根因：`wormholeGridTravel`在覆盖期间有意不触发信标；围剿胜利只解除覆盖，没有补原地点的到达效果；`wormholeGridActivate`又无条件拒绝非入口信标。必须离开后重入才有机会触发，同时离开耗回合可能又刷回本格。
- 两格合成盘面只有已清围剿格和出口格，修复前`spawnTargetsOf`仍选中前者，下一回合刷新1个并立即袭击；修复后候选为空，不再重刷。

## 已实施修复方案

1. 信号空间围剿胜利后，若原格为未读信标，自动执行原有信标效果，不再额外消耗回合。首个标入口，后续揭示最近未揭示谜质并驱散其星云；每格只触发一次，复用同一实现。
2. 已有在途档若当前站在已清围剿覆盖、未读的信标上，也补触发；不重置已读信标、不补发物品，不触及被误写过完成标记且无法确认历史效果的旧格。
3. 仅信号空间本层`foe.cleared=true`的格子不再进入围剿候选，保留该既有随档标记；不把原地点`activated`冒充围剿清除标记。其他格、同屏50%上限、每耗1回合尝试刷新、战果与强度不变，候选耗尽就不刷。
4. 该规则替代旧「已清围剿格可重占」，不扩大为所有访问过/已完成原地点免刷，未来虫洞巡逻规则不变。界面参数读取现有字段，中英显示随参数同步，历史公告不回改。
5. 鱼雷舰按表中10%/20%加成差值转移，保留现有乘法合成，不另做保伤害补偿。批准后做信标首/后续、旧在途恢复、重载幂等、不重刷、候选耗尽、原矿/残骸回归及双舰各伤害类型专项。
