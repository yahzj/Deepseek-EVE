### 6.2 第三次报障：「仓库内图标模式依旧是空的，且图标模式无法使用道具」（同日 · 根因已修）

> **船长原话（照抄）**：「**检查了，手册内有了，但是仓库内图标模式依旧是空的，且图标模式无法使用道具（没有按钮）**」

**① 「空的」不是"图标不对"，是"根本没画出来"——色板漏定义了一个 tone 变量。**
逐格读计算样式抓到：`stroke: none`（不是颜色错，是描边整条没了）。根因链：

- `ui/tones.ts`：`consumable: toneVar('consumable')` ⇒ 生成 `rgb(var(--wui-tone-consumable))`；
- `packages/ui/src/index.css`：**从来只定义到 `--wui-tone-luxury`，没有 `--wui-tone-consumable`**
  （2026-09-29 加道具档时色板那边漏了一步）；
- 于是 `rgb(var(--…未定义…))` 是**非法颜色** ⇒ 整条 `stroke` 声明被丢 ⇒ SVG 描边回到初始值 `none`
  ⇒ **图标隐形**（同一个坑 2026-09-22 踩过一次，当时是少了 `rgb()` 包裹）。

三处落地：
1. **补 token**：`index.css` 的 **7 个 tone 块**逐个加 `--wui-tone-consumable`（取同块 `--wui-tone-ore`
   的薄荷值；逐主题对比度由既有闸门盯）；
2. **加兜底**：`toneVar()` 改成 `rgb(var(--wui-tone-X, 143 163 184))` —— 以后任何一条 tone 忘了登记，
   最坏只是**变灰**，不会再隐形；
3. **补护栏（真正的防线）**：`tools/ui-token-check.ts` 新增「**拼接名专项**」——原先它遇到
   `var(--wui-tone-${kind})` 这类拼接名会**主动跳过**，`toneVar('…')` 的字面量调用因此**从没被核过**；
   现在逐个对色板核（键数 143 · tone 块 7 个）。这条闸门挂在 `npm run ui:theme-check` 里。

**② 「图标模式无法使用道具」**：图标模式点格子开的是 `ItemActionModal` 详情卡，卡上原先只有
「装到船上 / 卖出 / 去市场」⇒ 两件道具没有使用入口。已在详情卡按**同一套 id 常量判据**补上「使用」
（与列表行同款），并把卡片那张 40px 大图标也改成 `itemGlyphName`。

**运行时复核**（同一探针，读数）：
- 三个格子的 `--tone` 从**空**变为 `rgb(94 230 200)`、`stroke` 从 **`none`** 变为 `rgb(94, 230, 200)`、
  尺寸 30×30 ✓（图标真的画出来了）；
- 详情卡文本变为「…**使用** 装到船上 市价卖出 ↖ 查看市场订单」✓（图标模式下有使用入口）；
- 三件的路径数据仍各不相同（燃料罐身／桅杆信号弧／双箭头）✓。
