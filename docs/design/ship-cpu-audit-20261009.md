# 全船CPU预算检查

> **状态：四舰CPU已调整并完成自测，待验收**（一号 · main · 2026-10-09）
> 船长原话：「巢群重型突击舰数值不合理，发现CPU过低，检查下是否其他船也有这个问题」
> 范围/不做：舰船装配域；检查46艘船后只提高已确认的四艘基础CPU，其他42艘及全部其他属性/装备数值/存档/公告/英文不动，不推送。沿用当前静态JSON和CPU预算/装配校验，不另造计算接口，不跨业务域。
> 待裁决点：无；船长追加「其他没问题，只提高这四艘舰船CPU」，确认前轮候选360/350/240/260。

## 检查口径

- 以`buildSimContext()`当前目录、`cpuBudgetOf`、`fittedCpuUsed`、`droneCpuUsed`为准；不读玩家档或船长真档。
- 武装/装甲船按档位使用MK1/MK2/MK3主武器，高槽可全部装炮；中槽至多推进/盾抗/索敌三件，低槽至多甲量/甲抗两件。无人机作战舰另用导控/近防配装，不强迫所有高槽装主炮。
- 辅助件分别检查MK2经济配装及同档配装；不要求每个槽位全部塞最贵装备、不把机舱体积当作必须满载的战斗预算。
- 工业船与货舰独立检查生产/物流装备，不与战斗船混比。
- 基础CPU与工程Lv5的预算并列；所有读数无协处理器/CPU插件，扩容只作有代价的补救，不假装免费基础预算。
- 同档、同角色比较只做线索，不单独判错。

## 历史依据

`docs/design/wormhole-exclusive-20260913.md`末轮槽位裁定记载：巢群重突4/3/5、CPU280保持；陵寝4/4/4、CPU300回滚保留。不能将历史审查表中240/260或旧船名视为当前真值。现行数值需按当前装备占用重新复核。

## 结果

正式工具`npx tsx tools/ship-cpu-audit.ts`（可加`--json`）读取当前46艘定义，2种配装×2技能档，共184次真实`fitModule`/`adjustDroneLoad`校验，算账与装配允许/拒绝全部一致。不是界面CPU漏算或工程技能失效；主炮MK1/2/3分别占10/28/52，工程技能Lv5预算为基础×1.25取整，装载无人机与模块共用预算。
