# 矿带排序口径重定：行情产值最高（状态：进行中 · 2026-09-30 船长令）

> **船长原话（照抄）**：「**矿带开采的排序，原矿价值最高的排序已经落后。**」
>
> **本轮范围**：`verify` 工作树（三号）。仅动矿带开采页的排序口径与它的选项文案。
> **不做**：卡面读数（2026-09-23 口径）不动 · AI 收入统计整族的口径不动（见"待裁决点"已决）。

## 1. 查实（为什么"落后"）

- 这一档排序的算式原本在**渲染层**：`pages/MapPage.tsx` 的排序一处、矿带卡片一处，
  口径 = **每小时产出 × 物品基准价 `baseSellPriceIsk`**（2026-09-09 二号实现，
  `docs/design/departure-sort-20260909.md` §2 原话："与矿带卡内效率行同口径"）。
- 而**卡面口径 2026-09-23 已由船长改掉**：卡面不再出现「≈N ISK/h」，改列
  「物资 ×N/h（仓库 M · **行情** P）」（唯一实现 `ui/yieldView.tsx` 的 `marketPriceOf`：
  价史右端点 → 挂单价兜底）⇒ 那条"同口径"的前提失效，**排序与卡面数字对不上**。

产量 3,910/h）。根因：基准价是**档位化的**（7/15/32/68/144/145），行情价是**活的**（同一批矿 11 → 533）。

## 2. 船长裁定（2026-09-30 · 集中提问后一次选定）

1. **口径** = **每小时产出 × 当前行情价**（无行情退回基准价）；
2. **选项文案** 改「**行情产值最高**」（原「原矿价值最高」）；
3. **AI 副船回港「收入估算」日志 ＋「AI 累计收入」统计**（`core/ai.ts:766`，同样用基准价）
   **本轮不动，只登记待办**——理由（已呈船长）：AI 收入统计整族（制造/工业/组装）都走
   `marketBasePrice` 基准价，只改采矿一处会让同一本统计出现两把尺，应整族一起定口径、单独立项。

## 3. 实现（改动清单）

- `packages/core/src/mining.ts`：新增 **`BeltYieldRow` / `beltYieldRows()` / `beltValuePerHour()`** ——
  每小时产出的**唯一实现**（复合带按权重分摊，权重池非法回落主产物）；产值 = `Σ(逐项 × priceOf)`，
  `priceOf` **由调用方交入**（行情口径仍只有渲染层 `marketPriceOf` 一份），取不到行情退基准价。
  搬进 core 的理由与组装机排序（`sortManuRows`，2026-09-14）同款：**渲染层没有测试运行器**，
  口径漂移只表现为"看着乱"、不报错——本次报障正是这一类。
- `packages/core/src/index.ts`：导出上述三个符号。
- `apps/desktop/src/renderer/src/pages/MapPage.tsx`：排序行改调 `beltValuePerHour(…, marketPriceOf)`；
  矿带卡片的逐项产出改调 `beltYieldRows`（**去重**：这段算式原先在页内写了两遍）；注释按新口径重写。
- `packages/data/src/l10n/table.ts`：`ui.MapPage.010` 值改「行情产值最高 / Highest market value」
  （id 不变、不复用新 id）。
- `packages/core/tests/belt-sort-value-20260930.test.ts`：5 例锁口径
  （单产物带与 `getMiningParams` 同源 · 复合带权重分摊且各行相加 = 总产出 · 产值 = Σ(×价) 且无参数为 null ·
  缺行情退基准价 · **船长报障症状锁**：基准价口径极光云场在前、行情价口径蓝霜冰环在前）。
- `docs/single-source.md` ＋ `tools/arch-guard.ts`：把这条单点**两处一起登记**（F3 核对）。
