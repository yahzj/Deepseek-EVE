> 范围：信号空间/虫洞自动准备门禁、五类准备阵容、旗舰旧阵容兼容、存档清洗及回归；不改主控忙时不能随队的规则，不停主控工作，不自动出发/换船，不改补给模板、价格或战斗数值，不读写个人真档。

## 已确认规则

- 未选主控的自动队伍只检查实际参与船与AI核心；主控卡片仍显示交接拒因，但假设加入主控的试算不能挡住整队。
- 真选主控时保持原忙态与接任规则，成功交接仍需确认；不停止主控采矿/打捞/运输等工作。
- 五类分别随角色存档记忆：信号空间手动/自动、虫洞手动/自动、入侵旗舰。记录实例uid及顺序，上限沿用4艘。
- 修改选择即记忆，关闭、重开、重启/读档保留；明确空阵容保持空，不自动补位。已不在舰队的实例过滤，暂忙者仍保持选中，由当前准入判断拒因。
- 从未记忆才用原默认；旗舰兼容`weekendPrepSquad`，新虫洞已有通道草稿只作首次兼容来源，不覆盖新的分类记忆或补给请求。
- 使用可选字段，无存档版本升级；清洗保留有意义的空数组，坏值不生成假空阵容，读写调用共用一个core单点。
- 新版自动整备的预览只隔离与队伍/补给无关的主控作业变化，所选舰、库存、技能与通道的真实变化继续使预览失效。
- 船长批准：虫洞→入侵旗舰准备/存档清洗。按完整方案及「确认修复」实施，参照旧旗舰阵容记忆、现有整备模板与自动主控交接口；不扩改活动门禁系统。

- 使用`react`与`vitest`，共享选择hook、core读写清洗单点，按五类与新旧准备入口做真实组件回归。

## 实施与影响面

- 根因：信号空间与虫洞准备页把「假设主控加入」的交接拒因直接用于整队门禁。现仅在主控实际选中时使用该拒因，副船队仍按真实核心余量和船只可派性校验。
- 新版自动整备的预览指纹不再包含无关主控作业的进度，实际所选舰、主控身份、库存、技能和通道变化继续使旧预览失效。自动出发仍重验资格，不借手动入口停止主控工作。
- `preparationSquads.ts`负责五类清洗、恢复和记忆；`state.ts`、`save.ts`成对接入可选随档字段；`index.ts`导出，`engine.ts`提供页面读写入口。
- `usePreparationSquad.ts`共用选择生命周期；`SignalSpace.tsx`、`Wormhole.tsx`、`WeekendFlagshipPrep.tsx`覆盖五类准备。普通重绘不写盘，切换分类或加载角色重新恢复，旧组件选择不会写进另一分类或角色。
- `weekendLaunch.ts`保留旧旗舰阵容来源，新分类记忆优先；新版虫洞的旧手动通道草稿仅作无记忆时的默认来源，自动准备不覆盖手动草稿。补给草稿和模板不改。
- 已选的忙舰可以移出队伍，不能重新加入；记忆只保存实例与顺序，不保存装配、不换船、不自动出发。新增专项测试和正式原生回归工具，单点已登记。
- 功能域以虫洞/信号空间准备为主，按船长「确认修复」批准跨入侵旗舰准备与存档清洗。参照旧旗舰阵容记忆、现有整备草稿和自动主控交接，不扩改活动门禁。
- 范围工具报告虫洞、活动入侵、存档3域；新共享文件与信号空间部分文件尚未归类，如实保留提示，本批不修改域表。
