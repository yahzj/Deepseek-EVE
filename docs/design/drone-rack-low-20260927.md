# 无人机扩舱件改归低槽 ＋ 掠袭机库 40 ＋ 两艘势力无人机调槽（2026-09-27）

**状态：已实现待船长验收**

**船长原话照抄**：

- 「将扩大无人机舱的装备从高槽移动到低槽，掠袭机库的无人机舱扩展提高到 40。」
- 「反而2艘势力的无人机，需要将一个中槽移动到低槽。」
- 三处确认：「1，是。2可以。3可以。」——① 两艘指**机库无人机作战舰**与**巨构无人机作战舰**；② 旧档归位按「低槽满 ⇒ 挤掉最后装上的非扩舱件、退回装备库」；③ 在洞编队跳过归位。
- 槽位比例冲突裁决：**甲** —— 给无人机专用舰加豁免（与 D 族三艘、鹦鹉螺、虎鲸同款机制）。

**范围**：六件扩舱件的槽位归属、掠袭机库的扩舱数值、两艘势力无人机的槽位形状、旧档归位、随之必须同步的契约与用例。
**不做**：不改 CPU 占用、不改其余五件数值、不动战术导控与中继天线的槽位、不动官方无人机船（梭鱼 / 王鲭）的槽位。

## 三、存档兼容

`repairDeprecatedModules` 的 2.6 段与既有 2.5 段（作业装备归位高槽）同款口径，读档即归位、幂等：

- 旧档里停在高/中槽的甲板扩展 ⇒ 搬进**低槽**的空位；
- 低槽满 ⇒ 从**最后装上的那件**往前找非扩舱件，退回装备库腾位（**件不丢、随时可装回**，日志写明件数）；
- **在洞编队跳过**（进洞后改装是锁的；出洞再载入即归位）；
- 只管 `slot === 'drone-rack'` 一族 —— 战术导控与中继天线不动。

## 四、契约联动与豁免

- `content:check` 的「rack 标注与推导一致」契约自动跟着生效（`rackOf` 默认已改），契约本身无需改。
- **槽位比例冲突**：机库无人机作战舰改 4/2/4 后不满足既有契约「武装舰 高槽 ≥ 低槽 + 1」（船长 2026-09-14 立、2026-09-17 给 D 族三艘开过豁免）⇒ 按船长 2026-09-27 裁决**甲**，在 `wh-ship-baseline.test.ts` 里新增 `DRONE_SHIP_EXEMPT`（E 族两艘无人机专用舰），理由与鹦鹉螺 / 虎鲸同款：**中槽→低槽后低槽更多是设计本身，不是笔误**。
- 装备库展示顺序（`mod:order` 的非武器件按槽位分组）随槽位改动自动生效，该工具契约通过。

## 七、取舍与遗留

1. **低槽变竞争位**：梭鱼（3 高 / 2 低）与王鲭（4 高 / 2 低）的低槽现在要同时装扩舱件与装甲/货舱/支援件；官方船槽位本批未动，若实测装配吃紧再单独报。
2. **高槽被释放**：无人机流的高槽从此专供导控 / 中继 / 武器 —— 这是搬槽的主要收益。
3. 三件势力专属件的槽位一起搬了（船长选"六件全搬"）；它们的掉落池、蓝图、图鉴都只引用 id，不受影响。
