## 一、船长原话（照抄）

「**购买舰船也会触发第一艘自造船的通讯，这不对**」

二选一裁决（同日）：**甲 = 改成"造过才发"**。

## 二、根因（先查证，不猜）

**买船并没有触发它**——真正在起作用的是「老档补发」。两条独立证据：

1. **探针复现（`tools/_probe-firstship.ts`，跑完已删）**：四种现场各跑一遍 ——

   | 现场 | 修前 | 修后 |
   |---|---|---|
   | ① 新档 + 买船 | 不送达 ✓ | 不送达 ✓ |
   | ② 新档 + 什么都不做（对照） | 不送达 ✓ | 不送达 ✓ |
   | ③ **老档（删掉字段）+ 买船** | **送达** ← 看起来像"买船触发" | **不送达** ✓ |
   | ④ **老档（删掉字段）+ 什么都不做** | **送达** ← 与买船无关，铁证 | **不送达** ✓ |

2. **船长真档只读实测**（`%APPDATA%\whale-idle\save.json`，未改写）：`state.firstShipBuilt` **字段缺失** ·
   `shipStore` **空** · 机库 19 艘（`sandcat` / `whale-king` ×N / `sh-thresher` ×8 …）**全是买来的** ·
   `msg-first-ship` 已记送达 ⇒ 这就是一份"**从没造过船的老档**"，而旧口径把它当成了"造过船"。

**机制**：`commsTriggerMet` 的 `shipBuilt` 分支原为 `state.firstShipBuilt !== false`，配合 2026-09-15
三问裁决「**丙**：老档缺字段 ⇒ 读档即补发」⇒ 字段缺失 = 判定为真 ⇒ 读档那一拍就送达。
买船走的是 `market.buyAtMarket → depositGood → addShipToFleet`，**不碰这个字段**（置位点全仓唯一 =
`manufacturing.settlePiece()` 造船分支）⇒ 买船只是时间上的巧合。

## 三、冲突与裁决（§5.2）

| | 内容 |
|---|---|
| **新提议（照抄）** | 「购买舰船也会触发第一艘自造船的通讯，这不对」 |
| **冲突旧规则** | 2026-09-15 三问裁决「丙，甲，甲」中的 **Q1 = 丙**：老档缺字段 ⇒ **读档即补发**（出处：`core/types.ts` 的 `shipBuilt` 注释 · `core/comms.ts` 的判定分支 · `data/messages.ts` 的 `msg-first-ship` 注释 · 用例 `core/tests/comms.test.ts` 原「老档补发」用例明钉） |
| **不可同时成立的后果** | 保留"缺失 = 补发" ⇒ **任何 2026-09-15 前开的档都会收到这封"第一艘自造船下线"的祝贺信，哪怕一艘都没造过**（船长那份真档正是如此）；要"没造过就不发" ⇒ 必须收窄该分支 |
| **备选（乙：按痕迹判）为何不取** | 查过**没有可靠痕迹**证明老档"造过船"：`shipStore` 也能由"把机库船转进仓库"产生、组装机无历史账本 ⇒ 只能拿 `shipStore` 非空当痕迹，会**漏**（造过又取出的）也会**误**（买来的船转进仓库） |
| **裁决** | **甲：只认 `firstShipBuilt === true`**（造过才发） |

## 六、已知取舍（如实登记）

1. **"早就造过船"的老档**：这封指路信会晚到——要等它**下次造船**时才送达（内容仍然对）。换来的是
   **从没造过船的档永不误收**（船长这份档就属于后者）；
2. **已经误发的副本不回撤**：船长档里 `msg-first-ship` 已记送达（收件箱里那一封还在、弹窗已点掉）。
   真档只读、且"删玩家已收到的信"属越权 ⇒ **不动它**；本修正只保证此后不再误发。
   新档与其它老档不受影响（它们要么没送达，要么会按新口径判）。
