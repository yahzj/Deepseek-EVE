# 快递任务：出发地钉成母港（2026-09-20）

> **状态：进行中**（已实现，四闸门全绿，待船长验收）
>
> **船长原话（照抄）**：「**所有快递任务，起点都是从母港触发，以避免玩家到达某个空间站后原地送快递**」

## 一、原来为什么会"原地送快递"（查证结论）

快递任务其实有**两套航程口径**，此前不同源：

| 环节 | 原口径 |
|---|---|
| 任务刷出：**报酬**与**限时时限** | 已经按「**母港 → 目标副站**」的标称航程标定（`refreshBoard` 里 `shortestTravelMinutes(ctx, HOME_GALAXY_ID, …)`，注释还写着"与玩家实际用哪条船无关 ⇒ 不好被换船薅"） |
| 出发：**真实航程** | 按「**玩家当前所在星系** → 目标副站」（`originGalaxyOf(state, ctx)`） |

而**到站结算会把玩家留在目标副站**（`settleCourierDelivery`：`dockedSite = 目标站`）。
⇒ 玩家送完一单停在副站，接着接下一单时航程从副站起算，可能**短到 0**（代码里那条
`arriveAt <= departAt` ⇒ "立即结算"分支）⇒ **白拿母港级运费**。

## 二、改了什么

| 项 | 旧 | **新** |
|---|---|---|
| 出发地 | 任意（玩家当前星系） | **必须在母港**（`isAtHome(state)`：不在野外、也没停靠副站） |
| 真实航程 | 当前星系 → 目标 | **母港 → 目标**（与报酬/时限同一把尺） |
| 老档兜底解析目标站 | 距**当前位置**最近的已建成副站 | 距**母港**最近的已建成副站 |
| 拒绝文案 | — | 新增 `core.sideTasks.019`：「快递投送需从母港出发：请先返航母港，再出发投送。」（中英双语） |

**没动**：运费公式（级别 × 航程系数 × 限时溢价）· 限时时限算法 · 每板条数 · 接单上限 4 ·
体积档 · 跃迁门槛 · 虚拟货物（不扣物品、按体积占舱）· 结算入账与超时作废（甲案）· 副站目标池。
"立即结算"分支**保留**（副站都在红环/烬火星系、非母港 ⇒ 正常内容下走不到；留作异常兜底）。

## 三、玩家可见变化

- 停靠在副站（或人在野外）时点「出发投送」⇒ 被拒，提示**先返航母港**。
- 从母港出发的投送，**航程与报酬/时限口径一致**（不再有"短程拿母港运费"）。
- 送完一单人仍在目标副站 ⇒ 想再接一单必须先回母港（这是本令要的循环）。
- ⚠ 未做（要不要做等一句）：任务中心「出发投送」按钮在"不在母港"时**置灰 + 悬停说明**
  （现在点了才弹提示；与既有"忙碌互斥"按钮的处理方式一致，只是多一个前置条件）。

## 五、口径确认（若我理解偏了，一句话即可改）

本批落的是**乙案：必须站在母港才能出发**（"起点就是母港"的字面义）。
另有**甲案**：允许在任意位置点出发，但航程一律按"母港 → 目标"算（堵住白拿运费，却不要求返航）。
两者差别 = **要不要强制玩家先回母港**；甲案下会出现"人在副站、船却按母港航线飞"的叙事错位，
故我按乙案落。要改成甲案说一声。
