# 快递任务：出发地钉成母港（**不在母港则自动返航**）· 2026-09-20

> **状态：进行中**（已实现，四闸门全绿，待船长验收）
>
> **船长原话（照抄，两句 · 后一句改判前一句的实现方式）**：
> ① 「**所有快递任务，起点都是从母港触发，以避免玩家到达某个空间站后原地送快递**」
> ② 「**出发不用加守卫，点击出发后自动返回母港。**」

## 一、原来为什么会"原地送快递"（查证结论）

快递任务其实有**两套航程口径**，此前不同源：

| 环节 | 原口径 |
|---|---|
| 任务刷出：**报酬**与**限时时限** | 已经按「**母港 → 目标副站**」的标称航程标定（`refreshBoard` 里 `shortestTravelMinutes(ctx, HOME_GALAXY_ID, …)`，注释还写着"与玩家实际用哪条船无关 ⇒ 不好被换船薅"） |
| 出发：**真实航程** | 按「**玩家当前所在星系** → 目标副站」（`originGalaxyOf(state, ctx)`） |

而**到站结算会把玩家留在目标副站**（`settleCourierDelivery`：`dockedSite = 目标站`）。
⇒ 玩家送完一单停在副站，接着接下一单时航程从副站起算，可能**短到 0**（代码里那条
`arriveAt <= departAt` ⇒ "立即结算"分支）⇒ **白拿母港级运费**。

## 二、改了什么（**最终口径：不加守卫、点出发就自动返航**）

| 项 | 旧 | **新** |
|---|---|---|
| 出发地 | 任意（玩家当前星系） | **母港**：不在母港时，**点「出发投送」先把舰船自动送回母港**，再按母港航线投送 |
| 真实航程 | 当前星系 → 目标 | **母港 → 目标**（与报酬/时限同一把尺） |
| 老档兜底解析目标站 | 距**当前位置**最近的已建成副站 | 距**母港**最近的已建成副站 |
| 返航段代价 | — | **0 时间**——与 `location.startTransitHome` 定稿的「**换港返航即时到站、去程取消**」同一把尺；只追加一条事件日志（新增 `core.sideTasks.020`：「快递出发：舰船先自动返航母港（自「{p1}」），再按母港航线投送。」） |
| 校验顺序 | — | **位置复位放在全部前置校验之后**（忙碌互斥 / 目标可用 / 货舱 / 跃迁门槛 / 航路可达都过了才动人）⇒ 不会"先把人送回母港、再告诉他这单发不了" |

> 中途一版曾按"字面义"落成**硬守卫**（不在母港直接拒 + `core.sideTasks.019` 文案），
> 按船长第 ② 句**已撤掉守卫**（该条文案一并从表里删除，不留无用条目）。

**没动**：运费公式（级别 × 航程系数 × 限时溢价）· 限时时限算法 · 每板条数 · 接单上限 4 ·
体积档 · 跃迁门槛 · 虚拟货物（不扣物品、按体积占舱）· 结算入账与超时作废（甲案）· 副站目标池。
"立即结算"分支**保留**（副站都在红环/烬火星系、非母港 ⇒ 正常内容下走不到；留作异常兜底）。

## 三、玩家可见变化

- 在**任意位置**点「出发投送」都能发单；若人不在母港，日志会写明「舰船先自动返航母港」。
- 投送航程恒为**母港 → 目标**，与报酬/时限口径一致（不再有"短程拿母港运费"）。
- 送完一单人留在目标副站；再发一单同样自动回母港起算 ⇒ 不再有"原地送快递"。
- **限时快递不再被本次改动波及**：时限本来就按"母港→目标 + 5% 宽限"标定，而返航段 0 时间 ⇒ 完全对齐。
