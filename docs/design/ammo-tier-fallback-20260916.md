# 弹药取档口径改判：同族取"能装得最多"的那一档（2026-09-16 · 报障修复）

> **状态：进行中**（工作文档；船长验收 + 合入 main 后按 AGENTS.md §8 归档三步：并入 roadmap ＋ 词典改写 → 删本文件 → 重跑 `docs:index`）

## 一、船长报障（照抄）

「**玩家反应，爆破导弹MK2的仓库有553个，，舰船携带重型导弹架MK2进入战斗后提示无弹**」

## 二、根因（真引擎探针实测 · `_` 探针跑完即删）

**不是漏接线**，而是 2026-09-09「选档制」那条裁定在实战里露出的两个缺口：

| 情形（3× 重型导弹架 MK2 · 本场需求 **207 发**） | 改判前 | 改判后 |
|---|---|---|
| **A · 没在装配页选弹种档**（默认） | 只装**基础弹**；仓库 553 发 MK2 **一发未动**；基础弹 0 ⇒ `exp = 0` ⇒ **界面「（无弹）」** ← **玩家遇到的就是这个** | **自动装 MK2 207 发**（`ammoIds.explosive = ammo-explosive-2`）＋ 日志「⚙ 基础弹可用量不足，本场改用爆破导弹 MK2（预载 207 发）」 |
| **B · 选了「爆破导弹 MK2」** | 装 207 发 ✓（本就没问题） | 不变 ✓ |
| **C · 选了 MK2，但持有量 < 207**（例：只有 30 发） | **整族回退基础弹** ⇒ 那 30 发 MK2 **一发不用**；基础弹 0 ⇒ 仍（无弹） | 取同族**能装最多**的一档：基础弹 60 > MK2 30 ⇒ 装基础弹 60（**不再是 0**）＋ 日志；若基础弹为 0 ⇒ 装 MK2 那 30 发 ✓ |

**本场需求怎么来的**：`ammoLoadTotals` = `⌈4 分钟交战上限 × 1.5 余量 ÷ 装填(5280ms)⌉ × 门数(3)` = **207**
（吃「弹药集约学」+8%/级）。

## 四、现行口径（落码）

**取档单点 = `combat.resolveAmmoTier(state, ctx, shipId, type, want)`**（**引擎装载与装配页共用**）：

1. 候选 = **基础弹恒在** ∪ 物品表里同族（`ammo-<族>-*`）的全部档 ⇒ 日后加档自动纳入；
2. 各算**可装量** = `min(该档货舱+仓库库存, 本场需求)`；
3. **取可装量最大者**（不再"不足整批就整族否决"）；**允许装不满**（有多少装多少）；
4. **平局按"期望档优先"**：`ammoPref` ＞ 基础弹 ＞ 其余（id 序）⇒ 选了档仍优先用所选档；
   **没选档且两档都够 ⇒ 仍走基础弹**（"不选档 = 基础弹"的旧语义保住，不会偷偷烧玩家没选的高级弹）；
5. `fellBack` = 实际档 ≠ 期望档 ⇒ 调用方记日志（文案 `ammoTierFallbackLog`：期望档 = `ammoPref`，
   没设则写"基础弹"）；
6. **`battle.ammoIds` 只要有实装就记"实际档"**（含实际档 = 基础弹）——⚠ 这条是**正确性修复**：
   旧口径只在"设了档"时记 ⇒ 若实际装了基础弹而 `ammoPref` 是 MK2，**推进重建会按 MK2 结算伤害、
   退还却退基础弹**（串档）。

**界面（装配页「弹药档位」）**：两侧库存都显示（`基础弹 ×A · MK2 ×B`）＋ 一行「本场预载：〈档名〉可装 C/D」
（D = 本场需求，走同一个 `ammoLoadTotals`；C/D 走同一个 `resolveAmmoTier` ⇒ **界面显示 = 实战结果**）；
`C = 0` ⇒ 红字「⚠ 两档都没货：本场将无弹可打」；发生改档 ⇒ 红字「⚠ 〈期望档〉不足，将自动改用〈实际档〉」。
工具提示里旧句「库存不足整族回退基础弹」已改写。
