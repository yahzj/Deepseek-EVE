## 症状与铁证（用截图上的两个总数对账）

截图：入侵结算 · 墨潮帮 · 第 1 场 —— 清缴贡献 **100%（A 档）** · 夺回星系 **4/4** · 四行全是「贡献 100% · 已夺回 · **—**」。

| 面板显示 | 应为 | 实得（反推） |
|---|---|---|
| 稀有残骸 **450** | 贡献奖 12 件(360 m³) ＋ 旗舰 3 件(90 m³) ＋ 夺回 4×8 件(**960 m³**) | 360 ＋ 90 = **450** ⇒ 夺回那 960 m³ 完全没有 |
| 信用点 **88,000,000** | 贡献奖 800 万 ＋ 进度收入 8,000 万 ＋ 夺回 4×200 万 ＋ 全清 500 万 | 800 ＋ 8,000 = **8,800 万** ⇒ 夺回的 800 万与全清 500 万完全没有 |

⇒ 两个数精确等于「**不含夺回奖励**」的那一份 ⇒ **32 件稀有残骸（960 m³）＋ 1,300 万信用点一分没发**。

## 根因

夺回奖的记账与入账**挂在战斗结算那条路上**：

```ts
// weekendBattle.ts:936（weekendApplyBattleOutcome 内）
if (r.reclaimed !== undefined) {
  noteReward(evNow, involved.galaxyId, { … })
  noteReclaimPending(evNow, { … })
}
```

而"夺回"在本作里是**按进度判**的（`weekendEvent.weekendReclaimedAt` = `weekendProgressAt(...) >= 1`），
多数场次的夺回是**进度条被逐拍推满**（NPC 铺底 ＋ 玩家投入），**根本没经过"战斗结算"那一拍**
⇒ 这段代码从未执行 ⇒ `rewardLedger.byGalaxy` 是空的（面板每处都显示 `—`）、
`reclaimPending` 也是空的（结束结算时自然也没补发）。

## 修法（2026-09-27 船长令「按你推荐来」）

1. **记账改逐拍检测**：新增 `weekendBattle.weekendSyncReclaimRewards` —— 每拍比对
   「**已夺回**（进度 ≥ 1）∧ **还没记过奖**（不在 `ev.reclaimPaid`）」的星系 ⇒ 记
   `noteReward(该星系, …)` ＋ `noteReclaimPending(…)` ＋ 写进 `ev.reclaimPaid`；
   首达"全处夺回"时再追加全清那 5M（用 `reclaimPaid.length === 总处数` 判，天然只发一次）。
2. **战斗结算那一段改为调用同一函数**（删掉原来那两行）⇒ 只有一份口径，不留两套。
3. **补发（幂等、自动）**：`weekendSettleAndGrant` 每拍都被调（幂等靠 `prizePaidAtWallMs`）⇒
   在它的 **early-return 之前**先跑一次 sync；若 `prizePaidAtWallMs` 已置（**本场已结算过**，
   正是船长这一场）却 sync 出了新的待发 ⇒ 立刻 `weekendGrantRewards` **迟到补发**并清零
   `reclaimPending` ⇒ 玩家下次进游戏自动补齐，**不需要单独的迁移脚本、不碰存档**。

## 不做 / 取舍

- **不动**贡献四档与旗舰掉落的既有口径（那两笔实发正确）。
- **不写**一次性补丁脚本：补发靠"已夺回 ∧ 未记账"这条**幂等判据**自然完成（老档一样走这条路）。
