# 装配页补「命中率」属性（2026-09-19）

状态：进行中（已落码 + 闸门自测；等船长观感验收）

## 船长原话
「装配界面的舰船属性里，少了命中率属性」

## 口径裁决（2026-09-19 船长两轮定）
1. 补 **「命中率（含装备）」**：整机百分数（本船炮台 / 导弹架 / 激光炮的均值），**取代**原来的「开火命中修正（含装备）」行。
2. 口径选 **A（纸面加算口径）**，并令「**解除上限锁** —— 超出上限的部分能够抵消射程的命中削减」⇒ 本行**一律不截断**，
   读数允许 >100%（那部分余量正是实战里被射程衰减与敌舰回避消费掉的量）。
3. 括号明细：`船体加成 +17% · 索敌 ×1.08 · 推进失稳 ×0.95`（缺省项不显示，免得 ×1.00 噪声）。
4. 三个引擎对齐点（逐字核过 `combat.hitChance` 与开火分支）：
   - 船体加成**加算**在武器基础命中上（`types.ts` 的 `hitBonus` 注释原文「加到武器命中率上」）；
   - 索敌件 `eqHitMul` 与推进失稳 `hitMul` **只作用于掷命中武器**（激光 `hit = 1` 必中、不吃失稳）；
   - 引擎的 `clamp(0,1,…)` 在**最后一步**（距离衰减之后）⇒ 显示行刻意不截断，把余量留给玩家读。
5. 基础舰炮与无人机是 `kind:'fixed'`（必中）⇒ 不进均值（与 `rawDpsOf` 同一取舍）。

### 真引擎读数（临时探针，5 型船 · 满装：炮台 MK1 + 导弹架 MK1 + 激光 MK1 + 索敌 MK1 + 推进器 MK1）
- 本行读数：**100~104%**。例（长尾鲨级导弹巡洋舰）：炮台 `(0.80+0.17)×1.08×0.95 = 0.995` ·
  导弹架 `(0.92+0.17)×1.08×0.95 = 1.118` · 激光 `1.00` ⇒ 均值 `1.038` ⇒ 显示 **104%**。
- 为什么纸面读数贴着 100%：导弹架 MK1 基础命中 **0.92**（唯一「掷命中却不吃距离衰减」的武器，`falloff: 1`），
  加算 +17% 即 1.09、被 100% 上限截断——**解除上限锁后这部分余量才可见**。
- 引擎侧对照（同一门炮 · 锤头鲨级 +18%）：现行 `(命中 + 加成 − 回避) × 衰减` 在射程端 43.0%；
  若改序为「加成不被距离缩水」（`命中 × 衰减 + 加成 − 回避`）= 46.0%（**+3.0pp**）——**本次未采用**：
  船长选「只解显示行的锁、零战斗影响」。（另两条留档：只放开 `hitMax` 实战零变化、且会让 DPS 预估虚高；
  改公式顺序属战斗数值改动，中远距 +1.5~3.0pp、整机 +0.0~0.8pp，且只增益玩家——敌方 `hitBonus` 恒 0。）

## 现象与根因
- 装配页属性表 = `shipInfoLines(shipDef)` 过滤掉 `COMBAT_BASE_KEYS`（名单里有「命中加成」「回避率」）后，在下方"装后合成"行里补回。
- 补回的只有「回避率（含装备）」与「开火命中修正（含装备）」（后者只给失稳 / 索敌两个**乘子**）
  ⇒ 船体 `spec.hitBonus` 被过滤后**没有任何地方显示**，装配页因此看不到命中那一条。

## 涉及文件
- `apps/desktop/src/renderer/src/pages/FitPage.tsx`：新增 `meanHitRateOf` / `hitDetailText`；
  命中率行取代「开火命中修正（含装备）」；表尾 note 补一行口径与「超 100% = 余量」的说明。

- 不改其它页面的属性表口径。
