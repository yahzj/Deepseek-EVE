机制（`packages/core/src/salvage.ts`）：
- **保底价值/批 = 体积 × 档位当量（`RECYCLE_YIELD_PER_M3`）× 池均价**；三档当量与池均价互为倒数
  ⇒ **收益 = 卡级（档位当量 × 卡级池均价）的加权平均**，组档位只决定「给什么矿 · 高级箱命中率 · 残骸收价」。
- B3.1 契约（`tools/content-check.ts`）把组钉死在三处：② **保值**（组池均价 = 卡级加权目标 ±3%）·
  ③ 不凭空造矿（组池 ⊆ 卡级池并集）· 组档 = 成员卡**多数档** ⇒ 想抬某族的价，必须从**卡级**动手。

## 顺手修掉的两处（同批报告）

1. **主题件检查曾静默失效**：`content-check` 那段「主题彩头仅限 sec<0.5 星系 / 中安挂 modules / 低安挂 mk2」
   读的是 `def.recycleLoot`——该字段 2026-09-19 随残骸合入组表时已从 `AnomalyDef` 删除 ⇒ 整段恒读 0 张卡、
   什么都不查（打印「0 张卡」）。现改读现行卡级表 `RECYCLE_LOOT_PILOT`，检查复活（23 张卡）。
2. **主题件里出现无人机时的错账**：高级箱「未命中 ⇒ 必给主题件」这一支原先把抽中的 id **无条件**塞进
   `modules`，而结算点（`industry.ts`）把 `modules` 一律记进 `moduleBay` ⇒ H 三件里的无人机
   （`drone-ink-heavy`）会变成一件"假模块"进装备库。现按件型分派：蓝图 → `blueprints` ·
   物品且 `kind === 'drone'` → `drones`（一次 30 架）· 其余 → `modules`（**旧口径逐字不变**，
   `rare-box-weight` 用例的合成 id 抽样不受影响）。
   ⚠ 另有一条**口径限制**（已写进契约警告）：普通残骸的**直出池只收模块**，所以 H 三件里的无人机
   **不会**从普通残骸直出（只有稀有残骸高级箱给得出）；两件支援件则直出池 + 高级箱兜底都给。
