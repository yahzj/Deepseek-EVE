# 玩家舰船残骸（含加固结构插件回收接口）（2026-09-26）

状态：已实现并合入，2026-10-09归档为玩家沉船现行入口。早期加固回收60%接口已被以下加算封顶规则覆盖，后文保留历史依据。

## 现行整船回收与战损

- 正常星系主控/AI沉船留下48小时残骸，打捞优先于稀有池与手选对象；信号空间/虫洞不生成玩家沉船残骸，货物与弹药不返还，无人机仍用独立回收率。
- 整船首轮仅判一次，基础25%；Rank4舰体打捞工程每级+5个百分点、Rank5高级每级+4个百分点，加上既有插件修正后上限90%。两技能满级本身为70%，不写成90%。两条Rank5（高级舰体、装备保全）都以前置Rank4的Lv1为门槛，训练许可/时长走原算法。
- 回收成功拖回母港舰队，结构和装甲各20%，不自动切主控；普通装备基础保全80%，Rank5装备保全每级+4个百分点至100%，逐件一次，失败永久损失。`recoveryRules:2`的新残骸用此规则，旧残骸无标记保留原逐轮尝试，不静默迁成一次判定。保全装备按原位及真实槽位/CPU装回，装不下退库，先装必要算力件；不借本次回收删除库存。
- 成功回收50%概率加战损，最多3类、同类不重复，六类为盾/甲/壳/速度/货舱/武器及无人机射程之一，单项-15%。`damagePlugs`与普通`plugs`分开保存，战损不占普通格、不制造/交易/卸下、不随维修清除、不进方案；带战损船不得入仓/挂售。
- UID分配包含尚在现场的残骸与损失记录，防止新造或回收同型船覆盖旧记录。残骸、舰队、通讯三处快照保留战损；显示同普通插件卡格并列，桌面/触屏查看同源富属性。我的舰队普通插件已隐藏，但战损保留。
- 沉船装备卡及保存装配方案规则见`ship-plug-20260926.md`；主动拆船返还制造料单50%并退装备/普通插件/无人机/货物，是另一个入口，不等同概率打捞。

实现`1bc1ef19`及后续同区展示已合入；`shipWrecks.ts`概率、`shipDamage.ts`惩罚、`salvaging.ts`入账为唯一算法。核心23项整船、10项显示及方案/旧档/库存专项，隐藏两布局×两语言×桌面/手机8组合IPC/重载验证通过。测试入口为`docs/test-saves/wreck-fit-20261007.md`与`docs/test-saves/ship-recovery-20261007.md`。概率与兼容验收沿这些真实用例，不读取个人档。

## 设计总结（已确认）

### 一、一句话

船在正常星系被打没 ⇒ 该星系留一具写着船名的残骸，48 小时（游戏时间）线性衰减；
在那儿打捞时它排在最前面（压过稀有池），每轮从它身上捞 1 件、逐件掷概率回收装备；
**没有矿物、没有信用点、没有其它资源**。

### 二、触发面

| 损毁路径 | 调用点 | 是否生成 |
| --- | --- | --- |
| 主控远征失利遭追击（正常星系） | `expedition.ts` | ✅ |
| AI 副船远征失利遭追击（正常星系） | `ai.ts` | ✅ |
| 虫洞内被击沉 / 失联 | `wormholeBattle.ts` ×2 | ❌ |
| 低安遭遇战 | `encounters.ts` | ❌（结构 5% 底线，根本不丢船） |

**实现要点**：`loseShip()` 加**可选**入参 `wreckGalaxyId`，**只由两处正常星系调用点传入** ⇒ 虫洞那三处不传、不可能误生成。

### 三、打捞四级序

```
①★ 玩家舰船残骸（新） ← 有就每轮从中捞 1 件
① 稀有池（捞完为止）
② 普通池 ⓐ 同池内入侵残骸优先  ⓑ 否则按各组数量比
```

- 有玩家残骸时它**独占**该轮（不碰两池、不参与组比）；手选打捞对象也压不过它。
- **掷完所有件 ⇒ 残骸消失**；**48h 到点 ⇒ 无条件消失**。

### 四、回收概率（逐件掷 · 分档 · 保底）

| 件类 | 回收率 |
| --- | --- |
| 武器（炮台 / 导弹 / 激光 / 无人机导控 / 中继） | **60%** |
| 装甲 / 护盾 / 货舱扩展 | **40%** |
| 无人机舱各型 | **25%** |
| 其它（支援件等兜底） | **40%** |

**保底**：整具残骸至少掷回 1 件。**不吃技能加成**（打捞学管"每轮多捞多少 m³"，与"这件能不能捞回"两回事）。

### 五、加固结构插件接口（本次只留口子）

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| `ModuleDef` | `hullRecoveryChance?: number` | 带此字段的件 = 加固结构插件（0~1 整船回收率）。**现无一件带此字段 ⇒ 恒不触发** |
| `ShipWreckRecord` | `reinforceChance?: number` | 损毁那刻把该船装着的加固件数值**求和存下**（日后插件改值不影响已生成的残骸） |

**唯一判定单点** `salvage.hullRecoveryChanceOf(rec)` = `clamp(0, 1, Σ)` ⇒ 日后加插件只改数据表 ＋ 新增那件模块，本机制零改动。

**流程**：玩家残骸被捞的**第一次**先掷整船回收 —— 命中 ⇒ **整艘船回港**（连同当时装配与无人机）、跳过逐件掷骰、残骸消失；
未命中 ⇒ 记"已掷过"标记（**一具只掷一次**，防反复刷概率），此后走逐件回收。

**船长三点裁定**：① 回**母港舰队**、耐久/装甲按残骸时刻打折（结构 30% / 装甲 50%）、**不自动成为驾驶船**、
货舱货物不回；② **同一艘船**（保留自定义船名与装配）；③ 回收率**加算、封顶 60%**（数值等插件定稿时拍）。

### 六、边界 / 不做

- **不做**：虫洞残骸 · 低安遭遇 · 货舱/弹药回收 · 跨星系打捞 · 市场/图鉴新物品（残骸是**星系账**，不是物品）。
- **不改**：稀有池与普通池的既有语义（只是前面多插一档）· 既有三类残骸的产出与价格 · 技能效果。
- 已知取舍：这是给玩家的**一次止损**（丢船从"装备全没"变成"至少捞回一半上下"）。若觉得太宽松，
  只降武器档（60% → 40%）即可，一个常量的事。
- 存档：`state.shipWrecks` 为**可选字段，零版本迁移**（照 2026-09-25 `weekendWrecks` 成例；老档缺键 = 无残骸）。

### 一处实现期的发现（值得记）

`pullOneWreck` 里原有「手选对象已捞干 ⇒ 本轮不出」那道**存量闸**排在玩家残骸之前 ⇒
手选了一个捞干的组时，玩家残骸会被跳过。按船长「**优先打捞该残骸（比稀有残骸优先级还高）**」的字面口径，
**残骸里的件与任何型号池的存量无关** ⇒ 已把残骸那一支**提到存量闸之前**，并由用例钉住。
