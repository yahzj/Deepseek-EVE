## 二、方案（三档，按风险递增；每档都能单独交付）

### 第一档 · 手机「可读可点」（纯版式，**桌面一字不动**）

| 编号 | 改动 | 目标读数 |
|---|---|---|
| M1 | **取消二次缩放**：手机档先压版式再缩——顶栏 `nowrap` 单行（统计降为 `--wui-fs-s`）、距离尺 89 → **≈48**（隐藏分档小字，只留游标与当前距离）、底栏改**左右两栏并排**（左：图例/装填；右：滑杆＋战术三键）191 → **≈120** | `need ≤ 554` ⇒ **k = 1**（`battleFit` 不介入），物理缩放恒定 ×0.703 |
| M2 | **字号与触控**：手机档可点元素最小高 ≥ **44 逻辑 px**（现 ≈38/40）、相邻间距 ≥8、正文最小 15 逻辑 px（现 11~13.5 的次要行抬高） | 触控物理高 ≈31px（现 ≈21）· 字物理 ≥10.5px（现 ≈7.2） |
| M3 | **安全区**：旋转层顶栏/底栏补 `env(safe-area-inset-*)` 内边距（刘海与手势条不吃按钮） | 真机读数：按钮不落进系统条 |
| M4 | **血条加高**：手机上三层血条 8 → **12 逻辑 px**（绝对定位贴舰影下沿 ⇒ 不额外占高） | 战场内容高不变，可读性提升 |

### 第二档 · 信息层级（桌面与手机**同时**受益）

| 编号 | 改动 | 说明 |
|---|---|---|
| I1 | **一屏一把尺**：距离尺留在舞台，底栏滑杆只留「战术三键 ＋ 期望交距」（期望值数字仅拖动时显示） | 现在同一读数在两处（尺 89px ＋ 滑杆行） |
| I2 | **底栏分层**：图例 chip 收起「逐武器射程数字」改成**点开详情**，chip 只留伤害类型徽标＋名称；弹药/修理/装填合并一行；装填条「逐件一行」→ **紧凑网格（每件一列）** | 手机端不再需要横滚才能看全装填 |
| I3 | **触屏可及**（手机端最大一处"看不见"）：所有只靠 `title` 的信息改为**点按出卡片**（沿用 `ui/Tooltip.tsx` 接管层；桌面仍悬停，手机「点按开、点空白关」） | 覆盖：敌舰名单与挂载件效果、伤害类型说明、推进器周期 |
| I4 | **状态语义**：距离尺 `role="img"` ＋ `aria-label`（当前/期望距离）；三层血条 `role="progressbar"`（读数 = 各层百分比） | 桌面视觉零变化 |

### 第三档 · 结构级（改动大，需单独排期与验收）

| 编号 | 改动 | 取舍 |
|---|---|---|
