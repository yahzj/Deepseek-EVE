### 8.2 与草案的差异（如实记录）
1. **4 个舰级按"档次"组织，且每档绑定一个战术**（一档快艇 brawl / 二档护卫舰 orbit / 三档狙击舰 kite / 四档头目舰 elite）——
   因为**战术后射程带、速度、主系都要有绝对落点**；四档 = 头目档，与船长「④按四级」一致。
2. **同行档内差异用精确倍率吸收**（如碎晶 = 快艇 ×`285/150` / `47/28` / `377/351` / `2273/2215` + 主系覆写 kinetic）——
   6 张卡的属性组合实际有 6 种（主系/射程/速度各不同），4 档装不下"零难度变化"，故倍率是必需的。
   倍率的语义 = "**同一条船的变体**"，且**卡上看得见**（这正是"改一艘船不连带别的"的落地形态）。
3. **`赤潮` 的 `foeDmgMul 0.27` 与 `蜃影` 的 `0.30` 随本改造退场**——伤害并入舰级单发 × 倍率表达，
   逐卡伤害压制补丁清零（与船长早前「两处伤害 foeDmgMul 都移除」同一方向）。
4. **`混编` 试点未实际使用**：6 张卡保持原编成（⑥「先不改数值」），其中灰霾/蜃影的"主 + 僚"是**同一舰级的两条编成**
   （×0.6 血与单发、`escort: true`），故 content-check 如实报"混编 0 张"。**混编与头目档的能力由
   `packages/core/tests/foe-ship-path.test.ts` 直接覆盖（9 项测试）**，不靠"将来某张卡会用到"兜底。
5. **卡面 `tactic` / `defProfile` / `dmgMix` 保留**（卡面口径），与舰级定义**重复**——由新增「舰级契约」锁死一致性。
6. **战力校验改为报告式**：原计划的"硬断言"未落地，因阈值需船长拍板；报告式审计亦未在本批输出，
   **留待 A 族特色批**（届时赤潮/蜃影那类"实际火力远低于卡面威胁"的偏差才需要判定）。

### 8.3 安全等级交换的**真实连带**（内容校验当场抓出并已修）
换区后 `content:check` 立刻报出 2 处 **B3.1 特色回收池**失配——因为**危险度档位随 sec 走**：

| 卡 | 换区 | 档位 | 池均价（修前 → 修后） |
|---|---|---|---|
| 烬火围攻战 | 低安 −0.7 → 中安 0.0 | 危 → **常** | 15.05 → **11.44**（目标 m×9.8 = 11.446） |
| 蜃影导航劫持令 | 中安 0.0 → 低安 −0.7 | → **险** | 32.95 → **43.10**（目标 m×27.6 = 43.249） |

同时**主题追加件按区划分**（中安 = `modules`、低安 = `mk2`）：两卡的追加件已互换，否则烬火那两条
会变成"**永不掷出的死配置**"（`mk2` 仅 sec<0 掷，而它已不在低安）。

⇒ **这是"海盗进低安"的收益面**：蜃影那条矿带不仅会招来海盗，**残骸还更值钱**了。

### 8.4 顺带修掉的两处结构缺陷
1. **族系单一真相源**：删掉 `shipArt.tsx` 里 22 行硬编码 `FOE_FAMILY`，`foeFamilyOf` 改读数据侧
   `AnomalyDef.foeFamily`（两处调用点同步改）；`演习场靶机` 按数据侧补齐为 B ——
   **分脑（美术侧 B / 数据侧空）就此消除**。
2. **战术显式化**：`烬火42 / 回音52 / 天底66 / 虚海88 / 穹顶96` 补上显式 `tactic: 'orbit'`
   （原先靠 `combat.ts` 的 `?? 'orbit'` 缺省值生效，是个静默陷阱）。

### 8.6 追加（2026-09-11 第二轮，船长「头目建议允许多个战术」）
原实现把**头目档的战术写死在 `brawl`**，且契约「卡面战术必须等于主体舰级战术」会**拦住**头目换战术——
与船长「鱼龙混杂」冲突，已改：

| 项 | 改前 | 改后 |
|---|---|---|
| 舰级 `tactic` | 必填且写死 | 降级为**默认战术** |
| 编成条目 | 无战术字段 | 新增 **`tactic?` 覆写** |
| 射程带 | 只有倍率（两端同乘，**换不了档**） | 新增 **`rangeMinM?` / `rangeMaxM?` 绝对覆写** |
| 契约「卡面战术 = 主体舰级战术」 | 硬等 | 放宽为「卡面战术须落在**主体有效战术集合**内」（混编允许各主体不同战术） |
| 敌速契约 / 族→战术契约 | 读舰级 `tactic` | 读**有效**战术（覆写优先） |
| 引擎 | `foeTactic: ship.tactic`；突进资格看舰级战术 | `foeTactic: slot.tactic ?? ship.tactic`；突进资格看**有效**战术 |

⇒ **头目的"强"来自档位，"怎么打"由卡上定**——正落在船长「卡上用修正」的原则里，
也贴合海盗"缴获改装、换套武器换打法"的设定。新增 3 项测试（同舰换战术 + 绝对射程覆写 /
未覆写走默认 / 混编各用各的战术），`foe-ship-path` 共 **12 项**。

### 8.7 口径更正：**射程与战术仅弱相关，不实时强绑定**（船长同日追加）
8.6 里我写的"换战术**必须**同时给射程，否则会出现'想打远战却只有 2.6 km'的矛盾"**是过度约束，已作废**。
船长原话：「**射程和战术仅仅的弱相关，并不实时强绑定**」。

修正后的口径：
- **战术**决定敌方的**意愿**（`tacticDesireFactor`：想在射程带内哪个位置打、怎么进退）；
- **射程**是**独立的绝对值旋钮**（`rangeMinM`/`rangeMaxM`/`rangeMul`），按设计需要单独调，**不跟随战术**；
- 旧路径的 `TACTIC_RANGE[战术] × 成长`（强绑定）**只保留在未写 `ships` 的卡上**，舰级路径不再继承该耦合；
- 因此"给一条短射程的头目舰配 kite 战术"**是合法设计**（它想拉远、但武器够不到那么远——这本身就是一种可用的性格），
  "给长射程的 brawl 舰"同理；数值设计时**不要**用"战术 → 射程"的强绑定去反推。

### 8.5 新增契约（content:check）
- **舰级契约**：编成引用的舰级必须登记在表内 / 舰级族 = 卡族 / 卡面战术·血型·伤害构成与主体舰级一致 / 至少一条主体。
  输出：`6 张舰级路径卡（8 条编成，其中混编 0 张）引用有效、族与卡面口径一致`。
- **族→战术契约**：只登记**已裁定**的族（当前仅 A 族 = 鱼龙混杂，三战术全允许），未裁定的族不校验（不预设、不猜）。
  输出：`6 处族内战术声明均在已裁定范围内`。
- **敌速口径契约**（改造）：舰级路径卡改按"实际建出的舰级速度"校验比率。输出：`20 张逐卡显式标定 + 6 张引用舰级速度`。

## 六、方案丙（船长三轮提议）：**直接交换星系的安全等级**

> 船长原话：「那么**直接将星系互换**呢？**安全等级也跟着换**」+「**矿带保留在原位**」

### 6.1 为什么更优：它把 §四 的两条硬约束**整个绕开**

- 卡**一张都不动** ⇒ "卡名 ↔ 星系名"绑定问题消失（§四 约束二作废）
- 威胁值**一个都不改** ⇒ "够不够得着低安"的问题消失（§四 约束一作废），且与 ⑥「先不改数值」完全一致
- 代价只是改**两个数字**（两个星系的 `security`）

### 6.2 矿带：已核实**不会被带动**——而"留在原位"正是收益所在

- 矿带是**独立数据表** `packages/data/src/belts.ts`，每条矿带用 `galaxyId` 挂到星系上
  ⇒ **改安全等级不动矿带**（矿带仍挂在原来的星系 id 上，一点没挪）✅ 符合船长要求
- ⭐ 而"矿带留在原位"恰恰是**收益**：低安伏击只发生在「**停留与就地作业**」
  （采掘 / 打捞 / 扫描 / 驻留，见 `encounters.ts` 头注），而**伏击者取自该星系可见的悬赏敌群**
  ⇒ 蜃影星系变成低安后，**在那条矿带上挖矿就会招来海盗**——
  这正是"低安要有海盗族"最实在的体现：**不是多一张卡，而是那条矿带从此不安生**。

### 6.3 安全等级的连带面（比"卡的位置"大得多，必须知情）

### 6.4 交换对象选址：**蜃影星系 ⇄ 烬火星区**
