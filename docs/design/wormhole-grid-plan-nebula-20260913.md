**为什么下限要"兜底翻转"**（这条是我自己踩的坑，记下来）：70/30 那道分法是**逐格掷骰**

## 3. 三处"落码时才发现"的坑（都记下来，免得后人重踩）

### 3.1 只补"残骸信号数"不保证遗迹格数
见 §1 末段：**期望 ≠ 保证**。补信号只把"会掷几次"抬上去，掷出来仍可能是 0。

### 3.2 空占比的量纲：是"占**可分配池**"，不是"占**总格数**"
- 这一层的可分配池 = 全部格 − 终点格（终点不参与分配）；
- 旧式 `空 = ⌈总格数 × 50%⌉` 在层 1（19 格）得 **10 空**，而池只有 **18 格** ⇒ 实际是 **55.6% 占池**；
- 本批把量纲写成"占池"，并**令层 1 逐格不变**（19 格 / 10 空）——**船长原口径在层 1 上一字未动**；
- 我中途推错过两次（一次按总格数解、一次忘了"非空 = 池 − 空"），是**用例把我拦下的**
  （层 1 一度变成 6 空 / 32%、另一版甚至 18 空把整盘填满）⇒ 这类算式的正确性只能靠"逐层逐 seed 实数"钉。

### 3.3 副产物：各信号计数**从"随 seed 漂"变成逐层定额**
旧口径下池子大小**取决于终点格自己是不是空的**（池恒为 17 或 18）⇒ 同一层不同 seed 的信标数会在
**1/2 之间漂**。现在空格数是定额 ⇒ 池子定额 ⇒ **各信号计数逐层定额、与 seed 无关**
（信标：层 1/2 = 1 · 层 3/4 = 2 · 层 5+ = 4）。这是纯改进（校准与用例都不必再留"取整容差"），
但**"各层信标数照旧"那条旧断言因此失效**，已按新分配重钉。

### 3.4 ⚠ 界面上有一处**真的会漏**的地方（已修）
地图此前**直接读 `c.place` 上色**（`signalOfPlace(c.place)`）——那是**真相**。
星云要是只加在 core、不接界面，边框颜色立刻把被遮的信号漏出去（"这格橙色 ⇒ 里面有舰船"）。
现在地图的**信息档一律走 core 的 `revealOf`**（四档同源：`unknown` / `signal` / **`nebula`** / `known`），
星云格走 `.is-nebula`（**不上信号色**）+ 新增 `WhNebulaGlyph` 云团线稿 + 图例新增一档。

## 4. 星云机制的行为口径（本轮落定的细节）

| 环节 | 口径 | 出处 |
|---|---|---|
| 出没层 | **层 4 起**（层 1~3 恒 0） | 船长「四层以上及以上」 |
| 长在哪 | **只长在有信号的地点上**；空地与下一层入口都不长 | 船长「空地没有星云」+ 导航标记不该被遮 |
| 配额 | `⌈有信号格数（不含入口）× 15%⌉`，且最多占一半 | 经办定（层 4 = 4 格 · 层 5+ = 6 格） |
| 首扫 | **只读到"星云"**（`{ kind: 'nebula' }`）：信号与地点都不给 | 船长「星云会遮挡该地点的信号」 |
| 驱散 | **一次扫描动作**把扫描圈内**所有**被遮的格一起驱散（不是每格一次） | 经办定（"再扫描一次"= 一个动作） |
| 驱散后 | 信号显形；**不额外给奖励**（它是**回合税**，不是收益机制） | 经办定（避免与"遗迹下限"叠加过强） |
| 到达 | **到达即真相**照旧（既有口径优先）：云没散，走过去也照样知道那儿是什么 | 船长 2026-09-13「到达后才能知道确切信息」 |
| 前往 | **不额外确认**：已扫描（只是被蒙住）≠ 未扫描，不弹"前往未知地点" | 与 `unknown-target` 判据同源 |
| 拒绝口径 | **既没新格可揭、也没云可驱散** ⇒ 扫描被拒且**不扣回合**（旧口径不破） | 既有 |
| 提示 | 第一次下到层 4：一次性事件（心跳弹）+ 通讯一封（`msg-wormhole-nebula`）；**跨趟只一次**（`nebulaHintShown` 随档） | 船长 ③⑤ |

**通讯那封刻意不给 `hint`**：`CommsHint.page` 只认导航直系页（`CommsJumpPage`），而星云发生在
**虫洞面板**里（不是一级页）⇒ 硬塞一个 `map` 会把玩家带去错误的地方，说明文字都写在正文里。

| 配置 | 稀有残骸件/趟（改造前 → 后） | 船损/趟 | 到手 ISK/趟 | 回合余量 |
|---|---|---|---|---|
| 4×长尾鲨 · **单层** · 安全(0.7) | 2.00 → **2.15** | **0.00** | 582,902 | 11.8 |
| 4×长尾鲨 · 2 层 · 安全(0.7) | 2.20 → **2.35** | 0.05 | 676,387 | 8.7 |
| 4×长尾鲨 · 3 层 · 安全(0.7) | 2.20 → **2.35** | 0.05 | 676,387 | 8.7 |
| 4×长尾鲨 · 3 层 · 激进(0.5) | 2.45 → **2.40** | **0.70** | 821,944 | 2.0 |
| 4×电鳐 · 3 层 · 安全(0.7) | — → **1.90** | 0.35 | 572,431 | — |
| 4×鹦鹉螺 · 5 层 · 激进(0.5) | 2.40 → **2.25** | **1.60** | 784,474 | 12.9 |

**读法（三条）**：

1. **浅层确实抬了**：单层 **2.00 → 2.15 件/趟（+7.5%）且仍是零船损**；2~3 层安全打法 **2.20 → 2.35**；
   而且 2~3 层现在**真能站上第 2 层**（改造前平均卡在 1.4、现在 1.4 但余回合更多）。
2. **深潜仍不划算、差距也没缩小**：3 层激进比单层多拿 **0.25 件/趟**，代价 **0.70 艘船/趟**；
   5 层激进反而**掉到 2.25**（回收率只有 80%——收进去的没带回来），代价 **1.60 艘/趟**。
   ⇒ "遗迹下限"抬的是**浅层拿得到的量**；深潜那道"船损墙"没被这条改动碰到（它属威胁/回合口径）。
3. **资产口径略降**：单层 668,640 → 582,902 ISK/趟（−13%）——因为非空格子里**矿脉占比被摊薄**
   （各信号按权重分的那口池变小了，残骸优先拿走）⇒ **拿一点母矿换了稀有残骸**。
   按船长校正后的口径（**专属产出才是目标、资产收益只是附带**），这正是想要的方向。

⚠ **深潜要成立还缺"威胁 / 回合"那一侧的改动**（本批没动）——见
`wormhole-fleet-optimum-20260913.md` §7 的建议①②。
