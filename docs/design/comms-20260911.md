## 1. 一句话

左侧导航新增**「通讯」**一级页（邮件形图标）：NPC 以**发消息**的形式补充剧情与任务提示，
玩家在此查看**历史通讯记录**；有未查看的消息时，导航图标**闪烁**并挂**未读计数**。

## 2. 船长已定六条（逐条）

| # | 问题 | 裁决 | 落法 |
|---|---|---|---|
| ① | 消息从哪来 | **甲：数据表 + 触发条件** | `packages/data/src/messages.ts` 一张 `COMMS_MESSAGES` 表，每条带 `trigger`；core 每帧廉价判定、条件满足一次即送达（幂等） |
| ② | 与既有 T9 通讯剧本（建站介绍/庆贺）的关系 | **甲：合并（统一到通讯页）** | 剧本**照旧**在抵达时弹通讯器浮层（既有体验不动），同时**镜像进通讯页**成为一条历史消息；通讯页 = 全部 NPC 通信的唯一收件箱 |
| ③ | 消息里带任务怎么做 | **甲：只给提示 + 跳转** | 消息可带 `hint`（一句提示 + 一个跳转目标页）；**不在通讯页里接取/完成任务**，点击提示只是跳到对应页面 |
| ④ | 未读口径 | **甲：逐条已读 + 图标闪烁 + 未读计数** | 未读 = 已送达且未读；点开某条即标已读；导航图标在有未读时**闪烁**（`prefers-reduced-motion` 退化为静态红点）+ 右上角**未读数字徽标** |
| ⑤ | 版式 | **甲：双列，列表内部滚动，一级页不滚** | 左列 = 消息列表（内部滚动），右列 = 正文（通讯器造型）；整页高度 = 主窗口内容区，**整页无滚动条**（约定第六章） |
| ⑥ | 玩家能否回复 | **预留回复选项接口，但本期不启用** | 类型与数据字段（`replies`）与界面分支都留好，开关常量 `COMMS_REPLIES_ENABLED = false`；玩家侧**不出现**任何回复控件（不做空按钮） |

## 3. 数据模型

```ts
/** 触发条件（core 判定；幂等：满足一次即送达，重载/复算不重复送） */
type CommsTrigger =
  | { kind: 'start' }                                  // 开局：首次推进即送达
  | { kind: 'day'; days: number }                      // 游戏内第 N 天（24 小时 = 1 天）
  | { kind: 'explored'; count: number }                // 已探明星系数 ≥ N
  | { kind: 'galaxy'; galaxyId: string }               // 探明指定星系
  | { kind: 'skill'; skillId: string; level: number }  // 某技能达到 N 级
  | { kind: 'isk'; amount: number }                    // 现金 ≥ N
  | { kind: 'siteBuilt'; siteId: string }              // 指定副站建成

interface CommsMessageDef {
  id: string                                  // 稳定 id（已读/送达按 id 记账）
  factionId: string                           // 发件势力（v2：不再写自由文本发件人）
  deptId?: string                             // 发件部门（缺省 = 势力本部，只显示势力名）
  signer?: string                             // 具名联系人（悬停说明，不改发件人写法）
  kind: '剧情' | '提示' | '委托'               // 内容类型（须落在势力/部门白名单里）
  subject: string                             // 主题
  body: readonly string[]                     // 正文（逐段）
  trigger: CommsTrigger
  hint?: { text: string; page: CommsJumpPage; tab?: string }   // 提示 + 跳转（裁决③）
  replies?: readonly CommsReplyDef[]          // 预留（裁决⑥，本期不启用）
}
```

**§3.1 v2：发件方 = 势力 + 部门**（`docs/design/npc-factions-20260911.md`）
- `data/src/commsFactions.ts` 的 `COMMS_FACTIONS`：`id / name / species(恒「章鱼人」) / alignment / tone / glyph / brief / kinds[] / departments[]`；
- **玩家看到的发件人写法不变**，仍是 `势力名 · 部门名`（协会 `深空工业协会 · 航行管制`、打捞队工会 `打捞队工会 · 老陈`）；
  拼装与降级都在 core 的 `resolveCommsSender` 一处（解析不到 → 显示原文 id，不崩）；
- 内容类型走**两级白名单**（势力 `kinds` ⊇ 部门 `kinds`），契约强制；
- 4 份建站剧本挂靠 `dshi · 基建部`（`commsFactionId`/`commsDeptId`/`commsSigner`，均可选；未挂靠回落 `title` 原文）。

剧本合并（裁决②）：`DialogueScriptDef` 增可选 `subject`（已有 4 份剧本就地补一句主题），
剧本送达/播放时记入同一收件箱，正文 = 各发言句（`发件人：内容`）。

## 4. 存档字段（零迁移）

| 字段 | 含义 | 归一化 |
|---|---|---|
| `state.commsDelivered: Record<string, number>` | 消息 id → 送达时的游戏内毫秒 | 只收「id 非空 + 数值 ≥ 0」；缺失 = 从未送达（老档天然如此） |
| `state.commsRead: Record<string, boolean>` | 消息 id → 已读 | 只收 `true`；缺失 = 未读 |

两字段均可选语义：**不写迁移版本**，老档读入后通讯页为空收件箱（除"开局信"会在下一次推进时补送）。

## 5. 界面

- **导航项**：`NAV_ITEMS` 末位新增 `{ key: 'comms', label: '通讯', icon: 'nav-mail' }`；
  图标 = 邮件 SVG 线稿（24×24 / 1.7 描边 / currentColor，与既有导航图标同语言），
  `NAV_TONES['nav-mail']` 取同族新色（青白蓝，与 `nav-items` 金黄、`nav-market` 橙区分）。
- **未读提醒**：`.app-nav-item.is-unread` 上图标走 `app-comms-blink`（**只动 transform/opacity**，约定第十四章），
  `@media (prefers-reduced-motion: reduce)` 下退化为静态红点；徽标复用 `.app-ann-dot` 家族做法，新增 `.app-nav-badge` 显示未读数。
- **双列**：`.app-comms-grid` = 左 `minmax(210px, 290px)` 列表 + 右弹性通讯器；
  列表 `overflow-y: auto`（唯一滚动区），通讯器的**屏幕**自身 `overflow-y: auto`（长文在屏幕内滚）。
- **通讯器造型（v2：机身 + 内嵌屏幕）**：右列通讯器 = **机身式大圆角外框 + 内嵌屏幕圆角框**（双层线），
  两个 `rect` 走 **SVG 线稿** + `vector-effect="non-scaling-stroke"`（任意尺寸描边恒定），
  机身线跟随面板边框色、屏幕线走通讯青白蓝；**禁止 CSS 拼形状**（约定第六章 / 第九章）。
  屏幕内**三层信息**：大标题（右侧内容类型小片）→ 细分隔条（发件人 + 立场小片 + 送达时间）→ 正文；
  屏幕**下方**通栏胶囊「前往」（带 `hint` 的消息才出现）。
- **立场 / 内容类型小片**：复用全仓 `.app-chip` 家族（不另造样式），按发件势力 `tone` 着色（内联 `color`/`border-color`）；
  立场小片的悬停 = 势力 brief + 部门 brief（「这是谁」）。
- **交互**：点列表某条 → 右侧显示正文并**标已读**；标题行右侧「全部标记已读」；
  空收件箱 = 一句占位说明（复用 `app-exp-idle` 家族样式）。
- **不做**（船长对参考图的裁定）：头像、未解锁占位行、扫描线/人字纹/噪点/电量格/旋钮等装饰、任何新增动画。
  v1 的「14 顶点不规则外框」按 v2 换成上面的圆角机身语言（历史做法已作废）。

## 6. 不做的事（边界）

- 不在通讯页里**接取/推进/交付任务**（裁决③：只提示 + 跳转）。
- 不做**玩家回复**（裁决⑥：接口预留、开关关闭）。
- 不做**主动删除/归档**消息（历史记录永久保留；后续若要再加）。
- 不改既有 T9 剧本的弹层行为，也不改建站流程。

## 7. 验收口径

1. 新档推进一次 → 收到「开局信」，导航图标闪烁 + 未读计数 1；
2. 点开即已读、计数递减、全部已读后图标停止闪烁；
3. 触发型消息（探明星系数 / 指定星系 / 技能等级 / 现金 / 副站建成）在条件达成后**恰好送达一次**（重复推进不重复送）；
4. 建站剧本播放后，通讯页能看到同一条历史记录；
5. 存档往返：送达与已读状态原样保留；老档读入不报错、通讯页为空；
6. 一级页整页无滚动条，列表内部可滚（v2 起：屏幕内部也可滚，面板体与整页不滚）；
7. `content:check`「通讯消息契约」全绿（id 唯一、触发器字段可解析、跳转目标页合法、引用星系/站点 id 存在）。
