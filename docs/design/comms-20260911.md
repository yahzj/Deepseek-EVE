## 1. 一句话

左侧导航新增**「通讯」**一级页（邮件形图标）：NPC 以**发消息**的形式补充剧情与任务提示，
玩家在此查看**历史通讯记录**；有未查看的消息时，导航图标**闪烁**并挂**未读计数**。

## 3. 数据模型

```ts
/** 触发条件（core 判定；幂等：满足一次即送达，重载/复算不重复送） */
type CommsTrigger =
  | { kind: 'start' }                                  // 开局：首次推进即送达
  | { kind: 'day'; days: number }                      // 游戏内第 N 天（24 小时 = 1 天）
  | { kind: 'explored'; count: number }                // 已探明星系数 ≥ N
  | { kind: 'galaxy'; galaxyId: string }               // 探明指定星系
  | { kind: 'skill'; skillId: string; level: number }  // 某技能达到 N 级
  | { kind: 'isk'; amount: number }                    // 现金 ≥ N
  | { kind: 'siteBuilt'; siteId: string }              // 指定副站建成

interface CommsMessageDef {
  id: string                                  // 稳定 id（已读/送达按 id 记账）
  factionId: string                           // 发件势力（v2：不再写自由文本发件人）
  deptId?: string                             // 发件部门（缺省 = 势力本部，只显示势力名）
  signer?: string                             // 具名联系人（悬停说明，不改发件人写法）
  kind: '剧情' | '提示' | '委托'               // 内容类型（须落在势力/部门白名单里）
  subject: string                             // 主题
  body: readonly string[]                     // 正文（逐段）
  trigger: CommsTrigger
  hint?: { text: string; page: CommsJumpPage; tab?: string }   // 提示 + 跳转（裁决③）
  replies?: readonly CommsReplyDef[]          // 预留（裁决⑥，本期不启用）
}
```

## 4. 存档字段（零迁移）

| 字段 | 含义 | 归一化 |
|---|---|---|
| `state.commsDelivered: Record<string, number>` | 消息 id → 送达时的游戏内毫秒 | 只收「id 非空 + 数值 ≥ 0」；缺失 = 从未送达（老档天然如此） |

  `@media (prefers-reduced-motion: reduce)` 下退化为静态红点；徽标复用 `.app-ann-dot` 家族做法，新增 `.app-nav-badge` 显示未读数。
- **双列**：`.app-comms-grid` = 左 `minmax(210px, 290px)` 列表 + 右弹性通讯器；
  列表 `overflow-y: auto`（唯一滚动区），通讯器的**屏幕**自身 `overflow-y: auto`（长文在屏幕内滚）。
- **通讯器造型（v2：机身 + 内嵌屏幕）**：右列通讯器 = **机身式大圆角外框 + 内嵌屏幕圆角框**（双层线）；
  **机身**由 SVG 线稿画（`rect` + `vector-effect="non-scaling-stroke"`，描边恒定，跟随面板边框色），
  **内嵌屏幕的圆角框由屏幕容器自己画**（`.app-comms-screen` 的 `border-radius` + CSS `outline` 线段描边，
  只描边不改盒形，**不是 CSS 拼形状**）——这样"文字容器"与"圆角框"是同一圈，**窗口任意尺寸都不会错位**；
  **禁止 CSS 拼形状**（约定第六章 / 第九章）。
  屏幕内**三层信息**：大标题（右侧内容类型小片）→ 细分隔条（发件人 + 立场小片 + 送达时间）→ 正文；
  屏幕**下方**通栏胶囊「前往」（带 `hint` 的消息才出现，钉在机身下檐口，不参与屏幕的弹性布局）。
  > **几何口径（2026-09-11 船长实测反馈后定）**：机身内工作区 = 上 15 / 侧 19 / 下 54（机身檐口 15 +
  > 按钮与屏幕间距 8 + 按钮 31）；屏幕内缩因此**与窗口高度无关**。此前内框画在 SVG 里按百分比拉伸、
  > 屏幕容器内边距却是固定值 ⇒ 机身 900px 高时内框在 39px 处、屏幕框整圈落在框外（文字看着在框外）。
- **立场 / 内容类型小片**：复用全仓 `.app-chip` 家族（不另造样式），按发件势力 `tone` 着色（内联 `color`/`border-color`）；
  立场小片的悬停 = 势力 brief + 部门 brief（「这是谁」）。
- **交互**：点列表某条 → 右侧显示正文并**标已读**；标题行右侧「全部标记已读」；
  空收件箱 = 一句占位说明（复用 `app-exp-idle` 家族样式）。
- **不做**（船长对参考图的裁定）：**人像照片式头像**、未解锁占位行、扫描线/人字纹/噪点/电量格/旋钮等装饰、任何新增动画。
  v1 的「14 顶点不规则外框」按 v2 换成上面的圆角机身语言（历史做法已作废）。
  > 2026-09-11 船长追加：**左上角要有章鱼头 SVG**（代表官方章鱼人）——这是**势力代表符号**，与上一条禁的"人像头像"不冲突。

## 6. 不做的事（边界）

- 不在通讯页里**接取/推进/交付任务**（裁决③：只提示 + 跳转）。
- 不做**玩家回复**（裁决⑥：接口预留、开关关闭）。
- 不做**主动删除/归档**消息（历史记录永久保留；后续若要再加）。
- 不改既有 T9 剧本的弹层行为，也不改建站流程。

## 7. 验收口径

1. 新档推进一次 → 收到「开局信」，导航图标闪烁 + 未读计数 1；
2. 点开即已读、计数递减、全部已读后图标停止闪烁；
3. 触发型消息（探明星系数 / 指定星系 / 技能等级 / 现金 / 副站建成）在条件达成后**恰好送达一次**（重复推进不重复送）；
4. 建站剧本播放后，通讯页能看到同一条历史记录；
5. 存档往返：送达与已读状态原样保留；老档读入不报错、通讯页为空；
6. 一级页整页无滚动条，列表内部可滚（v2 起：屏幕内部也可滚，面板体与整页不滚）；
7. `content:check`「通讯消息契约」全绿（id 唯一、触发器字段可解析、跳转目标页合法、引用星系/站点 id 存在）。

## 9. 收尾修正（2026-09-11，船长实测反馈）

**反馈**：「中间消息窗口，文字所处的容器大小位置不对，未处于圆角方框内」。

**根因（实测取数）**：内嵌屏幕的框原来画在 SVG 里（第二个 `rect`，`preserveAspectRatio="none"` 按百分比拉伸），
而屏幕容器的内边距是固定像素 ⇒ 机身一变高，两者就错位：**机身 900px 高时内框在 39px 处、屏幕容器从 20px 起，
屏幕框整圈落在内框外面**（顶部差 19px、底部差 21px），文字因此看着不在圆角框里。

**改法**：**内嵌屏幕的框改由屏幕容器自己画**——去掉 SVG 的内框 `rect`，屏幕容器用 `border-radius: 10px`
（CSS 圆角，`outline` 只描边不改盒形，**不算 CSS 拼形状**）；机身仍由 SVG 画（非缩放描边、跟随面板边框色）。
机身内工作区内边距改为**上 15 / 侧 19 / 下 54**（下 = 檐口 15 + 与按钮间距 8 + 胶囊按钮 31，让屏幕上下居中），
通栏「前往」改为 **`position: absolute` 钉在机身下檐口**（左右比屏幕各内收 8px），不再参与屏幕的弹性布局。

**核验（无头 Chrome，三个真实视口高度 560 / 722 / 900 / 1000 各测一遍）**：
- 屏幕相对机身内缩**恒定** = 上 15 / 下 54 / 左 19 / 右 19（**与窗口高度无关**，即"错位"根因消除）；
- 机身 900px 下：正文段落、标题、分隔条、两枚小片 **7/7 全部落在屏幕框内**（`outsideCount=0`）；
- 「前往」按钮始终在机身内、且在屏幕下沿之外；
- 机身与整页均不滚，只有屏幕自身滚（`deviceScrollable=false` / `screenScrollable=false`）；
- 极端矮窗（560px 高，屏幕被压到 53px）下内容整体在屏幕内滚动，属于既有的二级窗滚动口径，非描边错位。

## 10. 大窗口（全屏）观感优化（2026-09-11 船长：「全屏这类大窗口模式下，消息界面显得很空，有无办法优化」→ 裁定「在丙的基础上，让下方跳转在全屏下更大」）

**实测依据**（2560×1440 全屏，内容区 1963×1002）：屏幕可视高 933px 而内容仅 **167px**（填充率 **17.9%**，空出 767px）；
屏内正文行长只占屏幕宽 **31.4%**（500 / 1591px）；左列 290px 内 8 条共 443px（列表底也空 559px）。
⇒ "空"的成因 = **框大内容小**（设备框拉满整宽整高，而文字短、字号固定 12.5px）。

**处方（船长定 = 丙：大窗口放大字号 + 下方跳转更大；不限宽、不改双列比例）**
- 断点 `min-width: 1500px`：屏内正文 12.5 → 14.5px、大标题 15 → 18px、发件人 12 → 13.5px、送达时间 11 → 12.5px、
  页头说明 13.5px；左列条目内边距与发件人/主题字号同步放大；屏内边距 18/24/20、段间距 10；
  **「前往」胶囊**：内边距 7/18 → **11/26**、字号 13 → **15px**（提示文字 13.5px）、左右内缩 27 → 31px、底部仍钉在檐口 15px；
- 断点 `min-width: 1900px` 再跳一档：正文 → 16px、标题 → 20px、胶囊内边距 **14/32**、字号 **16px**（提示文字 15px）；
- **机身下檐口同步抬高**（54 → 80 → 90px），否则按钮变高会顶进屏幕框（屏幕内缩是固定值）。
- 字号一律走 `calc(var(--ui-fs, 1) * Npx)`，与"设置 → 字体大小"**叠加而不互相覆盖**。

**核验（无头 Chrome，五个窗口尺寸各测一遍）**

| 窗口 | 屏内正文 | 「前往」高 | 屏幕填充率 | 几何 |
|---|---|---|---|---|
| 1280×800 | 12.5px | 33px | 84.1% | 内缩 15/72/19/19，无重叠、无滚动 |
| 1600×900 | 14.5px | 44px | 68.9% | 内缩 15/80/19/19，无重叠 |
| 1920×1080 | 16px | **51px** | 44.6% | 内缩 15/90/19/19，无重叠 |
| 2560×1440（全屏） | 16px | **51px** | 23.6%（原 17.9%） | 按钮左右内缩 31px、距底 15px；机身/整页/屏幕均不滚 |

### 11.3 顺带修掉的真 BUG：点「开始教程」白屏（React #185）

**现象**：在简报态点「开始教程：采集富凡晶石」后**整棵界面消失**（DOM 里只剩空 `#root`），控制台报
`Minified React error #185`（Maximum update depth exceeded）。

**根因**（二分 + 产物插桩定位）：`panels/ActivityBar.tsx` 里有一处**渲染期派生状态**写法——
`if (retreatAsk && !playerItems.some(i => i.stop === 'retreat-battle')) setRetreatAsk(false)`。
React 只允许"该组件自己触发、且立即收敛"的渲染期更新；**撤退活动消失时该条件恒真**，于是**每次渲染都调一次
setState**，生产版在同一次提交里累积到阈值（50）就把整棵树卸载。步骤 0.5 → 1 的切换刚好给它多凑了几次渲染。

**修法**：搬到 effect（`useEffect(() => { if (retreatAsk && !hasRetreatActivity) setRetreatAsk(false) }, [...])`）——
**提交后清理**，语义相同、不参与渲染；`hasRetreatActivity` 同时抽成变量供两处复用。

**为什么之前没被发现**：老流程 `step 0 → 1` 由玩家操作（点「醒来」、等待演出）驱动，单次渲染里凑不满阈值；
新流程把切换压缩到一次点击里，才把它逼出来。

## 15. 教程跳转两处修正（2026-09-11 船长实测反馈）

**① 步骤 2/7 跳任务中心不切内层标签**（船长原话：「步骤2/7，跳转任务中心时，不会切到指定标签页」）
- 根因：星图「任务中心」是**两级标签**——外层 `MapTab 'task'` + 内层 `TaskTabKey`（重要任务/资源任务/快递任务/赏金任务），
  而内层标签**会记住玩家上次的选择**（`localStorage['whale-idle:task-tab']`）。原来跳转只带外层 `mapTab`，
  内层停在玩家上次看的那一页，交付要在「重要任务」里办却落到了别处。
- 落法（沿用既有"请求 + 序号"套路，同 `mapGoto` / `commsFocus`）：
  `TutorialStepDef.taskTab`（步骤 2 = `important`）→ 通讯 `hint.taskTab`（契约：只有 page=map 且 tab=task 才允许，
  键白名单 four 档）→ `CommsPage.onGoto(..., taskTab)` / 顶部引导条 `GuideGo.taskTab` → App `taskFocus{tab,seq}`
  → `MapPage` 透传 → `TaskPanel.focusTab`（seq 变化即切标签并写回 localStorage）。步骤切换（含读档归位）也会自动带上。
- 其他步骤无需内层标签：步骤 3 的物品页内层标签**不持久化**（每次进页都回「仓库」），故不存在同类问题。

**② 步骤 7/7 先指引选副船**（船长原话：「步骤7/7建议先指引玩家选择副船（高亮对应下拉框）」）
- 根因：光圈只扫 `button`（`lastVisibleMatch`），而「AI 指挥中心」的第一个必填项是**下拉框**（舰船），扫不到 ⇒ 光圈直接指「指派任务」，
  玩家没选船就点，指派会被拒。
- 落法：`StepPlan.selectFirst`（步骤内元素级焦点）——步骤 7 挂 `aiAssignShipSelect()`：舰船下拉框（`select[data-ai-ship]`，
  ShipPage 加的识别钩子、不涉样式）**还没选船时**返回它并显示气泡「点这里：选择空闲舰船」；选好副船后返回 null，
  光圈自动回落到本步关键字（「指派任务」）。与既有"步骤内分阶段"（S1 先切沙猫 → 再出击）同一设计语言。
- 文案同步：步骤 7 正文拆成 01 进 AI 指挥中心 / 02 **先在指派表单第一个下拉框选中副船** / 03 装基础 AI 核心 / 04 任务类型选「副船 · 采矿任务」并点「指派」。

**核验（无头 Chrome + 步骤存档 + 外部探针，1600×900）**
- 步骤 2：先把 `whale-idle:task-tab` 预置成 `resource`（模拟玩家上次的选择），点引导条「前往任务中心」后读数 =
  外层 `任务中心` ✓、内层 `重要任务` ✓、localStorage 回写 `important` ✓。
- 步骤 7：光圈读数 `ringOnSelect=true`（内容盒 = 下拉框 ±4px，与既有光圈画法一致）、气泡「点这里：选择空闲舰船」；
  选中沙猫后 `ringOnAssign=true`、气泡「点这里：指派任务」✓。

## 16. 机身下檐口：动作按钮常驻（2026-09-11 船长定「乙」）

### 17.2 两条新触发器：都不写死"哪几个星系"
