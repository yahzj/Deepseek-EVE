# 组装机「循环制造」上移到卡片级（2026-09-10 船长定；状态：**已确认并实现**）

> 船长原话：「发现你指出的问题点了，确实哪怕正常宽屏幕也会，那么进度条不做更改。开关和数量
> 单独领出来，改为针对当前生产卡片。对所有在该卡片工作的 AI 都生效。数量为所有 AI 合计。」
>
> 前情：船长先提出「屏幕过窄且开启循环制造时，组装机不显示进度条腾位置」；三号实测后回报
> ——组装机卡的线行宽度由网格 `minmax(240px, 1fr)` 决定，**基本恒定在 240~300px**（窗口越宽列越多、
> 卡片反而更窄），所以"挤"与屏幕宽窄并不对应，**隐藏进度条治不了本**。船长据此改为本方案。

## 一、结论（改了什么）

「循环制造」的**开关**、**目标件数**、**本轮已产合计**三件从**逐条制造线**上移到**整张生产卡**
（= 一个蓝图）：

| 项 | 旧（2026-09-09） | 新（2026-09-10） |
|---|---|---|
| 开关位置 | 每条线行内一个滑动开关 | **卡片一行一个**（名册上方独立控制条） |
| 作用范围 | 仅该条线 | **该卡全部制造线**（含主控亲自那条）；打开后新开的线自动继承 |
| 目标件数 | 每条线各自一个目标 | **全卡合计**一个目标 |
| 已产计数 | 每条线各自累计 | **全卡合计**（本轮） |
| 存储 | `manufacturingRuns[].autoRepeat/repeatGoal/produced` | `state.manufacturingLoops[blueprintId]`（逐线字段停用，仅读老档时归并） |

## 二、口径（船长逐条批复，全部取推荐项）

1. **作用范围**：该卡全部制造线都吃这张卡的开关，**含主控亲自那条**（同一张卡只有一个开关，
   行为可预期；主控线的产出也计入合计）。
2. **合计起点**：每次把开关**从关到开**，合计从 0 重新计（= 开一批新循环）；开关本来开着时
   只更新目标件数，**不动**已累计的合计（改数字不该把进度重置）。
3. **停线后开关**：达成目标 / 材料不足导致停线 → **自动关闭开关**，并在卡片上标明停因
   （如「已停线：已达成目标 20 件」），避免"全停但开关还亮着"的误读。
4. **多线超产**：刚好达成目标时，**正在跑的那几件跑完再停**（不砍已扣料的在跑件）——
   最多超产 = 同时在跑线数 − 1（目标 20 件、3 线并行 → 实际停在第 21~22 件）。
5. **控制条位置**：卡片内「运转名册」**上方单独一行**（就是原先逐线开关所在的区域，
   只把"每行一个"改成"整卡一个"）；腾出来的行宽正好还给了名册。
6. **老档归并**：同一卡多线目标不一致时——`on` = 任一为真、`produced` = 各线之和、
   `goal` = 各线目标之和，但**只要有任一条线是「无目标」→ 卡片也无目标**（跑到材料不足）。

## 三、引擎实现（`packages/core/src/manufacturing.ts`）

- **字段**：`state.manufacturingLoops: Record<string, ManufacturingLoopState>`，值为
  `{ on, goal?, produced?, stopWhy? }`（`state.ts` 的 `GameStateV24` 追加，兼容字段、**无版本号变化**）。
- **判定**：`advanceManufacturing` 每条线在推进时**实时读**该卡配置（`loopRefOf`），
  不往线上写副本 → 「新线自动继承」「同卡各线同一开关」天然成立。
- **计数**：`loop.produced` 只在**开关打开期间**逐件累加（含首件）；达成目标的那一件计入
  （合计 = 目标数 = 停线依据），随后收尾的在跑件**不再计入**（故卡片显示的数字与目标一致）。
- **停线**：带停因（达成目标 / 材料不足 / 数据缺失）且开关开着 → `on = false`、`stopWhy = 停因`，
  写**一条卡片级汇总日志**（`循环制造停止：<产物>（本卡合计 N 件）——<停因>；本卡其余 M 条线
  跑完当前件即停；AI 核心已归还核心库`）。同 tick 内同卡多条线一起到点时**只结一次账**
  （后面的线读到 `on = false` 即自然收尾，不重复记日志）。
- **命令**：`setManufacturingLoop(state, blueprintId, on, goal)`（原签名是线号，已改为蓝图 id；
  桌面引擎 `GameEngine.setManufacturingLoopAt(blueprintId, on, goal)`）。
- **视图**：`manufacturingLoopOf(state, blueprintId) → { on, goal, produced, stopWhy }`（界面统一入口）；
  `ManufacturingView` 的 `autoRepeat/repeatGoal/produced` 改名为
  `loopOn/loopGoal/loopProduced`（语义 = 该卡，不再是"本线"）。

## 四、存档与兼容（`save.ts`）

- 新档：`manufacturingLoops` 直接读写；空记录（开关关、无目标、无合计、无停因）不留档。
- 老档：逐线 `autoRepeat/repeatGoal/produced` 读入时按第二节第 6 条**一次性归并**进卡片配置，
  归并后逐线字段**不再写回**（`manufacturingRuns` 里这三位彻底退场）。
- 同档若已带新字段（`manufacturingLoops`）则以**新字段优先**，不与老字段重复计数。

## 五、界面

- **工业页 · 组装机**（`panels/Industry.tsx` 的 `BlueprintCard`）：名册上方新增卡片级控制条
  `.app-belt-loop`（虚线描边同族、`min-height: 24px` 固定行高防跳动）——
  `循环制造` 滑动开关（沿用 `.app-toggle`）+ 打开后显示 `目标 [__] 件（全卡合计）` +
  `已产 N 件` + 停因 + 右侧说明「作用于本卡全部制造线（当前 N 条）」。
  逐线行内原有的「循环开关 + 目标 + 已产」**全部移除** → 行内只剩「劳动者 + 剩余约 + **进度条** +
  取消」（**进度条一行未改**，本轮不隐藏）。
- **舰船页 · AI 指挥中心**（`pages/ShipPage.tsx`）：组装机行文案由「连续生产（目标 N 件）」
  改为「循环制造 · 本卡合计 12/20 件（或 12 件）」，与卡片同口径。
- **精炼炉 / 回收炉卡不动**（本就没有循环开关，一直是循环运转）。

## 六、已知取舍（都在上面逐条确认过）

- 允许**超产**（最多 = 同时在跑线数 − 1），换取"不砍已扣料的在跑件"。
- 超产的那几件**不计入卡片合计**：合计 = 停线依据 = 目标数时正好相等，玩家不会看到
  "已产 22 / 目标 20"这种矛盾数字；日志里会写清其余线收尾。
- 手动关开关**不写停因**（属玩家主动收手，不是自动停线），卡片也不显示"已停线"。
- 开关可以**先开、后开线**（预制循环）：卡片无需正在生产；这是卡片级带来的自然能力。
- 「循环制造」的数值**零改动**：材料、耗时、折扣、AI 效率、核心占用一概不变，只改
  "谁控制续做 + 计数口径"。
