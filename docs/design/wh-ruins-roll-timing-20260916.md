## 一、原话与三答（照抄）

1. 船长先问：「**货柜也是迹格的最后一堆被打捞完那一刻掷一次吗**」（答：是，与 AI 核心同一拍）。
2. 船长裁定：「**时间点改为遗迹第一次打捞**」。
3. 三问三答：**范围 = 甲**（遗迹安全货柜 **＋ AI 核心**一起提前）· **发货 = 甲**（掷中**即发货**）·
   **惊扰守卫 = 乙**（**也提前**到第一次打捞）。

## 二、改前 → 改后

| | 改前 | 改后 |
|---|---|---|
| 遗迹安全货柜（70% · 层 2 起） | 该遗迹格**最后一堆**打捞完那一拍掷 | 该遗迹格**第一次打捞**（实际收走 ≥1 堆）那一拍掷 |
| AI 核心（10%） | 同上 | 同上 |
| 惊扰守卫（当场开战） | 同上 | 同上（船长选乙） |
| 残骸堆货柜（0.75%/堆 · 上限 1 件/次） | 每收走一堆掷 | **不动** |

- 三条掷骰**都保持各自独立的盐值流**（不消费 `state.rng`）⇒ 不挤占别的掷点、旧读数不受影响；
- **掷中即发货**：货柜/核心走原「收货阶梯」（货仓 → 临时空间 → 散落该格），守卫当场 `pendingRuinsBattle`
  拦下后续动作（打完才能做别的）；
- **每格只结算一次**：新增 `grid.ruinsRolled`（格键数组 · **随档** · 空数组不写 ⇒ 老档零迁移）；
- **"第一次"以实际收走 ≥1 堆为准**：货仓满到一堆都收不走的那次空动作**不算**，不浪费该格判定。

## 四、影响面与读数

- **收益节奏**：不必清完遗迹格就能拿到 70% / 10% ⇒ 原来"打一半（货仓满/回合不够）白错过判定"的情况消失；
  **"必须清完"的张力消失**（船长已知情并选择甲案）。
- **危险节奏**：惊扰守卫提前 ⇒ 第一次打捞就可能当场开战（船长选乙）。
- ⚠ **旧档/在途档**：老档没有 `ruinsRolled` ⇒ 那些还没首捞过的遗迹格照常"首捞结算"；
  已经打过一半的格子（旧口径下**没结算过**）会在下一次打捞时结算一次——这是改时机的自然结果。
- **读数**：见 §五（`wormhole:econ` 对照；`WORMHOLE_AUTO_MANUAL` 自动探索那条是另一条口径、不受影响）。
