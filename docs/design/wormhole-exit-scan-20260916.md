# 报障：扫描扫不出下一层入口（2026-09-16）

**状态：待船长裁决（甲 / 乙 / 丙）** · 经办：一号 · 工作文档（裁决并落码后归档；未确认不动工）

## 一、船长原话（照抄）

「**发现一个问题，玩家扫描无法直接扫出下一层入口**」

## 二、现状事实（探针实测 · 8 盘样本：4 种子 × 层 1/4）

一次性探针（`tools/_probe-exit-scan.ts`，跑完即删）走真 API，把玩家挪到出口格**邻格**（扫描半径 1）再扫：

| 时刻 | 读数 |
| --- | --- |
| 扫描前 · 前往出口格 | **被拒**：`code=unknown-target`「这个地点还没扫描过：前往未知地点？」 |
| 第 1 次扫描后 | 出口格 **`scanned=true`**（扫出来了）；`revealOf` = `signal(null)`；`exitKnown` 仍 **false** |
| 扫完 · 人还没走过去 | 界面 `isExit=false` ⇒ 那一格显示成 **「没有信号：空信息地点」**（线稿 = 空地，与真·空信息格**无法区分**） |
| 扫描后 · 前往出口格 | **ok（不再要确认）** ⇒ core 已经把它当"已知"，只有**地图标记**没跟上 |

**一句话**：core 认"扫出来了"（前往不再拦），但**地图/看板把它当空地画**——玩家扫过入口位置也认不出那是入口，只能撞上去（站上去才显示「下一层入口」）或读到漂浮信标。

两处结构事实（复核过）：① 出口格**恒为 `empty`**——造盘时它被排除在信号分配外（`others` 过滤），遗迹下限只翻 `graveyard`、谜质下限显式跳过出生格与出口格（`wormholeGrid.ts:853`）；② 出口格的入口标记**吃不到"清空删图标"那条**（`isExit` 的格永远保留图标）。

另有一处**失实注释**：`wormhole.ts:1091` 写「出口格不参与信号分配 ⇒ 它**永远不在 `scanned` 里**」——已被探针证伪（扫到即进 `scanned`）。这句是 2026-09-13 那次改动留下的想当然。

## 三、冲突（§5.2：新提议 vs 既有已确认口径）

**旧口径（逐字 + 出处 + 日期）**

1. `docs/design/wormhole-extraction-endgame-20260912.md:579`（2026-09-13 落码）：**「入口标记的条件从"到达过"放宽为"到达过 or 被信标标出"」**；同表 `:575`「信标信号 ⇒ 到达即读出下一层入口位置，此后地图上一直标着（`grid.exitKnown = true`）」。
2. `packages/core/tests/wormhole-run.test.ts:713`：「默认为假：**入口不标在地图上**」。
3. `tools/wormhole-econ.ts:624`：「`grid.exitKnown === false` 时**不许偷看** `grid.exit`（信标到达才置 true），没读到就继续探索」——工具把"信标＝得知入口"当成设计前提在模拟。

**二者不能同时成立的地方**：现行设计是"**入口靠信标（或撞上去）得知**"，扫描只揭"地点信号/空地"。船长的报障要求"**扫描就能直接扫出入口**"⇒ 入口判据必须把"已扫描"纳进来，信标随之从"唯一途径"降为"不必靠近的捷径"。

## 四、三案（含影响面与取舍）

### 甲案（推荐）：扫到即标「下一层入口」

- **落法（单点 · core）**：`wormholeGridScan` 里，若本次扫描的 `targets` 含出口格 ⇒ `grid.exitKnown = true`（语义与信标同一条："此后地图一直标着"）。**UI 一行不用改**（`Wormhole.tsx:2181` 已读 `exitKnown`）；`exitKnown` 已在 `save.ts` 清洗白名单 ⇒ **零迁移**。
- **信标还留着用**：它是唯一的**远程**途径（不用走到那一带就能知道入口）；只是不再是唯一途径。
- **代价**：入口提前暴露 ⇒ 探索回合压力略降（这本来靠"走遍/撞信标"兜着）；⚠ 必须同步 `tools/wormhole-econ.ts` 的"不许偷看"口径（否则工具读数与游戏分岔）；用例要补/改 3 处（`wormhole-grid.test.ts:194` 补"扫到即 exitKnown"、`wormhole-run.test.ts:713` 限定为"没扫到之前"）。
- 口子定义（我按自然读法先定，若你要改说一声）：**必须扫到出口格本身**（它落在那一圈的扫描半径内）才算，不是"扫任何一格都知道入口"。

### 乙案：保持现状（信标＝唯一途径），只修"地图撒谎"那两处

- 出口格扫出来**不再显示「没有信息地点」**（它是入口、不是空地 ⇒ 现在这句是误导，且空地里混着入口这一档信息价值被稀释）；顺带改正 `wormhole.ts:1091` 的失实注释。
- **代价**：船长的报障原样保留（扫到也认不出入口，仍得靠信标/撞）。

### 丙案：只给提示、不改地图标记

- 扫到出口格时**日志加一句**「这一圈扫到了下一层入口（Qx · Ry）」，地图标记仍等信标/到达。
- **代价**：地图上不标，玩家得自己看坐标；好处：信标"指路"的地位基本保住。
