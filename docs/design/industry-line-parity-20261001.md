## 1. 船长原话（三次，按时间）

1. **报障（本批起因）**：「**实验室的生产是不是没有和其他工业生产使用同一套逻辑？玩家又反应了一些早就修好的BUG（比如材料占用）**」
   → 追问后的指示：「**你应该先查是否使用同一套逻辑**」
2. **裁定**：「**实验室本质上也是一个组装机，建议按照组装机的来。之后所有的新的生产，优先采用组装机的。

3. **二次令（位置）**：「**循环应该和组装机一样是放在顶部的**」

## 2. 结论（一句话）

**不同一套。** 全仓是**三份平行实现**（`industry.ts` 炉子 / `manufacturing.ts` 组装机 / `lab.ts` 实验室）；
实验室当时跟着"炉子"那一套，而**两条既有产线本身也不统一**（取料来源：炉子/实验室＝货仓优先，
制造线＝只吃仓库）⇒ 三套各漏各的，不是"实验室一家跑偏"。船长据此定下**默认族 = 组装机型**（约定 §十七）。

## 4. 关于「材料占用」

- **"起线即预占材料"这一类旧 BUG，实验室没有**（它起线不扣料、每批到点才扣、停线无需退料；
  老口径的痛点是炉子那本"炉内预占账" `claimedUnits`，实验室压根没有这本账）。
- 玩家说的"占用"最可能落在：① **船上货仓的料被优先吃掉**（炉子/实验室＝货仓优先；组装机只吃仓库）
  ② AI 核心占用（同日修的两处）③ 另一件具体现象。**本批按船长裁定把实验室统一到"只吃物品仓库"**，
  ① 这条从此对实验室不再成立。

## 5. 组装机那套的确切语义（改造照它 · 带行号）

| 面 | 现实现（`manufacturing.ts`） |
|---|---|
| 线形态 | **一条线 = 一件产物**；完成即结束（要连续跑 ⇒ 开**循环开关**） |
| 投料时机 | **开工那一刻整批扣**（`spendMaterialsFor`） |
| 取料来源 | **只吃物品仓库**（`removeWare`；`countWare`），**不碰货仓** |
| 等价组 | 组内**按序取够**（`materialGroupIdsOf`），逐笔记账 |
| 退料账 | `spentMaterials`（记**实际扣的那种**，"只记在跑那一件"）⇒ 取消/自动停机**按账退回** |
| 缺料 | 开工前 `missingMaterials` 拒；循环中缺料 ⇒ 线结束 ＋ 标停因 |
| 循环 | 卡片级开关（`manufacturingLoops[id]`）：目标批数 / 缺料 / 关开关 ⇒ 自停，写停因 |
| 一次性图纸 | 开工吃书；取消**退书 ＋ 退名额**；完工不退 |
| 技能 / 核心效率 | `calcBuildDurationMs`（材料学 + 产线节拍 5%/级）· AI 核心 ÷效率 |
| 离线统计 | `advanceManufacturing(…, stats)` ⇒ 件数/造船数/收入进离线简报 |

## 6. ⚠ 实测到的组装机 BUG（**本批已修**）

**现象**：循环线**续做的那几件不扣料**（玩家手上只有「通用黑匣」这类**等价组**材料时）⇒ **白造**。

- **根因**：`advanceManufacturing` 的续做分支直接 `removeWare(state, need.itemId, matNeedCount(…))` ——
  ① **不查等价组** ② **不写 `spentMaterials`** ③ **忽略返回值**；而**开工那一处**是走等价组 ＋ 记账的
  ⇒ 同一张卡两条路两种口径。
- **实测读数**（临时探针：仓库只有通用黑匣 ×5、配方要墨潮黑匣 ×1、循环开）：
  开工后 `通用 4` ✓ → 第 1 件完成并续做后 **`通用 仍 4`**（**第 2 件白造**）→ 取消后 `4 → 5`（退的是首件那笔）。
- **修法**：收成 `spendMaterialsFor`（等价组按组序取够 ＋ 逐笔记**实际扣的那种** ＋ 凑不齐**整体回滚并停线**）；
  并把退料账语义钉成"**只记在跑那一件**"（交付即结清）。
- **用例**：`tests/manufacturing-loop-materials-20261001.test.ts`（3 条，改前必红）。
