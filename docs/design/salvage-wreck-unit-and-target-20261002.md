## 一、船长那条怀疑的答案（先答后修）

**半对** —— 物品层面**不冲突**（探针逐条核过）：

- `corona-drift / split / converge / nexus` → 残骸组 `r-inv` → 物品 **`wreck-r-inv`**（在物品表里 ✓）；
  稀有 `wreck-rare-r-inv`（在表里 ✓）；H 族同构 → 组 `h-hi` → `wreck-h-hi` / `wreck-rare-h-hi` ✓。
- R 族场注入 120 m³ ⇒ 逐轮正常出（77.76 → 27.37 → … 第 5 轮见底）；箱子照出（30 m³ 一件）✓。

**真冲突在"打捞对象那个键"上**：`SalvageOpState.targetGroup` 是老档残留（手选入口 2026-09-26 当天
就被船长撤掉了），若它留着**上一族那套组键**（H 族的 `h-hi`），遇上 R 族残骸 ⇒ **每轮返回"什么都不
产出"**，池子一寸不动（读数 `对象=h-hi · 池 120.00 → 120.00 · pick=null`）；而主控作业与 AI 副船
拿到 `null` 都会**直接终止任务**（日志还说成「敌群情报缺失」，误导）。**这就是"数字不变也打捞不到"**。

## 二、两处缺陷与修法

### ① 不足 1 m³ 的那一轮白捞（主因）

同日更早那批「甲」（入侵池按余额封顶出量）之后，**"一轮不足 1 m³"成了常态**；而入库那一步
`inventory.addItem` 是 `Math.floor` ⇒ 0.6 m³ 的一轮：**池子扣光了、货舱一件没多**：

```
池 0.60 m³ · 货舱里的 wreck-r-inv = 0
第1轮：pick=wreck-r-inv ×0.60 · 池 0.60 → 0.00 · 到手 0 → 0   ← 捞了等于没捞
第2轮：pick=wreck-a-hi ×0.51 · 池 0.00 → 0.00 · 到手 0 → 0   ← 星系残骸同理
```

**修**（船长选甲）：新增单点 **`wreckUnitsOf(volumeM3)`**（`salvaging.ts`，导出）——
**出了量（>0）就至少入舱 1 件**，否则 `floor`；**池子仍按实际出的 m³ 扣**（甲令"标称多少最多就捞
多少"一字未改）。主控作业（`advanceSalvageOp`）与 AI 副船（`ai.ts` 打捞支）**共用它**。
附带修掉 AI 那支的一个小毛病：它原先**直接累加小数**（`cargo[id] += 0.51`）⇒ 货舱里会攒出"0.51 件
残骸"这种读数。

### ② 陈旧的打捞对象把整条路堵死

原口径「手选组已捞干 ⇒ 本轮不出（`return null`，不自动换组）」是**手选时代的语义**，随手选入口被撤
一起作废 ⇒ 现改为与 `startSalvageOp` / `setSalvageTarget` 那句「**给的对象不可用 ⇒ 回落全部**」
**完全一致**：**对象已捞干 / 只剩箱子也没有 ⇒ 就地清掉它、本轮按「全部」出**（自愈，不再空转）。
⚠ 那条闸的**位置仍在"玩家舰船残骸最高优先"那一支之前**（自愈只清字段、不跳支）⇒ 船长 2026-09-26
定的「玩家残骸优先、与任何池的存量无关」一字未改。
