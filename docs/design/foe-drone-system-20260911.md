## 五、A5「机群火力计入总火力」的算法（**必须定死，否则卡面威胁失真**）

**现状口径**（`createFoeSpecsFromShips`）：卡的 `dmgMul` 作用在**舰级单发**上，并按 **多舰船补偿 `2N/(N+1)`**（N = 编成单位数之和）在建档时缩放。

**拟（甲案）**：

1. **总火力式**：`卡的总单发 = dmgMul × [ Σ(母舰单发 × N) + Σ(机群单发 × M) ]`
   —— 机群与母舰**吃同一条 `dmgMul`**（口径与现有一致，不新造第二条链）；
2. **补偿系数 N 只数母舰**（机群**不吃** `2N/(N+1)`）：
   机群本来就是"多而小"的设计意图，再乘补偿等于**双重放大**；且机群单发是**舰级绝对值**，不需要补偿去抵消"多炮口"的问题；
3. **卡上不手改**：挂上机群后，母舰单发**自动按比例让位**（因为总式里多了一项）——
   满足 A5「母舰单发相应让位」，也满足"改一艘船只影响引用它的卡"；
4. **逐卡对账**：`battle-calibrate` 的 CSV 增列"母舰单发 / 机群单发 / 机群火力占比"，验收时逐卡核 `总单发` 与卡面威胁是否仍匹配。

⚠ **待船长点**：机群**是否也吃补偿**（我建议**不吃**，理由如上）。这一条直接决定机群的实际 dps，是**难度旋钮**。

### 五·补、**逐卡「机群／炮台火力占比」**（2026-09-11 船长：「允许调整敌舰的无人机/炮台火力比例。这个要根据每个悬赏卡制定」）

上面 §五 的口径有一个隐含后果：**机群与炮台吃同一条 `dmgMul`** ⇒ 两者只能**同比例**缩放，
**卡上没有任何旋钮**能改它们的**相对占比**（占比实际由「机型 `dmg` ÷ 舰级 `shotDmg`」× 架数隐式决定——
实测两张 E 卡：泰坦残骸勘探机群占 **14.4%**、奥罗武装残骸群 **21.9%**）。

**船长七项裁定**（逐条点选）：

| 项 | 裁定 | 落地 |
|---|---|---|
| 口径 | **守恒拆分**（写"机群占比 s"，**总火力不动**） | 与 A5「母船单发让位」同源 |
| 层级 | **编成条目级**（`FoeShipSlot.droneFireShare`），**缺省回落舰级** | 同卡不同条目可各写各的（"头目炮台为主 + 亲兵全机群"） |
| 基准 | 以「**该条目现口径的实收总单发 T**」为基准，**机群先取、余额给炮台** | 含 `dmgMul`、含多舰补偿、含逐条取整 |
| 边界 | **0~1 闭区间，两侧各保底 1**（机群 ≥1/架、炮台 ≥1/单位） | 不产生 0 伤害条目；`s=1` = 母舰近乎不开火 |
| 显示 | **不显示**（纯内部旋钮） | 卡面/玩家可见零改动 |
| 范围 | 只含「**机群 vs 母舰武器组**」 | 敌侧近防炮照 B3 裁定不动 |
| 数值 | **本批只做机制**，E 族两张卡暂不写（缺省=现状） | 等船长逐卡给值 |

**算法**（`combat.droneFireSplitOf`，逐条目）：
1. `T = N × (炮台旧单发 + Σ机群旧单发)`（`N` = 该条目单位数）；
2. `D = clamp(round(T×s), 架数, max(架数, T−N))`、`G = T − D`；
3. 机群 D 均摊到逐架（**余数补给前面的架次**，Σ = D）；炮台 G 均摊到逐单位（同条目权重相等，Σ = G）；
4. **未写 s 的条目返回 `null` ⇒ 走旧算法**（零行为变化，硬保证）。

**契约**（`content:check`「机群与防空契约」⑥）：取值域 0~1 · 只有"会展开机群"的条目/舰级可写 ·
**守恒实测**（写了比例的卡，其单位武器 Σ 单发必须与"同卡去掉比例"逐字相等）。

**不动**：命中 / 射程 / 装填 / 血型 / 期望交距 / 多舰补偿口径（本旋钮**只**改火力构成）。

### 五·补2、**备用机库（改判 A3）** 与 **单次出击上限（本轮不采用）**（2026-09-12 船长）

船长原话：「**能否限制敌机单次出击数量或者给敌机添加备用机库（损坏后补充敌机）**」→ 追问后定：
「**先都做，但是本轮只采用乙。甲留作后续其他机制。**」（甲 = 限出击数，乙 = 备用机库）

| | 机制 | 落点 | 本轮状态 |
|---|---|---|---|
| **甲** | **单次出击上限**：`maxAloft` = 同时在空最多几架，其余在机库按批次窗口轮换（`cycleMs` 缺省 = 机型装填）；`keepDps: true` ⇒ 在空架次有效装填 ×(k/在场架数) ⇒ **平均 DPS 守恒**（否则按 k/N 降） | `FoeShipDef.droneLaunch` → `UnitSpec.foeDroneLaunch` → `combat.aloftDroneSet` | **机制就位、不启用**（船长「留作后续其他机制」）· `content:check` **禁止任何舰级写**它 |
| **乙** | **备用机库**：`count` 架同机型备用（建档时展开成额外条目、开局 `inHangar`），前线战损 ⇒ 排期一架、`respawnMs` 后**满血**放出；**母舰阵亡则整群停**（含备用机） | `FoeShipDef.droneReserve` → 池条目 `inHangar`/`readyAtMs`/`maxS~maxH` | **已启用**（E 族三条舰级）· ⚠ **与 A3 裁定「打光为止不补充」相反 = 改判**（新裁定优先） |

**为什么是改判**：A3 原文把"打光为止不补充"写进了数据结构与契约（上表 §四 第 1 行）；
本次新裁定优先级更高 ⇒ 该句在 E 族**作废**，但**其它族未写 `droneReserve` ⇒ 行为一字不变**。

**账目口径**（防误读）：备用机条目带 `WeaponSpec.reserve: true` —— 它**不属于常驻齐射**，
而是**库存深度**；所有"总火力/守恒"类核对**一律排除它**，界面也不把在库备用机算作存活架数
（`foeDrones[].hangar` 单列）。E 族实测：常备齐射 **216 / 154 / 672 不变**，
备用库存 **2 / 6 / 3 架**（每舰 +2 · +2 · +3，补位 10s / 10s / 12s）。

## 六·补、单发口径改判（2026-09-12 · 以本条为准）

**船长原话**：「**提高近防炮伤害，且因为其射程更短，威力应该提高**」（选自我给出的方案「丙」）。
**起因**：玩家反馈「近防炮攻击好像偏低了」⇒ 实测取证（真数据真引擎）：旧口径单发 3/5/6、对舰名义 DPS 2.00/3.57/4.62
（仅为同档主炮的 39~44%）；打机群更差——**反应式 + 消费制**（一次敌机齐射只换一炮）使一场只开 3~20 炮，
对 E 族警戒机群（7 架共 644 血）**一架都打不下来**（整场打出 93 伤害 = 14.4%）。
**新口径（本批落码）**：`dmgMult` 0.5/0.8/1.05 → **1.65 / 2.65 / 2.85** ⇒ 单发 **10 / 16 / 17**、
名义 DPS **6.67 / 11.43 / 13.08**（= 同档主炮的 **1.28 / 1.24 / 1.24 倍**），射程、命中、装填、CPU、价格一律未动。
**实测效果**：对同一批卡，近防炮整场对机群伤害约 ×1.85（泰坦 93 → **173**、核心舱段 144 → **265**、蜂群卡 44 → **52**），
E 族核心舱段卡首次能击落 1 架、G 族蜂群卡满分清场（2/2）。

## 六·补2、打机群命中口径改判「丁案」+ 警戒机削血 40%（2026-09-12 · 以本条为准）

**船长原话（两条，同一轮）**：「**按丁修复，近防炮给予一个对无人机伤害加成。**」＋「**将警戒机的血量削弱40%**」。

### ① 丁案：打机群不吃两舰距离衰减（**闪避生效版 · 船长终裁，以本条为准**）

**起因（玩家实测追问）**：「**我方近防炮不是 90 命中率吗**」——装备表写的 `hitRate 0.9` 是**基础命中**，
实战走 `(基础命中 × 火控 × 距离衰减 − 机型闪避) × 索敌件`，而近防炮射程 **2,500m** 短于典型交距
（3,211~5,545m）⇒ 距离衰减**恒落在下限 ×0.5** ⇒ 实收命中只剩 **0.27~0.35**（旧口径逐档读数：
贴脸 0.72 / 1,000m 0.54 / 2,000m 0.36 / ≥2,500m **0.27**）。
这与船长 2026-09-11 的裁定「**打机群不看两舰间距**」自相矛盾——**选靶**早已照办（出击型不受射程限制），
**命中**却还在按两舰间距打折。

**口径沿革（三条 · 别照旧文重开）**：
1. 最初：吃距离衰减 ⇒ 实收 0.27~0.35；
2. 「按丁修复」：**去掉距离、仍减闪避** ⇒ 实收 **0.72（E 警戒机）/ 0.45（G 蜂群机）**；
3. 同日一度改判「无视距离的 90」（连闪避也不减）⇒ 船长随即裁定「**哦 滚回到上一个闪避生效的版本**」
   ⇒ **以第 2 条为准**（本稿即记这一条）。上一版"敌机 `evasion` 对近防炮失效、G 族难打中性格消失"
   的结论**随之作废**：**闪避字段仍然生效**。

**终裁口径**：**打机群命中 = (装备自身命中 × 火控阵列学 − 机型闪避) × 索敌件**——**无视两舰距离、机型闪避照常参与**。
**基础值 vs 实收值务必分开写**（本轮教训：把实收 77% 当裸读数报给船长被纠正）：

| | 基础命中 | 对 E 警戒机（闪避 0.18）实收 | 对 G 蜂群机（闪避 0.45）实收 |
|---|---|---|---|
| 近防炮 MK1/MK2（无技能无配件） | 0.9 | **0.72** | **0.45** |
| 近防炮 MK3 | 0.92 | 0.74 | 0.47 |
| 火控阵列学 5 级（+15%） | 1.035 | **0.855** | 0.585 |
| 再乘索敌阵列 MK2（×1.12） | — | **0.90** | 0.66 |

⚠ **只对机群生效**：**打舰仍走原 `distFactor` + 守方回避**（"近防炮射程短、所以对舰吃亏"不许被顺手抹掉）。
引擎落点 = `combat.droneHitChance`（`hitChance` 的距离衰减覆写为 1、**守方闪避照传**）；用例 = `tests/pd-damage-ladder.test.ts`
「打机群不吃距离衰减」2 例（含"打舰仍吃衰减"的负向对照）。**实测**：单门混装对泰坦巨构的击落 0 → **0.6**、
两门 0.8 → **1.8**、四门 4.4 → **7.2**（配装含索敌件时实战命中 52~72% ⇒ 90%）。

### ② 警戒机三层血削弱 40%（已落码）

盾/甲/结构 **28/20/44 = 92 → 17/12/26 = 55**（×0.6 后逐层取整，合计 −40.2%）；**抗性（甲层动能抗 0.15）与闪避（0.18）一律未动**。
**作废**旧落点「三层共 92（比我方制式战斗机 80 更厚）——'巨构的东西更厚'」：现值**比**我方制式战斗机（80）**更脆**，
警戒机靠"数量 + 备用机库"站住。契约 = `content:check`「机群与防空契约」⑤g（E 族机型三层血 = 55）。
**影响面**：只改"能不能打掉机群"，**不改常规难度**——标准复核四行（A0~A3，不带防空武器、打不到机群）
逐格读数**完全相同**；机群池血随之下调（泰坦卡 14 架 **1,288 → 770**、奥罗 2,760 → **1,650**、核心 1,840 → **1,100**）。

### ③ 近防炮「防空」属性 = **×2**（已落码 · 船长 2026-09-12：「**那伤害倍率按2倍算**」＋「**给近防炮系列添加一个属性"防空"，将近防炮的对无人机伤害 ×2 写到防空属性里**」）

**落法（两版合并成一条属性）**：装备表字段 `ModuleDef.antiDrone`（**值 = 对无人机伤害倍率**）——
**一条属性两个含义**：①**能筛到敌方机群**；②**对无人机伤害 ×该值**。
原 `canHitDrones: true`（布尔）与 `antiDroneDmgMul`（倍率）**两个字段已并入本字段**（三档都是 **2**）。
建档时带进 `WeaponSpec`（`canHitDrones: true` + `antiDroneMul: 该值`），在玩家开火链的**"打机群"分支**上乘

（装配页 / 装备库 / 货舱 / 市场 / 手册图鉴同一数据源 `moduleInfoLines`）。
契约 = `content:check`「机群与防空契约」①②（射程 ≤ 2,500m · 防空值须为正且**现值 = 2**）；
用例 = `pd-damage-ladder.test.ts`（装备表 + 武器条目）+ `foe-drone.test.ts`（**引擎真的乘了**：

在玩家开火链的**"打机群"分支**上乘（`droneHit` 非空才乘）——**对舰伤害一字不动**。
契约 = `content:check`「机群与防空契约」⑤f（防空属性取值须为正、现值 = 2）；
用例 = `pd-damage-ladder.test.ts`（装备表 + 武器条目）+ `foe-drone.test.ts`（**引擎真的乘了**：

## 九、契约与护栏（`content:check` 拟新增）

1. **防空武器必须短射程**：带 `canHitDrones` 的武器射程上限须 **≤ 阈值**（拟 2,000m）——防止防空属性被当成"万能增伤"；
2. **敌机只能登记在舰级上**：`drones` 只存在于 `FOE_SHIPS` 的舰级行；引用它的卡必须走舰级路径；
3. **机群机型必须在本族机型表内**（`family` 一致），且 `role` 必须落在 `DroneClass` 四型内（A2）；
4. **A5 守恒**：卡的 `总单发`（母舰 ×N + 机群 ×M，同一条 `dmgMul`）在工具里可核、逐卡对账；
5. **敌侧近防炮**（B3/C1，**2026-09-12 已按船长八条裁决改版，见 §十二**）：原口径"`pdThreatFloor` / `pdCd` / `pdDmg` 一律不改"**仅适用于本批（S1~S4）**；改版后**玩家侧仍 = 真武器**（占槽、可打机群也可打舰）· **敌侧仍 = 抽象自动系统**（每舰一台、不看距离、**不参与对玩家的常规攻击**，故**不能打舰**）——**这组"两侧形态差异"没有变**，变的只是敌侧的命中/伤害/选靶规则。

## 十二、敌侧近防炮 · 2026-09-12 改版（船长八条裁决 · **以本节为准**）

> **船长原话**：「**敌人防空火力受舰船级别影响。越大的舰船防空火力越强。改为集火制度。优先攻击哨戒和攻坚无人机，
> 给攻坚无人机添加 25% 全抗性。侦查和普通战机相同权重抽取。允许命中下限 10%。基础命中率提高到 70%**」
> ＋ 追加口径「**优先攻击哨戒机的前提是哨戒在射程内**」。
> **动因（P-41 标定轮读数）**：改前三张代表卡 **机群战损 0 架 · 战损估值 0 ISK · 占奖励 0.0%** ⇒ 近防炮**没有牙**。

### 12.1 现行规则（八条落点）

| # | 规则 | 落点 |
|---|---|---|
| ① | **命中 = `clamp(pdHitFloor 0.10, 1, pdAcc 0.7 − 机型闪避)`**（原 0.5、无下限 ⇒ 专属机闪避 0.55 **曾永久免疫**，已修） | `balance.pdAcc` / `pdHitFloor` |
| ② | **伤害 = `pdDmg 5 × 舰种档系数`**，`pdTierMul = [1.0 / 1.5 / 2.0 / 3.0 / 4.0]`（T1…T5，**越大的船防空越强**） | `balance.pdTierMul`；单位档位 = 新增的 `UnitSpec.hullClassTier`（敌侧由编成条目所引舰级写入） |
| ③ | **集火制度**：锁定一架**直到击落才换靶**（原口径每拍随机换靶 ⇒ 伤害摊薄到整群、几乎打不掉） | `BattleState.pdFocus`（可选字段，**零迁移**） |
| ④ | **选靶优先级：哨戒机 → 攻坚机 → 其余等权**（侦察机与战斗机**同权**） | `PD_PRIORITY_BY_ART` / `pdPriorityOf` |
| ⑤ | ⚠ **哨戒机优先的前提 = 它在近防炮射程内**（`PD_SENTRY_RANGE_M` 2,500m）：不在射程 ⇒ **不入选、不占优先级**，优先级落到「攻坚机 → 其余」，**集火锁同步解除** | `aliveDroneIndices` 的 `if (!sentriesInRange) return others` |
| ⑥ | 攻坚机 **25% 全抗性**（三层 × 三系全 0.25；取代原"甲抗爆炸 0.15 / 结构抗动能 0.05"） | `data/items.ts` `drone-heavy` |
| ⑦ | **判定频率 500ms 保留**（船长问「不是改成反击型了吗」⇒ 答：**反击制只管"能不能开火"，频率管"开火后多久掷一次命中"** = **还手速率上限 2 次/秒** ＋ 大步长（离线/快进）补算上限；实测令牌速率 ≈0.23 次/秒 ≪ 上限 ⇒ **当前不是瓶颈**） | `balance.pdJudgementMs` |

### 12.2 同批修掉的一处真 bug（开火许可 AND → OR）

旧 `resolvePointDefense` 拿到"出击型打一次换一次"的反击令牌后，**又要求"哨戒机在 2,500m 射程内"才放行**
（`if (!sentryInRange) return`）⇒ 两条开火许可被 **AND** 卡在一起，等于把出击型那条路**整条掐死**
（**出击型机群永远不会被反击**，与船长 2026-09-11「出击型：攻击一次换一次**无视射程**的反击」直接矛盾）——
这也是"实测 0 战损"的一半原因。**现改为两条独立许可（OR）**：
a) **反击令牌**（我方无人机打过敌舰 ⇒ 窗口内还手，**无视距离**）；b) **哨戒机在射程内**（不需令牌）。
