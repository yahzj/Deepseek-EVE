## 五、A5「机群火力计入总火力」的算法（**必须定死，否则卡面威胁失真**）

**现状口径**（`createFoeSpecsFromShips`）：卡的 `dmgMul` 作用在**舰级单发**上，并按 **多舰船补偿 `2N/(N+1)`**（N = 编成单位数之和）在建档时缩放。

**拟（甲案）**：

1. **总火力式**：`卡的总单发 = dmgMul × [ Σ(母舰单发 × N) + Σ(机群单发 × M) ]`
   —— 机群与母舰**吃同一条 `dmgMul`**（口径与现有一致，不新造第二条链）；
2. **补偿系数 N 只数母舰**（机群**不吃** `2N/(N+1)`）：
   机群本来就是"多而小"的设计意图，再乘补偿等于**双重放大**；且机群单发是**舰级绝对值**，不需要补偿去抵消"多炮口"的问题；
3. **卡上不手改**：挂上机群后，母舰单发**自动按比例让位**（因为总式里多了一项）——
   满足 A5「母舰单发相应让位」，也满足"改一艘船只影响引用它的卡"；
4. **逐卡对账**：`battle-calibrate` 的 CSV 增列"母舰单发 / 机群单发 / 机群火力占比"，验收时逐卡核 `总单发` 与卡面威胁是否仍匹配。

⚠ **待船长点**：机群**是否也吃补偿**（我建议**不吃**，理由如上）。这一条直接决定机群的实际 dps，是**难度旋钮**。

## 九、契约与护栏（`content:check` 拟新增）

1. **防空武器必须短射程**：带 `canHitDrones` 的武器射程上限须 **≤ 阈值**（拟 2,000m）——防止防空属性被当成"万能增伤"；
2. **敌机只能登记在舰级上**：`drones` 只存在于 `FOE_SHIPS` 的舰级行；引用它的卡必须走舰级路径；
3. **机群机型必须在本族机型表内**（`family` 一致），且 `role` 必须落在 `DroneClass` 四型内（A2）；
4. **A5 守恒**：卡的 `总单发`（母舰 ×N + 机群 ×M，同一条 `dmgMul`）在工具里可核、逐卡对账；
5. **敌侧近防炮不动**（B3/C1）：现有 `pdThreatFloor` / `pdCd` / `pdDmg` 一律不改，只在注释里并列登记"两套反无人机手段"的口径差异——**玩家侧 = 真武器**（占槽、可打机群也可打舰）· **敌侧 = 抽象自动系统**（每舰一台、不看距离、**不参与对玩家的常规攻击**，故**不能打舰**）。
