# 手机模式 · 虫洞探索界面全屏两栏 ＋ 货仓触摸拖拽（工作文档）

- **状态：进行中**（2026-10-02 开工，船长已四问四答确认方案，实现与闸门待跑）
- 经办：三号（worktree `Deepseek-EVE-verify`，分支 `verify`）
- 归档时：关键结论并入 `docs/roadmap.md` 一条精简条目后删除本文件（§8 文档纪律）

## 1. 船长原话（照抄）

> 「手机模式下，虫洞探索的界面有问题，探索地图下方的操作界面过于狭窄，导致无法进行操作，货仓背包无法对背包内的物品进行拖动等行为。建议操作手机模式下，虫洞探索界面放大到全屏，操作界面挪到右侧。」

## 2. 现状读数与两个独立缺陷（动手前实测）

手机竖屏经 JS 旋转成 **1200×554 的逻辑空间**（`--mob-w: 1200px` / `--mob-h` 由 JS 按可见区算）。但虫洞弹层自己的规则是
`width: min(1060px, calc(100vh - 40px))`，而旋转模式下 `100vh` 量的是**手机竖屏高 ≈ 844** ⇒ 面板实际 **804 × 522**，
**左右各白扔约 198px（合计 33% 逻辑宽）**。这是「操作界面过于狭窄」的直接来源。

**缺陷 A · 布局**：探索视图是「地图行在上（定高 300px）；下面 左列＝扫描/作业/继续深入 按钮、右列＝地点信息」⇒ 在 804px 里挤。

**缺陷 B · 拖拽（真 bug，与宽窄无关）**：货仓格板的搬运只接了 **HTML5 拖放**（`draggable` + `onDragStart/onDragOver/onDrop`），
这套在**触屏上根本不触发**；`onPointerDown` 只记了个抓取偏移，全仓**没有任何 `pointermove/pointerup` 路径**。
⇒ 手机上唯一能走的是「点一下选中 → 再点空格落位」。**光把面板放大救不了拖拽**。

## 3. 船长裁决（2026-10-02 四问四答，全部取甲案）

| 问 | 取 |
|---|---|
| 「操作界面挪到右侧」的排法 | **甲：整视图改左右两栏**（左＝地图吃满高度，右＝操作区） |
| 「放大到全屏」的口径 | **甲：铺满逻辑空间但四周留 12px 边距（1176×530）** |
| 货仓拖拽这条真 bug | **甲：补指针拖拽，与桌面 HTML5 拖放并存** |
| 改动范围 | **甲：只改手机旋转模式；桌面与窄屏竖屏（≤640px）一字不动** |

## 4. 逐条改动（已确认）

1. `panels/Wormhole.tsx`：探索视图那段现成的 `<>…</>` 片段换成 `<div className="app-wh-explore">…</div>`
   （该片段的作用域天然正好是「地图行 ＋ 图例 ＋ 移动确认 ＋ 工作区 ＋ 各提示行」，只换开闭标签、不搬内容）。
2. `styles.css`：新增 `.app-wh-explore { display: contents }` —— 桌面上它**不产生盒子**（本仓既有惯用法，见 `.app-win-host`），
   ⇒ **桌面布局零变化**。
3. `styles.css`（`is-mobile-rot` 段）：面板尺寸由 `100vh` 轴换成**逻辑空间轴**（宽 `--mob-w − 24px`、高 `--mob-h − 24px`）；
   `.app-wh-explore` 在旋转模式下变两栏 grid（`minmax(0,1fr) / 400px`），地图占左栏吃满高度，右栏纵向排且**自己滚**。
4. `styles.css`：旋转模式下 `.app-wh-mapbox` 由定高 `300px` 改为吃满左栏。
5. `panels/Wormhole.tsx`：货仓格板补**触摸指针拖拽**（判据 `e.pointerType !== 'mouse'` ⇒ 鼠标仍走原 HTML5 拖放）；
   格子层补 `data-wh-cell` / `data-x` / `data-y` 供命中用（无视觉与布局影响）。
6. `styles.css`：旋转模式下格板加 `touch-action: none`（防拖到一半页面跟着滚）。
7. 生成件 `ui/layout-css/styles-{modern,classic}.css` 由 `npm run ui:layout-css` 重新生成（不手改）。

## 6. 已知取舍

1. **地图框不再定高**：原设计（2026-09-13）故意定高 300px 让窗口不随地图变大；手机上改为吃满高度是船长本次要求，桌面仍定高。
2. **`touch-action: none` 的代价**：手指按在**物品块上**起手时是拖物品、不再滚页；按空格或格板外仍可滚。
   全屏后货仓通常不需要滚 ⇒ 暂按此口径；若船长要「按物品也能滚页」，改为长按 300ms 才起拖。
3. **落点命中用 `elementFromPoint`**：目标格是空格时必然准确；手指停在**另一个物品块**上时落到它底下的格
   （"交换位置"语义合理）。更严的做法是拖动中临时关掉整层物品块命中，先按简单的来。
