## 九、报障修复：快进后不刷新入侵（2026-09-25 船长报障）

> 船长原话：「为什么打开调试模式，快进后不会刷新入侵」

**两条病因叠在一起**（都实测确认）：

1. **入侵时钟与"快进"不同源**：入侵的三条时间线（开局面 / NPC 铺底 / 旗舰倒计时）一律读 `Date.now()`（真实墙钟），
   而"快进"推进的是**游戏自己的模拟墙钟** `state.savedAtWallMs`（`debugFastForward` → `simulateOffline(wallBase, wallBase+ms)` 只推游戏时间）
   ⇒ 快进 8 小时，入侵一点没动（既不开新场，铺底也不涨）。
2. **快进管线里根本没接入侵**：`weekendTick` 只由**桌面引擎每拍**调用，`simulateOffline` 那条离线/快进管线不碰它。

**修法**（两处，都在引擎与本模块，未动任何数值）：

| 件 | 改动 |
|---|---|
| `core/weekendEvent.weekendClockOf(state, realNowMs)`（新） | **入侵时钟 = 真实墙钟与游戏模拟墙钟取较大者**：正常在线恒等于真实墙钟（行为逐字不变）；快进后跟着模拟墙钟走、**永不倒回** |
| `engine.wallNowOf()` | 一处定义，给心跳的 `weekendTick`/`weekendSyncComms` 与 `advanceSlice` 的 `nowWallMs` 共用（后者原先也传 `Date.now()`，与离线管线口径不一致） |
| `engine.pumpWeekendAt(wallNow, lastSeenWallMs)`（新 · 抽出） | 一拍的全部动作：补发贡献奖 → `weekendTick` → 三条日志 → 结束结算入账 → 两封通讯。**心跳与快进共用同一段**（不会再漂） |
| `engine.debugFastForward` | 推完模拟离线后，**按 1 小时一步**补跑入侵拍（1h 正是调试模式的"上一场结束 +1h 刷新"粒度）⇒ 中途该结束的结束、该刷新的刷新，快进结束时手上就是**当下该有的那一场**（只补末尾一拍的话，跨过结束点的快进会留下"没有活着的入侵"） |

**验证**：`weekend-event` 新增 1 例（**25 例**）——「快进：入侵时钟取两者较大者 · 跨过"上一场结束 +1h"即开新场且 T0 = 快进后的墙钟」；全量闸门 typecheck ✓ · core **2,355 例全绿**（209 文件）· content:check ✓ · l10n:check ✓ · `ui:rot-check` ✓ · `ui:theme-check` ✓ · build ✓ · docs:index ✓。

## 十二、修：存档墙钟账只许前进、不许回退（同日 · 与快进配套）

**病根**：`serializeSaveFile` 写盘时一律把文件级 `savedAtWallMs` 盖成 `Date.now()`，而"调试快进"把
`state.savedAtWallMs` 推到了未来（它消费的正是那段未来时间）⇒ **读档即被拽回现在**，于是：
① 快进刚推进的入侵时间线要重来一遍；② **再快进一次会把同一段未来算两遍** ⇒ 这一场被 NPC 铺底**瞬间吞掉**
⇒ 板面恢复正常悬赏、遇袭也不再触发（船长看到的"忽然只剩默认悬赏"就是这条）。

**修法**：`stamp = max(nowWallMs, state.savedAtWallMs)` —— 正常在线恒等于 `nowWallMs`（**行为逐字不变**）；
快进后保留未来值；离线结算见到负间隔自然不动（那段时间已经在快进里花掉了）。
**验证**：新用例（`save.test.ts`：正常在线按 nowWallMs 盖戳 · 快进后保留未来值 · 读回仍是该值）·
typecheck ✓ · core **2,356 例全绿** · content:check ✓ · l10n:check ✓ · build ✓ · `save:migrate` **84/84 真档** ✓。

## 十五、抽签口径答疑 ＋ 修「撤退不记伤害」（2026-09-25 船长两问）

> 船长问：「⑤是在玩家开战前就确定了敌舰只是不告诉玩家对吗？如果玩家撤退会重新抽取吗」

**答（逐条从代码确认）**：

| 场景 | 敌舰什么时候定 | 撤退/再打会不会重抽 |
|---|---|---|
| **主动出击**（板面 / 星系详细那一行） | **开局那一刻就定了**：`weekendGarrisonFoeCardId` = 抽签 `(存档种子, 本场场次号 seq, 该星系在占领区里的位序 idx)`，**盐恒 0** ⇒ 一整场不变、读档不变、换窗口不变；玩家看不到的只是"是哪一支"（界面只给威胁范围） | **不会**。撤退后再打还是**同一支**；换一支要等**新一场入侵**（seq +1）或换存档种子 |
| **旗舰战** | 敌卡固定 = 本族旗舰卡（不抽签） | **不会**；但**已打出的伤害会留在血池里**（跨场累计，下次接着打） |
| **遇袭** | **每场重抽**：抽签盐 = `floor(now / 5 分钟) + 1`（区域冷却同粒度）⇒ 每次遇袭落在不同档 | 那一场结束就是结束；**下一次遇袭是新的一次抽签** |

**顺着这一问查出的真缺口（已修）**：母舰伤害是在**战斗收尾**那一步量进血池的
（`weekendApplyBattleOutcome` → `flagshipBattleLedger`），而**撤退 / 自动脱离 / 超时 / 无法交战走的是另一条收尾路径**
（遭遇槽的 `settleEscape`、远征的 `settleBattleRetreat`）⇒ **原先这一场对母舰打出的伤害白打**，
与设计稿「按对母舰造成的伤害决定」（撤退 / 战败的伤害照记）不符。

**修法**：那两条撤退路径各补一次 `weekendApplyBattleOutcome(..., victory: false, battle, {kind, galaxyId, source:'battle'})`
——按"没打赢"结算：**只记伤害 · 不给进度 · 不判击沉**（非入侵战斗内部直接 no-op，老路径零变化）。

## 三十四、「旗舰现身」日志会重复出现 —— 查证（船长问"是什么问题"）（2026-09-25）

> 船长原话：「**有时候'入侵核心已被打通：旗舰现身。'会一直发送是什么问题**」

**结论：不是"同一场刷屏"，是"每一场入侵各记一条"** —— 调试模式下入侵"上一场结束后 1 小时"就刷新，
一场接一场 ⇒ 同一条文案连着出现，看着像刷屏；**读档回到旧档**（船长刚在测网页版本地存档/备份）
也会让那一场重走一遍、再记一条。

**证据（临时探针复刻引擎每拍的三件事：`weekendTick` ＋ `weekendTickBoss`；探针用完即删）**：

| 场景 | 结果 |
|---|---|
| ① **同一场**连跑 660 拍（调试窗口 10 分钟 ＋ 1 分钟余量，1 秒一步） | 触发 **1 次** ✓ |
| ② 中途**存读档往返**（`serializeSaveFile → loadSaveFile`，模拟刷新/读档）后再跑 120 拍 | 锚点 `flagshipAtWallMs` **原样保住**，又触发 **0 次** ✓ |
| ③ 母舰被击沉（`flagshipDown` 已写、血条满）之后再跑 120 拍 | 又触发 **0 次** ✓ |
| ④ 24 小时一场接一场（1 分钟一步、调试模式、玩家不参战） | 只开出 1 场（**玩家不接战 ⇒ 池子不锁定 ⇒ 章鱼人不削血 ⇒ 本场不结束**）⇒ 日志 1 条 |

**真档只读取证**（`%APPDATA%/whale-idle/save.json`，21:08:28 与 21:08:43 两次采样）：
`flagshipAtWallMs` **两次完全相同**（21:07:00）⇒ 锚点没有每拍重写；`seq` 恒为 4。

**机制回顾**（2026-09-25 那次的修法仍然成立）：引擎那一行的判据是 `weekendTick().flagshipAnchored`
（**只在首次把 `flagshipAtWallMs` 落盘**的那一拍为真，`weekendEvent.ts:896`），不是 `flagshipShown`
（那样才会每拍一条）。

**可选的"看起来不像刷屏"改法**（等船长发话，本批未做）：给这条日志**带上场次号**（「…（第 4 场）」），
或把同文案的多条**折叠成一条并计数**。

## 三十五、入侵触发加声望门槛（船长令）（2026-09-25）

> 船长原话：「**给入侵触发加一个前提，需要拥有至少40声望，才会触发入侵。**」
> 四问四答（船长已选）：**协会（DSI）声望 ≥ 40** · **调试模式不受限** · **只在开新场那一刻判** ·
> 不足**静默不开**（不记日志、不提示）。

| # | 落法 |
|---|---|
| ① **常量** | `weekendEvent.ts` 新增 `WEEKEND_MIN_STANDING = 40`（与既有**虫洞解锁线** `WORMHOLE_SCAN_UNLOCK_STANDING = 40` 同值，但那是另一件事的旋钮 ⇒ **各自独立**，日后可分别调） |
| ② **判据单独成口** | `weekendInvasionAllowedFor(state)` = **调试模式恒真**；否则 **协会声望 ≥ 40**。取数刻意**不 import `expedition`**（`expedition` 反过来 import 本文件 ⇒ 会成环，同本文件头注那条依赖方向纪律），本地读 `state.standings['dsi'] ?? 0`（`firstTasks` 里也有一处同样的本地写法） |
| ③ **接线位置** | `ensureWeekendEvent` 的**正常模式那一段**（`weekendWindowOpen` 之后、抽签之前）加一句 `if (!weekendInvasionAllowedFor(state)) return false`。位置**刻意落在调试分支之后** ⇒ 调试模式根本走不到这一句（船长答"调试不受限"）；也只在"该开新场"那一拍才判（进行中的场次不受影响） |
| ④ **为什么还要一条源码级契约** | 当前 `WEEKEND_DEBUG_ONLY = true` ⇒ **正常模式那一段压根跑不到**（函数第一行就把非调试情形挡了）⇒ 门槛有没有接上、接在调试分支的**前面还是后面**，用例测不出来 ⇒ `content:check` 新增「**入侵声望前提契约**」扫源码钉三件：常量 = 40 · 正常模式那一段必须调判据口 · **门槛的下标必须大于调试分支的下标**（位置正确）＋判据单独成口 |
