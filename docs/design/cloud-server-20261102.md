# 云存档与聊天服务器 · 设计与实现（2026-11-02）

> 状态：P0（云存档+聊天）、P1（账本+产出校验+恢复码+订单簿市场）已实现并通过测试，测试服已部署；P2（客户端接入）与转正式待做。
> 代码位置：`apps/server`（workspace `@whale/server`）。本文件只记本批结论与口径，后续并入现行文档。

## 1. 目标与约束

- 桌面版（Electron）与网页版（GitHub Pages）共用一套云存档与聊天服务；
- 规模预期：不超过 1000 同时在线；小圈子自用，不引入重装备；
- 服务器：腾讯云轻量应用服务器（Ubuntu 24.04，2 核 1.9G，40G 盘，峰值 200Mbps）；
- 硬约束：网页版在 https 页面，浏览器禁止连接 http/ws，正式期必须域名 + 证书。

## 2. 已确认口径（船长四轮问答）

| 主题 | 结论 |
|---|---|
| 服务端底座 | 自研轻量 Node（不引入 Nakama/PocketBase/Supabase） |
| 存档权威性 | 混合：存档仍由客户端演算，物品与信用点的进出走服务器账本 |
| 账号 | 设备码免登录 + 恢复码找回（恢复码只存哈希，注册时明文返回一次） |
| 聊天 | zh / en 双频道；客户端 3 秒打包发送；单帧 ≤5 条、单条 ≤500 字、批间隔 ≥3 秒 |
| 聊天留存 | 每频道保留最近 5000 条 |
| 交易行 | 订单簿式市场，冻结式挂单；可交易：舰船/装备实例、矿石材料、蓝图插件；信用点只作支付货币 |
| 撮合粒度 | 混合：可堆叠物聚合成交，实例物逐个挂单 |
| 成交价 | 取先挂单方（maker）报价，买方多冻结差额退回 |
| 交易税 | 5%，从卖方收入扣，进系统账户（货币回收池） |
| 物品归属 | 服务器账本为准；客户端联网时拉账本差量覆盖本地 |
| 产出可信 | 客户端上报结算批次 + 服务器按速率上限校验；超限整批拒绝并记审计，不封号 |
| 最低价 | 只做挂单下限：`floor = floor(basePrice × 0.6)`，全部物品（含稀有）适用；存量挂单不撤、只卡新单 |
| 备份 | 每日本地 SQLite 快照，保留 7 天 |
| 部署 | 先测试服（直连 IP:8787），域名 HTTPS 与 SSH 密钥加固留到转正式 |

## 3. 架构

```
客户端 ──HTTP/WS──> Node 单进程 @8787
                      ├─ auth（设备码 / token / 恢复码）
                      ├─ saves（版本 + 历史回滚）
                      ├─ production（产出上报 + 速率校验）
                      ├─ ledger（双分录 + 哈希链，资产唯一真相）
                      ├─ market（订单簿 / 冻结 / 撮合 / 税 / 最低价）
                      ├─ chat（zh/en，打包帧）
                      └─ catalog（读 content-csv，算最低价）
                    SQLite（WAL）+ 每日本地快照
```

设计参考（借模型，不搬代码）：Nakama 的 wallet/ledger 与 storage 版本号；EVE 市场的订单簿与 maker 定价；PocketBase 的单进程 + SQLite 部署形态；Rocket.Chat 的消息游标分页；TigerBeetle/Stripe 的幂等与禁止负余额约束。

## 4. 数据模型

| 表 | 作用 | 关键约束 |
|---|---|---|
| `accounts` | 设备码、token 哈希、恢复码哈希、昵称 | 昵称唯一，设备码唯一 |
| `saves` | 存档 JSON + 版本 | 每账号保留 10 版 |
| `items` | 唯一实例（instanceId、归属、属性快照、状态） | 归属唯一，上架时 `status='listed'` |
| `item_stacks` | 可堆叠物（qty / locked） | 不可为负 |
| `wallets` | 信用点（credits=可用）与冻结额（escrow） | 均不可为负 |
| `ledger_entries` | 双分录流水 + `prev_hash`/`hash` | 只追加，链式校验 |
| `orders` / `trades` | 订单与成交 | 订单状态 open/filled/cancelled |
| `production_events` | 产出上报与校验结果 | `batch_id` 唯一（幂等） |
| `messages` | 聊天 | 按频道保留 5000 条 |

## 5. 关键机制

1. **物品编号**：`instanceId`（UUID）+ `HMAC(seed, id|定义|归属)` 签名；签名用于客户端展示校验，归属判定以 `items` 为准；实例变更写账本但不进 `item_stacks`，避免重复计数。
2. **账本**：`appendEntry` 同时写流水（含 `credits_delta`/`escrow_delta`/`qty_delta`）与物化状态，全程包在 `BEGIN IMMEDIATE` 事务里；任何余额为负立即回滚。哈希链可被 `GET /api/ledger/verify` 定位到断点。
3. **产出校验（逐物品）**：每个物品单独算上限。原料/材料（可堆叠、单价 ≤ 2000 cr）用 `min(kind 硬顶, max(配额 ÷ 基准价, 2000))`——**带 2000/分钟数量保底**，否则 1300 cr 的虚空母矿会被压到 384/分钟、正常采矿全被误拒；成品与珍稀掉落用 `min(kind 硬顶, 配额 ÷ 基准价)` 最低 1。再叠加**比例叠加闸门**：`Σ(入账量 ÷ 各自上限) ≤ 3`——用比例而非绝对产值，因为绝对闸门会误杀单件高价物（6750 万的战列舰本身就超过任何合理的每分钟产值阈值）。配额默认 50 万 cr/分钟（实测最优矿船约 3000 单位/分钟、5 万 cr/分钟，取 10 倍余量）。近 60 秒累计超限整批拒绝并落 `production_events(accepted=0)`。效果：12 cr 矿石 8000/分钟、1300 cr 虚空母矿 2000/分钟、6750 万战列舰 1 艘/分钟、8000 万黑匣 1 个/分钟，531 个物品无需手配。
4. **冻结与撮合**：卖单冻结物品、买单冻结信用点；撮合价格优先时间优先，成交价取 resting 单价格；成交后释放对应冻结、按 5% 计税，订单结束时退回剩余冻结；禁止自成交。
5. **最低价**：目录加载时从 `market.csv` 的 basePrice 派生；仅校验新挂卖单，内容更新改价不追溯旧单。
6. **聊天**：batch 帧落库后按帧广播；每连接限频；`hello`/`presence` 提供在线状态。
7. **实例快照校验**（`src/instance-props.ts`）：舰船白名单字段 `hullId/name/fit/plugs/hp`，`hullId` 必须等于商品定义，装配件数 ≤ 高+中+低槽总数且每件须为已知装备，插件 ≤ 8，耐久 ≤ 白板 2 倍 + 1000，快照 ≤ 2KB。装备/蓝图/核心只做对象与体积校验。
8. **限流**（`src/rate-limit.ts`）：进程内滑动窗口，每 IP 每分钟 600 次总请求、20 次注册/登录，超限 429 + `retry-after`；放在 Caddy 后面时用 `WHALE_TRUST_PROXY=1` 读 X-Forwarded-For。

### 5.1 三个待决事项的结论（本轮落定）

| 原待决 | 结论 | 依据 |
|---|---|---|
| 产出阈值逐物品 | 已实现：价值配额折算 + 类别硬顶 + 跨物品价值闸门 | `npm run mining:curve` 实测最优矿船约 300 万 cr/小时 |

## 7. 客户端页面（2026-11-02 第二批）

按船长指示「前端以端口参数形式，先不接入现有游戏内」，服务端自带一个独立客户端页面（`apps/server/public/`）：

- `/` = 云端客户端（深空主题单页）：账号（注册/登录/恢复码/改昵称/钱包）、云存档（拖拽上传带 baseVersion、409 冲突二选一、历史版本下载与回滚）、聊天（zh/en 双频道、3 秒打包、断线重连、未读红点）、市场（搜索/盘口/下单/撤单/成交）、库存与账本（实例核验、手动产出入账、全链校验）；
- `/debug` = 原接口级调试台（保留）；
- 结构：`index.html + app.css + app.js`（DOM 层）与 `api-client.js`（HTTP 封装）、`chat-queue.js`（打包队列）分离——后两个无 DOM 依赖，游戏正式接入时可直接复用，且有确定性测试（`src/client-queue.test.ts`、`src/client-api.test.ts`）；
- 静态服务在 `src/static.ts`：只允许 public/ 内普通文件、拒绝路径穿越、内存缓存、`cache-control: no-cache`；
- 验证：本地与远程均 83/83 测试通过；另用本机 Chrome 无头模式跑过真实页面冒烟（注册 → 恢复码展示 → 存档上传 → 聊天 3 秒打包收到自己消息 → 市场搜索橄榄岩 floor=7），截图确认三栏布局与页签切换正常（过程中修了 `.panel` 的 `display:flex` 覆盖 `hidden` 属性导致四个页签堆叠显示的 bug）。
