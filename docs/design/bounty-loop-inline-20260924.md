# 工作文档 · 重复清剿并入「④ 悬赏」每一行（删掉独立容器）（2026-09-24 · 三号）

## 一、我上一版错在哪（如实记）

2026-09-24 早些时候按船长令「允许玩家在星图的星系详细悬浮窗里进行重复清剿」＋三条裁定
（①**乙**列出候选卡让玩家挑 ②**乙**允许顶替但先确认 ③**甲**条件照旧）落码时，我把「**乙：列出候选卡**」
理解成"得有一个完整的候选清单"，于是**另开了一个容器** `BountyLoopBlock`（自带标题「重复清剿」、
自己的一份卡片列表、自己的忙碌/顶替判定、以及四条 `.app-map-loop*` 样式）。

结果同一个悬浮窗里**同一批卡被列了两遍**：上面 ④ 悬赏一份（带「出击」按钮），下面重复清剿一份（带环按钮）。
这违反约定 §九「**任何位置新增内容，样式一律优先参考同级相似项 UI**」——候选卡本来就在那张列表里。

## 二、改法（船长 2026-09-24 选定）

1. **删掉整个容器**：`BountyLoopBlock` 组件、它的调用点、四条死样式 `.app-map-loop*` 全部移除；
2. **环按钮并入 ④ 悬赏的每一行**（纯图标 `ico-loop`；环已开时按钮转 `is-warn` 琥珀态，点击即停）：

   | 列 | 内容 |
   | --- | --- |
   | 卡名 + 状态字 | 威胁/奖金/已首胜（原有）＋ **冷却剩余秒**（原有 `ui.Expedition.037`）· **征战中** · **循环中**（新增 436/437 两条，其余复用卡面既有文案） |
   | 环按钮 | 悬停说明复用卡面那套（开启 `ui.Expedition.155` / 停止 `ui.Expedition.043` / 忙碌 `ui.Expedition.154` / 再开受阻 `autoLoopReopenBlockReason`） |
   | 出击按钮 | **沿用原有禁用与文案**，本次只补上冷却/征战中的置灰与说明 |

3. **顶替确认保留**：已给 A 开环再点 B ⇒ **在该行内联**出警示条（`app-ga-switch-confirm`，照抄同文件
   `goAskAno`「采矿中转战」的内联写法 + `.app-ano-switch-confirm` 同形样式），**不新增弹窗机制**；
4. **列表可见性必须一起改（关键）**：原 ④ 悬赏把**冷却中/进行中**的卡**过滤掉了**，而"开环"恰恰最需要它们可见
   —— core `setAutoLoopBounty` 只受 `autoLoopReopenBlockReason`（装甲/结构 ≥50%、机群够、货舱够）管，
   **与卡片冷却无关**（读 `core/expedition.ts` 确认）。不改这一条就会出现"打完那张卡从列表消失、环还在跑却看不到也停不掉"。
   现改为**列出该星系全部悬赏**，只保留**声望门槛**过滤；空态分两句（无卡 / 有声望不够）。

## 三、状态与开关的唯一性（没变）

- 开关仍然只有 **T8 那条唯一入口** `engine.bountyLoopAt(anomalyId | null)`：**不新增状态、不改存档结构**；
- 忙碌与"再开"门槛与卡面**同一把尺**（`busyOther` / `autoLoopReopenBlockReason`）。
