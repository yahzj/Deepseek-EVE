## 二、为什么会漏（两条，都是我的错）
1. **比对口径缺列**：首次回写的比对脚本只比 **名称 / rank / x / y** 四列，把「**前置（读数）**」当"读数"跳过 ⇒
   船长在这一列上的改动**根本没进比对**；
2. **一句话读窄了**：船长早先说「**不同类型的舰船不应该是上下级关系**」，我理解成"采矿舰入门学与采矿舰操作
   也不设上下级"；他的本意是**不同族之间**（采矿舰 / 武装舰 / 装甲舰互不隶属）不设，而**同一族内的
   "入门 → 操作"要有上下级**。

## 三、本批落地
1. **采纳那 1 处**：`industrial-ops`（采矿舰操作）`prereq = ['mining-frigate']`（采矿舰入门学）——
   rank 2 ≤ 3，符合树契约「父 rank ≤ 子 rank」；连带读数：**有前置 29 条 / 连线 29 条 / 根 53 条**（原 28/28/54），
   `b-indship` 那本从"两个并列根"变成一条链（`layout-check`：`b-indship 2 格 · 连线 1`）。
2. **新增逐列比对工具 `npm run skilltree:diff`**（`tools/skilltree-diff.ts`，正式入库 ＋ 版本自检头）：
   把工作台与代码在 **名称 / rank / 技能书 / 大类 / 前置 / 坐标** 六类上**一次比全**，点名"表里有、代码里认不出的
   名字"，并给出待回写清单。**起因就写在工具头注释里**（防再漏）。
3. **导出工具改造**（`tools/skilltree-export.ts`）：表头直接标注可改性 ——
   **可改①写 `skills.ts`：名称 · rank · 前置 · 技能书 · 大类**；**可改②写 `skillTreePositions.ts`：x / y**；
   其余为读数；说明页补两条：「前置怎么写」「为什么坐标列有时会'变'（rank/前置一改布局就重排，重导即同步）」。
4. **重导工作台**：`content-csv/skilltree-workbench.xlsx` 已按当前代码重出 ⇒ 表与代码**零差异**（`skilltree:diff` 全 0）。
