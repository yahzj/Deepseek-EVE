# 支援舰参战修复（"增援的敌舰不会攻击也没有效果"）

状态：**进行中（待船长验收）** · 经手：二号 · 分支 `d2/workspace`

船长原话（照抄）：
- 「**玩家反馈BUG，增援的敌舰不会攻击也没有效果**」
- （追问后澄清）「**是入侵母舰复活的敌舰**」

范围：**只修"复活的支援舰算不算敌人"这一件事**。
**不做**：不改复活节拍/上限/优先名单（`everyMs 60s` · `count 2` · 优先进攻舰不动）· 不改后备/数值 · 不动存档结构。

---

## 一、根因（数据/代码证据，不是推测）

挂载件「支援舰船召唤装置」（`foe-mount-revive-escort`，H 族入侵母舰挂）的召唤在
`packages/core/src/combat.ts` 的 `resolveFoeRevive`：它从**本波编成**里挑已阵亡的条目，`seedUnit` 成
新 tag `sup{n}-<原tag>` 写进 `battle.units`。

而**敌人开火 / 我方选靶 / 判清波与判胜**三件事，全都只看调用方**递进 `stepBattle` 的那份 `foes`**
（= `advanceBattleFor` 里的 `curFoes` = 本波编成）：

| 位置（改动前） | 口径 |
| --- | --- |
| `stepBattle` 敌方开火循环 | `for (const f of foes)` |
| `stepBattle` 我方选靶 | `foes.filter(isFoeEngageable)` / `firstAliveFoe` / `pickFoeDroneTarget` |
| `stepBattle` 结束判定 | `const foeAlive = foes.some((f) => isAlive(b, f.tag))` |
| 转场清波判据 | `!curFoes.some((f) => isAlive(battle, f.tag))` |

支援舰不在 `curFoes` 里 ⇒ **它入得了场（有舰影、有血条、有入场动画、有战报），却一炮不开、
谁也打不着它、也不挡清波/判胜**——正是玩家看到的"增援入场但毫无作用"。

> 代码里本来就有这条自我提醒（`resolveFoeRevive` 的槽位注释）："支援舰不是 `curFoes` 里的条目"
> ——但那条只用来数"在场槽位数"（防超编），**没有人把它接进参战列表**。

## 二、修法（三处接入，一个私有函数）

新增私有 `foesWithSupport(battle, foes)`：**本波参战敌阵 = 编成条目 ＋ 已入场的支援舰**。

- **配对靠剥壳回查本波编成**（`baseFoeTag`）：查得到才收（本波召唤的），查不到（跨波遗留）不收
  —— 与"只补当前波"同一条边界；
- **一律追加在队尾**，绝不插队：`battle.pdCd` / `pdFocus` 是**按下标**对齐这份列表的
  （`resolvePointDefense`），插队会让近防炮冷却与集火锁错到别的舰上；
- 规格由**原条目重建**（`{...base, tag}`）：与换波/读档中断补缺同一口径 ⇒ **不新增任何存档字段**；
- **零变化早退**：`foeReviveCount` 缺省（本场一次都没召唤过）直接返回原数组，连数组都不建。

接入三处：

1. `stepBattle(..., liveFoes, ...)`（在 `resolveFoeRevive` **之后**取 ⇒ 本拍刚入场的支援舰本拍就参战）；
2. 转场**清波判据**（本波编成全灭但支援舰还活着 ⇒ 不记"已全灭"、不刷下一波）；
3. `battleArcsFor` 的**敌机机群汇总**（`foeDroneWings`）：支援舰的机群池由召唤时建
   （`initFoeDronePools(b, [spec])`）、引擎里**真会放飞**（复活的战列巡洋舰带 1 架重袭机）
   ⇒ 画面必须同源，否则"无人机打人却没有画面"。

## 四、待船长裁（本批新增）

1. **难度**：修好后复活舰既开火又必须打掉 ⇒ 旗舰战明显变长变难（上表）。要不要给这条机制加闸门/限幅？
   可选：① 保持现状（机制本该如此，"不超本波原编成"已是上限）② 降低每拍复活的**船体强度**
   （例如复活舰只带部分血）③ 给复活加**总次数上限**（如本场最多 4 次）④ 复活舰**不开火**只挡清波（不推荐：
   与"支援舰入场"的表现矛盾）。**二号的看法**：先按现状（①）——这次修的是"它根本没参战"这个缺陷，
   难度回到"设定值"；若实测仍嫌难，再调 ③ 最直接。

## 五、已知边界（记录在案，未改）

- **跨波遗留的支援舰不收**：`foesWithSupport` 按"剥壳 tag 能否在**当前波**编成里查到"配对 ⇒
  换波后旧波的支援舰（只可能来自改动前的老档在途战斗）不进参战列表——与"只补当前波"同一把尺。
  改动后不会再有这种残留（清波判据已算上支援舰）。
- **敌方后勤/挂件修理脉冲仍只遍历"波 0 编成"**（`pulseFoeRepair` / `foeRepairPulses` 的两处循环）：
  这是**既有**口径（多波卡的后几波本来就不在里面），且当前内容里**没有任何敌舰挂 `repairPulse`/
  带 `repairPct`**（`FOE_G_REMNANT_TENDER` 未进卡）⇒ 本批不动它；日后若给 H 族加入后勤舰，须一并接。
- **不改存档**：`sup{n}-` 单位本来就随档（`battle.units`），规格每次由编成重建 ⇒ 无迁移、无新字段。
