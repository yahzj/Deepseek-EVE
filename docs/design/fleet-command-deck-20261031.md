# 我的舰队卡牌与编队操作融合

> 状态：界面实现完成，待船长审核。二号，`d2/workspace`，2026-10-31。

## 船长原话

「新的多舰船编队已经测试，基本上没问题，但是UI过于简陋，允许使用和寻找网络上的SKILL优化，要求风格和现有的统一，优化‘我的舰队’界面，将编队和我的舰队界面合并，可以参考《远行星号》的编队界面。打开编队界面时，历史保存的编队舰船置顶（本次窗口期间排序不变）。UI修改后生成一个简易参考给我审核。」

随后澄清：「我的意思是，将’我的舰队‘和’编队‘功能融合，修改；我的舰队；的列表排列方式，并直接赋予编队选择取消功能。单个舰船采用卡牌的形式，各种按钮保持原功能」。

## 实现范围

- 只保留一个「我的舰队」列表，改为纵向舰船卡牌网格，删除上版额外增加的编队指挥台和槽位清单。
- 面板标题内显示编队人数、成本和容量摘要；超预算及出勤状态在同一面板内提示。
- 每张卡牌由编队选择栏、舰影、名称/角色、原操作按钮、单舰成本/级别、属性和耐久组成。
- 卡内直接「编入 / 取消编入」，使用 `Plus`、`Check` 和 `aria-pressed`；主控舰显示「已编入」并禁止取消。
- 装配、收藏、改名、锁定、维修、即时维修组件、入仓确认和切换驾驶保持原有处理函数、禁用条件与入口。
- 编辑保护统一落在切换处理函数：出勤期间不可调整、主控船不可移除、超过最大舰船数时提示、被舰船操作策略锁定时不可编入但仍允许移出。

## 排序规则

舰队页签挂载期间建立一次排序快照，之后不因点选、搜索筛选或引擎状态刷新而重排：

1. 存档中的 `preparationSquads.combat` 成员，按保存顺序置顶并去重。
2. 当前驾驶舰；若它已经在历史编队中，不重复插入。
3. 收藏舰船，按收藏顺序追加。
4. 其余舰船，按级别与舰队实例 UID 的稳定顺序追加。

历史舰船卡带有金色左边界标记。存档中已不存在的历史 UID 不显示，但不会污染当前排序；本次窗口新出现的舰船只追加到末尾。

## 视觉方向

参考船长提供的`H:\大鲸鱼\QQ图片20261031112539.png`中的舰船卡牌网格。沿用本项目的舰船SVG线稿、深色面板、青绿色选中态、金色当前驾驶态和`wui`变量。卡牌至少240px宽，舰影区100px高；桌面三列、窄桌面两列，手机沿用项目现有自动横屏。列表仍在原舰队二级面板内滚动。

复用本地`ui-ux-pro-max`与`frontend-design`；`refactoring-ui`用于检查布局与层级。已核实的技能建议是控件保留键盘焦点状态；卡牌排列及独立选择按钮依据船长明确澄清，不把技能建议当作额外功能授权。未添加新依赖或网络素材。
