# 入侵母舰「支援舰船召唤装置」改判：每次 2 艘 · 优先复活干扰舰（2026-09-26）

状态：**已实现 · 待船长验收**

## 船长原话（照抄）

1. 「**入侵活动中，H族入侵母舰的挂载件复活效果，改为每60秒复活2艘船。且必定会复活干扰舰。**」
2. 「**应该是优先复活干扰舰**」（同日追答 ⇒ 定调为**优先**语义，不是"无条件必补"）

## 改前 / 改后

| 项 | 改前（2026-09-25 口径） | 改后 |
|---|---|---|
| 每次艘数 | **1 艘** | **2 艘**（`count: 2`） |
| 选谁 | 从"当前波已阵亡且槽位空着"的池子里**随机** | **优先名单**（`priorityShipIds`）先占名额，取完再随机补足 |
| 优先名单 | —（无此概念） | **墨潮干扰舰 `foe-h-ink-jammer`** |

**语义（优先，不是必补）**：干扰舰只要**在可补池里**（= 阵亡且它的槽位空着）就**先占一个名额**
（按名单顺序取）；它活着 / 已补进场 ⇒ 名额回落到随机。
每次实际艘数再受两道封顶：**本波剩余空槽**（"不超本波原编成"）与**可补池大小** ——
所以"只剩 1 个空槽 / 池里只有 1 艘"时就只补 1 艘。

**不变的四条**（2026-09-25 已定）：池子 = 只补当前波 · 上限 = 不超本波原编成 · 满血入场 ·
表现 = 「敌方支援舰船入场」（新 tag `supN-<原tag>` + 入场窗口，每艘各记一条战报/日志，序号连续）；
总开关 `BattleBalance.foeReviveEnabled` 照旧（关 ⇒ 零行为变化）。

## 落地

- `types.ts`：`FoeMountDef.reviveEscort` 与 `UnitSpec.foeReviveEscort` 各加 `count?: number` 与
  `priorityShipIds?: readonly string[]`（缺省 = 旧行为：1 艘、全随机 ⇒ **没挂该件的战斗逐字不变**）。
- `foeMounts.ts`：挂载件参数 `{ everyMs: 60_000, count: 2, priorityShipIds: ['foe-h-ink-jammer'] }`
  （core 侧不 import data ⇒ 舰 id 写字面量 + 注释）；`note` 记两条原话。
- `combat.ts`：`resolveFoeRevive` 由"抽一艘"改为"**按配额补 `count` 艘**"——先按优先名单取，
  再在剩余池子里随机补足；每艘各走一遍原入场流程（`seedUnit` + 机群池/修理账本 + 画面提示 + 战报日志）。
- 用语统一：注释/文档一律「**优先**复活干扰舰」，同时保留船长两条原话（先"必定"、后追答"优先"）以便追溯。
