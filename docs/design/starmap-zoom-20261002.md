## 1. 船长原话（照抄）

> 「玩家还反应，手机端，星图界面各个星系判定范围过小（尤其是未探索的星系），几乎点不中/点了没反应。建议星图和虫洞探索一样允许放大。并扩大判定范围。」

## 2. 现状读数（动手前实测）

- 星图 = `.app-starmap`，`viewBox` = **716 × 320**（内容坐标 (0,0)-(700,300) ＋ 留白 8/20）。
- **可点范围就是圆点本身**：`r = 7`（未探索 frontier）/ 8（普通）/ 11（母港），单位是 viewBox 单位。
- 全仓**没有任何星图的手机适配**（`is-mobile-rot .app-map*` 0 条）；旋转模式再 × **0.7033**
  ⇒ 未探索星系的可点直径只剩几个物理像素 —— 与玩家"点不中"的反馈一致。
- 星图**没有缩放**（缩放/拖动此前只在虫洞探索地图里有）。
- 20 个星系两两距离：最近 **10.2**（`galaxy-vault(608,127)` ↔ `galaxy-nadir(606,137)`，圆点半径各 8
  ⇒ **本来就压在一起**），其余 ≥ 33.5。

## 4. 逐条改动（已确认）

1. `panels/Expedition.tsx`：每个 `.app-map-node` 在圆点**之前**加一枚不可见命中圆
   （`r = MAP_HIT_R = 16`、透明、`pointer-events: all`）——点击照旧冒泡给本组原有 `onClick`
   ⇒ **坐标换算与选中逻辑一行不改**。
2. `panels/Expedition.tsx`：缩放走**改 `viewBox`**（不是给内容套一层 transform）——
   坐标系整体缩放 ⇒ 节点/标签/连线/判定圆**一起变大**，且**不动任何 DOM 结构**。
   锚点 = **当前选中星系**（没选中取图心），与虫洞「以玩家所在格为锚点」同一套口径；
   可视窗口夹取在基准视图内。
3. `panels/Expedition.tsx`：`＋ / － / 倍数 / 复位` 四件放进 `.app-map-viewbar` 最右端
   （`margin-left: auto`，不挤那三档显示模式）；步长 25%、范围 100%～**300%**
   （上限比虫洞的 2.5 高：要把相距 10.2 的那两颗分开得放到 3 倍上下）。
4. `panels/Expedition.tsx`：拖动平移 —— 阈值 4px（与虫洞 `WORMHOLE_MAP_DRAG_THRESHOLD_PX` 同值）、
   指针捕获、拖动中关过渡、**拖过就吃掉紧随的那次 click**（否则"拖完顺手选中一个星系"）。
5. `panels/Expedition.tsx`：桌面滚轮缩放 —— 自挂**非被动**监听（React 的 `onWheel` 是被动的，
   里面 `preventDefault()` 无效），锚点与按钮一致。
6. **编辑模式（开发工具的布局编辑器）下禁用缩放与平移**：它按 `MAP_VB_W/H` 常量换算拖拽坐标
   （`toViewBox`），叠上缩放会算错；该模式下缩放控件整组不出现。
7. `styles.css`：`.app-map-hit` / `.app-map-zoom*` / `.app-starmap.is-zoomed`（可拖光标）、
   生成件重跑。
8. l10n：新增 4 条（放大 / 缩小 / 复位 / 缩放·组标签），中文只进 `table.ts` 的 `zh` 列。

## 5. 已知取舍

1. **r=16 是实测安全上限**：除 vault/nadir 那对外（16+16=32 < 33.5）两两不重叠。那两颗共享一段重叠区
   （**现在也重叠**），重叠带里后画的优先 —— 想彻底分开得靠放大。
2. 只把判定圆放大到 r=16，手机下约 14 物理像素，仍低于「手指可点」的 44px 经验线
   ⇒ **放大与缩放两件要一起做**才够。
3. 缩放走 `viewBox` ⇒ 描边宽度跟着一起放大（与虫洞那种 transform 缩放同一观感）；
   若船长觉得放到 3 倍时线条太粗，再另议。
