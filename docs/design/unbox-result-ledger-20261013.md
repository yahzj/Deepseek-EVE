# 货柜拆解上一批产物记录

> **状态：已实现，自测通过；待船长观感验收及发布**（二号 · d2/workspace · 2026-10-13）
> 船长原话：「在精炼炉页面的货柜拆解卡牌上加入一个按钮，用于记录上一批玩家拆解货柜获得了哪些东西。这个记录不仅存档，关闭浏览器后就消失。UI需要明确符合游戏，每个产物类型单独占一行，左侧是名字，右侧是数量，玩家鼠标悬停可以查看产物的相关信息富文本。」；方案确认后回复「确认」。
> 范围：精炼炉货柜拆解卡、玩家本次启动期间的内存记录、产物行富文本悬停。
> 不做：不写入 GameState/玩家存档/localStorage/IndexedDB，不改货柜随机池、掉落概率、产物入库、日志内容或其他工业卡。
> 待裁决点：无。

## 已确认口径

- “上一批” = 玩家点击开始货柜拆解后，直到该卡下一次开始拆解前的所有拆解产物；下一次开始时清空旧记录。
- 记录按产物 id 合并，军用备货柜的一箱多件也逐项累计；每种产物一行，名称在左、数量在右。
- 产物行复用现有 `ItemHover` 富文本规则；装备、图纸与物品分别按当前目录解析富卡内容。
- 记录只在当前渲染进程内存中存在，刷新页面或关闭浏览器/桌面窗口即消失；切换工业子页不清空。

## 实现与边界

- 记录单点是`game/unboxLedger.ts`的`UnboxSessionLedger`，由`GameEngine`持有；按当前内存档及货柜类型隔离，切一级页、筛选或工业子页不丢产物，换档后不继承上一批。
- 每次成功点击开始拆解（主控或AI）清该卡旧记录，失败/警告开工不清；同卡并行产物按实际完成逐项合并，查看/收起按钮不改变账本。卡有本次记录时即使库存归零仍保留入口。
- `advanceRefining`在原入库位置读取产物入库前后增量，通过可选回调交给当前渲染会话；随机、发奖、日志、存档形状不变。在线推进、启动离线补算和调试推进复用；恢复/导入候选不污染当前记录，成功切换内存档后自动清旧账。离线新结算可生成当前启动记录，不从历史存档还原旧记录。
- 货柜卡星标旁增加固定尺寸历史图标按钮，按钮提示/无障碍名称明确；卡内展开使用既有仓库行、金色产物名及右对齐数量，144像素内滚，不加嵌套装饰卡。
- 物品/装备分别走`ItemHover`、`ModuleHover`；图纸调用`blueprintHoverLines`及`InfoHover`，共用参数表与悬停单例。长名称换行、数量不挤占名称；键盘按钮焦点明确。
- 功能域：工业与精炼；同类参照：精炼卡、仓库行、实验室产物富卡与市场图纸富卡。回调透传只服务本次工业记录，共享底层不扩展为其他系统。
- 中文四条取`ui.IndustryPage.148`至`.151`，英文只登记`docs/l10n-pending.md`并回退中文。中途误写的新英文已全部撤回，已有英文不改。

## UI依据

`ui-ux-pro-max`的ux域命中`Keyboard Navigation`：按视觉顺序保留键盘访问，控件可见焦点；react栈`Use semantic HTML`要求真实button承担点击。本批据此使用button、`aria-expanded`/`aria-controls`、固定历史图标与列表；沿用现有主题/富卡，不新增悬停机制，观感由船长裁定。
