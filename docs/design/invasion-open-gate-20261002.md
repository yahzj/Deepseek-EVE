只保留"**当前有入侵正在进行 ⇒ 不开**"。

## 二、改了什么（判据层）

`packages/core/src/weekendEvent.ts` · `ensureWeekendEvent` 正常档：

| | 改前 | 改后 |
|---|---|---|
| ③ | `if (ev && nowWallMs - ev.startedAtWallMs < WEEKEND_WINDOW_MS) return false`（**看间隔**） | **删除** ⇒ 不再看"隔了多久" |
| ④ | `if (ev && ev.endedAtWallMs === undefined) return false`（上一场未结束 ⇒ 取消） | **保留** ⇒ 这就是"看有没有正在进行" |

⇒ 开新场的**全部条件**变为：**① 在窗口内（`weekendWindowOpen`）** ＋ **② 声望 ≥ 40** ＋
**③ 当前没有进行中的场** ＋ **④ 抽得出核心**。窗口内只要上一场**已结束**，**下一拍就开新的一场**。

## 三、这条令修掉的真问题（"看间隔"的错处）

只有**上一场的 `startedAtWallMs` 不是某期 T0** 时，旧判据才会误挡。现实里只有两条路造出非 T0 起点：

1. **调试档**开的场：`ensureWeekendEvent` 调试档分支写 `startedAtWallMs = nowWallMs`（任意时刻）；
2. **首场特例**：`WEEKEND_FIRST_T0_WALL_MS` = 2026-09-25 22:00（已过期）。

**反例（改前会误挡）**：调试档在**周三 20:00** 开一场、21:00 打完，然后关掉调试
⇒ 旧判据下**本周五 20:00 那一期被挡住**（只隔 48h < 96h）⇒ 整个周末不开入侵，要再等一周。
⇒ 改后（甲）在周五 20:00 照常开局。

## 四、甲的直接后果（如实登记，都是判据的必然）

1. **窗口内可连开**：周五 20:00 开局、旗舰被打死 ⇒ **下一拍立刻再开一场**（`seq + 1`、重抽核心、`contributed` 归零），
   一直连到窗口关（周二 20:00）。⇒ **夺回奖（A 档 12 残骸 ＋ 800 万）· 进度收入（每 1% 20 万）· 协会声望（0~15）·
   旗舰黑匣** 都随之**每场各发一次** —— 这是"一期一场"作废后**可重复获取**的部分（船长已知情并选甲）。
2. **每场都会重发一封预警通讯 ＋ 闪一次开局警报**（`weekendSyncComms` / `invasionAlarmPending`）—— 连开几次就收到几封。
3. **族不变**：族按**本期 T0** 定（`weekendFamilyForWindow(t0)`）⇒ 窗口内连开的每一场**都是同一族**
   （本期 = R）。这对"反复实测新族"是便利。
4. **T0 不倒着走的两处例外**（老场起点早于本期 T0 时，新场仍按本期 T0 起算）：
   - 首场特例那晚：首场 T0 = 09-25 22:00，结束后同窗口补开的新场 `startedAtWallMs = ` 周排期的 **09-25 20:00**
     ⇒ 新场的窗口早于旧场的起点（只是记账口径，窗口同在本周二 20:00 前关）；
   - 调试档旧场（起点 = 任意时刻）：补开的新场按**本期 T0** 起算，可能早于旧场起点。
   ⇒ 两者都只影响"NPC 铺底起点 / 窗口到点"这两条按 `startedAtWallMs` 算的时间线，**不影响结算**
   （换场只换**已结束**的场 ⇒ `settleWeekendPrize` 在 `weekendTick` **之前**跑，先结旧的再开新的，见 `engine.ts:1207`）。
