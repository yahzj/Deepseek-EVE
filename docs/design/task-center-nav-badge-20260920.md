# 导航「任务中心」的「第一次」推进提醒（2026-09-20）

> **状态：进行中**（已实现，闸门全绿，待船长实机验收）
>
> **船长原话（照抄）**：「**每推进一阶段第一次任务时，在导航栏的任务中心选项处进行提醒。**」
>
> **本件范围**：**「第一次」任务推进时的导航徽标提醒**。**不做**：赏金新板/通讯未读那两套既有徽标（一字未动）·
> 里程碑（次数链）与成就的提醒 · 任务中心页内排版。

## 一、口径（与「赏金新板提示」逐字同款，复用既有机制）

仓库里已有两套导航徽标：**通讯 = 未读条数** · **任务中心 = 赏金新板条数**（2026-09-14 船长定：
「当任务中心有新的赏金任务时，提示玩家，玩家进入后消除提示」，判定 = 换板未看、进页记账即消）。
本件**照同一套做**，不新造第二套提醒机制：

| 项 | 落地 |
|---|---|
| 判定 | **当前那一条「第一次」≠ 玩家看过的那一条** ⇒ 亮（core `firstTaskNotice(state)` 单点） |
| 形式 | 左侧导航「任务中心」的**数字徽标**（复用 `.app-nav-badge`，与赏金那条**合流**：`赏金新板条数 + 1`） |
| 悬停 | **先说「第一次」**：`ui.App.120`「有新的「第一次」任务：{p1}（进任务中心即清除）」，p1 = 任务标题；赏金那条另起一行（两条都有时各占一行） |
| 消除 | **进「任务中心」页即记账**（`firstTasksMarkSeen`）⇒ 立刻灭（页内恒为 null，不必等下一拍） |
| 记账挂点 | 挂在 `page === 'task'` 的 effect 上（**不是按钮 onClick**）——点导航 / 通讯「前往」/ 教程跳转三条入口都会走到，挂按钮会漏后两条（与赏金那条同一处注释口径） |
| 状态 | 随档：`state.firstTaskSeenId?: string`（可选兼容字段、**零迁移**）；**没记过账就不写这个键**（老档与新档的快照往返逐字一致，与 `bountySeenWindow` / `fitPresets` 同款口径） |

**"每推进一阶段"的起点**：`finishPrologue`（序章收尾/跳过）会**替新档记第一笔**——开场信本来就指路
「待办清单在任务中心」，所以**新档开局不亮**、**完成第一条之后才开始亮**（这才是"每推进一阶段"）。
老档不经过序章收尾（`step` 已是 99）⇒ 仍是**首帧亮一次**（与赏金那条「老档默认亮起提示」同款处置）。
13 条全做完 ⇒ 没有"当前那一条" ⇒ 不亮。

## 二、改了什么

**core**
- `state.ts`：新增可选字段 `firstTaskSeenId?: string`（口径注释写全）。
- `firstTasks.ts`：新增 **`firstTaskNotice(state)`**（判定，返回 `{ taskId, title } | null`）＋
  **`firstTasksMarkSeen(state)`**（记账，幂等，返回是否真的记了）。
- `onboarding.ts`：`finishPrologue` 调一次 `firstTasksMarkSeen`（起点口径，见上）。
- `save.ts`：读写归一——非字符串/空串丢弃；**没记过账不写键**。
- `index.ts`：导出两个新函数。

**渲染层**
- `game/engine.ts`：两个包装 `firstTaskNotice()` / `markFirstTaskSeen()`（与 `bountyNewCount`/`markBountyBoardSeen` 并列）。
- `App.tsx`：任务中心那支徽标改成 `bountyNew + (firstTaskNew ? 1 : 0)`；悬停文案两条合流；
  新增 `page === 'task'` 的记账 effect。
- l10n：新增 `ui.App.120`（中英）。

**用例**（`first-tasks.test.ts` 新增 3 例，与赏金那 4 例同款覆盖）：
推进 ⇒ 亮（带标题）· 记账 ⇒ 灭且幂等 · 再推进 ⇒ 又亮 · 13 条全完成 ⇒ 不亮且不写键 ·
**序章收尾记一笔 ⇒ 新档开局不亮、第一次推进后才亮** · 存档往返（**没记过账不冒出这个键**）。
