## 三、统一方案（按你的口径：能直接切就自动取消；只有高收益高周期的给警告）

### 规则（三条，覆盖全部入口）

1. **可自动取消的当前活动**（上表 1~7）⇒ 开始新活动时**自动停掉它**，写一条日志
   「已自动停止〔××〕（原因：开始〔××〕）」，然后照常开始新活动。**不再要玩家先手动停**。
2. **高收益 / 高周期的那几项**（**建议 = 长途运输**；见 §四 待你定是否加 远征/快递）⇒
   **两段确认**：首击弹警告（写清"将停止××、损失 = 本段报酬拿不到"），二击执行——沿用 2026-09-20 那套
   `ui.Hauling.033/034/035` 的样式与话术，**不新造交互**。
3. **不能自动取消的**（远征在途 / 快递在途 / 人在洞里 / **战斗中** / 换港返航途中）⇒ **仍然拒**，但文案统一改成
   "这趟不能中断：等它结束 / 先撤离 / 先打完这一场"（现在散在 9 个 errorId 里的措辞统一收口）。
   ⚠ **战斗中**（**2026-09-21 船长追加**）的判据单点建议 = `cannotInterruptReason(state)`：把三处战斗槽
   （`expedition.battle`（远征实时战）· `standby.battle`（掩护巡逻战）· `wormhole.run.battle`（洞内战））
   ＋在途低安遇袭场次一起判 ⇒ **战斗一律不可被"切活动"打断**（连站内的"亲自开炉/开线"也拒：主控正在打仗）。

### 落地要点（实现层面）

- **单点**：新增 `core/activity.ts` 的 **`haltCurrentFor(state, ctx, next)`**（把"要停谁、代价是什么、日志怎么写"
  收成一处，返回 `{ halted: ActivityKind | null; warn?: string }`），9 个 `start*` 入口改为调用它 ⇒
  **以后加减活动只改一处**（现在的 30+ 处 busy 检查是散在各模块的）。
- **警告名单**：`WARN_ON_HALT: ActivityKind[]`（初值 `['hauling']`，见 §四）。
- **文案**：统一日志 1 条 ＋ 统一警告头 1 条 ＋ 各活动"代价"短语（采矿/打捞"本趟货留在船上"·
  长途运输"本段报酬拿不到"· 扫描虫洞"进度保留"· 掩护巡逻"召回"· 开炉/开线"停炉/停线"）⇒ 约 8~10 条新 id（中英）。
- **界面**：启动按钮在首击遇到"会中断"时改成确认态（与长途运输那四点同款）；不能中断的仍置灰＋理由。
- **用例**：`tests/activity-switch.test.ts` 新增一张**矩阵用例**（9×9：可自动取消的必须切成功且日志正确 ·

### 九、玩家报障：「为什么我在采矿时无法直接切换精炼炉手动运转？」（2026-09-21 当晚修）

**根因两层，都不是判据写错，而是"顺序"和"界面留了一份旧名单"**：

1. **core 侧顺序**：`stationIndustryBlocked`（站内工业要求停靠空间站）原先排在统一判据**之前**；
   而**打捞 / 掩护巡逻 / 长途运输**在跑时会把舰船记成"不在站内"（`awayGalaxy` 非空）⇒ 玩家先撞上
   「需停靠空间站」，可实际上**一停机舰船就即时归位了**。现改：**统一判据在前、位置门在后**
   —— 四处站内工业（`startRefineRun` / `startRecycleRun` / `startUnboxRun` / `startManufacturing`）
   ＋ 长途运输的"野外不能接单" ＋ 远征的"出发地航路"都按这条重排（位置门正是被停机**满足**的那一条）。
   与停机**无关**的前置（物品/配方/材料/够不够一批/货仓）留原位（在判据之前）。
2. **界面侧**：`IndustryPage.manualBusyNote` · `Industry.manualBuildNote` · `Hauling.busy` ·
   `Expedition.pilotBusy` 各自还写着"采矿/打捞/远征/掩护巡逻在跑 ⇒ 按钮置灰"⇒ **core 通了、按钮还是灰的**。
   现改：界面只留"点了也白点"的两类（**位置** · **锁定态**）＋**同一个手动工作位**那两条；
   跨活动一律交 core 判（可自动停的照点，远征那类由 core 给统一拒因）。
3. **口径边界（本次未改，提请确认）**：
   - **同一个手动工作位**（精炼炉·回收炉·拆解·制造线）之间仍是**硬拒**——它不算"切换活动"，而是同一工位
     换机器，停掉会**丢掉手上那一批**（稀有残骸一炉一箱，丢了是真损失）⇒ 不替玩家做决定。
   - **换矿带**（开采 → 同一活动的另一个矿带）仍是"先停再开"（`startMining` 的同项自检），界面也照旧置灰。
4. 新用例：`industry.test.ts`「**位置门排在统一判据之后**」（掩护巡逻中直接开炉 ⇒ 停巡逻 + 开工；
   运输中 ⇒ 回两段确认那句警告且不停；纯野外 ⇒ 仍旧位置门拒）；`t9.test.ts` 的位置门三例改用**真实 id**
   （假 id 会先撞"未知物品"，验不到位置门）。
