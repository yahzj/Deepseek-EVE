## 一、真因（探针实测 · 四个场景，人都在穹顶墓园）

旧判据 = `beaconLaunchHighSecOf` 里看 **`playerGalaxyIdOf(state)` = `awayGalaxy ?? 母港`**；而
**采矿/打捞期间 `awayGalaxy` 是被有意清空的**（那批"站内工业门槛"报障的修法，见 `location.ts`
「而**采矿期间却能开**（`startMining` 会把 `awayGalaxy` 清空）」那段注释）。

| 场景（人都在穹顶墓园 · security −1.0 = 低安） | `awayGalaxy` | 旧判据取到的"玩家所在" | 旧结果 |
|---|---|---|---|
| ① 在穹顶墓园**采矿**（`startMining` ok） | `null` | **大鲸鱼Ⅳ（高安）** | **误报警告** ← 报障现场 |
| ② 在穹顶墓园打捞（作业态） | `null` | **大鲸鱼Ⅳ（高安）** | **误报** |
| ③ 在穹顶墓园**野驻**（「前往」） | `galaxy-vault` | 穹顶墓园（低安） | 不警告 ✓ |
| ④ 对照：人真在母港 | `null` | 大鲸鱼Ⅳ（高安） | 警告（符合旧口径） |

⇒ **错的是"玩家在哪"那个取数口，不是规则本身**：同一个地点（③ vs ①）两种结果。
连带后果：声望够则**白扣 10 点**、不足则**直接点不着火**。

## 二、改法（逐条）

1. **`packages/core/src/consumables.ts`**：`beaconLaunchHighSecOf(ctx, targetGalaxyId?)`
   —— 判据 = **目标星系属高安**（`securityZoneOf(ctx, targetGalaxyId) === '高安'`）；
   不传目标（默认那条路：候选集随机抽、候选集本身排除高安）⇒ 一律 false。
2. **删掉 `playerGalaxyIdOf`**（含 `index.ts` 的导出）：它把"玩家在哪"简化成 `awayGalaxy ?? 母港`，
   采矿/打捞期间必然错 —— 正是这次误判的根；改判后它已无消费者（全仓 grep 确认）。
3. **星图**（唯一有"选定目标"的入口）：判据传 `galaxy.id` ✓；**警告里的星系名改传 `galaxy.name`**
   （= 这一页正在看的、也就是玩家选定的那个）——旧代码传的是"玩家所在地"的名字，所以警告才写着大鲸鱼Ⅳ。
4. **物品页 / 货仓页**：这两条是**默认那条路**（没有选定目标）⇒ 判据恒 false，原来的"二次警告弹层"
   永远不可能出现 ⇒ **连同状态与 import 一并删掉**（不留死代码）。
5. **core 扣声望那条日志**：文案里的星系 = **选定的目标**（原来是"玩家所在地"）。
6. **用例**：`tests/invasion-beacon-20260930.test.ts` 按新口径改写（触发条件从"把 `awayGalaxy` 挪到高安"
   改为"目标取一个属高安且无空间站的星系"）＋**新增报障回归**：在穹顶墓园采矿时选定穹顶墓园 ⇒ 不警告、
   不扣声望、不写 `beaconHighSec` 留痕。
