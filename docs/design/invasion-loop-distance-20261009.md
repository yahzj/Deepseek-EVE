# 入侵循环期望距离变化核查

> **状态：已实现，专项与双端构建通过，待验收及合入**（二号 · d2/workspace · 2026-10-09）
> 船长原话：「玩家反应BUG，循环作战时，打的是同样的入侵，但是设定的目标距离会变化」。
> 范围：船长回复「确认」批准下方修复范围，保留入侵主动出击/循环与旗舰的目标距离；不读写玩家真档、不改变普通悬赏/虫洞距离规则或自动换星系机制、不混入此前推送工作。
> 待裁决点：无。

## 现状

- `setBattleDesire` 与 `beginBattleAt` 均按实际作战星系保存/读取；循环入口没有显式改写距离。
- 设置时按当前波战场上限钳制，开战时按首波 `battleOpenM` 钳制。后波较远的选择在下一场可能被压小，但偏好表仍保持原值。
- 循环收复后会换星系，各星系本来独立保存距离，需与同一星系复现分开。

## 合成档复现（不读玩家真档）

- 同一场C族入侵、同一作战星系 `galaxy-kor`，巨齿鲨装激光MK1；第二波选择可用最远距离、结束并重新开同一张卡。
- `alien-escort`：首波上限6072m，第二波6600m；选6600m、偏好表6600m，下场开局却6072m。
- `alien-main`：首波上限6072m，第二波8250m；选8250m、偏好表8250m，下场开局却6072m。
- 对照单波 `alien-vanguard`：6072m→6072m，未发生变化；墨潮两波卡也出现同类首波钳制。
- 根因：`combat.ts` 单舰与编队开局用 `Math.min(openM, rawDesire)`；`openM` 来自首波。`setBattleDesire` 则按当前波 `battleMaxDistanceM` 允许选择更远距离。开局不会重写偏好，但本场 `myDesireM` 缩小且后波不恢复。
- 原有 `desire-invasion-20261002.test.ts` 只检查5000m，低于此次首波上限，无法发现此边界。
- 另验证自动换到外围时使用外围自己的偏好（未设置则默认4416m），不与上述同星系同卡问题混为一谈。
- 关联距离记忆与循环路线19项既有测试通过；一次性探针复现通过后删除，未修改业务代码。

## 已确认修复范围

- 入侵的已保存目标距离保持玩家选择，开局不因首波上限永久压小；实际交战距离仍按当前波合法范围约束，不扩大武器射程。
- 兼容手动入侵及循环入侵，核对旗舰编队路径；普通悬赏/虫洞默认距离规则不动，自动换星系仍用各星系独立偏好。
- 增加同星系同卡连续出击、不同入侵卡切换、跨波及读档回归；不迁移或改写玩家真档。
- 若实施需要改变既定首波钳制规则或新增随档字段，先明确方案与边界，不以报障直接扩大共享战斗规则。
