## 一、需求与裁定

船长原话：「**装配界面，添加一个保存当前装配和使用预设装配的功能。**」

集中提问四问四答（全取推荐档）：

| 问 | 答 |
|---|---|
| 归口 | **按船型（`defId`）** —— 同型号任意一艘（含以后新建的）都能套用 |
| 套数 | **每个船型 3 套** |
| 存什么 | **三类槽位装备（高/中/低 逐位）+ 无人机舱装载** |
| 不足时 | **尽力装 + 逐条提示**（装上的保留，未装的逐条列出） |
| 套用前旧装备 | **先卸光再装**（全部卸回装备库、无人机退回仓库） |
| 入口/命名 | 入口 = **「装配目标」栏右侧**；命名 = 玩家自定（默认「方案 N」，列表内可重命名） |

## 二、口径（正文在 `fitPresets.ts` 头注释，此处摘要）

- **方案内容**：`fitted { high/mid/low: (id|null)[] }`（**尾部空位已裁**）+ `droneLoad`。
  **不含弹药档位**（弹种仍在装配页右栏手动设）。
- **套用 = 先卸光再装**：① 三类槽位全部卸回装备库（`unfitAllModules`）→ ② 无人机全部退回仓库
  （`clearDroneLoad`）→ ③ 按方案逐位装 → ④ 无人机按方案装载 → ⑤ 弹一条结果小结 + 写日志。
- **装配顺序**（结果可复现、且避免"假超载"）：**扩容件（`cpuBonus > 0`）→ 高 → 中 → 低 → 无人机**。
  协处理器给 CPU 预算，先装才不会让后面的件被误判超载；逐件走 `fitModule`（自带四道校验：
  进洞锁定 / 装备库有货 / 位可用 / CPU 预算）⇒ **中间态永不超载**。
- **尽力装 + 逐条提示**：装备库缺件 / CPU 超预算 / 未知（下架）件 / 无人机缺货或机舱不足
  ⇒ 逐条进"未装"清单；小结形如
  `已套用「主力」（亡军鱼雷舰）：卸下 8 件 · 装上 6 件 · 装入无人机 4 架 · 装备库缺 1 件（亡军残炮）· 1 件未装（…：装配超载…）`。
- **槽位布局对齐**：方案数组若比目标船长（数据改动后出现）⇒ **超出的位丢弃、不足的位留空**，不报错。
- **锁定**：进洞中 / 自动探索中的船，**保存 / 套用 / 重命名 / 删除 / 一键卸下**一律拒绝
  （船长 2026-09-13：「进洞船只所有行为都锁定」）。锁判定放在 `unfitAllModules` **函数内**
  （装配页「一键卸下全部装备」按钮直接调它，不能只靠套用入口的判定）。

## 三、数据与存档

- 新字段：`GameState.fitPresets?: Record<defId, ShipFitPreset[]>`（类型 `ShipFitPreset` 在 `state.ts`）。
- **零迁移、不升版本**（`CURRENT_STATE_VERSION` 保持 **25**）：与同日 `shipStore` / `wormholeScan` 同款落法
  —— 可选字段 + 归一化清洗 + **缺省不写键**。⚠ 归一化是**逐字段重建**，新字段必须同步进 `normalized`
  对象（否则读档静默丢，本项目踩过两次）；且**只在真有方案时才落键**（无条件写空表会让老档往返多一个键，
  `toEqual` 快照用例会红——`bountySeenWindow` 的教训）。
- **清洗规则**（`save.ts`，本层拿不到内容表 ⇒ **不校验 id 是否存在**）：每型 ≤ **3** 条 ·
  名称去空白并限长 **12** · 位数组只留非空字符串、裁掉尾部空位、长度 ≤ 7（槽位上限）·
  无人机只收正整数 · **全空方案丢弃** · 删空 ⇒ **字段一起清掉**（回到"老档形状"）。
- **下架/未知装备**：不在清洗层丢（拿不到内容表），而在**套用时**逐条报进"未装"清单。

## 四、界面

- 「装配目标」栏右侧加两个按钮：**保存装配**（存当前实装为方案）· **装配方案 N/3**（打开方案浮层）；
  浮层复用既有 `app-fit-overlay` / `app-fit-modal` 结构与 `app-btn` 档位，列表每行 = 名称 · 摘要
  （`fitPresetBrief`：`装备 8 件（高 4 / 中 2 / 低 2） · 无人机 2 型 5 架`）· **套用 / 重命名 / 删除**；
  底部 = 「把当前装配存为新方案」+「一键卸下全部装备」（次要危险档）+ 套用语义说明一行。
- 满 3 套时保存会失败并**自动把列表打开**（让玩家先删一套或覆盖同名）。
- 样式新增 `app-fit-preset-*`（复刻同级 `app-fit-*` 语言；**双倍行距**与本文件一致）。
  ⚠ **一级页不滚**：控件加在**既有那一行内**（该行本来就是 `flex-wrap`），浮层是 overlay 不占页高；
  窄窗下该行可能多折一行——**观感/几何请船长过目**（我没截图）。

## 五、取舍与已知边界

1. ⚠ **先卸光 + 尽力装的固有代价**：方案凑不齐时，套用后**可能比套用前更差**（旧装配已回库）。
   这是船长选定的语义；小结与日志会逐条列出缺什么、哪几件未装。
2. **一键卸下全部装备不动无人机**（机舱还在）；卸下甲板扩展导致舱容变小时，超出的无人机按既有规则
   自动退回仓库（`trimDroneLoadToBay`）。
3. **不做**（本次边界）：跨船型共享方案 · 方案导入导出 · 拖拽排序 · 自动买件补货 · 弹药档位随方案。

### 6.1 「一级页不滚」实测读数（**读数型**，不是观感结论）

正式工具 `tools/ui-geom.ts` 需要**四份手工导出的输入档**（当前没有），故本轮用**一次性无头探针**
（`_` 前缀、用完即删）量了三档窗口 × 装配页（与 `ui-geom` 同口径：`scrollHeight > innerHeight`）：

| 窗口 | 页面纵向滚动 | 页面横向滚动 | 页高 | 「装配目标」栏高 | 方案控件 |
|---|---|---|---|---|---|
| 1600×1000 | **false** | false | 1000 | 39（单行） | 151×21 · 2 按钮 |
| 1366×768 | **false** | false | 768 | 39（单行） | 151×21 · 2 按钮 |
| 1024×768 | **false** | false | 768 | **66（折两行）** | 151×21 · 落第二行 |

⇒ 红线成立：**三档都无滚动条**；窄窗（1024）下该行折成两行、控件落到第二行，**页高未涨出视口**。
浮层为 overlay（`app-fit-modal`，内部可滚 = 二级窗，符合「滚动只进二级窗」）。

### 6.2 运行时冒烟（同一探针，改样式/接线后复跑）

- 点「保存装配」（新游戏初始装备库为空 ⇒ 空装配）⇒ **被拒并弹提示**：
  「这艘船现在没装任何装备、机舱也是空的：先装几件再保存（要清空装配请用「一键卸下全部装备」）。」，
  同时自动打开方案浮层显示空态「还没有方案——…」、计数 `0/3`。
- 浮层「关闭」、行内两按钮（`保存装配` / `装配方案 N/3`）渲染与点击均正常；全程页面无纵向滚动。
- 换装浮层在空装备库下给出既有提示「装备库没有适配此槽位的装备——市场购买或…」（**非本批引入**，
  探针顺带核过：新游戏初始 `moduleBay` 为空 ⇒ 候选 0 属正常）。

### 6.3 ⚠ 本轮抓到的一处不一致（已修）

冒烟时发现：**空装配也能存成方案**（显示「装备 0 件」），而 `save.ts` 清洗的规则是**全空方案丢弃**
⇒ 玩家存下的空方案会在**读档后无声消失**。已改为**保存即拒**（与清洗层对齐；要清空装配请用「一键卸下全部装备」），
并补用例「空装配不许存 / 只装一件或只装无人机就能存」。

- **负向验证两处（各自精准）**：① 归一化改无条件写键 ⇒ 只有「存档」用例红（`expected {} to be undefined`）；
  ② 拿掉 `unfitAllModules` 的锁判定 ⇒ 只有「锁定」用例红（`expected true to be false`）。
  ⚠ 第一处最初写的断言**咬不住清洗层**（`serializeSaveFile` 走内存态、不经过 `normalizeState`），
  负向验证暴露后补了直压清洗层的断言——这条记下来给后来者。
