## 推荐决策

### 1. 重连两阶段

- 点击重连即暂停该文件写入并失效旧请求令牌；暂停的是文件目标，正常浏览器存档仍可保存。
- 权限申请保留用户手势链，不先等待游戏保存或队列清空。权限获批只表示可读取，不立即恢复自动写入。
- 权限后等待此前已开始的文件写入收尾，再读文件；已排队且尚未开始的旧快照不能在授权后落盘。
- 读取、大小限制、BOM 处理与 `loadSaveFile()` 校验分别处理；空文件、过旧档、非法文件、拒绝权限、读取失败都不覆盖原文件。
- 文件、当前进度与浏览器持久化快照比较时使用有效状态内容，不只比较墙钟时间；剥离会话日志与保存时间等不代表进度的元信息。同一保存时刻而内容不同仍是冲突。
- 只有确认内容等价才直接恢复写入。任何进度差异均显示选择，不因文件较旧而自动覆盖。现有启动时取较新策略本批不全局改判，重连是单独的来源重新出现流程。

### 2. 三个选择

| 选择 | 行为与失败政策 |
|---|---|
| 载入文件进度 | 严格校验，沿既有导入修复链、离线结算和铁人门禁；先准备候选并提交浏览器存档，成功才替换当前内存，再开启文件写入。校验或浏览器保存失败时保留当前游戏与原文件，不开启新档代替坏文件。 |
| 保留当前并覆盖文件 | 选定时冻结当前进度快照，明确警告会替换文件进度；成功才恢复文件写入。失败保留暂停与重试入口。 |
| 取消 | 不覆盖文件、不替换当前进度；文件维持暂停，浏览器存档按既有政策继续保存。关闭弹层、Esc 与遮罩均按取消处理。 |

- 没有强档案身份字段，不能把角色名/创建时刻当可靠身份；摘要只作玩家辨识，所有不同进度都询问，不增加随档身份字段。
- 选择提交前重读文件：若与展示时的文件不同，重新展示选择，不按旧确认覆盖新内容；选择请求与绑定句柄代次配对，解绑/换绑后旧确认不得生效。
- 文件与浏览器存储不能跨介质原子提交；载入成功但随后文件写失败时明确报告“已载入，文件写入暂停”，保留浏览器里已提交的候选和文件原内容，不伪装成整体未发生。覆盖当前文件成功但浏览器保底失败时也要明确报告部分成功，不再次用旧快照回滚文件。
- 取消后的保护持续到再次确认，不因关设置、下一次 tick 或失焦解除。刷新后也不能仅凭已获权限立即覆盖此前未解决的文件冲突。
- 系统授权与任意外部应用没有跨进程事务保证；提交前重读能检测已发生的变化，不能宣称能锁住用户编辑器在检查后的写入。
- 不新增恢复/导入自动备份（沿 2026-09-17 既有裁定）；不改变铁人救援条件、奖励或导出代次政策。

### 3. 多标签页：单写者

- 推荐同一 origin 一个游戏写入者，用 Web Locks 排他锁，在读档/存档体检之前取得；覆盖浏览器主档、备份、账本与绑定文件。
- 已运行页面保持写入权；新开的第二页不启动另一套游戏推进，停在提示界面，允许查看存档摘要和导出已保存快照，不绑定、恢复、重置或写账本。
- 不因切后台释放写入权，避免两个活着的游戏轮流保存。原页关闭后，第二页点击重新载入；必须重新读持久化快照，不直接把旧内存升为写入者。
- 不支持 Web Locks 或锁请求异常时推荐保护性降级：只读提示＋导出，不用 localStorage 时间租约冒充互斥。此项影响较旧浏览器，须船长确认；不能悄悄退回双写。
- 覆盖页恢复、崩溃与 BFCache；页面恢复后要核对写入权，无权则停止写入并要求重载，不用无条件释放锁＋延时抢占。

## 界面与文案草稿

- 参照同域 `SaveManager.tsx` 与设置中的 `app-modal` / `app-settings-row`，不新建样式体系、不嵌套卡片、不变更页面信息架构。
- 单个冲突弹层：当前进度与本地文件两个摘要列，窄窗换成上下排列；角色名、保存时刻、游戏时长与铁人代次均从已校验快照读取。
