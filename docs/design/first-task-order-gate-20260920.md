## 一、根因：显示一把尺、判定另一把尺

顺序解锁（船长同日第一道令）当初只落在**显示**上：`visibleFirstTasks` 只给"数组序里第一条没完成的"，
而 `advanceFirstTasks` **每拍把 13 条全判一遍**。于是"任务中心只显示 1 条"是真的，但**任何一条的条件一旦满足就会当场判过**——
不显示也照样：

- 发**一次性奖励**（采集器/打捞器/蓝图书/鲣鱼级/基础 AI 核心…）；
- 发**情报信**（`commsDelivered[taskId]`）并可能弹窗；
- 点亮**成就徽章**（`ach-first-*` 直接读 `importantTasks[taskId].done`）；
- 让**里程碑页**提前解锁该链（`unlocked` = 对应「第一次」已完成）；
- 让「寻找人类」的发布闸门（= 13 条全完成）**提前**满足。

玩家侧表现就是船长看到的那句：**列表里还没出现过的任务，自己先完成了**（例如先手动打赢一场悬赏，
任务中心还停在别处，「第一次完成悬赏」已经打完并悄悄发了船）。

## 二、修法：只判当前那一条（显示什么就判什么）

`packages/core/src/firstTasks.ts` → `advanceFirstTasks`：

```ts
const current = FIRST_TASKS.find((d) => state.importantTasks[d.id]?.done !== true)
if (!current) return []               // 13 条全完成
if (current.judge(state, ctx) < 1) return []
state.importantTasks[current.id] = { done: true }
return [current.id]
```

三条口径（都写进了函数头注释）：

1. **只判当前那一条**：后面的条目即便条件已满足也**不提前判过**（不提前发奖励/情报信/成就/解锁）。
2. **一拍最多判过一条**：完成一条后要等下一拍才轮到下一条（避免"一口气跳完"）。
3. **判据仍读 `state` 现状 ⇒ 自愈、进度不丢**：玩家先干的活不会白干——轮到它那一拍按档内现状**补齐**
   （`firstStats` 计数 / `exploredGalaxies` / 声望 / 技能等级都是状态，不靠"当拍事件"）。
4. **老档迁移不受影响**：`save.ts` 的 v25 迁移是把 13 条**一次性**写成 `done`（不经过本函数）。

  模块头与 `visibleFirstTasks` 的注释补上"**判定的当前条与显示的当前条是同一把尺**"。
  **其余一字未动**：`visibleFirstTasks` / `firstTaskProgress` / `firstTaskNotice` / `milestoneBoard` / 13 条判据与奖励表。
- 未新增状态字段、未动存档结构（`CURRENT_STATE_VERSION` 仍 **v30**）。

**用例**（`packages/core/tests/`）
- `first-tasks.test.ts`：新增 `reachQueue(state, taskId)` 夹具（把排在它前面的任务标 `done` = "队列走到它了"，
  **只写标记、不发奖励**），并把 6 条"越序完成"的既有用例接上它
  （精炼/维修/悬赏/生产/造船/虫洞）；「第一次学习技能」那例同款。
- `first-tasks.test.ts` **新增 1 例**（本次报障的回归钉）：
  「未显示的第一次任务**不能提前完成**」——把维修/虫洞/采矿判据全做掉后推一拍 ⇒ **只有**当前那条
  （第一次扫描）判过，其余不判过、不给奖励（`repairkit-civ` 0、`wormholeStock` 0）；下一拍只前进一条；
  再 `reachQueue('first-repair')` ⇒ 轮到即补齐、奖励照发（**自愈**）。
- `achievements.test.ts`：那例"任务判定与链记账同拍可见徽章"补 `reachQueue('first-repair')`（同款夹具）。

**工具**
- `tools/flow-newgame.ts`：**按新的队列顺序整篇重排**（动作顺序 = 队列顺序，否则后面的条目拿不到判定），
  并补上原先没走的两步：**⑥ 第一次打捞残骸**（装打捞器 → 母港残骸点打捞，基础密度 > 0）
  ＋ **⑪ 第一条船**（学会 `sbp-sandcat` → 备料 200 三钛 / 50 类晶体胶矿，不足则"再跑矿 → 再炼" → 造船交付）。
  ⑦⑧ 两步专门钉本次报障：**先打赢悬赏**（`bountyWins=1`）⇒ 断言队列仍在「第一次维修舰船」时
  「第一次完成悬赏」**没被提前判过、也没发船**；修完船轮到它 ⇒ 下一拍补齐并发奖励。
  收尾加两条硬断言：**已完成集合正好 = 队列前 11 条**（多一条就是"跳级完成"复发）＋ 当前队列 = 「第一次长途运输」。
  头注释同步（含"为什么动作顺序必须等于队列顺序"）。

## 四、影响面 / 已知副作用（登记备查）

1. **演习场照会战加成会多挂一段**：`isFirstBountyBattle`（命中/回避各 +0.5 的教学加成）判据是
   「打演习场驱逐令 ＋ 本舰主控 ＋ `first-bounty` **未完成**」。判定变严后，这条任务要等**维修做完**才判过 ⇒
   加成在"赢了第一场但还没修船"这段里**继续生效**（旧口径在赢下第一场的那一拍就失效）。
   按"任务未完成就还算教学场"讲得通 ⇒ 已上报船长，**船长裁定（2026-09-20）：「不影响。」** ⇒ **保持现状、不改码**。
2. **`docs/design/task-center-seq-milestone-20260920.md` §五**那句「`first-ai` 还没轮到——但它的**判定与可见性无关**，
   流程里照样指派并判完成」**随本件作废**（新口径下判定与可见性同源；该件的 `flow:newgame` 断言已重写）。
   该文件是同一批的工作文档，按 §8 不在工作期间回头改，**归档时以本件口径并入 glossary/roadmap**。
3. **工具与用例的"越序"写法要显式走 `reachQueue`**：直调 core 的探针（不经引擎）不受影响；
   凡"跳过队列验某条奖励"的地方，今后都要先声明"队列到它了"，否则会静默变成"没判过"。
4. **玩家侧唯一可见变化**：任务中心里**已显示的那一条做完才会轮到下一条**，且不再出现
   "没见过的任务先完成"（奖励/情报信/成就同步对齐）。
