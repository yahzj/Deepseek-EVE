## 〇、一句话结论

**卡顿 = 切过去的那个子页要从零把卡片 DOM 造一遍，代价 ∝ 卡片数 × 单卡节点数。**
组装机 **151 张 × 55 节点 = 8298 个节点**，四个子页里最重；把 CPU 降速到 1/6（代理"配置差的机器"）后，
切一次组装机原来要 **1.56 秒** —— 这就是玩家说的「数秒的卡顿」。

**三步做完后的复测（同档、同种子、同一台机器、同一降速倍率）：**

| 读数 | 改前 | 改后 | 变化 |
|---|---|---|---|
| **切组装机（1×）** | 154.3 ms | **7.7 ms** | **−95%** |
| **切组装机（6×·弱机代理）** | 1563 ms | **65.1 ms** | **−96%** |
| 切造船厂（1× / 6×） | 78.9 / 1660 ms | 28.7 / 340 ms | −64% / −80% |
| 组装机挂机主线程占用（1×） | 35.4% | **8.5%** | −76% |
| 造船厂挂机占用（1×） | 22.1% | 11% | −50% |
| 对照组：技能页挂机占用（1× / 6×） | 15.4% / 97.1% | 10.3% / 97.4% | 未动（见"还剩什么"） |

⚠ **仍然要船长看观感**：滚动条与落点（第 1 步的占位高度）、切换后面板内筛选/滚动位置不再复位（第 2 步）——
这两条是行为/观感变化，读数只能证明"几何没漂、界面还活着"，好不好只有船长能判。

## 一、复现方法与读数

工具 `npm run industry:lag`（正式入库，可复跑）：

1. 构建网页版 → 本地托管 → 无头 Chrome（**非默认调试端口**）；
2. CDP 发**真实鼠标点击**（不是 JS `.click()`，才会带上输入排队），按三段计时：
   `输入排队`（事件处理器开跑 − 浏览器给这次输入打的时间戳）＋ `提交`（新面板进 DOM − 处理器开跑）＝ `端到端`；
3. `Performance.getMetrics` 增量量主线程去向（任务／脚本／布局／样式）、`PerformanceObserver('longtask')` + rAF 采样量长任务与掉帧；
4. `Emulation.setCPUThrottlingRate` **降速倍率 N** 代理弱机（对比优化前后必须用同一个 N）；
5. **活值探针**：同一子页静置 5 秒，比面板全文行差 ⇒ 用来判"这块界面还活着吗"（防 `memo` 冻住实时数）；
6. **交互回归** `--act`：点一张卡的「AI 制造」，看这张卡自己是否变化、倒计时是否持续在走；
7. `--explore` 节点构成 · `--bg` 背景隔离（A-B-A-B）· `--cv`/`--css` 候选规则**先试后报** · `--diag` 抓页面异常。

存档：`docs/test-saves/save-20260920-164600.json.json`（后期档 466 KB · 组装机 151 张卡）。

### 1.1 一次切换要多久（端到端 = 玩家感受到的"点了到换过去"）· 改前

| 目标子页 | 面板节点 | 1× CPU | **6× CPU（弱机代理）** |
|---|---|---|---|
| ♨ 精炼炉 | 1,404 | 0.6 ms | 26 ms |
| ⚒ 组装机 | **8,298** | **154 ms** | **1,563 ms** |
| ⚓ 造船厂 | 3,367 | 79 ms | **1,660 ms** |
| ▦ 蓝图书架 | 148 | 11 ms | 166 ms |

连点 8 次的序列：1× 中位 **75 ms**；**6× 中位 797 ms / 最大 1399 ms，最长长任务 1389 ms**。
逐次明细（1×）**高度可复现**：→ 精炼炉 21.5 与 25.3 ms · → 组装机 **138.2 与 133.2 ms** · → 造船厂 75.4 与 75.3 ms · → 蓝图书架 11.4 与 11.1 ms。

⇒ **同一张卡点两次（138.2 → 133.2 ms）几乎一样** ⇒ 每次都是**全量重建**、没有复用；
耗时几乎是节点数的线性函数：**≈16 µs/节点（1×）· 每张卡 ≈0.9 ms**。

### 1.2 挂机（不点任何东西）主线程被吃掉多少 · 改前

| 当前子页 | 节点 | 1× 占用 | 6× 占用 | 活值变化行数（5 秒） |
|---|---|---|---|---|
| ▦ 蓝图书架 | 148 | 7.5% | 58% | 0（本就静态） |
| ♨ 精炼炉 | 1,404 | 27% | 102% | 21 |
| ⚓ 造船厂 | 3,367 | 22% | 110% | 105 |
| ⚒ 组装机 | 8,298 | 35% | 102% | **155** |
| 对照组：技能页（无重面板） | 1,471 | 15% | 97% | 1 |

- 提交次数实测 **1–2 次/秒**，与引擎 1 Hz 心跳对得上；每次提交 = **整棵 App 树重渲染**（`App.tsx` 的 `force()`）。
- 6× 下**整机被吃到 ~100%**：此时点任何东西都要排队（实测输入排队中位 22 ms、最大 54 ms）。

### 1.3 已排除的两条

- **引擎计算**：`npm run industry:perf` 全项 < 0.1 ms（上一稿已证），与"数秒"差 4~5 个数量级。
- **背景动画（星野/星云/氛围光）**：把背景层 `visibility:hidden` 做 **A/B/A/B 四窗交叉对照** ⇒
  主线程占用 13.7% → 9.2% → 9.3% → 11.2%，**方向不一致、不成立**（第一窗偏高是切页余温）。**不是它**。

## 二、根因（三条，均有读数）

1. **切换 = 冷启动重建**：`pages/IndustryPage.tsx` 原是三元链 `sec === 'craft' ? … : 'shipyard' ? …`，
   同一时刻**只挂载一个**子页 ⇒ 旧面板整棵卸载、新面板从零造。
2. **单卡很贵**：组装机 **55 节点/卡**（151 张）、造船厂 53 节点/卡（57 张）；大头是**每行材料**的
   「×N（原 ×M，折扣后）（仓库 K）⚒ 去精炼」——一行材料 ≈3~4 个节点。
3. **每秒 1~2 次整树重渲染**：卡片上写着**实时仓库数量**（组装机 5 秒内 155 行文本在变、造船厂 105 行），
   ⇒ 这些数**不能靠 `memo` 冻住**（冻住就变成"数字不再更新"的 BUG）。

## 三、改法与实测（三步全部落地）

### 第 1 步（`.app-belt-card.is-assembler` 加两条 CSS）· 提交 `094901c8`

```css
.app-belt-card.is-assembler { content-visibility: auto; contain-intrinsic-size: auto 523px; }
```

原理：屏外卡片**跳过布局与绘制**（脚本仍要造节点 ⇒ 只能省掉一半，实测正好一半）。
**占位高度 523px 是"先试后报"选出来的**（`--css` 逐条实测）：

| 占位高度 | 网格总高（真实 20455） | 滚动落点是否漂 |
|---|---|---|
| 300px | 13360（−35%，滚动条明显缩水） | — |
| 547px | 21403（+4.6%） | 4000/8000/14000/19000 四处不同 |
| **523px** | **20611（+0.7%）** | 与改前**同一套落点**；"整表滚一遍"前后总高与落点**完全一致（无滚动中跳动）** |

另：前 8 张卡 640 个元素的**矩形零漂移**（文本相同却位移的元素 = 0 处）⇒ `contain` 没有挪动任何东西。

### 第 2 步（四个子页**保活**，切换只切显示）

`pages/IndustryPage.tsx`：`seenSec`（进过一次就常驻）+ `.ind-pane`（`display: contents` 参与原 flex 布局 /
`is-off` 时 `display: none`）+ `styles.css` 两条规则。
行为变化（已报船长）：面板内部的筛选/搜索/滚动位置**不再因切换而复位**；
另把"高亮定位"的 `querySelector` 收紧到**当前显示那一栏**（否则可能滚到隐藏栏里的旧高亮）。

### 第 3 步（卡片按"实时指纹"`memo`）· 提交 `70f703d8`

- 目录模型移进 `useMemo`（依赖 `engine.ctx` / `engine.blueprints`，二者只在换语言时一起重建）；
  模型里删掉随心跳变的字段 —— 原来那两个 `running` / `canStart` **全仓无人读**（只有赋值没有读取），
  顺带省掉每拍 151 次 `missingMaterials`；`ownedCount` 改为 `countOwned` 闭包、卡片现取。
- 新增 `cardLiveKeyOf(...)`：把卡片真正显示的**每一个实时读数**串成指纹（材料库存 / 折扣后需求 /
  制造线剩余与进度 / 循环批数与停因 / 学会与书存量与名额 / 收藏星标 / 产物持有量），逐条注释对应卡面位置。
- `BlueprintCard` 改 `memo`：父级每拍算指纹，只有指纹变了的卡才重渲染。造船厂同款。

## 四、还剩什么（**没修**的部分，如实列出）

1. **弱机档整机仍然吃满**：6× 下技能页（**完全没有工业面板**）挂机占用仍是 **97%**，
   工业页也回到同一量级 ⇒ 瓶颈已不在工业页，而在**"每秒整棵 App 树重渲染 + 那部分非脚本非布局的主线程开销"**。
   这一条要动的是全 App（`App.tsx` 的 `force()` 与分域订阅），**超出本工单**，请船长定是否另开一单。
2. **首次进入组装机仍要一次冷启动**（1× 7.7 ms / 6× 65 ms，已经很小）；要再降只能减卡内节点（第 5 步）。
3. 保活后工业页常驻约 1.3 万节点（内存/首屏），可接受但记在这里。
