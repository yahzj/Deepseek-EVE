# 战报改造（2026-09-14 · 状态：已确认）

> 船长原话（照抄）：「**战斗胜利后的战斗报告现在过于简陋，并且假如在虫洞内，我方损失了舰船也显示大捷。**」
> 船长批准（同批五答）：取正文方式 **甲**（引擎写结构化战报）· 判定词 **甲**（四档）·
> 内容 = **弹药消耗 + 双方各层残余 + 我方沉船名单**（机群战损、维修消耗两行已有，保留）·
> 版式 **甲**（保持现有单卡片只加行）· 关闭时长 **甲**（12 秒 → **20 秒**）。

## 一、两个报障的根因（都在"取正文的方式"与"判定只看胜负"上）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 「过于简陋」 | 弹层正文靠**在事件日志里找含「战报」二字的那条**（`battleViewCore.lastBattleReport` 的字符串匹配）。而**洞内战斗**写的是「🕳 第 N 层…交火结束：…」、**低安遭遇**是「★ 遭遇战大捷（…）」、**无法交战**是「⚔ 无法交战（…）」——**三条都不含「战报」** ⇒ 那三类战斗的弹层**永远取不到正文**，只剩兜底句「大捷：敌方编队全灭，舰队开始返航。」 |
| 2 | 「损失了舰船也显示大捷」 | 标题只看 `ended === 'me'`（`won ? '⚔ 大捷' : '⚠ 失利'`）⇒ **完全不看我方损失**；卡片上**根本没有"损失"这一行**（沉船只在日志里各写一条） |

## 二、四档判定（引擎出判定，界面只显示）

| 情形 | 判定 | 界面 |
|---|---|---|
| 胜 + **零沉船 且 机群无净损失** | `great` | **⚔ 大捷** |
| 胜 + **有沉船 或 机群有净损失** | `pyrrhic` | **⚔ 惨胜（损失 N 艘）** |
| 我方全灭 / 结构归零判负（含弃船） | `defeat` | **⚠ 失利** |
| 未分胜负就中止（结构撤退 / 超时 / 无法交战 / 主动撤退） | `break` | **⚠ 脱离** |

- 判定 = core 纯函数 `battleVerdictOf(record)`（**纯函数才进得了用例** —— 渲染层没有测试运行器，
  上一轮的弹道 bug 就吃过这个亏）。
- **「惨胜」沿用胜色（金色）**，只在标题里带损失数 —— 不新增一档配色（船长 2026-09-14 批准）。
- ⚠ **超时**在本引擎里"按被迫撤退处理"是**结算口径**（轻损、不弃船），与这里给的**判定词**
  （`break` → 「脱离」）是两件事，别把两者混起来读。

## 三、结构化战报（唯一构造点）

`GameState.battleReport?: BattleReportRecord | null`，**不落档、零迁移**（照 `droneLossReport` /
`wormhole.lastSettle` 惯例；老档读到 `undefined` ⇒ 弹层回落兜底句）。

| 字段 | 来源 / 口径 |
|---|---|
| `battleStartedAtGameMs` | 弹层靠它与自己的快照**配对**，防并行战斗（AI 副船）串场 |
| `source` | `'expedition' \| 'encounter' \| 'wormhole' \| 'ai'`（只选措辞，不参与数值） |
| `outcome` + `breakReason?` | 四档判定；`breakReason ∈ {hull, timeout, cannot-engage, manual}` |
| `durMs` / `stats` | 与 `battle.stats` **逐字同源** |
| `shipsLost[]` | 调用方给了就用（洞内传船长口径的显示名），否则从 `battle.units` 推导（我方且三层血合计 ≤ 0） |
| `myUnits[]` | 逐舰 盾/甲/结构（当前 + 上限）；单船 = 只有 `player`，多舰 = `myFleet` 顺序（主控在前） |
| `foe` | `alive` / `total` / `hpFrac`（`hpMax` 为分母） |
| `ammoUsed` | = 开战预载 − 战后余额（`ammoLoaded` 四条路径都在写 ⇒ 四类战斗都算得出） |
| `dronesGone` | 从 `state.droneLossReport` 读**净损失**（按时刻配对；AI 副船不写它 ⇒ 0） |
| `summary` | **本场引擎写的那条日志原文**（弹层正文用它 ⇒ 卡片与日志同源） |

**构造点唯一**：`combat.captureBattleReport(state, battle, opts)`。四个结算点各一行：
`expedition.ts`（胜 / 弃船 / 失利 / 中止）· `encounters.ts`（胜 / 败）· `wormholeBattle.ts`（胜 / 全损）·
`ai.ts`（胜 / 败）。

## 四、界面（`panels/BattleScreen.tsx` 战报弹层）

1. **标题**：四档（见上表）；取不到记录（老档/配对不上）⇒ **回落旧口径**（只看胜负），行为与改造前一致；
2. **正文**：读 `record.summary`；取不到 ⇒ 原来那句兜底话；
3. **新增三行**（船长勾选的三项）：
   - `我方损失：长尾鲨、玳瑁（2 艘 · 船上装备一并遗失）` —— 有沉船才显示；
   - `双方残余：我方 长尾鲨 盾 1240/1240 · 甲 860/860 · 结构 420/420 ｜ 敌方 全灭（共 3 艘）`
     （多舰用「 ｜ 」连；敌方未全灭时写 `存活 a/t · 残余血量 X%`）；
   - `弹药消耗：动能 ×120 · 爆炸 ×40` —— 0 的弹种不列、全 0 **整行不显示**；
4. **关闭时长 12 秒 → 20 秒**（卡片上那句"12 秒后自动关闭"同步改）；
5. 机群战损两行、船体维修装置消耗**照旧不动**。

## 五、删除

`battleViewCore.lastBattleReport`（**根因函数**）连同它的导出与 import 一并删掉 —— 它是"靠日志里
『战报』二字猜"的做法，留着只会让下一个人再踩一次。**注意**：各结算点的**日志文案一行未改**
（留档照旧），改的只是"弹层从哪里取正文"。

## 七、零影响 / 边界

- **不动任何数值**：只新增记录与展示；判定发生在展示层（`battleVerdictOf`），不参与结算；
- **日志文案一行未改**（留档口径不变）；
- **不落档**（`battleReport` 是内存字段）⇒ **零存档迁移**；
- 遭遇战与 AI 副船**照旧不弹战报弹层**（前者不进战场、后者不弹）——只是也各写一份记录，
  让"四类同源"成立、将来要弹随时可弹；
- **AI 副船的战斗会覆盖 `state.battleReport`**：弹层靠起手时刻配对，配不上就回落兜底句
  （与既有 `droneLossReport` 同一套保护）。
