# 虫洞「路径拦截」：直线路径上有敌人 ⇒ 前往中途被拦下开战（2026-09-16）

> **状态：进行中**（工作文档；船长验收 + 合入 main 后按 AGENTS.md §8 归档三步：并入 roadmap ＋ 词典登记 → 删本文件 → 重跑 `docs:index`）

## 一、船长原话（照抄）

「**虫洞内，当玩家点击某个位置准备移动过去时，假设直线路径上有敌人，能否新增一个敌人拦截机制（提升玩家有路径上有敌人阻拦，直接前往会触发战斗）**」
（原文"提升玩家"按上下文读作"**提示**玩家"；六问六答与 §5.2 裁定见下）

## 二、现状（动手前先摸清的）

| 事实 | 出处 |
|---|---|
| **移动是"点到点"**：直接把 `grid.pos` 设成目标格、**不限距离、恒定 1 回合**（没有逐格行走） | `wormholeGridTravel` · `WORMHOLE_TURN_PER_MOVE` |
| **只有"终点恰好是舰船信号"才开打**：`place === 'ship'` 的格**到达即开打**（不额外扣回合）；**从它旁边穿过去无事** | `wormholeGridTravel` 的 `arrived.autoBattle` → `wormholeTravelTo` → `wormholeStartBattle('node')` |
| 层末守卫只在"站在出口格上点激活"时才打 | `wormholeGridActivate` |
| 未扫描格显示为蓝灰虚线边框（看不出里面有没有敌人）；一张盘上舰船信号约占 28% 信号配额 | `Wormhole.tsx` / `WORMHOLE_SIGNAL_WEIGHTS` |
| `wormholeStartBattle('node')` 要求"**当前格**是舰船信号"，敌卡按该格 `gridContentIndex` 取 | `wormholeBattle.ts` |

⇒ 结论：拦截只需把**这次移动截断在拦截点**（`pos` 落到那一格），后续开战链路**天然吻合**，不需要新敌卡口径。

## 三、六问六答（船长 2026-09-16）

| # | 问题 | 船长裁定 |
|---|---|---|
| 1 | 哪些格会拦？ | **乙：任何未清掉的舰船信号格都拦（含未扫描格）** |
| 2 | 被拦后这次移动怎么算？ | **甲：就地停下并开打，移动的 1 回合照扣；打赢后由玩家再点一次继续走** |
| 3 | 拦截战要不要额外扣回合？ | **甲：不额外扣**（与"到达即开打"同口径） |
| 4 | 怎么提示？ | **甲：地图先画路径 ＋ 被拦格描红 ＋ 弹确认框** |
| 5 | 路径上多个敌人？ | **甲：只拦最近的一处**（之后再移动可能再被拦，每次移动最多一战） |
| 6 | 穿越中间格要不要揭开？ | **甲：不揭开**（只有扫描/到达才揭开） |

## 四、§5.2 冲突上报与裁定（**甲**）

- **旧口径原文**（`wormholeGrid.ts`，船长 2026-09-13）：「**玩家只有到达目标地点后才能知道目标地点的确切信息**」；
  同批还专门修掉一处泄漏——「原先未扫描格也按 `cell.place` 上信号色（橙色边框等于告诉玩家"这格里有舰船"）
  ⇒ 现在**只在已扫描/已到达时才上信号色**」。
- **冲突点**：裁定 1 = 乙（未扫描格也拦）＋ 裁定 4 = 甲（被拦格描红）——**未扫描的拦截格一旦描红，
  就等于告诉玩家"那格有敌人"**（因为只有舰船信号会拦），正是当时修掉的那类泄漏。
- **船长裁定（2026-09-16，一个字）**：**「甲」** ⇒ **已知格**（已扫描/已到过）描红 ＋ 显示信号图标；
  **未扫描格不指名**——只把**路径线**置为警示色，确认框写「路径上**可能**有敌人阻拦」。
  ⇒ **不泄漏未知格内容**（2026-09-13 那条修漏口径**继续有效**，不作废）。

## 五、机制（落码口径）

1. 玩家点目标格 ⇒ 引擎算**起终点连线的中间格**（六边形直线）；
2. 从起点往终点逐格查，遇**第一处「未清掉的舰船信号格」**（`place === 'ship'` 且不在 `activated`）即拦截点；
   **未扫描格照样拦**（裁定 1）；
3. 这次移动**被截断**：位置停在拦截点、**移动的 1 回合照扣**、**不额外扣回合**（裁定 2 / 3），
   就地开打（`wormholeStartBattle('node')`，敌卡 = 该格的内容序号 ⇒ 与"自己走到那格"完全同一场仗）；
4. 打赢后该格记 `activated`（现状同一支路）⇒ **之后穿越它不再触发**；玩家**自己再点一次**继续前往原目标；
5. 路径多处敌人 ⇒ **只拦最近的一处**（裁定 5）；
6. **中间格不揭开**（裁定 6）· **出口格（层末守卫）不拦**（只有舰船信号格拦）；
7. 拦截战打输 = 与现有任何一场洞内战同口径（编队全灭 ⇒ 全损）。

**判定细则**：起点与**终点都不参与判定**（终点本身是敌人 ⇒ 走既有"到达即开打"）·
连线**平局确定性**（立方坐标取整；方向先规范化 ⇒ `hexLine(a,b)` 与 `hexLine(b,a)` 互为倒序）·
已清掉的格不拦 · 同一格不会连拦两次 · **只在网格层成立**（线性老档、自动探索不受影响）。

## 六、范围与不做

- **做**：连线函数 · 拦截判定（界面预览与移动**同一函数**）· 移动截断 ＋ 确认闸（核心侧也有闸）·
  在拦截格开战（沿用现有整趟回滚）· 界面路径线/描红/确认框/日志 · 用例 · `wormhole:econ` 政策同步 ＋ 重跑读数。
- **不做**：不改"前往未扫描地点"的既有警告（两句并存）· 不另做"绕行寻路"（移动本就不限距离，
  绕不绕由玩家自己选目的地）· 不改自动探索（派队不下地图走格）· **不新增敌卡或数值**。
