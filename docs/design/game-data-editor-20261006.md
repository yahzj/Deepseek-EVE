## 一、现场与同类参照

权威数据不是独立SQL/JSON数据库，而是`packages/data/src/*.ts`及少量core派生来源；打包游戏把这些表编入产物。改源码后开发版重载/重新构建才使用新定义，不承诺运行中的玩家状态或旧订单立即重算。

既有`tools/content-schema.ts`、`content-export.ts`和`content-import.ts`提供工作台列契约与TypeScript AST字段级回写，`docs/content-workbench.md`和`docs/data-map.md`规定联动及派生字段边界。优先复用列契约/校验与AST思路，不新建第二份权威数据，不以Excel旧副本覆盖源码。

现导入器是命令行、先写再检查、部分表达式/派生行只读跳过，不具备桌面编辑所需的多文件事务、并发冲突和失败恢复；不能只外套界面直接调用其整表写入。需要把相关纯解析/计划能力提取到同域共享，CLI行为保持，编辑器写入事务单独承接。

市场`marketCatalog.ts`的`basePrice`为基准/均衡价，实时行情由core依据存档库存、冲击和噪声计算。`ShipDef.priceIsk`、蓝图书价、物品卡价有部分同值或派生约束，不能把所有同物数字强行改成一个值。稀有售价/收购倍率不同于基准价，某些派生残骸卡没有直接可写的对象行。

## 二、首期功能

| 分类 | 数值范围 | 限制 |
|---|---|---|
| 舰船 | 护盾/装甲/结构、三层抗性、CPU、槽位、货仓/机舱、速度/动力/跃迁、采集参数及既有数值特性 | ID、名称、角色与特殊行为开关只读；级别变更另视结构约束 |
| 装备及舰船插件 | CPU、倍率、射程、装填、命中、抗性/血量/速度加成、已有数值效果 | 不随意新增效果、改槽族、改引用或上线闸门 |
| 物品/无人机 | 体积、基础估值、机群伤害/射程/装填/CPU/三层防御等已有数字 | 不编辑配方结构、文本、类别与引用 |
| 商品 | 基准价、收购/供应倍率、库存池目标/流量、限额补货量/周期等 | 不编辑玩家实时行情/持有量/未决订单；标明来源与派生只读项 |

按名称/ID搜索，按舰种/档位/装备家族/商品类别筛选；查看关联商品，多个条目并排对比，指定字段批量设值、加减或乘倍率。批量计划逐项预览，整数按字段规则处理，不悄悄取整。

中文字段、显式单位、数值输入；百分比字段采用百分比显示并明确引擎原值，倍率仍显示倍率，毫秒/秒/立方米不混用。未设置、0及继承/派生值分开，不将空输入当0或删除。

草稿支持撤销/重做、切条目不丢修改、未保存关闭确认；保存前集中显示旧值→新值、文件/行、关联改动。检查结果有对应字段定位与错误摘要，不只有红框或日志。

## 三、工作区与写入

1. 首次启动选择源码项目目录；默认建议`Deepseek-EVE-zero`。顶部常显绝对路径、分支与当前版本，切目录前处理未保存草稿。主树默认只读，首期不提供绕过按钮；有需要先在零号改后按原流程合入。
2. 数据读取以选择的项目现场为准，不用打包工具内的旧表。读取有版本/字段能力校验；不执行未知目录任意脚本，验证指令限定本仓固定清单并提示代码执行边界。
3. 用TypeScript AST定位ID及字段，最小范围改数字，保留编码、BOM、行尾、注释与其他用户WIP。只写白名单路径和字段，符号链接/路径逸出拒绝。
4. 每个可写字段标直接值/共用常量/继承/派生。首期复杂表达式与派生值只读并显示源位置；共用常量改动需要展开所有影响项，未实现可靠来源追踪时禁止回写，不能改成字面量切断继承。
5. 建候选文件集合，在隔离临时目录验证类型/内容与相关回归，失败不写选定工作区。合法数值被既有冻结断言阻挡时保留草稿并显示原因，不改测试/删除护栏。
6. 保存前复核原文件哈希与基线，外部修改则拒绝过期计划并允许重新载入对比。备份包含当前原文而非HEAD，保留原有未提交改动；多文件落盘有事务日志/崩溃恢复，无法确认安全时停写，不谎称多个rename天然原子。
7. 回滚仅恢复本次可证明仍未被外部修改的目标，不用`git reset`或全文件覆盖抹掉别人改动。导出只提供本次差异/调整记录；既有Excel如有未导入手改不能自动覆盖，派生导出另写新文件。

## 四、价格与关联

改商品基准价时列出舰船定义价、物品估值与关联蓝图书价等真正相关项：硬同值关系纳入显式联动计划，公式或登记例外只显示影响与约束。需要改变蓝图倍率/材料配方/冻结标定的部分不自动改，留作另批裁定。纯数值修改不猜测重写中英文描述；发现说明内硬数字冲突时提示并阻挡受影响写入，按既有文案流程处理。

保存不意味着游戏内瞬时更新，界面给出源码写入状态、检查状态与构建状态。首期可提供固定的一键检查/构建命令，但不自动启动个人游戏或读取个人档，不打补丁到游戏EXE/asar。

## 五、独立交付与技术方案

拟新增独立`apps/data-editor`，复用仓内React/TypeScript/Electron打包链；单独appId/userData，不加载游戏启动、存档、调试或铁人桥。打包Windows x64便携EXE，双击无需手敲npm；读取/编辑进程与验证工作进程隔离，界面不获得任意文件写入能力。

编辑器内置自身运行时及AST/字段能力；对选定仓库的完整检查/构建仍需有效项目依赖。启动体检依赖，缺失清楚列出，不假称单EXE能无依赖编译任意源码项目。不得静默安装系统依赖。未签名EXE可能被Windows提示，交付时如实说明。

界面为开发工具，左分类/搜索、中条目表、右分组属性，底部可收起改动与检查结果；无英雄页、装饰动画或套游戏战场皮肤。`ui-ux-pro-max`整体检索返回营销布局不适用，未采纳；实查ux的Bulk Actions、Error Placement、Focusable Error Summary适用于批量数字编辑与可定位校验，表格内滚、键盘焦点可达和低高度测试作为护栏。

新增/修改：独立编辑器应用与打包配置、同域纯字段计划/验证/写入模块及测试、必要列契约补齐、使用说明与生成索引。删除：无。明确不做：新增/删条目、改ID/文案/行为/存档、敌军/技能/全局平衡规则、强制通过、自动Git操作、修改已安装游戏。

涉及内容维护工具→舰船/装备/物品/市场及关联蓝图的数据定位，申请本批必要跨域权限；只建立编辑能力，不在开发过程中擅自改正式游戏数值或标定。

## 七、数据库化与结构化数据替代方案（2026-10-06追加讨论，未确认）

船长原话：「那么，能否将现有的各类数据转换成数据库数据方便调整？或者做出其他修改？」

### 7.1 推荐：结构化数据是权威，代码只装配与运算

将舰船、装备/插件、物品/无人机、商品等静态定义逐类迁出TS，采用按内容域分文件的JSON及统一字段契约；既有`SHIPS`/`MODULES`/catalog导出接口先保持，由薄装配层读取数据。不是把最终`SimContext`快照反向存为权威：快照已混入过滤、本地化、默认和派生，不能用于还原原始缺省语义。

JSON保存ID、静态数值/引用、明确布尔及文本ID等纯数据；本地化表、公式、技能应用、默认/继承、上线过滤、行为和派生逻辑留代码。真实例子：舰船插件槽按级别派生、市场残骸卡按组生成、运行目录做稀有度/黑市/上线过滤，不能将这些派生行变成另一份可手改定值。初期文案保持原来源，参数以ID连接，不复制中英文全文进每张数字表。

编辑器直接读写权威JSON，不需定位TS数字区间。字段契约同时供编辑器控件、运行/构建校验、CLI工作台和测试使用；旧schema逐步接入，不保留两份同义约束。生成或编译产物只从JSON单向生成并检查新鲜度，禁止回写生成件。JSON可由Git逐行审查合并，SQLite如用于搜索/索引只能作为可重建缓存，不得同时是第二份权威来源。

空值/未设置、显式0、数组顺序、重复ID及大整数须验证；非有限数字拒绝。引用字段有存在性检查，数据结构与游戏存档各有自己的版本，不能只因搬表升级个人存档。部分静态字段之间的真正同值关系通过显式来源/规则管理；物品估值、市场基准、倍率不是天然同一值。

### 7.2 SQLite备选：只作开发期权威数据库

可用单文件SQLite保存基础表与一对多子表（抗性、材料、掉落/舰队编成等），编辑器通过事务、键约束与变更记录保存，再导出经验证的版本化数据包供网页/桌面。游戏启动一次加载完整包，core仍只吃内存catalog，不在战斗tick执行SQL。不能让SQLite与JSON互相双向同步，必须确定数据库为唯一编辑源、导出件为只读生成件。

收益为事务、SQL筛选批量与复杂引用查询；代价为数据库schema迁移、二进制Git难审/难合并、多个工作区并行数据合并与导出新鲜度管理，仍需游戏范围/语义/经济校验。只把TS数组序列化塞进一个数据库JSON列不会减少派生/联动复杂度。当前只有数百条内容且网页静态部署，不为基础数字编辑引入运行时SQL/WASM或后端。

### 7.3 生效方式与分批

第一阶段结构化文件仍随构建发布，编辑后开发版重载/重建使用新定义，不声称改数据即可让已安装EXE瞬时生效。若后续明确要求免重编译，可单独设计启动加载外部数据包：格式版本、内容哈希、完整校验、失败保留上次有效包，桌面/网页同源发布；战斗/生产/订单与离线结算必须锁同一套版本，不中途热换。此项是额外运行期与兼容设计，不默认塞进首期。

推荐实施顺序：字段契约/数据装配与严格等价读数→舰船迁移试点→装备/插件/物品/商品逐类→同一EXE编辑器与批量/事务→发布/构建联动。舰船与市场/蓝图价需要同批一致的项列明，不为完成单表试点制造暂时双价。技能、敌舰/敌卡、配方、全局平衡与通讯等以后逐类接入，不一次搬全仓。

迁移本身不改任何数值/玩法：前后zh/en完整catalog、ID/引用/顺序/缺省/派生/过滤逐项相等，确定性引擎同档同种子输出、旧档往返、内容/类型/本地化/架构/经济读数及双端构建回归。只要等价不成立先修迁移，不能改旧断言掩盖。合理调参被历史冻结数值断言阻挡的治理另讨论，不借搬表削弱技术校验。

### 7.4 本轮建议与确认

推荐§7.1：**JSON为权威静态数据＋统一字段契约＋原有TS运行规则＋独立EXE编辑器**，替代§三的日常AST回写方案；不是只做TS外套界面，也不是把游戏换成SQL应用。AST仅保留迁移取证与旧CLI兼容需要，不成为两份权威写入口。

数据库SQLite方案保持备选，用户若明确需要SQL管理再细化完整关系表与发布流水线。当前仅方案补充，未迁移任何游戏表、未创建数据库/EXE、未改存档或主树；需船长确认架构取舍与跨域后开始。
