# 深层盘读档被丢 —— 结案「深入下一层后，显示本层没有网格」（2026-09-20）

> **状态：进行中**（已实现并本地提交 `d3d6130e`，待船长验收）

> **玩家报障（照抄）**：「**玩家虫洞深入下一层后，显示本层没有网格。**」
>
> 性质：**2026-09-20 盘面阶梯批（每层 +1 环、上不封顶）的连带回归**，出在我这边。

## 一、根因

`packages/core/src/save.ts` 的读档清洗 `cleanWormholeGrid` 写死了一条半径上限：

```ts
if (!(radius >= 1 && radius <= 8)) return undefined   // 整块丢弃该层网格
```

这条 `8` 是当年"**每 2 层 +1、封顶 R=4**"时代的余量（留了两倍）；同日把阶梯改成
「**每 1 层 +1 环、上不封顶**」（`wormholeGridRadiusFor = 2 + (层−1)`）后，没人回头看它
⇒ **层 8 起（R=9+）的盘在读档时被判为坏结构、整块丢掉**，该层退回**旧式线性地图**
⇒ 界面走 `ui.Wormhole.155`「本层没有网格」那一支。

**触发时机**：任何"存档 → 读档"往返（重启应用 / 恢复备份 / 导入 / 网页版刷新）。层 1~7 不受影响
（R ≤ 8 恰好通过），所以只有深入到第 8 层以后才会撞上。

## 二、复现与修复（临时探针 · 真存档往返 · 逐层）

| 层 | 阶梯半径 | 盘面格数 | 修前（读档后） | 修后（读档后） |
|---|---|---|---|---|
| 1 / 2 / 5 / 6 / 7 | R=2~8 | 19~217 | **在** | 在 |
| **8 / 9 / 10 / 12 / 20** | R=9~21 | 271~1,387 | **❌ 被丢掉** | **在**（R、格数、pos 全同） |

修法（一并做）：
1. `wormholeGrid.ts` 新增 **`WORMHOLE_GRID_SAVE_MAX_R = 64`**——只是"坏档护栏"，**与阶梯彻底解耦**
   （注释写明本事故，以后改阶梯不必动它）；`save.ts` 改用它，并把这条边界的历史与后果写进注释。
2. 顺带修 `wormholeRuinsFloorFor` 上方那句过时注释（"刻意沿用网格半径那条节拍（也是每 2 层 +1）"）——
   **遗迹保底的值一律不动**（它是船长审核过的 1~10 层明细表里那一列），只把注释改成"本阶梯自己走每 2 层"。

**回归守卫**：`packages/core/tests/save.test.ts` 新增 1 例——**逐层走真实存档往返（层 1~40，含 R>8）**，
断言 `grid` 与 `radius / cells.length / pos` 全部保留 ⇒ 以后"阶梯 ↔ 读档护栏"再耦合会直接红。

## 三、影响面（如实）

- **已经中招的那一层，本修不会把它变回来**：盘在被丢的那次读档后就已经不在档里了。
  线性层照旧能撤离 / 深入，**深入一层即生成新盘**（R 更大）。
- **可行的"修复路径"（本批不做，待船长定）**：读档时若 `run.grid` 缺失而 `run.seed` 在
  （种子随档、盘面按 `(seed, depth)` 确定性生成）⇒ 用 `wormholeMakeGrid` **重建同盘**。
  代价：该层**已探索进度会重置**（`scanned` / `visited` / `activated` 回到初始圈），
  且当时的 `scanBonus` 没随档 ⇒ 初始扫描圈可能与原盘差一圈。属行为取舍，故先不动。
