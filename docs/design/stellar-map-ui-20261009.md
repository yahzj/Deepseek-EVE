## 三、布局方案

```text
┌ 星系星图  星系选择  坐标/恒星类型/开发状态        关闭 ┐
├──────────────────────────────────┬──────────────┤
│ 缩放/全图/定位工具                │ 选中星球     │
│                                  │ 类型/勘探阶段│
│           恒星与轨道星图          │ 已知属性     │
│                                  │ 已知特性     │
│      类型与勘探/开发状态标记      │ 勘探/进入地表│
├──────────────────────────────────┴──────────────┤
│ 探索任务：随机/指定坐标  搜索/暂停/放弃  自动搜索 │
│ 库存/候选名额/剩余时间/进度  探测机生产与制造入口 │
└ 操作反馈与停止原因                              ┘
```

- 顶部保留星系选择器，不新增排序/收藏/重命名功能；展示当前坐标、恒星类型、天体数与已开发状态。复制/放弃坐标放在同一行的图标操作菜单或紧凑工具区，危险操作仍确认，已开发星系仍禁止丢弃。
- 中央地图成为视觉主区域，不套装饰卡片、不铺全屏扫描线。工具条保持缩放、适应全图与定位选中目标，读数刷新不重置缩放、平移或选择。
- 右侧只负责目标详情：星球编号、类型、勘探阶段、危险/宜居区间、已知特性、未知特性数量，以及现有详探/深探/进入地表操作。未选中时使用等尺寸空态，不挤走地图。
- 底部固定任务区将搜索和生产与目标详情分离。搜索运行/暂停/停止原因、剩余时间和进度一直可见；生产列表在固定内部区域滚动，不随着任务数量增高。继续随机搜索复用checkbox，不包装成文字按钮；随机/指定模式使用分段控件。
- 原型星球入口保留为次要命令，不删除既有调试/兼容路径。进入地表沿用`PlanetaryPanel`，返回时不丢星图上下文，本批不改地表界面。

建议桌面结构仍为最大1300×850窗口，右侧详情320px，地图剩余空间自适应；上下区带约束，不让天体数量或任务条目撑大外壳。字体沿用游戏尺寸档，不采用随视口变化的字体。长文案换行，内容完整可达，不靠裁切隐藏功能。

手机沿现有横屏逻辑空间布局；右侧详情可用260~320px约束，底部任务区可分搜索/生产两页签以维持地图可用高度，两页签保留持续任务状态摘要。不新增物理vw/vh覆盖层，不把移动端整个窗口变成长表。最终尺寸以桌面和旋转逻辑几何矩阵验证，若现有逻辑空间确实容纳不下则先报告调整，不硬裁。

## 四、视觉与交互

- 采用克制的科幻仪表语言：中性深色面板、细分隔线、现有青色用于选中/操作，金色表示恒星与关键数值，绿色表示已开发，危险红仅用于危险/拒绝。直接接现有主题变量，两套布局颜色分别跟随原主题，不硬塞一套新调色板。
- 恒星与星球用现有SVG线稿增强类型差异：气态环、冰裂纹、海洋波线、岩质轮廓、熔岩裂纹等；图形只由已经公开的类型决定，不根据隐藏资源/特性画不同细节。仍保留轨道尺度的示意含义，不伪装成真实天文比例。
- 勘探阶段/已开发标记采用图标和文字搭配，选中环与键盘焦点清晰；颜色不能是唯一信息载体。编号避让与透明命中区继续走现有几何单点。
- 复制、关闭、暂停/继续、定位等工具优先现有Lucide/项目图标；可执行主要命令仍有文字，图标悬停用既有Tooltip。触屏和键盘不用悬停也能识别和完成主要操作。
- 操作反馈保留`role=status`，失败原因可读，控制区有清晰的disabled/忙态；取消/丢弃确认与目标绑定，不能在切换星系后误操作另一份坐标。
- 可选动效仅用于用户选择/任务状态反馈：短暂选中反馈、进度推进；不转动全部轨道、不持续闪烁标签、不在整块地图上使用昂贵filter。尊重减少动态设置；所有命中坐标不被动效扰动。

## 五、技能评估

- `frontend-design`负责探索场景的主体与信息结构，避免通用卡片仪表板；`design-system`只给现有变量补同域语义/组件映射，不生成覆盖全仓的第二套token。
- `ui-ux-pro-max`的HUD/Sci-Fi FUI条目明确适用于科幻游戏，同时标记对比度/焦点/减少动态与性能风险；采用细线、仪表组织，不照搬霓虹/模糊/持续闪烁建议。
- UX检索依据：Submit Feedback的「Show loading then success/error state」；Loading Indicators的「preserve layout focus and accessible busy status」；Color Only的「Use icons/text in addition to color」；Focus Not Obscured的「Don't let headers footers ... fully cover focus」。底部任务区使用布局预留空间而非覆盖内容。
- 动效若实际增加，再按`review-animations`审查；React实现复用组件与当前取数单点，不因为技能建议引入新的框架、图标包或动画依赖。

## 八、船长追加：天体更真实与PixelPlanets（2026-10-09）

船长确认布局，并提出「同时我希望星系星图和星球能够更真实好看一些，我是否需要切gpt图片的AI？关于星球，我在大鲸鱼根目录添加了一个PixelPlanetsWindows的GODOT程序，其能输出星球外形的GIF或者PNG，不知道这个对生成星球外形是否有帮助」。

只读取证：实际文件`H:\大鲸鱼\PixelPlanetsWindows.exe`，约38MB，Godot3.5内嵌资源。未启动EXE、未安装工具、未写其目录；内嵌GUI有PNG/GIF/spritesheet导出、种子、像素密度、旋转、颜色与图层控件；资源包含陆地、干燥地表、冰、熔岩、气态/带环气态、无大气、恒星、黑洞等。检查未导出图像，不能宣称实际效果或透明度已验收；未发现已验证的批量命令行接口。

原项目`Deep-Fold/PixelPlanets`README称Godot像素星球shader集合，LICENSE为MIT；本地EXE版本/来源不能仅凭名称直接证明一致，正式入库前核验工具来源及导出素材权利，附许可和来源清单，不推送EXE本身或把Godot变成游戏运行依赖。

推荐追加路线：小星图使用静态透明PNG，目标详情使用较大预览；必要的缓慢自转优先spritesheet便于暂停、控制可见区域播放与减少动态，而非满图GIF。种子到类型/变体的选择确定、重载不变、不修改探索rng、不根据隐藏资源或特性选外形。导出有限类型变体做本地资产库，不预生成每个可能星系，也不每次启动运行EXE。

PixelPlanets提供统一像素风与球体光照，不等同照片级写实天文模拟；当前EXE尚未进行输出画质/动画边缘/尺寸性能评估。先制作岩质、海洋、气态三张样片供船长选择风格，再决定七类类型资产集。若目标是平滑高细节写实星球，再考虑独立AI生成透明静态素材作为概念/最终预览，不将自动生成图等同可无缝自转资产。

规则冲突：开发约定§九现行要求所有视觉物件采用SVG线稿。建议仅为恒星与星球本体开放本地PNG/精灵图例外，轨道、命中区、焦点、选中环、HUD与交互标记保持SVG。例外与像素素材路线须船长明确确认后更新规则及台账，尚未授权使用位图，不擅自改写既有规则。

图像AI问题：当前任务工具检索未提供内置image_gen；切换聊天文字模型不等于启用图像工具。无需为布局优化更换模型，也不需要在游戏运行时调用图像API。若后续选择API/CLI图像生成，须单独明确授权和提供可用API配置，不能静默调用或安装。官方图像文档确认生成/编辑以及透明PNG/WebP能力，不承诺当前账户/界面一定可用。参考`https://developers.openai.com/api/docs/guides/image-generation`。
