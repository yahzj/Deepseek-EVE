# 蓝图获取速率调整（碎片门槛下调 · 市场蓝图书权重 5% · 蓝图单寿命 6 小时）

> 状态：**已确认**（船长 2026-09-10 拍板）。经办：大鲸鱼一号。
> 触发：船长复核「残骸与市场两条蓝图获取路线」后要求调整出率；先答复「D2 那批专属装备无蓝图、不上市场」，
> 随即定下本批两处系数 + 两处边界。

## 一、决策链（船长逐轮拍板）

1. **残骸侧：只降集齐门槛，概率不动**——`FRAGMENT_RECIPES.need` MK2 100 → **25**、MK3 1000 → **250**；
   `RECYCLE_CHANCE.fragT2/fragT3`（0.00045 / 0.0007 每 m³）保持不变。
2. **市场侧：蓝图书权重 50% → 5%**（`balance.market.blueprintWeight = 0.05`）。
3. **边界一（船长二次确认）：5% 也影响奇货渠道**——稀有抽取与奇货掷骰共用同一个权重。
4. **边界二（船长选丙案）：蓝图单寿命延长到 6 小时**（`balance.market.blueprintLifeMs`），
   与奇货同为 6 小时；普通稀有单仍 36 分钟。
5. 旋钮范围（船长定）：出率 + 集齐门槛；**书价、声望门槛、暗市闸不动**；收购侧（玩家回卖）不动。

### 为什么必须加 `tier` 字段（本次唯一的连带重构）

改动前，引擎用「片数 == 100 / == 1000」判断配方属于 MK2 还是 MK3 档（`salvage.ts` 两处池拆分、
`wreckFlavor.tsx` 的威胁门槛、`tools/salvage-econ.ts` 两处）。**只改 need 会把两个池一起打成空数组**
（碎片一片都不出）。故档位改为显式字段，所有判据改读 `tier`。

| 指标 | 改前（权重 0.5） | 改后（权重 0.05） |
|---|---|---|

17 行合计 ≈ **0.98 张/天**（无技能）——造船线从"随时能买到"变为"要蹲、要攒"。

## 四、碎片池规则与报表口径（船长同日追加两次拍板）

**① 碎片池「集齐前不重复」（船长 2026-09-10 定）**：碎片命中后从**该档还没拿到蓝图的书**里等概率抽 1 张，
**已学会（含市场买书学会）或碎片已集齐门槛的模块移出池子**。理由：碎片不可出售、无市场卡，
重复给就是死库存；旧实现里"学了还继续抽到它的碎片""集齐了还继续吃碎片"两个口子一并堵上。
效果：凑齐该档三张书**恰好 3 × 门槛片**（MK2 75 片 / MK3 750 片），**尾部消失**——
原"纯随机"口径含集邮损耗（MK2 +17.2%、MK3 +5.7%，见下表的旧估算），现在报表的"整档"数字就是真实期望。
实现：`salvage.fragmentPoolOf(state, ctx, tier)`（回收开箱与完好舰体彩头共用），回归见
`tests/recycle.test.ts`「碎片池」4 项（空档全在池 / 集齐即移出 / 已学会即移出 / 池空不报错）。

> 旧口径的集邮损耗（**已被 ① 取代**，留档备查）：每片等概率给 3 张书之一，故"三张全要"是集邮问题。
> 精确 DP + 蒙特卡洛（20 万次）双向校验：MK2 期望 87.9 片（硬下限 75 片，+17.2%，中位 86 / P90 99）；
> MK3 期望 792.9 片（硬下限 750 片，+5.7%，中位 789 / P90 824）。

**② 报表口径：碎片不计 EV，只给一行"大概的剩余残骸预估"（船长 2026-09-10 定）**：
`tools/salvage-econ.ts` 的「彩头 EV/h」行**只算可兑现件**（基础件 + 低安 MK2 件 ≈ **4,979 ISK/h**，
占保底 10% 护栏的 3.4%）；碎片另起**一行**，只写"凑齐该档三张书大概要多少残骸 + 炉时"：

```
碎片进度（不计 ISK；集齐前不重复 → 三张书合计 75 / 750 片）：
  凑齐 MK2 三张 ≈ 需 166,667 m³ 残骸（炉时 116h 无技能 / 93h 满技能）· MK3 三张 ≈ 1,071,429 m³（744h / 595h）
```

（原先那版把碎片按"蓝图市价 ÷ 片数"折算成 ISK/h，门槛下调后折算值涨 4 倍并越过护栏——
那是"收藏折算"不是产出，船长定：**不要**，只留这句大概预估。）
