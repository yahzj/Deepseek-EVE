## 5. 血泪清单（本会话真踩过的坑，按发生顺序）

1. **`git checkout -- <路径>` 会丢掉未暂存的改动**：我用它"还原负向验证"时，把 `combat.ts` 里**尚未提交**的
   整套改动一起丢了（`git checkout --` 取的是**索引版**，不是工作区快照）⇒ **负向验证要用 `edit` 工具改回**，
   或在改之前先 `git add`。改完立刻 `git status` 核对。
2. **PowerShell 里 `Set-Content`/`Out-File` 写中文会毁文件**（我拿它做替换，直接写出非法 TS ⇒ 测试 collect 失败、四连假红）
   ⇒ 一律走 `edit`/`write` 工具，或 .NET `WriteAllText` + `UTF8Encoding`（AGENTS §4 早有明文，我违反了）。
3. **`edit` 的 `old_string` 若跨了要保留的行，会连带删掉**：我两次把 `},` 与紧随的注释吃掉、又两次靠 typecheck 才发现
   ⇒ 改结构行时**只框住真正要换的那几行**，改完立刻 `npm run typecheck`。
4. **`fx` 是 48 条环、丢最旧** ⇒ 断言"最终环里有某类事件"会**假失败**（`foe-drone.test.ts` 的 pd 断言就是这样：
   机群被打光后只剩对舰开火，早期 pd 事件被挤出环）⇒ 要**逐秒推进 + `seq` 游标无损收集**。
5. **命令行输出中文经 PowerShell 管道会显示成乱码**（`Get-Content` / `Out-String`）——**不是文件坏了**；
   用 `read` 工具或 .NET 读原文核对（我据此避免了一次"仓库有坏文件"的误报，另一次真以为 roadmap 被转码）。
6. **测试夹具的前提要复核**：属性合并后，"无加成对照件"**不能再靠摘掉属性**（那样连"能打机群"都没了、两次跑的开火
   次数就不同）⇒ 改成**把防空值降为 1**（引擎对 `antiDroneMul === 1` 不乘）。写对照实验先问"两次跑的前提真的一样吗"。
7. **汇总行/读数行必须按结果分支**（二号同款教训）：改契约时顺手检查"有错时它打印什么"，别让汇总行撒谎。
8. **负向验证必须真红才算数**：本会话共 7 处（含"把下限加回去""把闪避加回去""把乘子关掉""把防空值改成 1"…），
   红过再还原，并把读数写进提交信息。
