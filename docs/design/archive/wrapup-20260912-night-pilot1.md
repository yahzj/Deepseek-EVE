> ⚠ **本卡起草时写错了一处**，2026-09-12 深夜复核后改正：当时说「`hullDps()` 夹具只统计第一条条目 ⇒

## 2. 裁定二：一次性图纸（**已实现 · 待验收**）

**船长原话**：「能否实现一次性图纸？既玩家无法学会，只能制造一次的图纸」

**七条口径（船长逐条裁定，实现与用例逐条对齐）**：

| # | 裁定 | 落地 |
|---|---|---|
| 1 | **甲**：仍是"书"，只能造一次 | 进蓝图书架、**不可学习**（引擎拒 + 界面不给按钮）；到组装机直接用 |
| 2 | **乙**：已永久学会同名配方 ⇒ 书**不用也不消耗** | `recipeCapability` 返回 `learned`：一本不动、不记名额 |
| 3 | **甲**：**开工那一刻**扣书 | 与材料同一时刻扣除；取消/失败**不退**（书 = "一次制造资格"） |
| 4 | **乙**：**可卖** | 本批不加出售限制（能否卖取决于有无市场卡；本批也没加市场卡） |
| 5 | **只做机制** | 未加来源、未上市场、未改掉落 |
| 6 | **不进**逆向研究 | 引擎天然不涉及（不在已学会表）；`content:check` 新增契约拦"出现在碎片配方表" |
| 7 | **成品完全一样** | 产出路径完全复用现有制造链（属性/入库/可卖逐字相同） |

**状态：`待验收`**——船长 2026-09-12 明确「一次性图纸先不验收」，且**当前数据里没有任何一张**
一次性图纸，故**界面上看不出效果**（要看效果需先在数据里挂一张）。

**关键实现点（供复核）**：
- 可用性**单点** = `manufacturing.recipeCapability`（`ok` / `learned` / `exhausted` / `no-book`）；
  判定顺序是「**书在架上就可用**」优先于「名额已用尽」——否则**重复获得的图纸会被误拒**
  （本批用例抓到过这个洞）；
- 名额记录 = `GameState.spentOneTimeRecipes?: string[]`（**老档缺省 = 空，零迁移**）；
- **一次性图纸不循环**（"只能一次"）⇒ 该卡的「循环制造」开关整块不渲染；
- 舰船蓝图同样支持（`ShipBlueprintDef.singleUse?`）。

**验证读数**：typecheck ×4 绿 · core **107 文件 / 1070 用例**全绿（新增 10 条）·
`content:check` 绿（含两条新契约）· 桌面 build 绿 ·
**负向验证**：关掉"开工扣书" ⇒ 4 条红；去掉"名额用尽"判定 ⇒ 1 条红（各自还原后全过）。
