## §5 本会话亲历的坑（照抄避雷）

1. **误写主树**（本会话犯了两次）：`edit`/`write` 的路径**必须写 d2 的绝对路径**。发现误写后的正确处置：主树 `git diff --output=<d2>/tools/_x.patch -- <文件>` → d2 `git apply` → 主树 `git checkout -- <文件>`（**只回退自己动的那几个文件**，别人在途的改动一个字不许碰）。
2. **PowerShell 内联 node 是引号地狱**（本会话栽了 3 次）：`node -e "…"` 里的中文、单引号、反引号、`\r\n` 都会被 PowerShell 吃掉或转义错。**一律写成 `tools/_xxx.mjs` 再 `node tools/_xxx.mjs`**；脚本内部的 JS 字符串用双引号包含单引号的行。
3. **`Set-Content` 会毁中文**（本会话栽过 1 次，探针文件整片乱码）：写中文盘只用 node `fs.writeFileSync(p, s, 'utf8')` 或 .NET `WriteAllText` + `UTF8Encoding($false)`。
4. **`write` 工具产 LF**：本仓 `.md`/`.ts` 约定 **CRLF（无 BOM）**。新建文件后立刻用 node 转 CRLF 并自检：`BOM 无 · LF-only 0 · 首行完整`。
5. **批量删/改行要按"块"定位**：本会话有一次按"行数估算"删，**多吃了一行注释**（`ui.shipInfo.185` 上面那条）。删块请找起止锚点、删完 grep 复核。
6. **合并冲突的固定解法**：`docs/INDEX.md` ⇒ 直接重生成（`npm run docs:index`）再 `git add`；`docs/roadmap.md` ⇒ **两侧条目都留**（我方在前）；`tools/content-check.ts` / `core/save.ts` ⇒ "同一处各加各的"就两侧都留、并把计数/注释合成一条。
7. **`market.test.ts` 的「收购额度」用例是种子敏感的**：**新增市场行会整体平移随机相位**（已发生三次：H 遗骸行 · 本轮 3 行）。修法 = 逐种子打表选一个落在大额度配置的 seed，并把读数写进用例注释（`seed 5` 是当前值）。
8. **`docs:index --check` 在主树可能因别人新增文档而红**：那是 INDEX 旧了，重生成后随本次合入一起推即可（本会话发生过）。
9. **推送要带代理**：GitHub 直连超时；用 `git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main`（**别写进全局配置**）。
10. **新字段会被多条契约拦下**：装配页短行（`moduleShortEffect`）· 支援件「恰好一类效果」· 物品/无人机计数 · 挂载件归属白名单 · 市场行/图鉴跳转 —— `content:check` 的 ❌ 会逐条点名，照做即可。
11. **随档字段两处落笔**：`state.ts` 的字段 ＋ `save.ts` 清洗器；漏了就是"读档即丢"（本会话踩过 `byGroup` / `targetGroup` / `WeekendWreckRecord.family`）。
12. **`tools/` 不进 typecheck**：字段名拼错静默变 `undefined`（`foe:export` 出过 `NaN 秒`）。tools 里读数据要加脏值自检。
13. **临时探针**：`_` 前缀、收尾删除；日志落 `tools/_ui-artifacts/*.log`；后台任务每 2 分钟巡检一次。
