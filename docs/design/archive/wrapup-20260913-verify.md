## 5. 血泪清单（本会话真踩过的）

1. **PowerShell `Get-Content`/`Select-String` 读 UTF-8 中文会乱码**：据此差点误报"文件被转码"⇒ 一律
   `read`/`grep` 工具或 .NET `ReadAllText(UTF8)`。
2. **`.NET` 的当前目录 ≠ PowerShell 的 `Get-Location`**（约定 §三 早写过，本会话仍踩一次）⇒ 脚本里一律用**绝对路径**。
3. **`edit`/`write` 前必须先用 `read` 工具读过该文件**；**`write` 新建文件默认 LF**，入仓文件必须 **CRLF**（踩过一次，已归一后复查）。
4. **`git checkout -- <路径>` 会丢未暂存改动**：改用"先 `git diff > 补丁` 再 restore"（半成品先落补丁）。
5. **解合并冲突"并集"不能盲留 HEAD**：两侧同名条目内容可能不同（收口审计条 main 版更新）⇒ 逐字比对取较新。
6. **位置类表现层改动别只验结构**：一号那版只验了环数/颜色/绝对定位，**位置偏低 142~234px** 是船长肉眼报出来的
   ⇒ 位置必须量"元素盒 vs 目标盒"偏差。
7. **层级类问题代码里看不出、肉眼才看得出**：提示条 z-index 10 vs 弹层 120 长期存在 ⇒ 用 **`elementFromPoint` 命中测试**
   当场判"在最上层/被盖住"（本次即靠它拿到"修前命中遮罩、修后命中提示条"）。
8. **无头 Windows Chrome 里 `typeof navigator.share === 'function'`，但 `canShare({files})` 为 false** ⇒
   验分享必须**注入桩**，不能凭"有这个 API"就断言能分享。
9. **玩家报错里引用的文案可能是旧版客户端的**：先查该文案是否还在**源码**里，再查构建产物与线上部署
   （今日市场那条「供应簿只剩 0 件」即此）；线上部署状态可用 GitHub Actions API 核对。
10. **负向验证必须真红**：本会话四轮都做了（舰影 23→0 · 未探索卡 1→23 张 · 飞入首帧 −217→+36 ·
