## 5. 血泪清单（**本会话真踩过的坑，按发生顺序**）

1. **.NET 文件 API 必须用绝对路径**：`[System.IO.File]::ReadAllText('相对路径')` 按 **.NET 进程当前目录**解析，
   **不等于** PowerShell 的 `Get-Location`——我脚本已 `Set-Location` 到 d2，相对路径却落到会话工作区根 ⇒
   读失败后**仍继续执行写入**，把 `docs/roadmap.md` **写成 0 字节**。救法 = **`git checkout -m -- <path>` 就地重建冲突态**
   （两侧版本都在库里、内容零损失），**别 `merge --abort`**。已并入 `development-conventions.md` §三。
2. **改数据必须按唯一键 / 舰名"锚定块"，禁止裸正则**：我用 `slots: { high: 6, mid: 5, low: N }` 这种裸正则
   去改旗舰，**先命中了同形的巨齿鲨** ⇒ 改错了船、旗舰没动（下一提交才修正）。
3. **CPU 别自己比船体字段**（见 §2.7）——我因此报过一次**假超载**，船长实机一眼否掉（"剩余 175 / 414"）。
4. **汇总行不许撒谎**：我新加的体检汇总行一开始在有错时仍打印"含等离子 ✓" ⇒ 已改成**按结果分支**
   （§5 的老坑，本会话又差点踩）。
5. **加内容会牵动"隐式口径"**：敌速基准船是"按船池取中位"⇒ 我加两具壳体就让尺子漂了 2.7%、顶红一条既有契约。
   **凡"按全池统计"的派生量，加数据前先想它会不会动。**
6. **新契约一加就抓到我自己的错**：本轮体检先后拦下我的**总槽位 12 上限 · 武装舰缺 `powerBonus` ·
   盾须大于甲 · 舰船数硬断言 25** 四处 ⇒ **护栏越密，改数据越安全**（别嫌它烦）。
7. **文档纪律照旧**：write/edit 工具写出的是 **LF** ⇒ 提交前扫一遍改动文件归一 **CRLF**；合入/批量写文档后
   **必做三条自检**（BOM/行尾一致 · 全仓往返解码乱码 0 · 与**两侧父提交**逐行"父提交有的行还在"）。
8. **别在对方工作区动手**：本会话全程只在 d2 改，合入走"主树干净 → FF"。
