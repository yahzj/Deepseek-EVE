## 2. 接手必读口径（本会话新增/改动，别踩）

1. **ⓘ（常驻说明）体系**：`packages/ui/src/Panel.tsx` 的 `hint?: ReactNode` 把标记渲染在**标题文字后面**；
   渲染层一律用 `ui/Hint.tsx` 的 `HintIcon tip="…"`（本体只是带 `title` 的小图标 ⇒ 悬停走 §5 那条自绘接管，**零新增悬停机制**）。
   **收/不收的口径**：`.app-note` 成段说明**全收**；空态里的**常驻引导**也收；**动作/状态反馈**（搜索无果/筛选后空/没有可精炼的资源…）**保持常显**。
   ⚠ **说明不一定挂 `.app-note`**：组装机那处挂的是 `.app-exp-idle`，只扫 `app-note` 会漏（船长就是这么发现漏的）。
2. **标题行字号 = 一个旋钮** `--app-head-fs`（`styles.css` `:root`，默认 13px）：标题 1× · 行内伴随文字
   （`.wui-panel-right` / 标题行里的 `.app-dim` / 行内小按钮）.92× · ⓘ **1.23×**（ⓘ 尺寸由 CSS 覆盖 `svg`，
   `HintIcon` 的 `size` 只作非标题场合兜底）。作用域**只有标题行**（`.wui-panel-head` / `.app-modal-head` /
   `.app-fit-modal-head`）；正文 11px `.app-dim` 一字未动。**要整行放大/缩小只改这一个变量。**
3. **市场详情的高度优先序（改这块前必读）**：**折线图先让（130 → 64px）→ 买卖盘档数再降（8 → 5）→ 才轮到面板体内滚**。
   对应三条不可回退的取值：`.app-mkt-chart-wrap` / `.app-mkt-chart-empty` 的 `flex: 1 1 auto; min-height: 64px; max-height: 130px` ·
   `.app-mkt-detail-books` 的 **`flex: 0 0 auto`**（写成 `0 1 auto` 会与折线图**按比例分摊收缩** ⇒ 买卖盘被抢掉几行、最下面一行裁一半）·
   `.app-mkt-detail { height: 100% }` ＋ `.app-mkt-detail-left` **不得**加 `min-height: 0`（那会让折线图溢出压到买卖盘上）。
4. **右栏高度分配**：富余高度给**第一个**面板（「市场详情」）；「我的挂单」`flex: 0 0 auto; max-height: 40%`，
   且**可见高度由 JS 对齐到整行**（`MarketPage.MyOrders`）——船长明确不接受"半行订单"。
5. **两个 HTML/CSS 级坑（都实测踩过）**：a) `.wui-panel-body` 是 **content-box** ⇒ `max-height` 只限内容、
   内边距另算；b) 对齐整行时**下内边距必须归零**，否则下一行会从内边距里露出一条边。
6. **量尺寸不要量"自己被压缩后的高度"**：买卖盘第一版量自身高度反推行数 ⇒ 它被压到下限后尺寸不再变化、
   `ResizeObserver` 不再触发 ⇒ **卡死在下限**。要量**尺寸由窗口/布局决定的稳定触发源**（面板体），并把各兄弟块一并 observe。
7. **自绘提示接管层**（`ui/Tooltip.tsx`）是 `title` 的唯一出口：新增提示**照常只写 `title`**；实时读数的
   `title` 由该层的 `MutationObserver` 自动重摘（一号 09-14 修）。别在别处再起一套悬停机制。
8. **教程/布局类 effect 的承重写法**：光圈定位四路（首帧/轮询/scroll/resize）**一律只登记 rAF**，
   提交期绝不 `setState`（`f69510b7` 的根因就是提交期连环 setState ⇒ 黑屏）。
9. **手机自绘下拉**：`pointerdown` 只记录，`pointerup` 且自按下 ≥200ms 才插面板，滑动 >24px 不弹（`c6ab776f`）。
10. **合并冲突「并集」不等于「留 HEAD 版」**：两侧同名条目可能内容不同 ⇒ 逐字比对取**较新**那份，
    再跑三条自检（BOM/行尾一致 · 全仓往返解码乱码 0 · 与两侧父提交比"父提交有的行还在"）。

## 5. 血泪清单（本会话真踩过的）

1. **PowerShell 控制台读 UTF-8 中文会乱码**（`Get-Content` / `Select-String` 直出）⇒ 一律用 `read`/`grep` 工具或 .NET `ReadAllText(UTF8)`。
2. **`[System.IO.File]` 的相对路径按进程 cwd 解析**（=`H:\大鲸鱼`），不是 PowerShell 的 `Get-Location` ⇒ 脚本里一律**绝对路径**。
3. **`cmd /c` 里 `^` 是转义符**：`git show HEAD^1:path` 传给 cmd 会被吃掉 ⇒ 先 `git rev-parse HEAD^1` 拿哈希再 `git show <hash>:path`。
4. **`write` 工具新建文件默认 LF**，而本仓工作树是 CRLF ⇒ 入仓前用 .NET 归一（本会话 `ui/Hint.tsx` 归一过一次）。
5. **`.wui-panel-body` 是 content-box**：`max-height` 只限内容、内边距另算 —— 写成"内边距 ＋ 行高"会多让 16px，正好露出下一行的多半截。
6. **量"自身被压缩后的高度"会卡死**：元素被压到下限后尺寸不再变化 ⇒ `ResizeObserver` 不再触发，读数冻结在旧值（买卖盘卡死在 5 档）。
7. **flex 收缩是"按比例分摊"的**：想让某块先让，必须把另一块设成 `flex: 0 0 auto`；否则两块一起缩，最下面一行被裁一半（实测 1600×900 裁 49~53px）。
8. **读数脚本末尾必须 `ws.close(); process.exit(0)`**：否则 WebSocket 吊住事件循环，PowerShell 管道（`Select-Object`）永远等不到输出 ⇒ 表现为"超时且无输出"。
9. **复现"尺寸类"报障必须逐个对象扫**：只量默认选中项会漏 —— 市场内滚那次，默认选中的富凡晶石恰好是**不触发**的那一档（89/123 才触发）。
10. **探针要能覆盖极端档**："我的挂单被遮住一半"只有**22 条挂单**的测试档能复现（船长真档是空挂单）；尺寸类问题要把窗口从小到大扫一遍（1600×900 与 1920×1080 的表现就不同）。
11. **负向验证仍要真红**：本会话每处都留了对照（内滚 89/123 → 0/123 · 重叠 103/123 → 0/123 · ⓘ 卡死 5 档 → 3~8 档自适应），红过再还原复跑。
12. **别把"读数"当观感结论**：观感审查权在船长（§6）——三号只交读数与几何，好不好看请船长本地过目。
