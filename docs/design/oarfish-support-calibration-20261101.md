# 新版支援皇带鱼护航复测

状态：二号完成本轮取数，待船长审阅；船长同意继续新版实战重测。仅独立合成取数，不调整生产参数，不读个人档，不提交合入推送。

## 问题与范围

1. 满载皇带鱼在当前敌人质量、多波及增幅上限下，单船和不同护航是否能打赢？
2. 新版修理无人机、护盾投送力场及阵列与纯炮击/原配装相比如何？
3. 正式离线24小时中，伤损和补给跨场保留后，实际运费、持续运输与净收益如何？
4. 简报中的真实遇袭、战果、交付与消耗是否和独立库存/事件账一致？

沿用`oarfish-escort-readings.ts`合法皇带鱼配装及`sustainFixture`护航基线。固定皇带鱼原货量1,527,660m³作等货量比较，额外单列整队满仓与25%装载；不把护航带来的额外货量偷偷混入对照。后勤支援模板替换高槽前两件为MK2力场与MK2阵列，换载两架修理无人机；其他配装不变。全技能5级、补给充足、仓库补给开。

强制遭遇只用于战斗压力；自然遇袭长流程走`simulateOffline`，不重置损伤、不补回损失、不手动续运、不注入胜利。指标分列运费、战利品现金、目录价补给/机群消耗、沉船舰体装备插件损失及期末维修负债。净收益是成本估算，不是已成交后的钱包净额；不含资本占用、训练采购耗时与未打捞残骸价值。种子样本不是总体概率。

使用游戏设计技能的验证原则：先声明问题和可量化指标，区分单场胜利与可持续循环；不因少数结果擅自追求所有配装等强或扩大玩法范围。

单船满载净值范围约-2.25万～5,250万/小时；完整支援同货量约5,123万～5,864万/小时。范围来自有限种子，不是长期置信区间。完整支援满载每24小时平均补给成本约13,462信用点，维修负债为0；有修理无人机战损，所有无人机损耗计入补给成本，不自动补回装载。

净值公式：实际运输费－补给与无人机损耗目录价－沉船舰体/装配/插件估值－期末港修报价。战利品现金另列，不计入表中运输净值；插件无公开售价时按现行图纸材料目录价估算，不含技能制造减免、替代料择价、资本占用及残骸回收。该批无沉船，因此插件估值未实际扣账。

不同配置会改变战斗耗时和随机数消费，后续运价与遇袭抽样不再逐场配对；混编约5,437万与四炮击约5,226万的差异不能当成确定的经济优势。约7000万的理论读数也不能与这条航线的24小时随机运价、整段交付及停运结果直接等同。

### 独立校验与检查

- 全部场次均校验正式指挥预算及CPU；装载和换装走正式入口。
- 100场压力与56组自然运输的简报耗弹、组件消耗均和独立库存账一致；战斗未退款预载仍计资产，避免误算消耗。
- 自然运输简报的遇袭数、交付段数及运费和独立事件账一致，交付不是用钱包变化代替。
- 56组结束状态均经过正式序列化/读档，运输与海盗快照保真。
- 校准工具及依赖严格类型检查通过；修正后小规模冒烟5场战斗、7组6小时运输通过。此轮未改生产运行逻辑或参数，不替代完整核心回归及船长实机验收。

## 判断与待裁定

当前数据足以支持护航显著改善持续运输；不支持继续增加普通满载敌人的强度或削弱修理无人机。满技能护航样本在当前三波上限内全部获胜，力场模板甚至没有产生组件需求，说明这条路线对它压力有限。减少到25%货量在这些样本中也没有改变单船遇袭即停运、护航均胜的结果，因此承运量的风险收益取舍尚需扩大航线和强度范围验证。

本轮保持全部生产旋钮不动。后续若要调参数，需先明确目标：满载配多少护航应稳定、允许多大停运风险，再比较更危险航线及更低指挥预算，不以本批有限全胜样本直接判定全局过易。
