> **状态：进行中**（三号 · `verify40` · 2026-09-16）
> 归档指向：船长目测验收 + 合入 main 后，关键内容并入 `docs/development-conventions.md` §九（UI 细则）

## 一、船长原话（照抄）

1. 「**装配界面，鼠标悬停槽位上的装备时，显示出的装备详细过于简陋，参考仓库界面的物品详细。**」
2. 「**且装入和更换界面中，鼠标悬停的悬浮窗会被界面遮挡。**」

## 二、两条根因（都查实了，不是猜）

**① 详情简陋**：装配台那三处装备/无人机的悬停只挂了**一行 `title=`**（如
`title={`${fittedDef.name} · ${moduleShortEffect(fittedDef)}…`}`），而仓库页（物品页/货仓页/市场页/手册）
早已统一用**富卡**：`InfoHover` / `ModuleHover` = 标题 + `moduleInfoLines`/`itemInfoLines`
统一参数表 + 数据表描述。
⚠ `ui/shipInfo.tsx` 的注释里其实写着「由市场行、**装配台装备库行、已装槽位行**与手册列表挂载」——
**已装槽位这一处漏接了**，一直停在薄 `title`。

**② 浮窗被遮挡**：`.app-tip`（全局悬停提示层）`z-index: 1000`，而换装浮层
`.app-fit-overlay` 是 **1100** ⇒ 提示层虽然画在最外层的 `fixed` 单例里（`App.tsx` 末尾 `<TooltipLayer/>`），
仍被浮层**整片盖住**。

## 三、落码（3 个文件）

| 文件 | 改动 |
|---|---|
| `ui/shipInfo.tsx` | 抽出**唯一一份富卡皮肤** `infoCardContent(标题, 参数表, 备注, 追加)`；`InfoHover` 改用它；新增两个"不带包裹元素"的出口：**`moduleHoverContent(mod, hint?)`** 与 **`itemHoverContent(item, nameOf?, hint?)`**（供容器标签不能换的场合，如 `<button>` 槽位） |
| `pages/FitPage.tsx` | 三处改挂富卡（**并删掉原来的 `title`**）：① 已装槽位（行动提示降为末行注脚「第 N 位 · 点击更换」）② 换装候选卡（`fitOptionLabel` 那串"第 N 件衰减 / 取最长一件"降为末行注脚）③ 无人机舱单元格（`itemHoverContent`，原"舱内清单"口径降为注脚）。± 按钮与候选卡内的 chip **保留自己的提示**（内层优先，行为不变） |
| `styles.css` | `.app-tip` 的 `z-index` **1000 → 3000** 并写明沿革与规矩：**提示层必须压过全站所有浮层（现行最高 1100）**，今后新加浮层不得超过它 |

**纪律遵守**：① 同一元素**不并存** `title` + `hoverTipProps`（两个提示路径会在同一个单例层上互顶——
`ui/Tooltip.tsx` 明文规定）；② 富内容一律走 `hoverTipProps`（全站同延迟 500ms、同"内层优先"）；
③ 新增的是**复用**（仓库同款富卡），没有自造第二套悬停样式。

## 五、已知取舍

1. **候选卡与槽位都挂了富卡** ⇒ 悬停时会同时看到"卡上已有的一行摘要"与"富卡里的完整参数表"；
   两者不冲突（摘要给扫读、富卡给决策），但如果嫌重复，可以把卡上那行摘要收窄——**等你目测定**；
2. **禁用态候选卡（已装在此位）** 也挂了富卡：Chromium 对 `disabled` 按钮照派发鼠标事件
   （`ui/Tooltip.tsx` 里 2026-09-14 的实测登记），故应照常弹；若真机不弹属观感/交互问题，报我改回 `title`；
3. 本轮**只动装配页三处**：其它页面（市场/手册/物品页/货仓页）本来就是富卡，未动；
   `ui/shipInfo.tsx` 那句"已装槽位行"的注释**现在才成立**。
