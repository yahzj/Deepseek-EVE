# 报障修复：阵亡（已损毁）单位被维修脉冲复活 · 2026-09-19

- **状态：进行中（已实现 · 待船长实机验收）**
- **船长原话（照抄）**：「玩家反应，生物损管腔之类的修理会让已经损毁的船复活」
- 经办：一号 · 修法已落码并自测全绿 · 是否发公告待船长定

## 1. 根因（读码坐实）

`battle.units` 里的**尸体永不摘除**——多波增援、战报、敌方「在场过 = 存在」这几条都靠它
（`combat.ts` 内多处注释：「已入场（含已阵亡的尸体）」）。而**两条维修脉冲原先只查「甲 + 结构是否已满」，
不查存活**，于是三条路都会把尸体修活：

| # | 通道 | 代码位置 | 旧行为 |
|---|---|---|---|
| ① | 本舰自己的无消耗自愈件（生体损管腔 / 生体甲壳板，`repairFree`） | `pulseRepairsFor` 的 `u.free` 分支 | 三层全 0 的船每 5 秒自修结构 4 点 ⇒ 复活 |
| ② | 本舰自己的船体维修装置（耗组件） | 同上，非 `free` 分支 | 每跳修甲 5 + 结构 5 ⇒ 复活，且**白扣一枚组件** |
| ③ | 后勤舰的选靶（「三层剩余比例最低的队友」） | `pulseRepairsFor` 的 `allySpecs` 扫描 | 尸体的剩余比例恒为 0 ⇒ **每一跳必然首选尸体**，既修活它、又让活着的重伤队友拿不到这一跳 |
| ④ | 敌方后勤舰 | `pulseFoeRepair` 的供血方与选靶 | 阵亡敌舰被自家后勤修活；**阵亡的后勤舰照旧供血** |

**为什么必须修（后果面）**：洞内收口按「三层全 0」判沉船（`wormholeBattle.sunkShipIds`）⇒
被修活的船**照常归队**（船 + 货仓 + 装备一起保住，玩家的「已沉没」舰船复活）；
同一条路还会让「我方全灭判负」永远触发不了（场上永远留着一条 4 点结构的船）。

**判据同源**：被动护盾回充（`stepBattle`）、护盾充能脉冲（`pulseShieldChargeFor`）、结束判定
**本来就查 `isAlive`**（三层任一 > 0）——只有维修脉冲这两处漏了，属同一把尺上的缺口，不是设计取舍。

## 2. 改动清单（4 处，全部在 `packages/core/src/combat.ts`）

1. `pulseRepairsFor`：入口加 `if (!isAlive(b, spec.tag)) { r.nextPulseAtMs = undefined; return }`
   —— 本舰阵亡 ⇒ 整台装置**永久停机**（尸体不会回到场上，无需再排程）。
2. `pulseRepairsFor` 后勤选靶：候选循环加 `if (!isAlive(b, tag)) continue` —— 阵亡队友不进候选，
   这一跳改修**活着的**最缺血队友。
3. `pulseFoeRepair` 供血方：`donors` 过滤加 `isAlive(b, s.tag)` —— 阵亡的后勤舰不再产生修理值。
4. `pulseFoeRepair` 选靶：目标扫描加 `if (!isAlive(b, s.tag)) continue` —— 阵亡敌舰不被修活。

**不做**：不改「尸体留在 `battle.units`」这条既有口径（多波/战报/续战都依赖它）；不改任何数值与文案。
