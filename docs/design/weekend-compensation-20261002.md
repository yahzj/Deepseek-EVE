## 二、成因（一号 2026-10-02 核过）

1. 本期该出哪一族按**窗口 T0**（最近一个周五 20:00）算：`weekendFamilyForWindow(weekendT0Of(now))`
   ⇒ 10-02 20:00 那一期 = **光环科技**（族循环锚点与「特意设置某一期」两处都指向 R）。
2. 但开新场有一条硬前提：**「上一场还没结束 ⇒ 本期不开」**（`weekendEvent.ts` `ensureWeekendEvent`）。
3. 而"上一场"何时结束：周排期场到**下一期 T0** 才收场、**玩家召唤场豁免**那条、只按自己那 96h；
   另有「正在打旗舰战 ⇒ 顺延到打完 + 60 秒」。
   ⇒ **上一期（墨潮帮）那场结束得晚或还没结束**的档，本期压根不开新场 ⇒ 界面里**还是墨潮帮**。

## 四、不做 / 边界

- **不动**玩家手上正在打的那场（补偿只在他手上没场时开）；
- **不改**族循环（本批一字未动；⚠ **附带发现**：族循环锚点常量比它自己的注释晚 8 小时 ⇒ 「10-09 那期 = H」
  实测不成立，见 §七）；
- 受影响玩家**不发**信号发射器（只开补场）；其余玩家**只发**信号发射器（不开补场）——**一人一条路**；
- 不动入侵其它收益（夺回奖 / 进度收入 / 声望 / 黑匣一律照旧）；
- 补场**照常规场**结算（不进 `beaconLit` 那条：声望不按"点火场固定 5 点"算）。

**已知边界（如实记账）**：补场开新场时仍走**声望前提** `weekendInvasionAllowedFor`（≥40 累计声望）——
与排期入侵同一条门；若某档在补偿窗口内声望不足，补场不开（该档本来也开不出任何入侵）。若船长要
"补偿不受声望门限制"，改一行即可。

## 七、附带发现（**不在本批范围 · 未改**，报请船长裁）

一号在做 §三 的日期锚时，用**真实函数**核对族循环，发现 `weekendEvent.WEEKEND_FAMILY_ROTATION_ANCHOR_WALL_MS`
的现值 **`1_790_971_200_000` = 2026-10-03 04:00 本地**（＝`2026-10-02T20:00Z`），**比它自己的注释
（「循环锚点 = 2026-10-02 20:00（本地墙钟）」）晚 8 小时**：

| 期（本地周五 20:00） | 期号 | 实测族（`weekendFamilyForWindow`） | 注释里的意图 |
|---|---|---|---|
| 2026-10-02 | 0 | **R**（光环） | R ✓ |
| 2026-10-09 | 0 | **R（光环）** | **H（墨潮帮）** ✗ |
| 2026-10-16 | 1 | H | R ✗ |

⇒ 族循环**整整错一期**（被 `Math.max(0, …)` 的钳位遮住了前两周）。一行可修：
把常量改成**本地** 2026-10-02 20:00（`new Date(2026, 9, 2, 20, 0, 0, 0).getTime()`）。
**本批刻意不顺手改**（不属本批范围，且会改玩家可见的族排期）——**等船长一句话**。
本批自己的日期锚已按**本地时间组件**算（`weekendCompensation.localAt20`），不受该常量影响。
