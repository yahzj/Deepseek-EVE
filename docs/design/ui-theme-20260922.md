## 四、方案（落地形状）
1. **token 化**：颜色字面量收成语义变量，写法用**空格分隔三元组**（`--wui-text: 200 214 229;` ⇒ `rgb(var(--wui-text))` / `rgb(var(--wui-text) / .08)`）—— 这样 605 处 `rgba()` 的**透明度变体**不用各占一个 token。
   **实测规模**：`styles.css` 974 处字面量 → 改写 944 处，**只剩 85 处阴影/滤镜里的颜色故意保留**；TSX 内联色 30 处 → 全部收口（含战斗画面血条/弹道/敌舰名、无人机描边、物质科技页签）。
2. **主题**：根元素 `data-theme="deepspace|daylight"`；`:root` 放深空默认值，亮白只**覆盖**差异项。**481 个色 token × 2 套**，键集完全一致（由 ② 项守）。
3. **语义色阶单点化**：新增 `ui/tones.ts`（135 条 → 键 → `var(--wui-tone-*)`）＋战斗/无人机/页签等 14 条补齐 token；`Glyphs.tsx` 只做转出。
   ⚠ **踩过的坑**：色值走 `var()` 后，**SVG 呈现属性（`fill="…"` / `stroke="…"` / `stop-color`）不认 var()** ⇒ 会静默渲染成默认黑。
   已把 `Glyph`、战斗射程弧、族色光晕渐变、星图火花点、货仓箭头等 8 处改成 `style={{ … }}`；这条写进了 `ui/tones.ts` 文件头防再踩。
4. **深空 = 现状**：原本承诺"默认皮肤视觉零变化"——**该承诺已由船长两轮口径取代**（见 §六）。
5. **入口**：`App.tsx` 的 `SettingsPanel` 新增一行「界面配色」（深空 / 亮白 / 跟随系统）+ 亮白下禁用「换一张宇宙底图」并给出说明；键 `whale-idle:ui-theme`（不进存档、零迁移）；首帧前写 `data-theme`（不闪）。
6. **字号上限**：125% → **150%**（默认字号未动 ⇒ 排版零风险）。
7. **闸门**：`npm run ui:contrast`（真实底像素对比度，两套主题）+ `npm run ui:theme-check`（引用齐全 / 键集一致 / 深空基线冻结 / 无残留字面量 / 前景×底色对比度）。

## 八、三次事故与它们的守门人（如实记录，防再犯）
1. **裸 `var()` 当色值用**（船长报「字都没办法辨认」的真因）：色板 token 是**空格三元组**，必须包 `rgb(...)`；
   而仓里原有 **481 处**是"token = 完整颜色"时代的裸写法 ⇒ 那些声明整条失效、`color` 回落**黑**。
   深色皮肤上黑字压深底=看不见，亮色皮肤上碰巧正常 ⇒ 只在深空暴露，我上一轮的双主题体检也因此没抓住。
   **已修 470 处**；守门人 = `ui:theme-check` **⑥ 无裸 var()**。
2. **降刺眼时把"面"当"字"压**：按"压在面板上 ≥4.5"对所有色阶压实 ⇒ **浅色底**被判"对比度不足"而**压暗**，
   导航栏/顶栏变中灰 `rgb(90,90,94)`、其上深字掉到 **1:1**（亮白一夜之间从 12 项不合格变 404 项）。
   根因 = 没区分"面"与"字"。**修法**：亮白色板按**角色**重生成（判据 = 它在深空里亮不亮：
   亮 ⇒ 是字/图标 ⇒ 取反后压实 ≥4.5；暗 ⇒ 是面/槽/边 ⇒ 取反后**中性化 + 封顶 93%，绝不压暗**）。
   工具：`tools/_daylight-regen.ts`（一次性探针，逻辑已固化进 `ui:theme-check` ⑤ 的口径说明）。
3. **数据侧写死的浅色**：通讯页发件人色调来自 `packages/data/src/commsFactions.ts` 的 hex（`#ff8ab5` 等），
   亮白下只有 **1.7:1**（我前几轮的 TSX 字面量扫描没覆盖 `.ts` 数据文件 ⇒ 漏网）。**修法**：改为引用既有色阶 token
   （`var(--wui-tone-nav-ai)` 等），并同步放宽 `content:check` 的势力色调形参（hex **或** `var(--wui-tone-…)`）。

**教训（写给以后的自己）**：颜色 token 化的坑**不在"颜色选得对不对"，而在"用法是否合法"** ——
三元组必须包 `rgb()`、SVG 呈现属性不认 `var()`、"面"与"字"不能同一套标准压。三处各配了一条可复跑的契约。

## 十二、追加（2026-09-22 晚）：图标失效事故 + 三套新主题【待修】

### 12.1 「各种 svg 图标都失效了」（船长报障 · **已修**）
真因：`ui/tones.ts` 的 `toneVar()` 生成 `'var(--wui-tone-*)'`，而色板 token 是**空格三元组**
⇒ 当色值用**必须包 `rgb(...)`**。图标色全走这张表 ⇒ `stroke` 整条失效、线稿消失
（填充型 `currentColor` 图标不受影响，所以是「各种」而不是「全部」）。
**修法**：`toneVar` 改为 `rgb(var(--wui-tone-…))`；**守门人 = `ui:theme-check` ⑥-b**：
CSS **与渲染层 TS/TSX 一起查**裸 `var()`，并点名"拼接式色值串缺 rgb() 包装"。

### 12.2 三套新主题（`warm` 暖色护眼 / `night` 纯黑夜间 / `cb` 色盲友好）：**已修好并放行（六套齐）**
**真因**：生成这三套时，"压实前景色"的角色判据只看了 token 名字前缀（`bg-`/`border`…），
而**长尾 token 叫 `x24`/`x74` 这种看不出语义** —— 它们是**导航栏/顶栏的底色**（深空里是深色），
却被当成"字"**提亮到 4.5:1** ⇒ 导航栏被点亮、其上文字掉到 **1:1**（三套各约 400 处不合格）。
**修法**：判据改为**看它在深空里亮不亮**（L ≥ 0.55 ⇒ 字/图标；< 0.55 ⇒ 面/槽/边，一律不许提亮）——
与亮白侧同一把尺子。压实项数从 158/135/151 降到 **26/4/17**（说明之前是"大面积误伤"）。

**复验（真实底像素 · 9 个一级页 + 设置面板）**：`warm` 不达AA **2** / 低于3 **0** · `night` **1 / 0** · `cb` **2 / 1**
—— 与原有三套同一量级（深空 1/0 · 亮白 7/1 · 高对比 0/0）。

**另一条踩坑记录**：`readChoice()` 按 `THEME_CHOICES` 校验本机偏好 ⇒ **把某套主题从表里撤下后，
连探针都读不进来**（报"主题没生效：data-theme=deepspace"）。调试某套主题前，先确认它在表内。
- 色板块已写入 `packages/ui/src/index.css`（各 481 token，键集与深空一致 ⇒ 契约 ② 过；色板层对比度全部 ≥4.5:1）；
- **元素级体检未过**：真实底像素下约 **400 处低于 3:1**（`cb` 401 · `night` 370 · `warm` 432），
  而同一批元素在深空 / 亮白 / 高对比下都正常（0~7 处）⇒ 差异只在"识别色色相被重映射"这件事上，
  怀疑与**识别色既当文字、又当半透明底**有关（色相一换，底与底上文字的对比关系就变了）。
