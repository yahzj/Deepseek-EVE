## 一、机制语义

**现状**：一张卡的编成单位**开战即全部在场**；多波次（`AnomalyDef.waves`）只在**整波清空后**换来下一波。

**本机制**：给**单波次内**的某个编成条目一个**入场时机**——它开战**不进战场**，
由 `advanceBattleFor` **每拍**检查条件，命中才**入场**。用于"**打着打着援军赶到**"这类节奏，
不必走"整波清空"的粗粒度转场（波次转场还有 3.3 秒演出窗口 + 距离重开，粒度太粗）。

### 1.1 触发条件（`FoeShipSlot.enterAt`，任一满足即入场）

| 字段 | 语义 | 有效值 |
|---|---|---|
| `sec` | **开战满 N 秒**后入场（战斗时钟 `lastTickGameMs − startedAtGameMs`，与推进器相位同口径、波次演出窗口不计时） | `> 0` |
| `afterKills` | **本场已击毁的敌方单位数 ≥ N** 时入场（三层血全归零即计；尸体留在 `battle.units` 里，直接数） | `> 0`（取整） |
| `hpBelow` | **己方（本波敌方编成）存活剩余总血比例 ≤ N** 时入场（"**残部呼救**"） | `0 ~ 1` |

- **未写 = 开战即在（= 现状，逐字不变）**；
- **三个条件一个都没写（空对象 / 全非法值）同样按"未写"处理 = 开战即在**——
  刻意**不产生"永不入场"的沉默副作用**（少报一个单位比多报一个更难查）；
- ⚠ `hpBelow` 的分母 = **本波编成的满血总量**（含尚未入场的增援——"残部呼救"要按编制总量看），
  分子 = 在场单位的剩余三层血之和。它指的是**敌方自己**的残损；若要"**玩家残血才来援**"，
  **请另加字段**（如 `playerHpBelow`），**不要改本字段语义**（会造成两张卡两种意思）。

### 1.2 入场表现（与波次转场同款）

- `seedUnit(battle, spec, { enterReload: true })` —— **哑火窗口 ≈ 一次装填时长**（与波次增援一致，
  给"援军抵达"一段自然的不开火缓冲，不改变任何结算语义）；
- **日志**：与波次转场同风格的一条 `warn` 日志 →
  「⚔ 敌方增援自远处入场（{星系}·{卡名}）：{舰级名} ×N 加入战斗。」（`addLog` 即既有机制）；
- **界面提示复用现有机制**：① 上面那条战报日志（`BattleScreen` 已读 `state.logs` 的最近战报）；
  ② 入场单位**自动出现在敌舰名录/血条/武器弧**（既有渲染，无需改动）。
  **刻意不新增界面标记字段**——那会引入新的存档字段，与"存档零迁移"的红线冲突
  （「敌突进中」用的是 `battle.foeChargeOn`，本机制按裁决**不加字段**）。

### 1.3 距离重开（独立旋钮）

`BattleBalance.foeReinforceReopenFrac`，**语义完全沿用 `waveReopenFrac`**：
入场瞬间把战斗距离向**开战距离**回拉这个比例（`0` = 原地入场不重开 = **缺省口径**；`1` = 回满）。
「增援自远处入场、重新接近中」的观感就来自这个旋钮。

### 1.4 判胜口径（**重要**）

**未到触发点的增援不参与判胜**：在场者全灭即胜——「**援军来不及赶到**」是一种合法结局（也是玩家的操作奖励）。
替代方案（"有未到场援军时战斗不结束"）会让 `afterKills` 这类**可能永不命中**的卡**无限拖到 10 分钟硬上限**，
且要改判胜逻辑，**本批不做**；若将来要这种语义，需单独裁决。

### 1.5 存档零迁移（红线）

- **不新增任何存档字段**。判断"某个单位是否已入场"= **`battle.units` 里有没有它的 tag**
  （`seedUnit` 对已存在的 tag 不覆盖，尸体也留着，所以"在场过"永远是"存在"）；
- 读档续战时 `advanceBattleFor` 用**同一份编成**重新推导，未入场者继续等条件命中；
- 已入场的单位**本来就在 `battle.units` 里**（旧档天然兼容，无版本迁移、无 normalize 改动）。

### 1.6 仅舰级路径

`enterAt` 长在 `FoeShipSlot` 上 ⇒ **只有写了 `ships` 的卡**（舰级路径）能用到；
**旧威胁推导路径（未写 `ships` 的卡）完全不受影响**（用一条用例显式覆盖）。

## 三、⚠ 与「多舰补偿系数 `2N/(N+1)`」的关系（**不可叠加**）

A 族数值批（2026-09-11）引入了**数值层的多舰船补偿**：N 个单位**逐个被击毁**时敌人整场累计输出只有
账面的 `(N+1)/(2N)`（N=4 → 62.5%），故把名义 DPS × `2N/(N+1)`（N=4 → ×1.6）**在数值上补回来**。

两者解决的是**同一个问题**，但走的是两条路：

| | **多舰补偿系数（已在用）** | **单波次内增援（本机制）** |
|---|---|---|
| 层次 | **数值层补偿**：把"阶梯衰减"折算进单发 | **结构解法**：让 N 个单位**不再同时在场**，分批到场 ⇒ **阶梯衰减本身不成立** |
| 代价 | 敌人单发被放大 1.6 倍（对玩家的瞬时压力上升） | 需要关卡节奏设计（什么时候来、来几艘） |
| 适用范围 | 舰级路径**全部**多单位卡（现为 A 族 6 张） | 逐条目可选（写 `enterAt` 才生效） |

⇒ **若将来启用增援，多舰补偿系数必须下调或退场**：否则同一件事被补两次
（援军"分批到场"已经消掉了衰减，再 ×1.6 就是**双倍补偿**，实际火力会明显超标）。
启用批的推荐流程：
1. 先用**被增援的卡**做对照实测（补偿系数仍为 1.6）→ 看实际火力与难度；
2. 把该卡的补偿系数**按 N 重新标定**（或用"在场单位数"口径）→ 直到实测难度符合设计；
3. 全批复核（`battle:calibrate --csv` 逐卡对照）后，再考虑把补偿系数从"按编成总数 N"改成"按在场单位数"。

⚠ 另有一条**已知口径**（启用前需裁决）：`battleOpenM` / `foeDesiredRange` / 预估胜率目前都用**全编成**推导，
即"还没到场的援军也参与期望交距与胜率预估"。启用时应决定是否改成只看**已入场单位**（改动面在若干调用点）。
