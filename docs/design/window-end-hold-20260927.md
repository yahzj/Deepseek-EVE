# 窗口到点顺延：玩家打完再满 60 秒才收场（2026-09-27 · 二号 · d2）

状态：**进行中（待船长验收）** · 船长原话已落码 · 自测全绿 · 归档按 AGENTS.md §8（等验收 ＋ 合入 main 后）。

## 船长原话（照抄）

> 「**复活的保持现状。不发公告。到点的延期到玩家打完1分钟后。**」

三句分别对应：① 支援舰参战**保持现状**（不加闸门/限幅，无需改码）；② 这条改动**不发玩家公告**；
③ **窗口到点那一刻正在打的旗舰战 ⇒ 顺延到"玩家打完 1 分钟后"**（本批唯一落码的一件）。

> 「**如果顺延到了下次入侵还没结束，那么下一次入侵将会被顶掉。**」
> （追问澄清）「**被顶掉的意思是，直接错过该次入侵。**」
> （当日最终裁定）「**假设，入侵我拖了一周，到下周该开入侵的时候，我还没结束。那么下周的入侵就应该取消。
> 按照这个修改**」

⇒ 第一句点出的洞**真实存在**（第六节有探针读数）：改动前新场照开、**被顶掉的是旧场**——它永远不会被标
"结束"，`weekendSettleAndGrant` 又不认没结束的场 ⇒ **贡献奖 / 待到账夺回奖励 / 协会声望 / 结束通讯一起
静默丢掉**。中途我一度按"到点先给旧场收口、下一拍再开新场"实现，**船长随后改判**：拖过一周就**取消那一周
的入侵**（旧场照旧由玩家打完）⇒ 现按最终裁定实现（第六节）。

同日两条追问的裁定（本次一并落）：

| 问 | 裁定 |
| --- | --- |
| 顺延要不要设时限？ | **甲：不设** —— 只要那场没打完就一直等；真拖过一周 ⇒ 下一场入侵取消（最终裁定） |
| 顺延期间章鱼人要不要一起闸？ | **要** —— 只要有没打完的旗舰战，本拍既不由章鱼收走、也不按窗口结束 |

## 前因（这条在修什么）

`weekend:sim` 的 `window` 场景（打到一半活动窗口到点）改动前坐实：**母舰血条照掉到 0，但这一场整场作废**
——伤害台账不记、不判击沉、不掷黑匣、不发残骸、一条旗舰日志都没有。病根是 `weekendTick` ④ 在窗口
到点那一拍**不看有没有战斗在打**就 `endWeekendEvent`，而结算侧随后以"本场入侵已结束"回落。

## 一、口径（现行）

- **判据 = "此刻还有一场没打完的旗舰战"**：`weekendLaunch.weekendFlagshipBattleActive`（读的是**存档里的
  遭遇槽**，与战斗界面、章鱼停工同源单点）⇒ **打到一半退出游戏、回来接着打也算"没打完"**，不会因为
  掉线把这一场丢掉；
- **顺延**：窗口到点后有战斗在打 ⇒ 本拍**不结束**，把 `ev.windowEndHoldUntilWallMs` 推到 `now + 60 秒`
  （新常量 `WEEKEND_WINDOW_END_HOLD_MS = 60_000`，与章鱼停工 `WEEKEND_OCTOPUS_HOLD_MS` **同值但语义独立**）；
- **结束**：战斗结束后这 60 秒走完（`now >= windowEndHoldUntilWallMs`）那一拍，才按窗口到点结束本场
  ⇒ 结束文案走已有的 `ui.weekend.117`（"窗口到点但本场有旗舰"，此前是**不可达**的一档）；
- **不设上限**（船长裁定甲）：那场没打完就一直等；真的弃场 ⇒ 本场入侵吊着，直到下周窗口
  `ensureWeekendEvent` 开新场时被顶掉（最坏 = 那几个星系这一周一直是占领状态）；
- **章鱼人一起闸**（船长裁定）：`weekendTick` ③ 的"得手"判据加同一把闸 ⇒ 顺延期间它既不削血
  （原有 60 秒停工照旧）、也**不判得手**；否则"离线超 24h 回来"那一拍它会先把玩家正在打的那一场判走；
- **只有旗舰战触发**（与章鱼停工同一把尺）；其它入侵战斗不顺延；
- **结算侧一个字都不用改**：顺延期间活动仍然活着 ⇒ 伤害/判沉/黑匣/残骸/日志全走正常路径。

## 六、拖过一周 ⇒ 下一场入侵取消（船长当日的最终裁定）

**船长原话（照抄）**：「**假设，入侵我拖了一周，到下周该开入侵的时候，我还没结束。那么下周的入侵就应该
取消。按照这个修改**」（前两句：「如果顺延到了下次入侵还没结束，那么下一次入侵将会被顶掉。」＋
「被顶掉的意思是，直接错过该次入侵。」）

**先核实（临时探针，跑完即删）**：摆一场"弃场"（窗口到点后一直处于战斗态 ⇒ 顺延一直推）＋ 把墙钟拨到
下一场入侵的 T0：

| 读数 | 实测（改动前） |
| --- | --- |
| 下一场入侵开不开 | **开**（`seq` +1、`startedAtWallMs` = 新 T0） |
| 旧场 | `endedAtWallMs` **仍然缺省**、`prizePaidAtWallMs` 缺省 ⇒ `weekendSettleAndGrant` 返回 **null** |
| 结论 | 被丢的是**旧场**：它的**贡献四档奖 / 待到账的夺回奖励 / 协会声望 / 结束通讯**一起静默消失 |

⇒ 病根：`ensureWeekendEvent` 到点**直接换掉** `state.weekendEvent`，而结算要求 `endedAtWallMs` 有值。
这个洞**顺延之前就存在**（玩家整周没上线同样会踩），"不设时限的顺延"只是把它变成了常规路径。

**中途方案（已按船长改判撤掉）**：我一度做成"到下一场 T0 就先按窗口到点给旧场收口、下一拍再开新场"
（旧场不再被静默丢弃，新场照开）。船长随后裁定要的是**取消下一场**，于是改为下面这条。

**现行实现（`ensureWeekendEvent` 正常模式）**：

```
开新场的前提 = 上一场**已经结束**（ev.endedAtWallMs !== undefined）
```

- 玩家把入侵拖过窗口（顺延让它继续活着）、到下一个 T0 还没收场 ⇒ **那一周的入侵不开**
  （`started=false`、不记"入侵开始"日志 —— 界面本来就靠"有没有入侵"表达，无需新文案）；
- **旧的这一场照旧活着**、照旧由玩家打完（没被强行收口、也没被顶掉）：打完收场后若还落在某一周的窗口内，
  当周照常补开新场；窗口已过则等下一个 T0；
- **连续拖 ⇒ 连续取消**（不是"只取消一次"）；
- 这条规则顺带**永久堵住**"覆盖未结束的场"：只要不覆盖，`weekendSettleAndGrant` 就永远等得到
  `endedAtWallMs` ⇒ 旧场的奖励/声望/结束通讯一条都不会丢；
- 原有的"一个窗口只开一场"（`now − startedAt < 96h ⇒ 不开`）**照旧保留**（管"同周不重复开"）。

## 四、边界与已知效果

- **界面零改动**：入侵界面本来就没有窗口倒计时（船长 2026-09-25 让撤了）；顺延期间玩家看到的就是
  "战斗还在打、活动还没结束"，结束时正常弹那一条结束通讯。**"下一场取消"不加任何新文案/提示**
  （界面靠"有没有入侵"自然表达）；要加一句说明的话，说一声我再补 id ＋ 中英。
- **拖过一周的代价**（船长定的规矩）：那一周的入侵**取消**（不开新场）；旧的这一场照旧打完、照常结算；
  连续拖就是连续取消。
- **不覆盖的边角**：顺延只认"遭遇槽里那一场旗舰战"。玩家在窗口到点前**没有**开打 ⇒ 照旧按窗口到点
  结束（旗舰撤走、不判击沉）——这一档口径未变。
- **与"章鱼停工"两把闸各自独立**：一个管"章鱼什么时候开始削"、一个管"窗口什么时候算到点"，
  常量同值但**不许合并**（日后要调其中一个，另一个不受影响）。
