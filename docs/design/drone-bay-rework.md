## 一、背景与动因
- 校准首次覆盖无人机(D1-D3):满技能全面超同船炮流;且"战斗自动贪心装载"使玩家无法指定出战无人机、
  机舱/预算不可见、无法为"击毁/消耗"机制做准备;全船机舱无定位差异(武装线 30~130 随手给)。
- 船长实测反馈后拍板系统大改(见下)。

## 二、定稿口径(船长 Q1-Q7 拍板)
1. **新「无人机舱」区**:装配页**低槽组下方**新增区块(默认命名「无人机舱」),内部:
   - **容量条**(参考 CPU 条视觉)显示在**卡片流上方**(即低槽组与卡片之间;不在页面顶部 CPU 条旁):
     `m³ 已用/上限(船体 + 已装「甲板扩展」)`;上限 = 机舱容量(单位 m³),已用 = Σ(架数×单架 unitM3);
   - **卡片流 = 一型一张卡 + ×N 乘数**(不逐架铺卡);卡上 **+ / −** 微调数量(钳到余量)、
     **「全部卸下」专用按钮**(清空清单,全部退回仓库;不做逐型卸下——船长定"卸下 = 全部卸下");
   - 空态:单张「+ 装入」占位卡,点击弹层「选型 + 数量」(数量受 舱容余量 与 CPU 余量 钳制);
   - 高槽的「甲板扩展/战术导控」机制不变(扩容/增伤照旧)。
2. **只放飞已装入**:战斗装载 = 读该船 `droneLoad` 清单(不再从仓库/货仓自动贪心)。清单空 = 无无人机。
3. **CPU 预占**:每架 cpuUse 在**装入时即计入**船体 CPU 预算(与装配/高槽装置共用池;船长确认)——
   装配页 CPU 条、装配校验与装载钳制同源;装配改动(换装)不会挤爆已装载无人机(校验互斥)。
4. **清单入存档**:舰船新字段 `droneLoad: Record<droneId, count>`(0 键删除;旧档缺省 = 空 = 无无人机)。
5. **回港自动补充(结构预留,本轮不激活)**:引擎留「停靠时按清单补足」钩子与注释——
   **本轮不实装无人机被击毁**(价格/自制蓝图未配套,船长 2026-09-08 定);
   激活点注:未来开击毁时 `droneLoad` 宜作"配置目标",实载另记(见 §七)。
6. **手册/词典/文案**:手册「装配」条目与物品页说明改为新口径(只放飞已装入、回港补足预留语不提前出现)。

## 五、数据 / 存档 / 引擎设计
- `state.ts` 舰船实例字段 `droneLoad?: Record<string, number>`(数量制;0 清理;缺省无);
- `save.ts` normalize 清洗(正整数、删 0/非法类型;无版本号,旧档零迁移);
- 引擎装载(combat buildUnit):读 `droneLoad` 逐型生成武器条目(伤害 = dmg ×(1+Σ导控)×(1+无人机作战学 5%/级);
  装填 2200×整备技能(不变);**不再读仓库/货仓贪心**;CPU 防御截断保留(若装配后余量不足清单,从清单
  逆序剔除超量并 warn 日志——正常由 UI 预占互斥避免);
- CPU 汇总 helper(export,供 UI/校验):`Σ(count × ItemDef.cpuUse)` per ship;
  装配校验(fit/unfit)与 CPU 条把该船无人机占用计入;
- 回港补足钩子:停靠处理点调用 stub(本轮 noop,注释激活条件)。

## 六、UI 设计(装配页 FitPage,样式同级复刻)
- 布局:低槽组下方新增「无人机舱」组;组头 = 名称 + 「全部卸下」;
- 容量条 = CPU 条同款视觉(`app-fit-cpustrip` 族复用/适配),文案 `m³ 已用/上限 · 占用 CPU X`;
- 卡片流:型卡(icon + 名称 + ×N + [−][+])→「+ 装入」占位卡;
- 装入弹层:4 型列表,每型选数量(自动钳 舱余量/CPU 余量),确认装入;
- 目标船 = 装配页当前目标(非驾驶船也可配,同 fit 语义)。
