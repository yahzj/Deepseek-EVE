## 3. 本会话引入的引擎能力与契约（接手人先看这一节）

**新字段**
- `ModuleDef.repairFree`：无消耗自愈（不吃修理组件、永不停机；与 `repairKit` **互斥**，护栏强制二选一）。
- `ModuleDef.hullResistAdd`：结构层抗性（缺口复合）。
- `ModuleDef.speedPenaltyPct`：**机动代价**（只许挂装甲容量件；`speedMps ×(1−值)`；**多件取最重一件**）。
- `ModuleDef.hullHpBonus`：**结构层容量**（此前唯一没有容量模块的一层）。
- `ItemDef.exclusive`：**专属型号**（只在高级箱出；死物品护栏改判"不得有市场卡"；四型定位契约豁免区间校验）。
- `AnomalyDef.dmgMix`：**语义变更**——正权重键 = 参战系（≥2 系即混伤、份额归一化）；旧"缺省键权重 1"作废。

**既有字段的新用法**
- `FOE_LAIR_GEAR` 池**可混装模块与物品**（模块进装备库、无人机进物品仓库）。
- `equipment.ownedItemCount`：物品持有口径（仓库 + 各船机舱）——专属无人机"打光后再进池"的依据。
- `salvage.RARE_BOX_DRONE_UNITS` = 10：专属无人机一次掉落架数。
- `lairs.FOE_SUB_DMG` / `LAIR_SUB_DMG_SHARE` / `lairAnomalyOf`：窝点混伤 6:4 与副系族签名。
- `combat.foeDamageComposition` / `splitShotByComposition` / `applyFoeShot`：混伤三件套（战斗、预估、界面同源）。
- `data/droneRoles.DRONE_ROLE_ANCHORS`：四型**锚点机型**（阶梯与单发基准只比锚点）。

## 7. 风险与注意事项（踩过的坑）

- **`docs/roadmap.md` 是最常见冲突点**：两位 agent 都往顶部插条目 → 解冲突口径 = **两条并存**；
  实操上先 `git checkout --theirs docs/roadmap.md` 再把自己的条目重插（注意：`git add` 之后再编辑
  必须**再 add 一次**，否则合并提交会漏掉新内容——本会话踩过两次）。
- **合入前先看主树脏不脏**：git 会拒绝覆写对方未提交的文件（`lair.ts/salvage.ts/types.ts` 都遇到过），
  此时**停手报告**、绝不 force；对方提交后再合。
- **混伤与高级箱同日生效**：实测时"敌人变疼"与"掉落变好"是两件叠加的事，别把观感混在一起归因。
- **无人机是消耗品**：专属无人机打光后可再刷（池子会重新收它）；机舱/CPU 上限照常约束放飞数。
