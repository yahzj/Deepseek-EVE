## 一、船长原话与授权范围

船长对本轮三个关键问题的答复：

1. 「我授权你在该仓本地改并本地提交」
2. 「第一版走『只做只读对账与观测，不动资金/库存、不改存档表』」
3. 「按方案一次改完」
4. 「可以修改文档记录进度」「开工吧」

**主代理对第 2、3 条的解释（已在开工前写明、船长未叫停）**：第 2 条约束的是系统做市账户的资金/库存及其持久化方式（不改 `MakerInitialCash`/`MakerInitialShares`、不改 `saveAccountTx`、不加 SQLite 表）；第 3 条「一次改完」指功能范围（两层自适应 + 六人格覆盖/追单上限/冷却/券源与风险预算一次落地）。动态深度与价差只改内存报价参数，统计只做只读聚合，两者因此不冲突。

此前船长给出的方案要点：6 人格不增至更多，按 6 家风格不同的机构设计；调节依据用真实交易需求而非在线人数；系统做市商负责 8 只股票基本双边深度，六人格提供可观察可博弈的机构行为；避免「玩家买 AI 就砸、玩家卖 AI 就拉」；人格扩大覆盖时共享自有账户与总预算，不复制本金；不先提高每回合 2 单上限；20%～40% 只作模拟实验区间，不直接当上线定值；杠杆按名义金额计；撤单与反复挂单不能扩容。

## 二、范围与不做

**本批做**：

- 只读交易需求观测：独立玩家账户数（自动策略与所属账户合并计一次）、委托名义、成交额、符合成交条件却未成交额、买卖两侧失衡、`mm`/人格/玩家三方承接占比、两侧深度与价差、系统做市账户现金与库存（只读对账）。
- 一小时（12 回合）滑动窗口 + 不对称 EWMA：需求上升权重 50%、下降 12.5%，收缩慢于扩张。
- 两层自适应：系统做市商每档名义与价差；六人格单笔预算、标的覆盖、连续追单上限、按偏离分配资金、空头风险预算、克隆潮规模上限、利维坦冷却期。
- 合成账户压测：20/100/300 活跃玩家、少数巨鲸重仓、全员同向买入、集中平仓，外加按各标的最高合法杠杆档（2～90x）放大仓位的高杠杆场景；20%/30%/40% 系数对比。
- 公开只读接口 `GET /api/exchange/demand`；后端仓 `HANDOFF.md` 与本工作文档留痕。

**本批不做**：

- 不改系统做市账户现金/股票库存、不改 `saveAccountTx`、不加 SQLite 表或列、不改存档结构。
- 不给六人格补钱、不改 2 亿初始资本、不改每人每回合 2 单上限、不改六人格注册表与性格信号。
- 不改客户端 UI、不新增玩家可见文案、不改已发布公告、不准备公告待审稿（本批无玩家可见变化）。
- 不推送远端、不部署腾讯云、不改 systemd 环境变量、不读船长真档。

## 四、实现口径

- **有效需求** = 玩家成交额 + 符合成交条件却未成交额。`price × qty` 已是名义金额（杠杆放大的是可买股数，体现在 `qty` 里），不再乘杠杆档，避免把保证金口径重复放大。委托名义只作观测；不跨清算价的挂单、撤单与反复挂单不计入扩容。
- 统计只取 `account_id > 0` 的玩家委托；人格（负数 ID）与系统做市挂单（无数据库行）不算玩家需求。人格只读聚合后的公开热度，不读单个玩家身份与单笔委托明细，保持原公平红线。
- 观测随 `settlePlan` 走，**只在结算事务成功后**并入窗口；失败回合不计入。窗口是纯内存、不落库，重启后冷启动回到基础值。
- **六人格预算**：合计目标 = 该股票平滑有效需求 × 目标系数（默认 3000bp），按各人格 `OrderBp` 分摊；受 `MaxPosBp` 仓位上限、自有现金、库存、券源/保证金、缩放上下限约束。无观测数据或该股票冷清时退回原固定预算，保证冷启动与既有确定性用例行为不变。
- **系统做市商**：需求未超过基础深度（每只股票双边 2 亿）时保持 5 档 × 2000 万与 30bp 价差；超过时按平滑值放大每档名义并收窄价差，买卖长期失衡时略放宽，放大受 4× 上限约束。只改内存报价参数。
- **六人格分工落地**：星门局按流动性缺口排序并逐回合轮换覆盖（冷清时在 8 只间轮换）；锚定者按低估偏离程度加权分配资金并保留单只集中度上限；截击者只放大有主动成交支持的趋势并设连续追单上限；黑隐者受券源、保证金与空头风险预算三重约束；克隆潮放大倍数上限减半；利维坦金额随有效需求缩放、冷却期随市场规模延长。所有订单仍共享各自账户与总预算，每回合仍最多 2 笔。
- **配置**：`EXCHANGE_DEMAND_ENABLED`（入口默认 true、库层默认 false）、`EXCHANGE_DEMAND_WINDOW`（12）、`EXCHANGE_DEMAND_TARGET_BP`（3000，实验区间 2000～4000）、`EXCHANGE_DEMAND_MAX_SCALE_BP`（40000）。

## 五、验收读数（本地合成场景，不读真档）

命令：`go test ./internal/exchange -run "TestDemand" -count=1 -v`。读数单位为基点，`每股平滑需求` 为信用点。

| 场景 | 成交可达性 | AI 承接（mm / 人格 / 玩家间） | 冷门股双边深度 | 每股平滑需求 | 预算系数 | 人格最低权益 |
|---|---|---|---|---|---|---|
| 20 人均衡 | 5728bp | 6216 / 1283 / 0 | 3990 股 | 1,612,797 | 10000bp | 9995bp |
| 100 人均衡 | 3407bp | 6046 / 1453 / 0 | 3990 股 | 7,066,963 | 10000bp | 9995bp |
| 300 人均衡 | 1921bp | 3750 / 1250 / 2500 | 3990 股 | 20,751,216 | 10000bp | 9985bp |
| 100 人巨鲸重仓 | 1616bp | 6046 / 1453 / 0 | 3990 股 | 16,220,647 | 10000bp | 9995bp |
| 100 人全员同向买入 | 10000bp | 5000 / 0 / 0 | 3870 股 | 1,071,329 | 10000bp | 9980bp |
| 100 人集中平仓 | 10000bp | 3343 / 406 / 0 | 3930 股 | 2,771,925 | 10000bp | 9995bp |
| 100 人高杠杆重仓 | 564bp | 1250 / 0 / 0 | 3870 股 | 230,215,806 | 15722bp | 9996bp |

结论：

1. 无杠杆 20/100/300 人场景下，每股有效需求（155 万～2075 万）远小于基础双边深度 2 亿，自适应按设计**不放大**，预算系数保持 10000bp、每档名义保持 2000 万。这符合「玩家越活跃市场越由玩家形成、避免某只股票突然被 AI 主导」。
2. 高杠杆重仓场景把有效需求推到 2.3 亿/股才进入触发区间：预算系数 15722bp、每档名义最高 8000 万（4× 上限）、冷门股仍有报价、六人格未破产。
3. 目标系数 2000/3000/4000 在高压场景下读数已出现分化（成交可达性 566 / 564 / 561bp，人格最低权益 9997 / 9996 / 9995bp）；纯函数用例另断言系数确实改变预算。**上线定值仍需船长结合真实体验裁定，当前 3000bp 只是实验默认值。**

## 八、待裁决与已知取舍

1. **目标系数上线定值**：默认 3000bp 是实验值，绿灯后需船长结合真实两三百玩家体验定案；也可先用环境变量灰度。
2. **系统做市账户不守恒、不落库**：本批只做只读对账（`/api/exchange/demand` 暴露现金与每标的库存），不改账。放大做市深度等于放大这个不落库对手盘的敞口；是否后续改成有限且可结算，需单独授权（会动表结构与重启语义）。
3. **生产下发**：本次部署未改 systemd，四个参数走服务入口默认值（`EXCHANGE_DEMAND_ENABLED=true`、窗口 12、目标系数 3000bp、上限 4×）；`/api/exchange/demand` 随 nginx 通配已对外公开（只读），是否收紧待船长决定。
4. **统计窗口不落库**：重启后前几回合回到基础流动性，属于冷启动取舍；若要求重启前后需求曲线连续，需要新增持久化（本批明确不做）。
5. **无观测时行为不变**：所有新分支都在有需求快照时启用，冷启动与既有确定性用例保持原行为；这是刻意设计，不是开关式兼容层。
6. **汇报口径**：`docs/design/stock-exchange-handoff-20261104.md:23` 另记有一套汇报抬头，与当前会话显式规则不同；本批按当前会话规则执行，未改动该文档。
