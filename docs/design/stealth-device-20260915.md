## 二、六问六答 → 落法（逐条）

| # | 裁决 | 落法（代码位置） |
|---|---|---|
| Q1 | **甲**：开战隐身 → **本舰首次开火立即现形**，最长 N 秒（先到者为准） | `createBattleState` 写 `stealthUntilMs = nowMs + stealthMs`；开火处（`b.stats.meShots += 1` 旁）清窗；`stepBattle` 每拍收尾处「到点」清窗 |
| Q2 | **甲**：敌方**选不到**我方 ⇒ 主炮与机群**停火待机** | 敌方**唯一选靶单点** `pickMyUnitTarget`（主炮与机群共用同一个 `pickTarget()` 闭包）加 `isMyUnitTargetable` 过滤；池空 ⇒ 返回 null ⇒ 该发停火 |
| Q3 | **甲**：**只护装了装置的那一艘** | 窗口写在**逐舰**运行时字段上（`b.units[tag].stealthUntilMs`），选靶按 tag 判 |
| Q4 | **两档 MK2/MK3 = 20 / 30 秒 · 极度吃 CPU** | `mod-stealth-2` / `mod-stealth-3`，`stealthMs` = 20000 / 30000，CPU = **75 / 120**（既有装备最高 70，契约强制"高于全表"） |
| Q5 | **丙**：先落码 + 交对照读数，再定要不要加代价；**追加禁令：有推进器类时直接解除隐身** | 读数见 §五（工具 `npm run battle:stealth-readings`）；禁令落在 `createPlayerSpec`：`propDefs` 非空 ⇒ `stealthMs = 0`（推进器不会中途装卸 ⇒ 装配期即判） |
| Q6 | **甲**：零新增界面（只加战斗日志一行）＋ **预估一并算入** | 战斗内提示条 `pushBattleNotice`（两句：进入隐身 / 现形；**不写 `addLog`**——2026-09-11 船长机制提示纪律）；`bountyDamageForecast` 把敌方有效输出时长扣掉隐身窗口 |

**开局/结束的两支清窗（Q1「先到者为准」）**：① **开火** = 本舰任一门武器打出第一发时立即清窗（同一拍稍后的敌方开火段因此已经"看得见"它）；② **到点** = 每拍收尾检查 `lastTickGameMs >= stealthUntilMs` 就清窗（一直没开火也不会永久隐身）。

## 五、对照读数（船长 Q5 丙 的决策依据）

**工具**：`npm run battle:stealth-readings`（正式入库；口径 = 真引擎实战，大白鲨级炮舰 + **全技能 L3** + 弹药管够 + **40 种子/格**；读数落 `tools/_ui-artifacts/stealth-readings.log`）。

**表 1 · 机制净效果**（同一套装配里把第 5 门炮换成装置，CPU 超船体、仅隔离机制）

| 卡 | 4×炮台（对照） | ＋隐秘 MK2 | ＋隐秘 MK3 |
|---|---|---|---|
| 灰霾伏击团清剿令 | 胜率 **40%** · 102.2 秒 · 甲残 16% · 壳残 33% · 敌开火 95.1 | **45%** · 111.5 秒 · 21% · 41% · 85.8 | **65%** · 115.2 秒 · 31% · 46% · 77.6 |
| 穹顶守卫 | 0% · 13.6 秒 | 0% · 27.1 秒 | 0% · 36.1 秒（活得久，打不动） |
| 噬口猎杀令 | 0% · 50.9 秒 | 0% · 50.9 秒 | 0% · 50.9 秒（该配装打不动） |
| 三张软卡（演习场 / 边境 / 碎晶） | 100% · 5~19 秒 · 无损 | 同 | 同（打得太快，没挨打 ⇒ 无差别） |

**表 2 · CPU 合法的真实取舍**（大白鲨 225：满火力 4 门 = 208；2 门 + MK2 = 179；2 门 + MK3 = 224）

| 卡 | 满火力 4×炮台 | 2×炮台 + MK2 | 2×炮台 + MK3 |
|---|---|---|---|
| 灰霾伏击团清剿令 | 40% · 102.2 秒 | **35%** · 119.4 秒 | **45%** · 146.3 秒 |
| 穹顶守卫 | 0% · 13.6 秒 | 0% · 27.1 秒 | 0% · 36.1 秒 |
| 三张软卡 | 100% · 无损 | 同 | 同 |

**读数的三条结论（供船长裁代价）**：
1. 装置**真的有用**，但只在"会被先手打一整套"的长战卡上：灰霾净效果 **40% → 65%**（MK3）、敌开火少 **17.5 发**、甲残 16% → 31%；
2. 代价已经很硬：MK3 吃 **120 CPU**，合法装配要拿 **2 门攻坚炮（−50% 火力）**换 ⇒ 表 2 里 MK3 只比满火力净 **+5 个点**（灰霾），**MK2 反而 −5 个点**（拿炮更划算）；
3. 因此**我的建议 = 暂不加额外代价**（"极度吃 CPU"本身已是惩罚，且收益只在特定卡型成立）；若船长要压强度，最省的旋钮是**窗口时长**或**CPU 再上调**（数据一处改）。

## 六、已知取舍与边界（如实登记）

1. **胜率口径**：隐身窗口内双方都不开火 ⇒ 解析口径的**胜率比值不变**（只是开打更晚），故 `bountyDamageForecast` 只把**敌方有效输出时长**扣掉窗口（损耗预估下降）；**玩家可见的胜率走 `winEstimate.ts` 的蒙特卡洛**（直接跑真引擎）⇒ 装置**自动计入**，无需另算。
2. **AI 接单门槛**（`aiWinPreview`，解析口径）**不含装置** ⇒ AI 对装了装置的副船**偏保守**（只会少接单，不会冒进）。
3. **推进器禁令**是"装配期即判"：推进器不会中途装卸 ⇒ 等价于"带推进器就没有隐身"；**微型跃迁引擎（`mod-mwd-*`）同属 `propulsion` 家族 ⇒ 同样触发禁令**。
4. **Q4 只做两档**（无 MK1）：与"极度吃 CPU"定位一致（入门档位与它不搭）。
5. **未发公告**（战斗机制新增，按 §7 属"大更"⇒ 若要上公告，我另出待审稿递船长审核，不直接写入 `announcements.ts`）。
