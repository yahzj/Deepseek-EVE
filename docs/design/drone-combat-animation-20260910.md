# 无人机战斗动画 + 损毁系统（2026-09-10 船长逐轮拍板，状态：已确认）

> 三号 经办。本文记录全部已确认口径（含后续损毁系统），实现分两批交付：
> **第一批 = 动画演出**（本轮）；**第二批 = 损毁系统骨架**（紧随其后）。

## 一、背景

玩家反馈："战斗动画与普通武器同质化"。根因（读码确认）：
- `WeaponSpec.kind` 只有 `gun/beam/fixed`，**无人机与「基础舰炮」同为 `fixed`**，引擎层分不出；
- `BattleFx` 只带弹型（kinetic/explosive/plasma）+ 命中，**不带武器来源** → 表现层只能按弹型画弹道；
- 战斗画面只画主舰与敌舰，**画面上看不到任何无人机**。

## 二、已确认口径（逐条）

### 机型与演出
1. 四型：`drone-scout` 蜂鸟 / `drone-assault` 赤鸢 / `drone-heavy` 猎鹰 → **放飞-回巢**；
   `drone-sentry` 雷鸥哨戒 → **常驻伴飞（母舰下方）**，多架只显 1 架动画。
2. 放飞触发 = 该型首次开火；**该型 ≥1.2s 无开火 → 回巢**（收舱时仅机库口微光）。
3. 演出制式（2026-09-10 船长二次定，两套都保留、常量切换）：
   - **出击制 `sortie`（默认）**：无人机自母舰放出 → **飞到敌舰侧的攻击阵位开火** → 无开火 1.2s 后原路返航；
   - 机群制 `formation`（保留）：无人机在母舰上侧编队巡飞，弹道自编队位起飞。
   切换点 = `ui/droneArt.tsx` 的 `DRONE_STYLE`（两套 CSS keyframes 均在）。
4. 每型显示上限 **6 架** + `×N` 徽标；混装各型各自编队；战败（母舰被毁）**不回收**，随机体消失。
5. 哨戒常驻位置（2026-09-10 船长二次定）：**母舰上方**伴飞（原下方方案已按船长意见上移）。
6. 两制式**完全隔离**（船长："旧方案要单独隔开，避免干扰"）：渲染层按 `DRONE_STYLE` 挂
   `is-sortie` / `is-formation` 互斥类，CSS 不再用 `:not()` 交叉匹配——出击制的位移/停泊与
   机群制的编队动画互不影响；旧方案（机群制）整段保留在"旧方案·机群制（保留区）"注释块内。
7. 出击制返航 = **先掉头再飞回**（`scaleX(-1)` 翻转机头朝母舰），不是倒退漂回。

### 弹道与表现层
4. 颜色**按弹型**（动能金 / 高爆橙 / 能量青，与炮台同一读图语言）；**机型决定弹点形制与密度**
   （蜂鸟最密最小 / 赤鸢中等 / 猎鹰大而沉 / 哨戒远程小束点；猎鹰与雷鸥同为能量型，靠形制区分）。
5. 弹道起点 = **该型机体当前位置**（不参与母舰炮口轮换；炮口轮换只留给炮台/激光/导弹）。
6. 同型同帧多架开火 → **合并为一波**（每波 ≤3 条蜂群点，密度体现数量）。
7. 命中特效**小型化**（与炮台大 puff 区分）。
8. 顺带修：射程弧列表把无人机逐架条目**合并为「机型 ×N」一条**（冷却条同步），不再 16 条刷屏。
9. 视觉纪律：机体与弹点全部 **SVG 线稿**（禁止 CSS 拼形状；动作走 CSS 动画 + 类切换）。

### 多单位接口（为副本机制预留）
10. 机群渲染器按**单位**设计（unitTag + 锚点 + 显示宽 + 机型表）；当前只喂主舰 `player`。
    未来副本机制的多船舰队战斗**只需把友军单位加进列表**，引擎无需再改（`fx.tag` 已标识单位）。
11. **敌方机群预留**：`foeSpec.drones` 结构 + 机群层按单位渲染；敌族数据/敌近防炮留待后续排期。
12. 状态窗（左侧导航）、装配页本轮**不做**机群预览（同一渲染器后续可复用）。

### 损毁系统（第二批交付）
13. 无人机 = **舰载子单位**（挂 `单位.drones[]`，三层血量 / 存活 / 装填相位），**不进主目标池** →
    现有全部武器与锁定装置（集火）**按构造**看不到无人机（"现有武器不攻击、不锁定"零改动成立）。
14. **近防炮预留**：`WeaponSpec.canHitDrones` 标记 + 短射程；开火时带标记武器**优先筛机群**，
    无无人机则打舰（先机后舰）。本轮只落字段与筛选分支，用测试用假近防炮驱动；真装备数据待上线。
15. 血量口径 = **物品现有 `defense` 三层**（蜂鸟 6/3/10、赤鸢 10/6/18、猎鹰 20/12/34、雷鸥 30/20/55）
    + 回避率，兑现 V11 契约。
16. 损毁演出：该架停火（机群减 1）+ 小型爆炸/坠落 SVG；新增 fx 事件 `droneDown`；战报统计
    「无人机损失 N 架」。
17. 战后结算：**损毁数从舰上机巢（droneLoad）扣除**——永久损失，需回港重新装载；日志提示。
18. 平衡影响：当前**零**（无武器可打无人机）；待近防炮与敌方机群上线后再出校准矩阵。

## 三·补 2026-09-10 船长目测反馈后的修正（第一批内）- **无人机弹道不显示（已修）**：根因 = 普通弹条靠 `scaleX(.05→1)` 曳光，弹条被压到 7px 后等于不可见；
  现改为**沿弹道飞行的曳光点**（`.app-bts-bolt-dot` + `app-bts-drone-fly`，`--fly` = 行程 px），
  与机型形制无关地保证可见性；引擎侧同时加了"实战开火事件确实带 src/artId"的回归（4 条）。
- **放飞动画改为出击制（新方案，旧方案保留并隔离）**：见上 §二.3 —— 放出 → 飞至敌侧攻击阵位开火 → 掉头返航。
- **出击制"位置偏移（仍在母舰上方）"（已修）**：根因 = 机体 `left/top` 用的是机群制编队位（舰上方）作基准，
  而位移量按"阵位 − 舰锚点"计算 → 终点 = 阵位 + 起飞点偏移，整体被顶到舰上方；现改为
  **基准位 = 机库口（`droneTakeoff`）、位移 = 阵位 − 基准位**，终点精确落在攻击阵位。
- **哨戒位置**：由母舰下方改为**上方**（船长二次定）。
- **曲线出击/返航 + 阵位错开 + 弹道跟随（2026-09-10 船长三次定）**：
  ① 航路改曲线——去程**上凸弧**（中点抬升 `droneArcHeight(lane)`）、返程**下凸弧**（中点下压），
     每道弧高不同（34 + lane×11），航路之间自然错开；CSS keyframes 用 `--mx/--my`、`--nx/--ny` 中点变量；
  ② 攻击阵位改**新月形分层**——`y = (lane−2.5)×20`、`x` 再按 |k| 与奇偶分三档（中间道贴近敌舰、外侧道后退），
     6 架不再挤成一团；
  ③ **开火位置（2026-09-10 船长四次定："开火位置依旧不对，疑似刚飞出就开火"）修正**：
     根因 = 放出时刻原由**开火事件**置位 → 新一轮首发的航路进度恒为 t=0，弹道必然出现在机库口（母舰侧）。
     现改为两条并用：**(a) 进入该型射程即放出**（不等开火，无人机先飞抵阵位待命）；
     **(b) 飞行途中到达的开火 → 弹道延迟到无人机抵达阵位再显示**（`delay = (1−t)×去程时长`，
     `BoltV.delay`/`FlashV.delay`，寿命同步延长），既不丢发、位置也正确。
  ④ **"依旧是飞到固定地点（指 Y 轴）+ 停留位置与弹道位置对不上"（2026-09-10 船长六次定）修正**：
     根因 = 无人机装填周期约 2.2s，而"无开火 1.2s 回巢" → 每轮开火之间无人机**早已飞回机库口**
     （所有机型都停在母舰同一个高度），而弹道按时出现在敌侧阵位 → 两者看起来对不上。
     先改为与开火周期对齐的节拍；**最终按船长七次定重做为单轮时序**（见下 ⑥）。
  ⑤ 位置由渲染层**逐帧插值**（`dronePathPos`）直接写 `left/top`，不依赖 CSS 关键帧的 `forwards` 终止值
     （敌舰移动后阵位实时跟随，不会停在旧坐标）；CSS 只保留漂浮微动（margin-top）。
  ⑥ **单轮出击时序定稿（2026-09-10 船长七次定，最终口径）**：
     - 修复"战斗开场无人机即出现在敌侧"（首发事件曾把"停在阵位"状态直接套上）→ 每轮都从机库口飞出；

**经验教训（供后续表现层改动参考，均在本轮踩过）**

1. **渲染体的提前 `return null` 之后禁止出现 hook**——战斗结束 `view.combat` 变 null 时提前 return，
   落在其后的 `useEffect` 被跳过 → hooks 数量不一致 → React 卸载整棵树（**黑屏无反应**）。
2. **动画位置不要依赖 React 重渲染节奏**——位置写在渲染体内时，33ms 循环"仅在距离变化≥0.05m 才 setState"，
   敌舰一就位就只剩 10Hz 通知刷新 → 表现为 10fps 步进。改为 **rAF 直接写 transform**（并做"值未变不写"守卫）。
3. **组件局部的"生死/演出登记"必须与引擎真值对齐**——`deadRef` 是局部状态，退出战场即清空，
   重进后 hp=0 的敌人被当成存活重新渲染（**重进战场复活**）。现按 `battle.units` 入场预登记。
4. **位移动画不要交给 CSS 关键帧的 `forwards`**——终止值冻结在动画结束那一刻，目标（敌舰）移动后机体停在旧坐标。
5. **大 SVG 子树上的 `filter` 与大幅 `box-shadow` 缩放会造成绘制尖峰**——尸骸灰化改用"传灰色 + 降透明度"，
   爆炸环走独立合成层。快照证据：`long 63ms` → 改后 `long 0`。
6. **锚点几何依赖的测量值（列宽）必须随编队数量重测**——否则击毁僚舰后锚点偏移、弹道落点偏右。
7. **引擎事件的展示字段（`WeaponSrc`/`artId`）是表现层差异化的地基**，先做地基再谈演出，改动面最小。
