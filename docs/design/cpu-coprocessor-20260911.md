## 一、结论（玩家侧一句话）

**协处理器 = 低槽装配件，为这艘船追加 CPU 预算**：MK1 +10 / MK2 +15 / MK3 +20，**本件自身不占 CPU**；
装配校验、无人机放飞共用这同一份预算。卸下即收回扩容——**卸到超载会被拒绝**（见第四节）。

## 二、数值与渠道（船长裁定）

| 型号 | 效果 | 自身占用 | 稀有度档 | 市场渠道 | 蓝图 |
|---|---|---|---|---|---|
| 协处理器 MK1 | 装配 CPU 上限 **+10** | **0** | 2 | 稀有订单 | `bp-cpu-1`（书价 = 产物 ×2 = 776,000） |
| 协处理器 MK2 | 装配 CPU 上限 **+15** | **0** | 3 | 稀有订单 | `bp-cpu-2`（书价 = 产物 ×2.5 = 4,850,000） |

- **族**：新开 `slot = 'cpu'`（显示名「协处理器」，**低槽**）——与装甲/货舱/支援件抢同一批低槽位。
- **叠加**：多件全额叠加（与容量类同口径），天然上限 = 该船低槽位数（1~3）。
- **价格**（沿用本档既有价带，2026-09-10「MK2/MK3 装备价对齐同级武器价」的带）：
  MK1 **388,000**（第 2 档 38.5~48.1 万带）、MK2 **1,940,000**（第 3 档 192~240 万带）、MK3 **2,600,000**（奇货带）。
- **配方锚**：材料 ≈ 产物价 × 0.45（与全仓一致）——`bp-cpu-1` 料 174,000（三钛 13,000 + 类银 4,000 + 类晶 1,100）、
  `bp-cpu-2` 料 872,500；制造耗时 900s / 1,900s。
- **规模感**（全船 CPU 60~390）：沙猫 60 → 70/75/80（+17%~+33%）；灰鲭鲨 195 → 205/210/215；
  牛鲨 390 → 400/405/410（+2.6%~+5%）。**前期显著、后期边际**——占一个低槽是它的真实代价。

## 三、契约放宽（船长裁决「甲」）

原 `tools/content-check.ts` 的 V10.5b 契约要求**每件装备 `cpuUse ≥ 1`**，与「自身不占用」冲突。裁决「甲」后改为：

- `cpuUse` **必填、整数、≥ 0**；
- **`cpuUse = 0` 只允许带 `cpuBonus` 的件**（"零占用"只在"本件就是加预算"时成立，别的件漏写占用照旧报错）；
- 蓝图说明里的「CPU N」声明，在 `cpuUse = 0` 时改按 `cpuBonus` 核对；
- 「模块跨族字段契约」登记 `cpuBonus → cpu`（本职槽位 = cpu 族）。

## 四、防套利：**双向校验**（船长点名的那件事）

**漏洞形状（修前）**：`fitModule` 只在装的时候校验，而 `unfitAt` **完全不碰 CPU** ⇒
装协处理器（占 0、给 +Y）→ 用多出的预算把其它件装满 → **卸下协处理器** ⇒ 预算掉回原值、占用也还回来，
但**其它件留在船上** ⇒ 净偷 Y（低槽还空出来，可重复刷）。同一手法还能顶无人机清单
（`adjustDroneLoad` 只在装入时校验）；载入修复链 `repairDeprecatedModules` 退件同样不重算。

**修法（单点口径）**：
- `equipment.cpuBudgetOf(state, ctx, shipId, fittedOverride?)` = 船体预算（含「舰船系统工程」+5%/级）
  **+ 已装协处理器 `cpuBonus` 之和**；`fittedOverride` 供**预演**用；
- `equipment.cpuOverloadText(state, ctx, shipId, { remove?, addModuleId? })` = **超载预演**（装配/卸载/换装/无人机四处共用）：
  按"假想的最终装配"算 占用 vs 预算，超了给出玩家可读文案；
- **装**：`fitModule` 走预演（`addModuleId`），拒绝文案点名「或装一件『协处理器』扩容」；
- **卸**：`unfitAt` 先预演（`remove`），超载则**拒绝卸下**（EVE 同款）；界面侧 `engine.unfitAtAt`
  取值改回 `CommandResult`，装配页把原因直接弹给玩家；
- **换装**：新增 `swapModuleAt`（core）——一次成型、按**最终状态**预演，避免"先卸后装"把
  「换协处理器」这类最终态合法、中间态非法的换装卡死（装配页 `pickModule` 已改走它）；
- **无人机**：`adjustDroneLoad` 与战斗侧 `createPlayerSpec` 的余量口径都改吃 `cpuBudgetOf`；
- **旧档/迁移**：不自动卸件（只在需要时按最终态拒绝新增），旧档若因迁移停在小幅超载，行为是"能打、但不能加装"。

## 五、实测

**引擎（core 用例 6 例，`tests/cpu-coprocessor.test.ts`）**：自身不占 / 预算 +10·+15·+20 /
100 CPU 的船装不下 40+40+60、扩容 MK3 后 20 的件装得下 / **吃满扩容后卸协处理器被拒** /
无人机共用预算且超载时拒卸 / 换装按最终态预演（降档会超载则拒、合法升降档都放行）。

**界面（无头 Chrome + 网页版 · 掘洞级 CPU 90 · 高2 中2 低1）**：
低槽协处理器 MK3（+20）+ 高槽 2×精密采集器 MK3（80）+ 中槽姿态陀螺 MK2（15）⇒

| 步骤 | CPU 条读数 | 说明 |
|---|---|---|
| ① 开局 | **CPU 剩余 15 / 110** | 预算 = 90 + 20 扩容，占用 95 |
| ② 点低槽「卸下」 | **仍是 15 / 110**，低槽仍 1/1 已占 | 提示：**「CPU 超载：合计需 95，预算 90（协处理器只扩容、卸下即收回——先卸下其它装备或无人机）。」** |
| ③ 先卸一件高槽（占用 → 55） | CPU 剩余 **55 / 110** | 卸载普通件不受影响 |
| ④ 再卸协处理器 | CPU 剩余 **35 / 90** | 预算回落到船体 90，低槽空出 |

另：换装卡对比段已按**装后预算**给数（`CPU 剩 58→100 / 105 / 110`，分别对应装 MK1/MK2/MK3）；
高/中/低槽组标题、组装机与市场的装备子分类、手册装备图鉴分组均已含「协处理器」。
