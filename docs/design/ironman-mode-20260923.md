## 三、边界与已知取舍（如实登记）

1. **不做自动备份**（船长令）⇒ 救援**依赖玩家自己手动备份**；从不备份的玩家没有救援档。
2. **换机导入**（新机器账本为空）会被接受一次（提示"本设备首次载入铁人档"）⇒ 单机方案天花板，公告只讲"铁人档不可回退"。
3. **账本可被删/改**仍可绕过（双写只提高门槛）⇒ 符合船长"提高成本、不彻底堵死"。
4. 关闭铁人是**单向门**；关闭后的回滚无法追溯。
5. 福利造成两种模式的数值分叉；**工具与读数默认普通档基线**（不传墙钟 ⇒ 1× 那套免疫照旧）。

### 4 「桌面实测」怎么落的（未启动 Electron 的理由）

船长要的链路是「转换 → 关闭 → 导入旧档被拒 → 救援 ≥48h 放行」。**没有启动 Electron 实测**，理由：d2 与主树共用同一个 `app.getPath('userData')`（同一个 `%APPDATA%\whale-idle`）⇒ 起一次 d2 的窗口就会**读写船长正在玩的真档与真账本**，违反 §4「真档只读/走备份，绝不覆写船长正在玩的档」。替代做法：
- **把生产实现抽出来跑**：账本读写（双写取 max、删主/写坏退化、档内保存时刻）＋ 闸门四判据 ＋ 救援记账，全部由 `npm run ironman:check` 在**系统临时目录**里真写文件跑一遍（15 项，本次全绿）；闸门判据本身另有 core 用例 18 条。
- **留给船长的手工验收路径**（两条，各 1~2 分钟）：
  1. **新档**：顶栏「重置」→ 确认 → 新档模式弹层选「铁人模式开始」→ 存档页应显示「铁人 · 代次 #N」；成就页应同时出现「铁人」徽章。
  2. **旧档转换 + 闸门 + 救援**：存档页「备份当前档」（手动备一份）→ 「开启铁人模式」（两段确认）→ 玩一会（自动存档 ⇒ 代次 +1）→ 用刚备份的那份「恢复」⇒ **应被拒绝**并提示"铁人档不能回退，可取两天前的备份" → 找一份 **≥48h** 的备份（列表行尾会写「可救援」）恢复 ⇒ 放行 → 「关闭铁人模式」（两段确认）⇒ 状态变「铁人 · 已关闭（代次 #N）」，开启按钮不再出现，成就页多出「铁人 · 已关闭」。
