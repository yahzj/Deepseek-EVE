# 战斗结束立刻补足机群（优先货仓、其次仓库）· 2026-09-20

> 状态：进行中
> 船长原话（照抄）：「**战斗结束立刻自动补充，优先货仓，其次是仓库。**」
> 追问后的补充裁定：「**按本场出发快照补**」。
> 起因 = 玩家报障：「装配无人机清缴，无人机被击坠后，会停止重复清缴，手动点击出击，会显示无人机装配 0/0，无法出击。」

## 一、为什么以前不补（查证结论）

不是漏判，是 **2026-09-08「无人机舱大改」留的钩子一直没激活**：

| 出处 | 原文 |
|---|---|
| `docs/design/drone-bay-rework.md` §二.5 | 「**回港自动补充（结构预留，本轮不激活）**：引擎留「停靠时按清单补足」钩子与注释——**本轮不实装无人机被击毁**（价格/自制蓝图未配套，船长 2026-09-08 定）；激活点注：未来开击毁时 `droneLoad` 宜作"配置目标"，实载另记（见 §七）。」 |
| 同文 §五末行 | 「回港补足钩子：停靠处理点调用 stub（**本轮 noop**，注释激活条件）。」 |
| 同文 §七 | 「无人机被击毁：战斗内实载扣减 → **停靠按"配置目标"自动从仓库补足**……`droneLoad` 届时语义改"配置目标"，实载另记。」 |

2026-09-10 船长拍板「无人机可被击落（永久损失/耗材流）」时，只落地了"打掉就永久扣清单"那一半；
§七 的"停靠补足"与"实载另记"两半都没做（core 里连那个 noop stub 都不存在）⇒ 现状是"打掉就永久少、只能手动一架架点 +"。

## 二、本批口径（船长 2026-09-20 定）

| 项 | 定稿 |
|---|---|
| 时机 | **战斗结算那一刻立刻补**（不等回港、不等停靠） |
| 货源 | **① 本船货仓 `fleet.cargo` → ② 物品仓库 `warehouse.items`**；**不自动花钱买** |
| 补到多少 | **本场出发时的清单快照**（`battle.droneLoadAtStartBy[tag]`，主控回落 `droneLoadAtStart`）——**不新增落档字段** |
| 上限 | 舱容（船体 + 甲板扩展）与 CPU 预算双重校验，与 `adjustDroneLoad` 同一把尺 ⇒ 绝不超载 |
| 生效面 | 七处结算点同源（主控远征胜/败、主动撤退、遭遇战 ×2、虫洞战斗逐舰 ×2、AI 副船） |
| 顺序 | **先记战损账、后补货**：安全阀「战损过半停环」照旧响一次（记账=补货前存活架数），补满后重复清剿的再开门槛当场满足；货源不足没补满 ⇒ 门槛照旧拦住并说明缺几架 |
| 日志 | 一行 `机群补充：蜂鸟 ×5（货仓 3 · 仓库 2）`；货源不足另起一行 warn 说明缺几架 |

**连带**（一并做）：再开门槛文案写清"补到几架才行"（全灭时不再写「现 0 架 / 停环时 0 架」那种自相矛盾的话）·
重复清剿被拦时在卡面直接写原因 · 装配页无人机舱显示「再开重复清剿还差 N 架」。

**不动**：2026-09-08「只放飞已装入」不变（清单仍是玩家显式装配的结果，本批只把"被打掉的部分"补回来）；
2026-09-18「装甲或结构 <50% ⇒ 拒」不变；机群门槛保留，语义由"你有没有手动补过货"变成"**货源够不够**"。

## 三、已知取舍

- **棘轮效应**（船长知情并选定）：货源不足只补到 3 架时，下一场的"目标"就是 3 架（因为目标 = 本场出发快照）。要做"永远补回编制"需落档「配置目标」字段，本批不做。
- **野外补给线**（船长知情）：战斗在野外结束时就从物品仓库取货 ⇒ 相当于自带补给线；若要收紧，改成"只从货仓取"即可（一处开关）。
- 弃船：船没了 ⇒ 补足自然为空操作（随船损失，不额外补）。

## 四、实现落点（2026-09-20 落地）

| 落点 | 内容 |

| `core/state.ts` | `DroneLossReport.survivors?`（不落档，零迁移） |
| `renderer FitPage` | 无人机舱区新增一行读数：`「重复清剿」再开还差 N 架（停环时 X 架 · 现 Y 架）`——只在真缺时出现（判据走 core 单点，界面不自算）；舱区说明补上"战斗结束自动补足（货仓 → 仓库）" |
| `renderer itemView / Handbook` | 无人机说明与手册「机群战损」条目同步新口径（**从"回港后请补充"改为"战斗结束自动补足（货仓 → 仓库），都没货才需自购"**） |

**顺序红线（写进注释 + 测试钉住）**：`settleDroneLosses` 内 **先记 `survivors`、再补货**；
`droneBattleOutcome` 读的是 `survivors`（补货前）⇒ 否则"战损过半"永远判不出来（安全阀静默失效）。

**未做（记录在案）**：重复清剿按钮的"卡面内联原因"——自动补足后该门槛只在"货源为空"时触发，
此时已有三处提示（补货 warn 日志 · 停环一次性提示 · 悬停说明）+ 装配页缺额读数，故不在卡面再堆一行；船长若要，一句话即可加。
