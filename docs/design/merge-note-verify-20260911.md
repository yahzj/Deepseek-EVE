## 三、既定结论（**技术性裁决 · 不需要船长点头：这是"哪一版没有 bug"，不是设计偏好**）

### 「窝点退役」必须保 **d2 的修法**（`retiredLairCards.ts` + `context.ts` 白名单）

**事实**：两边都按船长裁决 8「没有窝点，排除出赏金范围」**删掉了两张 B 卡的 `lairCore`** ✓（口径一致）；
但**旧档兼容的处理不同**：

| | d2（f12caf7） | verify（b1b6ead） |
|---|---|---|
| 数据层 | 两卡 `lairCore` 已删 ✓ | 两卡 `lairCore` 已删 ✓ |
| 稀有残骸注册条件 | `hasLairCore(a) \|\| RETIRED_LAIR_CARD_IDS.has(a.id)`（`data/context.ts`） | **仍是裸 `if (!hasLairCore(a)) continue`** |
| 白名单常量 | **有**：`packages/data/src/retiredLairCards.ts` | **无**（该文件相对 d2 标 `D`） |
| 契约守卫 | **有**：`content-check`「退役窝点卡契约」4 条 | 无 |

**后果（已实测，不是推断）**：verify 那一版**存在旧档兼容洞**——旧档里已经获得
`wreck-rare-ano-harbor-escort` / `wreck-rare-ano-abandoned-platform` 的玩家，读档后这两件会解析不到物品定义。
**负向对照实证（本批实跑）**：把物品定义从 `ctx.items` 摘掉（= 不注册的实现方式）后，回收炉首行守卫直接报
> `未知物品：wreck-rare-ano-harbor-escort。`

而 d2 版在同一链路上：识别（定义可解析）→ 存档（`loadSaveFile` 后两件都在、名字正常）→ 结算（`startRecycleRun` ok、
`advanceGame` 派时间后残骸耗尽并产出、高级箱 30/30 命中）**全通**（详见 `docs/design/foe-faction-b-scavenger-20260911.md` §六 与 roadmap 同日条目）。

⇒ **结论：保 d2 版**（这不是口径选择，而是"哪一版没有已知缺陷"）——**已作为裁决依据写明**。

### 冲突 ②：期望交距修法（**技术对比，含实测**）

| 维度 | **d2 机制（现行，已落码）** | **verify 机制（B 专用）** |
|---|---|---|
| **字段** | `UnitSpec.foeRangeBand?: {min,max}`（**只由舰级路径写**） | `FoeShipDef.desireRangeM?` / `FoeShipSlot.desireRangeM?` ⇒ `UnitSpec.foeDesireRangeM?` |
| **判定逻辑** | `带 = foes[0]?.foeRangeBand ?? TACTIC_RANGE[战术]`，期望 = `带.min + factor[战术] × (带.max−带.min)` | **先**看 `foes[0].foeDesireRangeM > 0` ⇒ 直接返回该值；否则回退**旧全局表** |
| **代码位置** | `packages/core/src/combat.ts`（`UnitSpec` 字段 + `createFoeSpecsFromShips` 写值 + `foeDesiredRange` 分支） | 同文件（`UnitSpec` 字段 + `createFoeSpecsFromShips` 写值 + `foeDesiredRange` 分支） |
| **影响面** | **全部 9 张舰级路径卡**（A 族 6 + B 族 3）；旧路径 20 张**逐字不变** | **只有写了该字段的单位**（现为 B 两舰级：skiff 1300 / armed 1800）；**A 族与旧路径零变化** |
| **守卫** | core 用例 4 条（含"全 9 卡期望必落在自身带内"）+ `content:check` | `content:check`「期望射程契约」：取值必须落在该舰级自身射程带内 |
| **验收** | 已过四条判据（弱技能无触顶 ✅ / 教学卡回 100% ✅ / A0 不劣化 ⚠ 蜃影 −8pp / 旧路径逐字不变 ✅） | 三号侧按其自测口径（`typecheck×4` + core 852/852） |

**B 族三卡：两套机制的期望交距取值**

| 卡 | 自身射程带 | **d2 机制**（带内 0.55） | **verify 机制**（写死） | 差 |
|---|---|---|---|---|
| 演习场驱逐令 | 1~2200 | **1210 m** | **1300 m** | +90 |
| 新港商路护航令 | 1~2200 | **1210 m** | **1300 m** | +90 |
| 占港武装通缉 | 366~4815 | **2813 m** | **1800 m** | **−1013** |

**对照实测（在 d2 引擎上把"敌人期望交距"精确调到 verify 的取值，其余一切不变；
旋钮 = `bal.tacticDesireFactor`，全引擎只被 `foeDesiredRange` 使用，故是干净的单变量对照）**
——5 播种（1/7/13/29/51），格式 = 胜率｜时长｜残血｜最近交距｜我开火｜敌开火(头目/杂鱼)：

| 卡 · 行 | d2 机制（1210 / 2813） | verify 机制（1300 / 1800） | 差 |
|---|---|---|---|
| 演习场 · A0 标准中距 | 100%｜7s｜100%｜3564m｜我3.6｜敌0.0/0.0 | 100%｜7s｜100%｜3564m｜我3.6｜敌0.0/0.0 | **无** |
| 演习场 · A3 弱技能行 | 100%｜9s｜100%｜3581m｜我4.4｜敌0.0/0.0 | 100%｜9s｜100%｜3581m｜我4.4｜敌0.0/0.0 | **无** |
| 演习场 · **裸船零技能** | **100%｜30s｜99%**｜1233m｜敌6.6 | **100%｜30s｜99%**｜1267m｜敌6.6 | **无（都不死锁）** |
| 新港 · A0 / A3 | 100%｜7s / 9s｜100% | 100%｜7s / 9s｜100% | **无** |
| 新港 · **裸船零技能** | **100%｜84s｜100%** | **100%｜87s｜100%** | +3 s（可忽略） |
| 占港 · A0 / A3 | 100%｜10s｜100%｜敌1.6 | 100%｜10s｜100%｜敌1.6 | **无** |
| 占港 · **裸船零技能** | **100%｜327s｜残 44%** | **100%｜322s｜残 63%** | **残血 +19pp**（verify 更容易） |

**⇒ 实测要点**：
1. **两套机制在 B 族三卡上"目标达成度相同"**：都**彻底消灭了 600 s 死锁**（裸船行 100%，最近距离 1233~1267 m），
   **A0/A3 两行读数逐格完全一致**；可观测差异只有两处：新港裸船 +3 s、**占港裸船残血 44% → 63%**。
2. **差异的量级很小**：换机制的净效果 = 一张卡的一个辅助行差 19 pp 残血，**主力行（A0/A3）零差异**。

**两套能否并存？（事实）**
- **数值上不会双重生效**：两者都是"**取一个标量**"的规则，不是乘子 ⇒ 不存在复利/叠加；
- **但会产生三条优先级规则管同一个标量**（`desireRangeM` 覆写 → 舰级路径自身带 → 旧路径全局表）⇒
  **维护歧义**：例如某张 B 卡将来像 A 族那样写 `rangeMinM/MaxM`（"同卡同带"），d2 机制会**自动跟随**新带，
  而写死的 `desireRangeM` 会**静默忽略**它 ⇒ 两个旋钮互相矛盾；
- 且 verify 那套需要把**字段 + 建档写值 + 契约**一并搬进 d2（属**代码搬运**，不是文档合并）。

**若必须选一个（⚠ 以下是二号的建议，不是结论）**：
**建议保留 d2 的全局机制**（`foeRangeBand`），理由三条：
① 它**已经**在 B 族三卡上达成 verify 机制的目标（实测：死锁都消失、主力行读数一致），**换过去收益≈0**；
② 它把"期望交距"**从结构上**锁死在自身射程带内（值由带算出 ⇒ "写在带外"这类错误**不可能发生**），
   而写死值需要靠契约事后拦（verify 自己也因此加了「期望射程契约」）；
③ 它是**一条**机制覆盖 9 张舰级路径卡，与 A 族已验收的读数同源；引入第二条机制会让 A/B 两族**口径分叉**。
**若船长确要 B 族取特定值**（例如教学卡 1300 而非 1210），建议**用既有的带覆写字段表达**
（`rangeMinM`/`rangeMaxM`，A 族四张 kite 卡已在用"同卡同带"）——**不需要新增字段**。
