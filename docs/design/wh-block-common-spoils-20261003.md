# 洞内「禁止打捞普通残骸」开关：扩到「战斗战果」

- **状态**：进行中（**逻辑已落码** · **开关说明文案待船长审字** · 等验收）
- **船长原话（照抄 · 报障）**：

  > 「**虫洞的禁止打捞普通残骸，同时也会移除在虫洞内击败敌人获得的普通残骸**」

- **船长裁定（照抄）**：

  > 「**我希望那个开关同时能关闭战斗后获取的普通残骸**」

  **参照的同类子模块**：开关自己在 `wormholeSalvage.wormholeSalvageAt` 里的既有写法（"只挑稀有堆"）
  ⇒ 本批把同一条口径搬到战果的**产生端**（不发、不落格），不新造第二套。**是否跨域**：**否**。

## 一、改前的真因（探针复现）

战果装不下时**散落在该格**（`cell.piles`），而它与"打捞铺出来的"普通堆**共用同一本账**；开关只按
"稀不稀有"筛 ⇒ 那几堆**再也拿不走**（离开这层即丢）—— 而游戏自己还先写了句
「🕳 战果里有 N 堆装不下：先散落在该地点，**可以照打捞规则回收**」⇒ 自食其言。

```
① 打赢层末守卫（背包装满）：入包 0 堆 · 散落该格 6 堆 ⇒ 本格 {rare:3, common:3}
② 腾空背包 ＋ 开关打开 ⇒ 打捞一次：收走 1 堆（稀有 1）· common 3 不动
③ 关掉开关 ⇒ 再打捞：收走 2 堆（普通 2）· common 3→1
```

## 二、改法（逐条）

1. **`packages/core/src/wormholeSalvage.ts`** 的 `wormholeGrantShipSpoils`：开关打开 ⇒
   **战果里的普通残骸根本不产生**（`commons = 0`：不发、不入包、不落格）；**稀有残骸件数与货柜掷骰
   一字不变**。⇒ 从源头对齐"洞里不要普通残骸"，也就不再有"落在格子上拿不走"的那批。
2. **`packages/core/src/wormhole.ts`** 的开关口径注释改写：原句「⚠ 不影响：…战果结算的随行战利品…」
   **按本令作废**，改成"两个来源都管"（打捞动作 ＋ 战果），并把起因（玩家报障 ＋ 探针读数）写进去。
3. **用例**（`tests/wormhole-rare-only.test.ts`）：新增两条 —— ① 开关打开 ⇒ 三个形状（node/boss/ruins）
   的战果**普通残骸一堆都不产生**、稀有件数照旧；② 对照：关着时战果照旧"普通 ＋ 稀有"全给
   （⚠ 计数按形状表的总堆数，因为同 id 的普通堆会被 `tryMergeIntoBag` 并成一格）。
4. **不动**：`save.ts` 一个字没动（本批走"产生端过滤"，不需要给堆加来源标记）· 打捞动作那条路
   （只挑稀有堆 / 只剩普通就拒且不扣回合）一字未改 · 采集（虚空母矿）· 自动探索 · 掉落与堆生成。
