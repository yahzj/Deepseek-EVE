# 快递任务不更新调查

> 状态：已确认，已实现，自测通过，待合入验收（三号 · verify · 2026-10-04）
> 实施批准：船长「修」，授权本稿建议的任务刷新与对应存档字段修复。
> 船长：「玩家经常会出现快递任务不更新的情况，检查下」。
> 基线：19f1a449。调查阶段仅取证；确认后的实施与结果见文末，没有读写个人档。

## 确定根因

- advanceSideTasks离线大推进只处理最后一个资源窗口；refreshBoard用courierDueAtWindow判断该窗口是否恰好是120分钟整数倍，没有判断两次推进之间是否跨过快递周期。
- refreshBoard先把共用board.window推进到新资源窗口，快递即使没有换新，也会由sideTaskBoard/courierDeadlineMs按新的window显示下一周期倒计时。
- 因此旧单可继续挂在板上，倒计时看似重新开始；acceptCourierTask没有独立到期闸，漏刷后的旧单仍能接单。不等于所有玩家的个案已定位。

## 真实入口复现

使用buildSimContext/createInitialState，合成一座已建成副站，advanceGame及simulateOffline真入口；临时6条取证测试与现有4条周期测试均通过。取证测试断言的是旧BUG仍存在，不是修复通过，用后删除，修复时改为正常行为回归。

| 场景 | 实得 |
|---|---|
| 在线20分钟逐窗推进到120分钟 | 正常换快递ID |
| 从100分钟一次推进到140分钟 | 资源ID换新；快递ID仍8~13，字段逐字未变；倒计时恢复约99分59秒；旧单仍可接取 |
| 首批在20分钟生成，真实离线130分钟 | 末资源窗140分钟；快递旧ID保留 |
| 连续4次两小时大推进 | 窗口20→140→260→380→500，同一批快递始终未换 |
| 已接单跨正常刷新 | accepted保留，未接单的新板正常换；这是既定行为，不计BUG |
| 人工构造board.window偏移1秒 | 连续24个资源周期也不落120分钟整数倍，快递始终未换；只证明兼容风险，未证明实际玩家档有这种偏移 |

## 其他核对

- UI的SideTasksArea每次渲染调用engine.sideTasksView读取当前数组，排序只复制数组，不缓存旧任务；正常挂机推进后notify。没有据此排除所有平台重绘问题。
- 未建成副站不生成快递是解锁规则；新副站建成后首批随资源窗补种，和这次旧批不换不同。
- refreshBoard还把虚拟快递生成放在资源候选池非空之后；候选池为空会提前返回，导致快递也不生成。当前真实目录合成世界有候选，只列为耦合风险，不断言本次玩家报障由它引起。
- 快递倒计时基于gameMs，序章冻结或非写入页面不推进时间是既有规则，不擅改成墙钟刷新。

## 已批准修复范围

1. 将快递刷新判断从命中某个整点改为跨过快递周期；离线仍只生成当前最后一批，不补刷所有中间批、不重复影响市场。
2. 快递独立记录批次时刻，列表、倒计时和未接单到期判定使用同一来源，不再跟随每20分钟的资源window续期。对应随档字段须写入点/读档规范化成对测试；旧档缺标记的未接单板初始化时换一批自愈，已接单/在途保持原单及原酬金。
3. 虚拟快递生成不依赖资源商品候选是否为空。
4. 保持快递120分钟、资源20分钟、条数、任务体积、运费、已接单保留及在途结算规则不变；补在线/离线跨界、连续多周期、初始化及存档往返回归。

## 实施与验证

- 模块：任务板刷新，连带存档规范化；跨任务→存档依据船长「修」及前述明确方案。同类参照为原资源末窗刷新、赏金/活跃独立时间标记；不改UI、词条、经济数值或其他模块。
- 新增sideTasks.courierWindow可选字段，在换快递板时写入、normalizeState严格读取；非法/未来值删除，缺失标记的旧未接单板首次推进重建一次，不丢accepted/deliver。
- 快递刷新用独立批次截止判断已经跨界；首次开板/空板补种沿用既有逻辑，已建副站才有任务。资源末窗算法原样保留（包括旧窗口偏移），快递另以绝对资源格点记录，避免偏移越界后每拍重复刷板。
- 倒计时、出发到期闸和接单过期闸同读快递批次，不再由资源window续期。未接单过期不允许通过接单变为永久有效；已接单不受板截止影响，在途到站仍用原酬金结算。
- 虚拟快递生成从资源候选池提前return之后拆开，无商品候选也能生成；资源市场影响仍只对末窗所刷资源单逐商品应用一次。
- 新增11条真实引擎回归：逐窗、100→140跨界、离线130分钟、连续多周期、30秒分片、窗口偏移、空候选/无副站、首次建站/空板、旧档首次自愈、接单/在途及奖励保护、非法字段/未来值和往返不重刷。SideTasksState键类型穷尽，新增字段不会在存档白名单中被遗漏。
- 专项63条（11新回归+原29任务+4周期+19存档）全绿；全量331文件3900用例全绿。四包typecheck、content:check、l10n:params、arch:guard、git diff --check及桌面/网页构建通过，正常提交钩子再跑对应技术检查。
