## 三、根因

`Industry.tsx` 的「目标」输入框**只在 `onBlur` / `onKeyDown(Enter)` 提交**（`goalDraft` 草稿是组件局部 state）。
**程序化跳页**（通讯「前往」、教程跳转、任务卡跳转、以及任何不经过焦点转移的切页）**不产生 blur**
⇒ 玩家刚打的数字**从未提交**；切回来输入框是空的，而**循环开关仍是"开"** ⇒ 目标为空 = **无限生产**。
鼠标点左侧导航会先触发 `mousedown → blur`，所以"有时候"丢、有时候不丢——正是玩家描述的那个"有时候"。
（同时排除：存档清洗/离线结算/存档往返都不会丢 `goal`——测试档里 10 张卡的 goal 全在；core 只在达成目标/缺料时置 `on=false` 并保留 goal。）

## 四、修法（`apps/desktop/src/renderer/src/panels/Industry.tsx`，玩家可见改动只有一句 tooltip）

1. **草稿进 ref**（`goalDraftRef`），并加「这一版草稿是玩家打出来的」标记（`goalTouchedRef`，`onChange` 置真、**任何一次正式提交即清账**）；
2. **卡片卸载兜底提交**：`useEffect(() => () => { if (touched) setManufacturingLoopAt(bp, true, 草稿) }, [engine, blueprintId])`
   ⇒ 切页/切子页签（卡片都会卸载）时，**打过字就一定生效**；
3. **"没打过字"与 StrictMode 的"挂载即卸载"都不会误提交**（touched=false ⇒ 直接返回），"静默清空目标"这条风险被堵死；
4. **清空照旧如实生效**：清空后跳页 ⇒ 目标真的清掉（= ∞），与输入框所见一致；
5. tooltip 由「回车/失焦生效」→「**回车、点空白处、或离开本页都会记住**」（`content:check` 文案纯净通过）。
