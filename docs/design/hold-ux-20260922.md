## ⚠ 落码前必须先定的一件事（避免写出第二套搬运逻辑）

**「货仓 → 临时空间」目前没有现成的 core 单点入口**（反向的 `wormholeTempStowPiece` 有）。
两条候选都**复用既有原语**，但语义/风险不同：

- **甲（推荐）**：`wormholeBoardTransfer + findFreeSpot` —— 与拖拽走**同一个搬运函数**，形状/实占格原样带过去，
  只是落点由我们现算；好处是"拖动与 Ctrl+点击"在 core 侧完全同源，失败口径也一致。
- **乙**：`wormholeTempAddShape(...)` —— 更"高层"，但**签名未核**（是否按 itemId 加、是否处理散货条都待查）；
  若它只服务形状件，散货条还得另找路 ⇒ 会分叉出两套。

⇒ 我按**甲**落（同源优先）；若你更想用乙，说一声我改。

## 四条落法

1. **残骸 / 稀有残骸配色照手册**：格子块与清单行的取色改用**同一单点**（`toneOf` / `TONES`），不新造色。
2. **格区独立滚动**：滚动窗口 = **格板外层的 `.app-wh-hold-scroll`**（`max-height` + `overflow-y: auto`），
   ⚠ **不能把封顶写在格板 `.app-wh-hold-grid` 上**（2026-09-23 船长追答「**还是压缩了高度**」后改定的）：
   格板里有一层 `position:absolute; inset:0` 的**物品块层**（`.app-wh-hold-figures`），它的包含块 =
   最近定位祖先的 padding box —— 封顶写在格板上时块层被截成可视高（520px），13 行物品块被压进 520px、
   与格子错位（实测最大错位 **350.3px**）。放外层 ⇒ 格板保持自然高度、块层跟着整块走，滚的只是外层窗口。
3. **Ctrl+点击整件搬**：两板的件 `onClick` 里判 `e.ctrlKey || e.metaKey` ⇒
   货仓件走 `engine.wormholeTempStow(id)`、临时空间件走 `engine.wormholeHoldStowItem(itemId)`；
   失败 `onToast(..., true)`（与拖动同一条文案 id）；成功后 `setDragId(null)` 清选中态。
4. **清单类型分隔线**：按同一分组键在"类型变化处"给行加一个类名（如 `is-group-start`），样式复用仓里既有分隔线家族。

## 验证口径

- 闸门：typecheck 四包 0 错 · `ui:rot-check`（样式改动必跑）· `content:check` · `build` · `l10n:check` 未译读数仍 0。
- 读数（无头）：① 格区出现独立滚动条且不再撑高面板（量格区 `scrollHeight > clientHeight` 与面板高度）；
