# P0 · 敌方期望交距改取「舰级自身射程带」（2026-09-11 · **已裁决 · 已落码**）

> ## 状态：**船长 2026-09-11 采纳（②）· 已落码 · 四闸全绿 · 未合入 main**
>
> 本稿第 1~6 节是**决策依据**（原稿，字句未改）；**第 7 节 = 落码记录与验收结论**（新增）。
>
> **一段话**：`foeDesiredRange()` 给敌人算"想站的交距"时用的是**旧路径的全局战术射程表**
> （`TACTIC_RANGE[战术] = brawl 0~2200 / orbit 350~4600 / kite 1200~9200`）**× 战术偏好系数**，
> **完全不看舰级自己的射程带**——而舰级路径的射程带早已是**绝对值**（船长 ⑤「射程和战术仅仅的弱相关，
> 并不实时强绑定」）。带与位置脱节 ⇒ 敌人会站在**自己射程之外**（或玩家射程之外）⇒ 出现
> **弱技能行打满 600s 硬上限**、**教学卡 0%**、**近战装配下玩家 0 开火**三类同源故障。
>
> **修法一句话**：把期望交距改成**取该单位自己的射程带**，**战术只决定"带内的偏好位置"**
> （沿用现有 `tacticDesireFactor`：brawl 0.20 / orbit 0.55 / kite 0.85）。**旧路径一字不动。**

## 二、根因

`packages/core/src/combat.ts`：

```ts
const TACTIC_RANGE = { brawl: {0,2200}, orbit: {350,4600}, kite: {1200,9200} }   // ← 旧路径的全局表

export function foeDesiredRange(_me, foes, bal) {
  const tactic = foes[0]?.foeTactic ?? 'orbit'
  const band = TACTIC_RANGE[tactic]!                      // ← ② 用全局表，不看舰级自己的带
  const pos = clamp(0.05, 0.95, bal.tacticDesireFactor[tactic] ?? 0.5)
  return Math.max(bal.minDistanceM, Math.round(band.min + pos * (band.max - band.min)))
}
```

- **舰级路径**里，单位的射程带来自**舰级绝对值**（+ 条目 `rangeMul`/`rangeMinM`/`rangeMaxM` 覆写），
  与 `TACTIC_RANGE` **毫无关系**；
- 于是敌人被要求站在一个"**按旧表算出来的位置**"，而它在那个位置上**可能打不到人**（带太短），
  或者反过来把玩家甩在自身射程之外（风筝卡）；
- **与既有船长口径冲突**：船长 2026-09-11 已定「**射程和战术仅仅的弱相关，并不实时强绑定**」
  （`FoeShipSlot.tactic` 注释、`docs/glossary.md`「射程 × 战术（弱相关）」条）——
  **期望交距却仍强绑全局战术表**，正是这条口径漏掉的一环。

**对照实验（证明"同源"而非"舰级路径独有"）**：同一装配、同样两行弱技能，去打**旧路径 kite 卡**
`幽灵舰信号 T46` ⇒ **80% / 54s（无技能）、100% / 46s（低技能），不触顶**；
`深渊之门 T45` 与三张 E 段墙**快速判负**、也不触顶。
⇒ 旧路径卡的"期望交距"与"敌人射程带"**同源**（都出自旧表），双方都在射程内、战斗必然收敛；
**舰级路径把射程带换成绝对值、却没同步换期望交距** ⇒ 才有"打不完"。

## 三、修法草案（**待裁决，未实施**）

**核心**：`期望交距 = 该单位自身射程带.min + tacticDesireFactor[战术] × (自身带.max − 自身带.min)`。
`tacticDesireFactor`（brawl 0.20 / orbit 0.55 / kite 0.85）**原样保留**——战术只决定"**带内偏好位置**"，
不再决定"带有多大"。带的两端一律取**建档后的有效值**（含 `rangeMul` / `rangeMinM` / `rangeMaxM` 覆写）。

### 3.1 混编卡（一张卡多个单位、带不同）怎么取？三个候选

| 方案 | 定义 | 优点 | 代价 |
|---|---|---|---|
| **A（推荐）** | 取**首个单位**的带（现状取 `foes[0]` 的战术，改成同时取它的带） | 最小侵入、语义直白；与"同卡同带"覆写（A 族已给四张卡的头目写过）**天然互补**——想让整队一致就写覆写 | 混编里带不同的单位仍可能够不着（需靠覆写逐卡纠偏） |
| B | 取全单位带的**交集**带内偏好位置 | 保证"整队都能开火"，理论上不再出现 0 开火 | 把 kite 的实际交距拉近（A 族灰霾：交集 1255~2210 ⇒ 期望 ~2.1km），**削弱拉距身份** |
| C | 取全单位带的**并集** | 保住拉距身份 | 仍可能出现个别单位够不着（= 现状痛点） |

**推荐 A**：与船长「射程与战术弱相关、射程是独立旋钮」一致，且"逐卡覆写"这条既有的纠偏旋钮已经存在
（A 族四张 kite 卡的头目就是靠它把 60% 火力救回来的）。

## 五、验收判据（修完后必须全过）

1. **弱技能行无触顶**：六张 A 族卡 ×（无技能 / 低技能）× ≥5 播种 ⇒ **无 600s 触顶**；
2. **A 族中位行不劣化**：六卡 **胜率均 100%**；带损失的四张（信标/灰霾/赤潮/蜃影）残血**不显著上升**（建议 ≤ +10pp）；
   边境/碎晶**允许变难**（它们本该被还手）——但需给出对照读数；
3. **强制新列「敌开火次数」> 0**：标准中距行下，每张非硬卡**敌人至少开过火**；
   唯一豁免 = 清场过快（时长 < 15s，需在报告里注明）；
4. **双向射程检查**：贴脸近战行下 `我开火 > 0`（不再出现"玩家够不着"的 0% 死局）；
5. **旧路径零回归**：`battle-calibrate --csv` 的 20 张旧路径卡**逐行逐字不变**（`Compare-Object` 无差异）；
6. **回归守卫**：把"期望交距 = 自身带内偏好位置"写成常驻用例（给固定带 + 固定战术算期望值），
   并在 `content:check` 里加一条"**舰级路径卡的期望交距必须落在自身射程带内**"的契约（可枚举 9 张卡实算）。

## 七、落码记录与验收结论（2026-09-11 · 船长采纳②后新增）

### 7.1 实现（改了什么、在哪）

| 位置 | 改动 | 说明 |
|---|---|---|
| `packages/core/src/combat.ts` `UnitSpec` | 新增可选字段 **`foeRangeBand?: { min; max }`** | **只有舰级路径会写**（建档时把该条目**含覆写后**的有效射程带写进去）；旧路径一律不写 ⇒ 旧口径零变化 |
| `createFoeSpecsFromShips()` | 建档时写 `foeRangeBand: { min: rangeMin, max: rangeMax }` | 值 = 舰级射程带 × 条目 `rangeMul`，或被条目 `rangeMinM`/`rangeMaxM` 覆写后的**有效值**（与武器实际带同源，不会漂） |
| `foeDesiredRange()` | 带改为 **`foes[0]?.foeRangeBand ?? TACTIC_RANGE[战术]`** | 舰级路径取自己的带；**旧路径回退全局表，一字不动** |
| `TACTIC_RANGE` 注释 | 标注"**只服务旧威胁推导路径**" | 防后人误以为它还管舰级路径 |

**带内偏好位置（与旧口径的可比映射）**：`期望交距 = 自己的带.min + tacticDesireFactor[战术] × (带.max − 带.min)`，
`tacticDesireFactor` **原值不改**（brawl 0.20 / orbit 0.55 / kite 0.85），语义从"在旧全局表里取比例位置"
变成"**在自己带里取同一个比例位置**"——即**战术只决定相对位置，带由舰级决定**（船长口径「射程和战术弱相关」）。

**混编卡取哪个单位**：取 `foes[0]`（卡上首个主体单位，与既有"战术取自 foes[0]"一致）；
需要"头目与杂鱼站在同一带"时用条目 `rangeMinM`/`rangeMaxM` 覆写（**同卡同带**，A 族四张 kite 卡已用），
**不引入加权平均**（避免"谁都不到位的中间值"）。

### 7.5 P0-2（开战距离 / 先手）——**建议留作下一批**，理由三条

1. **影响面不同**：开战距离 `battleOpenM` 由**双方最远武器射程**决定（`射程 + max(100, 10%)`），
   它**本来就参考了射程带**（不是固定值），但会把远程一方（玩家 5740m 炮）的开场拉到 6314m ⇒
   慢速敌人在开场有 ~1km 的"挨打窗口"。改它会动**全部 26 张卡（含旧路径 20 张）**，
   而本次判据 4 要求旧路径逐字不变 ⇒ **同一批混改会让判据 4 无法证成**。
2. **归因需要单变量**：本次已改"期望交距"，敌人在**接近段**的行为随之变化（教学卡的
   "敌人一炮未放"已被顺手解决，实测 0/25 格）。先拿到新口径下的开场窗口读数，再定开战距离怎么改，
   否则前后对照无法归因。
3. **候选修法需船长选型**：①开战距离按"双方射程带的**重叠区**"；②让慢速敌人在开场即位于自己带内
   （先手/预置距离）；③只对教学与低威胁卡缩短开战距离。三者难度与影响面差别很大，宜单独一批讨论。
