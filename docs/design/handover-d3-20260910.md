## 5. 船长已定的口径（别再翻案；问起就照这个答）

1. **循环制造 = 卡片级**（2026-09-10 定）：一张卡（一个蓝图）一个开关、一个目标件数、一个「本轮全卡合计」；
   作用于**该卡全部制造线（含主控亲自那条）**，新开的线自动继承；目标 = 全卡合计，达标即停、在跑件跑完再停
   （最多超产 = 同时在跑线数 − 1）；达成/缺料 → **自动关开关 + 卡片标停因**；「关→开」= 新一批（合计与停因清零）；
   改目标不动已累计合计；手动关不写停因。精炼炉/回收炉**不动**。
2. **悬赏附赠 = 已全部移除、机制保留**：数据清空、字段与结算链路保留（日后可再挂）；手册「货仓装不下缴获会暂停」按船长指示**保留原文**；
   重复清剿因此不会再因货仓满而暂停。
3. **星图派系标记 = 横向永远居中 + 冲突上抬 + 1.6s 缩放脉动**（红方框/红圆点/`✦`/全称标签四处强调是一号按船长口径加的，别删）。
4. **星图坐标**：烬火星区右移 40 是为了让「敌对派系活跃」全称标签居中时不撞「星噬之口」；蜃影星系下移 12 是为了让
   「碎晶带→烬火星区」航线让开它的圆点（垂距 1.6 → 13.0）。**改坐标必须复算航线与徽标带**（§6）。
5. **市场类型 = 高/中/低槽装备三类型**（原来的「装备」类型已移除，装备的功能子分类保持原样，两级叠加）。

## 7. 已知坑（三号视角；与一号文档 §7 互补）

1. **绝不用 PowerShell 改仓库文本**：本会话被 `Set-Content`/`-replace` 弄花过两次中文
   （`ActivityBar.tsx` 一次、临时探针一次）。批处理一律"写成 `%TEMP%\*.mjs` 用 Node 跑"，跑完删；
   仓库内文本用 read/write/edit。
2. **PS 5.1 的 `Select-String` 中文检索会假阴性**，控制台乱码常只是渲染问题——查中文用 grep/read 工具。
3. **`docs/roadmap.md` 是最高频冲突点**（三位 agent 都往顶部插条）→ 解冲突口径 = **两条并存**；
   解完**必须 `git add` 再 `git commit`**（否则合并提交漏内容）。
4. **"宽窄"要量实宽**：网格 `minmax(240px, 1fr)` 让卡片宽度与窗口宽**不严格相关**——
   这就是"屏幕过窄时隐藏进度条"被否的根因（正常宽屏卡片也只有 240~300px）。同类判定一律
   `clientWidth` + `ResizeObserver` 或用坐标几何算，别按窗口宽猜。
5. **改数据先想契约**：改 `loot`/图标键/槽位归类都可能被 `content:check` 的契约拦下（那是好事）；
   测试里 `dock-unload`/`t8`/`helpers` 用的是**自带测试卡**，不读真实悬赏表——清空真实卡数据不会伤它们。
6. **合并顺序**：先 `git merge main` 到 verify（解冲突）→ 再在主树 `merge verify --ff-only`；
   主树是你和一号/船长的共享面，**合入前后都别在主树落任何文件**。
