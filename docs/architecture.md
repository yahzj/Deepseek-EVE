# 架构文档

> **协作铁律见 [`docs/development-conventions.md`](./development-conventions.md)——每轮开工先读它。**
> 本文件只记录技术架构与决策；功能设计文档见 `docs/design/`。

## 一句话核心设计

> **游戏 = 一颗"纯函数式、确定性"的状态树 + 时间演算。UI 只是这颗状态树的投影。**

所有游戏逻辑（数值、时间推进、随机）都在纯 TypeScript 的 `packages/core` 里，
不依赖 DOM、不依赖 Node、不依赖框架。未来上线时把同一个核心包搬进服务器，
就是"在线版"——这是整个方案最重要的决策。

## 分层与目录

```
界面（apps/desktop renderer）
   │ 订阅状态 / 发送指令（trainNextLevel、dequeueAt…）
   ▼
引擎封装（apps/desktop renderer game/engine.ts）
   │ 读档 → 离线结算 → 每秒 tick → 自动保存（胶水层，不做规则）
   ▼
@whale/core  ← 纯 TS 引擎：advanceGame / 技能队列 / 存档迁移 / 种子随机
   ▲
@whale/data  ← 内容数据：技能表（core 不直接认识任何具体技能）
   ▲
@whale/ui    ← 界面组件（Panel / ProgressBar / LogList）
```

## 关键决策（ADR 式记录）

### 决策 1：core 与 UI/运行时彻底分离
- 规则只存在于 `@whale/core`；数据表驱动内容；桌面层只做"读档、喂时间、渲染"。
- 收益：可单测、可仿真、可整体搬服务端。

### 决策 2：确定性 = 时间注入 + 种子随机
- 引擎只按"流逝毫秒数"推进（`advanceGame(state, deltaMs, catalog)`），不知道墙钟；
  在线每秒 1 次小 delta，离线读档 1 次大 delta，同一套逻辑。
- 随机用种子 RNG（种子 + 使用次数存进存档），结果可复现。**禁止裸 Math.random()**。
- 收益：离线结算与在线推进结果一致；以后探索/战斗/反作弊可复现可校验。

### 决策 3：统一"作业"抽象
- 技能 = 连续型队列（队首正在练，练完出队练下一个）。
- 采矿（M1）= 循环作业：循环时长与产量经技能修正，货舱满自动停。
- 制造（M2）= 限时批次作业：开工扣材料并锁定完成时刻，到点自动完成入库。
- 远征（M3）= 事件型批次作业：出发锁定火力与完成时刻，到点掷种子随机出文字战报；
  作业间互斥由引擎层保证（采矿与远征共船），技能训练永远并行。
- 界面显示统一为进度条 + 日志事件。

### 决策 4：数据驱动内容
- `@whale/data` 的技能表是"一行一个技能"；引擎只认 `SkillDef` 形状。
- 收益：加内容不改代码；数值平衡可批量改表、批量仿真。

### 决策 5：内部包"源码直连"
- core/data/ui 通过 npm workspaces + Vite 别名让渲染进程直接消费 TS 源码，
  开发改完即时生效；包内同时保留"先 tsc 后消费"的能力（未来服务端用 tsup/tsx 同源打包）。

## 存档设计

```
文件（JSON） = { format: "whale-idle-save", version: N, savedAtWallMs, state }
```

当前结构版本 v16：
- **v10**（v9 之上）：六槽位模型——fitted 扩为 miner/cargo/turret/shield/armor/propulsion，
  盾/甲/推进原为占位家族（效果随战斗系统启用，见 v10b 文档）；
- **v11**：随机事件流（events.nextAtGameMs，间隔 10~30 分钟，见 `docs/design/v11-random-events.md`）；
- **v12**：远征两阶段状态机（out→battle→back）+ 实时战斗状态落档（battle 只存动态量）、
  AI 任务 phase/battle、主控采矿 phase 化（见 `docs/design/v12-combat.md`；迁移链 v11→v12 在案）；
- **v13**：星图探索——exploredGalaxies（已探索星系集，初始母港）+ scanning 扫描探索作业
  （见 `docs/design/v13-exploration.md`；迁移链 v12→v13 在案）；
- **v14**：扫描续扫——scanProgress（星系 → 已完成就地扫描窗口毫秒；终止探索时保存，下次补扫）；
- **v15**：调试模式——debugQuick（开发工具：所有作业按 1 秒完成 + 离线快进，见 docs/design/v15-debug.md）；
- **v16**：矿带空间分层 + 复合产出池——删除克洛基石/熔辉石/赤曜石（折算迁移）、悬赏与矿带门槛按星图空间（X 纵深/环心/死路/辐射）重排（见 docs/design/v16-tiering.md）。
v0→…→v16 迁移链在案，老档自动无损升级；真实档迁移经隔离冒烟验证。
- `version` 是**结构版本号**，每次改结构 +1 并补迁移函数（见 core/src/save.ts）；
  读档 = 逐版本迁移 → 逐字段容错补默认值 → 可用状态。
- 保存 = 先写 `.tmp` 再改名覆盖（防断电损坏）。
- 日志环形上限默认 300 条，防存档无限膨胀。

## 星图与航行（V12.1）

- **星图 v2 定稿**：20 星系 × 27 航线（无向带权边，`travelMinutes` 分钟权）。默认坐标为船长
  在游戏内布局编辑器手动排版后导出合入（`packages/data/src/universe.ts`，2026-09-04）。
- **布局编辑器 = 开发工具，默认对玩家隐藏**：需要调整布局时在 DevTools 执行
  `localStorage.setItem('whale-idle:dev-layout','1')` 后刷新；支持拖拽、通路交叉实时红线检测、
  「自动整理」（确定性模拟退火去交叉）、「保存并复制 JSON」回传合入（见 `docs/design/v12a-starmap.md`）。
- **航行跃迁**：星系际实际耗时 = 标称分钟 × (3.0 / 船 warpSpeedAus) × 航行加速技能乘算
  （导航学/跃迁引擎操控/加速控制理论，每级 -4%）；只缩放航行段，矿带内 4 分钟周转与交火不缩放；
  最短路径规划仍用静态边权（见 `docs/design/v12b-travel-warp.md`）。
- **探索迷雾（V13）**：只显示已探索星系与它的一跳"未知信号"剪影；剪影连向更远处的通道
  画半段虚化提示。点亮 = 实际到达（远征到港/矿船开工）或对剪影执行「扫描探索」
  （往返航行 + 10 分钟扫描窗口，扫描期间事件倒计时 ×2 且改从「探索发现」池抽取）。
  未点亮星系封锁远征/采矿/AI 出发（母港不受限）；悬赏情报例外显示（见 `docs/design/v13-exploration.md`）。
- **扫描终止与续扫（V13 附 v14）**：扫描作业可随时终止（进度条「终止探索」按钮）——
  就地扫描窗口已完成毫秒存入 `scanProgress`（随档保存），下次对该星系扫描只补扫剩余窗口；
  返航段终止直接结算点亮；完成/结算均清除进度。

## 离线规则（M0）

- 结算时长 = min(真实离开时长, 8 小时上限)；超出部分放弃并写日志说明。
- 时钟回拨（现在 < 上次保存）→ 不结算、不报错。
- 数值上限与结算入口都在 core（`simulation.ts`），界面无法绕过。

## 升级在线路线（预留，不在 M0 实施）

```
Phase 1（现在）  单机：core 本地跑 + 文件存档
Phase 2         云存档：服务器只做对象存储 + 账号（storage 接口替换）
Phase 3         在线：core 搬进服务器权威跑，客户端发指令收快照
```

因为决策 1/2/5，Phase 3 是"换壳"而非重写。反作弊（时长校验、指令校验）在 Phase 3 补。

## 开发约定

1. 新规则写进 core；core 不 import 任何 DOM/Node/框架代码。
2. 新内容写进 data（技能一行、以后舰船一个文件）。
3. 界面只调 `@whale/core` 公开 API（src/index.ts 是唯一出口）。
4. 涉及存档结构的改动：version+1 + 迁移函数 + 迁移测试。
5. 随机一律走 `nextRandom/nextInt`（种子来自存档）。
6. 日志文案用中文，编码用 UTF-8。
