## 当前路径与历史差异

- `mod-lair-web-h`是`support`家族，不触发推进器禁令；投网在`advanceMyCaptureWebs`独立推进，不写`stealthUntilMs`。
- `mod-lair-blink-r`在2026-10-19已由获批提交`7c43bc2d`改为`support`家族（短距离跃迁装置），普通舰与隐秘行动可以共存；原2026-10-18稿将它归为推进器的结论已过时。
- 真正的`propulsion`家族仍会在普通舰装配取值时取消`stealthMs`，与闪避是否触发无关。鹦鹉螺、幽影侦察舰的`stealthIgnoresPropulsion`及当前袭击者插件的`stealthWithPropulsion`可以豁免互斥；不豁免开火及到期现形。
- `combat.ts`只有实际开火和隐身时限到点两处清除隐身窗口；开火包含无人机、近防炮，即使未命中也现形，基础舰炮在隐身内停火。
- 跃迁规避只在敌方舰炮命中本体时触发。正常隐身内敌舰无法选中本舰，因此闪避通常是现形后的受击结果，不是隐身失效原因。

- 鹦鹉螺及幽影：网加规避、不带输出装备，投网后推进10秒，隐身窗口仍为30000ms，我方/敌方开火均为0，规避未触发。继续推进，两舰本轮首次规避均在30300ms，晚于30000ms现形时限；视图由active转为used。
- 鹦鹉螺网加规避并装炮：炮冷却归零后推进一拍，投网且武器开火，隐身清除，提示为「本舰开火现形」。只有无人机、不装舰炮的对照同样在无人机首次攻击后现形。
- 全部复现使用独立合成战斗和真实`startBattleFor/advanceBattleFor`，没有修改个人档、生产代码或装备数据，也没有运行桌面外壳；结论属于引擎机制核查，不是玩家原档定因。

## 结论与边界

- 没有复现「捕获网或闪避触发直接清除隐身」；短距离跃迁装置现为支援类，不能继续按旧推进器分类解释玩家现象。
- 若玩家用的是侦察舰，必须再核对本舰输出（包括无人机/近防炮）和20/30秒时限；不能仅凭两种装置的动画出现便归因。
- 普通舰仍需检查是否另带真正推进器、有无侦察舰/袭击者豁免；具体玩家配装未知，未擅自认定已复现或修复其原问题。
- 模块：战斗；参照既有`stealth-device.test.ts`、`player-blink-desire-20261008.test.ts`和`battle-device-view-20261008.test.ts`。新增仅专项测试与本核查报告，无跨域玩法改动。
