# 测试门槛存档（Test Saves）

> 约定见 `docs/development-conventions.md` 第八章。B 批次 / 新玩法数值交付时，用
> `tools/make-test-save.ts` 基于船长当前真档注入门槛，生成存档提交到本目录。

## 命名规则（2026-09-08 船长定）

测试存档命名必须符合用途：文件名 `<feature>` 段 = `make-test-save.ts` 中注册的
case 名（即该档服务的唯一测试用途），格式固定为 `test-save-<feature>-<stamp>.json`，
**禁止随意命名**。新增测试用途时：先在脚本头注释 + `INJECTORS` 注册新 case，再在本
「档案清单」补一段说明（注入门槛 + 建议测试路径），然后才生成存档。

## 加载方法（固定步骤）
1. 游戏内「存档管理 → 备份」（保留当前档）；
2. 退出游戏；
3. 把目标 `test-save-<feature>-<stamp>.json` **复制替换** `%APPDATA%\whale-idle\save.json`；
4. 启动游戏即测；测完回到游戏「存档管理 → 恢复备份」还原原档。

每个测试档旁都带一份生成时刻的 `user-backup-<stamp>.json`（注入前的原档副本，双保险）。

> **2026-09-11 去重说明**：`user-backup-20260910-233010.json` 与 `user-backup-20260910-233013.json` 当时**字节完全相同**
> （同一份真档在 3 秒内被备份两次，MD5 均为 `BDA8EE38…`），已按船长裁决**只保留一份**（`-233010`）。
> 故 `lairgear` 档（233013）没有独立配对备份 —— 其配对内容与 `etier` 档（233010）的那一份相同，信息无损。
> 其余真档备份一律不删；同 case 的旧版本（drone / redtide 各两版）保留，取用时**取最新一份**。
