# 数据速查页（改数值时该动哪几处）

> 用途：船长要求「修改某个舰船或装备的数值」时，**照本页走，不要临时通读全仓**。
> 本页只回答两个问题：**① 改哪一行；② 还要连带动什么**。
> 建立日期：2026-09-27（船长令「统一数据速查页」＋「按你推荐来」采纳甲案）。

## 一、单点数值改动 = 标准三步（快速通道）

1. **定位并改掉那一行**（数据表：`packages/data/src/{ships,modules,items,skills,foe-ships,...}.ts`）。
2. **同步"说明文案"**：⚠ 数据侧 `description` 里**手写的数字**是唯一真正的冗余副本 —— 见 §二-①。甲案生效后**新写/新改的说明不再手写数字**（§五）。
3. **跑体检**：`npm run content:check`（＋改动涉及战斗/经济时跑 `npm run test -w @whale/core`）。

**不做**（正常情况**不需要**）：不去通读"谁在读这个字段"——消费方是**读数据源**的，改一处即全线跟随。

## 二、会产生"连带"的只有三类

### ① 说明文案里手写的数字（唯一真正的冗余副本）
- 形态：`description` 是**纯字符串**（`readonly description: string`），里面的数字是**人写的**；
  `⟦…⟧` 只是**高亮标记**（界面把符号去掉、把该段加亮），**不会**把数字变成"读参数"。
- 护栏：`content:check` 有一条契约 ——「说明里的数字必须能被真实数值解释」，不同步就红。
  ⇒ 这道红**是护栏在正常工作**，不是"跨过了护栏"。
- **甲案（2026-09-27 船长令）**：**新写/新改的说明不再手写数字**，数值一律由界面参数行渲染
  （`apps/desktop/src/renderer/src/ui/shipInfo.tsx` 已经这么做了，例如
  `tr("ui.shipInfo.102", { p1: pct(mod.shieldHpBonus) })`）；说明只写**定性**。
  存量条目**随改随迁**（§五）。

### ② 同一份数据的第二表示：`content-csv/` 工作台
- `content-csv/*.csv` 与 `content-workbench.xlsx` 是**同一份数据的另一个副本**（不是消费方）。
- 单向同步：代码表 → 工作台 `npm run content:export`；工作台 → 代码表 `npm run content:import`。
- ⚠ 改完代码表**记得导出**，否则工作台与代码脱节（下次导入会把旧值带回来）。

### ③ 已标定的平衡关系与守护用例
- 有些数值不是孤立的，而是被**关系**钉住的（例：近防炮对舰名义 DPS 反超同档主炮 1.2~1.3 倍；
  蓝图价格阶梯倍率；精炼配平）。改单个值可能让关系失配 ⇒ **有用例会红**。
- 处置：跑测试，红在哪就**要么调数值、要么改标定**（并如实说明改的是哪一边）。

## 三、接线易漏清单（"数据写了、消费方没人读"）

⚠ 这类**体检查不出来**（数据自身自洽）——历史上踩过三次，全部是"数据侧有字段、engine 没接"：

| 字段/效果 | 症状 | 现状 |
|---|---|---|
| 插件 `shieldHpAdd`/`armorHpAdd`/`hullHpAdd`/`speedAddMps`/`speedPenaltyMps` | 曾"只在累加、全仓无消费" | 已接到建档基线（`combat`） |
| 插件 `cpuBonus` | 「CPU 上限的插件装上后无效」 | 已接到 `equipment.cpuBudgetOf`（装配预算单点） |
| 插件 `midSlotsAdd`/`lowSlotsAdd` | 装上跟没装一样 | 已接到槽位单点 `plugs.shipSlotsWithPlugsOf` ＋ 装插件即扩容 |

**护栏**（2026-09-27 加，随 `content:check` 跑）：

```
· 插件效果接线契约：12 个字段全部有 core 读取点 · 数据侧用到 12 个 · 全部已登记
```

两向断言：**数据侧出现的每个效果字段都必须登记** ＋ **登记字段必须能在 `packages/core/src`
（除 `types.ts` 定义处）找到读取点**。⚠ 第一版曾是伪护栏（注释里的字段名也被当成读取点）⇒
实现里**先剥注释**再查。新增插件效果字段时若忘了接线/登记，这一条会当场红。

## 五、甲案：迁移一件装备说明的标准动作（随改随迁）

改到某件装备/舰船时，顺手做：

1. 看它的 `description` 里有没有**手写数字**（`⟦…⟧` 里或句中的裸数字）。
2. 有 ⇒ **删掉句中的数字**，只留定性描述（"护盾上限提升"、"射程更远"）；
   数值由界面的参数行渲染（`shipInfo.tsx` 那套 `tr(id, { p1: mod.xxx })` 已经在做）。
3. 若该数值**界面上还没有参数行**，则在 `shipInfo.tsx` 里**补一行**（走既有 `tr(id, {p1})` 模式，
   id 进制、中英双列），而不是回到"手写数字"。
4. 跑 `content:check` ＋ `l10n:check`。

⚠ 迁移是**增量**的：不要求一次性清完存量；但**新写的一条不许再手写数字**。
