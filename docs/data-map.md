# 数据速查页

> 只定位当前权威字段、连带修改和验证入口，不通读全仓或旧记录。原因：普通数值修改应沿现有数据链工作。

## 一、标准动作

1. 按ID定位权威字段。舰船、装备、插件、物品、商品及已接入敌方源数字在静态JSON，具体路径见`docs/data-editor.md`；未迁移表、公式、名称与文案仍在TS。原因：派生快照不能成为第二份参数来源。
2. 检查说明和界面是否重复写数。新写或改写说明只保留定性，数字由`ui/shipInfo.tsx`等同源参数行显示；新文案先id、英文按显式启动规则登记待译。原因：手写副本会在调参后静默失效。
3. 跑`content:check`、类型与受影响专项，数值体系变动按确认方案跑校准；全量core回归时点按开发约定第二章。原因：不把每次单点编辑扩大为全量集中验收，也不省略最终回归。

普通参数修改不要求通读全部消费方；新增字段或机制则核实实际接线。数据随构建生效，不直接热换已安装游戏或进行中的战斗、订单。

## 二、连带检查

- `description`为文本，`⟦…⟧`仅高亮、不绑定参数。旧说明随改随迁，需要的数字若缺参数行就补同源显示，不另手写。原因：高亮语法不能保证数值同步。
- Excel/CSV是编辑副本；源改后重导前先核对未导入手改，先导入、另存或导出到新目录。原因：自动备份不能替代避免覆盖用户编辑。
- 已标定关系被改动时复核数值与守护用例，明确批准后才同步调整标定，不能删断言换绿。原因：单字段合法不代表战斗和经济关系仍成立。
- 插件等新效果要登记字段并接实际core消费点，不能只有类型、注释或累加无使用；预算、槽位和战斗读同一导出。原因：数据自洽不能证明效果生效。

## 三、命令入口

| 用途 | 入口 |
|---|---|
| 四包类型 | `npm run typecheck` |
| 内容契约与效果接线 | `npm run content:check` |
| 专项引擎用例 | 核心包Vitest按文件筛选；全量仅集中验收时运行 |
| 本地化 | `npm run l10n:check`；参数/渲染改动再跑对应专项 |
| 界面静态契约 | `npm run ui:rot-check` |
| 桌面构建 | `npm run build`；网页在`web/`单独构建 |
| 编辑副本导入导出 | `npm run content:export`、`npm run content:import` |
| 独立数值编辑器 | `docs/data-editor.md`及`data:editor*`命令 |
| 采矿收益 | `npm run mining:curve`，参数以工具用法为准 |
| 当前文档索引 | `npm run docs:index`，不读取旧记录 |

## 四、取数边界

同一字段的效果、预算、显示和保存路径先查`docs/single-source.md`；新增派生值先登记机器注册表和人读索引。原因：修一处数值不应顺手产生第二份实现。
