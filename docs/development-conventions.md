# 开发约定

> 现行协作正文。开工先读`AGENTS.md`与`docs/catalog.md`，再按任务查本页章节。原因：入口负责缩小范围，正文保留执行细节。
> 章节编号保留缺口，不回收或重排。原因：既有文档和代码按章引用。
> 没有船长明确查阅要求，禁止阅读、检索、扫描或自动载入历史留档，包括`docs/archive/`、`docs/design/archive/`及Git历史。原因：旧方案和过期授权不能成为当前工作依据。

## 一、确认流程

- 新的大功能、系统改动、设计取舍、数值体系、存档结构变化，以及需求或范围不明确时，执行集中提问、中文设计总结、等待显式确认、实现并登记决策四步。总结列清方案、取舍、模块、数值、边界和新增/修改/删除项。原因：船长应在实施前了解后果并决定。
- 沉默或「随便、你看着办、都行」不能代替明确范围；批量需求逐项核实，可直接执行的先说明理由。原因：含糊许可不足以支持新的设计取舍。
- 已确认方案的执行可以继续，每段汇报依据与复核入口；需要推翻确认方案时，先重新总结并确认。原因：执行授权持续有效，但不包含替换设计的权限。
- 新提议与旧规则冲突时，停下冲突部分，一次列出原话、规则出处、后果、选项与推荐，等船长裁定后同步规则。原因：执行者不能私选有利口径。

## 二、思考与工作过程约定

- 先读任务所需现行文档与代码，改结构前查调用、界面、测试和工具引用；大任务列清单，逐组修改并验证。原因：记忆和局部实现不足以证明影响范围。
- 玩家报障按玩家提供的条件、代码及确定性用例复现，不拿船长本地真档替代；结论写复现路径、根因位置、玩家现象与改法，设计如此也要检查提示是否充分。原因：不同存档的库存和进度不能相互证明。
- 开发阶段跑受影响的专项测试，行为改变同步增改确定性用例；全部修改确认且船长明确开始集中验收时才跑完整`npm run test -w @whale/core`，最终验收或发布不能以专项替代全量。原因：专项用于快速定位，全量用于最终跨功能回归。
- 固定类型检查为`npm run typecheck`；提交钩子的类型、内容、本地化和UI四项技术检查不跳过，相关内容检查使用`npm run content:check`。原因：人的批准不能代替技术契约。
- B类审批用`npm run commit:approval -- approve --reason <批准依据> -- <精确路径...>`；记录绑定工作树、分支、基线及完整暂存树，变更后重新核实，成功提交后消费。原因：审批必须对应实际提交内容，工具本身不认证人的授权。
- UI或样式变更跑`npm run ui:rot-check`；其检查包含旋转、提前返回、标签和属性拼装，不能描述为只读CSS。原因：布局与提示契约分布在样式和源码中。
- 结构变化跑构建、对应目标的冒烟和存档检查；涉及真档先备份或用副本。原因：类型通过不等于产物能启动或存档能往返。
- 数值或经济改动按影响跑`balance`及本域校准；任务、次数链、市场收入和训练耗时用`balance:chains`对应段。原因：收益和耗时由多处共同决定，应按当前数据重算。
- 新增随档字段同时维护写入点和`normalizeState`白名单，并跑`save:roundtrip-audit`及相关穷尽用例。原因：手工重建对象会丢掉未登记字段，破坏进度和去重账。
- 每次汇报第一行写「报告老大喵」，结论先行，写修改文件、行为变化、验证和已知取舍；自家违规说明规则及修正。原因：这是船长指定的注意力检查和交付口径。

## 三、多会话协作与工作区

- 一号与船长维护主树`H:\大鲸鱼\Deepseek-EVE`；二号、三号、零号分别用同级`Deepseek-EVE-d2`、`Deepseek-EVE-verify`、`Deepseek-EVE-zero`，分支现场核实。原因：工作树隔离写入，旧分工不能冒充当前基线。
- 附属树开工核对main基线，在所属树完成实现和提交；完成后先同步main并解冲突，主树干净且核验通过才合入，随后附属树追平。原因：避免WIP互相污染和误伤他人改动。
- 主树docs是已合入规则的权威入口，附属树不另维护规则；船长指定在附属树改文档时先在指定树检查提交再合入。原因：不能让多树形成不同的生效约定。
- 开发只本地提交；自测、船长验收及大更公告审核满足后，代码与公告同批推送；未完成标待验收或待发布。原因：本地进度不等于对外发布许可。
- 获准联网操作先直连，失败按现场代理设置做命令级重试，不改持久配置。原因：连接条件会变，单次排障不应改全局网络行为。
- 发现他人批量改写、类型跃变或未触碰区域大面积报错等重叠迹象时，停写相关区域，核对自身成果，报告证据、影响与交接建议，等协调；不覆盖、回滚或抢修对方中间态。原因：并行工作可能尚未完成，擅改会造成成果丢失。
- 一般会话仅在技能明确要求时使用该步骤的子代理；零号可为已确认任务委派新子代理，先指定工作树、文件边界并亲自核验，不据此向既有一至三号会话派工。原因：任务内委派授权与跨会话协调授权不同。
- 零号每完成大项先汇报交审，再进入获批的下一项；委派不替代确认、跨域审批、真档保护和发布纪律。原因：增加执行者不会扩大任务授权。
- 不覆写船长真档，需修改时先备份或另写新文件。原因：个人进度不是可丢弃的夹具。
- 获准处理历史文件时优先让Git直接物化到安全目标；不得覆盖他人WIP。批量写入显式UTF8、绝对路径、写前核对内容与预期结果，保持原BOM及行尾，合入后检查乱码和应保留内容。原因：隐式转码、错误相对路径和空内容会损坏中文正文。
- Shell行为现场核实，多行或复杂提交消息用`commit:msg`或UTF8文件配`git commit -F`；文件损坏从干净基线恢复本批范围，不凭记忆补写。原因：旧Shell假设和复杂传参不能保证文本完整。

## 五、检索纪律

- 文档先目录与索引；默认`rg --glob '*.md' --glob '!**/archive/**' <关键词> docs`，在读取前排除旧记录，当前材料不足先记录缺口。原因：先搜索后过滤仍然读到了历史正文。
- 条目按id或唯一键定位后小范围修改，只有无主键的纯文本才以少量上下文核实唯一性。原因：长文案相似匹配易误中，且会随改版失效。
- 跨表查询优先结构化读取，探针按第十章收尾。原因：数据关联应按键而非近似文本推断。

## 七、沟通与语言

- 开发沟通、文档、注释与日志用中文，首现术语说清含义，少堆缩写；代码、提交信息和既有表头标识符保留。原因：船长应能直接理解和审阅。
- 玩家金额单位写「信用点」，显示源为`money.ts`的`MONEY_UNIT`，内部`isk`字段保留。原因：显示命名和持久化键承担不同职责。
- 新约束简短复述并登记；讨论下一步先读`docs/roadmap.md`并同步待办状态。原因：当前决策与后续安排必须有稳定入口。

## 八、测试门槛存档约定

- 大系统、结构或规则数值及新玩法首交付提供可复现生成器、门槛档与加载说明，小修不配。原因：船长应能直接复测关键条件。
- 优先合法初始状态独立合成，确需基于个人真档先获准并备份，输出另文件；通过正式序列化和读档入口。原因：复现不能危及个人进度或绕开字段合法性。
- 只注入难达成门槛，不代做可手动操作，前后写系统日志；通用case或专用生成器都登记用途。原因：保留真实操作路径和可追踪条件。
- 命名`test-save-<feature>-<stamp>.json`，与case用途一致；说明写先游戏内备份、退出、替换测试档、测试后恢复。原因：防止混用存档或误覆盖真档。

## 九、UI风格一致性

- 新增或调整内容先找同组、同页、同域、全仓`app-*`的同类实现，沿用结构、类名与状态后缀，再改差异；页签用既有`app-subtabs`族及可访问状态。原因：一致的交互和盒模型可减少学习成本。
- 容器、卡片、槽位、空满状态按最大内容预留稳定尺寸，长名截断须有完整内容入口。原因：装备和状态变化不应推挤布局或丢失信息。
- 一级页不滚，滚动放二级窗口，内部沿用既有滚动样式；内容必须完整可达，装不下先讨论，不能硬裁隐藏。原因：导航需稳定，同时功能不能因布局被删掉。
- 顶栏与工作区沿用`--app-max-w`、全宽、边框盒和居中；全屏场景及独立弹层读自身约束，不抄固定宽度。原因：既要限制超宽显示，也要避免普通窗口横向溢出。
- 舰船、敌舰、战斗和其他视觉物件沿用SVG线稿；背景氛围可CSS。原因：保留现有视觉语言和资产复用。
- 星系恒星、星球本体及轨道场景允许获批本地位图、Canvas与二维WebGL，七类行星/六类星系可复用有许可的PixelPlanets算法；操作标记沿用现有SVG，不扩大到舰船、战斗或三维场景。原因：星系表现有明确局部授权。
- 星系素材登记来源许可，按公开类型和确定种子选外形；光向、距离衰减、公转仅作表现，暂停、减少动态、后台停画和命中同帧同步齐备，游戏不依赖外部素材服务。原因：动效不能泄露隐藏资源、改变核心坐标或扰动随机序列。
- 普通提示HTML写`title`、SVG写`data-tip`，富内容用`hoverTipProps`或`HoverTip`，统一交`ui/Tooltip.tsx`接管，同元素仅一种机制，内层优先，不写SVG`<title>`子节点。原因：避免原生与自绘叠弹、父子抢占和React卸载冲突。
- 延迟读`TIP_DELAY_MS`，几何读`ui/tooltipGeometry.ts`，不抄常量或在CSS另设上限；短提示按内容收窄，参数名和长说明完整可读，不缩字号或省略文字。原因：首帧、实测定位和全部入口必须同源。
- 接管时压住整条祖先链的原生title，内容更新走现有观察器；保留React管理节点，不在页面直接操作提示DOM。原因：祖先也会弹原生提示，摘节点会破坏卸载。
- 观感由船长验收；浏览器仅用于代码无法判断的几何、性能读数或明确要求的取证，后台运行并注明目标及工具，不用截图自授观感通过。原因：客观读数不能替代船长审美判断。

### 九之七、悬停详情的两个单点

- 完整参数富卡复用`ui/shipInfo.tsx`的`infoCardContent`、各Hover及无包裹内容出口，已有按钮容器用`hoverTipProps`接入。原因：同一物件在仓库、市场、手册与装配都应有一致详情。
- 提示层高于需要提示的浮层，层级读当前样式与单例；同元素单机制、内层优先和统一延迟同时成立。原因：提示被遮或重复归属都会使详情不可用。

### 九之八、UI审核

- 船长或执行者提出UI修改，先查代码与取数，再用`ui-ux-pro-max`按最小主意图查询；无命中收窄重试一次，仍无命中如实说明，不编依据。原因：设计意见应有可核实依据。
- 回话给技能依据、自己的意见、风险与护栏；布局或图形重做按第一章确认，工作文档登记技能结论与裁定。原因：技能不代替项目规则或船长决定，触屏与可访问性也需考虑。

## 十、工具纪律

- 可复跑工具入`tools/`、补用途/用法/输入输出，常用者挂脚本；临时探针用`_`前缀，收尾有复用价值转正式，否则删除，只处置自己的探针。原因：保留有用能力，同时避免垃圾和误删他人在途工作。
- 只关闭自己启动且能以PID证明归属的进程或工具管理任务，不按名称、命令行或调试端口批量关闭；端口先查占用，归属不明保留并报告。原因：船长与其他会话也可能运行同类程序。
- 后台任务两分钟无新输出时查日志与进程，收尾写清遗留任务。原因：及时发现阻塞且不误报完成。

## 十一、术语词典纪律

- 中文词查`docs/glossary.md`，新术语确认当天登记定义、来源与状态，存疑先查；与设计稿冲突时核实现行代码及船长裁定并同步。原因：跨会话不能重新发明同一概念。

### 十一之二、本地化排队

- 未完成、挂起或仅预留的功能不进本地化排队，代码和文档留`⟪未完成 YYYY-MM-DD⟫`与恢复入口，roadmap挂账；完成并合入时移除标记，补id及待译记录。原因：未定稿翻译会反复作废，残留标记又会永久漏译。

### 十一之三、id映射本地化

- 新玩家文本先取稳定id，再接`t`、`textId`或`errorId`，中文进`packages/data/src/l10n/table.ts`，内容名与说明沿用按定义id的覆盖入口；id一经使用不复用、不改名。原因：语言扩展和中文修改不能使既有译文失联。
- 英文准备须船长明确启动，中文确认、实现、合入或发布均不自动授权；未准备时写`en: ''`、`enDeferred: true`并登记`docs/l10n-pending.md`，共享入口回退中文，保留已有英文。原因：中文落地与英文工作的授权独立。
- 启动英文后按`docs/glossary-en.md`审核稿补译、清延期标记；需原样保留的代码串就地声明`l10n-keep`并在收口复核。原因：术语和例外必须可追踪，不能用中文伪填英文。
- 列表参数传`p{n}List`逐项值及可选的`ItemId`、`ItemParams`，分隔符由渲染按语言取；core用`logParams`或`logParamsOf`，空列表用槽id，模板硬槽即使无内容也传空串。原因：拼好的分隔符和缺键会直接泄露到玩家文本。
- 按影响跑`l10n:check`、`l10n:list`、`l10n:params`、`l10n:core-zh`；数组常量和先拼变量仍需夹具人工核，修改`composeParts`或`paramsFor`必跑`l10n:render`。原因：静态工具各有盲区，参数契约必须经过实际渲染。
- 语言选择不进游戏存档，既有文本日志不按切换语言重写。原因：语言偏好与已发生记录是不同状态。

## 十二、游戏内更新公告

- 大系统、玩法、结构、数值体系或重大修复合入前准备公告待审稿，含id、标题、日期、分类及通常3至5条玩家向要点；明确批准后才入`announcements.ts`。原因：公告随产物生效，草稿不能提前发布。
- 公告用第三人称「玩家」，只写世界变化与体验，不写开发、验收、校准话术。原因：玩家需要实际变化而非内部工作过程。
- 已发布公告不追平当前机制，只清开发残留、排版和错别字；改机制陈述或条数例外须船长精确授权本篇本次，不沿用已完成批次的旧许可。原因：公告是当时记录，单篇批准不是常设回改权限。

## 十三、玩家文案纯净与设定

- 玩家可见文本符合世界设定，不含作者、版本、日期、内部编号、字段名、待定、复核、占位或审批语境；交付扫描自己改动的字符串。原因：开发过程不应泄露到游戏世界。
- 按船长报障或裁定调整的文案在改动处留`⟪文案调整 YYYY-MM-DD⟫`与缘由，工作文档登记日期、位置、原文与新文、原因；归档随过程移走。原因：需要定位哪些文案为何调整，普通新写不必标。
- 说明只讲本件是什么、有什么用，定性描述；数字由界面同源参数行提供，不重复CPU、槽位、占格、渠道或档位标签，不点名他件作比较，不写设计原因或绝对推销断言。原因：重复读数和跨件结论会随调参失效。
- 不可制造可中性说明，有蓝图者不重复制造入口；登记的定位契约和非数据断言风味语可留。原因：说明应补充有用信息，不能代替界面标签。
- 括号额外解释能不加就不加，必要时先与船长沟通；既有规格与专名保留，不在括号写因果目的。原因：重复解释会挤占正文并泄露设计理由。
- 不另设任意说明长度上限；叠加采用「多装递减」「多件不叠加」「同类叠加，多来源收益递减」对应真实机制，克制读`typeLayerMult`。原因：长度不是正确性的替代标准，机制用语必须与实现一致。
- `content:check`的纯净、原因解释、跨件对比等护栏不能代替人工审核，匹配不到简写或间接文本的地方仍需核实。原因：词表扫描无法理解全部语义。

## 十四、表现层实现与性能

- Hooks全部位于渲染体提前return之前。原因：条件跳过Hook会破坏React调用顺序。
- 逐帧位置用自己的rAF时间轴更新DOM transform，值不变不写；结构和显隐仍由React管理，跟随位移不交给CSS forwards。原因：低频重渲染和冻结终点都会造成停顿或错位。
- 生死与演出ref入场按引擎状态重建。原因：卸载重挂不能让已毁单位重新存活。
- 大SVG子树状态优先用颜色、透明度和描边，避免整树filter；重阴影缩放走独立合成层。原因：整树重栅格化会造成绘制尖峰。
- 编队、波次和窗口变化后重测锚点，测量与布局循环节流。原因：旧几何会使弹道偏离当前目标。
- 事件先带来源与资产标识再做差异演出，缺省路径保留；一次只改一个主因，按需用`perfHub`取数。原因：展示需要真实事件依据，集中变量才能定位性能问题。

## 十五、工作文档与归档

- 开工建`docs/design/<主题>-<YYYYMMDD>.md`，写状态、经办/分支/日期、船长原话、范围/不做和待裁决项。原因：每批授权和过程应有独立入口。
- 工作期间更新本批文档及代码、数据、测试，旧设计与现行总结留到收口；规则维护、新术语、目录和机器索引按其更新时点维护，AGENTS仅船长明确指示时改。原因：未验收过程不能混入生效结论，及时规则又不能被归档时点阻塞。
- 船长验收并合入后当批归档：有效结论并入现行文档，过程原文移入`docs/archive/`，从常用文档移除，重跑`docs:index`；未决事项保留摘要。原因：保留可追溯记录，同时让日常工作只接触当前依据。
- roadmap只记当前待办、待裁决与实施边界，不存滚动批次流水；旧`docs:seal`流程退役。原因：旧格式会把历史正文和链接重新带回常用入口。
- 旧记录默认禁读，含搜索命中、批量读取、自动索引及Git绕行；普通开发、续接或旧链接不授予查阅权。明确获准后只查指定主题或文件，结束恢复禁读；归档维护可按明确清单复制和校验字节。原因：维护档案与使用历史作工作依据是不同权限。

## 十五之二、取数与派生

- 每个派生数字、文本和标签只有一个导出实现，页面与工具调用单点或ctx；必要直读在`ALLOW_TABLE_READERS`登记理由。原因：同义局部函数和内联拼装同样会形成第二份规则。
- 新单点先登记`tools/arch-guard.ts`的`SINGLE_SOURCE`，同步`docs/single-source.md`再实现，改名搬家一起维护。原因：先明确所有权，避免并行重复和悬空索引。
- `arch:guard`覆盖分层、已登记同名重复、符号落点、ctx取数、跳转目标、本地化日期、存盘心跳、活动门禁及导入环；存量直读白名单须有理由。原因：不同契约需要机器持续检查。
- F2不识别异名同义或漏登记，F3只核机器符号落点不核两份文字表，标签直读另由`ui:subs-check`检查。原因：如实保留工具边界，避免误把通过当作完整审查。
- 注释写依据、判据、公式与单位；净收益、料价、平衡点等结论数字写成用例或现算工具读数，旧失效注释在本批触及时修。原因：一次读数不能伪装成永久规则。

## 十六、规则维护记录

- 约定及AGENTS变更在`docs/development-conventions-changelog.md`登记当前维护记录，旧流水随归档移走，不列日常必读。原因：规则要可追溯，历史过程不能累积回执行正文。

## 十七、生产系统两族

- 新生产默认组装机型：多料到一物，开工整批扣仓库材料，按`spentMaterials`退款，交付结清，卡片级循环按目标、缺料或封顶停机；参照`manufacturing.ts`和`lab.ts`。原因：同族复用投料、退款和循环契约。
- 原矿、冰或气转原材料等一转多才用炉子型，在模块写例外理由；每批到点扣料、货仓优先再仓库，预占账按现有清洗处理。原因：不同投料时点不能混用退款方式。
- 两族均核停靠门槛、手动工位、AI上限占用、调试快速生产、离线统计、视图、随档白名单及主控活动登记。原因：选族不应省略共享生命周期。
- 技能分通用、家族、专属三类，新产线默认接通用加成；当前通用产线节拍学按本产线真实消费实现，卡片读同一core导出。原因：照抄其他产线读数会显示实际上未生效的收益。

## 十八、模块范围

- 模块按功能域，同域core和UI算一个；一次只改一个域，跨域先获船长批准并在提交与工作文档写依据。原因：影响范围需要明确审查。
- 域内先找同类子模块复用，无对照才设计并说明理由；共享类型、样式和文档的修改理由仍须服务本批。原因：共享文件不能成为顺手扩大范围的入口。
- 交付自报功能域、同类参照和是否跨域；`scope:check`只提示不阻断，未归类显式报告，域表随目录维护。原因：静态表能数文件，不能判断设计意图或代替批准。
- 生产单文件超过800行先给拆分方案，获准后才改；模块整理按实际完成范围汇报。原因：大文件影响面需先厘清，不能把局部搬迁写成全仓完成。
